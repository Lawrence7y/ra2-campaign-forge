## 2.122 R118 —— IID 判据的**口径错位**：六轮共用「常量地址」当身份键，而 GUID 是 16 字节**值**；按值精确搜索后 OleSaveToStream 侧 43/43（非 35/43），并证伪「RTTI 能给出接口方法数」

本轮主攻 R117 下轮待办②（0x7f7c80 的 L3 中「通用包装器」替代解释未排除）与④（`IPersistStream` 方法数，R113 起老欠账）。两条都**未被当作"再找一条链"**处理，而是先审判据本身，结果查出 R112..R117 六轮共用的一个前提是错的。

### 2.122.1 判据口径错位（本轮唯一的真发现）

R112..R117 全部把「IID 的身份」当成「它在 `.rdata` 里的那个常量地址」（0x7f7c70 / 0x7f7c80 / 0x7f7c90 …）。但 GUID 是 16 字节的**值**，同一个值在镜像里可以有**多份拷贝**。本轮实测：8 个被研究 IID 共 14 份拷贝（`.rdata` 8 份 + `.data` 6 份），其中 5 个 IID 存在第二份。

r118f 用**16 字节原文全镜像 `raw.find()`**（不经任何形态判据）逐字节精确搜索，与 r118a 的形态判据产物交叉核对：形态判据漏 3 份，`0x7e9530`（0D5CD78E-6470-11D2-9B74-00104B972FE8）有 2 份、`0x7e9ae0`（170DAC82-12E4-11D2-8175-006008055BB5）有 1 份。故 `0x7e9530` 的按值口径应为 2 个 push 站点，而非 r118a 报的 0。

按 GUID 值合并后的 push 请求站点数（`.rdata` + `.data` 真记录拷贝）：
- IPersistStream 00000109：0x7f7c80 = 60，0x820270 = 8，合计 **68**
- IPersist 0000010C：0x7f7c70 = 0，0x818858 = 16，合计 **16**
- IUnknown 00000000：0x7f7c90 = 56，0x817bc0 = 9，合计 65
- ILocomotion 070F3290：0x7ed358 = 7，0x817bb0 = 4，合计 11
- IPiggyback 92FEA800：0x7e9b10 = 0，0x819088 = 8，合计 8
- ILinkStream 0D5CD78E：0x7e9530 = 0，0x83d598 = 2，合计 2

### 2.122.2 对 OleSaveToStream 侧的实质改写（**修正 R116 数字**）

`ole32!OleSaveToStream` 的 IAT 槽 0x7e15f4 全镜像 43 个 `FF 15` 站点（43 个不同函数）。判据 = 同函数内、push 请求站点**早于**该调用：

| 口径 | 耦合数 |
|---|---|
| 按 `.rdata` 地址（R116 口径） | 35 / 43 |
| 按 GUID 48 字节值 | **43 / 43** |
| 按值 + 不看时序（放宽） | 43 / 43 |
| 全镜像任意位置（恒真上界） | 43 / 43 |

R116 落盘的 35 可**精确复现**（按地址口径），数字本身没错；错在口径。R116 的「97.2% vs 0%」效应量表述必须撤销：43/43 与 K2 放宽后仍 43/43 说明该判据**无鉴别力**（R116 审计员当时已提过这一点，本轮补上了机械证明）。

反控：IClassFactory（0 站点）耦合 0；IUnknown（65 站点）耦合 0；LOAD 侧 8 站点按同判据耦合 IPersistStream **0 个**（值口径没有把 LOAD 侧误粘上）。

### 2.122.3 `.data` 拷贝**不是同一种东西**（本轮自我降级）

`.data` 里的 GUID 拷贝必须先分类，不能一律并进统计。判据三条同时成立才算「真记录」：`+0x10` 是 `type_info` vftable（0x7f9594）、`+0x18` 是合法装饰类名、且落在 `.data`。

- 真记录 **2 份**：0x818858（后跟 `.?AV?$VectorClass@G@@`）、0x820270（后跟 `.?AVEditClass@@`）
- 同值巧合字节 **3 份**：0x817bc0、0x817bb0、0x819088

故 **IUnknown / ILocomotion / IPiggyback 三个 IID 的按值数字（65 / 11 / 8）偏高，必须回退到 `.rdata` 数字（56 / 7 / 0）**；IPersistStream 与 IPersist 的 `.data` 拷贝是真记录，数字 68 / 16 不变。

区分力反控：`.data` 里 `type_info` vftable 出现 988 处，前面 16 字节构成 COM 形态 GUID 的只有 3 处 ⇒「type_info 紧跟 GUID」不是普遍结构；`.data` 里 GUID 形状常量 5 个，被判为真记录的 3 个（60%）⇒ 判据有区分力，非恒真。

### 2.122.4 IPersist 的客户端用途与 IPersistStream 不同

IPersist 的 16 个值口径站点：24 个真记录拷贝站点全部满足 QI 三参数形态（`push ppv; push iid; push this; call [reg]`），**同函数内之后出现 OleSaveToStream 的 0 个**；QI 返回指针在 **14 / 16** 站点通过 vtable 槽 `+0xc` 被消费。

deepseek 执行员（task 215）指出「不耦合 ≠ 语义无关」：实测 16 个站点里有 **5 个**在 0x400 字节内有 OleSave 调用，但都在**兄弟函数**里（如 0x4af6a5 在 0x4af610，OleSave 在 0x4af800，两函数以 `ret 8` + `nop` 分隔）—— 典型 QI 包装方法对。采纳为措辞加固，不改数字。

### 2.122.5 `IPersistStream` 方法数：RTTI 这条路被**证伪**（老欠账如实降级）

R113 起挂 6 轮的欠账。本轮试了 RTTI 的 BCD 数据面（与前六轮不共用字节）：
- BCD 是 **24 字节**结构（pTD / numContainedBases / mdisp / pdisp / vdisp / attributes），本轮用 0x7fb020 起 8 项连续条目钉住
- IPersistStream 的 `numContainedBases = 2`（IPersist 1、IRTTITypeInfo 1、IUnknown 0）
- 26 个 `.?AU` 接口中 21 个恒为 1，取 >1 的 5 个：IUnknown(0)、IPersistStream(2)、IStream(2)、INIEntry(2)、INISection(2)

**决定性反例**：把 `numContainedBases` 当输入、R115 的 S 尺槽数当输出做函数性检验 —— 输入 `1` 映射到槽数 `{5, 6, 8, 9, 15, 50}` 六个不同输出 ⇒ 它**不可能**是方法/槽数。Spearman rho=0.733（n=10）仅作参考，不当证伪依据（初稿把它当判据，是本轮自错 S-49）。

**结论：`IPersistStream` 方法数仍未取得，且「从 RTTI 推方法数」这条路已被机械证伪。** 这比"再挂一轮"有价值：它排除了一整类下手点。

### 2.122.6 跨家族与规则 D 复算

- **exec deepseek task 215**（succeeded，4.7 分钟，无 OVERTIME）：三条数字全部**独立复现**（自写 PE 解析 + 指令对齐扫描，不复用我的库）。提出 3 条实质异议，我逐条复算（r118d，8/8 PASS）：
  - 异议 1「按值口径论证失去力度」—— **不成立**。它把「漏检」误读成「效应量」：结论是「按地址普查漏掉了 8 个站点」，不是「它们更耦合」。实测 `.data` 拷贝站点耦合率 16.7% vs `.rdata` 21.9%，无实质差别，这一点它说对了。
  - 异议 2「不耦合 ≠ 语义无关」—— **成立**，已采纳为措辞加固（见 2.122.4）。
  - 异议 3「push-only 漏 8 个 mov 站点，IPS 应为 76」—— **不成立**。实测那 4 个 `mov edi,imm32` 站点后续紧跟 `repe cmpsd`，是 R112/R113 早已分层的**服务端比对基址**，不是客户端 QI 请求。
- **audit hy4 task 216**（`x118audit_method.md` 11.9 KB）：C1/C3/C4/C6 四条成立、C2/C5 部分成立。**全部由主会话复算并修复**：
  - **C1（真错）**：我声称「按值口径不依赖形态判据」是**虚假陈述** —— 拷贝来源仍取自 `found`（形态判据产物）。已写 r118f 用 16 字节原文全镜像 `raw.find()` 重做，并据此改正 `0x7e9530`（0→2）。这是本轮最重要的一条外部纠错。
  - **C4（真错）**：`load_riid` 逐**字节**步进取「最后一个落区段 dword」，不等价于逐指令，方法不可靠（结果碰巧对）。已改为指令对齐 + 窗口 0x60（初改 0x20 时 0x4b62ab / 0x54b7c4 被截掉，见 S-54）。
  - **C6（真错）**：r118d/r118e 共 7 处断言条件直接写字面 `True`，恒真挂进证据链。已全部改成真实条件。
  - **C3（成立）**：槽 `+0xc` 统计无法证明因果（可能混入别的对象调用），14/16 应视为**上界**，已降级表述。
  - **C5（部分成立）**：S-43 我只降级措辞未真修，本轮已由 r118f 补成真修（见 C1）。

### 2.122.7 自错登记 S-42..S-54（本轮 13 条，全部当场抓出）

- **S-42** 复用 r112_lib 的 `fo()` 是朴素 IB 偏移，在 `.detour` 整节错位（真 fo 0x497000，朴素 0x795000 越文件尾）⇒ `struct.unpack_from` 抛 buffer too small。R117 S-40 的同一个坑，我又踩一次。改用按节表映射的本机 `fo/u32`。
- **S-43** 形态判据不完备：`0x7e9530` / `0x7e9ae0` 在 `found` 里 0 份却被当作"普查结果"。初稿只改口径名 + 列 `known_miss`，**未真修**（审计 C5 抓出），r118f 才真修。
- **S-44** 反控打在不下手处：200 个「GUID 形状但非已知常量」位置的 dword 当 push 立即数，命中 1041 次。异质空面（R115 S-16 / R117 S-37 同族）。改为同质空面：末 4 字节取反的伪 GUID（8 个，命中 0）。
- **S-45** `consume_profile` 固定窗口 1200B/400 条，4 个站点离函数入口 1.7~4.5 KB 被**静默截断**在窗外 ⇒ P3a 报 12/16。改自适应扩展。
- **S-46** `0x52119e` 落在「最近 HB 入口的函数体之外」：0x520efb 是 `ret`，其后是跳转表再往后才有代码，那处入口不在 HB 里。HB 是启发式召回（R108 §EJ 已量化），不是完备集。退化成本地窗口，归属不明如实登记。
- **S-47** 把 BCD 当 32 字节、`+0x18` 叫 pCHD —— 那其实是**下一条 BCD 的 pTD**。实测 24 字节布局。
- **S-48** `is_td()` 写成 `cstr(va)`，但名字在 `TD+8` ⇒ 读到 vftable 指针字节，`is_td` 恒 False，1002 个 BCD 候选一条名字都解不出。S-48b 是同一个错误在 `bcd()` 里的第二处。
- **S-49** Q5 写成 `abs(rho) < 0.9` 即 PASS，rho=0.733 靠阈值侥幸通过，结论其实不由 rho 支撑。改为 Q5b 函数性检验（一对多即证伪）。
- **S-50** `ends_with_ret_pad` 取函数内**第一条** ret，而该函数有 3 个 ret 出口，第一条后面还是同函数代码 ⇒ 判据必然错。改为取**最后一个** ret。
- **S-51** r118d 的时序方向写反（`t < s` = SAVE 早于 push），导致耦合率全为 0.0%，一度把执行员的异议 1 误判为「部分成立」。正确是 `s < t`。
- **S-52** 「按值口径不依赖形态判据」是虚假陈述（= 审计 C1）。
- **S-53** `load_riid` 逐字节步进（= 审计 C4）。
- **S-54** 改指令对齐后窗口 0x20 太窄，`0x4b62ab` / `0x54b7c4` 的 REFIID push 在 s-0x30 被截掉 ⇒ P4 从 8/8 掉到 6/8。窗口放宽到 0x60。

### 2.122.8 收口

6 个脚本 **53 项断言全 PASS、连跑两次一致**（r118a 13 / r118b 11 / r118c 7 / r118d 8 / r118e 7 / r118f 7）。全程 `disasm_lite` 分块线性扫描，未对 `.text` 整段开 `detail=True`；脚本均带 `timeout`；收口前确认无孤儿进程。五项 CR 全绿 1081/137/337/0/2952；`check_disc.py` exit 0。

**范畴边界（不越界）**：① 本轮证明的是「判据口径错位」这一方法论事实，以及它对 43 个 SAVE 站点数字的修正；**没有**给出 0x7f7c70 的接口名（本机仍无 IID→名映射表）。② 2.122.5 是**否定性结论**（RTTI 不能推方法数），不是"取得了方法数"。③ `.data` 真记录拷贝的存在不蕴含 L3 升级。
