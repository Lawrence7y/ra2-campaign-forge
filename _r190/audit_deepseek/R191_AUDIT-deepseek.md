## 1. A1：**表述错误，结论方向需改写**

被审主张：「1,013 个直接槽不构成有统一规律的东西；同组内值匹配实测 0，但不能断言语义互不相同」。

### 1.1 前半句与数据相反

按 **(层偏移, 槽号)** 分组（这是我自设的、与被审不同的口径），1,013 个直接槽只落在 **79 个** 组里：

| 组类型 | 组数 | 覆盖槽数 | 占比 |
|---|---|---|---|
| 组内单值（同层同槽号全类同址） | 28 | 129 | 12.7% |
| 组内 `n:1` 塌缩到单一地址 | 28 | 129 | 12.7% |
| 组内 1:1（每类各自实现，纯虚/覆盖形态） | 9 | 78 | **7.7%** |
| mixed（主导值 + 少数例外） | 42 | 806 | 79.6% |

- 同 (层,槽号) 跨类比较 **21,183 对中 16,432 对值相同 = 77.57%**（`r191_audit6.py` X3）
- 决定性结构事实：**278 个不同目标地址，每个地址恰好只对应 1 个槽号，0 例外**（`r191_audit7.py` Y4）。即「地址 → 槽号」是单值函数，这不是统计倾向而是硬结构
- 1,013 槽按层分布：layer4 800（79.0%）、layer8 78、layer12 78、layer24 30、layer36 12、layer40 4、layer44 2、layer1728 6、layer21784 3。**前三个 UI 层合计 956 槽 = 94.4%**

所以「不是一组有统一规律的东西」在 94.4% 的槽上是**错的**：它们有很强的统一规律 —— 值由 (层, 槽号) 决定，且落到 5 个桩地址上（0x410590 ×78、0x410220 ×78、0x410230 ×78、0x410210 ×76、0x410580 ×75，合计 385 槽 = 38.0%；字节分别为 `c20400` / `8b4424048b400cc20400` / 分支桩 / `8b4424048b50fc…ff522c` / `32c0c20800`）。

真正「各自实现」的只有 **78 槽 = 7.7%**：layer4 的 k∈{16,17,18,29}（各 12 槽 12 个不同值）与 layer24 的 k∈{3..7}（各 6 槽 6 个不同值）。

### 1.2 更强的一条：副表槽不是基类接口默认实现的拷贝

对 159 个「该层基类子对象唯一、且其接口在本镜像有本地主表」的槽逐位比对：**与接口自身主表同槽号相同的 = 0 个，全部不同**（`r191_audit2.py` T2）。例：layer12 slot0 = 0x410590（`ret 4`），而 `?AVINoticeSource@@` 主表 slot0 = 0x4c9150。

即：副表槽值**不是**「从基类表抄来的」，而是派生类一侧统一锻造的桩。这进一步否证「无统一规律」。

### 1.3 后半句（不能断言语义互不相同）成立，但理由与被审不同

被审用「同组内值匹配 0」支撑这一点 —— 该论证无效，理由见 §2（R1）。有效理由是 §1.2：副表槽是合成桩，桩地址相同**不蕴含**它们代表的虚函数语义相同，也不蕴含不同。所以「语义互不相同」既不能证也不能否，这一半是对的。

**A1 判定：❌ 前半句不成立（94.4% 的槽有统一规律，仅 7.7% 是逐类实现）；✅ 后半句成立但需换论据。**

## 2. R1：被审的「同组内值匹配 0」信息量为零

### 2.1 比对空间实测只有 123

| 口径 | (表对, 槽号) 三元组数 |
|---|---|
| 全部多表组内表对覆盖 | 1,172 |
| 其中至少一侧是直接槽 | 951 |
| **其中两侧都是直接槽（真正可比）** | **123** |
| 两侧都是 thunk 或非直接 | 344 |

命中数：两侧都直接的 123 对里相等 **0**（`r191_audit6.py` X1）。

### 2.2 这个 0 是零假设的期望值，不是证据

| 零假设 | 期望命中 | 实测 | 结论 |
|---|---|---|---|
| 逐槽独立（按 278 个目标的多重集基率 Σp²=0.03301） | 4.06 | 0 | Poisson P(0\|4.06)=0.017 |
| **层内值置换（尊重「每层塌缩到主导值」这一结构）2000 次** | 中位 0 / p95 0 / max **0** | 0 | 0 恒等于零假设 |

正确的零假设是第二个：值不是独立抽的，而是按 (层, 槽号) 塌缩的。条件化到这一结构后，**0 命中就是期望值本身**，信息量为零。而且 123 次自由度远小于直觉上的「94 个多表组 × 平均槽数」。

### 2.3 域错配：这 123 次比较在语义上不合法

- 94 个多表组内，**组内存在 mdisp 相同的表对 = 0 组**（`r191_audit7.py` Y3）。所以被审的 123 次比较 **100% 跨层**
- layer8 的基类子对象是 `?AVINoticeSink@@`，layer12 是 `?AVINoticeSource@@`（`r191_audit3.py` U2/U4）。同槽号在这两层指**两个不同接口的不同成员**
- 分 (层A,层B) 看，两侧值集合两两不交（`r191_audit6.py` X2）：(12,8)：{0x410590} vs {0x410580,0x41bc30,0x522a60}；(24,4)、(36,4)、(40,4)、(40,36)、(44,4)、(44,36)、(1728,4) 交集全空

拿不同接口的第 k 个成员互相比较，命中 0 是同义反复。

**旁证（被审方自己的产物）**：`_r190/r190e_direct.log` 的 N2 反控记录 —— 「允许跨名字组匹配时命中 **783**」被判 FAIL。这条 FAIL 恰恰说明该判据的 0 是分组口径的产物：放松分组，783/1013 立刻出现。

**R1 判定：属实且更严重。被审的 0 应作废，不可写入任何结论或证据行。**

## 4. A3：**不成立（数据不支持该解释）**

### 4.1 R3 先做：BCD 布局在本镜像成立

| 校验 | 结果 |
|---|---|
| 5,302 条描述符 dword@0 是合法 TypeDescriptor（pVFTable==0x7F9594 且名非空） | 5,302/5,302 |
| dword@12（pdisp）直方 | {0xFFFFFFFF: 5,302} 唯一值 |
| dword@16（vdisp）直方 | {0: 5,302} 唯一值 |
| 自项名 == COL 名 / 自项 mdisp==0 / 自项 ncb==numBaseClasses−1 | 1214/1214 三项全中 |
| **反控 A**：按「20 字节内联记录」解释基类数组 | 前 200 张表里 **527 项**二次间接不命中 type_info ⇒ 内联假设不成立，数组存的是指针 |
| **反控 B**：按指针数组解释 | 5,302/5,302 项二次间接命中 type_info |
| **独立验证 attributes@+20 的位语义**：(attr&2) ↔ 「同名基类在本类数组中重复出现」 | TP=740 / FP=0 / FN=0 / TN=4,562 |

结论：`{pTD, ncb, PMD{mdisp,pdisp,vdisp}, attributes}` 共 20 字节的布局在本镜像成立，atts@+20 可用。附带证实 bit1 = `BCD_AMBIGUOUS`。

（顺带：`_r190/r190k_order.log` 的 K3「反例 5/1214」是我复算不到的 —— 我的同类检查得到基类数组 mdisp 序列的异常与它吻合度不足，此项不列入本审计，登记为未复核。）

### 4.2 但判读 attributes 后，该解释被否定

**否证 1：bit0 不是 non-virtual 标志。**

MSVC 中 non-virtual 由 PMD 表示：`pdisp != -1` 或 `vdisp != 0` 才是虚基类。本镜像 **5,302 条 pdisp 全为 0xFFFFFFFF、vdisp 全为 0** ⇒ 全部是 non-virtual 基类。若 bit0 是 non-virtual 标志，则应有 5,302 条 bit0=1；实测 **bit0=1 只有 12 条**（全在 attr=9 里）。二者直接矛盾。

**否证 2（R4 要求的具名反例）：extra 四档 attributes 全为 0，却一条副表都没有。**

| mdisp | 条数 | attributes 直方 | pdisp | 基类名 | 宿主类 |
|---|---|---|---|---|---|
| 172 | 8 | **{0: 8}** | −1 | `?AVStageClass@@` | `AnimClass`、`TerrainClass` |
| 176 | 4 | **{0: 4}** | −1 | `?AVBounceClass@@` | `VoxelAnimClass` |
| 240 | 25 | **{0: 25}** | −1 | `?AVFlasherClass@@` | Aircraft/Building/Foot/Infantry/Techno/Unit |
| 248 | 25 | **{0: 25}** | −1 | `?AVStageClass@@` | Aircraft/Building/Foot/Infantry/Techno/Unit |

对照组：**attributes 同为 0 却有副表的描述符 4,488 条**。
⇒ attributes=0 与「有副表」「无副表」两种结果**同时兼容**，判别力为零。

**否证 3（最硬的一条）：同一基类、同样的 attributes 判据，在 36 档出 4 张副表，在 172/248 档一张不出。**

`?AVStageClass@@` 作为基类出现 37 次（`r191_audit6.py` X4）：

| mdisp | attributes | pdisp | 有副表 | 宿主 |
|---|---|---|---|---|
| 36 | 9 | −1 | **True ×4** | `FactoryClass` |
| 172 | **0** | −1 | **False ×8** | `AnimClass`、`TerrainClass` |
| 248 | **0** | −1 | **False ×25** | Aircraft/Building/Foot/Infantry/Techno/Unit |

同一个基类、同一个 pdisp 值、attributes 在 172/248 两侧完全一致，结果却是「有副表 / 无副表」二分。同时 4,488 条 attributes=0 有副表的记录证明 bit0=0 不充分。

**A3 判定：❌ 不成立。** attributes 分布不支持该解释；且 A3 引用的位本身就错位（non-virtual 由 pdisp/vdisp 表达，与本镜像全部 non-virtual 的事实一致，因而对四档**没有任何**区分能力）。

### 4.3 我可以给的、数据支持的替代观察（不作为结论）

extra 四档的基类 `StageClass` / `BounceClass` / `FlasherClass` 在本镜像**有本地 TypeDescriptor（`0x817ab8` / `0x845e30` / `0x817ad8`，pVFTable 均为 0x7F9594）但没有本地 COL**（`r191_audit11.log`）。这与「该基类在本镜像不被实例化」一致。但 `FactoryClass` 的 `StageClass`@36 也是同一个没有本地 COL 的基类，却生成了副表 —— 所以「有无本地 COL」也不足以解释四档。**四档成因在本轮静态数据内未取得**，需要动态取样构造点的 vptr 指派（属 win-main 节点任务，超出本卡边界）。

复算：`python3 _r190/audit_deepseek/r191_audit6.py | sed -n '/X4/,$p'`；`python3 _r190/audit_deepseek/r191_audit7.py | sed -n '/Y2/,/Y3/p'`

## 5. R2：两个去重口径不混淆，但被审的 278 需注明语义

| 口径 | 数值 |
|---|---|
| 地址去重（不同实现地址） | **278** |
| (表, 槽) 去重 | **1,013** |
| (COL, k) 去重 | 1,013 |
| (类名, k) 去重 | 893 |
| 槽号去重 | 48 |
| 1013 / 278 | 3.64 |

不存在「同一地址在不同表里重复计数」造成的虚增：1,013 就是槽实例数，278 就是不同地址数，两个数各自正确、含义不同。
更进一步：**没有一个地址跨两个槽号**（0/278），所以**不存在**「同一地址被两个槽号共用」的情形。被审 E4 的「278」与「36」我独立复核得到同样的两个数（被 ≥10 张表引用的地址 = 36，被 ≥10 个槽实例引用也是 36 —— 因为单值性，两种读法在这批数据上同值，属巧合）。

**R2 判定：✅ 无混淆；但稿子里凡出现 278，必须写明是「不同目标地址数」，不得与 1,013「槽实例数」并列比较。**

## 7. 结论汇总

| 主张 | 判定 | 一句话 |
|---|---|---|
| **A1** 直接槽无统一规律 / 同组匹配 0 / 不可断言语义互异 | ❌ 前半句错，✅ 后半句对 | 94.4% 的槽有强统一规律（值由 (层,槽号) 决定、塌缩到 5 个桩地址、地址↔槽号单值 0 例外）；只有 7.7% 是逐类实现。后半句成立，但不能用那个 0 论证 |
| **A2** 直接槽目标聚集是结构性的 | ✅ 成立，需拆机制 | ×648（逐槽独立基率）／×8.2（最保守的多重集零假设）／地址↔槽号单值 0 例外。但「聚集」含两个不同机制：UI 三层默认桩 94.4% + Locomotion 12×50 表 55.7% |
| **A3** 四档因 non-virtual 基类 | ❌ 不成立 | attributes=0 同时对应 62 条无副表与 4,488 条有副表；同一 StageClass 在 36 档出副表、172/248 档不出。且 bit0 不是 non-virtual 标志（pdisp 全 −1 已表全部 non-virtual） |
| **R1** 同组匹配 0 的信息量 | 无信息量 | 可比对只有 123 次；正确的层内置换零假设下期望中位 0、max 0；且 94 组内 0 对同 mdisp ⇒ 比较 100% 跨不同接口，域错配 |
