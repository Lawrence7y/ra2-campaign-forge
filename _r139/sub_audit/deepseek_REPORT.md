## A1 TypeDescriptor 偏移 — 同意

```

BuildingClass  str=0x00818D68 str-16=7340404040000000 str-8=94957f0000000000  TD+0=0x007F9594 TD+4=0x00000000
```

逐字节取样 5 个类（BuildingClass / AircraftClass / AircraftTypeClass / CStreamClass /
WalkLocomotionClass），`str-8` 处一律是 `{0x007F9594, 0x00000000}`，`str-16` 处是上一个串的尾巴
（`73404040`=`s@@@`、`436c6173`=`Clas` 等）。**−8 正确，−16 无反例支持。**

补充证据：962 个 TD 的 `+0` 全部 = `0x007F9594`（唯一值），该处 `vt-4 = 0x80EE30` 反查类名为
`type_info` —— 这正是 MSVC 9.x 的 `type_info::vftable`，与 RTTI 结构定义自洽。

**须记的作用域**：`+4==0` 一项**不能**区分 −8 与 −16（`(str−16)+4==0` 也命中 587/962）；
真正区分二者的是 `+0` 指向 `type_info` vtable 与 `(str−16)` 处是垃圾。主会话 r139e 的 docstring
把 `+4 == 0`、`+8 内联 .?AV? 前缀` 都列为「校验」，其中 `+8` 项其实是 name 定义本身，恒真。

## A2 COL 结构 — 部分同意

实跑（raw.txt L24–56，raw3.txt，pass8）：

```

三点不同意 / 须补：

1. **「有虚表可唯一确定」的数字不是 952。** 按「候选虚表（vt−4 指向某 COL）」口径，
   952 类中只有 **858** 类唯一；1216 个候选平均 1.28 个/类，94 个类有 ≥2 个候选。
   唯一性只在 **mdisp==0 口径**下成立：每类 mdisp==0 候选数分布 = `{1: 952}`（raw8）。
   F29/A2 用「唯一确定」一词时，必须声明是 mdisp 口径，否则 952 这个数站不住。
2. **判据 2 与判据 3 的后半条件是恒真同义反复。**
   `COL = r−12` 且验 `dword[COL+12]==TD`，而 `dword[r]==TD` 就是 `r` 的定义；
   同理 `vt = p+4` 且验 `dword[vt−4]==COL`，而 `dword[p]==COL` 就是 `p` 的定义。实测：

   ```
   TD 指针引用总数 = 2186 ; 其中前 12 字节处 dword==0 的 = 1214
   即「dword[COL+12]==TD」一项剔除了 0 个候选（恒真），实际只有 signature 一项在筛
   ```

   r139e 的 `ck('1.4 每张虚表 vt-4 都指向自己的 COL')` 因此是**恒真断言**，
   不构成任何独立验证；PASS 它不能作为链成立的证据。
3. **952 与 F01 的 954 差 2，未披露。** 把 `.?AU` 一并算：

   ```
   .?AV 类名 962 ; 有 COL 的 .?AV 类名 952 ; 无 COL 的 10 个
   .?AU 名 26 ; 有 COL 的 .?AU 名 2 个: ['INIEntry@INIClass', 'INISection@INIClass']
   合计有 COL 的类名 = 954 （F01 称主 COL 954）
   唯一 COL VA（signature==0 且 +12==某 TD）= 1214   （F01 称总 COL 1211，差 3）
   唯一 vtable VA = 1216
   ```

   952 是 `.?AV` 口径、954 是 `.?AV + .?AU` 口径。两数都对，但 F29/A2 只写 952 而不写
   「952 不含 2 个 .?AU 类」时，会与 F01 的 954 直接冲突。**这是口径缺口径，属 A2 的实质缺陷。**

10 个无 COL 类的 ref−12 处 dword 已逐个核（raw8 首段），全部 `≠0`（是 `FFFFFFFF` 或别的结构表头），
判据 2 正确排除，无假阴性。

## A4 「有效桩」跟终点规则 — 不同意（数字对、机制错）

### A4-1 结论数 64/77 成立

```
mode=fix    两槽皆 追到桩 = 64/77
mode=strict 两槽皆 追到桩 = 63/77     （不跟 8B44240450 E8 转发形态）
扩展跟链（把 FF15/FF25/EB 也跟）14 例外中翻案 = 1 ; 全 77 = 64
正确基址 81=+13 83=+10 / 任一虚表            64
正确基址 81=+13 83=+10 / 真实主表            64
主会话   81=+12 83=+8  / 任一虚表            64
主会话   81=+12 83=+8  / 真实主表            64
```

四种「口径×基址」组合都出 64，所以**这个数稳健**。

### A4-2 但 follow 的两个跳转基址都错

- `81 6C 24 04 imm32 ; E9 rel32` 全长 = 4 + 4 + 1 + 4 = **13**，主会话用 `va + 12`（差 1）。
- `83 6C 24 04 imm8 ; E9 rel32` 全长 = 5 + 1 + 4 = **10**，主会话用 `va + 8`（差 2）。

capstone 独立确认（raw.txt L239–242）：

```
816c240404e9   -> capstone 报 sub dword ptr [esp+4], ... / jmp  (前 12 字节已消费，含被误拼的 imm)
836c240404e9   -> [('sub','dword ptr [esp + 4], 4',5), ('jmp','0x100a',5), ...]  合计 10
8b44240450e8   -> [('mov','eax, dword ptr [esp + 4]',4), ('push','eax',1), ('call','0x100a',5)] 合计 10
```

按正确边界逐一反汇编（raw.txt L250–255）：

```
DriveLocomotionClass +4 0x004B4DA0 [('sub','dword ptr [esp + 4], 4',5), ('jmp','0x4b4cb0',5), ('int3','',1)]
FlyLocomotionClass   +4 0x004D0520 [('sub','dword ptr [esp + 4], 4',5), ('jmp','0x55a950',5), ('int3','',1)]
```

影响面（raw.txt L530）：

```
受 off-by-1..2 影响的槽数 = 238 ; 但两种口径的 77 计数 main=64 fix=64
```

238 个槽的终点地址算错 1–2 字节，只是因为错位目标恰好不是桩体起点，77 计数才没翻。
**这是「结果侥幸正确、过程有已知错误」**，任何把它写成「已验证的跟链器」的表述都不成立。

### A4-3 「多出的是 AircraftClass」这个叙事站不住

AircraftClass 的原始槽字节（raw.txt L165–168，raw6 段 1）：

```
AircraftClass vt=0x007E22A4 +4 -> 0x004142F0 bytes=8b44240450e806c0ffffc20400...
    trace=[('callfwd', 4276976, 4260608)] 终点=0x00410300 in_stub=True
AircraftClass vt=0x007E22A4 +8 -> 0x00414300 bytes=8b44240450e806c0ffffc20400...
    trace=[('callfwd', 4276992, 4260624)] 终点=0x00410310 in_stub=True
```

即 `mov eax,[esp+4] / push eax / call 0x410300 / ret 4`，跟到 `0x410300` = 桩。**规则对它确实成立。**

但「只多它一个」不是因为规则严格，而是因为 AircraftClass 在 **5 张候选虚表**里有 3 张在正确基址下都
判皆桩（pass7）：

```
任一虚表 fix vt=0x007E22A4 mdisp=0    slot1->0x410300 slot2->0x410310 皆桩=True
任一虚表 fix vt=0x007E2250 mdisp=1728 slot1->0x410300 slot2->0x410310 皆桩=True
任一虚表 fix vt=0x007E2288 mdisp=4    slot1->0x410300 slot2->0x410310 皆桩=True
```

`vt=0x007E2250` 的 `mdisp=1728`（=0x6C0），显然是 COL 链被误认成虚表，却也被判皆桩。
**「跟终点才翻案」实际由「任一虚表」口径兜住，不是由跟链器兜住。**

### A4-4 对「是否对别的 13 张也成立」的回答

**不成立。** 13 个例外（11 Locomotion + BulletClass + CStreamClass）的槽终点是真 AddRef：

```
FlyLocomotionClass +4 0x004D0520 83 6C 24 04 04 E9 ... -> 0x0055A950
0x55A950 处 = 8b4424048b153ccdab0083c014425089   （mov eax,[esp+4]; mov edx,[0xabcd3c]; add eax,0x14; ...）
0x4B4CB0 引用的 0x55A950 是否桩 = False
BulletClass +4 0x0046AFD0 bytes=8b4424048b153ccdab0083c01c425089153ccdab  -> stop, 非桩
CStreamClass +4 0x004A2930 bytes=8b4424048b153ccdab0083c00c425089153ccdab -> stop, 非桩
```

即 `0x55A950` 处有 `add eax,0x14`（对 eax 做字段调整）—— 恰好命中 F29 正文自己写的
「真转发器的判别点是**有没有对 eax 做字段调整**」。所以 64 而不是更高，是**正确的**，
且这条判别点与实测一致。这一点我确认主会话的 64 没有虚高。

### A4-5 follow 规则的两处过宽（推广时会炸，当前 77 上恰好没炸）

1. `8B 44 24 04 50 E8 rel32` 形态**未校验 call 返回后的后缀**。全镜像该序列 47 次，
   call 后 3 字节分布 `[('c20400', 36), ('84c00f', 5), ('85c074', 2), ('84c075', 1), ...]`
   —— 有 11 处 call 后不是 `ret 4`，是 `test al,...` 的普通函数，按此规则会被误跟。
   77 类候选里 14 个该形态槽全部 call 后为 `c20400`，故未误判。
2. 深度上限 6 **从未被触及**：77 类全部候选虚表全部槽的跟链最大长度 = **2 跳**。
   F29 限制段「依赖跟转接链的深度上限 6 跳」是对未触发约束的声明，不构成风险披露。

## A6 判别力 — 不同意

### A6-1 「随机置换 200 次最大仅 64」不可复现

实跑（raw5 末段）：

```
主会话 seed=20261126 N=2000 复现:  最大 = 64  分布 = [(63, 1998), (64, 2)]
N=200 seed=1         最大=66
N=200 seed=2         最大=63
N=200 seed=3         最大=63
N=200 seed=7         最大=63
N=200 seed=20261126  最大=64
N=200 seed=424242    最大=63
seed=555001   N=20000 最大=68 ; >=74 次数=0 ; 均值=63.005 ; top6=[(63,19920),(64,72),(66,7),(68,1)]
seed=20261126 N=5000  最大=66 ; >=74 次数=0
```

**seed=1、N=200 就拿到 66；N=20000 拿到 68。** 「最大仅 64」只是 seed=20261126、N=200 的样本极大值，
不能作为「上限」断言。F29 正文若写「随机置换族标签 200 次最大仅 64」，把一个**样本极值**写成
上界，属统计表述错误。正确写法应是「P(stat≥74) ≈ 5.4e−11」或「20000 次抽样最大 68」。

### A6-2 这个检验是不是「两族纯」的复述？——**是**

```
解析：块大小固定 %s 时该统计量的全域最大值 = 74 ; 实测 74 是否已到顶 = True
解析：达到上限的精确概率 = 1.577e-11（多重超几何口径 5.448e-11）
统计量 = Σ_f max(k_f, n_f−k_f)，仅是三个 (n_f,k_f) 对的函数，与类名归属无关。
```

三条依据：

1. **统计量只依赖三个数对。** `stat = max(k1,11−k1)+max(k2,22−k2)+max(k3,44−k3)`，
   与「哪个类名落在哪一族」完全无关，只与每族的桩数有关。而族划分是**类名后缀预先固定**的
   （与字节无关），所以这个检验真正测的是「(11,0),(22,22),(44,41) 这组数在固定块大小下的
   超几何分布里多极端」—— 即族纯度本身。
2. **74 就是该统计量的全域最大值。** 14 个非桩若恰好 11 个进 11 块、3 个进 44 块、0 个进 22 块，
   即得 11+22+41=74。实测正好取到这个上界。所以「74 显著」与「族是纯的」是同一句话。
3. **族定义与族纯度同源。** `LocomotionClass` 的 11 个类是同一套继承体系里的 11 个兄弟类，
   共享 AddRef/Release 实现是 C++ 虚函数的必然结果，不是独立于族标签的第二个证据。
   而 `TypeClass` 22 个全桩同理（同属 ObjectTypeClass 派生族）。所以「族属性携带真实信息」
   在没有跨族反例（如某个 LocomotionClass 是桩、某个 TypeClass 非桩）时，是不可否证的同义反复。
   F29 已诚实登记 Other 的 3 个例外 —— 这 3 个例外恰恰是**唯一**有判别价值的部分。

结论：该检验**能**否证「族与桩无关」（p 极小），但**不能**支持「族属性携带真实信息」这一因果读法；
它支持的是「三个族各自的桩比例分别是 0/11、22/22、41/44」这一描述。F29 正文「族属性携带真实信息
且几乎决定结果」中，「决定」可由 74/77 支撑，「携带真实信息」是循环表述。

### A7-2 桩集合的定义风险：40 个里只有 12 个是干净函数体

```
40 个命中里「干净独立桩」(前后均 90 90 90 90) 的个数 = 12
40 桩中「非独立函数体」(前后非 90909090) = 28 / 40  例: ['0x40d230','0x42e662','0x4a3850']
  0x0040D230 pre=ff5108c3 stub=b801000000c20400 post=90909090
  0x0042E662 pre=48067508 stub=b801000000c20400 post=33c0c204
  0x004A3850 pre=00007508 stub=b801000000c20400 post=568b7424
```

28/40 的「桩」嵌在别的指令流里（`pre=48067508` 之类），是字节巧合而非函数体。
但 63 实际只用到 **6 个**桩地址，且全在这 12 个干净桩里：

```

40 个命中里被 63/77 用到的、且不干净的 = []
```

故结论不受影响，但「用 40 个桩的全集」这一设定是噪音源：把桩集合缩到 12 个干净桩后仍应是 63
（我用 2 个常驻桩得到 61，见 raw2 L88），而「40」这个数被 F29 限制段反复引用（并已声明与 63 无因果），
属应删而未删的干扰项。

### A7-6 未落盘 `.data` 尾段（对主会话有利，但主会话未披露）

```

这是一个必须写进 F29 限制的**前提**，否则别人换一份 `.data` 压缩不同的镜像就会静默漏算。

## 判决汇总（供主会话入账）

- **可入账（复现通过）**：77 / 63 / 64 / 74 四个数在「mdisp==0 主表」口径下全部复现，
  14 个非桩名单逐字一致，族划分 11/22/44 与 74 的算术无误。
- **须改表述（数字对、机制错）**：
  1. follow 的 `81` 基址 `+12`→`+13`、`83` 基址 `+8`→`+10`（238 槽终点算错，77 计数未变）；
  2. 「随机置换 200 次最大仅 64」是样本极值，非上界（seed=1 即 66，N=20000 得 68）；
     F29 应改引 `P(stat≥74) ≈ 5.4e−11`；
  3. 「有虚表可唯一确定」须标 mdisp 口径（候选口径是 858 不是 952）；
  4. 952 须标「不含 2 个 .?AU 类（含则 954，与 F01 一致）」。
- **须补披露**：
  1. 判据 2/3 的后半条件恒真，`ck('1.4')` 是恒真断言，不构成独立验证；
  2. 「最低 VA」选表口径下 63 归零 → 63 对选表规则敏感；
  3. 主会话代码用「任一虚表」口径，与 F29 限制段声明的「主表规则」不一致（77 上同值属侥幸）；
  4. 96.8% 的类共用同一对桩 `(0x410300,0x410310)`；
  5. `.data` 有 3.1 MB 未落盘，本链成立前提是全部 RTTI 恰在落盘区（实测 0 例外）；
  6. `0x6C2AC0`/`0x6C51C0` 属**工厂类表** slot1，不参与产品类主表 63/77，须与 63/77 分段。
- **不同意的核心**：A4 的「跟终点才多出 AircraftClass」叙事不成立（该判定由「任一虚表」口径兜住，
  且 AircraftClass 有 3 张候选表都在正确基址下判皆桩）；A6 的统计表述与因果读法均须降级。
