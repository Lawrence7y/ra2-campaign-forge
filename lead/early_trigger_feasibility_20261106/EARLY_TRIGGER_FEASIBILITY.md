## Q1 起点可观测性及误差

### 1. 理论上界推导与因果时序模型
在连续物理时间轴上，设游戏逻辑主线程因计算瓶颈导致当前帧推进停滞的真实物理跃变点为 $S$。外部监控器以标称频率 $f_s = 500\text{ Hz}$（标称周期 $T_s = 2.0000\text{ ms}$）对帧号（`CurrentFrame`）进行周期性离散读取，采样时刻序列为 $\{t_0, t_1, \dots, t_k\}$。
由于前序拍 $t_{k-1}$ 观测到的帧号仍处于正常推进状态（$f(t_{k-1}) \ne f_{\text{stall}}$），而首个观测到停滞帧号的采样拍为 $t_k$（$f(t_k) = f_{\text{stall}}$），因此在因果连续时间下，物理起点 $S$ 必然被相邻两次采样夹逼在半开半闭区间内：
$$t_{k-1} < S \le t_k = \hat{S}$$
在线因果触发机制必须以首个停滞采样拍 $\hat{S} = t_k$ 作为物理起点的因果代理。则单向观测滞后误差定义为 $e = \hat{S} - S = t_k - S$。代入区间关系可得误差范围：
$$0 \le e < t_k - t_{k-1}$$
在理想无抖动的 500 Hz 标称均匀离散采样下，相邻间隔 $t_k - t_{k-1} = T_s = 2.0000\text{ ms}$。因此，以因果首拍作为代理时，物理起点观测误差的**理论单向滞后上界严格为 $2.0000\text{ ms}$**。

### 3. 「S 后 50ms 内」实际剩余操作余量 $(50 - e)$ ms 核算
D-29 裁决约束要求「原始上下文在物理起点 $S$ 后 50ms 内实际保存」，即完成保存时刻 $C$ 须满足 $C - S \le 50.0\text{ ms}$。将因果观测关系 $S = \hat{S} - e$ 代入，因果首拍到达后留给在线仲裁、线程挂起与抓栈保存的剩余物理操作余量严格为：
$$\text{Margin} = C - \hat{S} \le (50.0 - e)\text{ ms}$$
对有效样本量 $n = 1677$ 条逐项核算：
- 理论标称余量：$50.0 - 2.0000 = \mathbf{48.0000\text{ ms}}$；
- 实测中位余量：$50.0 - 2.5150 = \mathbf{47.4850\text{ ms}}$；
- 算术平均余量：$50.0 - 7.9427 = 42.0573\text{ ms}$；
- **余量充沛样本数（$\text{Margin} > 0\text{ ms}$，即 $e < 50\text{ ms}$）**：$n = 1621$ 条，占比 **96.66%**；
- **余量透支样本数（$\text{Margin} \le 0\text{ ms}$，即 $e \ge 50\text{ ms}$）**：$n = 56$ 条，占比 **3.34%**；在极端最坏样本下，观测首拍到达时已滞后起点 488.6160 ms，余量透支达 $-438.6160\text{ ms}$。

### 4. 数据检验结论
- 在采样调度维持常规波动（误差 $e < 50\text{ms}$，样本占比 96.66%）的假设下，数据支持「离散采样观测对物理起点的因果滞后受控在中位数 2.515ms，留给后续保存操作的理论时间余量达到 47.485ms」；
- 在采集线程遭遇长掉拍或调度阻塞（误差 $e \ge 50\text{ms}$，样本占比 3.34%）的假设下，数据不支持「在物理起点 $S$ 后 50ms 窗口内完成现场捕获，因果观测到达瞬间该时序窗口已发生物理透支」。

## Q2 50ms 窗口内的可捕获性

### 1. 50ms 窗口持续性判定机理与物理硬边界
检验提前触发机制的核心物理边界，在于判定事件在推进至 $S + 50\text{ ms}$ 这一时间截面时，引擎内部是否仍在停滞（即采样时序中帧号 $f$ 是否仍保持不变未推进）：
1. **目标截止时刻**：以事件观测起点 $\hat{S} = t[\text{startTick}]$ 为因果锚点，设定保存窗口截止时刻为 $T_{\text{target}} = \hat{S} + 0.050\text{ s} = t[\text{startTick}] + 50\text{ ms}$；
2. **状态判定逻辑**：停滞段末尾采样拍为 $\text{endTick}$（对应时戳 $t[\text{endTick}]$，帧号为 $f_{\text{stall}}$），其下一采样拍 $\text{endTick}+1$ 帧号推进为 $f_{\text{stall}}+1$。若 $T_{\text{target}} \le t[\text{endTick}]$，则截面时刻严格落在停滞平台内部，帧号未推进，确证可捕获；若 $T_{\text{target}} > t[\text{endTick}]$，则代表引擎在 50ms 截面前已恢复帧推进；
3. **物理硬边界属性**：若某事件在 $S+50\text{ ms}$ 之前就已恢复推进（即事件物理持续时长 $d < 50\text{ ms}$），则当检测生效与捕获到达 $S+50\text{ ms}$ 时，逻辑主线程已离开停滞现场并进入后续游戏循环，现场已不复存在。此属于超出捕获窗口的物理硬边界，非触发策略缺陷。

## Q3 假阳性

### 1. 模拟实验基准与三档判据定义
提前触发方案的核心假设是在停滞游程达到某较小阈值 $k$ 时立即触发快照捕获。离线检验采用全量真实推进窗口（`moving64`，样本量 $n = 64$ 窗，覆盖全部 1,681 条真实事件）进行连续时序全流仿真：
- **触发判据**：数据流中连续 $k$ 个采样拍保持同一帧号（$f_{i-k+1} == \dots == f_i$），在平台长度首次达到第 $k$ 拍时记为一次触发；
- **档位设定（三档全给）**：
  - **$k = 10$ 档**：连续 10 个采样点同帧，标称名义窗口 **$20\text{ ms}$**；
  - **$k = 25$ 档**：连续 25 个采样点同帧，标称名义窗口 **$50\text{ ms}$**；
  - **$k = 50$ 档**：连续 50 个采样点同帧，标称名义窗口 **$100\text{ ms}$**；
- **分类标准**：
  - **误触发（False Trigger, $T_{\text{false}}$）**：触发后该平台在当前窗内的最终物理持续时长未达到停滞门槛（$d < 100\text{ ms}$）；
  - **正确触发（Correct Trigger, $T_{\text{correct}}$）**：触发后该平台物理持续时长达到停滞门槛（$d \ge 100\text{ ms}$，对应停滞事件候选）；
  - **误触发率**：$T_{\text{false}} / T_{\text{total}}$；**漏触发率**：未被触发的真实事件数 / 真实事件母体样本数（$n = 1681$ 条）；**净收益（查准率）**：$T_{\text{correct}} / T_{\text{total}}$。

### 3. 假阳性物理机理与时序因果矛盾深度剖析
1. **$k=10$（20ms）高误触发成因**：
   红警 2 引擎在战术交火复杂场景下，正常逻辑渲染帧率常处于 $20 \sim 30\text{ FPS}$ 区间。在 30 FPS 下，单帧正常执行周期即达 $33.3\text{ ms}$（跨越 $16\sim 17$ 个 500Hz 采样拍）；在 20 FPS 下单帧耗时更达 $50.0\text{ ms}$。因此，$k=10$ 判据会将引擎正常的帧渲染推进**大规模误判为停滞**，导致 64 窗内累计产生 26,590 次误触发（平均每窗 442 次，折合每秒误触发约 17.7 次，误触发率高达 93.98%）；
2. **$k=50$（100ms）仍存在 162 处误触发成因**：
   连续 50 个采样拍并不等同于物理时长绝对达到 100ms。受局部紧凑采样与时钟抖动影响（例如抽验样本 `l3_1101v3a/w2:166-215`，50 拍物理时长仅为 97.26ms），部分平台游程达到 50 拍但物理时长不足 100ms 即恢复推进，构成 162 处假阳性（8.68%）；
3. **★ 核心时序因果矛盾**：
   D-29 明确要求「证明原始上下文在物理起点 $S$ 后 50ms 内实际保存」。
   - 若选择查准率较高（91.32%）的 $k=50$ 档，系统必须从起点 $S$ 起等待连续 50 拍（约 100ms）方能满足触发条件。触发动作发生的物理时刻已处于 $S + 100\text{ ms}$，**较 D-29 的 50ms 截止线滞后整整 50ms，在时间因果上无法满足「50ms 内保存现场」的要求**；
   - 能够在 $S + 50\text{ ms}$ 窗口内产生触发判决的仅有 $k=10$（时间余量约 30ms）与 $k=25$（时间余量约 0ms），但这两档在数据上呈现出严重的假阳性，误触发率分别高达 **93.98%** 与 **68.11%**。

### 4. 数据检验结论
- 在要求触发时刻必须早于 $S+50\text{ms}$ 截止线（采用 $k=10$ 或 $k=25$）的假设下，数据不支持「提前触发判据能保持低误触发率（实测误触发率高达 68.11%～93.98%，净收益仅 6.02%～31.89%）」；
- 在采用高查准率档位 $k=50$（误触发率降至 8.68%）的假设下，数据不支持「在因果时序上满足 D-29 关于在物理起点 $S$ 后 50ms 内完成现场保存的硬性约束」。

## Q4 配额与回退

### 1. 配额模型与实验视角
为防止误触发引发系统风暴，工程上通常限定单窗（每窗时长约 25 秒）内最多允许触发 $N$ 次。当窗口内累计触发达到 $N$ 次后配额耗尽，后续事件全部放弃。基于真实事件母体样本量 $n = 1681$ 条（分布于 $n = 26$ 个包含真实事件的战斗窗中），实测三档配额 $N \in \{1, 3, 5\}$：
- **视角 A（理想分类基准）**：假设存在理想的事前/事后筛选，配额完全不被正常波动的误触发浪费，仅由真实停滞事件按时序先后消耗；
- **视角 B（在线探测器实况）**：在线触发器无预知能力，前序短波动误触发按时序实时抢占并扣减配额。

### 3. 极端严重长停滞（$d > 500\text{ms}$，样本量 $n=3$）专项核查
在全量 1,681 条真实事件中，持续时间超过 500ms 的极端停滞共有 $n = 3$ 条（`_feasibility_probe_out.txt:152-158`）：
1. 样本 1：`l3_20261031hb/w1`，时长 519.87ms，起始采样点 `startTick = 6771`；
2. 样本 2：`l3_20261031hb/w2`，时长 531.31ms，起始采样点 `startTick = 1879`；
3. 样本 3：`l3_20261031hb/w2`，时长 566.96ms，起始采样点 `startTick = 2147`。

- **实测结果**：在理想配额与在线探测器的所有档位（$N = 1, 3, 5$）下，**全部 3 条大于 500ms 的极端停滞事件捕获数严格为 0 条（100% 被放弃）**；
- **物理成因追溯**：长停滞多发于战斗最激烈的窗口中，单窗内真实事件多达 $70 \sim 127$ 次。3 次极端长停均处于窗口时序中后段（采样点 1879、2147、6771 拍处）。在此之前，单窗配额 $N \le 5$ 早已被窗口前序几秒内的短停或正常波动消耗殆尽，导致最具危害的严重停滞在时序上必定落入配额耗尽区而被遗漏。

### 4. 捕获失败与配额耗尽的回退记录要求（规范定义，不设计实现）
依据 D-29 审查要求，当触发发生但由于配额耗尽、超时或系统异常导致捕获失败时，必须在轻量记录层沉淀最小追溯证据：
1. **必要记录字段集合**：
   - `timestamp`：触发时刻的高精度单调时钟时间戳（微秒/纳秒）；
   - `frame`：触发时的逻辑帧号 `CurrentFrame`；
   - `trigger_tier`：触发所依据的游程档位（$k=10/25/50$）；
   - `quota_used`：当前窗已消耗额度与配额上限状态；
   - `failure_reason`：失败原因枚举（如 `QUOTA_EXHAUSTED` / `BUFFER_FULL` / `TIMEOUT`）；
   - `post_event_duration_ms`：后台轻量时序流在事后检测到该平台最终恢复推进时的总持续时长；
2. **记录非阻塞要求**：上述记录必须通过固定容量的内存无锁环形缓冲区或后台异步队列落盘，严禁在主采样线程中执行同步阻塞式文件 I/O。

### 5. 数据检验结论
- 在设定单窗配额为 $N \in \{1, 3, 5\}$ 的假设下，数据不支持「保持对全量停滞事件的高覆盖捕获（在理想分类下覆盖率仅为 1.55%～6.96%，在线实况下仅为 0.24%～6.07%，且 3 条极端严重长停滞全部被遗漏放弃）」；
- 在配额耗尽导致现场捕获放弃的假设下，数据支持通过结构化轻量回退日志记录时序元数据与事后时长，以保障审计链完整性。

## Q5 扰动

### 1. 验证状态声明
- **当前状态**：**【未验】（UNVERIFIED）**；
- **未验成因**：既有语料为外部无侵入轻量采集数据流（仅包含时间戳序列 `samples.t` 与帧号序列 `samples.f`，全量采样点样本量 $n = 1125992$ 点），其中**未包含**任何运行时真实现场捕获动作（如调用 `SuspendThread` 挂起目标线程、遍历线程调用栈、执行内存镜像快照或 `MiniDumpWriteDump` 等侵入式 API）引入的微秒/毫秒级时延实测数据。依据铁律，严禁将离线估算标注为实测。

### 2. 判据计算理论上界估算与采样线程关系
在离线统计与系统机理视角下，对提前触发判据本身的理论开销边界定量核算如下：
1. **触发判据纯计算开销推导**：
   - 在既有 500 Hz 采样循环内部（标称采样周期 $T_s = 2.0\text{ ms} = 2,000,000\text{ ns}$），仅需在每次帧号读取后维护一个整数游程计数器；
   - 每次采样仅新增 1 次寄存器整型比较（`f[i] == f[i-1]`）、1 次条件分支与 1 次计数器自增。在现代 x86-64 处理器体系结构下，该序列耗时约在 $3 \sim 5$ 个 CPU 时钟周期（约 $1.0 \sim 1.5\text{ ns}$），占单次 2.0 ms 采样周期时间预算的比例低于 $0.0001\%$；
   - **内存访问与系统调用零增量**：判定逻辑复用采样线程已读入寄存器/本地缓存的 `CurrentFrame` 变量，无需新增任何跨进程内存读取（RPM）或内核态切换系统调用，其纯计算开销理论上界完全可忽略。
2. **触发频次与时序压力实测（推进窗全集样本量 $n = 64$ 窗，累计时长约 1,600 秒）**：
   - **$k = 10$ 档（20ms 触发）**：全集内累计触发 **28,294 次**，平均每窗触发 442.1 次，平均触发间隔仅为 56.5 ms，折合**平均每秒触发 17.68 次**；在激烈交火样本窗（如 `l3_20261031hb/w2`，采样点 $n = 12501$ 点）内单窗触发峰值达 812 次，瞬时触发频率高达 **32.5 次/秒**；
   - **$k = 25$ 档（50ms 触发）**：全集内累计触发 **5,343 次**，平均每窗触发 83.5 次，平均触发间隔为 299.4 ms，折合**平均每秒触发 3.34 次**；单窗瞬时峰值达 142 次；
   - **$k = 50$ 档（100ms 触发）**：全集内累计触发 **1,866 次**，平均每窗触发 29.2 次，平均触发间隔为 857.4 ms，折合**平均每秒触发 1.17 次**；单窗瞬时峰值达 47 次。

### 3. 实时扰动与对局现场破坏机理
若采用在时序上能够满足 50ms 保存窗口的 $k=10$ 或 $k=25$ 档位，在线监控系统将承受每秒 $3.3 \sim 17.7$ 次（峰值超 30 次）的高频触发。在此高频负荷下，现场快照机制将面临严重的现场破坏风险：
1. **线程挂起导致的级联卡顿**：
   Windows 下对游戏主逻辑线程执行 `SuspendThread` 属于异步内核注入机制（通过排队内核 APC 实现）。若现场抓取操作（栈回溯、寄存器上下文复制）单次耗时达到 $1 \sim 3\text{ ms}$，在每秒 17.7 次的触发频次下，游戏主线程每秒将被强制冻结累计 $17.7 \sim 53.1\text{ ms}$，直接导致对局发生非自然丢帧与卡顿；
2. **扰动正反馈滚雪球效应**：
   抓快照引发的人工微卡顿会进一步拉长当前帧的执行时间，进而诱发后续采样拍再次满足连续同帧判据，触发新一轮快照保存。这种正反馈扰动将彻底篡改被测红警引擎的原始现场，导致后续采集到的停滞事件失去物理真实性。

### 4. 验证扰动所需的实测数据依赖清单（Dependencies）
为完成 Q5 扰动的定量验证，必须在真实宿主机有载运行环境下实测获取以下 4 项核心指标数据：
1. **依赖项 1：现场快照 API 单次耗时分布实测**
   - 依赖指标：在目标游戏满负荷交火状态下，实测线程挂起、抓取调用栈及生成迷你转储的单次耗时分布（需给出样本量 $n$ 及 $P_{50}, P_{90}, P_{99}$ 分位数）；
   - 准入参考门槛：单次保存操作的 $P_{99}$ 耗时须严格低于 5.0 ms。
2. **依赖项 2：SuspendThread/ResumeThread 内核态往返时延实测**
   - 依赖指标：实测发出挂起指令至目标线程实际响应并停顿在安全点、以及恢复执行的完整往返延迟分布；
   - 准入参考门槛：往返累计开销均值须低于 500 μs，严禁引发目标线程锁竞争死锁。
3. **依赖项 3：高频写入下内存无锁环形缓冲区吞吐抗压实测**
   - 依赖指标：在 $k=10$ 档瞬时 30 次/秒的高频触发冲击下，实测内存无锁队列向后台工作线程分发快照任务时的吞吐瓶颈与丢包率；
   - 准入参考门槛：高并发快照请求丢包率严格为 0%，无内存持续泄漏与页面置换缺页抖动。
4. **依赖项 4：并发同步机制对 500 Hz 既有采样线程的调度抖动实测**
   - 依赖指标：实测配额原子计数器读写、状态机切换与快照唤醒事件对 500 Hz 采样循环微秒级调度周期的扰动（统计有效采样点样本量 $n > 100,000$ 的相邻间隔方差）；
   - 准入参考门槛：采样周期标准差增量须小于 50 μs，不导致既有 500 Hz 采样发生二次掉拍。

### 5. 数据检验结论
- 在缺乏运行时侵入式现场捕获实测耗时与内核调度时延数据的现状下，数据支持将提前触发机制的运行时扰动明确归类为「未验」；
- 在实测触发频次达到每秒 1.17～17.68 次（峰值超 30 次/秒）的假设下，数据支持「必须在实测获取上述 4 项运行时核心依赖指标后方可定量评估扰动可控性，未获实测数据前不支持无扰动假设」。
