## 2 · ②-b 相关：`0x43F180` 的最终语义（三条判据交叉验证）

`0x43F180` = `BuildingClass` 主表（`vt=0x7E3EBC`, col_off=0）**slot 73（`+0x124`）**。
全函数**只有 2 处 grid 操作调用**（穷举）。跳表 `0x43FB0C` 四项：`[0]→0x43F1CA`、`[1]→0x43F1E9`、`[2]→0x43F9A6`、`[3]→0x43F1E9`。

| mode 参数 | 跳表目标 | 可达指令数 | 能到摘链 `0x43F1D5`？ | 能到挂链 `0x43F691`？ | 语义 |
|---|---|---|---|---|---|
| **0** | `0x43F1CA` | 12 | **✅** | ❌ | **Limbo（摘链）** |
| **1** | `0x43F1E9` | 566 | ❌ | **✅** | **Unlimbo（挂链）** |
| **2** | `0x43F9A6` | 114 | ❌ | ❌ | `[未证]` |
| **3** | `0x43F1E9` | 566 | ❌ | **✅** | **同 mode 1** |

- 复验脚本：`lead\next_re_20261116_r12\_lead_audit\reverify_914.py`（穷举 + 可达性 BFS + 寄存器溯源三合一）。
- 挂链路径含：can-place `[+0x1AC]` 两处（`0x43F218`/`0x43F678`）+ **逐格校验** `call 0x47C620`。
- ⚠️ **`cmp ebp,3` @`0x43F658` 不是 mode 门控**（`ebp` 那时是循环计数）——这是 R12 最贵的一个错，别再犯。

| 包装 | 大小 | 内部 call | 语义 |

  **`0x47E8A0` 本身不校验占用**（占用检查在上层建筑 Unlimbo）。

## 3 · ③ DLC 相关：`BATTLEMD*.INI` 通配枚举机制

| 项 | 值 |
|---|---|
| 通配符字符串 | **`BATTLEMD*.INI` @ `0x008261A8`**、`RULEMD*.INI` @ `0x0082626C`，**各仅 1 处 xref** |
| 处理函数 | **`0x52CB90`**（BATTLE，473 B）、**`0x52CD70`**（RULE，1728 B） |
| API（pefile 验过 IAT） | `FindFirstFileA`=`0x7E1208`、`FindNextFileA`=`0x7E120C`、`FindClose`=`0x7E1300` |
| 属性过滤 | `test dword [..],0x116` ⇒ 跳过 `TEMPORARY\|DIRECTORY\|SYSTEM\|HIDDEN` |
| **合并顺序** | **`FindNextFileA` 返回序（文件系统序），无排序调用** ⇒ 不存在"98 必覆盖官方" |

**RULE 与 BATTLE 语义不同，不可类推**：RULE 多文件时**弹 DialogBox 让玩家选一个**、把 `RULESMD.INI` 插到数组第 0 位；
BATTLE 是**全部并入 + 到达序**。

**键冲突判据 = 战役名**（`fn 0x46CE10` 用 `_stricmp(obj+0x24, [Battles] 值)`），命中即复用同一对象。

**DLC 包操作规范**：放散装 `BATTLEMD<后缀>.INI`；只写新 id（15+）与新段，**不重定义官方键**；
**不要设为隐藏**（`0x116` 会过滤）；`.bak` 后缀天然安全（不匹配通配符）。

⚠️ 该路径**走文件系统、不查 MIX** ⇒ 机制层印证了 `docs/DESIGN.md:211` 的勘误（删散装件不会回退到 MIX）。

## 4 · ① 相关：可引用的定量事实

| 数字 | 值 | 限定语 |
|---|---|---|
| 每移动对象 CPU | **0.284 ± 0.029 ms/帧**（CV=0.101） | 单场景 120 s / 2361 样本。⚠️ **另一次测量给 0.91 ms（差 3 倍）** ⇒ **该比值不是常数，引用必须带场景**（台账 §917-6） |
| 相关性 | `r(cpu/帧, moving) = **+0.76**`；`r(cpu/帧, objects) = **−0.55**` | 同上；`r(moving,objects)=−0.63` 保证分离有效 |
| 拟合 | `cpu/帧 ≈ 0.2442 × moving + 0.4981`，RMSE 0.36 ms | n=12 窗 |
| 节流除数 | **`[[0x8871E0]+0x1808] = 16`**（局内稳定；菜单期为 0） | ⚠️ **只门控 `[0x4DA56E,0x4DA63B)` 那 60 条（应答/声音）**；**locomotion 每帧都跑**（§916）。**不要再写"单次 4.54 ms"** |
| 固定开销 | ≈ 1.9K 指令/对象/tick（1500 对象 ≈ 5.7 ms）⇒ **不主导** | W164 |

**禁止**：`0.65 ms/发` 当真实每发成本、"子弹驱动帧时间"、`r=0.921`、`r(目标搜索/帧)=0.442`。

**注意两段式**：0 弹时 CPU 只占墙钟 **20%** ⇒ 32 ms 满帧是**帧限速地板**；
CPU 越过地板后墙钟才跟随 CPU。

**调大 N 不降成本**（平均值 = 单次/N，同比例变化）——它只是把成本集中到更少帧，**尖峰可能更糟**。

### 4.1 【§919 已判定】① 的整改可行性 —— 能做什么、不能做什么

| 方案 | 可行 | 依据 |
|---|---|---|
| **减少屏幕上同时绘制的精灵数/面积** | **✅ 唯一直接有效** | `BuildingClass::Draw`（`0x43D290`，621 指令）**内部无视口裁剪、无矩形相交、无脏区跳过** |
| **让对象"不在格中"或"进 Limbo"** | **✅ 能直接减少绘制** | slot 65（`+0x104`）入口在调 Draw 前做三重剔除：`[+0x80] && [+0x74] && ![+0x81]`；不过则直接返回 al=0（台账 §920） |
| 靠引擎自身的脏区跳过 | **❌ 这个机制不存在** | 同上。前向跳全是"某返回值==0"类判据，没有"此区域未变则跳过" |
| 减少同时移动的对象数 | ⚠️ 只是**间接**（影响"画面变化"的感知） | 不改变"每对象每帧都画"这个事实 |
| 调大 N=16 | **❌ 与绘制无关** | N 只门控应答/声音那 60 条（§916） |

- **blitter 是启动时缓存的单例**：工厂 `0x48EBF0`（6145 B / 1700 指令 / 227 跳转）**只有 5 个调用者**
  ⇒ §918 的 61.9% 是执行 `Blit()`（各 blitter 类 **slot 1**），不是构造。
- 引擎屏幕坐标是**浮点**，每次绘制都要付一次 `_ftol`（`0x7C5F00`，**1974 个调用者**，EIP 3.2%）。
- **绘制管线是两段式**（台账 §920-8）：slot 65(`+0x104`) 剔除 → `call [+0x114]` Draw 本体 → `call [+0x4E4]` 绘制后半。
  绕过剔除的 slot 70(`+0x118`，21 B 裸转发器) **全镜像只有 1 个调用点** ⇒ 剔除有效，无大面积绕过。
- ⚠️ **不得写"引擎每帧全量重绘"**。准确说法：**每个处于世界中的对象每帧都完整绘制一次；
  引擎只按对象状态剔除，不按屏幕区域剔除。**
- `[未证]`：`[+0x80]` 的精确语义（179 写点只抽样 6 个）；`0x705E00` 的 68 个前向跳只看了 8 个；
  绘制列表的收集/排序阶段是否有第三层过滤（台账 §920-7）
  （即"调用 Draw 之前是否已排除不可见对象"）。

## 6 · 纪律清单（每条都是实际翻车换来的）

1. **双通道必须至少有一条不依赖 `function_atlas.tsv` 的 `entry+size`** —— Ghidra 对无人引用区不建函数，
   两条通道都依赖 atlas 边界会**一起漏**（HeapFree 真值 4 处、W156 两通道都报 3）。
2. **capstone 必须 `skipdata=True`** —— 默认遇不可解码字节**静默停止**，4 MB `.text` 只解出 15 万条（真值 139 万）。
3. **capstone 默认 `skipdata=False` 时，`boundary_check` 的 `max_bytes` 超限必须返回 `unknown`，不能返回 `False`** ——
   否则"我不知道"会被当成"它不是"（`0x617641`/`0x61CC5C` 就是这样被误判成假阳性的）。
4. **凡寄存器语义判断，必须回溯该寄存器的全部写入点** —— 只看"此处比较了某个常量"不够（`0x43F658 cmp ebp,3` 的教训）。
5. **凡"某分支什么都不做"的结论，必须把该分支从入口到 `ret` 的指令逐条打完** ——
   **输出被 `...` 截断 ≠ 代码不存在**（`0x43F1D5 call 0x5687F0` 的教训）。
6. **任何"这是栈参数"的判断，必须给出该函数 `[esp+N]` 的取值集合与最大值**，并证明它 ≥ 参数区起点
   （我把 `[esp+0x10]` 当栈参数，导致整个"每 tick 派发"结论反了）。
7. **凡穷举性结论双通道；任何字节命中先验指令边界**；不用"最大函数=热点""无调用者=死代码"。
8. **不要相信"距目标最近的 E8/E9 目标"这类入口启发式**判断构造/析构（§675 就是这么错的）。
9. **写"新发现"前先 grep 主台账**；结论只用 `[已证]`/`[静态推断]`/`[未证]` 三级。
10. **不改** `gamemd.exe`/`ddraw.dll`/`ra2youli\` 下任何文件；**真机需用户当轮明示授权**；不擅自 git commit/push。
11. **凡"某门控覆盖 X"的结论，必须给出该门控向下一条分支的跳转目标，并证明 X 在目标之后/之前。**
    只证明"门控存在且值为 N"是不够的（`frame % 16` 只跳过 60 条，我却外推成"整个移动段每 16 帧一次"，错了 3 轮）。
12. **派卡时给的"候选假设"必须标明是猜测。** W170 实测证明我猜的"mode 2 = 传送/换外观"、
    "`0x7014A0` = 重定位"**都错了**（真相：mode 2 = 附属子对象状态刷新；`0x7014A0` = `TechnoClass::SetOwner`）。
13. **EIP 权重 ≠ 调用频率。** 一段代码占 21.6% 的 EIP 样本，可能只是"少量调用 + 长循环"。
    要断言"每帧每对象调用一次"，必须另有调用计数证据（台账 §918-7 已标注该 `[未证]`）。
14. **凡 thiscall（`ecx` 传 this）函数的语义判断，必须回溯 `ecx` 的赋值来源。**
    我曾据 `[esi+0x44]`/`[esi+0x11E]` 把 `0x485020` 推成"对象造价"，实际每个调用点都先
    `call 0x5657A0` 取格、`ecx` 是 **`CellClass*`** ⇒ 真相是"每格算矿石价值"（台账 §923）。
    与 `cmp ebp,3` 那次同类：**只读指令序列、不追操作数来源**。
15. **凡"某功能不存在"的结论，必须检查它的调用链上下各一层。**
    我只看 `Draw`（`0x43D290`）本体就写"引擎不做视口裁剪"，实际裁剪在**调用它的 slot 65 包装**
    `0x43CEA0` 里（对象 rect + 滚动原点 `0x886FA0`/`0x886FA4` vs 视口 rect，4 次边界比较）——台账 §924。
16. **读反汇编时，写值必须逐字符核对，不能凭印象。**
    我曾把 `0x6D98EF mov byte [esi+0x80], 0` 记成"置 1"，据此推出"每帧无条件置位"的错误结论（台账 §925-2 已更正）。
17. **不要用 `entry_at_or_before` 判断站点归属，要用「函数区间包含」判定。**
    `entry_at_or_before` 在 atlas 空洞处会返回**更早的**函数，把站点错归。
    实测：`0x482854` 等 5 处曾被错归到 `fn 0x481A00`（size 1169，止于 `0x481E91`，根本不可能包含）。
    **`0x482000..0x483400` 整段 atlas 无函数**，真实入口 `0x4824D4` 只能靠「全 .text 扫 call/jmp rel32 目标」找到（台账 §926-1）。
    实测错归率：10 个抽样站点里 **5 个不一致**（全部被错归到 `fn 0x481A00`）。
18. **凡"不存在 X"的判断，除了查调用链上下层，还要查「X 的等价形式」。**
    我两次栽在同一处：先否"无裁剪"（实际有矩形裁剪，§924-1），又否"无位置过滤"
    （实际有**距离阈值** `[0x8871E0+0x172C]`，§926-5）。**"没找到我期待的形式" ≠ "功能不存在"。**
19. **扫"某全局被谁写"时，必须同时看「绝对寻址」与「立即数加载基址 + `[reg+off]`」两种形式。**
    只扫 `[0x8A0394]` 会得出"0 处写入"，而实际访问全是 `mov ecx,<base>` 后 `[ecx+off]`（台账 §928-1）。
    另注：`mov eax,[glob]` 的内存操作数在 **op1**，只检查 op0 会全部漏掉（我在同一处踩了两次）。
