# W171 · DISAGREE

> 格式：**我预期 X，实测 Y，因此 X 错。** 只列有字节/穷举证据的。

## D1 · `[loco+0x54]`/`[loco+0x5F]` 门 ⇒ "跳过寻路"（派发提示词 + R12_FACTS §16.2 + W164 Q1.3）

- **预期**：`Drive 0x4B0500` 在 `0x4B055A`/`0x4B056A` 判 `[loco+0x54]==-1` 或 `byte[loco+0x5F]==0` ⇒ **跳过寻路**。
- **实测**：两门都跳到 **`0x4B066C`**，而 `0x4B066C` **不是 `ret`**；它继续走到 **`0x4B0A79 call 0x4B2630`（大 Process，含 3 个寻路站点）**。
  边删除可达性：强迫两门"跳"后仍可达 `0x4B0A79`（403 条指令）；强迫两门"不跳"则只可达 `0x4B0647`（216 条）。
  ⇒ 门控决定的是**走哪条 Process 入口**，不是"是否寻路"。
- **因此**：派发提示词的"跳过寻路（§904，字节级已证）"作为**结论**不成立；字节本身没错（`0x4B0564 je 0x4B066C` 是真的），
  错在**把 `0x4B066C` 当成了轻量出口**。W164 当年也标注了 `[静态推断]…未逐字节追踪到 0x4B066C 之后是否立即 ret`，本卡补上了这一段。
- 证据：`EVIDENCE\S3b_pathAB_prelude.txt` 前 5 行；`EVIDENCE\S3_gates.txt` PART 1。

## D2 · 「`FootClass::AI` 的后半段（含移动/寻路）只在 `frame % N == 0` 时执行」（R12_FACTS §18.1 / 台账 §909-3 ⇒ 4.54 ms 的来源）

- **预期**：`0x4DA568 jne 0x4DA63B` ⇒ 不整除时"整段跳过"，移动/寻路每 16 帧才跑一次，单次 ≈ 0.284×16 = 4.54 ms。
- **实测**：不整除时**仍有 662 条指令可达**（整除时 722 条）；**只有 60 条**（`0x4DA56E..0x4DA639`）被跳过，
  而这 60 条做的是"取 cell → `MapClass::GetCell` → `fild/fmul [0x8871E0+0x1818]` → `call 0x7C5F00` → `call [vptr+0x16C]`"，
  形态是**概率触发的应答/声音块**。
  而 locomotion 的每帧 Process 派发 **`0x4DA877 call [ecx+0x40]`（→ `Drive::Process 0x4B0500`）在 `0x4DA63B` 之后**，
  `FootClass::AI` 里 13 处 `[esi+0x674]`（loco 指针）读取**全部**在"不整除也执行"的集合里。
  `FootClass::AI` 的另 3 个 frame-modulo 节流（`0x4DA90E`/`0x4DA989`/`0x4DA560`）**都不是** `0x4DA877` 的支配条件。
- **因此**：「4.54 ms 单次执行」这个推导**不成立**——被 ×16 的是 60 条指令，移动/寻路是**每帧**执行。
  `0.284 ms` 应当直接读作**每移动对象每帧**，而不是"每 16 帧一次、单次 4.54 ms"。
- 证据：`EVIDENCE\S15_throttle_proof.txt`（§A/§B/§E 逐条）；`EVIDENCE\S14_throttle_scope.txt`（§2/§3/§7）；`EVIDENCE\S18_loco_dispatch_gates.txt`。

## D3 · `PathFinder::FindPath 0x42C900` = **1563 指令 / 67 call**（W164 `LOCOMOTION_COST.md` Q2 表）

- **预期（W164）**：`0x42C900` = 1563 指令 / 67 call。
- **实测**：`function_atlas.tsv` 行 `0042c900  974  327`（size=974 B，**n_instr=327**，n_callees=10）；
  本卡 CFG 通道 = **327**；线性扫 974 B = **327**。三通道一致。
  ⇒ **1563 不可能**：974 字节装不下 1563 条 x86 指令（<1 字节/条）。
  W164 那一格大概率是把别的函数的数字抄到了这一行（它的 `0x4B2630=2600`、`0x4D3920=669`、`0x4CBBA0=58` 都与本卡一致）。
- **影响**：不影响 W164 的定性结论（寻路链存在、SearchCore 544/轮），但**它 Q2 表里的 FindPath 一行是错的**，
  引用时以本卡为准。
- 证据：`EVIDENCE\S13_globals_dualchannel.txt` 末节 `(c)`；`EVIDENCE\S2_pathchain.txt` §A/§G。

## D4 · 「格/占位表更新 = `0x47E8A0`/`0x47EA90`（移动更新第 ③ 步）」（派发提示词的 Q1 ③ 假设）

- **预期**：一次移动更新会调 `0x47E8A0`（挂链）/`0x47EA90`（摘链）。
- **实测**：这两个函数（以及包装 `0x5683C0`/`0x5687F0`、逐格校验 `0x47C620`）
  从 `0x4B0500` 出发**深度 ≤8 全不可达**（探针深度 0..8，累计 940 个函数）。
  真正的到达路径是**虚槽 73**（`call [vptr+0x124]`）：`0x4D3920` 在 `0x4D3E11`（mode 0 = Limbo/摘链）与 `0x4D3EAC`（再挂）各调一次，
  `Unit/Infantry/Aircraft` 的槽 73 = `0x4D3780`，其内部 `0x5683C0→0x47E8A0`@`0x5684BB`、`0x5687F0→0x47EA90`@`0x5688EB`。
- **因此**：③ 确实存在（静态量 879 指令），但**不在静态调用图里**——凡"按调用图闭包统计格表成本"的做法都会把它算成 0。
  这是 R12_FACTS §6.2「双通道必须有一条不依赖 atlas」之外的一条新坑：**虚槽必须单独补**。
- 证据：`EVIDENCE\S8_callees_depth.txt` §3；`EVIDENCE\S10_slot73_chain.txt` §4/§6。

## D5 · `0xFFF7`(65527) 可作为"单次寻路的轮数上限"

- **预期（R13_COMMON 引用 §562/§563）**：轮数上限 65527。
- **实测**：`0x429D59 c7442470f7ff0000` 前面有 `0x429D51 mov eax,[esp+0x70]` / `0x429D55 test eax,eax` / **`0x429D57 jge 0x429D61`**
  ⇒ **`0xFFF7` 只在 `[esp+0x70] < 0` 时作为缺省写入**；`>=0` 时**保留参数值**。
  循环上界读的正是该槽（`0x429D71 cmp eax,ecx` / `0x429D79 jge`）。
  另有 `0x42A3E2 cmp ecx,0x2710`（10000）作为**收尾**判据。
- **因此**：「轮数上限 = 65527」作为无条件上限不成立，它是**缺省值**；有效上界取决于调用方传的参数（`[未证]`，见 UNKNOWNS A1）。
  台账 §566(a) 已记 `0x2710`；本卡**独立复核**该常量，并补上"`0xFFF7` 是条件缺省"这一层。
- 证据：`EVIDENCE\S7_argcount_closure.txt` §a3/a4；`EVIDENCE\S6_budget.txt` §2。
