# E1b 决定性发现：那个「弹窗」是 Windows 崩溃对话框，且崩溃地址在 .data

- 日期：2026-10-20 17:48
- 趟：`QC161-U0800-L1-E1b`（载体 carrierfix 修复后，**88/88 件齐全**）

## 一、弹窗真身（推翻此前全部判读）

`frame_early_01.png`（t=0.719s 抓帧，灰底占比 **15.2%**）实读内容：

```
┌─────────────────────────────────────────────────────┐
│ [红X] Red Alert 2                              [×]  │
├─────────────────────────────────────────────────────┤
│                  gamemd.exe - 错误应用程序           │
│                                                     │
│  gamemd.exe                                         │
│                                                     │
│                    确定      [ 关闭程序 ]            │
└─────────────────────────────────────────────────────┘

0x0084f2ba 指令引用了 0x0084f2ba 内存。该内存不能为 written。
要终止程序，请单击“确定”。
```

**这是 Windows 的应用程序错误对话框（Windows Error Reporting 前端），不是：**
- ❌ csf 语言表初始化失败框（工作流的判定）
- ❌ 游戏完整性检查弹窗（台账 §304）
- ❌ 释放磁盘空间提示（台账 §306）
- ❌ 任何 RA2 引擎自绘对话框

窗口标题 `Red Alert 2` = 崩溃进程的窗口标题（Windows 取进程主窗标题）。

## 二、崩溃地址分析

| 项 | 值 |
|:--|:--|
| 崩溃 VA | `0x0084F2BA` |
| 所在段 | **`.data`**（`0x00812000`–`0x00B79BE4`，vsize `0x367BE4`） |
| file_off | `0x44F2BA` |
| 该处内容 | `dd 3d c3 9c de 3d 7d 2c e0 3d 2e bc e1 3d d6 4b e3 3d ...` |
| 内容性质 | **小端 float 序列**（≈0.108, 0.1087, 0.1094, 0.1101, 0.1107, 0.1114…），等差浮点查表 |
| 访问类型 | **written**（写入被拒） |

**关键推论**：`.data` 段本该可写。程序试图写一个**浮点常量表**且被拒，说明：
1. 代码把某个「常量表」当成了「输出缓冲区」的地址 —— **地址计算错误 / 越界写**；或
2. 该页的保护位被改成只读（`PAGE_READONLY`）—— 排除，无此代码路径；
3. 写指针来自**已损坏的数据结构**（堆腐化后指针跑到 `.data` 里）。

第 3 条与 ② 目标的 RC-1（SBH freelist 毒值）假设**形态一致**：腐化指针解引用/写入。

## 四、为什么 `except.txt` 没记录

`except.txt` 是 **RA2 引擎自己的**异常处理器写的。Windows 崩溃对话框（WER）接管时，
进程直接终止，引擎的 SEH 处理器**没机会**写文件。

⇒ **不能再用「except 零新增」作为「非崩溃」的证据**。此前多轮把「except 无新增」
当作「干净退出」的判据，在本案**是错的**。

## 六、下一步（E3 已部分完成）

原来的 E3 是「抓退出码 + procdump 转储」。现在**崩溃地址已经直接拿到**（`0x0084F2BA`），
比抓退出码信息量大得多。

待做：
1. **定位 `0x0084F2BA` 的写入方**：反汇编 `.text` 找所有可能算出该地址的 `mov [reg+disp], ...`。
   但它是 `.data` 里的浮点表，正常代码不会写它 ⇒ 更可能是**腐化指针**命中。
2. **启用 `procdump -e -ma` 抓崩溃瞬间转储**：转储里的调用栈能直接指认写者。
3. **用 SBH 守卫做 A/B**：若 RC-1 守卫能拦下这个崩溃，则根因确认为堆腐化。
   —— 这正是 Notion 裁决3 说的「桌面单测过后 #4 可从单臂升级为两臂对拍」。
