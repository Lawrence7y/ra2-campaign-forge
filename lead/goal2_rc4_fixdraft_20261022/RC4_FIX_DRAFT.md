## 0. 一句话

在 `0x724730` 函数头插入 **4 字节 null 守卫**，`ecx==0` 时跳到**现成的安全出口** `0x7248A9`。
一次覆盖全部 **30 个调用者**（含 24 个无守卫入口）。

**已证实安全**：全部 30 个调用点都不读取返回值（§358）。

## 1. 现状（字节级）

```
0x724730  83 ec 0c              sub  esp, 0xc
0x724733  55                    push ebp
0x724734  8b e9                 mov  ebp, ecx        ← this
0x724736  56                    push esi
0x724737  8b 85 50 02 00 00     mov  eax, [ebp+0x250]  ← ★ 崩溃点（ebp=0 时 AV，Access=0x250）
0x72473D  8d b5 4c 02 00 00     lea  esi, [ebp+0x24c]
0x724743  85 c0                 test eax, eax
0x724745  0f 84 5e 01 00 00     je   0x7248A9
```

现成安全出口：
```
0x7248A9  5e                    pop  esi
0x7248AA  5d                    pop  ebp
0x7248AB  83 c4 0c              add  esp, 0xc
0x7248AE  c2 04 00              ret  4
```

⇒ `0x7248A9` 的栈平衡与函数头 `sub esp,0xc; push ebp; push esi` **完全对应**。
⇒ 只要在 `push esi` 之后插入守卫，跳到这里即可。

## 2. 修复方案 A（推荐）

### 2.1 补丁字节

在 `0x724738`（`push esi` 之后、`mov eax,[ebp+0x250]` 之前）插入 4 字节：

```asm
0x724738  85 c9                 test ecx, ecx
0x72473A  74 6d                 je   0x7248A9        ; +0x6D → 0x7248A9
```

**相对偏移计算**：
- `je rel8` 的位移是「目标 − (跳转指令结束地址)」
- 跳转指令在 `0x72473A`，长度 2 ⇒ 结束地址 `0x72473C`
- 目标 `0x7248A9` − `0x72473C` = `0x16D` = 365
- **365 > 127 ⇒ rel8 放不下，必须用 near jump（6 字节）**

### 2.2 改用 6 字节 near jump

```asm
0x724738  85 c9                 test ecx, ecx          ; 2 字节
0x72473A  0f 84 69 01 00 00     je   0x7248A9          ; 6 字节（rel32）
```

- 跳转指令 `0x72473A`，长度 6 ⇒ 结束地址 `0x724740`
- 目标 `0x7248A9` − `0x724740` = `0x169` = 361 = `0x00000169`
- 字节序：`69 01 00 00`

**合计 8 字节**。这 8 字节要**插入**（不是覆盖），因为原指令必须保留。

### 2.3 插入 vs 覆盖

`0x724738` 起是 `mov eax,[ebp+0x250]`（6 字节）+ `lea esi,[ebp+0x24c]`（6 字节）+ `test eax,eax`（2 字节）...

**不能原地覆盖**（会破坏原逻辑）。必须：
1. 把 `0x724738` 之后的代码整体后移 8 字节；或
2. 在文件末尾/cave 区放 trampoline，函数头改成 `jmp cave`，cave 里执行守卫 + 原指令 + `jmp` 回 `0x724738`。

**方案 A2（trampoline，推荐）**：

```asm
; 原 0x724730 处改写（前 5 字节）
0x724730  e9 <rel32>            jmp  <cave>            ; 5 字节，覆盖 sub esp,0xc; push ebp
0x724735  ...                   ; 剩余字节需 nop 填充（原 0x724730..0x724734 共 5 字节）

; cave 中（需找可写可执行空间，或用 .detour 段）
cave:
          sub  esp, 0xc                                ; 原指令
          push ebp                                     ; 原指令
          test ecx, ecx                                ; ★ 守卫
          jz   .null_ecx
          mov  ebp, ecx                                ; 原指令
          push esi                                     ; 原指令
          jmp  0x724737                                ; 回到崩溃点之前... 
```

⚠️ **等等**：`jmp 0x724737` 会回到崩溃点本身。正确做法是回到 `0x724737` 之后的逻辑，
但 `0x724737` 是崩溃点（`mov eax,[ebp+0x250]`），守卫通过后它就该执行。

所以 trampoline 应该是：

```asm
cave:
          sub  esp, 0xc
          push ebp
          test ecx, ecx
          jz   .null_ecx
          mov  ebp, ecx
          push esi
          jmp  0x724737            ; 回到 mov eax,[ebp+0x250]，此时 ebp != 0 ⇒ 安全
.null_ecx:
          add  esp, 0xc            ; 撤销 sub esp,0xc
          xor  eax, eax
          ret  4                   ; ★ 直接返回（调用方都不读返回值，§358）
```

**cave 长度**：约 8+4+2+2+3+5 = 24 字节。

### 2.4 cave 放在哪

现有 `.detour` 段（`0x00B93000`，vsize `0x2718`）是项目既有的补丁区。
需查该段剩余空间。若不够，需扩展段或找代码洞。

**这一步需要实际检查 `.detour` 段占用情况**——本轮未做，列为待办。

## 3. 方案 B（保守，只改 24 个无守卫调用点）

在每个无守卫 `call 0x724730` 之前插入：
```asm
test ecx, ecx
jz   .skip
call 0x724730
.skip:
```

**缺点**：
- 24 处 × 8 字节 = 192 字节，改动面大
- 每处都要保证跳过后的栈平衡（`call 0x724730` 是 `ret 4`，调用方 push 了 1 个参数）
- 24 处分别验证，易漏

**优点**：不需要找 cave，可在原地覆盖（因为 `jz` 的目标就在附近，rel8 够用）。

## 4. 两个方案对比

| 维度 | A（函数头 trampoline） | B（24 个调用点） |
|:--|:--|:--|
| 改动点数 | 1（+ cave） | 24 |
| 字节数 | ~24（cave）+ 5（头） | ~192 |
| 需要 cave | **是** | 否 |
| 覆盖完整性 | **全部 30 个**（含 6 个已守卫的，冗余但无害） | 只 24 个 |
| 验证难度 | 低（一处逻辑） | 高（24 处） |
| 风险 | cave 空间/段属性 | 24 处栈平衡 |

**推荐 A**，前提是 `.detour` 段有 ≥32 字节空闲。
