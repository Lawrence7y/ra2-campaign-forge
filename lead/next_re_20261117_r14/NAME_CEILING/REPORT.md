## 0. 一句话结论

22 个子系统里，**8 个**的 `named_S(R14)` 天花板已经够 `ceil(0.9n)`（S08、S10、S11、S13、S15、S16、S17、S20），**14 个够不到**。全表的"名字可解"供给总量小到可以一眼看完：**L1 = 0 行，L2 = 29 行（严格）/ 54 行（宽松）**。最优子系统是 **S10（天花板 513，门槛 474，余 +39）**；最接近却仍够不到的是 **S21（91 vs 117，差 26）**。

⇒ 卡片预期的"没有任何子系统能到 `ceil(0.9n)`"**不成立**。但"**22 个子系统全部达到 DoD 在数学上不可达**"**仍然成立**——支撑它的是两个门槛取交集，不是"名字对所有线都不够"（见 §6）。

## 1. 口径（逐条照卡片，未改动）

- 样本集合 = `coverage.tsv` 中 `entry` 落在 `function_atlas.tsv` 内的行。**entry 大小写归一后比对**（atlas 用小写十六进制）。
- `n` = 该子系统的行数；`A_named` = name 非空 ∧ 不以 `sub_` 开头 ∧ 不匹配 `::sub_`；`B_substyle` = 匹配 `^(sub_|.*::sub_)`；`C_slotstyle` = `A_named` 中形如 `::slotN` / `::vslotN` 的子集；`D_empty` = name 为空。
- 恒等式 `A + B + D = n` 在脚本内逐子系统 `assert` 通过；`C ⊆ A` 同样断言。
- `named_S(R14)` 现值 = `A_named`（含 `C_slotstyle`），与 `PANEL` / `R14_COMMON` §783 的 DoD 判定口径一致。
- `ceiling_off = A_named + L1 + L2`；`ceiling_on = A_named + (L1 + L2 中不是 slotN 形态的)`；`thr_named = ceil(0.9n)`；`reachable = ceiling_off >= thr_named`。
- **L1/L2 是"可解"判定，不是"已解"**。本报告所有 `ceiling_*` 一律读作"可解上限"，不得写成"已具名"。

## 4. 三问结论

### 问 1：有几个子系统的天花板够 `ceil(0.9n)`？

**8 个**。按余量降序：

|---|---:|---:|---:|
| **S10** | 513 | 474 | **+39** ← 最优 |
| S20 | 399 | 369 | +30 |
| S11 | 358 | 332 | +26 |

| S08 | 20 | 20 | +0（零余量） |
| S13 | 216 | 216 | +0（零余量） |
| S16 | 81 | 81 | +0（零余量） |

注意 **S08 / S13 / S16 是零余量**：任一行被降名或回退 `sub_` 即跌破（`R14_COMMON` §1247 已就 S13 提示过同一风险）。这 8 个的"够"完全来自 `A_named` 现值，**没有一行是 L1/L2 贡献的**（L2 只落在 S03/S05/S06/S07/S12）。

### 问 2：有几个即使全部可解也够不到门槛？差多少？

**14 个**，差 26 至 2,607 行：

卡片点名的 **S04 复核一致**：`A_named = 104`、门槛 `285`、差 `181`，73 个 ③b② 命中全部无名。

**关键量级对比**：名字通道的**全部**剩余供给（L1 0 + L2 29）不到任何缺口的 1/26。缺口最小的 S21 差 26，而 S21 自身 L2 = 0、L1 = 0——不是"再多扫一点"，而是**该子系统在表内与镜像里都没有名字来源**。

### 问 3：22 个全达标的不可达性

第 2 问的名单**没有**覆盖全部 22 个（8 个已够），所以卡片 §3 的触发条件不成立，不能照抄那句判词。**但"22 个全部达到 DoD 不可达"依然成立**，论据改成两门槛取交集：

- DoD 需 `named_S(R14) ≥ ceil(0.9n)` **且** `proved ≥ ceil(0.5n)`。
- 名字侧先出局 **14 个**（本卡实测）。
- 余下 8 个里，按 `SURVEY_3B2\survey.tsv` 现成口径 `can_close = True` 的只有 **S04、S15、S16、S17**（S04 名字已出局）。取交集只剩 **S15、S16、S17** 三个。
- 所以 DoD 的子系统数上限是 **3 / 22**，不是 22。`R14_COMMON` §1009 记"S17 达标"与此方向一致。

**三个最硬的数字**（供裁决引用）：

1. **最优子系统的名字天花板 = 513 = S10，门槛 474，余 +39** —— "名字够门槛"确实可能，所以**不能**用"名字对所有线都不够"来论证不可达。
2. **可闭 proved 且名字够的子系统的交集 = 3 个（S15 / S16 / S17）** —— 这是 DoD 的真实上限。
3. **14 个子系统的名字缺口下界合计 = 4,500 行，而全表可解名字供给 = 29 行** —— 差两个数量级。

## 5. L1 = 0 的证据链（本卡最重要的否证结果）

卡片假设"命名线索很可能就在 `strings` 列"。**实测不是。**

- atlas 12,916 行中只有 **1,019 行** `n_strings > 0`；其中落在 B 类（未具名）的 **593 行**。
- 按 L1 定义的两种形态逐表扫描 `strings` 列：
  - RTTI 类型描述符 `. ?AV` / `.?AU`：**0 行**（全表 0 次出现）；
  - 限定方法名 `Foo::Bar`：**0 行**（全表 0 次出现 `::`）；
  - 唯一的 `@@` 命中是 `005C1A10` 的普通文案 `Sending observer slot of 8 | @@@ Looking for %s`，**不是 RTTI**。
- B 类里 201 行含**断言源文件名**（`D:\ra2mdpost\Session.CPP`、`wonline.cpp`、`GDlgSupp.cpp` …，共 53 个不同文件）。这是**翻译单元级**线索：只能说明该函数属于哪个 `.cpp`，定不出方法名。按卡片纪律"拿不准记 L3" ⇒ 全部记 **L3**。
- 另有 9 行 strings 里出现 RTTI 类基本名（`Surface`、`Battle`、`Width` …），但全是通用词巧合命中，同样记 L3。

`ceiling.py` 草稿阶段曾用点分正则（`Egos.CPP` 之类）误收 209 行，已删除该规则——文件名不是限定名。

`L1 = 0` 是**对本卡的关键否证**：不存在"表内拉一下 strings 就多出一批名字"的机会。

## 6. L2 口径、自证与样本

### 6.1 方法（表 + 镜像结构，未做全镜像反汇编）

复用 `W130_atlas\vtables_rebuilt.tsv`（MSVC 标准 RTTI 布局：`vt[-1] = COL`，`COL+0x0C = pTD`，`TD+0x08 = .?AVClass@@`），从 `.rdata/.data` 读虚表槽 dword，落在 `.text = [0x401000, 0x7E038D)` 的即为槽函数。

**严格判定**（刻意比盘上既有命名更窄）：`primary == 1`（`COL.col_offset == 0`）∧ `bad_kind == 'next-col'`（表在下一个合法 COL 前结束＝run 覆盖完整）∧ RTTI 名可解码 ∧ 槽值在 `.text` ∧ **该函数在全表中只被一个 (虚表, 槽号) 指认**（多指认＝归属不唯一 ⇒ L3）。

结果：严格 `L2 = 29` 行（另 9 行因归属不唯一改记 L3）；宽松口径（接受全部 1,219 张虚表）`L2 = 54` 行（另 10 行不唯一）。

### 6.2 自证：与盘上既有 `::slotN` 名比对

比对分母 = 全库 6,241 条 `::slotN`/`::vslotN` 命名（其中 5,831 条落在 atlas 内，即 `C_slotstyle`）。

| 口径 | 槽内唯一函数 | 既有 slotN 名落在图内 | 类名一致 | 类名+槽号一致 |
|---|---:|---:|---:|---:|
| 严格 | 4,255 | 4,005 | 1,137 | **1,137** |
| 宽松 | 6,256 | 5,820 | 2,791 | **2,791** |

- **槽号零冲突**：两种口径下"类名一致但槽号不一致"的样本数都是 **0**。类名不一致的差额全部是模板名被清洗（`?$VectorClass@USubzoneConnectionStruct@@` → `?$VectorClass::USubzoneConne`），属命名风格差异，不是事实冲突。
- 严格口径只复现 1,137/5,831，说明它比盘上既有通行做法**窄得多** ⇒ 严格 L2 = 29 **是下界**，符合卡片"保守下界"要求。
- 宽松口径 `in_map` 5,820 ≈ 既有 5,831 ⇒ **虚表通道已被前序工作榨干**，剩余可归因的槽函数就是几十行，不是几千行。

## 7. 稳健性（`sensitivity.tsv`）

结论对 L1/L2 的解释口径不敏感：

| 口径 | 说明 | 够门槛数 |
|---|---|---:|
| **严格（本卡采用）** | L1 = 0；L2 = primary ∧ next-col ∧ 归属唯一 = 29 | **8** |
| 宽松 L2 | 接受全部 1,219 张虚表 = 54 | 8（同一批） |
| "有串即可解"（荒谬上界） | 593 行只要有 strings 就算可解 | 10（多出 S18、S21） |

即：**即便把"函数里出现过任意字符串"这种根本站不住的判据算作可解，也只有 10 个，仍有 12 个够不到**。反向也不动：8 个够门槛的全靠 `A_named` 现值，L1/L2 一格都没贡献。

另附一条口径敏感性（决定 DoD 另一条腿的观感）：若 `D-38` 改判为**排除** `slotN`（`named_pct_S(strict)`），则全表非 slot 真名只剩 7,203 − 5,831 = **1,372 / 12,916 = 10.6%**，**22 个子系统全部跌破 90%**（含上表 8 个：如 S10 82/526、S11 29/368）。本卡按 `D-38 裁定 A`（`slotN` 计入）计算。

## 8. 与卡片预设有出入的三处（lead 需知）

1. **"瓶颈是名字，不是证据"只对 14 个子系统成立。** 另 8 个名字已经够，它们的瓶颈在 `proved`——继续在名字侧投入对这 8 个没有增量。
2. **"没有任何子系统能到 `ceil(0.9n)`"不成立。** 8 个已到（其中 3 个零余量、2 个余量 ≤2），所以不能把"名字不够"当成 22 个通用结论。
3. **卡片预期本卡可能给出 S04 式的"最优子系统也不够"作为不可达论据；实测最优的 S10 反而够。** 因此不可达判词必须改挂在两门槛交集上（§4 问 3）。

另有一处**盘上口径分歧**需提醒（本卡未裁决、按卡片口径计算）：`R14_COMMON` §783 记 **S17 `named_S` = 91/102 = 89.22%**，而 `SURVEY_3B2\survey.tsv` 与本卡重算都是 **94/102**。差 3 行。若采信 91，S17 门槛 92 ⇒ 由"够（+2）"翻为"差 1"，够门槛数从 8 变 7。**这 3 行是什么，本卡未查到依据，留给 lead 裁决**（本卡不改 `coverage.tsv`，故不自行判定）。
