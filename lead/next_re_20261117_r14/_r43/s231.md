## 2.31 【R17 追加，2026-11-22】撤回「撤回」：一个 2×2 溯源表把「脚注错了」还原成「范围错标」

### 一 · 我上一轮（§2.30）撤过头了

§2.30 我判定「`F24` 自带的脚注是错的」，据此**撤回了整个档 C**。审计员 T4 用一个 **2×2 溯源表**把这件事还原到了精确位置：

同一正则 `(_before_|\.before|before_|_bak|backup/)`（`band_c_wide.py:21`），两个维度（**作用在档 A 还是档 C**）×（**带不带 `re.I`**）：

| | 档 A 全集 | 档 C |
|---|---|---|
| **带 `re.I`** | **384 行 / 258,794,083 B** ← **脚注的数** | **375 行 / 184,618,279 B** ← 我实测的 |
| **无 `re.I`** | 342 / 258,682,186 | **333 行 / 184,506,382 B** ← 审计员实测的 |

**四格我逐格复算，全部精确吻合。** 并且：
`258,794,083 − 184,618,279 = 74,175,804 B`，**恰等于被 C6 排除的 9 个 `*_out.txt`**（我逐行核过：档 A 命中但不在档 C 的正是这 9 个，形态全部 `_out.txt`）。

⇒ **脚注的 384 不是「算错」，是「范围错标」**——把一个**档 A 全集**口径的数，写成「档 C 仍含」。数本身是真的。
⇒ **档 C 的值 23,347 / 1,300,742,927 B 本身没有错**：它是「档 A 减去 selfkind 非空的 1,376 行」的机械产物，逐行 sum 精确复现。

**所以正确处置不是撤回，是改正注 + 改限定语。** v5.19 已恢复档 C，标为「按该正则口径得到的**中间值**，禁称干净语料/下界」，并把脚注改成 **375(re.I) / 333(无 re.I)** 双 flags 口径。

### 二 · 纪律 24 需要补条件（我上一轮立宽了）

§2.30 我写：「当一处引用的**限定语本身**被证伪时，正确处置是撤回该引用，不是再加一句限定。」
T4 指出这条**会误伤**，并给了一个精准切分：

- **构成性限定语**：它参与生成那个值。改它，值就变（例如「6 扩展名 + 排除 1,376 行 + 快照时刻」）。**这种被证伪 ⇒ 值作废。**
- **附注性限定语**：它只描述残留、不参与生成值（例如「本档仍含 N 个回滚副本」）。**这种被证伪 ⇒ 改附注、值照用。**

本方情形正是后者：`Σbytes(files_tier_C.tsv)` 与「仍含多少回滚副本」无关，附注写错不影响那个和。

⇒ **纪律 24 修正为**：**「当被证伪的限定语属构成性（改它值就变）时，撤回该引用；若属附注性（只描述残留），改正附注、保留值。」**

**这是本轮最该记的一条**：我上一轮不但撤过头，还为了「记住教训」把一条过宽的规则写成纪律——
**纠错时的过度反应，会把一个单点错误制度化。** 这比原来那个错误更难改，因为它是以「纪律」的形式落盘的。

### 三 · 新纪律 25 · 数字的口径必须包含**正则原文与 flags**

42 行 / 111,897 B 的差异，根因不是正则文本、不是全路径 vs basename，而是 **`re.I` 丢了**：

- 审计员的 `R17_R75_T1_AUDITSELF\_probe.ps1:26` 写的是 `$rxb=[regex]'(_before_|\.before|before_|_bak|backup/)'` ——
  PowerShell 的 `[regex]` 构造默认 **大小写敏感**，而它上一行注释还写着「**rx identical to band_c_wide.py**」。
- **文本 identical，flags 不 identical。** 那 42 行**全部是 `*/BEFORE_AFTER.txt`**，只有 `re.I` 下 `before_` 才能命中大写的 `BEFORE_`。

⇒ **纪律 25 · 声称「与某处正则相同」时必须连 flags 一起比；数字的口径里必须写 flags。**
只写正则文本的「相同」是**半个相同**——它与纪律 21（查错接口就会驳错）同族，但落点更具体：**这一族错误的成本是 42 行 / 111,897 B 的差额被挂了两轮「未查明」。**

### 四 · 本轮还补上了一个表达缺口（T4 的建议，采纳）

`F24` 只引档 A（含全部自身产物）后，读者想问「排除自身产物后大概多大」在文中**没有任何答案或指引**。
我此前拒用审计建议的区间写法（**[23,014, 23,419] 文件 / [1,116,236,545, 1,301,772,579] B**），理由成立（区间上下界各依赖一条未审计判据）。
但**拒用区间 ≠ 可以不回答**。v5.19 在 `limitations` 里加了一句**只标口径、不给数**的指引：
「想知排除自身产物后多大，请按 `files_tier_C.tsv` 的 selfkind 口径自算；该口径未经语义审计、对回滚副本判据敏感（−14.2%），且不覆盖 `*_out.json` / stdout 同族，**本条不给数**。」

### 五 · 一个必须正视的行为模式

这是**第六次**「我的处置被下一轮自己的数据推翻」，但**方向反了**：
前五次（§2.20 / §2.24 / §2.27 / §2.29 / §2.30）都是**倾向保留**，这次是**倾向撤回**。

⇒ 我并没有「学会正确处置」，只是**在两种过度之间摆动**：数据可疑时加限定、限定被证伪时又整档撤掉。
真正的判据不是「保守还是激进」，而是**「被证伪的那个东西，是否参与生成这个值」**——这正是纪律 24 修正后的问法。
