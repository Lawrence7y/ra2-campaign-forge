### 3.1 判定方法（两条独立路径，不读 name 列）

- **路径 A（原始层，不依赖 RTTI）**：扫 `.rdata` / `.data` 全部 4 字节对齐字，找所有 `dd <entry>`。
  这一步**故意不用虚表清单**，否则「某张表 RTTI 链断了 ⇒ 整张表被清单丢掉 ⇒ 误报『不在槽里』」这种假否定无法与真相区分。

## 四、第 3 步 · ② 成立行的 ③④

卡面预设「对 ② 成立的 3 行」顺判 ③④；实测 ② 成立只有 **1 行**，故只判这 1 行（其余 11 行 ② 不成立，③④ 无从判）。

**`00731A10`（`DeleteCommandClass` slot8）**

- **③ = 不成立**。函数体（31 B，10 条指令）：
  ```
  00731A10  call 0x63ac60          ; eax = dword[0xAC4BF0]（getter：mov eax,[abs]; ret）
  00731A15  test eax,eax
  00731A17  je 0x731a20
  00731A19  mov ecx,eax
  00731A1B  jmp 0x637d00           ; 尾调（真实现），返回值来自 0x637D00
  00731A20  push -1 ; push -1

  00731A29  call 0x4311C0          ; 日志/报错
  00731A2E  ret                    ; ← 失败路返回的是**日志函数的返回值**，不是约定状态码
  ```
  这是**空指针守卫 + 日志**，既无多值状态码、无 `Find` 返 −1，失败路连自己的返回码都没有
  ⇒ 按卡面口径（`{0,1}` 布尔不算）**③ 不成立**。
- **④ = 仅同源虚表槽**。唯一调用者 `00537F90` **就是 ② 所用的那张表 slot8 的槽值本身**（转发行桩），

⇒ 这一行 **② 成立但 ③ 断**。

## 五、四问回答

### 问 1：12 行里 ② 成立几行？不成立几行？

| 口径 | 成立 | 不成立 |
|---|---:|---:|
| **严格**（槽值 == entry，即卡面第 2 步原文） | **0** | **12** |
| 放宽到「转发行桩」变体（槽里是 `call entry; ret 4` 的纯转发桩） | **1**（`00731A10`） | **11** |

主答案取严格口径：**0 行成立 / 12 行不成立**；唯一一线生机是 1 行经 stub 间接成立。

### 问 2：不成立的断在哪一步？各类计数

卡面列的四类断因，实测分布（12 行）：

| 断因 | 行数（严格口径 / 含 stub 变体） |
|---|---:|
| **不在任何虚表槽** | **12** / **11** |
| 在槽里但 COL `sig` 不对 | 0 |
| 在槽里但 `pTD`/`TD` 链断 | 0 |
| 在槽里但名字读不出 | 0 |

⇒ **断因是单点的、退化的**：不是 RTTI 读法问题（§13.1/§13.2 两条坑在本卡 0 次触发），
而是**这些函数压根不是虚函数**。全池同样为零 RTTI 断裂（`虚表槽但RTTI断 = 0/1,181` 与 `0/552`）。

### 问 3：「无名行 ② 可用虚表钉住」这个假设成立吗？

**不成立**，而且卡面对旧结论的怀疑（「可能只是当时那个代理没试虚表路径」）**被证伪**：
旧结论「② 取不到」是**对的**，只是原因说错了 —— 不是没试，是**没有槽**。

证据（不只是 12 行，做了全池直测，可复跑 `python probe.py poolstats`）：

| **具名池（对照）** | 552 | **522（94.57%）** | 0 | 0 | 30（5.43%） |

### 问 4：若 ② 可解，剩余瓶颈变成什么？（③ 还是 ④）

用 12 行里唯一 ② 成立行的实际分布回答：**瓶颈是 ③，然后 ④**。

- `00731A10`：② 成立（`DeleteCommandClass` slot8）→ **③ 断**（空指针守卫 + 日志，失败路返回日志函数的 eax，

**结论：放宽 ② 也救不了这条通道。** 即使把 13 行全部推进，它们大概率仍卡在 ③（布尔/守卫形态）
与 ④（转发桩同源），与 S13 那 6 行「字面四环齐全却全卡 ④」同型。

### 6.2 踩过/未踩的坑（对照 `R14_COMMON.md` §13）

| 技术条 | 本卡状态 |
|---|---|
| `pTD`/`pCHD` 是**绝对 VA** | **遵守**；实现里先判 `值 ≥ ImageBase` 就直接解引用，未按 `IB+rva` 解（若那样解 954 张表会全盘越界） |
| `TD+8` 是**内联串**不是指针 | **遵守**；先验首 4 字节 `2E 3F 41 56/55`(`.?AV`/`.?AU`)，再读到 `0x00`；代码里没有「把 `u32(TD+8)` 当指针」的分支 |
| COL 在 `vt-4`，且 `vt-4` 是**指针** | **遵守**；先 `u32(vt-4)` 取指针再读 20 B 结构 |
| ㉓ 须枚举**全部**写点并排除两类 | **遵守**；`insn_sites_of_table` 全 `.text` 枚举，逐个判定删除析构器特征（`test byte[esp+X],1` + `call 0x7C8B3D` + `ret 4`）与 atexit 注册（`push <fn>; call 0x7C978A`） |
| capstone 须 `skipdata=True` | **遵守**；全 `.text` 扫出 **1,392,592** 条指令（与 §8.1 ㉖ 记录的 1,392,592 一致 ⇒ 无提前中止） |
| 错源 ⑨ 假否定 | **主动防**；阳性对照 + 清单↔原始层一致性 + 全镜像外扩扫描三道 |

### 6.3 本卡的边界（不夸大）

1. **「不在虚表槽」只否定了「② 走槽值/RTTI」这一条路**，不等于这些函数不可归类的任何方式都断了
   （例如从其调用者的类推断），但那不是本卡口径，也没有做。
2. **`0x00731A10` 的 ② 是「经转发行桩」得出的**，属同方法变体、判据比「槽值==entry」弱一档；
   已单独标 `成立(经stub)`，未与严格成立混计。
