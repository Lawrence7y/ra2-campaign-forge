# S13-PUSH — 攻 S13 的 proved 缺口（离达标最近的一个）

## 为什么是 S13

当前 22 个子系统里，绝大多数离门槛很远。S13 是**距离最近**的一个：`n = 240`，proved 现 **100**、`proved_strict` 现 **99**，proved 门槛 `ceil(0.5×240) = 120`，差 **20** 行。

先自己把 S13 的完整账面算出来（不许用我给的印象值）。

## 第一步：算清 S13 的 DoD 账面（必做，先于一切取证）

从盘上算并写进报告：

- `n`（S13 且 entry 在 atlas 内的行数；atlas 的 `entry` 是**小写**，比对必须大小写归一）
- `named_L` / `named_S(R14)` / `named_strict`
- `proved` / `proved_strict`
- 三个门槛 `ceil(0.9n)`、`ceil(0.5n)`
- 结论：**S13 现在差哪几项、各差多少行**

若 `named_S(R14)` 也不够，那么本卡要同时攻 named（见第四步）。

## 第二步：筛 proved 候选（按两条通道）

池：S13 中 grade 为 `[静态推断]` 或 `[未证]` 的行，且 entry 在 atlas 内。

按下面两条通道筛选，各自给命中数与基础率：

- **通道 A · ③b②（可伪证错误码/返回约定）**：函数体内 `call` 后接 `test eax,eax` / `cmp eax,<常量>` / `or eax,eax` 且**紧随条件跳转**；失败路径与成功路径**动作真正不同**；返回值**真被调用方消费**（注意陷阱：检查后 eax 立刻被 `mov eax,[esi+0x??]` 覆写 ⇒ 不算）。
- **通道 B · ③b①（跳转表）**：存在跳转表，且**每条路径可单独验证**。

**基础率必须诚实报**：`池大小 / 通道A命中 / 通道B命中 / 两通道合计可辩护行数`。

## 第三步：对候选逐行取证并产出 delta

对筛出的候选，逐行给四环：

- ① 入口（地址、函数边界，在 `.text = [0x401000, 0x7E038D)` 内）
- ② 类身份（RTTI 名 / 虚表归属 / 构造链，取不到写 `未取得`）
- ③ ③b② 或 ③b① 的具体形态 + 地址锚（**不许**用"循环内非栈写"这种已判不成立的写法）
- ④ 使用见证（真实调用者或活虚表派发；**direct-only 不足**）

产出 `S13_delta.tsv`，只放**四环齐全**的行。

## 第四步：若 named 也不够，同时报 named 通道

对 S13 中 name 为 `sub_XXXXXXXX` 形式、但能由 RTTI / 虚表归属定出真实类与方法的行：

- 给出定名依据（RTTI 描述符地址、类名字串地址、虚表槽号）
- 产出 `S13_named_delta.tsv`（只做**改名**，`grade` 一个字不动）
- 注意：`slotN` 形式的名字**只满足** `named_S(R14)`，**不满足** `named_strict`，写清它进哪一列

## 输出（只写自己目录）

- `S13_PUSH\REPORT.md`：第一步账面 + 第二步基础率 + 第三步逐行四环 + 第四步定名依据 + **明确回答「按本次产出，S13 还差多少行、能不能达标」**
- `S13_PUSH\S13_delta.tsv`、`S13_PUSH\S13_named_delta.tsv`：6 列表头同 `coverage.tsv` 前 6 列；**`entry` 大写十六进制、不带 `0x` 前缀**
- `S13_PUSH\EVIDENCE\ROW_<entry>.txt`：逐行
- `S13_PUSH\base_rate.tsv`：`channel	pool	hits	defensible	rate`

## 执行纪律

1. **先算账面再取证**；账面算不出就先报账面。
2. **每核完一行立刻落盘**；每 5 行追加进度到 `PROGRESS.md`，中断不丢已完成行。
3. 单行取证克制，不做全函数语义重建。
4. 做不完就写 `PARTIAL.md`，已完成的行仍有效。
