# PANEL-L1-DOC — 给 PANEL 的标题行约定加一条显式说明（防误伤）

## 背景

`COVERAGE\PANEL.md` 的**第 1 行**是一条 9,829 字符的超长行，结构是：

```
# PANEL — R14 coverage <最新并表备注><次新备注>…<M9 的备注>）
```

即：**每次并表的备注被「前插」到 `coverage` 之后**，把原有内容推到同一行更后面。当前该行含 **M9–M77** 的备注链（缺号是那些未并表行、只做同步/回退的批次）。

**这个约定有真实风险**：任何写者若把插入点算错（比如误用 replace 而非 insert），会**切断历史链条且不易察觉**——因为文件仍是「合法 markdown」，行数、字节数都不会异常报警。

本卡不改任何历史内容，只加一条**说明性注**，让后续写者知道 L1 是链条而不是普通标题。

## 要做什么（唯一写者）

你是本轮**唯一**可以写 `COVERAGE\PANEL.md` 的人。
`coverage.tsv` **不许改**。不许 git commit。不许碰 `R14_COMMON.md`、`STATUS_BOARD.md`、台账、`BOARD_ARCHIVE.md`、任何 `NAMED_PUSH_*` / `AUDIT*` / `D47_SURFACE` / `INVENTORY*` / `PROBE*`。

改动前记 `PANEL.md` 的 `mtime` / 字节 / `sha256`，改后再记，写进 `PANEL_L1_DOC\BEFORE_AFTER.txt`。

### 具体改动

1. **在 L1 之后插入一个新行**（即新的第 2 行），内容原样为：

```
> 📌 **L1 是并表备注链，不是普通标题**：本行由 `# PANEL — R14 coverage` + 按时间**倒序前插**的各次并表备注（当前含 M9–M77）+ 末尾闭合括号组成。后续写者**必须在 `coverage` 之后、上一条备注之前插入**，不得用整行 replace（会切断历史且不报警）。校验方法：改动后 L1 中 M 号集合应 ⊇ 改动前的集合 + 本次 M 号。
```

2. **在 L1 的 M9 备注之后、闭合括号之前**追加本次标记（如果你这一轮没有并表行可写，则写 `；M78 仅加 L1 约定说明，未改任何数据`）：

```
；M78 仅加 L1 约定说明（未改 coverage.tsv、未改任何数据行）
```

3. **不要**动 L1 的任何既有字符。你的操作只能是「插入新行」与「在指定位置插入短串」两类。

## 必须做的校验（写进交付）

- 改动前把 L1 里的 M 号集合提取出来（正则 `M(\d+)\s*并表` 与 `M(\d+)\s+PANEL`），存为集合 A
- 改动后同样提取，存为集合 B
- **断言 `A ⊆ B`**；若不成立，**立刻回滚**（用你改动前保存的副本恢复）并报告
- 报告 L1 改动前后的长度、M 号集合的差集

## 交付

- `PANEL_L1_DOC\BEFORE_AFTER.txt`：PANEL.md mtime/字节/sha256 前后
- `PANEL_L1_DOC\CHECK.txt`：集合 A、集合 B、`A ⊆ B` 结论、L1 长度前后、新增的说明行行号
- `PANEL_L1_DOC\PANEL.md.before`：改动前的完整副本（用于回滚）

## 纪律

- **只做这两处插入**。不许顺便改数字、改格式、改备注措辞。
- 若发现 L1 在你改动前就已缺链（集合 A 里没有 M9 或没有最高号），**停下报告**，不要自己补。
