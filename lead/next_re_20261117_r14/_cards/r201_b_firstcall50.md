# R201 卡 B（执行员 hy4）：槽 0 首 call 的另外 50 个目标身份定性

## 环境
工作目录 /home/t628/projects/ra2-campaign-forge。共享模块 _r185/pe185.py（P.RAW / P.B / P.dw / P.where / P.r2o / P.cstr）。capstone 可用。禁止反引号。

## 背景（R200 已落盘，可直接引用，数字必须复现）
R200 得到：槽 0 的 516 个实现体，首 call 目标去重 51 个、记录 510 条，其中 0x7C8B3D 独占 360 条；51 个目标里落在虚表槽内的只有 4 个（0x40B270 / 0x410260 / 0x557AC0 / 0x55A9B0）、对应 9 条记录；只有 0x58A5B0 -> 0x40B270 是「装表后 call 槽 3」。R200 未取得项：另外 50 个目标（150 条记录）的身份。

## 任务（一条命令输出全部）
写脚本 _r201/b_firstcall50.py，重建 R200 的槽 0 集合口径：
- 用 _r199/m1_pair.json 的 pairs（vt_d, vt_b 十六进制串），只取 min(nslot(vt_d), nslot(vt_b)) >= 1 且 dw(vt_d) != dw(vt_b) 的对，实现体地址 = dw(vt_d)，共 538 条 store / 516 个实现（R200 值）。nslot 口径：从 vt 起每 4 字节 dw 若 in_text 则计数 +1，否则停。
- 首 call：对每个实现体地址所在窗口（宿主窗口终点口径同 R200：min(下一个 CALLAT 目标, 宿主+4096)），取窗口内第一条 mn=='call' 且目标 in_text 的指令。

必须输出：
1. 复现校验：去重目标数 51、记录数 510、0x7C8B3D 记录 360、虚表槽内目标 4 个 / 记录 9 条。任一不符 FAIL 并停。
2. 对 50 个非 0x7C8B3D 目标逐个给：目标地址、记录条数、目标首 24 字节 hex、目标落哪个段、目标前一字节、目标是否 in_text。
3. 对每个目标反查 CALLERS：全 .text 里 call rel32 目标等于它的调用点数量（这是「被多少处调用」的独立口径，应与记录数不同）。给出调用点数量与记录数的比值。
4. 对每个目标扫其体内是否引用 .rdata/.data 字符串：在目标起始后 512 字节内，找形如 push imm32 / mov reg, imm32 且 imm 落在含可打印 ASCII 的地址区间，给出最多 2 个字符串样本（用 P.cstr 取，长度 8..120，可打印占比 > 0.9）。若没有给出 None。
5. 对每个目标检查它是否出现在任何虚表中：扫所有 VT 的槽，看是否有槽值等于该目标；给 yes/no 与出现的 (vt 地址, 槽号)。
6. 目标体内的 call 出边（前 512 字节内 call 目标去重、共几条），并指出 50 个目标里是否有互相调用成簇。
7. 汇总定性：把 50 个目标按「在虚表内 / 有字符串引用 / 有出边调用」三标志分成若干组，给组大小与代表地址。
8. 反控：(a) 把窗口上限改 2048 / 8192 重算去重目标数与记录数；(b) 首 call 口径改成「窗口内第一条 call 无论目标是否 in_text」，看去重数变成多少。

## 输出纪律
全部断言 PASS/FAIL，末尾 SUMMARY asserts=N fails=M。不写反引号。单条 timeout 900。
