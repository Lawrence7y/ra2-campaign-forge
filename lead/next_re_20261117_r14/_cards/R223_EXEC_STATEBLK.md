## 任务一（主目标）：[ebx+0x7d0] 状态块布局枚举

背景（已知事实，不要重复验证）：函数 0x7c7371 有两个调用点 0x7c24a2 与 0x7c2557，两处都把 lea 生成的 &[ebx+0x7d0] 作为最后一个实参（[ebp+0x1c]）压栈；0x7c7371 开头 0x7c7379 mov ebx,[ebp+0x1c] 把它当结构体基址用。

要做的事：把 [ebx+0x7d0, ebx+0x800) 这 0x30 字节窗口内被访问的每一个偏移枚举出来，给出完整布局表。要求：

1. 扫描范围：以 0x7c7371 所在音频簇为主体，扫描 [0x7c6000, 0x7c8000) 整段；另外用 regex 在全 .text 扫 disp32 落在 [0x7d0, 0x800) 且基址寄存器是 ebx 的访存指令，作为交叉检查（全 .text 用 disasm_lite 一遍带过即可）。
2. 对每个命中的偏移给出：偏移 hex、访问宽度（byte/word/dword）、读还是写（mov r,[..] 读 / mov [..],r 写；还有 or/and/add/test 等读改写要单独标注）、指令地址、原始字节 hex。
3. 输出一张按偏移排序的表 offset / width / R-or-W / sites，最后给出：窗口内出现的偏移个数、最大偏移、未出现的空洞（gap）列表。
4. 反控：把基址寄存器换成 eax 重扫同一窗口范围，命中数必须明显不同（并给出数字）；正控：确认 0x7d0 本身至少被访问 1 次。

注意：这个窗口在对象 ebx 内部，ebx 的其它偏移（0x38/0x3a/0x3e/0x3f/0x78c/0x7a8/0x3f 等）不在任务范围内，不要混进来。

## 任务二：0x7c6620 的独立复核（不要照抄下面的说法，自己反汇编拿字节）

主会话得到的结论（你要独立复核，给 PASS/FAIL + 你的字节依据，不同意就明说）：

- T1 函数体范围 [0x7c6620, 0x7c672a)，共 0x10a 字节，末尾 0x7c672a 起是 int3 填充。
- T2 记录寻址 rec = dword[0xb0b6ec] + (arg1 + arg2 * dword[0x8759a4]) * 8，步长来自内存全局不是立即数。
- T3 记录只有两个字段：[rec+0] 是 dword 值，[rec+4] 是 dword 标志位，bit0 与 bit1 各被单独操作。
- T4 双重循环：(edi, ecx) 初值都是 0xffffffff，各自 cmp reg,2 / jl 回边，所以是 3x3 = 9 个邻居，(0,0) 那次被 0x7c6651 的 or eax,ecx / test eax,eax 提前跳出。
- T5 递归调用点唯一在 0x7c66ee，4 个实参（重算的邻居坐标 + 外层 arg3 + 外层 arg4），调用后 lea esp,[esp+0x10] 清 16 字节，说明是 stdcall 4 参数。
- T6 阈值常量 0xc（12）出现在两处 cmp eax,0xc，比较对象都是 abs(邻居值 - 本记录值)。
- T7 整个函数只有 3 个 ret，返回值只有 0 和 1 两种：任一冲突就返回 0。
- T8 函数在文件里没有任何外部调用者：全 .text 扫 e8/e9 rel32 只有 0x7c66ee 一条（自递归），全文件搜 dword 字面量 0x7c6620 是 0 次，push imm32 68 20 66 7c 00 也是 0 次。

## 任务三：0x8759a4 的写入者定位

1. 全文件搜 dword 0x8759a4 的全部出现位置（给出全 18 处的 VA），逐个判定是读还是写（看指令操作码方向）。
2. 把所有写点列出，并反汇编写点前后 24 条指令，说明写入值的来源（尤其是不是 [0x87f914] 加 1）。
3. 给结论：步长全局是被谁、在什么初始化函数里设置的（给函数入口地址，入口用 int3 填充边界或 push ebp/mov ebp,esp 判定）。
