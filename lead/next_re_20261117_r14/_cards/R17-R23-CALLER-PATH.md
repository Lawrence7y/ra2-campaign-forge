## 〇、这条路径为什么此前只差一步
已确立（引用即可，不要重算）：
- `0x43F180` = **BuildingClass 主 vtable `0x7E3EBC` 的 #73**（偏移 `0x124`）；`0x449440` = 同表 **#107**（偏移 `0x1AC`）。
- BuildingClass 的两个构造器 **`0x43B680`** 与 **`0x43B740`** 在序言后把 `0x7E3EBC` 等 4 个 vtable 写进 `[esi]`/`[esi+4]`/`[esi+8]`/`[esi+0xC]`。
  ⇒ **由这两个 ctors 构造出来的对象，其 vptr 就是 `0x7E3EBC`**。
- 对这类对象的虚派发形如 `call [obj+0x124]`（→ `0x43F180`）或 `call [obj+0x1AC]`（→ `0x449440`）。
上一轮 R12 已扫出全 `.text` 有 **267** 处 `call [reg+0x124]` + **86** 处 `[reg+0x1AC]`，但**无法把基址寄存器钉成 BuildingClass 对象**。本卡换一条路：**从构造点出发**。

## 一、做法（三步，全部有界）
**第 1 步 · 找构造点**
 全 `.text` 找**直接** `call 0x43B740` 与 `call 0x43B680` 的全部 site（`E8` rel32 解算），逐条给：site 地址、所属函数 host 与 fn_end（**字节实测**）、位置断言 `host <= site < fn_end`。
 若为 0 处，明确写「0 处」并说明你扫了什么。

**第 2 步 · 在构造者体内找对该对象的定偏移虚调用**
 对第 1 步每个 site 所在函数，在其 `[host, fn_end)` 内查找：
 - `call dword ptr [reg + 0x124]` 与 `[reg + 0x1AC]`；
 - 以及 `mov reg2,[reg+0x124]` 后 `call reg2` 的形态。
 对每个命中，判定**基址寄存器是否就是第 1 步构造出来的那个对象**（同寄存器、或经 `mov` 传递的链）。给字节链。

**第 3 步 · 若第 2 步找不到，扩一层但要有界**
 允许对第 1 步 site 所在函数**再向上找一层的调用者**（直接 `E8` 即可），并在新函数内重复第 2 步。**最多扩一层**，不得无限回溯。
