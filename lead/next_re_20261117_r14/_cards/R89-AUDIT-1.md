# R89-AUDIT-1 — 对「虚表[-4] 链与类名」两条断言的独立证伪（只做一件事）

## 你是谁

R17 子代理，家族 deepseek，角色跨家族审计员。只允许在目录 /tmp/r89audit/ 下写文件（自己 mkdir）。不得在仓库里写任何文件，不得修改任何文件。本卡与你的产物里都不要出现反引号字符。

## 硬性禁令（违反即作废）

1. 不许复制仓库存放树。临时文件只许建在 /tmp/r89audit/ 下。产物总量上限 20 MB。
2. 不许读 _r89/ 下任何文件（那是执行员的产物，你不能看，否则不独立）。
3. 不许把任何既有报告里的结论当依据。你要自己算。
4. 六步以内做完。

## 待证伪的两条断言（这是别人在本轮提出的，你要独立判断成立或不成立）

断言甲：对全部有 vtable_va 的类，镜像里 dword[V-4]（即 vtable 前 4 字节）指向一个「类对象定位器」结构 COL，COL+0xC 处是一个指针指向 type_descriptor，type_descriptor+8 处是以 0 结尾的装饰名；该装饰名与 symbols.json 里该类的 name 字段一致（去掉 .?AV / .?AU 前缀与 @@ 与 $$ 后缀后比较）。

断言乙：COL+0x10 处是 pSelf 字段（指向自己的 COL）。该镜像里此断言可能不成立，要实测。

## 输入（路径写死）

镜像 ra2bench/gamemd.exe（只读）。符号表 out/reverse/symbols.json，顶层 classes 是字典，每个值有 name / vtable_va / col_va（十六进制字符串）。

PE 节表（自己用 struct 解 e_lfanew 与节表，不要用 pefile 的高层封装，避免版本差异）：ImageBase 0x400000。

## 要做的事

1. 用你自己写的 PE 解析把第 1 节到第 5 节的 name / VirtualAddress / VirtualSize / PointerToRawData / SizeOfRawData 全部打印出来，与上面给的对照。
2. 对断言甲：遍历 classes 里全部有 vtable_va 的条目，逐条按断言甲走一遍链，报「全程走通且名字一致」的数量、「某一步走不通」的数量与原因分类、「名字不一致」的数量与前 5 个反例。
3. 对断言乙：对每条走通的链，读 COL+0x10 的 dword，报它等于 COL 本身的比例、等于别的值的比例，以及前 5 个不等于 COL 的例子（给 COL 地址与读到的值）。
4. 顺带报一个数：COL 结构到底几个 dword？用「COL 起始到下一个非零且不属于本 COL 结构的边界」不方便，改成这样测：对全部走通的 COL，读 COL+0x0 / +0x4 / +0x8 / +0xC / +0x10 / +0x14 / +0x18，报每一格落在 .rdata 内还是 .data 内、以及是 0 还是非 0 的比例。借此判断结构长度。

## 必须做的两条控制

1. 正控：你自己的链解析必须能对至少 1 条手工指定的链复现出名字。手工指定：vtable_va 为 007e1668 的类（CDFileClass），把 dword[V-4]、COL、dword[COL+0xC]、type_descriptor+8 的原始字节逐字节打印出来，与符号表 name 并排。
2. 负控：把一个 COL 地址故意加 4 再走链，必须报失败（说明链对地址敏感，不是任何地址都能出名字）。

## 输出

- /tmp/r89audit/REPORT.md —— 断言甲成立/不成立 + 数字；断言乙成立/不成立 + 数字；结构长度结论；两条控制的实测。
- 最后在你的回答正文里贴出 REPORT.md 全文（不要只写路径）。
