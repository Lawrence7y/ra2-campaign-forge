# R90-AUDIT-1 — 独立测定：一轮的「工作」发生在自己那份看板备份之前还是之后

## 你是谁

R17 子代理，家族 hy4，角色审计员。只允许在目录 _r90/_audit/ 下写三个文件：round_audit_r90.py、REPORT.md、round_audit_r90.json。不得修改、移动、删除任何其它文件。你写的所有文件里都不要出现反引号字符。不要读 _r90/_exec/ 与 _r90/ 下主会话写的任何文件（tail_r90.py / tail_r90.json / overlap_r90.py / snaps_r90.json / overlap_r90.json）。不要读 _cards/ 下除本卡以外的卡。

## 要回答的唯一问题

仓库里有一批看板历史快照，文件名形如 STATUS_BOARD.before_r55_174146.md，位于 lead/next_re_20261117_r14/R17_LEAD_BASELINE/ 下。另外还有一批以轮次命名的写入前备份，文件名形如 R89.before_LEAD_LOCK_20261123_104128.bak，同目录。还有一批按轮次命名的作业目录，形如 _r89（在仓库根）、R17_R88_T1_SEMDEF（在 lead/next_re_20261117_r14 下）。

问题：当文件名叫 before_rN 的那份看板快照被写入的时刻 T(N)，与「第 N 轮的作业产物被写入的时刻」相比，产物是更早还是更晚？换句话说，before_rN 是在第 N 轮的活儿干完之后写的，还是在第 N 轮的活儿干之前写的？

你必须自己定义并实现一个可判定的判据，不能引用任何既有结论。

## 建议做法（可自行改，但必须写清你怎么做）

1. 用 os.stat 拿到所有 STATUS_BOARD.before_r*.md 的 mtime，按文件名里的轮次号分组，每组取最早的那个文件，记为 T(N)。同时记下它是哪个文件名。
2. 用 os.stat 拿到所有 R<N>.before_*.bak 的 mtime，按 N 分组取最早，记为 B(N)。
3. 找作业产物：仓库根的 _rNN 目录下所有文件（递归）的 mtime；以及 lead/next_re_20261117_r14/ 下形如 R17_R<NN>_* 的目录下所有文件（递归，只取扩展名 .py/.json/.tsv/.md/.txt）的 mtime。按轮次号 NN 分组，取最早 mtime W(N)。
4. 对每个同时存在 T(N)、B(N)、W(N) 的轮次，报三列：T(N)、B(N)、W(N)，以及 W(N) < T(N) 是否成立。
5. 关键判别力控制：这三条时钟里有两条（T 与 B）都来自备份文件名里的数字，可能同时错。所以要再加一条独立于文件名的观测：对 _rNN 目录里的脚本，用文字搜索找出其中包含「before_r」或「R<NN>.before」字样的行，如果脚本自己记录了它读写的备份文件名，把该文件名与其实际 mtime 对照，看脚本是否在自己的产物之后才做备份。报你找到的条数与结论。

## 必须做的控制

1. 正控：任选一个轮次，把它对应的看板快照文件内容里出现过的最大「第 K 轮」标题号打印出来（用正则 ^## 或 ^> ## 开头、含「第」与「轮」的行）。对绝大多数 N，这个最大值应当是 N-1 或更小；若它是 N 或更大，如实列出并解释。
2. 反控：把 W(N) 的定义改成「该轮目录里最晚的 mtime」（而不是最早），重算第 4 步的结论，报结论是否翻转。若翻转，说明判据对「取最早还是最晚」敏感，你必须如实报这一点。
3. 边界控制：报出你有几个轮次同时具备三条时钟。少于 3 个就说明样本不足。
