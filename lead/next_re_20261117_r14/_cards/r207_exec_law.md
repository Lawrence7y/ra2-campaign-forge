# R207 执行卡（第二张·独立复算）：验证「额外视图 COL 何时生成」的判定律

## 目标
在 t628 本机用 python3 独立复算，**禁止读 /home/t628/projects/ra2-campaign-forge/_r207 目录下任何脚本或 json**，全部从 ra2bench/gamemd.exe 重新推导。

## 背景口径（自己验证，不要照抄）
- 类头 HEAD 36 B：+0=0 / +4=attributes / +8=numBaseClasses / +12=pBCA / +16..+35 内嵌 20 B COL（pCHD==HEAD 自身）。
- COL 20 B：sig(+0, 0..2) / mdisp(+4, 有符号) / cdOffset(+8, 恒 0) / pTD(+12, .data 内 TD 地址) / pCHD(+16, .rdata 内 HEAD 地址)。
- 一个 HEAD 可能有多条 COL 指向它：其中一条在 HEAD+16（内嵌主对象视图，mdisp 恒 0），其余是**额外视图**，地址不在 HEAD+16 且 mdisp 非 0。
- pBCA 指向 dword 数组，元素是 24 B BCD 记录的地址；BCD 的 +0 是 pTD、+8 是 mdisp(int)、+12 恒 0xFFFFFFFF。

## 待检验的判定律（我的主张，请你独立复算并给判定）
**律 L\***：类 a 的 BCA 中若某项的 BCD mdisp == m != 0，则 m 上会产生一条额外视图 COL，
**当且仅当**：m 上至少有一个基类 pTD 在**全局**（任意类的任意 BCA 项）曾以 mdisp == 0 的身份出现过。

## 必须实测并输出
1. 类头数、物理 BCD 记录数、额外视图 COL 总数（不含内嵌 +16 那一条）。
2. 定义 primary = 至少有一条 mdisp==0 的 BCD 记录的那些 pTD，报告其个数；定义 onlysec = 只在 mdisp!=0 出现过的 pTD，报告其个数与全部名字。
3. 按律 L* 逐类预测「该类应有哪些额外视图 mdisp」，与实际额外视图 mdisp 集逐类比对：报告**完全一致的类数 / 954**、预测视图总数 vs 实际总数。
4. **判别域分析（关键，不要漏）**：954 类中有多少类「既无额外视图、BCA 里也没有 mdisp!=0 的项」（这类两侧都是空集，自动通过，没有判别力）。报告判别域的类数，以及在判别域内的混淆矩阵（预测有且实际有 / 预测有实际无 / 预测无实际有 / 双无）。
5. 三档反控，**全部在判别域上计分**：(a) 去掉 primary 条件（任何 mdisp!=0 就预测有视图）；(b) 条件换成「pTD 在镜像里有对应类头」；(c) 从 .rdata 类头区间内随机取同尺寸 dword 集合充当 primary。
6. 报告是否存在「BCD 有 mdisp!=0 的项但该类额外视图缺失」的类，逐条列出类名、缺失的 mdisp、以及造成缺失的基类 pTD 名。

## 纪律
- 一条命令输出全部证据；不要写任何落盘文件；只读 .rdata/.data，不反汇编。
- 数字必须实测，禁止预估。与上述口径冲突时如实报差异。
- 输出格式：每项一行「项目名 | 你的数字 | 判据一句话 | PASS 或 CONFLICT」。最后一行给「总断言数 / FAIL 数」。
