# 卡 R194 执行（hy4，取证实测）：序列化三个辅助函数的调用面普查 + CRC 表引用面

## 角色与边界
执行类。只允许写 _r194/exec_r194/ 目录下的文件；不得修改任何其他文件。
不得运行 gamemd.exe，全部静态取证。必须一条命令输出全部证据（单脚本一次跑完）。
OOM 红线：禁止对整段 .text 开 detail=True 的 md.disasm；全段线性扫描只用
md.disasm_lite() 或 <=64KB 分块，且只对少数命中地址单独开 detail=True。
PE 映射可直接用 _r185/pe185.py（P.RAW / P.B 段表 / P.dw / P.where / P.r2o / P.cstr），
capstone 已装（capstone.Cs(CS_ARCH_X86, CS_MODE_32)，.text 在 P.B['.text']，
lo = 段虚拟起点，hi_file = 段文件末虚拟地址）。

## 已复核前置（可直接用，不要重推）
P1 gamemd.exe .text 约 4 MB，镜像基址由 PE 头推导。
P2 0x410410 是 AbstractClass 系主表第 13 号槽目标；体内顺序为
   mov eax, [esi+0x10] ... call 0x4A1D50 ... mov cl, [esi+0x20] ... call 0x4A1CA0 ... ret 4。
P3 0x4A1CA0 是「逐字节写 + 满 4 字节折进 CRC32」的实现，CRC 表基址 0x81F7B4。
P4 0x4A1D50 是 4 字节定长块写薄壳，内部 call 0x4A1DE0。
P5 0x4A1DE0 是底层写例程（约 154 条指令）。

## 你要独立回答的五问（只要这五问）
Q1 全 .text 线性反汇编后，收集所有直接调用（E8 call rel32）的落点。
   给出 0x4A1CA0 / 0x4A1D50 / 0x4A1DE0 三个地址各被调用了多少次，
   并各列出前 20 个调用点地址（升序）。若某地址 0 次，明确写 0 次。
Q2 同时收集 call 的间址形态（FF 15 call [imm32]、FF 55 call [ebp+x] 之类无法静态解析的）
   总数，用于说明「间接调用面」有多少是不可判的（只要总数与 FF /2 组形态的计数）。
Q3 用「函数起点启发式」把上述调用点归属到函数：起点集合 = 所有 call/jmp 的落点
   ∪ 位于 >=2 个 0xCC 或 0x90 填充之后的第一条指令地址，且起点必须落在 .text 内。
   给出 0x4A1CA0 / 0x4A1D50 / 0x4A1DE0 的**不同宿主函数数**，以及每个宿主函数起点地址
   + 被调用次数。特别回答：0x410410 是否落在这些宿主函数里（给出宿主起点是否等于 0x410410）。
Q4 扫描「立即数引用 0x81F7B4（CRC 表基址）」的指令：统计 mov r32, imm32 与 lea r32, [imm32]
   两种形态命中数，列出前 12 个命中地址与其宿主函数起点。回答：除 0x4A1CA0 与 0x4A1DE0
   之外还有哪些函数引用该 CRC 表（这是「读侧校验」的候选）。
Q5 对 0x4A1D50 与 0x4A1CA0 各给 64 字节 hexdump（地址 + 字节 + 逐条助记符，遇到 ret 停止），
   并回答：0x4A1CA0 的第二个参数（[esp+8] 或 [ebp+0xC] 之类）是否在体内被当作
   「剩余字节数」或「缓冲区指针」使用，给出具体指令地址与操作数原文。

## 三条反控（必须给你的数）
R1 把 0x4A1CA0 的调用扫描改成「任意形态的立即数出现」（包括 mov/lea/push imm32），
   命中数是多少？与 Q1 的 call 命中数是否相同？
R2 用完全不做函数起点归属的裸计数，0x4A1DE0 的调用点数是多少？（与 Q3 归属后的宿主数对比）
R3 若把函数起点启发式里的填充条件去掉（只保留 call/jmp 落点），Q3 的三个宿主函数数变成多少？
