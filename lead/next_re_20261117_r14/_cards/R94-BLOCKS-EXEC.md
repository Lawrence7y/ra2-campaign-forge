R94 执行卡 · 独立复算「基本块首集合」两个口径的块数（只读，禁写 live 树）

一、任务（纯机械，不许估计）
  对 ra2bench/gamemd.exe（只读）自己做一遍反汇编并统计四个数：
   A. 全库指令起始集条数（用 objdump 地址行建立，要求第三组非空且不是纯字节行）
   B. 口径一「不把 call 当块界」的基本块首个数
   C. 口径二「把 call 下一条地址也当块界」的基本块首个数
   D. .text 段虚地址范围 [lo, hi)

  背景两个互相矛盾的盘上数字，你要独立裁：
    主会话 R93 修正后：B = 204,546   C = 292,747
    审计员 #106 产物： B = 205,542   C = 292,747
  两者 C 一致、B 差 996。任务是把这 996 的成因说清楚，不是猜。

二、必须自己做的实现步骤
  1. 用 i686-w64-mingw32-objdump -d -M intel 反汇编到 /tmp 下（不要写进仓库目录）。
  2. 逐行解析地址行。注意：objdump 有「只有字节、没有 mnemonic」的纯字节数据行，
     这类行不是指令起始，必须排除。报告你排除掉多少条。
  3. 指令长度 = 字节列去掉空格后的十六进制字符数 / 2，用它算「下一条地址」。
  4. 块首集合定义（口径一）：
       (a) 第一条指令；
       (b) 每个条件跳转（jcc 及 jmp）的立即数目标，若落在 .text 内；
       (c) 每个条件跳转、jmp、ret/retf/iret/iretd、int/int3/hlt 的「下一条地址」，
           若落在 .text 内。
  5. 口径二 = 口径一 再加 (d) 每个 call 的下一条地址。
  6. 只统计落在指令起始集里的块首（不在起始集里的单独计数并报告，不要丢掉不问）。

三、关键：目标不落在指令起始边界上时怎么处理
  这是两个数字差的唯一可疑来源。请**两种子口径都算并分别报告**：
   子口径 X：直接丢弃该目标（不加入块首）
   子口径 Y：取位于该目标之后的第一条指令起始（bisect left 后一条）
  对 X 和 Y 各报一套 B、C，并报「目标不在起始集上」的个数。

四、反控（必须做，不许省）
  1. 正控：随机取 200 个块首，断言每个块首都在指令起始集里，报告 200/200。
  2. 反控：把「下一条地址」故意算成「当前地址 + 1」，B 必须显著变大（> 500,000），
     报出具体值。若不成立说明你的长度算法没生效。
  3. 正控：单独验证 push esi 的字节列长度为 1（0x56），call 相对调用的长度为 5。
  4. 校验 exe sha256 为 73201cc0 开头的 64 位串。
