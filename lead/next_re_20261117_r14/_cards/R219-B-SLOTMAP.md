# R219-B 925 个落 UnitClass 槽域的消费位点「槽号 -> 调用方函数」映射

## 环境
工作目录 /home/t628/projects/ra2-campaign-forge 。python3 + capstone 可用。
只读模块 _r185/pe185.py：P.B[段名] 给 lo/rawptr/rawsize；P.RAW 全文件字节；P.dw(va)；P.where(va)。
防 OOM 硬红线：严禁对整段 .text 一次性 md.disasm() 且 detail=True。必须按 <= 64KB 分块，
每块用 md.disasm_lite() 迭代，及时 del 释放；只对最终命中的少量地址单独开 detail=True 复核。

## 背景（主会话已实测，作为正控必须复现）
- 全 .text 线性 sweep 后共 1394120 条指令（逐字节 resync：解码失败就前进 1 字节）。
- call/jmp 的 mem 操作数、基址是 eax/ebx/ecx/edx/esi/edi/ebp 之一、无索引寄存器、排除 esp：
  共 18930 条（R218 口径含 esp 排除逻辑，另一份口径报 18935，两个数都要报并说明差异原因）。
- 其中 disp//4 = s >= 256 的位点 931 个，涉及 91 个不同 s 值。
- 落在 UnitClass（344 槽，即 s < 344）槽域内的位点 925 个；s 值 top：288:309 / 289:85 / 337:73 / 342:58 / 258:44。
- UnitClass 虚表基址 0x7f5c70，槽数 344（逐 dword 落 .text 判据）。

## 目标 B1（唯一目标）
把 925 个位点按 s 归并，产出表：s | 次数 | 该 s 在 UnitClass 表里的目标函数地址 | 调用方函数入口地址集合（去重后的前 20 个）。
调用方函数入口的判定规则（必须固定并写明）：从位点地址向前找最近的一个「>=2 字节连续的 0xCC int3 填充」，
取填充后第一个字节为函数入口；若 256 字节内找不到连续 0xCC，则退化为向前找最近的 0xC3 ret 之后第一个非 0xCC 字节；
两者都找不到就标 unresolved 并计入计数（不许丢弃）。

## 目标 B2（分布刻画）
- 报 925 个位点分布在多少个不同的调用方函数里（按 B1 规则）；
- 报调用方函数数量的前 10 名（函数入口地址 + 该函数内位点数）；
- 报有多少个函数同时消费了 >= 5 个不同 s 值（列出这些函数入口与该函数消费的 s 集合大小）。

## 目标 B3（反控 1：s < 256 的位点做同规则对照）
对 s < 256 的位点（数量应远大于 925）按同一规则统计「调用方函数数」与「函数内位点数 top10」，
用来证明 925 这组的分布不是 sweep 或函数边界判定的系统性产物。
反控 2：把 B1 的函数边界规则换成「位点地址本身作为函数入口」（即每个位点独立函数），
报函数总数必须恰好等于 925，证明规则真的在归并而不是常数。

## 输出格式
一条命令输出全部证据，不要分多次试探。
最后单列「异常与不确定」：说明 unresolved 函数入口的位点数、以及是否有位点落在 0xCC 填充区内（应极少，若有需逐个列出）。
