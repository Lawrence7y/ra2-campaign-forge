# 卡 R198 执行 B（hy4）：CRC 状态对象 +0 初值来源 —— 向上追一层直到最外层分配点

## 角色与边界
执行类。只允许写 _r198/exec_b/ 目录下的文件，不得修改任何其他文件。不得运行 gamemd.exe。
全部静态取证。必须一条命令输出全部证据（单个 python 脚本一次跑完，脚本自打印 PASS/FAIL）。
OOM 硬红线：禁止对整段 .text 开 detail=True 的 md.disasm()。全段线性扫描只能用 md.disasm_lite()，
或 <= 64KB 分块流式迭代并及时释放；仅对少数命中地址单独开 detail=True。后台命令必须带 timeout。
镜像基址 0x400000。.text 段 P.B['.text']：lo=虚拟起点，rawptr=文件偏移，rawsize=文件内长度。
PE 映射：sys.path.insert(0,'/home/t628/projects/ra2-campaign-forge/_r185'); import pe185 as P
  P.RAW / P.B[段名] / P.dw(va) / P.where(va) / P.cstr(va,n) / P.r2o(va)
capstone：capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_32)

## 已复核前置（主会话本轮实测，直接用，不要重推）
P1 0x4A1CA0 体 55 条 / 134 B / ret 4，是 CRC 累积例程（ecx = 状态对象）。
   状态对象四槽：+0x0 = CRC 值，+0x4 = 已缓冲计数，+0x8..+0xB = 折叠缓冲，+0xC = 计数影子。
   +0x0 的唯一写是 0x4A1D1B 的 89 01（read-modify-write 尾部），**本函数内没有独立初值写入**。
P2 0x4A1CA0 的直接调用点 331 处（字节法 E8+rel32 命中，已双法同值）。
   ecx 来路：来自 edi 281 处、前 40 字节无赋值 48 处、其余 2 处。
P3 宿主 0x410410（15 条 / ret 4）：0x410414 是 mov edi,[esp+0xc]（= 调用者第三参数），
   随后 0x410427 mov ecx,edi、0x410429 call 0x4A1CA0。0x410410 自身有 27 个调用点。
P4 0x410BE0 同样取 [esp+0xc] 并 push 透传，它有 23 个调用点。
   ⇒ 状态对象是由更外层调用者提供、逐层透传；本轮要往上追到底。

## 你要独立回答的六问
Q1 复算 P1/P2/P3/P4 的四个数（55/134/ret 4、331、27、23）。
Q2 从 0x410410 的 27 个调用点出发，对每个调用点向上找**它所在的函数入口**（最简单的口径：
   从 .text 起点做一次线性扫描记录所有直接 call 的目标地址集合，取「调用点之前最近的、且属于该集合」的地址；
   若找不到就写 UNKNOWN 并给该调用点地址）。输出：27 个宿主入口地址 + 每个宿主里对 0x410410 的调用次数。
Q3 对 Q2 得到的宿主入口（去重后）逐一判定：它们是否为 0x410410 的**直接透传层**？
   判据：在调用 0x410410 之前，是否把某个寄存器/栈参数（形如 [esp+K] 或 mov reg,[esp+K]）作为第三参数 push 进去。
   给出每个宿主的：第三参数来路（[esp+K] 或本函数内分配或未知）、以及该宿主是否对状态对象的 +0 槽写过任何值。
Q4 继续向上：对 Q2 里所有「第三参数来自 [esp+K]」的宿主，用同一口径再找它们的调用者入口，
   给出第二层的入口地址集合。重复到「入口地址集合为空」或「层数 = 4」为止。
   报告每层的入口个数与总调用点数，并给出整个上溯树的形态（是树、是链、还是有环）。
Q5 【关键】在整个上溯树覆盖的所有函数体内，是否存在对状态对象 +0 槽的初始化写入？
   判据：在任一宿主函数体内，若出现「mov/lea reg,[esp+K] 取得状态对象指针，然后 mov dword ptr [reg], imm」
   或「call 某个 _memset/零填充例程且第一参数是状态对象指针」形态，即为命中。
   给出命中条数、地址、字节。若为 0，必须给搜索口径（扫描了哪些函数、每个函数扫了多少字节、判据原文）。
   注意：rep stosd 形态（F3 AB）也是零填充，要单独统计它在上溯树范围内出现的次数与位置。
Q6 【结论口径】综合 Q2..Q5，回答状态对象 +0 槽的初值来源属于哪一类，并给数支撑 + 覆盖比例：
   (a) 最外层调用者在栈上分配并显式置 0；(b) 全局/BSS 静态对象（初值天然 0）；
   (c) 由 new/malloc 分配后未显式初始化（读的是未定义值）；(d) 上溯 4 层仍找不到（给卡点）。

## 三条反控（必须给数）
R1 把 Q2 的「函数入口」判据从「最近的前置 call 目标」改成「最近的前置 0x90/0xCC 填充之后的第一条指令」，
   27 个宿主的入口地址有几个变化（给变化个数与差异地址）。
R2 把 Q4 的上溯层数从 4 层改成 2 层，Q5 的命中数变成多少（说明层数敏感度）。
R3 把 Q5 的零填充判据从「只认 mov [reg],imm 与 rep stosd」放宽成「任何 mov dword ptr [reg], 0 形态
   （reg 不限于状态对象指针）」，命中条数变成多少（说明判据特异性）。
