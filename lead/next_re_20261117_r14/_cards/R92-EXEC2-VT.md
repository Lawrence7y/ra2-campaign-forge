必须独立完成的机械统计（全部只读 ra2bench/gamemd.exe）：

1) 反汇编与站点集
   用 i686-w64-mingw32-objdump -d -M intel 反汇编，用地址行建立全库
   指令起始集，报告指令条数。统计 call DWORD PTR [reg+0x48] 站点数。
   另用 capstone 从 .text 起点线性扫，报告指令条数，两者必须差 8 倍以上。

2) 值表达式构造（核心，必须自己设计，不得照抄任何现成代码）
   为任意寄存器在任意指令地址处构造一个「值表达式」，至少能表达：
   常量、某地址处的内容、某表达式的和、无法回溯的初值。
   内存操作数的基址寄存器也必须先求值，不能直接当成未知量。
   遇 ret 停止回溯，视为函数入口，得初值。

3) 四分类
   this := ecx 在该处的值表达式。
   逐站判定 vt 寄存器（call [reg+0x48] 中的 reg）的值表达式：
     P1: vt 值 == this 值的 load
     P2: vt 值 == (this 值 + d) 的 load，d 不为 0
     P3: vt 值 == 立即数地址 A 的 load，且 this 值 == A
     PX: 其余
   报告四类站点数，并给出 PX 的形态分布（按值表达式形状归类）。
   必须说明你的回溯是否跨基本块，若不跨，请明确写出这会让 PX 中哪一类
   站点变成不可达而非反例。

4) 缺陷复现
   把「第一条 operand0 写该寄存器的指令即视为写者」这一旧口径实现一遍，
   统计该口径下 call [reg+0x48] 的命中站数，并列出 5 个 push 被误认为
   写者的站点地址。

5) 反控
   随机取 800 个 .text 地址 + 随机寄存器，用同一判据统计命中率，
   给出观测率与基线的倍数。

6) 抽查
   给出 6 个 PX 站点的前 10 条指令原文，逐站说明不满足 P1/P2/P3 的原因。
