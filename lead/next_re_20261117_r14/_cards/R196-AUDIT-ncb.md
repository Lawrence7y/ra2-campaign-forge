## 待审计的六条主张（逐条给「成立 / 不成立 / 无法判定」+ 你自己的数）
A1 vtable 判据：.rdata/.data 里 dword v 若落在 .text 内、且 v-4 处是一个 COL 地址，
   则 v 是 vtable 起点。COL 判据：+0 在 {0,1,2}、+8 == 0、+12 指 .data 且 +4==0 且 +8 是 .?A 串、
   +16 指 .data 且 +8 是正整数、+12 是数组指针。
   主张：vtable 张数 = 1214，COL 个数 = 1214，不同 ClassHierarchyDescriptor 个数 = 954。
A2 主张：BaseClassArray 元素的地址**递减**，相邻差恒 -24（即结构体 24 字节，数组按指针存不是内联）。
   主张：BaseClassDescriptor 布局为 +0 pTypeDescriptor / +4 c / +8 d / +12 == -1 / +16 == 0 / +20 位集（位集 ⊆ 0xB）。
   给 c / d 的取值分布，以及 +12 / +16 的取值分布。
A3 主张：BaseClassDescriptor 总数 2615；其中 +0 指向的 TypeDescriptor 名字是
   "ss violation - no RTTI data!" 的有 14 个位置，涉及 11 个不同 TypeDescriptor 地址。
A4 主张：c == n-1 在**每个 CHD 的数组第 0 个元素**上成立，954/954；其中 n 是该 CHD 的数组长度。
   请给出：c == n-1 的总命中数 / 元素总数。再给 c == n-1-j（j 为 0-based 下标）的总命中数 / 元素总数。
A5 主张（核心）：c 的语义是「该结点在继承树中的**后代数**」，可用深度优先解析检验：
   从下标 0 起，若 c[i]=v 则结点 i 的子树占 i..i+v，下一兄弟从 i+v+1 起；
   要求整张 CHD 恰好被消费完且不越界。主张在 954/954 张 CHD 上成立。
   再给一份反控：把某一张 CHD 的某个 c 减 1 后解析是否仍成立；以及把 c 全置 0 是否成立。
   并给「c > 0 的元素数 / 元素总数」（主会话实测 1380/2615）。
A6 主张：子树内所有结点的 d 值（第 +8 字段）都 >= 子树根的 d 值，覆盖 2615/2615 个元素位置。
