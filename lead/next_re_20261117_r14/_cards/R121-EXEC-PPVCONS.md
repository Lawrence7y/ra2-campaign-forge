## 背景（只给事实，不给结论）
.rdata 里 0x7f7c80 处 16 字节：09 01 00 00 00 00 00 00 c0 00 00 00 00 00 00 46。
.text 里有若干指令把 0x7f7c80 作为 32 位立即数 push，紧随其后是一条虚调用。
争议：这些站点是「专门用这个接口」，还是「一个通用包装器顺带也用了它」。

## Q1 站点枚举与首个 call 的分类
 1) 在 .text 里找所有把立即数 0x7f7c80 当 push 操作数的站点。判据要求：该处指令首字节是 0x68，
    且其后 4 字节小端 == 0x7f7c80。报出站点总数与全部地址。
 2) 对每个站点，找出其后的**第一条 call 指令**（在站点后 64 字节内）。分三类：
    a) call dword ptr [绝对地址]  —— 该绝对地址若在 IAT 里，报出函数名；不在 IAT 里就报 "NOT-IAT:地址"
    b) call dword ptr [寄存器] 或 [寄存器+位移]  —— 报出寄存器与位移
    c) call 相对地址  —— 报出目标地址
 3) 对 2b 的情况：在该站点所属函数（用「向前最近的连续 0xCC 填充之后」当函数起点）内，
    向前找**最后一次**写该寄存器的指令。若那条指令形如 mov 寄存器, dword ptr [绝对地址]
    且该绝对地址在 IAT 里，则把该站点归为「寄存器缓存的 IAT 调用」，报出函数名。
    否则归为「未能解析」，并把你找到的那条指令原文报出来。
 4) 汇总：按（分类 / 解析出的 API 名）计数，输出全部桶与计数。必须合计等于站点总数。
 5) 反控 5a：把判据里的立即数改成 0x7f7c80+1，站点数必须为 0（或解释清楚为什么不是 0）。
    反控 5b：从每个站点 +1 字节处起算「首字节 0x68」判据，命中必须为 0。
 正控 5c：对 0x7f7c90（16 字节 00..00 c0 00 00 00 00 00 00 46）重复 1)-4)，报出站点数与桶分布；
    若它与 0x7f7c80 的桶分布完全相同，如实写明「该量在两者上无区分力」。

## Q2 出参（ppv）的去向
 QueryInterface 的三个实参在栈上是 ppv / riid / this。对 Q1 的每个站点：
 1) 找出 ppv 栈槽：在站点之前，找形如 lea R, [esp + K] 且紧跟着 push R 的两条指令（K 是常量）。
    报出有多少站点能找到这样的 (R, K)，多少找不到。
 2) 在站点后的第一条 call（即 QI 本身）之后，向后扫描最多 20 条指令，找**第一次**把
    「某寄存器 <- dword ptr [esp + K]」（K 同上）读出的指令，记该寄存器为 P。
 3) 从该处继续向后，找第一条 call 或 ret。若 call 是：
    a) call dword ptr [绝对地址] 且该地址在 IAT 里  => 记为 API:函数名
    b) call dword ptr [寄存器+位移]  => 记为 VTABLE:位移
    c) call 相对地址 / call 寄存器  => 记为 OTHER:原文
    若先遇到 ret => 记为 RET-NO-CONSUME。
 4) 输出每个站点的 (站点地址, ppv槽K, 消费分类)，以及汇总桶与计数。
 5) 关键量：统计「消费分类 == API:OleSaveToStream」的站点数，以及它占「成功解析出消费」的比例。
    必须同时报分母，不许只报比例。
 6) 反控：把 K 改成 K+4 重跑 3)-5)，OleSaveToStream 的计数必须变化（证明不是恒真）。

## Q4 站点所在函数体的字节同一性
 1) 对 Q1 的 60 个站点（以你实测数为准），从**站点所属函数起点**取函数体，先只取站点前 0x40 字节
    对齐块与站点后 0x40 字节，做 sha256，按 hash 分组，报出每组大小与代表地址。
 2) 改窗口为 0x80 与 0xc0 各重算一次分组数。
 3) 把相邻站点间距（排序后相邻地址差）全部列出来，报出最常见的间距与次数。
 4) 反控：把每组内部的代表地址换成「站点地址 + 0x10000」（仍取同长度字节），分组数必须变多
    （证明字节同一性不是任何一段代码都满足）。
 5) 结论只写一句：这 60 个站点里，字节完全相同的函数体复制有多少份、覆盖多少站点。
    禁止把「同一性」写成「同源」或「同一个函数」。
