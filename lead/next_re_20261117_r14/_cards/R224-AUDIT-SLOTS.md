## 被审主张（逐条独立判定，不要照抄）

### 主张 A：obj+0x784 与 obj+0x788 是一对函数指针槽，各自由一组 imm32 写入，且各只有一个间接调用点

- A1：全 .text 中形如 call/jmp dword ptr [reg + 0x784] 的间接调用只有 0x7bea07 一处；[reg + 0x788] 只有 0x7bea0f 一处。
- A2：向 [reg+0x784] 写 imm32 的站点是 0x7be741 / 0x7be75a / 0x7be773 / 0x7be7c1 / 0x7be7df / 0x7be7f8 / 0x7c323c 共 7 处，
      分别写 0x7c3d60 / 0x7c6fc8 / 0x7c6dd6 / 0x7c6e94 / 0x7c4260 / 0x7c6d40 / 0x7bf220。
- A3：向 [reg+0x788] 写 imm32 的站点是 0x6660f3 / 0x7be74b / 0x7be764 / 0x7be78c / 0x7be79f / 0x7be7ae / 0x7be7e9 / 0x7be811 / 0x7be820 / 0x7c325a 共 10 处，
      其中 0x6660f3 写的是常量 0x7d0（不是代码地址），其余 9 处写 0x7c3eb0 / 0x7c39c0 / 0x7c4b80 / 0x7c4f90 / 0x7c4730 / 0x7c43a0 / 0x7c57d0 / 0x7c53a0 / 0x7bf220。
- A4：0x7bf220 同时出现在两个槽里（共同占位器），且除它以外两槽目标集无交集。
- A5：除 imm32 之外还有用寄存器/内存值写入这两槽的站点（0x6660ed / 0x671762 / 0x7112b4 / 0x7be6c9 / 0x7be6cf / 0x7c3234 / 0x7c324e），
      因此「这两槽的取值集合」在运行期不限于上述 imm32 常量集。

### 主张 B（本轮核心订正）：这 15 个注册目标在纯控制流可达性下全部不可达

主会话用一个「控制流根」模型算可达性：根 = 全 .text 中所有 e8/e9 rel32 的目标（落在窗口 0x7c2000..0x7c8500 内的）+ 8 张跳转表（0x7c6b58/0x7c6b38/0x7c7778/0x7c7758/0x7c7b3c/0x7c7b1c/0x7c7f10/0x7c7ef0）的全部表项；
闭包规则：call 跟入 + 顺序落到下一条；jmp 跟目标（含表分派）；条件跳转两个后继；ret 终止；表区字节视为数据不进入。
在此模型下，去重后的 15 个注册目标（0x7bf220 与 14 个 0x7c39c0/0x7c3d60/0x7c3eb0/0x7c4260/0x7c43a0/0x7c4730/0x7c4b80/0x7c4f90/0x7c53a0/0x7c57d0/0x7c6d40/0x7c6dd6/0x7c6e94/0x7c6fc8）**全部**不在可达集内。

请独立复算这个可达性，并明确回答：

1. 你的可达集大小是多少（窗口内指令条数）？15 个目标里有没有任何一个在你的模型里可达？若有，给出从哪个根出发的路径（逐条指令地址）。
2. 你的模型与上述模型的差异在哪（根的定义、call 是否跟入、表是否展开、ret 后是否继续）？如果换一种合理模型（例如把 .rdata/.data 里的 dword 也当根），结论会不会翻？给出你的数。
3. 这个结论能否支持「这两个槽是这 14 个函数在静态二进制里唯一的到达方式」？还是只能支持「在纯 rel32+表 模型下唯一」？请给证据边界。

### 主张 C：0x7c7371 的形参与通道归属

- C1：0x7c7371 被 0x7c24a2 与 0x7c2557 两个 call 引用，两处各 push 6 次、调用后清 0x18 字节，因此是 cdecl 6 参数。
- C2：[ebp+0x18] 是输入字节数；主循环 esi+=4、edi+=0x10、dec ebp。
- C3：0x7c7371 的 [ebp+0x10] 只与 8 和 0x10 比较、[ebp+0x14] 只与 2 和 1 比较；cx==8 的两条分支都直接跳到 0x7c75cc（epilogue），任何解码都不执行。
- C4：12 字节状态块的四个字段按通道划分——[+0] dword 与 [+4] word 属通道1（四条入口都用），[+6] dword 与 [+0xa] word 只在 0x7c7b4e 之后的第二遍被读/写，属通道2。
