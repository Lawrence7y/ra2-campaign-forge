# 卡 R197 执行 B（hy4）：CRC 状态对象 +0 槽的「初值来源」取证

## 角色与边界
执行类。只允许写 _r197/exec_b/ 目录下的文件，不得修改任何其他文件。不得运行 gamemd.exe。
全部静态取证。必须一条命令输出全部证据（单个 python 脚本一次跑完，脚本自打印 PASS/FAIL）。
OOM 红线：禁止对整段 .text 开 detail=True 的 md.disasm()。全段线性扫描只能用 md.disasm_lite()，
或 <= 64KB 分块流式迭代并及时释放；仅对少数命中地址单独开 detail=True。后台命令必须带 timeout。
PE 映射用 _r185/pe185.py：P.RAW / P.B[段名] / P.dw(va) / P.where(va) / P.cstr(va,n) / P.r2o(va)。
capstone：capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_32)。.text 段 P.B['.text']，lo=虚拟起点，rawptr=文件偏移，rawsize=文件内长度。镜像基址 0x400000。

## 已复核前置（R194/R195 已实测，直接用，不要重推）
P1 五个 CRC 例程都在 .text 的 0x4A1C10 附近，均为 __fastcall 风格（ecx = 状态对象指针）：
   0x4A1C10（50 条，ret 4）
   0x4A1CA0（55 条，ret 4）—— 状态对象四槽：+0x0 = CRC 累加值，+0x4 = 已缓冲字节计数 0..4，+0x8..+0xB = 折叠缓冲，+0xC = 计数影子
   0x4A1DE0（174 条，ret 8）—— 通用 N 字节写 + 尾部补齐
   0x4A1FB0（24 条，ret 4）—— 通用 N 字节 crc32
   0x4A1FF0（28 条，ret 无立即数）—— NUL 结尾 C 串版
P2 CRC 表地址 0x81F7B4，disp32 在 .text 共 7 处。
P3 0x4A1CA0 的调用面已实测为 331 处（resync 线性扫描与字节 E8+rel32 两法同值得 331）。
P4 已知：0x4A1CA0 内对 +0x0 的**唯一写**是 0x4A1D1B 的 89 01（mov dword ptr [ecx], eax），
   是「读入 → not → 折叠 → not → 写回」的尾部，**没有独立的初值写入**。
   ⇒ 本轮要回答的是：这个 +0x0 槽的初值到底从哪里来。

## 你要独立回答的六问
Q1 复算 0x4A1CA0 的函数边界：用 resync 线性反汇编（分块 <= 64KB，块内逐字节重同步）从 0x4A1CA0 开始，
   取到第一个「无 fall-through 且无分支目标」的 ret 为止。报告：指令条数、字节长度、ret 的形态（ret / ret 4 / ret 8）。
   与 P1 的「55 条 / ret 4」比对。若不一致，给出你的完整指令清单（地址 + 字节 + 助记符）。
Q2 在 0x4A1CA0 内列出**全部**对 [ecx+0] / [ecx+4] / [ecx+8] / [ecx+0xC] 的读和写指令，逐条给地址、字节、助记符、操作（读/写）。
   明确指出：哪几条写 +0x0，哪几条读 +0x0。与 P4 的「唯一写 = 0x4A1D1B 89 01」比对。
Q3 【初值候选一：调用者写入】把 P3 的 331 个调用点全部找出（字节法：E8 + rel32 命中 0x4A1CA0）。
   对每个调用点，检查调用点前 64 字节内是否有对 ecx 所指对象的 +0x0 写入（形态：mov dword ptr [reg], imm / mov dword ptr [reg], reg）。
   由于 ecx 来路多样，请只做**可判定**的部分：统计「调用点前 64 字节内出现 mov dword ptr [ecx+0] / [ecx], X 形态」的条数，
   并给出这 331 个调用点的宿主函数地址分布（按函数入口聚类，给出 Top 20 宿主函数地址 + 各含多少调用点）。
Q4 【初值候选二：对象构造】找出所有「把 0x4A1CA0 所属状态对象分配出来」的代码。
   判据：搜索对状态对象**相邻槽位**（+0x4 / +0x8 / +0xC）的写入点，看是否有任何一处同时把 +0x0 置 0。
   若存在，给出地址与字节；若不存在，明确写「实测不存在」并给搜索口径（扫描范围、判据、命中数）。
Q5 【初值候选三：全局/静态对象】判断状态对象是否是全局或静态分配的：
   搜索 .data/.bss 里是否存在「一段 >= 16 字节、其中 +0x4 位置的 4 字节为 0 且后续被当 ecx 传入 0x4A1CA0」的地址。
   更直接的做法：把 331 个调用点里那些 ecx 明显来自**绝对地址**（形态 mov ecx, imm32）的挑出来，给与全部地址。
   若一条都没有，明确写「实测 0 条」。
Q6 【结论口径】综合 Q3/Q4/Q5，回答：+0x0 的初值来源属于以下哪一类，并给数支撑：
   (a) 调用者每次显式置 0；(b) 对象构造时置 0 一次；(c) 全局 BSS 零初始化（即分配在 .bss，初值天然为 0）；
   (d) 实测找不到任何写入点（则说明它读的可能是未初始化值，或写入点在本次扫描范围外）。
   必须明确指出你的结论能覆盖 331 个调用点的多少比例。

## 三条反控（必须给数）
R1 把 Q3 的「调用点前 64 字节」改成「前 16 字节」和「前 256 字节」，Q3 的命中条数各变成多少（说明窗口敏感度）。
R2 把 Q1 的扫描口径从「resync 线性」换成「单次连续 disasm_lite 不重同步」，0x4A1CA0 的指令条数变成多少（说明覆盖率影响）。
R3 把 Q5 的判据从「ecx 来自 mov ecx, imm32」放宽成「ecx 来自 mov ecx, [mem] 且 mem 是绝对地址」，条数变成多少。
