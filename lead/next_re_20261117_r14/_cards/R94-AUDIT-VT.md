一、命题
  对 ra2bench/gamemd.exe（只读）中全部形如
      call DWORD PTR [reg+0x48]
  的站点，问：该 reg 里装的值，是不是 (this 指针所指地址上的内容)？
  其中 this 取 ecx 在该站点的值。

二、盘上已有的三个数（都不许照抄，你要自己算第四个）
  V1 主会话 R92：851 / 929（线性回扫最近写者，不设基本块边界）
  V2 hy4 执行员：871 / 929（未知量折成无锚符号，会自等）
  V3 主会话 R93：864 / 929（硬块边界 + 未知量带来源锚）
  V4 = 你的实现。注意 V3 与 V1 差 13 站，这是本轮要裁的东西。

三、你的实现必须包含这几个决定（每个都要在 REPORT 里明说选了哪种）
  1. 指令起始集：objdump 地址行。注意纯字节数据行（只有字节列、没有 mnemonic）
     不是指令起始，必须排除，并报告排除了多少条。
  2. 基本块边界：这一条有两种口径，**两种都算，都报数**：
       口径 N：块界 = 跳转目标 + 分支/ret 的下一条地址（call 不算块界）
       口径 C：口径 N 再加「call 的下一条地址」
  3. call 是否破坏 eax/ecx/edx：两种都算（ON / OFF），报 2x2 四格。
  4. 未知量是否带来源锚：这是 V2 与 V3 分歧的根。请两种都实现：
       无锚：块入口的 esi 全库只有一个符号
       带锚：符号里带 (块首地址, 寄存器名)
     并报两种口径下的命中数。
  5. push 不写它的操作数（push esi 读 esi，不写 esi）。
  6. lea r,[m] 得地址，mov r,[m] 得该地址处的内容，两者不同层；命中要求 vt 是 load。
  7. 块末判定：块最后一条指令若使控制流不能顺序落入下一地址（jmp/ret/iret/hlt），
     则本体不延伸到下一条地址。

四、必须做的反控（每个都要 PASS/FAIL 明写）
  1. sha256 校验（应为 73201cc0 开头）。站点数应为 929。
  2. 随机基线：随机取 800 个 .text 地址 + 随机两个寄存器扮演 (this, vt)，
     报命中率。要求远低于 100%，报具体数和种子。
  3. 反向控制：在某个已知命中的站点上，把 this 的载体从 ecx 换成别的寄存器，
     必须全部变成不命中；同时换回 ecx 仍然命中。
  4. 结构控制：存在一批站点「块内无写者、块外有写者」，这些寄存器必须全部
     收口为块入口未知量。报这批站点的个数。
  5. 判据方向控制：构造一个必须不命中的最小例子（vt 是寄存器本身而非 load），
     断言判不命中。
