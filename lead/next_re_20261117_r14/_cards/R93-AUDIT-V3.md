R93 审计卡 · 独立复算「块界 + 带锚未知量」口径下的命中数（只读，禁写 live 树）

背景：同一命题（call [reg+0x48] 的 vt 寄存器值是否等于 this 值这个地址处的内容）
有三个实现，得到三个数：
  V1 主会话 R92 自写：851 / 929（线性回溯，不设基本块边界）
  V2 hy4 执行员独立实现：871 / 929（未知量折成无锚符号）
  V3 主会话本轮新写：864 / 929（硬块边界 + 未知量带来源锚）
你的任务是**独立实现第四遍**，看哪个数字能被复现，并独立裁开 20 站差额。

一、前置（必须自己算）
  1. 校验 ra2bench/gamemd.exe 的 sha256，应为 73201cc0 开头的 64 位串。
  2. 用 i686-w64-mingw32-objdump -d -M intel 反汇编，用地址行建立全库指令
     起始集，报告条数。不要用 capstone 从头线性扫（会少约 9 倍）。
  3. 统计 call DWORD PTR [reg+0x48] 站点数。

二、必须自己实现的三件事
  1. 基本块首集合：直接跳转的立即数目标，以及任何分支/ret 指令的下一条地址。
  2. 值表达式：某寄存器在某地址处的值，至少能表达
     常量 / 某地址处的内容 / 两个表达式之和 / 块入口处的未知量。
     内存操作数的基址寄存器必须先求值，不能直接当常量。
  3. 回溯规则：**不越过所在基本块的首地址**。块入口处没找到写者就是未知量，
     不得继续沿线性地址向前找写者。
     注意 push 不写它的操作数（push esi 读 esi 不写 esi）。
     注意 lea r,[m] 得地址，mov r,[m] 得该地址处的内容，两者不同层。

三、判定与反控
  1. this = ecx 在该处的值表达式。
  2. 对每个站点，求 vt 寄存器的值表达式。
  3. 命中判据：vt 值 == [this 值]（即 vt 是 load，且被 load 的地址表达式
     与 this 的表达式结构相同）。
  4. 报告：
       HIT_CONCRETE  this 是常量或可完全解析的地址表达式
       HIT_ANCHED    this 是块入口未知量，但 vt 的地址与 this 的未知量锚完全相同
       MISS          明确不满足
       UNDET         证据不足（如基址是带索引的地址）
     四类各几站，总数必须是 929。
  5. 反控必须做三条，逐条打印：
     a) 随机取 800 个 .text 地址 + 随机寄存器，用同一判据算基线命中率。
     b) 找出「块内没有该寄存器的写者、但块首之前有」的站点，断言你的实现在
        这些站点上把该寄存器值收口为块入口未知量，而不是取到块外那个写者。
     c) 把某个已知命中站点的 this 载体由 ecx 换成另一个在该处不持有 this 的
        寄存器，断言判据从命中变成不命中（证明判据不是恒真）。
