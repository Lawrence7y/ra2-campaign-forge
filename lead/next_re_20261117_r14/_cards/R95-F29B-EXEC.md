# R95-F29B-EXEC — 重测 F29「多为桩」的分母（桩字节按本卡的正确值）

你是执行员（异族执行，只认字节，不读不 import 任何既有脚本与其 JSON 产物）。
本卡是对 R95-F29DENOM-EXEC 的重发：**上一版卡片把桩字节写错了一个字节**，导致
你上一轮全盘返回 0。错误原因写在下面，请务必按本卡的正确值重做。

## 上一版卡片错在哪（必须先读，否则你会重犯）

- 上一版卡片写：判据字节序列固定为 8B 01 00 00 00 C2 04 00，注释为「mov eax,1 / ret 4」。
- 这是错的。8B /01 的指令是 mov eax, dword ptr [ecx]（取 ecx 指向的内容），
  不是 mov eax,1。mov eax, imm32 的机器码是 B8 后接 4 字节立即数。
- 正确桩序列 = B8 01 00 00 00 C2 04 00，共 **8** 字节（B8 + imm32 + C2 04 00）。
  上一版卡片还把它写成「共 7 字节」，也是错的（C2 04 是 ret 4，但 C2 后面还有一个 00
  是立即数的第 2 字节，共 3 字节；整条 5 + 3 = 8）。
- 本卡要求：先把你实际使用的字节串与字节数打印出来，再自证它反汇编为
  mov eax, 1 与 ret 4 两条指令。这一条是正控。

## 要做的事

### 一、虚表枚举（口径先钉死）
1. 扫 .rdata，取「连续 dword 全部落在可执行区间（.text 与 .detour）」的最大行程，
   报：行程数、其中能读出 RTTI 类名的行程数、读不出名字的行程数。
2. 命名链：行程首前 4 字节 = COL 指针；COL+0xC = pTD；TD+8 = 内联装饰名串（.?AV...）。
   报读不出名字的行程数与原因。
3. 正控：打印 3 张具名行程的段首地址、槽数、COL、类名。

### 二、77 张 TClassFactory 表与产品类
1. 类名匹配 TClassFactory，列出全部：表地址、槽数、COL、完整类名。
2. 从 .?AV?$TClassFactory@VX@@ 取出产品类型名 X，报 77 个 X。
3. 对每个 X 找类名恰为 .?AVX@@ 的具名行程。报找到张数、找不到的 X 清单。
   **注意**：同名可能有多段（.rdata 里同一张表会被非代码槽打断）。本卡指定
   主表规则 = 同名多段时取槽数最多那段，槽数相同取地址最小。若你认为这个规则
   不合理，照做并另报「改用第一段」时 63 这个数会变成多少（见三.4 的反控）。

### 三、桩判定（本卡核心，逐表逐槽给字节）
判据 = 从函数入口地址起逐字节比较 8 字节 B8 01 00 00 00 C2 04 00。

1. 77 个产品类表 slot1（偏移 +4）指向的函数，入口 8 字节是否逐字节等于该序列？
2. slot2（偏移 +8）同问。
3. 全镜像该 8 字节序列出现多少次？每次出现落在哪张具名行程的哪个槽？
   不在任何具名行程槽内的出现位置单列地址。给出三组计数与清单。
4. 三组数字：slot1 是桩的个数、slot2 是桩的个数、两者都是桩的个数，并列出对应 X 名。
5. 反控（必须做，缺一项本卡不合格）：
   - 把桩序列改 1 个字节后，命中数必须变 0；
   - 只比前 5 字节时命中数会变成多少（报数并解释是变松还是变紧）；
   - 改用「第一段」当主表后，两槽都是桩的个数会变成多少；
   - 把判据起点改成入口 +4 后，命中数必须变 0。
6. **例外逐个归类**（本条是上一版卡片漏掉的，必须给）：
   对每个「slot1 不是逐字节桩」的 X，从入口地址开始逐条反汇编，判它属于哪一类，
   并给出该类的指令序列（助记符 + 操作数）：
   - K1 转发：入口 mov eax,[esp+4] / push eax / call rel32 / ret 4，call 的目标入口
     仍逐字节等于桩序列（即转发到桩）；
   - K2 调整器跳板：入口 sub dword [esp+4], imm8 / jmp rel32，跳转目标入口再逐字节
     等于桩序列（要跟着跳，可多级）；
   - K3 真计数：入口出现对某个全局地址的读改写自增（形如 mov edx,[G] / inc edx /
     mov [G],edx）并且 call 一个内存间接槽；
   - K4 其它（必须写清字节）。
   每一类给出条数与 X 名清单。**K1 与 K2 都要跟到终点再判**，不许只看入口前 8 字节
   就下结论——终点是不是桩才是本质。
