### C-3 两行 FAIL 的证据链（`004322A0` / `004324B0`，共用宿主 `004011C0`）

**(1) 写入对象不是 `this`，而是栈临时对象。** ④ 自称「构造器体内 `mov [reg], vt`」，实测指令是
`004014C4: mov dword ptr [esp + 0x20], 0x7e1668`——**基址是 `esp`**，写的是局部栈对象。

**(2) 宿主 `004011C0` 不是 CDFileClass（或任何类）的构造器，也不是工厂。**
- 函数头 `sub esp,0x2c0; push ebx/ebp/esi/edi; mov [esp+0x10],edx; mov esi,ecx` 之后，
  **`ecx` 被当字符串用**：`mov edi,esi; repne scasb`（`strlen`）、`rep movsd/rep movsb`（`strcpy`）；
- 中段 `push 0x124; call 0x7C8E17`（分配 0x124 字节）→ `rep stosd` 清零 → `call 0x7C8DF0`（`strchr('.')` 类）
  → 打开/读文件（间接调 `[0x7E1208]`、`0x473B10`）→ `call 0x7C8B48`（带比较函数 `0x7C8D20`、元素 0x24 的排序/构造）
  → 写 `[ebp]/[ebp+4]/[ebp+0x10c]/[ebp+0x114]`，末尾 **`mov eax,ebp` 返回那块堆结构**；
- 全函数**只有一处 `ret`（004014DD）**，且**从未在 `this`(esi) 上写 vptr**：全镜像 5,732 处 vptr 存储中，
  该函数内仅 2 处，且两处都指向 `[esp+0x20]`（`0x7E16B0` 与 `0x7E1668`）。

**(3) 那两处 vptr 写是「内联析构器」，不是构造器**——决定性证据：
`004019A0` 的函数体与 `004011C0` 的尾部**逐指令同构**（同调用、同顺序、同偏移）：

```
004019A0: push esi / mov esi,ecx / lea ecx,[esi+0x58]
          mov [esi],0x7e16b0 / mov [esi+0x64],0 / call 0x43AE50
          mov ecx,esi / mov [esi],0x7e1668   <-- CDFileClass vptr
          call 0x431B80
          test byte [esp+8],1 / je .. / push esi / call 0x7C8B3D / mov eax,esi / ret 4
```
`test byte [esp+8],1` + `operator delete(0x7C8B3D)` + `ret 4` = **scalar deleting destructor** 签名
⇒ `004019A0` 是 `CDFileClass` 的删除析构器，`004011C0` 尾部是它**去掉删除分支后内联**的析构序列。
即：`004014C4` 写 vptr 时，对象正在被**析构**，不是在构造。

**(4) 该 vt 在盘上确有真构造器，执行器选的是 199 个站点里地址最低的那个。**
`0x7E1668` 全镜像 **199 处** vptr 存储，其中写 `this` 的 8 处；我逐一定性：
`00401950`/`004019A0` = 删除析构器；`00697A47` = 其它；
**`0047A9E3`(宿主 0047A9D0)、`0047AA10`(0047AA00)、`0047AA3C`(0047AA30) 是真构造器**——
`call 0x431B20`（基类构造器）→ `mov [esi],0x7e1668` → `mov eax,esi; ret`，无删除标志、无 `operator delete`。
执行器取的 `004014C4` 只是「最低地址命中」，落在一个无关函数的栈临时对象上。

**(5) 根因（可复现）**：`generate.py:82-88`
```python
op = x["op"]                                  # 单目操作数里的 [ ] 内容
if op.lower().startswith("0x"): form = "mov_abs"
elif op:                        form = "ctor_body"    # 任何非绝对操作数 => ctor_body
```
**从不校验宿主是不是构造器**——正是先例 `R16_AUDIT_D1_FINAL` NIT-2 预警的失效模式，本批实际踩中 2 行。
`install_site` 又直接继承 `R16_PROBE_4FINAL/final.tsv`（该 vt 取最低地址命中），进一步放大。

⇒ **C 判 FAIL（2/18）**；正确计数应为 `mov_abs 8 / ctor_body 8 / reg 2`
（`reg` = 卡面定义的「非构造器的寄存器形态」）。
