## Q1 · `[esp+0x23]` 的写点

**答案：写点 2 处，读点 1 处；但它不是任何被调函数的返回值，而是本块自己写死的 0 / 1 常量。**

| # | 地址 | 字节 | 解码 | 值 | 条件 |
|---|---|---|---|---|---|
| W1 | `0x43F249` | `88 5C 24 23` | `mov byte ptr [esp+0x23], bl` | **0** | 无条件，进入双层循环之前执行一次 |
| W2 | `0x43F4FF` | `C6 44 24 23 01` | `mov byte ptr [esp+0x23], 1` | **1** | 仅当某格走完整个「工作路径」后落到此处 |
| R1 | `0x43F5AB` | `8A 44 24 23` | `mov al, byte ptr [esp+0x23]` | — | 双层循环全部退出之后 |

栈槽归一化：三处都落在**同一帧槽 `slot 0xE7`**（`disp - espdelta`）。`espdelta` 追踪按
「call 视作清除自上次 call 以来压入的实参」（stdcall/thiscall）处理，否则线性扫描会因未建模的
实参弹栈而漂移（首版曾漂移 0x70 字节，已修正，见 `work.py:walk`）。

### W1 的值来源
`0x43F1EF`=`33 DB`（`xor ebx,ebx`），ebx 此后到 `0x43F249` 之间未被改写，
故 `bl`=0 → **初始化成败标志 = 0（失败）**。位置在 `0x43F238`/`0x43F245` 拿到两个循环上界之后、
`0x43F251`=`0F 8E CF 02 00 00`（`jle 0x43F526`）之前。

### W2 的值来源
`0x43F4FA`=`E8 E1 83 12 00`（`call 0x5678E0`）返回后紧接 `0x43F4FF`，再紧接 `0x43F504`（循环增量
`inc esi` / `cmp esi,[esp+0x18]` / `jl 0x43F269`）。写入的是**立即数 1**，不取任何寄存器/返回值。
即：**「这一格处理完了」这个事件把标志置 1**。

### 关键性质
标志**只置 1、从不复位**（除 W1 的一次性 0 初始化外无其它写点）。所以
`[esp+0x23] == 1` 的语义是「**至少有一格走完了工作路径**」，而不是「全部格成功」。

### 因此 Q1 的落点
`0x43F5B1` 按它判成败，而「失败」**不是由某个被调函数的返回值决定**：
它是本块自己的初值 0 从未被 W2 覆盖的结果。反过来说，失败的真实条件是
**没有任何一格抵达 `0x43F2BB`（工作路径入口）**——而入口条件就是 `0x43F2B3`=`84 C0`（`test al,al`）
之后的 `0x43F2B5`：逐格调用 `0x47C620` 的返回值 `al` 非 0。

## Q2 · `0x43F180` 与 `0x43F1E9` 的关系

**答案：不是两个函数；`0x43F1E9` 是 `0x43F180` 这个 switch 函数的 case 1 / case 3 程序体。**

字节证据链：

1. `0x43F180` 是函数入口（前有 `C3`+12×`90` 填充）：
   `81 EC B0 00 00 00`（`sub esp,0xB0`）/ `53`（`push ebx`）/ `55`（`push ebp`）/
   `8B AC 24 BC 00 00 00`（`mov ebp,[esp+0xBC]`，取 1 个栈参数）/ `56`/`57`（`push esi/edi`）/
   `8B F9`（`mov edi,ecx`，thiscall）。
2. 分派：`0x43F1B6`=`83 FD 03`（`cmp ebp,3`）；`0x43F1BD`=`0F 87 39 09 00 00`（`ja 0x43FAFC`，越界）；`0x43F1C3`=`FF 24 AD 0C FB 43 00`（`jmp dword ptr [ebp*4+0x43FB0C]`）。
3. 跳表 `0x43FB0C` 实际字节：`CA F1 43 00 | E9 F1 43 00 | A6 F9 43 00 | E9 F1 43 00`
   ⇒ 条目 = `0x43F1CA` / **`0x43F1E9`** / `0x43F9A6` / **`0x43F1E9`**。参数值 1 和 3 都落到 `0x43F1E9`。
4. `0x43F1E9` 起首 `8B 87 20 05 00 00`（`mov eax,[edi+0x520]`）**没有自身序言**（无 `sub esp`、无 `push`），
   直接使用 `0x43F180` 建立的 `edi`/`ebp`/帧——若把它当独立函数入口，`edi` 无来源。
5. `0x43F1E6` 的 `C2 04 00` 是 **case 0（`0x43F1CA`）的收尾**（`0x43F1CA` 段：`lea eax,[esp+0x28]`/`push edi`/`push eax`/`mov ecx,0x87F7E8`/`call 0x5687F0`/`pop edi`/`pop esi`/`pop ebp`/`mov al,1`/`pop ebx`/`add esp,0xB0`/`ret 4`），
   不是函数结束标记。`0x43F1E9` 段自己的成功出口 `0x43F5C9..0x43F5D7` 是**同型收尾**：
   `5F 5E 5D`（`pop edi/esi/ebp`）/`B0 01`（`mov al,1`）/`5B`（`pop ebx`）/`81 C4 B0 00 00 00`（`add esp,0xB0`）/`C2 04 00`（`ret 4`）。
   两段共用同一帧与同一收尾形态，正是 switch 各 case 的共同出口。

### 调用点清单（`.text` = `[0x401000,0x7E038D)`，扫 `E8 rel32`）

| 目标 | 直接 `E8` 命中数 | 调用点 |

| `0x43F1E9` | **0** | 无直接调用；只经 `0x43F1C3` 的跳表（条目 1、3）到达 |

| `0x47C738` | **0** | 该地址本身是一条 `E8 93 FC FF FF`（`call 0x47C3D0`）指令，不是任何入口，故命中数必然 0 |

## Q3 · 「目标格被己方单位占据」这条路径上，失败值由谁产生

### 链路（含每跳的字节 + 解码）

```
0x43F2AE  E8 6D D3 03 00        call 0x47C620          ; 逐格尝试放置，返回值 al
0x43F2B3  84 C0                 test al, al
0x43F2B5  0F 84 49 02 00 00     je 0x43F504            ; 该格失败 -> 跳过该格（标志不动）
   │
   └─ 0x47C620 内部：
      0x47C738  E8 93 FC FF FF        call 0x47C3D0   ; (this,&cellxy,0,0) 查询该格占据者
      0x47C73D  3B C5                 cmp eax, ebp    ; ebp==0
      0x47C73F  0F 85 0E 01 00 00     jne 0x47C853    ; 有占据者 -> 立即判定失败
      0x47C853  5F 5E 5D 32 C0 5B 83 C4 08 C2 0C 00     ; xor al,al ; ret 0xC  -> al=0
   │
   └─ 回到 0x43F1E9 的循环：该格被跳过，[esp+0x23] 保持 0
0x43F5A9  33 DB                 xor ebx, ebx
0x43F5AB  8A 44 24 23           mov al, byte ptr [esp+0x23]
0x43F5AF  84 C0                 test al, al
0x43F5B1  74 25                 je 0x43F5D8            ; 标志仍 0 -> 走拒绝出口
0x43F5D8  53                    push ebx
0x43F5D9  8B CF                 mov ecx, edi
0x43F5DB  E8 90 54 2B 00        call 0x6F4A70          ; 失败副作用（未分析）
0x43F5E0  5F 5E 5D              pop edi, esi, ebp
0x43F5E3  32 C0                 xor al, al             ; ★ 失败值在这里产生
0x43F5E5  5B 81 C4 B0 00 00 00 C2 04 00                 ; pop ebx ; add esp,0xB0 ; ret 4
```

### 三个层次要分清

1. **根因判定点（谁的返回值为 0）**：`0x47C73F` `0F 85 0E 01 00 00`（`jne 0x47C853`），
   判据是 `0x47C738` 调的 `0x47C3D0` 的 `eax` 返回值。
2. **该格失败的产出点**：`0x47C853` 起 `32 C0`（`xor al,al`）+ `C2 0C 00`（`ret 0xC`）→ `al=0`。
3. **整体拒绝的产出点**：`0x43F5B1` `74 25`（`je 0x43F5D8`）作决定，`0x43F5E3` `32 C0`（`xor al,al`）产生返回值 `al=0`。

### 被调函数 `0x47C3D0` 的返回约定（Q3 附加项）

- 调用形态：`mov ecx,edi`（thiscall，`this` 在 `ecx`）；`push 0` / `push 0` / `lea ecx,[esp+0x14]`（三次栈参）。
- 收尾：`0x47C4BC` `C2 0C 00`（`ret 0xC`，3 个栈参，被调方清栈）；另有 `0x47C4C7` 同型 `ret 0xC`。
- 返回：`eax` = **对象指针**（`0x47C4B2` `8B 44 24 14` 取最佳候选；无候选时 `0x47C4BF` 路径 `mov eax,esi`，`esi=0`）
  ⇒ **`eax==0` 表示该格无（阻挡性）对象**。
- 参数语义（读码所得）：`[ebp+8]`=指向格坐标 `{x,y}` 的指针；`[ebp+0xC]`=字节，非 0 时扫 `[ecx+0xE8]`、
  否则扫 `[ecx+0xE4]`（`0x47C400`-`0x47C415`）；`[ebp+0x10]`=需排除的对象（`0x47C432` `cmp esi,[ebp+0x10]`）。
- 过滤：`0x47C427` `8A 46 14` / `0x47C42A` `24 01` / `0x47C430` `74 75`（`mov al,[esi+0x14];and al,1;je skip`）
  ——与 `R14_COMMON §2.6` 的 bit0 闸判同一判据；**bit0 清零的对象不被当作占据者**。
- 选取：按 `call [edx+0x48]` 取得的格矩形算距离（`0x47C484` `call 0x4CAC40`、`0x47C48C` `call 0x7C5F00`），
  `0x47C499` `cmp eax,[esp+0x18]` / `0x47C49D` `jge` 取最近者。

### 结论
- 「目标格被**任意 bit0=1 的对象**占据」⇒ `0x47C3D0` 返回非 0 ⇒ `0x47C73F` 跳 `0x47C853` ⇒ `al=0`。
- 该格随后被 `0x43F2B5` 跳过，标志不置位；若**所有格都如此**，则 `0x43F5B1` 走 `0x43F5D8`，
  由 `0x43F5E3` 的 `xor al,al` 把 `0` 交回调用者。**这就是「目标格被占 → 放置失败」的拒绝成因**。
- 补充：`0x47C62x` 里还有一条独立的 Terrain 分支——`0x47C74A` `call 0x47C4D0`（WhatAmI 比 `0x24`）
  返回非 0 时经 `0x47C751` 落到 `0x47C757` 的 `32 C0`（`xor al,al`）同样判失败。
