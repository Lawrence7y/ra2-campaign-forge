## 二、口径（照卡逐条实现，可复跑：`python SURVEY_3B2\survey.py`）

- **池 pool** = 该子系统 ∧ entry 在 atlas 内 ∧ `grade != [已证]`（含 `[未证]` 与 `[静态推断]`；比 S15S16_3B2 的"[静态推断] only"池大，按本卡定义执行）。
- **p3b2 机械形态**（capstone 按 atlas size 反汇编函数体）：
  1. 函数体内存在 `call`，其后 +1..+3 条内出现 `test eax,eax` / `cmp eax,<imm>` / `or eax,eax`；窗口内只允许可辩护地"无关"的指令——可解码、非控制转移、**不覆写 eax**（call/`mov eax,…`/`xor eax,eax` 等一概断链）；
  2. 该比较后 +1..+2 条内紧跟条件跳转（capstone 5.0.7 全部 `X86_INS_J*`，除 `jmp`）；比较与跳转之间 eax 被覆写（`mov eax,[…]` 之类）、出现垃圾字节或控制转移的 **= 陷阱，不算**（卡片明令；即上一轮 13→9 的陷阱，本卡机械化为窗口/间隙断链规则）；
  3. 该跳转 taken 与 fall-through 的动作签名不同（直接 call 目标集 / ret 前 eax 常量集 / 是否 ret / 末端 eax 常量，沿用已过审的 `path_sig` 实现）；签名相同（同一处 call 只差参数）不算。
- **p3b2_named** = 命中行中 name 非空且不匹配 `^(sub_|.*::sub_)`。
- 与 S13_PUSH / S15S16_3B2 旧实现的差别：窗口 +1..+3（旧 +1..+4）、窗口/间隙断链（旧完全不查，靠人工剔陷阱）、并入 P2 分叉判据、**不含 P3 可伪证约定**（纯机械，P3 属后续语义证实步骤）。

## 六、明确回答卡片两问

### 问 1 · 若把全部 p3b2 可辩护候选都证实，有没有新子系统能达标？

**全口径（named + proved 双门槛）DoD 意义上：没有。** `can_close=True` 共 4 行：S15 / S16 / S17 是**本来就已过 proved 门槛**的（gap_now = −27 / −2 / −5，不是"新"），唯一的新面孔是：

- **S04**：proved 91 → best_proved 164 ≥ 门槛 158（余 +6）。proved 单门槛**可闭**。

但 S04 的 `named_ok=False`（named_S14 = 104 < ceil(0.9×316) = 285），且其 73 个 p3b2 命中 **p3b2_named = 0**（全部是 `sub_*`/`*::sub_*` 无名行）——即使 73 行全证实，S04 也过不了 DoD 第 1 条。**结论：把 1,733 行全部证实的上界世界里，严格达标子系统的集合不会扩大。**

### 问 2 · 有没有"proved 可闭但 named 不够"——瓶颈在名字不在证据的子系统？

**有，恰 1 个：S04。** proved 91/门槛 158 差 67、best_proved 164 可闭（余 +6）；named_S14 104/门槛 285 **差 181 个名字**，是它的唯一瓶颈。其余 `named_ok=False` 的子系统（S01/S02/S03/S05~S07/S09/S12/S14/S18/S19/S21/S22）全部连 proved 门槛都闭不了，瓶颈不在名字。附带观察：p3b2_named = 0 的还有 S02（83 命中）与 S19（59 命中）——这两处即使后续攻 named+proved 双线，现有命中也一行名字都不贡献。
