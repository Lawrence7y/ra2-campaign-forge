## 必须在报告里讲清的三条限定

### 1. 892 与 802 的差别（你给的前提需要修正）

- **892 行** = `evidence_path` 里**含有** `classification_trace` 的行数。
- **802 行** = `evidence_path` **只含** `classification_trace` 的行数（本核查的 R_TRACE_ONLY）。
- 差的 **90 行**是混合记录：`EVIDENCE/classification_trace.tsv#…;R4_DERIVABILITY/all848.tsv;R4_FILL_91_R2/evidence/ROW_xxxx.txt`。这 90 行的后两个路径**实测都存在**（`all848.tsv` 107,846 B；`R4_FILL_91_R2/evidence/` 下 91 个 `ROW_*.txt`），所以它们归 R_OK，不是 R_TRACE_ONLY。

按任务的 R_TRACE_ONLY 定义，正确数字是 **802**，不是 892。

### 2. R_TRACE_ONLY 的 802 行连 trace 文件都不在记录位置

这 892 行记录的 trace 路径是 `EVIDENCE/classification_trace.tsv`，而 `EVIDENCE/` 在三个基准下都不存在——**892/892 全部解析不到**。该文件实际只存在于 `C02_census`…`C10_census` 的 `EVIDENCE/` 下（共 9 份，同级歧义）。所以这 802 行不仅「只有分类追踪」，连那唯一线索也无法按记录定位；而分类追踪按定义本就不承载四环证据。

### 3. R_OK 的 478 行是真证据，但多是共享汇总文件

478 行证据文件全部真实且非空（最小 2,317 B，中位 26,496 B，最大 122,973 B，**0 个空文件**），且**没有一行是仅靠 `classification_trace` 成立的**。抽样 8 行独立复核全部 `True`。这一点必须明说：**R_OK 部分是扎实的，不能为了发现问题而说成底座全面塌陷。**

但要提示（超出本次核查范围）：478 行只落在 **70 个不同文件**上，最集中的 `R4_DERIVABILITY/all848.tsv` 一个文件就覆盖 90 行，其余多为 `NAMED_PUSH_AUDIT*/VERDICT.md`、`*/_audit/VERDICT.md` 这类共享审计件；`first_existing` 文件名里含该 entry 号的只有 4 行。即「文件存在」成立，但「逐 entry 专属证据」多数并不成立，这是另一层问题。

## 方法（可复跑）

脚本：`EVID_RESOLVE/resolve.py`（只读，纯标准库）

```bash
python resolve.py                # 默认路径
python resolve.py --repo D:\Project\ra2-campaign-forge
```

### 解析规则

1. **取行**：`grade == "[已证]"` → 1,654 行。
2. **拆路径**：按 `;` 和 `,` 拆分；实测另有 **2 行**用 `|` 连接（`0064C380`、`0064DAB0`），已一并拆分（拆分后类别不变，仅让候选更完整）。
3. **去锚点**：`#anchor`；实测另有 **6 段**用行号锚点 `:NN` / `:0x…-0x…`（如 `YRpp\CRT.h:87-88`、`docs/re/superweapon_re.md:708-721`），按同一语义剥离。剥离后 `YRpp/Unsorted.h`、`YRpp/CRT.h`、`docs/re/superweapon_re.md` 均在仓库根命中。这 6 段所属的 6 行里，5 行本来就靠其他路径段为 R_OK（故类别计数不变），剩 1 行（`006DBE20`，`work/t1a_xref2.py:0x6DBEB2-0x6DBECB`）仍为 R_MISSING——因为 `work/t1a_xref2.py` 在整个仓库里不存在。
4. **相对路径基准候选**（按此顺序尝试，前一个不中就退下一个）：

   | 顺序 | 基准名 | 实际路径 | 存在 |
   |---:|---|---|---|
   | 1 | `r14` | `D:\Project\ra2-campaign-forge\lead\next_re_20261117_r14` | 是 |
   | 2 | `lead` | `D:\Project\ra2-campaign-forge\lead` | 是 |
   | 3 | `repo` | `D:\Project\ra2-campaign-forge` | 是 |

   绝对路径（盘符 / UNC / 以 `/` 开头）只按原样试一次。三个基准实际都参与了：R_OK 里 **396 行在 `r14` 命中、82 行在 `repo` 命中、0 行在 `lead` 命中**。
5. **判定存在**：`os.path.isfile(...)`（**不是** `os.path.exists`，避免把目录误判为证据文件）。
6. **归类优先级**：空 → `R_EMPTY`；全部段都是 trace → `R_TRACE_ONLY`；否则任一候选命中 → `R_OK`；否则 `R_MISSING`。
