# P0-METHOD · UNKNOWNS（本卡未能闭合的每一条）

> 只读测量卡。下列每条都给出「我测到的事实」与「我为什么不敢下结论」，供 Lead 决定是否派卡或裁口径。

## U1 · 通道 C 的 8 行降级是**总体统计依据**，不是逐行证明
- 事实：`0x86E000..0x875000` 串 6,908 项 → coverage 0.41%、16B 对齐 6.5%、指令边界 34.8%、d1 4.28%；真入口总体（initterm 3,944）对应 98.88% / 99.92%。
- 未知：这 8 个具体地址（`004A20F0/004E7C20/0052D620/006E4080/006E62E0/006E80F0/007E0000` 共 7 个）**没有逐行证明**它们是 case 标签；只有「所在串的总体形态与函数指针表不符」。若某行恰是「该跳表里唯一一个真函数入口」，本卡会漏判（保守方向：漏 FUNC，不误判 FUNC）。
- 另注：该区段**在 .text 里 0 条静态引用**（既无 index-jmp/call，也无 `push imm`/`mov imm` 基址），故无法从引用端判定它是跳表还是函数表 —— 这是降级为「疑似」而非「NOT_FUNC」的原因。

## U2 · T2 里到底有多少真入口，只有统计区间，没有逐行答案
- 事实：T2 = 1,491 = D1 成立 1,401 + padding 后接 jmp 90；`d2_why` = ret 1,262 / single_insn_ret 113 / jmp_out 108 / undecodable 8。
- 可用的**非循环**参考：D1 在 initterm 真入口上 98.88%、在跳表标签总体上 4.28% ⇒ 若 T2 的行为接近真入口总体，多数是真入口。
- 但这是**总体推断**，且 P0 要求的是一行一行裁 ⇒ 本卡不做外推。**T2 必须留给 P1 或另立卡**。

## U3 · 【新错源候选，建议回写 §8.1】本镜像 RTTI 的 COL `signature` 全为 0，不是 1
- 事实：`.rdata` 里 1,214 个 COL 的 `+0` 字段**全部 = 0**（不是微软惯例的 1）。首版实现按 `signature==1` 过滤 ⇒ 通道 B **0 表 0 槽**，整条通道全灭。
- 修正：改为不依赖 signature，用「`COL+0xC`→TD 可读 ∧ `TD+8` 是 `. ?A…` 内联名串 ∧ `COL+0x10`→CHD 可读」三重结构约束，得 **1,214 表 / 14,044 槽**，与 §8.1① 逐数吻合。
- 建议：任何在本镜像上跑 RTTI 的卡，**不得先验 signature==1**（与 ⑧ 的「读不到必须 fail-closed」同型：先验假设会静默产出 0 命中）。

## U4 · TD 在 `.data`、CHD 在 `.rdata`，段约束过窄会再灭一次通道
- 事实：`COL 0x7FC618 → TD 0x8193A8` 在 **`.data`**；CHD `0x7FC608` 在 `.rdata`。首版只认 `.rdata` 内的 TD ⇒ 同样 0 命中。
- 未证：是否存在 TD 落在 `.text`/`.rsrc` 的异常表（本卡只按 `.rdata`/`.data` 两段收，1,214 表与审计值一致，故倾向无）。

## U5 · 与 ADJ4 的一处口径分歧（需 Lead 裁）
- 分歧行：`00407080`。ADJ4 判 **NOT_FUNC**（「首字节 E9，纯转发桩」）；本卡判 **T2 疑似**。
- 理由：C 口径（18,479 行）**包含 3,944 个 `_initterm` thunk**，说明本项目把「被调用的 thunk」算作入口；故转发桩不应判 NOT_FUNC。§8.1② 只否定「jmp32 直接当真入口」，未说「jmp 桩不是入口」。
- 未裁：若 Lead 认为 thunk 一律不算入口，则 T3 会增加一批（本卡未计）。

## U6 · `007E0000` 是 `.text` 末尾的边界行
- 事实：它是最末 16B 槽（`.text` 末 `0x7E038D`），字节 `C3 55 8B EC …` = 裸 `ret` 紧跟 `push ebp…`；表项指向的是那个裸 `C3`，真正的落点可能是 `0x7E0001`（非 16B 对齐 ⇒ 不在池内）。
- 未证：它属于「表项指向共享 ret 桩」还是「表项指向该函数而 C3 是前一函数尾声」。本卡按 C_LABEL 降级，未单独裁。

## U7 · jcc 目的判为「体内标签」依赖一个未证的假设
- 事实：153 行的最近 jcc 站点距离中位 **22B**、100% ≤4KB。
- 未证：**jcc 不能跨函数**这一点本卡没有证明（理论上跨函数 jcc 存在）。距离分布强烈支持「同函数体内」，但这是分布证据不是定理。若允许跨函数 jcc，T3 的 153 行里有少数需退回 T2。

## U8 · 「前驱非终止符且顺流可达」判据的边界
- 事实：只有 23 行进这一类（池内全部是指令边界，且绝大多数前驱是 `nop`/`ret`）。
- 未证：若前一条指令属于**不可达代码**（例如紧随无条件 `jmp` 之后、被 padding 隔开的残段），顺流仍不成立。本卡排除了「padding 后接 jmp」的情形（pad_jmp 归入 T2），但未穷举「前一条指令本身不可达」的所有形态。

## U9 · 未做的第五通道（本卡判据之外，可能改变 T2 归属）
- **真机/动态**：EIP 采样、`_initterm` 式表遍历、硬件断点 —— 本卡为纯静态，未做（且需用户当轮明示授权）。
- **Ghidra 重跑**：atlas 是**下界**且 atlas ∩ 池 = **0**（12,916 个已知入口无一个落在本池），故 atlas 对本池零信息；重跑 Ghidra 也许能为部分 T2 建函数，但那属 P1。
- **`.detour` 段（0x B93000，27,18 B）**：本卡未扫（不在 .text/.data/.rdata 三段的通道定义内）。若里面有指向 .text 的指针表，通道 C 会漏。

## U10 · 数值口径
- `coverage.tsv` 数据行本卡实测 **18,479**（与 §9.0i 一致）；§9.1 的 B 分母（14,487）与 PANEL M50 表（14,535）的差异不在本卡范围，未处理。
- ENUM 的 `predecessor` 列在池内分布：`nop` 5,253 / `ret` 201 / `jmp` 119 / `int3` 23 / `retf` 2 —— 本卡的 D1 **不使用**该列（它是建池条件），只用现场字节重算，故与 ENUM 的取值可能不一致（例如 ENUM 记 `nop` 而现场 padding 后确有 `ret` 的行，本卡判 D1=1）。这类行数未单独统计。
