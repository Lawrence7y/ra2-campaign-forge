## 2 · §3.1 主路线：返回地址采样 → 反推派发站点

### 2.1 Q1 可行性：`StackWalk64` 在这个镜像上没有数据来源

**事实（盘上可核）**

| 检查 | 结果 | 依据 |
|---|---|---|
| `.pdata` 节 | **不存在** | 节表只有 `.text/.rdata/.data/.rsrc/.detour` |
| 异常目录（DIR[3]） | **RVA = 0** | `pe.OPTIONAL_HEADER.DATA_DIRECTORY[3]` |
| 调试目录（DIR[6]） | 只有 **1** 项，`Type=4 (MISC)`，272 B | 该 272 B 内容是**镜像头拷贝**（含 `MZ…This program cannot be run in DOS mode`），不含符号 |
| FPO / CodeView / OMAP 项 | **全都没有**（`Type=3/2/7/8` 均为 0 项） | 同上 |
| `.debug$F` 节 | **不存在** | 节表 |

⇒ `StackWalk64` 的帧信息来自 `SymFunctionTableAccess`（x86 上即 FPO/COFF 表）。**本镜像一张表都没有**，
所以从第二帧起没有可依的展开信息（**这是推理，本卡未真机验证**；可验证的字节事实是上面那张表）。

**实测帧指针比例**（前 8 条指令窗口内出现 `push ebp` + `mov ebp,esp`）：

| | 函数数 | 占比 | 字节 | 占比 |
|---|---:|---:|---:|---:|
| 有 EBP 帧 | 468 | **3.62%** | 380,117 | 11.78% |
| 无 EBP 帧（FPO） | 12,448 | **96.38%** | 2,845,728 | 88.22% |

另有 8,198 个函数（**63.5%**）≤128 字节 —— 小函数最不可能维护帧指针。

**失败量级（推理，非实测）**：链式展开要求「沿途每一帧都能取到下一帧」，96% 的帧断了链，
所以现实预期是**每次采样至多 1 个返回地址，且只在落入那 3.6% 的帧时可用**；
`(0.036)^k` 的形态意味着第 3 帧起基本为 0。如果按「函数计数的均匀先验」估，单帧成功率 ≈3.6%；
按「字节/时间加权」可能到 ~12%，但**这是推理，不是测量**（真实时间分布要真机才能测，本卡不做）。

**替代通道（我建议的，比 `StackWalk64` 稳）**：不展开帧，直接
`EIP + GetThreadContext(ESP) + ReadProcessMemory(栈窗口) + 返回地址精确匹配 site+len`。
它的精度来自「精确等于某条指令的结束地址」，不来自「走栈正确」。误报量级：

- 单个 32 位字命中 18,763 个候选返回地址之一：`4.37e-6`；
- 1 KB 窗口（256 字）：**0.11%**。

⇒ **结论**：`StackWalk64` 这条路在这个镜像上物理上没数据；要采样就改「精确匹配」，它不需要任何展开元数据。

### 2.2 Q2 判定规则（可执行伪代码）

```python
# ---------- 离线一次：静态预处理 ----------
sites = []
for insn in linear_sweep(TEXT, cs_arch=X86, mode=32, skipdata=True):
    o = insn.operands[0] if insn.mnemonic == 'call' and insn.operands else None
    if o and o.type == X86_OP_MEM:
        m = o.mem
        if m.base and m.index == 0 and reg_name(m.base) not in ('esp', 'ebp'):
            sites.append(Site(va=insn.address, size=insn.size,
                              disp=m.disp or 0, base=reg_name(m.base)))

sites = [s for s in sites if s.va in descent_confirmed_boundaries]  # 去伪（见边界情况 ⑦）
by_ret = { s.va + s.size: s for s in sites }                        # 返回地址 -> 站点

# ---------- 运行期：只读采样 ----------
每 Δ 毫秒，对游戏各线程：
    ctx  = GetThreadContext(tid)                      # 只读：EIP / ESP / EBP
    words = ReadProcessMemory(ctx.ESP, 1024)           # 只读：栈窗口
    for i, w in enumerate(words):                      # 从低地址（靠近 ESP）往高
        s = by_ret.get(w)
        if s:                                          # 精确命中：w == site + size
            record(thread=tid, site=s, depth=i)         # depth 越小越可信
            break                                       # 只取 innermost 一帧
        # 可选加强：若 ctx.EIP ∈ body(E) 且深度最小 -> 见 2.3「PC 锚」
```

**为什么不是 `R-1` / `R-5`**：

- 返回地址的物理值是 **`site + size`**（精确等式）。`R-1 ∈ [site, site+size)` 与 `R == site+size` **等价**（在 `R>site` 前提下），
  但它额外容纳「`R` 指向指令内部」的错位值 ⇒ 只能当**诊断容差**用，不能当主判据。
- **`R-5` 对本题是错的**：`R-5` 只对 `E8 rel32` 的 5 字节 call 成立；`call [reg+disp32]` 是 **6 字节**，
  `R-5` 落在位移字段中间，`call [reg]` 是 **2 字节**，`R-5` 直接跑到上一条指令里。
  本卡 18,763 个站点里，指令长度分布必须逐条取 `insn.size`，不能写死。

**边界情况逐条**：

| # | 情况 | 处理 | 实测依据 |
|---|---|---|---|
| ① | `call [reg]`（disp=0） | **计入站点，但身份判据作废**：1,212 张表在 offset 0 都有 entry，共 **889** 个不同值 | 813 个站点 / 714 确认 |
| ② | `call eax`（寄存器直接调用） | 不是内存操作数 ⇒ **不是表派发**，不进 census | — |
| ③ | `call [reg+idx*4+disp]` | **必须剔除**：disp 是表基址不是槽号，照它推会推错行 | 仅 **4** 个站点 |
| ④ | `call [m32]`（绝对地址，无基址） | 单列：这是「函数指针全局表」形态（4GAP 的 V3），不是 vtable 槽 | **3,833** 个 |
| ⑤ | `call [ebp+8]`/`[esp+8]` | 调函数指针参数，无表 | **137** 个 |
| ⑥ | 负 disp / 巨大 disp | 保留原值但标记；实测 1 个负值（`0x90909090`）后判定为伪站 | 见 ⑦ |
| ⑦ | **填充字节造伪站** | 必须递归下降确认：`0x90` 填充被解码成 `call [reg+disp32]`（disp=`0x90909090`），确认阶段被剔除 | 94.00% 通过率（16,143/17,174） |
| ⑧ | 内联/重复代码 | 不影响：站点按**地址**识别，同样的指令序列在不同地址就是不同站点 | — |
| ⑨ | 尾合并 / 共享尾声 | 站点仍是站点（观测到的「执行」为真），只是它服务的源码路径可能有多条 | — |
| ⑩ | **陈旧栈值** | 返回地址会在栈上残留 ⇒ 假「执行过」。缓解：只取**最靠近 ESP 的最小地址**一个，并附加深度阈值 | 误报 0.11%/KB（推理上界） |
| ⑪ | 非 RTTI 表（COM/函数指针结构体） | 站点可执行但**推不到 entry**：实测 6 个 disp 在活表里 0 个持有者 | `disp_stats.tsv` |
| ⑫ | 同一 (site) 被多行争抢 | 单值偏移天然唯一 ⇒ 不会发生；非唯一时**必须**按 `R14_COMMON` §8.6 条 1「site 不共用」判 | — |

> 类别计数：`all=22,736` = base-only **18,763** + 无基址-**绝对表** 3,833 + 栈基 137 + 带 index 4 − **1 个重叠**
> （`00756843  call [esi*4+0x846840]`：无基址且带 index，是「函数指针跳表」形态，`disp` 是表基址不是槽号）。
> 注意它与 ③ `call [reg+idx*4+disp]` 是**同一物理形态**，都不可用于 disp 推断。

### 2.3 Q3 槽归属：**不能闭合**

**结论一句：不能。** 差的不是「更聪明的走栈」，而是**「站点 → 哪张表 → 哪个对象」**这一环。

**为什么不能（三条，逐条可核）**：

1. **采样点 ≠ 调用点**（物理事实）。`GetThreadContext` 拿到的是**采样那一刻**的寄存器；调用点的 base 寄存器
   （`edx`/`eax`…）早已被后续指令覆盖。这不是实现问题，是采样观测的物理边界。
2. **即便拿到 site，也拿不到「base 指向哪张表」**。本卡实测了 17,174 个站点的基址定义点：

   | 基址来源（站点前最后一次写 base） | 站点数 | 占比 |
   |---|---:|---:|
   | `mov reg, [obj]`（off 0，= 接收者 vptr） | 15,446 | **89.94%** |
   | `mov reg, [obj+disp]`（多继承的次 vptr） | 942 | 5.49% |
   | `mov reg, [绝对地址]` | 532 | 3.10% |
   | 其它（`push`/`pop`/`reg_copy`/…） | 254 | 1.48% |

   ⇒ 九成站点的 base 就是**接收者对象的 vptr**。要命名它，必须先知道**这个接收者是什么类** —— 那正是环 ②。
   用 ④ 去推 ② 再反过来用 ② 定 ④，是循环论证（`R14_COMMON` §12.3、§8.6 条 1 已经为此判死过两批）。
3. **采样能给出的最强信息只是「site 执行过」**，它证明**可达性**，不证明**身份**。而 ④ 要的是身份。

**差什么（清单，给下一张卡）**：

- 缺 **(a) 逐站点的接收者类型**（value-set / 类型恢复，静态可达）；或
- 缺 **(b) 一个不依赖寄存器的身份锚**（见下）；或
- 缺 **(c) 该 disp 的全局值唯一性**（= 降级形态，实测只有 2 行）。

**补充一条卡面没提、但能绕开寄存器的链（我称「PC 锚」）**：

> 若某个采样点上，**最内层返回地址** `R == site + size`，**且**同一时刻 `EIP ∈ body(E)`，
> 则「`E` 是被该站点派发的」成立 —— 不需要 base 寄存器。

理由：`R` 是「当前正在执行的函数」的返回地址；它等于 site+size 说明该函数是**从该站点**进来的；
`EIP ∈ body(E)` 说明当前执行的就是 `E`。两条合起来就把身份钉住了。

代价与风险：① 必须采样**落在 `E` 体内**（`E` 往往很小，窗口短暂）；② 若 `E` 已经被它自己调的更深函数取代，`EIP` 不在 `E` 体内，本次采样只得到「site 执行过」；
③ `E` 无帧指针时只能靠栈窗口扫描（本卡的两个候选 `E` 恰好都无帧指针，见 §2.4）。

**这条链的上限 = 317 行**（详见 §5），是唯一比降级形态值钱的东西。

### 2.4 Q4 降级形态：单值偏移成立，但只换 2 行

**静态可判据（正式化）**：对 disp `d` 和 entry `E`：

```
H(d)        = { T ∈ 活表 : slot(T,d) ≠ 0 且 slot(T,d) ∈ .text }     # 该偏移的持有表
strict(d)   ⟺ |H(d)| == 1
value(d)    ⟺ |{ slot(T,d) : T ∈ H(d) }| == 1                       # 唯一 entry 值
派发(d)      ⇒ 被派发者 = 唯一的那个 slot 值
```

要把它用成**合规** ④，还要加三条（来自既有裁决，本卡不新造规则）：
(i) 装表点在 `E` 体外（`R14_COMMON` §8.6 条 1）；(ii) 该 site 不被两行共用；(iii) 若 `E` 名是 `Class::slotN`，
则 ② 本身就是这个槽 ⇒ 触 `§12.3`，只能按 **D-47(A) 裁决 + PANEL 披露**处理（`R14_COMMON` §12.6）。

**全量统计（`disp_stats.tsv`，342 个 disp 全列）**

| 判据 | disp 数 | 覆盖站点 | 不同 entry | 落在 coverage | 落在 `[已证]` | 落在**无 ④** 缺口 |
|---|---:|---:|---:|---:|---:|---:|
| `strict`（恰 1 张活表有 entry） | **1** | 2 | 1 | 1 | **0** | **0** |
| `value`（所有持有表值相同） | **84** | 1,245 | 84 | 84 | 5 | **2** |
| 边界确认后（16,143 站点）的 `value` | 79 | — | 79 | — | 5 | **2** |

**为什么 `strict` 只有 1 个**：持有者数分布是 `0→6 个 disp、1→1 个、2→2 个、4→18 个、5→13 个、6→144 个、8→32 个、21→64 个…`。

唯一的 strict 是 `disp=0x55C → 0x73B140`（`UnitClass::slot343`，`[静态推断]`，两个站点 `0073B470`/`0073C5F0`）——
**它不是 `[已证]` 行，对缺口贡献 0**。

**84 个 witness 的画像**（这是判断「值不值」的关键）：

| 维度 | 分布 |
|---|---|
| grade | `[静态推断]` **79** / `[已证]` **5** |
| 名字形态 | `Class::slotN` 占位名 **75** / 真名 9 |
| 已含 ④ | 3（⇒ 缺口只剩 **2**） |
| 结构共性 | 主要是**基类共享、子类不覆写**的槽（`TechnoClass +0x414/+0x418/+0x41C/+0x444`、`AnimClass slot84` 等）：偏移落在只有 6 或 21 张长表够得着的位置，且这些类族共用同一实现 ⇒ 值自然唯一 |

⇒ **降级形态在逻辑上成立**（确实存在「只凭 disp 就能命名 entry」的情形），但它的产物恰好是
**本来最容易证明、且大多已经证过**的那批（5 个 `[已证]` 里 3 个已有 ④）。

**两个真缺口候选（这就是 §4 乐观值的全部）**：

| disp | entry | 行 | 现象 | 站点所在函数 | 被派发者有无 EBP 帧 |
|---|---|---|---|---:|---|
| `0x444`（slot 273） | `00706640` | S10 `AircraftClass::slot273` `[已证]`，4GAP 类 `F4:census_no_ring4` | 6 张表该槽同值 | 5 站点 @ `0043DA80` | **无**（`sub esp,0x11c`） |
| `0x41C`（slot 263） | `0070B570` | S10 `TechnoClass::ClampAndAdvancePairedFloatState_behavior` `[已证]`，4GAP 类 `F2` | 6 张表该槽同值 | 1 站点 @ `006F9E50` | **无**（`sub esp,0x10`） |

## 3 · §3.2 备选路线：`MiniDump` 事后取证

**结论：不解决问题，只是把「采样」换成「事后」。** 它拿到的是同一份「采样点栈 + 采样点寄存器」。

| 维度 | 评价 |
|---|---|
| 能不能给出「栈」 | 能。`MiniDumpNormal` 含线程上下文 + 栈内存（以及模块列表） |
| 能不能解决 Q3 | **不能**。dump 里的寄存器同样是采样点寄存器，调用点的 base 早已覆盖；dump 里没有「调用点寄存器」这种东西 |
| 与 2.1 比 | 误报率/精度完全一样（都靠「返回地址精确匹配」）。dump 的好处是**可离线反复看**、可保存证据、可多人复核 |
| 触发时机 | 这是大问题：`MiniDump` 通常要在异常/退出时落盘。卡面禁止写进程、禁止下断点 ⇒ 只能依赖游戏自带的顶层过滤写 `except.txt` 后退出，或外部定时 `MiniDumpWriteDump` |
| 额外代价 | `MiniDumpWriteDump` 内部会挂起目标线程（不是写内存，但**改变进程执行状态**）⇒ 需单列授权（见 §7 的 N1） |
| 对收益的影响 | **零**。上限仍是 317，降级形态仍是 2 |

**唯一值得保留的用法**：把「一次会话的原始证据」落盘（`MiniDumpNormal` + 自己的采样日志），
让**同一份证据可以被审计员离线复核**——这与项目「执行员不自审」的纪律一致。但这不产生新行。

## 4 · §3.3 负结果：逐条判死（越界在哪 / 为什么物理不可行）

| # | 方案 | 判定 | 越界点 / 物理原因 |
|---|---|---|---|
| 1 | **软件断点**（把 `0xCC` 写到目标地址） | **出局** | 写 `0xCC` = `WriteProcessMemory` ⇒ **写进程内存**，禁区（卡面 §2 明写本卡不得假设可用） |
| 2 | **硬件执行断点**（DR0–DR3） | **出局** | `D-36`（2026-11-19）已入账：命中时 CPU 在执行前抛 `#DB`，无人处理 ⇒ 未处理异常 ⇒ **进程终止**；游戏自带过滤则写 `except.txt` 后退出。**首次命中即终结游戏**，不是「最小只读扩展」。另外设置 DR 要 `SetThreadContext` ⇒ 也是写 |
| 3 | **`DebugActiveProcess` + 断点** | **半出局** | attach 本身有 D-48 授权，但「调试器 attach」**不等于**可以下断：断点要么写 `0xCC`（禁区）、要么写 DR 寄存器（禁区 + `D-36`）。attach 后能做的只有 `ReadProcessMemory`/`WaitForDebugEvent` 旁观，而旁观拿不到同步点，时序上等于本卡的轮询采样 |
| 4 | **DLL 注入 / inline hook** | **出局** | 禁区（卡面 §2 逐字列出） |
| 5 | **`PAGE_GUARD`（页守卫）** | **出局** | 改页保护 = `VirtualProtectEx` ⇒ **写进程内存**；且 `STATUS_GUARD_PAGE_VIOLATION` 的处理器必须在目标进程内（注入）⇒ 二次越界 |
| 6 | **单步 `TF`（Trap Flag）** | **出局** | 要 `SetThreadContext` 写 EFlags ⇒ 写线程上下文（`D-36` 已判不可行）；且单步整个游戏不现实 |
| 7 | **只读 attach + 轮询寄存器**（合法） | **可用但无用** | 不越界，但**拿不到调用点寄存器**（Q3），只能得到「site 执行过」 |
| 8 | **ETW / 内核栈采样 / 采样分析器** | **出局** | 需要驱动或管理员特权 + 系统级 hook，超出「只读本进程内存」的授权语义 |
| 9 | **改 `ra2youli\` 下任何文件**（如换 exe 打点版） | **出局** | 禁区逐字列出 |
| 10 | **`StackWalk64` 直用** | **不可用（非越界）** | §2.1：镜像无任何展开元数据；不是授权问题，是没有数据 |

## 5 · §4 收益上限估计

### 5.1 先复算盘上现状（不照抄卡面）

| 项 | 卡面 | 本卡独立复算 | 结论 |
|---|---:|---:|---|
| `[已证]` | 1,654 | **1,654** | ✓ |
| 口径 A（含 ④ 字样） | 375 | **375** | ✓ |
| 口径 B（`④ 活表槽位见证`） | 210 | **210** | ✓ |
| 完全无 ④ | ≈1,279 | **1,279** | ✓ |

复算脚本 `count_cov.py`；截面 `coverage.tsv` sha256 `3A1DC1DD3F67B7684BF167640CEECF3EC85330CF5B54C31B65A02CA98C993D4A`（4,079,053 B / 18,498 数据行）。
注：`coverage.tsv` 第一行是逗号表头（历史遗留），按 TAB 切会得到 1 个伪行 —— 复算时必须跳过，否则行数差 1。

### 5.2 结构性天花板：1,279 里 962 行根本不在任何活表槽位上

| 集合 | 行数 | 占 1,279 |
|---|---:|---:|
| 缺口 | **1,279** | 100% |
| ⇒ entry **从未出现在任何活表的任何槽位**（⇒ 没有任何 `call [reg+disp]` 站点能派发它） | **962** | **75.2%** |
| ⇒ entry 落在「至少一个有站点的偏移」上（动态派发的**理论**上限） | **317** | 24.8% |

这 962 行**没有任何一行被活表槽位持有**（复核：`held_by_live_slot = 0`），名字形态是真名 **931** / `sub_XXXXXXXX` **31**，
**没有一行是 `Class::slotN`** ⇒ 它们不是「活虚表上的虚函数」（自由函数、静态方法，或只出现在死表/未装表里的方法），
④ 只能靠 **direct call** 通道，动态派发通道对它们**结构性无效**。
（这与 `R16_PROBE_4GAP` 的 V1=0 相互印证。）用 canonical 表长复核，两套长度给出**完全相同**的 317/962。

### 5.3 317 行的歧义有多大（为什么它不能自动变成收益）

| 项 | 数 |
|---|---:|
| 覆盖 317 行所需的 disp 数 | **85** |
| 这些 disp 下的站点数 | **13,999** |
| 最肥的几个 disp | `0x30`(slot12) 45 行 / 90 个候选 entry；`0x2C`(slot11) 39 行 / 91 个；`0x0C`(slot3) 17 行 / **732** 个；`0x00`(slot0) 14 行 / **889** 个 |

⇒ 317 行的身份**全靠逐站点的接收者类型**（§2.3 缺的那一环）。**不知道表，就等于不知道 entry。**

### 5.4 两种口径（这是卡面要的两个数）

**假设清单**（两个口径共用）：① 只统计 1,279 行缺口；② 降级形态按 `value` 判据（`strict` 只有 0 行更没戏）；
③ 采样落在被派发者体内才算观测到（PC 锚或返回地址匹配）；④ 接受的证据形态按 D-47 披露（slot 同源需披露）。

| 口径 | 行数 | 占 1,279 | 假设 |
|---|---:|---:|---|
| **保守** | **0** | 0.00% | 其中 1 行（`00706640`）名字就是 `slot273`，② 与 ④ 同槽，D-47 披露下才算；两行的被派发者都无帧指针，只能用栈窗口扫描；一次会话能否命中这 6 个站点无法先验保证 ⇒ 记 0 |
| **乐观** | **2** | **0.16%** | 6 个站点在目标会话里真的执行、采样至少各命中 1 次、且两行的 ②/③ 都维持现判（4GAP 记 `F2` 与 `F4:census_no_ring4`，均无 `[未证]` 自陈） |

**采样量不改变这个数**（这点必须讲清楚）：

| 采样规模（10 分钟） | 观测到的不同站点（期望） | 可换来的行数上限 |
|---|---|---|
| 20 Hz（12,000 样本） | ≤ 12,000，实际远少（每次至多 1 个 innermost 站点，且大多数样本落在非派发指令上） | **2** |
| 100 Hz（60,000 样本） | 同上 | **2** |
| 1000 Hz | 同上 | **2** |

⇒ 收益被**歧义**卡死，不是被**采样率**卡死。要突破 2，必须去解 §2.3 缺的那一环（静态类型/数据流），
那是**另一张卡**，而且它一点真机也不需要 —— 上限 **317 行**（85 disp / 13,999 站点）。

### 5.5 一次游戏会话能覆盖多少 `.text`（卡面要求说清）

**不可静态测算**，这是本卡的诚实结论：`.text` 有 18,763 个站点，但一个站点只在**被调用的那一瞬**存在；
「覆盖率」在这个问题里不是几何量而是**时间量**。可给的只有上下界：
上界 = 12,000 个样本 → 至多 12,000 次站点观测（含大量重复）；下界 = 0（若会话不触发相关子系统）。
**无论上界下界，可换的行数都是 0–2。**

## 6 · 如果只能做一件事，做哪件

**建议：不做动态 ④。下一张卡做 `R16_PROBE_4GAP` §3.3 指的 `F1` 转写（76 保守 / 108 乐观）。**

三条理由，按权重排：

1. **收益差 40–50 倍**：F1 = 76–108 行；本路线 = 0–2 行。而且 F1 的证据**本来就躺在**
   `NAMED_PUSH_AUDIT*/verdict.tsv` 的 `ring4_at` 列里，是**文档转写**，不碰二进制、不碰真机。
2. **动态路线已经被结构性判死到 2 行**（§5.2–5.4）：75.2% 的缺口不在任何活表槽位上，剩下 24.8% 的歧义是 2–889 个候选。
   再多的采样也改不了这两个数。
3. **风险面**：动态路线唯一能拿到的东西（「site 执行过」）在现行判据里**不是必需的**——
   `D-43(A)`（`R14_COMMON` §8.8 条 4）明确写「**不要求存在真实的 `call [reg+disp]` 派发点**」。
   花真机预算去证明一个判据不要求的东西，是负收益。

**如果 Lead 一定要在 ④ 这条通道上推进**，那么唯一值钱的下一步是：
**静态逐站点基址溯源**（85 个 disp / 13,999 站点，上限 317 行，**零真机**）。
它的产物是「站点 → 接收者类」的映射；一旦成立，317 行可一次成批补 ④。但这是研究型卡（值集分析），不保证命中率，
