### 二、本卡最强弱点：EIP 分桶对本镜像无判别力（核心，务必写透）

审计裁决 `PARTIAL` 的统计批评集中于此：本卡采样密度**不足以支撑「出现 / 未出现」的二分判定**。故执行员「预期每帧 callee 5 个中出现 3 / 未出现 2」的 headline **不成立**，应判 `[未证]`。证据：`S01-V1\_audit\VERDICT.md` §B、§一表 4；`S01-V1\EVIDENCE\eip_raw_hist.tsv`、`S01-V1\EVIDENCE\stack_dense.ndjson`、`S01-V1\EVIDENCE\analysis_summary.txt`、`S01-V1\_audit\recheck_out.txt`。

**(1) EIP 列零判别力。** 全部 1,352,400 样本中 `.text` 仅 **2496** 个（0.18456%），散在 **654** 个桶（均值 **3.82**、中位 **1**、**65.6% 的桶只有 1 个样本**）。EIP region 命中 **4 / 2 / 0** 属**噪声量级**，且与栈结论**自相矛盾**：EIP 显示 `0x48C8B0` 命中 **0**，栈显示 **3**。⇒ EIP region 列应标注「无判别力」或删除（必改 ①）。

**(2) 承重的是栈，且零命中是真零。** 94744 次栈迭代中 **94739 次（99.995%）** 落在 `0x48CE8F`（`0x55D360` Sleep 帧限速内），只有 **5 个非 Sleep 样本**（`0x48CEA1` = 3、`0x48CEA6` = 2）。行数 = 迭代数、`t` 全唯一（94744/94744）⇒ 逐次各 1 命中、无丢样，故 0 命中是**真零**。

**(3) 检出下限计算（关键）。** 0 命中的 95% 上界 = 2.996 事件 ⇒ 未捕获函数每帧占用 **< 1.011 µs**（每帧 31.98 ms）。功效反演：每帧 t 秒的期望命中 = `(t / 31.98 ms) × 94744` ⇒ 50 ns:0.15、**500 ns:1.5**、**1 µs:2.96**、5 µs:14.8。即 **对 ≤1 µs/帧 的短函数，「每帧调」与「从不调」都会给出 0 命中**；87 B / 144 B 短例程（10–100 ns）期望仅 0.03–0.3 次，观测 0 对此**几乎零信息**。

**(4) 统计检验不显著。** k=3 占比 95% CI `[6.5e-6, 9.3e-5]` 与 k=0 `[0, 3.2e-5]` **重叠**；等曝光泊松条件检验**双侧 p = 0.25**。

**(5) 结论与方向性修正。** 综上**不能**得出「这 3 个在跑、那 2 个不在跑」——该判断应为 `[未证]`。可写的上界是：「3 个至少各执行过 1 次 `[已证]`；另 2 个 0 命中 ⇒ 每帧占用 < 1 µs `[已证上界]`，是否每帧调用 `[未证]`」。**而且**：`0x7241A0`（`0x48CE5D`）、`0x69BAB0`（`0x48CE85`）的 call site 实际位于**外层循环**（在内层回边 `0x48CEA8→0x48CE8A` 之上），命中率应为 **3/3 而非 3/5**（执行员在 DISAGREE D2 已发现该结构，但 #3/#4 的 headline 未跟着改）——这是对执行员结论的方向性修正。
