### 核心结论（卡面重点问的那一条）：`*_report.md` 与 `*/REPORT.md` 可否机械区分？

**可以机械区分，但"可机械区分"≠"有意义"，而且这个区分在盘上的实际行为是荒谬的。**

(1) **机械上：可分。** `measure_clean.py:68` 用的是 `fnmatch.fnmatch(base.lower(), "*_report.md")`——`*` 通配任意串（**含空串**），所以三种 basename 的命运不同：

- `report.md` → **不匹配**（长度 9 < `_report.md` 的 10，`*` 至少吃 1 个字符，没有这个字符）→ 保留。
- `_report.md` → **匹配**（`*` 吃空串）→ 被排。
- `REPORT.md` → `:68` 先 `.lower()` 再比，`report.md` 同样不匹配 → 保留。
- `xxx_REPORT.md` → lower 成 `xxx_report.md` → **匹配** → 被排。这就是 `falsifiable_no_relax_20261109/_fnr_REPORT.md`（43,390 B）、`needle_norm_20261109/_nn_REPORT.md`（40,549 B）等**大写**文件被排掉的原因。

⇒ 机械上，判据就是「basename 小写后以 `_report.md` 结尾」。**`REPORT.md` 与 `*_report.md` 的差别是"`report` 前面有没有一个下划线（且下划线前至少要有一个字符）"，这是一个纯粹的字面差异，`fnmatch` 判得干净利落、零歧义、零人工。**

(2) **但这个判据在盘上判出来的东西是反的。** 我实测档 A→C 的三组数字：

```
档 A  basename == REPORT.md（不分大小写）  = 208 个
档 A  basename 匹配 *_report.md           =  72 个
档 A  basename 含 'report'（任意扩展名）   = 760 个
档 C  basename == REPORT.md               = 208 个（全部保留，0 个被排）
档 C  basename 匹配 *_report.md            =   0 个（全部被排）
```

**被排的 72 个里，最大的是 43,390 B 的 `_fnr_REPORT.md`；被留的 208 个里，最大的是 `next_re_20261117_r14\R17_R19_RTTI_XCHECK\REPORT.md` = 49,887 B。两者的文体、作者、生成方式、内容类型完全相同**——都是"本线自己的实验报告"，都在 `next_re_20261117_r14\` 下，都是执行员写的。唯一的差别是文件名有没有下划线。报告 `:78` 用「无 `_report` 后缀」作为**对**的证据，这句话在盘上是**自相矛盾**的：一个文件是不是"对我自己工作状态的记录"，取决于它名字里有没有那个下划线。

(3) **更严重的是：这个区分在盘上导致"证据被算进语料、同质报告被算进语料"。** `next_re_20261117_r14\R14_COMMON.md`（311,946 B）、`STATUS_BOARD.md`（43,172 B）、`BOARD_ARCHIVE.md`（462,184 B）**全部留在档 C 里**，它们被 F24 自己点名引用为证据（见 Q6）。而 `_r37\ledger_1077.md`（7,796 B）因为目录叫 `_r37` 被排掉。⇒ 判据把「台账当前版」算成事实，把「台账旧版」算成产物；把「`R14_COMMON.md` 的 §2.28」算成事实，把「同样是 §2.28 的草稿 `_r40/s228_DRAFT_not_appended.md`」算成产物（后者不在档 A 里，见 Q4 说明为何）。

**Q1 裁定：判据 1 可机械执行；判据 2 与判据 3 靠人看名字，且代码只落地了其中一小部分，落地的部分与文字自相矛盾。`*_report.md` vs `*/REPORT.md` 在 `fnmatch` 层面可分，但这个"可分"是字面巧合，不是语义区分——它把 208 个同质报告留在语料里、把 72 个同质报告剔除，判定方向与"是否自身产物"无相关性。**

## Q6 · 这个档 C 能不能作为 `F24` 的引用值

先看 F24 现在**实际怎么写**（`R17_R74_FACTINDEX_V516\FACT_INDEX.tsv:25`，我逐字读的）：

理由（按严重性排序，每条都对得上上面的实测）：

1. **它的口径脚注是错的。** F24 写「仍含 384 个 / 258,794,083 B 的其它回滚副本」，盘上实测是 **333 个 / 184,506,382 B**（执行员的同一正则、同一张清单）。差 51 个 / 74,287,701 B。**引用值自带一条错的口径说明，比不带口径更危险**——它给了读者假的确定感。
2. **它的定义依赖一条已被证明自相矛盾的判据。** 判据 3 的 `*/REPORT.md` 不算 vs `*_report.md` 算，在盘上表现为 208 个同质报告留在语料、72 个同质报告剔除（Q1）。**一个"干净语料"定义，如果同一份东西换个文件名就从"脏"变"干净"，它就不能进 FACT_INDEX。**

- **(C) 重做档 C，换成可机械、可判据的规则**（见 OVERALL 建议）。
