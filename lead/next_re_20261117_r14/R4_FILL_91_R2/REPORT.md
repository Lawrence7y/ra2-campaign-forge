## 7 · 取数方法论（六个字段各自怎么测出来的）

| 字段 | 测法 | 校验 |
|---|---|---|
| vt（虚表地址） | `.rdata`+`.data` 全扫 `dd <entry>` 命中；由命中处每 4 字节回走，取最远的「`u32(vt-4)` 是合法 COL」的地址为表起点 | `u32(vt+slot*4)==entry` 回读 |
| 槽号 | `(hit - vt)/4` | 同上；并与 `all848.tsv` 逐行对账（0 处不一致） |
| COL | `u32(vt-4)` | `COL.sig==0`；`COL+0xC` 落在镜像内 |
| TD | `u32(COL+0xC)`（**绝对 VA**） | `TD+8` 按**内联串**读，须以 `.?A` 开头，再正则 `^\.\?A[VU](...)@@$` 去修饰 |
| 装表点 | capstone 5.0.7（`skipdata=True`）线性反汇编 `.text`，收 `mov [reg|abs], imm32` 且 imm 落在镜像内 | 指令尾部 4 字节 == vt |
| 构造器 entry | 装表点所在函数的起点：在 0x800 字节窗口内取「有独立锚点（atlas 函数起点 / `call rel32` 目标）或紧邻 `0x90`·`0xCC` 填充 / 前一条指令是`ret`·`jmp`·`int3`」的 16 字节对齐候选，由小到大做**控制流遍历**（跟条件跳转、不跟 call、遇 ret 停），取第一个能到达装表点者；若该遍历体内另有更强锚点也含装表点，则下潜一层（排除尾跳转并入；本卡 0 次触发） | 遍历体必须含装表点；装表点必须不在行 entry 的遍历体内；且从宿主到装表点之间没有 `jmp`（本卡 0 行有跨函数跳转风险）；`coverage.tsv` 里该宿主 entry 的**名字**交叉印证（91/91 行命中，多为 `XxxClass::XxxClass` 构造器） |

宿主判定分布：anchor 85 行、pad 6 行。

> 说明：`anchor` = 该起点是 atlas 函数起点或 `call rel32` 目标（两种独立来源）；`pad` = 仅靠「前有 ≥2 字节 `0x90`/`0xCC` 填充」定界。`pad` 的 6 行我逐行反汇编看过入口字节与前一条指令（`004A8630` / `0040CB80` / `005C93E0` / `006CF070`，各见其 `evidence/ROW_*.txt` §5）。

> **锚点为什么不含 `.rdata`/`.data` 里的指针**：实测存在指向函数体**内部**的 dd（如 `005C5D03`，它其实是 `call 0x5D5B60` 指令的地址），把它当函数起点会把宿主判错——我第一版就踩到：4 行的宿主被判成 `005C5D03`、1 行被判成 `004D33CC`（都不是函数起点）。排除之后 91/91 行的宿主在 `coverage.tsv` 里都有名字，交叉印证通过。

### 为什么不用 `W130_atlas/function_atlas.tsv` 单独定界
