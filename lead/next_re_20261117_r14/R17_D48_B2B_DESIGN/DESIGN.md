## Q1 · D-48 + D-36(A) 双重约束下，调试器实际还剩哪些观测通道

### 1.1 先把类型列全：**9 个 `DEBUG_EVENT`，不是 8 个**

卡面列了 8 个类型，漏了 `UNLOAD_DLL_DEBUG_EVENT`。完整枚举（`DEBUG_EVENT.dwDebugEventCode`）：

| # | 事件 | 能观测到什么 | 不能观测到什么 | 能否证明「某条具体指令被执行过」 |
|---|---|---|---|---|
| 1 | `EXCEPTION_DEBUG_EVENT`(1) | 第一/第二机会异常：`ExceptionCode`、`ExceptionAddress`、读写地址、`ExceptionFlags`、线程 id、`dwFirstChance`。attach 瞬间必然收到一次 OS 注入的 `EXCEPTION_BREAKPOINT`（初始断点，位于进程入口） | **普通指令执行不产生任何事件**。不装断点时，本工程关心的代码路径**一次都不会**触发本事件 | **否**。除非恰在 `0x47C738` 上装了断点，而装断点=禁区（见 §1.3） |
| 2 | `CREATE_THREAD_DEBUG_EVENT`(2) | 线程创建：`hThread`、`lpThreadLocalBase`(TEB)、`lpStartAddress`。attach 时对**所有既存线程**补发一遍 ⇒ 可用于枚举线程集合 | 线程内部执行了什么 | **否** |
| 3 | `CREATE_PROCESS_DEBUG_EVENT`(3) | attach 时发一次：`hProcess`、`hFile`、`hMainThread`、映像基址、`lpStartAddress`。**这是唯一可靠的「模块基址」来源** | 任何执行信息 | **否** |
| 4 | `EXIT_THREAD_DEBUG_EVENT`(4) | 线程退出码 | 执行信息 | **否** |
| 5 | `EXIT_PROCESS_DEBUG_EVENT`(5) | 进程退出码 | 执行信息；且只在终结时到达 | **否**（但可判定「游戏是不是崩了」，见 Q5） |

| 7 | `UNLOAD_DLL_DEBUG_EVENT`(7) | DLL 卸载 | 执行信息 | **否**（卡面未列，本卡补齐） |
| 8 | `OUTPUT_DEBUG_STRING_EVENT`(8) | **仅当**目标进程调用 `OutputDebugStringA/W` 才发 | —— | **否**；且见下方「本通道在本镜像上静态不可用」 |
| 9 | `RIP_EVENT`(9) | 调试器自身/系统的调试错误（`dwError`、`dwType`） | 目标进程执行信息 | **否** |
| 10 | **挂起/`GetThreadContext` 采样** `EIP/ESP/EBP` | **采样瞬间**的 `EIP`、`ESP`、`EBP`、通用寄存器、`Dr0–Dr7`（只读）。配上 `ReadProcessMemory` 读栈窗口，可得到「采样瞬间 `EIP` 落在区间 `[A,B)` 内」+「栈上存在值为 `X` 的 dword」 | 采样点**之间**发生的一切。**采样点不是调用点**，寄存器早已被覆盖（这一点 `R16_DESIGN_D48` §2.1 已给同类结论） | **否**（不能证明「某条指令」）；但**能**证明「某函数在采样瞬间正在执行」，再配栈窗口可证明「直接调用者是谁」 |

### 1.2 `OUTPUT_DEBUG_STRING` 在本镜像上静态不可用 —— `[本卡只读复核]`

### 1.3 为什么「证明具体指令被执行」在本卡约束下是 **0 个通道**

要让调试器知道「`0x47C738` 这条 `call` 执行了」，只有三条物理途径，全部出局：

| 途径 | 机制 | 卡面边界 | 结论 |
|---|---|---|---|
| 软件断点 | 向目标进程写 `0xCC`（`WriteProcessMemory` / `VirtualProtectEx`） | **写进程内存 = 禁区** | 出局 |
| 硬件执行断点 | `SetThreadContext` 置 `Dr0–Dr3` + `Dr7` | **D-36(A) 明令「不写线程上下文」**（卡面 §2：仍有效、未被 D-48 撤销） | 出局 |
| 单步 | `SetThreadContext` 置 `EFLAGS.TF` | 同上 | 出局 |
| 页保护 | `VirtualProtectEx(PAGE_GUARD)` 造 `STATUS_GUARD_PAGE_VIOLATION` | 改目标进程内存属性 = 写进程内存的同类；且会破坏游戏正常运行 | 出局 |

⇒ **D-48 授权的是「调试器身份」，不是「打断点的权利」。** 无断点 ⇒ 无指令级事件 ⇒ **`DEBUG_EVENT` 九类对 ②-b 的贡献恒为 0**。

## Q2 · 有没有只读可观测的内存副作用能区分两条路径

### 2.1 先把「两条路径」写成同一棵调用树（这是全卡的地基）

按 `[已入账]` §2.6 + `[本卡只读复核]` 的返回地址，两条路径的**闸核是同一个函数**：

```
P1（can-place 层）  0x43F180 ─0x43F218 call [esi+0x1AC]→ 0x449440 ─0x449482─┐
P2（逐格层）        0x43F180 ─0x43F2AE──────────────────────────call 0x47C620 ─┐
                                                                        ↓      ↓
                                                          0x47C620 ─0x47C738 call 0x47C3D0
                                                                    （bit0 闸核，同一个）
```

返回地址（`[本卡只读复核]`，逐字节核过，见附录 A）：

| 调用点 | 指令字节 | 返回地址 |
|---|---|---|
| `0x43F218` `call dword ptr [esi+0x1AC]` | `ff 96 ac 01 00 00`（6 B） | `0x43F21E` |
| `0x43F678` `call dword ptr [esi+0x1AC]`（§2.4 记的 second site） | `ff 96 ac 01 00 00`（6 B） | `0x43F67E` |
| `0x449482` `call 0x47C620`（can-place 内） | `e8 99 31 03 00`（5 B） | **`0x449487`** |
| `0x43F2AE` `call 0x47C620`（逐格内） | `e8 6d d3 03 00`（5 B） | **`0x43F2B3`** |
| `0x47C738` `call 0x47C3D0` | `e8 93 fc ff ff`（5 B） | `0x47C73D` |
| `0x47C805` `call 0x47C3D0`（第二闸） | `e8 c6 fb ff ff`（5 B） | `0x47C80A` |

⇒ **关键结构性判断**：两条路径在闸核内部**完全重合**（同一个 `0x47C620`、同一个 `0x47C3D0`、同一套 bit0 判据、同一份 `[cell+0xE4]` 链）。它们唯一的差别是**谁调用了 `0x47C620`**。这个判断直接决定了下面四类候选的全部结论。

### 2.2 逐条评估卡面四类候选

#### ① `0x449440` 的短路条件（`[BType+0x408]`、`[build+0x74]`）被求值时是否留下痕迹

`[本卡只读复核]`（依据已在盘上的 `GATE_BEHAV/EVIDENCE/resolve_canplace.txt`，本卡对 `0x449493` 支路补核）：

```
00449447  mov eax,[ecx+0x520]     ; BType*
00449451  mov edx,[eax+0x408]     ; 纯读
00449457  test edx,edx            ; 纯算
00449459  je  0x449493            ; 短路支路（不是 return 7，见附录 A/D-2）
```

- 两个条件全部是**寄存器级纯读**：无写、无计数器、无标志位落地、无缓存更新。
- 短路支路 `0x449493` 也不是「直接返回 7」，而是改调 `BType` 的 `call [edx+0xA8]` 谓词（`[本卡只读复核]`），同样**零非栈写**。

⇒ **结论：不可区分。** 理由：求值过程只经过通用寄存器与标志寄存器，卡面允许的只读手段在函数返回后拿不到任何残留。

#### ② 两路径的调用次数/遍历次数是否在某个可读计数器/字段上留下差异

| 事实 | 分级 | 依据 |
|---|---|---|
| 一次 `0x43F180` 调用内：P1 至多 1 次 `0x47C620`（can-place 内）；P2 至多 `N` 次（`N` = footprint 格数）⇒ **次数确实不同** | `[本卡只读复核]` | `0x43F210`/`0x43F2AE` 均在该函数体内 |
| `0x47C620` 体内**非栈写 = 0**（全部写入都是 `[esp+…]`，逐条核过 12 条 `mov [esp+…]`） | `[本卡只读复核]` | `S02B_GATE/EVIDENCE/fresh_47C620.txt` |
| `0x47C3D0` 体内**非栈写 = 0**（写入全为 `[esp+0x13/0x14/0x18/0x24/0x28/0x44]`） | `[本卡只读复核]` | `S02B_GATE/EVIDENCE/fresh_47C3D0.txt`（107 条逐条核） |
| `0x449440` 体内**非栈写 = 0**（唯一写是 `mov [esp+4],edx`，栈上影子存） | `[本卡只读复核]` | `GATE_BEHAV/EVIDENCE/resolve_canplace.txt` |
| 唯一形态像计数器的是 `[0xA8E7AC]`（`r=192 w=95 incdec=5`，**dword 计数而非 bool**）；但到达 `0x47C738` 的前提就是它 `==0`（非 0 直接 `0x47CA70` 放行）⇒ 在闸运行时它恒为基线值 | `[已入账]`（`0x47C632` 判据）+ `[已入账]` 计数形态（GATE_BEHAV 第一步表） | `R14_COMMON` §2.6 · GATE_BEHAV PROGRESS |
| 这 5 处 `incdec` 的**地址**是否落在 `0x43F180` / `0x449440` / `0x47C620` / `0x47C3D0` 体内 | `[未取得]` | **请求项 R2** |

⇒ **结论：不可区分。** 理由是**结构性的**，不依赖 R2：两条路径共用同一个 `0x47C620`，任何「在 `0x47C620` 内部自增」的计数器对两条路径都同样 +1，只能反映总次数；而总次数只存在于栈上（`[esp+0x1c]` 循环计数、`[esp+0x14]`/`[esp+0x18]` 最近距离缓存），函数返回即失效。补上 R2 也不会翻转，只能把「不可区分」从「结构性排除」升级为「逐条排除」。

#### ③ 格对象双链头 `[cell+0xE4]`/`[cell+0xE8]` 的遍历是否产生可读中间态

| 事实 | 分级 |
|---|---|
| 遍历只读 `[ecx+0xE4]`（选择子 0）/ `[ecx+0xE8]`（选择子非 0）、`[esi+0x14]`、`[esi+0x30]`（next）、`[esi]`（vptr）；**链头与节点的 next 指针均无回写** | `[本卡只读复核]`（`fresh_47C3D0.txt` 107 条逐条核） |
| 遍历唯一的「输出」写进栈局部：`[esp+0x14]`（最近对象指针）、`[esp+0x18]`（最近距离） | 同上 |
| 链长、遍历次数、是否走满 → 不落在任何可读堆/全局字段 | 同上 |

⇒ **结论：不可区分。** 排除对象（arg3）传入的是常量 0（§2.6 已入账），链遍历是纯函数式扫描，无可读中间态。

#### ④ 是否存在只在其中一条路径上发生的写（哪怕 1 bit）

| 事实 | 分级 |
|---|---|
| `0x449440` / `0x47C620` / `0x47C3D0` 三个函数体内**非栈写合计 = 0**（逐条核过；沿途被调函数 `0x5657A0` / `0x47C4D0` / `0x568300` / `[vt+0x48]` **未逐条核** ⇒ R1） | `[本卡只读复核]` |
| 两条路径在闸核内是**同一个函数**，故「同样会发生的写」也不是差异来源 | `[已入账]` + `[本卡只读复核]` §2.1 |

⇒ **结论：不可区分。** 拒绝路径在**非栈内存上零足迹**——这是一个比「有写但难读」更强的结论：本来就没有差异可读。

### 2.3 但存在一个**不在「副作用」范畴内**的可区分通道（本卡最重要的一条）

四类候选全部落在「内存副作用」里，答案都是「不可区分」。**差异不在内存副作用，而在栈上的调用者返回地址**：

| 观测对象 | 是什么 | 能否区分 |
|---|---|---|
| 线程栈上 `ESP` 以上某个 dword `== 0x449487` | 「`0x449440` 在 `0x449482` 调用了 `0x47C620`」的实证（该返回地址**只有**这一个产生点） | **能** |
| 同一窗口内 `== 0x43F2B3` | 「`0x43F180` 在 `0x43F2AE` 调用了 `0x47C620`」的实证 | **能** |

三点必须同时说清，否则会被误读成「有确定性通道」：

1. **它不是「副作用」**，是**瞬态调用栈内容**。栈是内存，但它在函数返回后被覆盖，不是可回读的状态残留。
2. **它是概率性通道**：只有在采样瞬间线程正处在 `0x47C620`/`0x47C3D0` 体内（或栈上该帧尚未被覆盖）才能读到。窗口是**微秒量级**，命中率必须实测（Q4 的 Stage 0）。
3. **它不需要 D-48**：`GetThreadContext` + `ReadProcessMemory` 属常设只读授权，attach 前后能力相同。**D-48 没有为它增加任何东西。**

### 2.4 Q2 结论汇总

| 候选 | 结论 | 一句话理由 |
|---|---|---|
| ① 短路条件求值痕迹 | **不可区分** | 纯寄存器读，零落地 |
| ② 调用次数/遍历次数落在可读计数器 | **不可区分**（结构性；R2 只能加强，不能翻转） | 两路径共用同一函数，内部计数对两者等价；总次数只在栈上 |
| ③ 双链头遍历中间态 | **不可区分** | 遍历纯读，链头与 next 无回写 |
| ④ 只在一条路径上发生的写 | **不可区分** | 三函数非栈写 = 0（链尾被调函数见 R1，不影响结论） |
| ⑤（本卡追加，**非**副作用范畴）栈上调用者返回地址哨兵 `0x449487` / `0x43F2B3` | **可区分，但概率性、需采样、与 D-48 无关** | 差异只在「谁调了 `0x47C620`」，栈是唯一留下它的地方 |

⇒ **对卡面 Q3 触发条件的回答：不是「都不可区分」**，所以 Q4 的预注册方案成立（见 Q4）；但「可区分」的那一条**不在 D-48 的能力范围内**。

## Q3 · 若都不可区分就明说；D-48 的最强结论；差哪种授权；处置建议

### 3.1 明说

- **在「内存副作用」这一范畴内：全部不可区分**（§2.4 ①–④）。
- **在「只读可观测」这一更宽范畴内：存在 1 条可区分通道**（§2.3 栈哨兵），但它**概率性**且**与 D-48 无关**。

### 3.2 D-48 在原理上能给 ②-b 的**最强**结论

| 想得到的结论 | D-48 能否给 | 为什么 |
|---|---|---|
| 「`0x47C738` 在本次会话中被执行过 ≥1 次」 | **不能** | 无断点 ⇒ 无指令级事件；`DEBUG_EVENT` 九类都不携带「普通指令执行」 |
| 「`0x47C620` 被调用过 ≥1 次」 | **不能** | 同上 |
| 「本次会话装载了哪些模块 / 开了哪些线程」 | 能 | `CREATE_PROCESS` / `LOAD_DLL` / `CREATE_THREAD` |
| 「游戏这次退出是不是异常退出」 | 能（弱） | `EXCEPTION_DEBUG_EVENT` + `EXIT_PROCESS_DEBUG_EVENT` |
| 「两路径可分」 | **不能** | §3.3 |

⇒ **D-48 对 ②-b 的净贡献 = 0**。它甚至做不到「弱结论」里的第一条。

### 3.3 要拿到「两路径可分」，还差哪一种授权（**只列举，不得宣称已获授权**）

| 选项 | 需要的新授权 | 能给出什么 | 风险/代价 |
|---|---|---|---|
| **(a) 写目标进程内存** | 明示授权 `WriteProcessMemory`（+`VirtualProtectEx` 改页属性） | 软件断点 `0xCC` → 命中即确定性获得 `EIP`/`ESP`/`EBP` 与栈，**唯一区分成立** | 每次命中都要改回原字节；漏恢复 ⇒ 游戏崩。属 D-48 明列的禁区，须另行明示 |
| **(b) 写线程上下文** | **撤销 D-36(A) 的「不写线程上下文」单条** | `Dr0–Dr3`+`Dr7` 硬件执行断点，或 `EFLAGS.TF` 单步；命中即确定性 | **注意：D-36(A) 的原始物理理由已被 D-48 消解**（见 3.4）⇒ 这是**政策性**撤销，不是新物理授权 |
| **(c) DLL 注入 / Hook** | 明示授权注入 | 驻留计数器（每次进 `0x47C738` +1），事后只读读取，**命中率 100%** | 需改 `ra2youli\` 之外的落点；最重、最易被 DRM 干扰 |

### 3.4 必须上报给 Lead 的一条：**D-36(A) 的物理理由已经被 D-48 破掉了**

`[推理 / 工程常识，未在本机验证]`

D-36(A) 的原文理由是：「硬件执行断点命中时 CPU 在**执行该指令前**抛 `#DB`，**无人处理** ⇒ 未处理异常 ⇒ 进程终止」。这个推理的前提是「无人处理」。而 **D-48 恰好就是那个处理器**：attach 之后 `#DB` 会作为**第一机会** `EXCEPTION_DEBUG_EVENT`（`EXCEPTION_SINGLE_STEP`）交给调试器，`ExceptionRecord.ExceptionAddress` **就是被拦截指令的地址**，调试器 `DBG_CONTINUE` 即续跑，游戏不需要感知。

⇒ 结论：**在今天（D-48 已授权）的授权组合下，「硬件执行断点必然终结游戏」这一物理障碍不再成立；真正拦住 (b) 的只剩 D-36(A) 那条政策条文。**

⇒ 因此 ②-b 的正确定性问题**已经被换了**：不是「要不要授权 attach」（已授权），而是「**要不要撤销 D-36(A) 的『不写线程上下文』**」。

⚠ 两条诚实标注：
1. 上述是推理，本卡**未**做任何真机验证（本卡零真机）。验证路径：用任意自制 x86 小程序 + attach + `SetThreadContext` 置 `Dr0` 走一遍（**这一步属真机操作，必须由后续卡在 LIVE_LOCK 下单独做**）。
2. 反方向的残留风险未排除：部分 DRM/反调试会在运行时清 `Dr` 寄存器或检测 `Dr` 非零（本机 `xyr.dll` 仅 1 个导入、`secdrv.sys` 存在，**是否探测 `Dr`：`[未取得]`**）。

### 3.5 给 Lead 的处置建议（一句话）

> **不要为 D-48 单独开真机窗口**（净收益 0）；要么把 ②-b 以 `[静态推断]` + 「两路径在闸核内共用同一函数、非栈写为 0」**永久收口**，要么把 D-36(A) 的「不写线程上下文」**单条提出来重裁**——后者才是唯一能确定性闭合 ②-b 的路。

## Q4 · 预注册取证方案（针对 §2.3 的栈哨兵通道）

> 前提声明：**本方案不需要 `DebugActiveProcess`**。attach 只在「顺便捕获崩溃现场」时才有用（可选，非必需）。若 Lead 决定开窗，也建议按「不开 attach」执行，少一层行为改变风险。

### 4.1 观察什么

| 符号 | 地址 | 含义 | 产生点唯一性 |
|---|---|---|---|
| `SENT_CANPLACE` | `0x00449487` | `0x47C620` 从 `0x449440` 内部返回 | 唯一（`0x449482`+5） |
| `SENT_PERCELL` | `0x0043F2B3` | `0x47C620` 从 `0x43F180` 逐格循环返回 | 唯一（`0x43F2AE`+5） |
| `W_GATE` | `[0x0047C3D0, 0x0047C4CA)` | 闸核（`0x47C3D0` 的 `ret` 都在 `0x47C4BC/0x47C4C7`，窗口取到 `0x47C4CA`） | —— |
| `W_620` | `[0x0047C620, 0x0047CB00)` | 调用体（上界 `[未取得]`，**R3**） | —— |
| `W_FRAME` | `[0x0043F180, 0x0043FB00)` | 更大窗口（命中率更高，判据更弱） | —— |

模块基址：`[本卡只读复核]` `DllCharacteristics=0x20`（**无 `DYNAMICBASE`**）、重定位目录 = 0 ⇒ 映像固定装载 `0x400000`，上面的绝对值直接可用；仍建议在会话开始时用 `CREATE_PROCESS_DEBUG_EVENT` 或 `Module32First` 复核基址。

栈窗口：`[ESP, ESP+0x1000)`，4 KiB。哨兵命中概率（单个 dword 误报）：`2/2^32 × 1024 ≈ 4.8e-7`。

### 4.2 采样节奏

- **事件驱动 + 周期**：合成输入点击前 10 s 起采，点击后 5 s 停采（覆盖 hover 预览 + 点击）。
- 采样率目标 **≥2,000 次/s**（单线程紧循环：`GetThreadContext` → 若 `EIP` 不在三个窗口内则立刻 `continue`，不进 `ReadProcessMemory`）。实测率必须落盘。
- 只采**主渲染线程**（`CREATE_PROCESS_DEBUG_EVENT` 的 `hMainThread`；或 `GetWindowThreadProcessId` + 线程枚举）。
- **不调用 `SuspendThread`/`ResumeThread`**（授权边界灰区，见 Q5）：`GetThreadContext` 内部自行短暂冻结线程，足以取得一致快照。

### 4.3 判定式（可执行伪代码）

```python
SENT = {0x00449487: "CANPLACE", 0x0043F2B3: "PERCELL"}
WINS = [("GATE",  0x0047C3D0, 0x0047C4CA),
        ("620",   0x0047C620, 0x0047CB00),   # 上界待 R3
        ("FRAME", 0x0043F180, 0x0043FB00)]

def sample_once(tid):
    ctx = GetThreadContext(tid)              # 只读
    eip, esp = ctx.Eip, ctx.Esp
    win = next((n for n, lo, hi in WINS if lo <= eip < hi), None)
    if win is None:
        return None                          # 绝大多数样本走这里
    buf = ReadProcessMemory(esp, 0x1000)      # 只读 4 KiB
    for off in range(0, len(buf) - 4, 4):     # 由 ESP 向上扫描
        v = u32(buf, off)
        if v in SENT:
            return Hit(win=win, eip=eip, esp=esp, sentinel=SENT[v], off=off)
    return Hit(win=win, eip=eip, esp=esp, sentinel="NONE", off=None)

# 关键：offs 必须递增扫描，"最近 ESP 的哨兵" = 直接调用者
#       （0x47C73D 在更近处，但它不是候选哨兵，故被跳过）
```

**每条样本的分类**：`CANPLACE` / `PERCELL` / `NONE`（落窗口但栈上无哨兵，即别的调用者）/ `None`（未落窗口）。

### 4.4 三臂设计（含灵敏度正对照——没有它，任何「未观测到」都无解释力）

| 臂 | 构造 | 预期放置结果 | 该臂的作用 |
|---|---|---|---|
| **A（对照）** | 目标格**空**地，正常放置 | 成功 | **灵敏度正对照**：`0x43F180` 在此情形必然调用逐格 `0x47C620` ⇒ 必须观测到 `PERCELL` ≥1 次。若为 0 ⇒ 采样器不可用，**立即判本卡失败** |
| **B（拒绝）** | 目标格有**己方步兵**（复刻 LIVE-L2 B 组：已入账 5/5 拒绝） | 拒绝 | 主体的判定臂 |
| **C（重复）** | 与 B 同构造，重复 ≥3 次 | 拒绝 | 稳定性检查（错源⑨：单次「未观测到」不算证据） |

### 4.5 预注册判定表（正式表见 `DECISION_TABLE.tsv`；此处给读法）

| 观测 | 判定 |
|---|---|
| A 组 `PERCELL` ≥1 | **CONTROL-PASS**（采样器有效），B 组数据才有解释力 |
| A 组两哨兵全 0（60 s） | **FAIL-NO-CHANNEL** —— 本卡失败，不做任何方向性结论 |

### 4.6 证伪条件（什么观测会推翻上表）

| 编号 | 观测 | 推翻什么 |
|---|---|---|
| **F1** | 某次**放置成功**的点击里观测到 `CANPLACE` 哨兵 | 推翻「`CANPLACE` 命中 ⇒ 拒绝」的读法（成功时 can-place 必然也调用过闸）⇒ 判定必须改为「臂间差分」，单次命中不足 |

### 4.8 Stage 0 可行性预检（先做，5 分钟，决定是否继续）

> 不点击、只 hover，采 60 s，统计 `hit_rate = 落在 W_GATE∪W_620 的样本数 / 总样本数`。

命中率模型（`[推理]`）：`P(hit) ≈ f_run × d_run`，其中 `f_run` = 该代码每秒执行次数、`d_run` = 单次执行时长。

| `f_run`（每秒执行次数） | `d_run`=0.3 µs | `d_run`=1 µs | `d_run`=3 µs | 60 s（2,000 样本/s）命中概率 |
|---|---|---|---|---|
| 1（只在点击时执行） | 3e-7 | 1e-6 | 3e-6 | **0.02% / 0.06% / 0.18%** ⇒ 不可行 |
| 10（每秒 10 次） | 3e-6 | 1e-5 | 3e-5 | 0.5% / 1.7% / 5% ⇒ 边缘 |
| 60（每帧 1 次 @60 fps） | 1.8e-5 | 6e-5 | 1.8e-4 | 2.4% / 7.2% / 21% |
| 300（每帧多次） | 9e-5 | 3e-4 | 9e-4 | 12% / 36% / 76% |

⇒ **结论**：若 `f_run ≈ 1`（预览不跑这段代码，只在上链那一刻跑），本方案**在原理上不可行**，应立刻停手、不申请真机窗口。
⇒ Stage 0 的通过门槛：**60 s 内 `hit_rate` ≥ 1e-3**（即 ≥120 次命中），否则判 `FAIL-NO-CHANNEL`。

### 5.2 「禁止操作」硬清单

见 **`FORBIDDEN_OPS.md`**（可勾选，逐条自证）。核心三条：

1. 不写目标进程内存（含 `0xCC`、含 `VirtualProtectEx` 改页属性、含 `PAGE_GUARD`）。
2. 不写线程上下文（含 `SetThreadContext`、含 `Dr0–Dr7`、含 `EFLAGS.TF`）。

### 不一致 D-1（影响 ②-b 的语义，**须 R7 闭合**）

`GATE_MAP.md` 第 34 行与 `R14_COMMON §2.6` 的路径叙述把 `0x43F2B5 je 0x43F504` 标为「**拒绝分支**」。本卡只读复核：

```
0043F504  mov eax,dword ptr [esp+0x18]
0043F508  inc esi
0043F509  cmp esi,eax
0043F50B  mov dword ptr [esp+0x1c],esi
0043F50F  jl  0x43F269          ← 回边到逐格循环头
```

⇒ `0x43F504` 是**循环增量 + 回边**，不是拒绝出口。
且在 `0x43F1E0..0x43F620` 全区间内，跳转到拒绝出口 `0x43F5D8` 的源**只有两处**：`0x43F220`（can-place 非 0）与 `0x43F5B1`；后者是循环结束后的

```
0043F5AB  mov al,byte ptr [esp+0x23]
0043F5AF  test al,al
0043F5B1  je  0x43F5D8          ← 标志=0 → 失败(al=0)
0043F5B3  ... call [eax+0x280](3) / call [edx+0xF8] / mov al,1 / ret 4   ← 标志≠0 → 成功
```

⇒ **逐格的 `0x47C620` 调用不直接产生拒绝**，它的返回值只决定「跳过此格 / 进入更深的逐格分析（可能置 `[esp+0x23]=1`）」；最终成败由循环后的标志位决定。

**这不推翻 `§2.6` 的任何字节事实**（bit0 判据、唯一写点、WhatAmI 集合、`0x47C3D0` 的选择子与链头全部不变），但**推翻了「`0x43F2B5` 直接拒绝」这一条出口映射**。后果：本设计能判定的严格对象是「`0x47C620` 的**直接调用者是谁**」，把它翻译成「哪一层拒绝」需要 **R7**。

### 不一致 D-2（措辞级，无实质后果）

`GATE_BEHAV/PROGRESS.md` 第一步写「`0x449440` 在 `[BType+0x408]=0` 或 `[build+0x74]=0` 时**不调闸即返回 7 拒**」。本卡复核（A10）：该情形走 `0x449493` 的 `BType vt[0xA8]` 谓词，**同样映射成 `0/7`**，不是硬编码 `7`。其「不能把『未调闸』写成『闸拒绝』」的告诫**完全正确**，只是机制措辞需订正。
