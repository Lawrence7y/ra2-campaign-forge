## 0. 锚点自检（先于一切结论）

`work.py:anchor_of()` 规则：向低地址扫到**最近的** C2 xx xx / C3 / 90|CC 填充串，返回该填充串之后的第一个字节；若返回值 == 给定地址，则该地址本身是锚点。

| 地址 | 锚点结果 | 依据 |
|---|---|---|
| 0x43F180 | **OK** | 12×`90` 填充止于 0x43F17F（其前 0x43F173 = `C3`）→ `81 EC B0 00 00 00` |
| 0x43F1E9 | **OK** | `C2 04 00` @0x43F1E6 → `8B 87 20 05 00 00` |
| 0x43F9A6 | **OK** | `C2 04 00` @0x43F9A3 → `8B 17 8B CF` |
| 0x43F5D8 | **OK** | `C2 04 00` @0x43F5D5 → `53 8B CF` |
| 0x47C620 | **OK** | 7×`90` 填充止于 0x47C61F → `A1 AC E7 A8 00` |
| 0x47C3D0 | **OK** | 7×`90` 填充止于 0x47C3CF → `55 8B EC 83 E4 F8` |
| 0x47C4D0 | **OK** | 6×`90` 填充止于 0x47C4CF → `A0 A0 E9 A8 00` |
| 0x449440 | **OK** | `C3 90 90`（0x44943D..0x44943F）→ `8B 44 24 04` |
| 0x6F4A70 | **OK** | 12×`90` 填充止于 0x6F4A6F → `8B 44 24 04`（其前 0x6F4A6D = `C3`） |

**本卡自己踩到并修正的锚点陷阱**（如实记录）：

1. 首版 `anchor_of` 把 `C2` 判定放在 `90` 之后 → 0x43F1E9 被判“无锚点”（因为 0x43F1E8 = `90` 落在 `C2 04 00` 的立即数里）。改为“终止符优先”。
2. `sec_of()` 首版按 `max(vsize, rawsize)` 界定节：.text 的 vsize(4,060,045) 远大于 rawsize(4,063,232，文件内实剩 4,059,264)，.text 吞掉 .rdata 起头，0x43F1E9 附近的 `C2 04 00` 被读成 `00 00 00`。改为按 **rawsize** 界定。
3. 复现 R7 的 0x47CA6E 陷阱：从 `0x47CA70` 之外直接线性起步会解出 `add byte ptr [esi-0x16ffbc07], ah`。正确入口是**标签** 0x47CA70（由 `0x47CA6A 0F 85 61 FC FF FF` 跳入）。

## Q1 · 0x43F180 与 0x449440 的调用者

**结论：两者各有且仅有一个静态引用点，且都是 `.rdata` 里的函数指针槽 ⇒ 虚派发，不是死代码。**

### (a) 虚表槽 / 指针表槽

| 目标 | 位置 | 值 | 表形态 |
|---|---|---|---|
| **0x43F180** | `0x7E3FE0` | `80 F1 43 00` | .rdata 中 stride=4、连续 9 槽的函数指针表 `0x7E3FE0..0x7E3FFF`：`0x43F180, 0x5F4730, 0x455C20, 0x456750, 0x5F4D10, 0x5F6C30, 0x459C00, 0x4436F0, 0x443410`。0x43F180 是**该表 slot #0**。 |
| **0x449440** | `0x7E4068` | `40 94 44 00` | 同区另一段函数指针表 `0x7E4050..0x7E4080`，连续 13+ 槽全为 .text 指针；0x449440 在 `0x7E4068`。 |

“疑似 vtable / 方法表”的依据强度：**中**。理由：① 只含 .text 代码指针；② 槽距 4、无空洞；③ 0x43F180 是 **thiscall**（`0x43F191 mov edi,ecx`，`0x43F188 mov ebp,[esp+0xBC]` 取 1 栈参，`ret 4`）；④ 同表其余槽目标同样以 `mov esi/edi,ecx` 起首。
**未取得**：这些表在运行期由谁取用（哪条 `mov/lea reg,[0x7E3FE0]`）。见 `residual.md` #1。

### (b) 立即数 / 数据引用（4 字节小端）

| 目标 | 命中数 | 位置 |
|---|---|---|
| 0x43F180 | **1** | `.rdata:0x7E3FE0`（同 (a)） |
| 0x449440 | **1** | `.rdata:0x7E4068`（同 (a)） |
| 0x43F1E9（附带） | **2** | `.text:0x43FB10`、`.text:0x43FB18`（switch 跳表 `0x43FB0C` 的 entry[1]、entry[3]） |
| 0x47C620（正控） | **0** | 无 —— 0x47C620 只经 `E8` 到达 |

### (c) 扫描范围声明（**本卡主动扩大的一处**）

卡面允许 Q1 对数据节扫描；我把 Q1 扩大到**整个文件映像的五个节 raw 数据**，逐字节找 4 字节小端目标值：

| 节 | VA 范围 | 扫描字节数 |
|---|---|---|
| .text | `[0x401000, 0x7DFA00)` | 4,059,264 |
| .rdata | `[0x7E1000, 0x811000)` | 200,704 |
| .data | `[0x812000, 0x87C000)` | 442,368 |
| .rsrc | `[0xB7A000, 0xB93000)` | 102,400 |
| .detour | `[0xB93000, 0xB96000)` | 12,288 |
| **合计** | | **4,817,024 B** |

未扫：PE 头 `0x0..0x1000` 与节间对齐空隙（`0x87C000..0xB7A000` 等），共 8,336 B —— 不含可执行代码，且 PE 头不会出现模块内 VA。

### 集合相等性证明（正控 = 扫描器有分辨力）

| 正控项 | 应得 | 实测 |
|---|---|---|
| `E8` → **0x47C620** | 10（含卡面点名的 0x43F2AE） | **10**，首位 = **0x43F2AE** ✅ |
| `E8` → **0x47C3D0** | 35（R7） | **35**，集合与 R7 逐项相同 ✅ |
| `E8` → **0x47C4D0** | 6（R7） | **6** ✅ |
| `E8` → **0x6F4A70** | 应含 0x43F198 / 0x43F5DB | **3**：`0x43F198, 0x43F5DB, 0x4D3799` ✅ |
| 4B 扫描 **0x47C620** | 必须 0（非表项） | **0** ✅（不虚构） |
| 4B 扫描 **0x43F1E9** | 必须 2（跳表） | **2**：0x43FB10 / 0x43FB18 ✅ |

⇒ 同一把尺子对 0x47C620 给出 (E8=10, 数据=0)，对 0x43F180 / 0x449440 给出 (E8=0, 数据=1)。(b) 的“恰 1 个”具备分辨力，**不是扫描器失效的假空**。

### ⇒ Q1 答案
- **0x43F180**：唯一静态引用 = `0x7E3FE0`（函数指针表 slot #0）；`E8` 命中 0 ⇒ 调用者是**虚派发** `call [vtbl+n]`，`n` **未取得**。
- **0x449440**：唯一静态引用 = `0x7E4068`；`E8` 命中 0 ⇒ 同为**虚派发**，槽偏移**未取得**。
- 二者**都不是“无任何静态引用”**。

## Q2 · 0x47C620 的精确函数尾界

### 入口（含序言字节）
```
0047c620  A1 AC E7 A8 00        mov eax, [0xA8E7AC]   ; 全局
0047c625  83 EC 08              sub esp, 8            ; 本地缓冲（非参数）
0047c628  53                    push ebx
0047c629  55                    push ebp
0047c62a  33 ED                 xor ebp, ebp
0047c62c  56                    push esi
0047c62d  57                    push edi
0047c62e  3B C5                 cmp eax, ebp
0047c630  8B F9                 mov edi, ecx          ; thiscall: this = ecx
0047c632  0F 85 38 04 00 00     jne 0x47CA70          ; 全局非 0 -> 直接成功
```
入口字节 `A1 AC E7 A8 00 83 EC 08 53 55 33 ED 56 57`；锚点 = 0x47C61F 前 7×`90`，再往前 `0x47C615 = C2 08 00`。栈约定：`sub esp,8` + 4 次 push，尾 `add esp,8` 在 pop 之后 ⇒ **thiscall + 3 个栈参**（`C2 0C 00`）。

### 精确尾界
```
0047ca4d  8B 87 EC 00 00 00     mov  eax, [edi+0xEC]
0047ca53  8D 14 C1              lea  edx, [ecx+eax*8]
0047ca56  03 C2                 add  eax, edx
0047ca58  D9 04 85 40 EA 89 00  fld  dword [eax*4+0x89EA40]
0047ca5f  D8 1D 48 17 7E 00     fcomp dword [0x7E1748]
0047ca65  DF E0                 fnstsw ax
0047ca67  F6 C4 40              test ah, 0x40
0047ca6a  0F 85 61 FC FF FF     jne  0x47C6D1          ; 唯一不在 epilogue 上的出口
0047ca70  5F                    pop  edi              ; <<< epilogue 公共起点（标签）
0047ca71  5E                    pop  esi
0047ca72  5D                    pop  ebp
0047ca73  B0 01                 mov  al, 1
0047ca75  5B                    pop  ebx
0047ca76  83 C4 08              add  esp, 8
0047ca79  C2 0C 00              ret  0xC
0047ca7c  90 90 90 90           ; 4 字节填充
0047ca80  83 EC 68 A1 90 10 AA 00   ; 下一个函数入口（锚点 = 0x47CA7C..0x47CA7F 的 90）
```
**精确尾界（最后一条指令之后的首字节地址）= `0x47CA7C`。** 函数体 `[0x47C620, 0x47CA7C)`，0x45C = 1116 B。

字节依据（三重）：
1. 最后一条真指令 = `0x47CA79 C2 0C 00`，止于 0x47CA7C。
2. `0x47CA7C..0x47CA7F = 90 90 90 90`（填齐 16 字节边界）。
3. `0x47CA80 = 83 EC 68 A1 90 10 AA 00` 是新函数序言，其锚点正是上述 90 填充。
**不存在跳转表外的尾巴**：0x47CA70 是 epilogue 的公共起点，不是“最后一个 ret 之外的东西”。

### 是否所有路径收敛到同一 epilogue？—— **否**
- `[0x47C620, 0x47CA7C)` 内共 **10 条 `C2 0C 00`**：`0x47C6CA, 0x47C6DA, 0x47C760, 0x47C833, 0x47C85C, 0x47C875, 0x47C9A4, 0x47CA30, 0x47CA4A, 0x47CA79`。
- 只有 `0x47CA79` 是“pop 4 个寄存器 + ret”的 epilogue，也是唯一返回 `al=1` 的出口；其余 9 条是各自的 early-exit 尾巴（形态 `pop edi; pop esi; pop ebp; xor al,al; pop ebx; add esp,8; ret 0xC`），**不经过 0x47CA70**。`0x47CA4A` 例外：返回查表字节 `mov al,[ecx*4+0x89EA60]`。
- 进入 0x47CA70 的共 6 条：`0x47C632 jne`、`0x47C8FD je`、`0x47C949 je`、`0x47CA25 jl`、`0x47CA6A jne`、以及 `0x47CA4D` 分支后的自然落点；**全部收敛到 0x47CA79**。
- ⇒ 结构是 **“1 个成功 epilogue + 9 个 early-exit 尾巴”，不是单 epilogue**。

### 与 R7 的差异与纠正
- R7 只解到 `[0x47C620, 0x47CA70)`，尾界记“未取得”。本卡补上 `0x47CA70..0x47CA7B` 12 B 后，尾界确定 **0x47CA7C**。
- R7 `disasm.txt` 两处解码错（同根因 = 未按标签起步）：`jne 0x47C853` 实为 **0x47C73F**（R7 正文挂在 0x47C73D 行）；`xor al,al` 实为 **0x47C856**（R7 正文写 0x47C853，该字节实为 `5F`=pop edi）。

## Q3 · 0x43F5D8 块内 `call 0x6F4A70` 的语义

调用点（字节证实）：
```
0043f5d8  53                 push ebx        ; ebx = 0（0x43F5A9 xor ebx,ebx）
0043f5d9  8B CF              mov  ecx, edi   ; this（edi = 0x43F191 mov edi,ecx）
0043f5db  E8 90 54 2B 00     call 0x6F4A70
0043f5e0  5F 5E 5D           pop  edi, esi, ebp
0043f5e3  32 C0              xor  al, al     ; <<< 返回值被立即丢弃/覆盖
```
- **返回值被谁使用：无人使用。** `al` 在 0x43F5E3 被 `xor al,al` 覆盖 ⇒ 该调用唯一作用 = **副作用**。

被调函数（锚点 = 0x6F4A6F 前 12×`90`，再前 `0x6F4A6D = C3`）：
```
006f4a70  8B 44 24 04           mov  eax, [esp+4]     ; 唯一栈参
006f4a74  56                    push esi
006f4a75  8B F1                 mov  esi, ecx         ; this = ecx  -> 使用 this
006f4a77  50                    push eax
006f4a78  E8 D3 0D F0 FF        call 0x5F5850         ; (this, arg)
006f4a7d  84 C0                 test al, al
006f4a7f  74 1C                 je   0x6F4A9D
006f4a81  8A 86 18 04 00 00     mov  al, [esi+0x418]  ; 读 this+0x418
006f4a87  84 C0                 test al, al
006f4a89  74 0C                 je   0x6F4A97
006f4a8b  8B 16                 mov  edx, [esi]
006f4a8d  6A 0D                 push 0xD
006f4a8f  8B CE                 mov  ecx, esi
006f4a91  FF 92 74 02 00 00     call [edx+0x274]      ; 虚调用，参 0xD
006f4a97  B0 01                 mov  al, 1
006f4a99  5E                    pop  esi
006f4a9a  C2 04 00              ret 4                 ; 被调方清 1 个栈参
006f4a9d  32 C0                 xor  al, al
006f4a9f  5E                    pop  esi
006f4aa0  C2 04 00              ret 4
006f4aa3  90 ×13                ; 填充
006f4ab0  83 EC 0C              ; 下一个函数
```

**可字节证实的事实（无推断）**
1. 序言 = `8B 44 24 04 56 8B F1 50`；尾 = 两组 `C2 04 00`；函数体 `[0x6F4A70, 0x6F4AA3)`。
2. **读写 this：是。** `mov esi,ecx` → 读 `[esi+0x418]` → 经 `[edx+0x274]` 虚派发（ecx=esi）。
3. **常量引用**：只有立即数 `0xD`（`push 0xD`）。**无任何可读字符串引用**（体内无指向 .rdata 字符串的 `mov reg,imm32`）。
4. 前置判据 = `0x5F5850(this,arg)` 的 `al`；`al=0` → `xor al,al / ret 4`。
5. 静态调用点共 3 个：`0x43F198`（同函数序言，传 case 号）、`0x43F5DB`（本卡）、`0x4D3799`。

**推断（明确标注，附强度）**
- *推断 A*（强度 **中**）：`0x6F4A70` 是“**失败/拒绝时的音效或提示播报**”类副作用函数。依据：① 同时被“正常入口（0x43F198，传 case 号）”与“拒绝出口（0x43F5DB，传 0）”调用，符合“按事件码播报”的形状；② 形态 `if (precheck(this,arg)) { if (this->f418) this->vfn274(0xD); return 1; } return 0;`；③ 返回值在 0x43F5D8 路径被丢弃 ⇒ 是**通知**而非**判定**。**不足以**断定是哪类音效/EVA。
- *推断 B*（强度 **中**）：`0xD` 是事件/音效 ID；ID→语义映射**未取得**。

**明确未取得**：`0x5F5850` 内部判据、`[vtbl+0x274]` 实装、`this+0x418` 字段名、`0xD` 语义。**未使用 YRpp 知识库作为证据**。

## 五 · 一致性核对（R7 vs 本卡）

### 核对 1：`[esp+0x23]` 是否恰 3 处 —— **一致，3 处**
- 独立方法：在 `[0x43F180, 0x43FB20)` 找原始字节 `24 23`（disp8=0x23），命中 `0x43F24B / 0x43F501 / 0x43F5AD` —— 即三条完整指令的 disp8（指令首字节 `0x43F249 / 0x43F4FF / 0x43F5AB`）。
- 限定 `[0x43F180, 0x43F660)` 再筛：仍是这 3 处，**差集为空**。

### 核对 2：到 0x43F5D8 的跳转源是否恰 2 条 —— **一致，恰 2 条**
- `0x43F220 = 0F 85 B2 03 00 00`（`jne 0x43F5D8`），源条件 `0x43F218 call [esi+0x1ac]` + `0x43F21E 85 C0 test eax,eax`。
