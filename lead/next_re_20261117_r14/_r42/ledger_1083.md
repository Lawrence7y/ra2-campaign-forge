## §1083
### 事项 · R17 第 42 轮补记：档 C 从「降级」改为「撤回」（脚注本身就是错的）；纪律 24；`FACT_INDEX` v5.18

**一 · 本轮先前处置不足。** §1082 把档 C 定为「带已知缺陷的中间值」。审计员 T1（R42）回件后，此处置不够，三条理由：

**（1）`F24` 自带的脚注是错的。** 它写「本档仍含 **384 个 / 258,794,083 B** 的其它回滚副本」。
我实测（档 C 清单按回滚正则匹配）**375 行 / 184,618,279 B**；审计员实测 **333 行 / 184,506,382 B**。
两份独立实现都指向「**字节与脚注差约 74 MB**」，行数也差 9–51 个。
⇒ **一条引用值如果自带的限定语就是错的，比不带限定语更危险**——读者会照脚注反推量级，得到错的数量级。

**（2）判据 2 的代码落地与文字自相矛盾。** 判据 2 的文字是语义谓词（「被记录对象是 lead 的工作状态」），
代码只落地 `PAT_REPORT=["*_report.md"]` 一条；`board_/ledger_/lock_` 全靠 `_r35.._r38` 整目录前缀规则，
而 `_r39` 白名单为空、`_r40/_r41` 整目录漏排、`summary_snap2.json` 的 `r4x_dirs_matched` 恒空
⇒ **判据形状随快照时刻漂**，不是稳定判据。

**（3）同族大面积漏排。** `*_out.json` **372 个 / 19,281,606 B**、含 `stdout/stderr` 的 **789 个 / 14,443,509 B**
与已排除的 1,270 个 `*_out.txt` **完全同构**，但判据 1 只写了 `.txt` ⇒ 约 **33.7 MB** 留在「干净语料」里，
**是全部假阳性（262,195 B）的 50 倍**。

**二 · 纪律 24（新立）。** **「降级」不是万能处置。** 当一处引用的**限定语本身**被证伪时，
正确处置是**撤回该引用**，不是给它再加一句限定。加限定只在「值对、边界没说清」时成立；
「边界说错了」说明这个值没有被真正掌握。

**三 · 处置：`FACT_INDEX` v5.18（`R17_R77_FACTINDEX_V518`）。**
只引**档 A** = 24,723 文件 / 1,589,964,358 B = 1.589964 GB = 1.480770 GiB——它是唯一「判据机械、不依赖人看名字」的档，
有逐文件清单可 `sum(bytes)` 复核，双实现正控同得 24,723（差 3 B 已定位为 38 秒时间差）。
**档 C 整段撤出 statement**，只在 `limitations` 保留撤回理由与三个实测数。核验（退出码 0）：
路径项 **153**（+1）、文件 **153/153**、带锚点 **117**、四类全 **0**、**MISS 0**。

**四 · 审计另查出两处结构问题（我没注意到）。**
① **档 B 在盘上是空档**：`files_tier_B.tsv` 的 `selfkind` 非空行数仍 1,376（与 A 相同），只标不排，实际只删 `_hits_primary.tsv` 1 个
⇒ 「档 B = 上一轮干净值口径的复测」这个说法**不成立**。
② **档 C 的 24.5% 字节是主动保留的 `EVIDENCE/`**（4,913 行 / 318,329,818 B），体量比判据 1+2 排除的全部（289,221,428 B）还大；
保留是对的（那才是被测对象），但**应写进口径**，而非隐含在「再排 1,376 个自身产物」里。

**五 · 一个反复出现的模式。** 这是第 **五** 次「我的处置被下一轮自己数据推翻」：
§2.20 → §2.24 → §2.27 → §2.29 → §2.30。共同点不是「判错某个数」，而是**我每次都倾向选一个「保留 + 加限定」的中间处置**。
该倾向在数据可靠时是保守正确的，但在**判据本身不成立**时会把「不可引用」伪装成「可引用但有保留」。
⇒ 纪律 24 即冲此写。下轮起遇「判据被证伪」，**默认处置设为撤回**，由证据来推翻这个默认。
