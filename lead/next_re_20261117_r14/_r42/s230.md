## 2.30 【R17 追加，2026-11-22】档 C 从「降级」改为「撤回」：脚注本身就是错的

### 一 · 我上一节（§2.29）的处置不够

§2.29 我把档 C 定为「带已知缺陷的中间值」，并把缺陷写成「208 个裸 `REPORT.md` / 2,267,327 B 被误留、72 个 `*_report.md` 被排除」。
**但审计员 T1（R42）交回报告后，这个处置不够**，原因有三条，最重的是第一条：

**（1）`F24` 自带的脚注是错的。** 它写着「本档仍含 **384 个 / 258,794,083 B** 的其它回滚副本」。
- 我实测（档 C 清单按回滚正则匹配）：**375 行 / 184,618,279 B**
- 审计员实测：**333 行 / 184,506,382 B**
- ⇒ 两份独立实现都指向「**字节数与脚注差约 74 MB**」，行数也差 9–51 个

**一条引用值如果自带的限定语就是错的，那它比不带限定语更危险**——读者会照那个脚注反推量级，得到的是错的数量级。

**（2）判据 2 的代码落地与文字自相矛盾。** 审计指出：判据 2 的文字是语义谓词（「被记录对象是 lead 的工作状态」），
但代码只落地了 `PAT_REPORT=["*_report.md"]` 一条；`board_/ledger_/lock_` 全靠 `_r35.._r38` 整目录前缀规则，
而 `_r39` 白名单为空、`_r40/_r41` 整目录漏排、`summary_snap2.json` 里 `r4x_dirs_matched` 恒为空。
⇒ **判据的形状随快照时刻漂**，不是稳定判据。

**（3）同族大面积漏排。** 审计点名：`*_out.json` **372 个 / 19,281,606 B**、含 `stdout/stderr` 的 **789 个 / 14,443,509 B**
与已排除的 1,270 个 `*_out.txt` **完全同构**，但判据 1 只写了 `.txt` 一种扩展名 ⇒ 约 **33.7 MB** 实打实留在「干净语料」里，
**是全部假阳性（262,195 B）的 50 倍**。

### 二 · 处置：撤回，而不是降级

`F24` 改为**只引档 A**（v5.18）：
- **唯一可引用值 · 档 A** = 24,723 文件 / 1,589,964,358 B = 1.589964 GB = 1.480770 GiB
- 它是唯一「**判据机械、不依赖人看名字**」的档：6 扩展名 + 根 + 两个排除项，且有逐文件清单可 `sum(bytes)` 复核，
  双实现正控同得 24,723（差 3 B 已定位为 38 秒时间差）。
- 档 C **整段撤出 statement**，只在 `limitations` 里保留「为什么撤回」与三个实测数（375/333/384 与对应字节）。

⇒ **纪律 24 · 「降级」不是万能处置。** 当一处引用的**限定语本身**被证伪时，正确处置是**撤回该引用**，
不是给它再加一句限定。加限定只在「值对、边界没说清」时成立；「边界说错了」说明这个值没有被真正掌握。

### 三 · 顺带记：审计还查出两处我没注意到的结构问题

1. **档 B 在盘上是空档**：`files_tier_B.tsv` 的 `selfkind` 非空行数仍是 1,376（与 A 相同），它只是标出而不排除，
   实际只删了 `_hits_primary.tsv` 1 个 ⇒ 「档 B = 上一轮干净值口径的复测」这个说法**不成立**。
2. **档 C 的 24.5% 字节是主动保留的 `EVIDENCE/`**（4,913 行 / 318,329,818 B），体量比判据 1+2 排除的全部（289,221,428 B）还大。
   保留是对的（那才是被测对象），但它**应当写进口径**，而不是隐含在「再排 1,376 个自身产物」这句话里。

### 四 · 一个反复出现的模式（值得单列）

这是第 **五次** 出现「我的处置被下一轮自己的数据推翻」：
§2.20（审计 PARTIAL 多报）→ §2.24（反控抓到列间矛盾）→ §2.27（驳回 T2 查错接口）→ §2.29（档 C 不自洽）→ §2.30（降级不够、须撤回）。

共同点不是「我判错了某一个数」，而是**我每次都倾向选一个「保留 + 加限定」的中间处置**。
这个倾向在数据可靠时是对的（保守），在**判据本身不成立**时是错的——它把「不可引用」伪装成「可引用但有保留」。

⇒ 纪律 24 就是冲这个倾向写的。下轮起，遇到「判据被证伪」的场合，**默认处置设为撤回**，由证据来推翻这个默认。
