## 2.29 【R17 追加，2026-11-22】「同类对象被分到两边」：档 C 的自洽性被自己人推翻

### 一 · 一句话结论

`F24` 原来把 **档 C = 23,347 文件 / 1,300,742,927 B** 当作「更干净的语料」引用。本轮查实：**它的分类不自洽**——
**同类对象里，被排除的 72 个 `*_report.md`（1,029,652 B）比被误留在档 C 里的 208 个裸 `REPORT.md`（2,267,327 B）小一个量级。**

### 二 · 怎么发现的（三步，每步都可复算）

1. 执行员 T1（R40）把「自身产物」判据**操作化**成 `files_tier_A_snap2.tsv` 的 `selfkind` 列：
   24,723 行里 1,376 行有标签（C1/C3/C5/C6/C7/C8/C9），23,347 行为空；**档 C 恰为 selfkind 为空的行**。
   ⇒ **应用是机械的**（空 vs 非空），但**标签是怎么打上去的**没人审过。
2. 执行员 T2（R42，做漂移分解时）顺手发现不自洽：`AUDIT_REPORT.md` 命中 `C5_report_md`（算自身产物），
   而裸 `REPORT.md` 是**空** selfkind（不算）。
3. 我去数了这一类：**裸 `REPORT.md` 共 208 个，selfkind 全部为空，合计 2,267,327 B**；
   `AUDIT_REPORT.md` 5 个，全部非空。而被排除的 `*_report.md` 只有 72 个 / 1,029,652 B。

⇒ **判据 2 与判据 3 的边界是一条下划线**：执行员自己的判据写着「`*_report.md` 算自身产物、`*/REPORT.md`（无 `_report` 后缀）不算」。
这条判据**字面上是可机械执行的**（后缀匹配），但**语义上把同一类对象劈成了两半**——
而且劈错了方向：该被排除的那半（208 个）比被排除的那半（72 个）大三倍多。

### 三 · 这暴露的不是「判据写得不好」，而是「判据写得太具体」

执行员给了三条**形态判据**，一条比一条依赖「文件名长什么样」。问题在于：
**文件名是命名习惯，不是语义分类。** 一个人写 `REPORT.md`、另一个人写 `AUDIT_REPORT.md`，内容可能同类；
把它们分到两边，判据就变成了**对命名习惯的考古**，而不是对「这是不是测量产物」的判断。

⇒ **纪律 23 · 分类判据必须能回答「为什么这一类该在一边」，而不只是「这类文件长什么样」。**
形态判据只能当**实现手段**；必须同时给出**语义理由**，并做**同类一致性检验**：
把被判到两边的项按「内容类型」再对一次，若同类被劈开，判据即不成立。

### 四 · 对 `F24` 的处置（v5.17）

- **档 A 升为主引用值**（24,723 / 1,589,964,358 B）——它是「含全部自身产物」的原口径，**没有分类问题**。
- **档 C 降级**为「带已知缺陷的中间值」，`limitations` 里写死缺陷（208 vs 72 的对照数），禁止再称「干净值」或「下界」。

### 五 · 顺带记：漂移分解终于做出来了（T2，逐字节闭合）

旧 24,676 / 1,586,426,788 B + 新增 47 / 3,525,160 B + 改写净 12,410 B = 新 24,723 / 1,589,964,358 B（**我复算，全等**）。
其中 **自身产物 37 文件 / 净 +3,441,605 B**、**树真实增长 15 文件 / 净 +95,965 B**
⇒ 该窗口内约 **97%** 的增量是测量与记录自身产物，约 **2.7%** 是树在长。

**这条终于满足了纪律 19**（叙事必须有分解产物）：从 R37 起我一直在说「漂移有相当一部分是自身产物」，

### 六 · 纪律 21 被收窄（审计员 T4 的修正，采纳）

我上一轮立的纪律 21 写的是「审计的结论即使措辞不精确，也要先查它指向的那个量再驳回」。
审计员 T4 指出这**太宽**：当**不精确本身就是缺陷**时（口径混同、或根本没有可核指向），直接驳回或要求补正才是对的。
⇒ 收窄为：**「措辞不精确但**仍指向确定可核量**时，先查再驳；口径混同或无可核指向者，允许直接驳回或要求补正。」**

这是本轮唯一由审计**改进**（而非否定）我的纪律的一条。T4 同时指出 §2.28 里「纪律 16 首次被真正执行」中的「首次」属叙事标签、未独立取证，已在此软化。
