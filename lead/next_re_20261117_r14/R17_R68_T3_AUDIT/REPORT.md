## 三 · Q2 · C1 的误报面

### 3.1 真实存在的误报（不需要构造）——F40

C1 的 PAT3 `不得写成[「『]?(...)` 在 F40 抽出的 token 是 **`事实`**：

```
F40 limitations: F16 limitations 已引本规则名但未陈述内容；引用单源推断须与 F16 同引并带推断强度标注，不得写成事实。
F40 statement : 单源结论一律降级为推断并标强度与依赖产物：只有一份产物支撑的判断不得写成事实，必须显式标注推断强度并写明所依赖的那份产物，缺任一项即视为越级成文。
```

F40 现在**没报**，纯属运气：它的 `statement` 在「事实」两侧 45 字窗口里恰好各有 `推断`（`单源结论一律降级为**推断**` 在前、`必须显式标注**推断**强度` 在后），`hedged=True`。

我把 F40 的正文改成一个**同样合规、语义更强**的写法（只把窗口里的「推断」挪远，不动禁令本身）：

```
构造: 硬规则：只有一份产物支撑的判断不得写成事实依据。
```

实测 C1 → **报出**，`token=事实`。这个句子完全合规（它本来就只是在陈述禁令「不得写成事实」），却被报为「降级声明 vs 正文用法」冲突。

**这是 C1 的一个现存结构缺陷，不是偶发**：PAT3 把「禁令的宾语」当成「被降级的断言对象」。凡是 `不得写成 X` 里 X 是禁令句子的宾语（而非本行自己用过的断言），PAT3 都会把它抽出来要求窗口内有 hedge。F40 里 `事实` 只是两个字，窗口里几乎任何文本都能凑出 hedge——一旦凑不出就是误报。

### 3.2 构造出的误报（用同义限定词）——F29

从真实行 F29 出发，只把句末的免责声明换成**语义等价的另一个中文限定词**（不动 token、不动 `limitations`）：

```
原文: 「InterlockedIncrement」系推断措辞、未经字节证实）
改A : 「InterlockedIncrement」未取得字节支持）      → C1 报出
改B : 「InterlockedIncrement」系待定）              → C1 报出
改C : 「InterlockedIncrement」系估计）              → C1 报出
```

三句**都带限定**，语义强度都不低于原文，C1 全判为「正文未带限定」。根因是 `HEDGE_WORDS` 是 10 个词的闭集合，`未取得 / 待定 / 估计 / 暂定 / 未见 / 未被证实 / 未被…证实 / 尚无… / 不作…断言` 都不在内。

### 3.3 还有一类误报：自身就是被降级对象的行

F08 的 `limitations` 里有 `不得写成 [已证]`（**不得写成** 后面跟的是 `[已证]`，不是引号短语，PAT3 的 `[「『]?` 可选所以能匹到）。F08 的 `grade` 就是 `[静态推断]`，正文里 `[静态推断]` 出现，而 `key()` 会把 `[已证]` 归一化后在正文里找——F08 正文里确有「不得写成 [已证]」这句话本身。这条目前**恰好**因为窗口里有 `推断` 而没报。但如果 F08 正文把 `[已证]` 挪到 45 字窗口外、而 `[静态推断]` 留在里面，就会报出——而 `[已证]` 恰恰是**禁令**引用的字面量。这与 3.1 同型。

**Q2 结论：能构造，且不用构造也已经存在（F40 的 `事实` token）。误报主因有两条：(a) PAT3 把禁令宾语当成被降级断言；(b) `HEDGE_WORDS` 是闭集合，任何同义限定词都被当成"没有限定"。**

一个从未命中的检查项要算「通过」，至少要满足：(i) 它**能**命中已知坏例（正控）；(ii) 它的豁免逻辑本身被验证过。C2 两条都不满足：

**Q3 结论（形式化回答）：C2 判定 = 太弱。它现在算不算「通过」的证据 = 不算。**

### 4.5 能让 C2 有效的改法（只写在这里，不改文件）

1. **把「引号豁免」从字符存在性改成成对区间判定**：先算出所有 `「…」/『…』/“…”` 的 `(open,close)` 区间，只有当 `m.start()` 落在某个区间**内部**时才豁免。改完后 F06 会立刻报出，这就是 C2 的第一个正控。
2. **把 grade 门从 `== '[已证]'` 改成 `startswith('[已证]')`**（并把 early-version 的 5 种变体纳入），否则归一化前的 8 个版本永久免疫。
3. **把 `break` 去掉**，逐词报；并让豁免词表从闭集合改成「否定式前缀 + 引述标记」的语法判据（`系…措辞`、`属…措辞`、`不得写成`、`非已证`、`仅推断`），而不是 10 个固定词。
4. 增加**自陈式冲突**判据：`grade` 含 `[已证]` 而同一行 `limitations` 含 `非已证 / 属静态推断 / 未取得` ⇒ 直接报，不依赖窗口。

v3 F02 的 `evidence_paths`（逐字）：

```
lead\next_re_20261117_r14\R14_COMMON.md(§2.9四);lead\next_re_20261117_r14\STATUS_BOARD.md(L215-216)
```

两个锚都是**文件**（存在），都读了：

- `R14_COMMON.md`：`7F4960` 出现 **0** 次（大小写都查，`7f4960` 也是 0；连 `7F49` 都是 0）。该文件里 TechnoClass 的相关内容是 `| TechnoClass（基类） | 0x6F4A70 | 51 B | 无 |`——**没有 TechnoClass 主 vtable 的地址**。
- `STATUS_BOARD.md`：`7F4960` **0** 次，`TechnoClass` **0** 次，`309` **0** 次，连 `L215` 都 **0** 次——**被引的那段根本不存在**（该文件只有 219 行，我逐行看过 L210–L225，内容是 FACT_INDEX v5.10 出表记录，与 F02 无关）。
- 全仓范围内 `7f4960` 只出现在 `BOARD_ARCHIVE.md`（4 处），而 `BOARD_ARCHIVE.md` **不是 F02 在 v3 的锚**。

**判定 = 真缺陷**：`0x7F4960` 在 v3 声明的两个锚里一次都没出现，C3 报对了。

### 5.2 F17 的 `0x449440` —— **误报（C3 的路径解析 bug）**

v3 F17 的 `evidence_paths`（逐字）：

```
R14_COMMON.md(§2.6四·L215; §2.10一)
```

这是一个**分号分隔的多节引用**，且**没有目录前缀**。checkC 的处理：

1. 先按 `;` 切成 `R14_COMMON.md(§2.6四·L215` 和 `§2.10一)`；
2. 再用 `re.sub(r'\([^()]*\)$','')` 去尾括号——**两段都不以 `)` 结尾**，所以**一个字符都没去掉**；
3. 拼到 `ROOT` 下 → 两个都不存在 → `pool` 为空 → `blob == ''` → **任何地址都"不在锚内"**。

所以 C3 对 F17 报的 7 个地址**全部是**来自「pool 为空」的假报。而 `0x449440` 在那个**本意**的文件里确实存在：

```
R14_COMMON.md 中 '449440' 出现 16 次
```

且 R14_COMMON.md 确实存在（`Test-Path` = True）。

**判定 = 误报**。根因：`evidence_paths` 的**括号内可以含分号**（`(§2.6四·L215; §2.10一)`），而 checkC 先按分号切、再按尾括号剥，两个步骤的顺序把整条路径拆碎了。这不是"锚位偏移"，也不是"并集里没找到"——是**锚一个都没解析成功，导致 C3 变成"凡是 F17 这种写法的行必然全报"**。

顺带：v3 里 **12 行**（F06/F07/F17/F18/F19/F20/F21/F22/F23/F24/F25/F26）存在同型路径解析失败（缺目录前缀、多节引用、裸目录）。其中 F21 见下。

### 5.3 F21 的 `0x87F924` —— **误报（裸目录锚）**

v3 F21 的 `evidence_paths`（逐字）：

```
R17_R35_V5657A0_TABLE; R17_R36_VERIFY_TABLEBASE
```

两个都是**目录名，不是文件**（我实测 `isdir=True`，`isfile=False`）。checkC 的 `os.path.isfile(p)` 对目录返回 False → 两者都进不了 `pool` → `blob == ''` → **5 个地址全部假报**。

而 `87F924` 在这两个目录里**确实有**：

```
87F924 FOUND in R17_R35_V5657A0_TABLE\REPORT.md
87F924 FOUND in R17_R36_VERIFY_TABLEBASE\VERDICT.md
87F924 FOUND in R17_R36_VERIFY_TABLEBASE\verify.py
```

`R17_R35_V5657A0_TABLE\REPORT.md:11` 逐字：

```
表基址：`mov ecx,[ecx+0x13C]` @0x5657BB，随后 `mov eax,[ecx+eax*4]` @0x5657C1。调用者常量 this=`0x87F7E8` ⇒ 表指针槽 = `0x87F7E8+0x13C = 0x87F924`
```

**判定 = 误报**。`0x87F924`、`0x87F7E8`、`0x5657A0` 三个都在这两个目录的产物里。C3 因为"锚是目录"而一个都没读。

（我另外查了：`0x40000` / `0x100000` 这两个**表规模**的数值，在 `R17_R35_V5657A0_TABLE` 与 `R17_R36_VERIFY_TABLEBASE` 两个目录里确实**都没有**（`100000` 0 次，`40000` 只在 `ImageBase=0x400000` 里出现 2 次）。所以 F21 这 2 个 token 若是真缺陷，也是「表规模没有逐字锚」这种小缺陷——但它被混在 5 个假报里，判别力为 0。）

### 5.4 Q4 汇总

- `F02 0x7F4960` = **真缺陷**（锚里 0 次，且被引的 STATUS_BOARD L215-216 内容与 F02 无关）
- `F17 0x449440` = **误报**（路径被分号/括号解析拆碎，pool 为空；本意文件里出现 16 次）
- `F21 0x87F924` = **误报**（锚是目录，pool 为空；两个目录里各有命中）

**7 行里至少 2 行是纯解析误报，1 行是真缺陷。而 C3 对「pool 为空」没有任何告警——空 blob 会让整行所有地址一起报，也会让整行所有地址一起免（见 Q5 盲区④）。**

## 六 · Q5 · C3 的口径盲区

### 盲区①：锚文件解析失败 = 双向失效（最严重）

`os.path.isfile` 失败时 `pool` 不增长、`blob` 为空、**不报错也不告警**。后果是双向的：

- **误报**：空 blob → 该行所有地址全部报出（Q4 的 F17、F21 就是这样）。
- **误放**：如果某一行的锚**只是"部分"解析成功**，只要有一个文件读了进去，`blob` 非空，任何在**那一个**文件里出现过的 token 就算过；解析失败的那些锚完全不参与判定。v3 里 12/26 行有解析问题；v5.12 里 F06/F07 各有一个锚 `R14_COMMON.md(§2.10 / 一 / (a′))` **仍然解析不了**（`(a′)` 里含 `′`，尾括号正则能吃，但这个 path 里还有 ` / ` 分隔的节号，剥完剩下 `R14_COMMON.md(§2.10` → 不存在）。实测这也是 v5.12 仍然存在的 2 行。

### 盲区②：只认 `0x` 前缀的字面写法

正则 `0x([0-9A-Fa-f]{4,8})` **要求字面的 `0x`**。项目自己在 F03 等行使用的是 8 位不带前缀的写法（`0x007E88D0` 式，见 F53 的 `0x007E88D0`、F54 的 `0x7E88D0`），只要某行写成 `004D3780` 而不带 `0x`：

- v5.12 我实测：**statement 里 6 位以上的裸十六进制 = 0 处**（正则 `(?<![0-9A-Za-z_x])([0-9A-F]{6,8})(?![0-9A-Za-z_])` 全 54 行零命中）。所以这个盲区**在 v5.12 没有实例**，但它是"写作风格"，不是"数据事实"——一旦有人按 F03 的习惯写 8 位裸地址，C3 就完全看不见。

### 盲区③：4 位以下 `0x` 值不检查

`{4,8}` 下限排除了 `0x14 / 0x20 / 0x30 / 0x75 / 0xA8 / 0xC / 0x124 / 0x13C / 0x1AC`。v5.12 实测这类 token **21 处**，全部被静默跳过：

```
F01 0xC | F03 0x124, 0x1AC | F04 0x124 ×2 | F05 0x30 | F06 0x14 ×2, 0x75, 0xA8
F07 0x14 ×2, 0xA8 | F09 0x1AC, 0x124, 0x1AC | F17 0xA8 | F18 0x14 | F21 0x13C
F29 0x20 | F52 0x20
```

这些里面 `0x124` / `0x1AC`（槽偏移）恰恰是 F03/F04/F09 的核心可核数字。**盲区有实例（21 处），但都是偏移量而非入口地址，是否该查属于口径选择——现在这个选择是隐含的、没写进文档。**

### 盲区④：十进制桥是"巧合通道"，且已经在起作用

C3 加十进制候选本意是「锚里以十进制记值」（注释：`如 lead_byte_checks.tsv 的 va=7839744`）。实测它**在 v5.12 上确实救了一行**：

```
F50 的 0x77A000 / 0x793000
with dec   -> []                        # 不报
without dec -> ['0x77A000','0x793000']  # 会报
```

为什么"不报"？我去看 `lead_byte_checks.tsv`（F50 的第二个锚），逐字：

```
section_.rsrc	va=7839744 rptr=4710400 vsize=98600 rsize=102400	va!=ptr
section_.detour	va=7942144 rptr=4812800 vsize=10008 rsize=12288	va!=ptr
```

`7839744` 是 `.rsrc` 的 **VirtualAddress**，`7942144` 是 `.detour` 的 VirtualAddress。F50 的正文说的是 `0x77A000 vs 0x47E000` 这一**对**（VA vs PointerToRawData）的比较。C3 通过十进制**只对上了 VA 的一半**（`7839744`），`0x47E000=4710400` 也恰好在这张表里当 rptr 出现——于是这一对"都算过了"。

**这是"碰巧"而不是"可追溯"**：C3 只要求"某个候选字符串在这个文件的**任意位置**出现过"，不要求出现在**同一行/同一记录**里。F50 这个例子恰好数据自洽，所以无害；但换个数字就是纯误放：`0x367BE4`（vsize，3570660）也在表里，`0x6C000`（rsize，442368）也在表里——这两个数在 F50 正文里是**关于 `.data` 的**，而表里的 3570660/442368 也是 `.data` 的，同样自洽。**但这个自洽是数据本身的巧合，不是检查器验证的**。

结论：**十进制桥是"字符串巧合"通道，且已在 v5.12 的 F50 上生效（救了 2 个 token）。它既可能误放（无关的十进制数字撞上），也可能造成"看起来查过了"的假象。**

### 盲区⑤：「在任一锚中找到」而非「在有资格的那个锚/那一节找到」

`any(c in blob for c in cands)` 的 `blob` 是**本行全部锚文件的全文拼接**。这违反本项目纪律 5 的反面情形——看起来像是在执行"锚是并集"，实际是把"哪个锚都行、文件里哪儿都行"当成了合格。

实例：F04 的 `0x43F180` 在 `BOARD_ARCHIVE.md` 里出现 24 次，而 F04 声明的是 `BOARD_ARCHIVE.md(R17 第 14 轮 段)` 和 `(R17 第 15 轮 段)`。**C3 无法区分"命中的是第 14/15 轮段"还是别的 22 处**。F10 的 8 个 `0x43F2xx` 在 `R17_LEDGER_1065\SECTION.md` 各命中 1 次、在 `BOARD_ARCHIVE.md` 各命中 1 次——都没问题，但 C3 本身**没有证据**说它命中了对的那一段。

### 盲区⑥：其它进制 / RVA 形式

- 只有 hex + decimal。**八进制、`RVA 0x47F924` vs `VA 0x87F924` 的 RVA/VA 区分**完全不认：F50 明确区分 `RVA 0x47F7E8` 与 `0x87F7E8`，C3 会独立把两者当两个 token 查；`0x47F7E8=4716520` 在锚里 0 次、`0x87F7E8=8910824` 也是 0 次（我实测），所以 F50 这两个靠**十六进制原样**过：R36 的 VERDICT 含 `0x47F7E8`。**RVA/VA 是否指同一处，C3 不判**。
- 地址**区间**（`[0x7E3EBC,0x7E43C4)`、`[0x43F191,0x43F5D8)`）只把两个端点当 token 查，区间覆盖关系不判。

**Q5 结论：盲区 6 类，其中 ①（锚解析失败双向失效）、④（十进制巧合通道）在 v5.12 有实例并已影响判定（F06/F07 解析失败；F50 靠十进制救回 2 token）；②③ 在 v5.12 无实例但有 21 处（③）被静默跳过；⑤⑥ 是覆盖率语义问题。**

## 七 · Q6 · 这套 C 漏掉的列间关系

C1 管的是 `limitations → statement`（单 token 级），C2 管 `grade → statement`（词级），C3 管 `statement → evidence_paths`（地址级）。**三列两两之间还有大量没被覆盖的关系**。以下每条我都尽量标了「机械可判 / 判不了」：

### ① `grade` ↔ `limitations` 的自陈矛盾（**机械可判，且 C2 本该管却没管**）

`grade` 是 `[已证]`，而同行的 `limitations` 自己写着 `非已证` / `属静态推断` / `未取得` ⇒ 这是行内等级自相矛盾，**不需要任何窗口或词典**。

v5.12 实例：**F06**。`grade = [已证]`，`limitations = 全程按指令边界解码、未用 C3/C2 字节扫描；语义定性属静态推断、非已证；不改变 ②-b 的 grade`。同一行同时说「[已证]」和「非已证」。

判法：`grade` 含 `[已证]` 且 `limitations` 匹配 `非已证|属静态推断|未取得字节|未经字节证实` ⇒ 报。**C1/C2/C3 都不做这件事。**

### ② `statement` ↔ `limitations` 的「引用义务闭环」（**机械可判**）

`limitations` 里说「须同引 X / 与 X 同看」（X = 另一 fact_id），那 **X 的 `limitations` 是否也点回了本行**（否则单向链：A 要求同引 B，B 不要求同引 A，读者只读 B 时会漏掉 A 的限制）。

v5.12 的 D 标签互指矩阵（我逐条抽出来的）：

```
F08 D-1 -> F17    F17 D-1 -> F36    reciprocal=False
F13 D-3 -> F20    F20 D-3 -> F13    reciprocal=True
F17 D-2 -> F36    F36 D-2 -> F17    reciprocal=True
F20 D-3 -> F13    F13 D-3 -> F20    reciprocal=True
F36 D-2 -> F17    F17 D-2 -> F36    reciprocal=True
```

**F08 ↔ F17 不对称**：F08 说「与 F17 部分重叠，引用时二者同看」，但 F17 的 D 标签指向 F36，**没有点回 F08**——同时 F17 正文又写 `须与 F08 同引 a–e 与 (a′)`。所以「同看」在 F08 侧成立、在 F17 侧的 D-tag 体系里丢了。**这是一个真实的单向引用义务**，C 一个都抓不到。

判法：抽 `D-n[:：]与 (F\d\d)` 与 `(?:同引|同看)\s*(F\d\d)`，建图，报非对称边。**代价：只对"标签写法"机械可判，散文式「须同引」抽不干净 ⇒ 半机械。**

### ③ `evidence_paths` 与 `limitations` 里的锚引用的**同一性**（**半机械**）

`limitations` 说「引 §16.1 只能引其判据」，`evidence_paths` 给的是 `R14_COMMON.md(§16.1 判据)`——但**是否 §16.1 里真有个「判据」小节、该小节是否就是那句**，C 不管。

v5.12 实例：F24 的 `引 §16.1 只能引其「判据」，其表内数字是历史快照（旧 478/374/802），数字须取现盘`，而 `evidence_paths` 是 `R14_COMMON.md(§16.1 判据)`。要判「§16.1 的『判据』小节是否与 F24 的负结论同框」，必须解析 markdown 小节结构 + 语义匹配 ⇒ **判不了，只能人读**。

### ④ `statement` 的断言强度 ↔ `grade`（**机械可判的弱版 / 强版判不了**）

C2 只看 4 个词，但强度是整个断言的性质。例如 F27 `grade = [已证]`、`statement` 写 `硬规则：atexit 严格形态仅 68 个…其余…属字节误命中，不得当作 atexit 注册集`——这条**是规则**而非本镜像的事实；`[流程]` 更贴切。反而 F13/F20（同为规则）被标成 `[流程]`。**同一类「硬规则」陈述在 grade 列被分到 `[已证]` 与 `[流程]` 两类**。

v5.12 实例：`[已证]` 27 条里，F27/F31/F32/F33/F45/F49 是**判据/规则**陈述（"硬规则：…" 开头），F06/F07/F10 是**实测**。前者该不该是 `[已证]` 是口径问题，但「`statement` 以『硬规则』起头而 `grade=[已证]`」是**机械可判**的（我实测 v5.12 有 6 条），需要人工定口径后才可判。

### ⑤ 空锚 / 目录锚 / 解析失败锚 —— `evidence_paths` 的自洽性（**完全机械可判，且 C3 已有全部零件却不用**）

`evidence_paths` 的每个分项是否解析到**文件**、是否带**可定位锚点**、括号内的分号切分是否会把一项拆成多项。这是纯粹的路径问题，不需要任何语义。

v5.12 实例：**F06 / F07** 各有一个 `R14_COMMON.md(§2.10 / 一 / (a′))` 解析失败（`os.path.isfile` = False）。v3 的 12/26 行同型。

判法：复用 C3 的 path 解析 + `isdir` 检查，报「锚未解析/锚是目录/一项被拆成多项」。**这是 C3 最该有却没有的一条，而且它自己的 F17/F21 误报就是这条缺失造成的。**

### ⑥ `statement` 内部的跨 token 自洽（**机械可判**）

同一 `statement` 里对同一对象的两个数字/地址必须相容。例如 F03 说 `0x43F180 = BuildingClass #73`，F04 说 `0x43F180 调用方链`，F01 说 `954 为「主 COL」数`；F11 说 `第1版 220 与第2版 26 已作废`，F14 说 `COVERAGE_ONLY 220 已被 §1062 第三版双口径取代`——**这两条说的是同一件事，F11 和 F14 在互相引用**，但 C 不检查「F14 声称作废的 220 是否在 F11 里确实被标为作废」。

判法：需要先建「同一被指对象」对齐（地址→实体），属**半机械**。

### 8.3 回溯脚本的一个统计口径问题
