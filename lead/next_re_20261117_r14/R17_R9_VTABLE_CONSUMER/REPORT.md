## 1. 第一步: 独立复现两张表 (不复用 R8 结论)

### 1.1 两个函数的全镜像交叉引用 (实证 R8 的 "唯一静态引用")

对 VA 做**全 5 节**逐字节小端 4 字节搜索:

| 目标 | 全镜像命中 | 位置 |
|---|---|---|
| 0x43F180 | 1 | .rdata 0x7E3FE0 |
| 0x449440 | 1 | .rdata 0x7E4068 |

⇒ R8 的 "唯一静态引用" 结论 **复现成功**。同理 E8/E9 直接调用 0x43F180 / 0x449440 的条数均为 **0** (对 4 字节目标做 E8/E9 位移反算), 与 R8 "直接 E8 命中为 0" 一致。

### 1.2 表的精确起止 (非 .text 指针即边界 —— 实测无效)

关键否定结果: **0x7E3FE0 与 0x7E4068 都不是表边界, 也不是表头。**

以 .rdata 为域做「连续 image 指针 (0x401000..0xB79BE3) 极大串」扫描, 含 0x7E3FE0 的唯一极大串为:

```
0x7E3E8C .. 0x7E4403  = 350 个连续 dword, 全部落在 .text
左边界外: 0x7E3E88 = 0x00818CE8 (.data 指针 → 0x818CE8)  ← 非 .text, 构成左边界
右边界外: 0x7E4404 = 0x00000000                        ← 构成长右边界
```

- 把 0x00818CE8 计入 image 指针, 串会向左延伸到 0x7E3E88 (351 槽); 但 0x818CE8 是 .data 地址, 按卡面的「非 .text 指针即边界」口径, **text-only 边界 = [0x7E3E8C, 0x7E4403]**。
- 0x7E3FE0 位于该串 **#85** (`(0x7E3FE0-0x7E3E8C)/4 = 85`); 0x7E4068 位于 **#119**; 0x7E4050 位于 **#113**。
- 串内 350 个槽全部是 .text 代码指针, 无一个 0 / 无一个非 .text 值, 因此**无法在串内部用指针/非指针判据切出子表**。

### 1.3 结论: 表形态复现 **失败 (未取得)**

- R8 声称的 "0x7E3FE0..0x7E3FFF 共 9 槽、0x7E3FE0 是 slot #0" —— **不成立**。0x7E3FE0 前一个槽 0x7E3FDC = 0x0070ADC0 (同样 .text), 后面 0x7E4000 起继续全是 .text 指针, 没有任何边界标记。9 槽口径的末槽 0x7E3FFC 之后 0x7E4000 = 0x00443410 仍是 .text, 边界不成立。若按 0x7E3FE0..0x7E3FFF 列 8 槽 (见 tables.tsv T1), 其 "边界证据" 仅为 R8 口径, **无字节佐证**。
- 同理, "0x7E4050..0x7E4080 一段 13+ 槽表" —— 无边界。0x7E4050 前 0x7E404C = 0x005F5C20 (.text), 0x7E4080 后 0x7E4084 = 0x005F5F40 (.text), **两端都不封闭**。
- 因此本卡不声称任何子表的起止; 只报「0x7E3FE0 / 0x7E4068 落在同一个 350 槽、连续、全 .text 的函数指针串 [0x7E3E8C, 0x7E4403] 内, 槽号分别为 #85 / #119」。子表切分 = **未取得**。

> 补充观察 (不计入结论): 该 350 槽串的槽内容按地址段有明显分组 (0x41xx / 0x43xx / 0x44xx / 0x5Fxx / 0x6Fxx / 0x70xx 交替), 但分组边界处**没有** 0 或其他非 .text 值, 无法用静态字节判据断言组边界。

## 2. 第二步: 运行期取用者 —— **0 条 (未取得)**

### 2.1 扫描口径 (全部实测, 非形态猜测)

1. **.text 内原始 4 字节小端立即数** 等于下列任一 VA, 全 .text (0x401000..0x7E038C) 逐字节扫描:
   - 表首: 0x7E3FE0 / 0x7E4050 / 0x7E4068 → **各 0 命中**;
   - 表内相邻地址: 0x7E3FDC / 0x7E3FE4 / 0x7E3FE8 / 0x7E4054 / 0x7E4058 / 0x7E405C / 0x7E4060 / 0x7E4064 → **各 0 命中**。
   - 合计 **12 个不同目标地址、0 命中**。
2. **宽口径**: .text 内所有落在乐队 [0x7E3E00, 0x7E4140) 的 4 字节立即数 —— 共 26 条, **最高只到 0x7E3EBC**, 无一条进入 0x7E3Fxx / 0x7E40xx。这 26 条全部位于 0x43A6xx..0x4500xx, 目标都是 0x7E3E54/0x7E3E74/0x7E3E80/0x7E3E88/0x7E3E90..0x7E3EBC 一类**字符串/常量**地址 (非函数指针槽), 与本卡两表无关。
3. **反证 (证明扫描器有效)**: 同一扫描器对 0x43F180 / 0x449440 两个函数 VA 在 .rdata 中各命中 1 条 (0x7E3FE0 / 0x7E4068), 对 0x7E3E54 等在 .text 中命中; 因此 "0 命中" 是文件事实, 不是脚本缺陷。
4. **二次间接一层 (卡 §二 要求)**: 扫 .data (0x812000..0xB79BE3) 中值落在串 [0x7E3E8C, 0x7E4403] 的 dword:

| .data 槽 | 持有值 | 相对串 | 对 .data 槽自身的 .text 引用 |
|---|---|---|---|
| 0x874D40 | 0x007E4078 | #123 (串内) | **0** (全 5 节 0 命中) |
| 0x874D44 | 0x007E427C | #252 (串内) | **0** (全 5 节 0 命中) |

   二者位于 .data 一个 239 项、[0x874CC0, 0x8750B8) 的指针数组内 (条目形如 0x7E0000, 0x7E0204, 0x7E0408 … 步长 0x204, 即 .text 中按固定间距的字节/指令位置数组, 非函数指针表)。该数组内部的任何地址 (含 0x874D40/0x874D44) 在 .text/.rdata/.data/.rsrc/.detour 中**均无取用者 (0 命中)**。⇒ 无寄存器基址, 无 `mov reg,[global]` 消费者。

### 2.2 结论

- 取用点条数: **0**。
- 是否找到 `call [reg+偏移]`: **否**, 因不存在任何把表基址 (或表内地址) 当立即数装载的指令, 也无从取得 reg / 偏移。槽偏移 **未取得**。
- 宿主判定: **不适用** —— 无 site, 故无 `host <= site < fn_end(host)` 可断言的对象; 本报告**不声称**任何 "所属函数", 未使用 forced_host, 未使用操作数形态匹配替代位置断言, 也未从任意地址线性起步反汇编 (无 site, 故无反汇编)。
- 对 R8 "推断为虚派发" 的评价: **静态证据不支持, 也不否定**。该 350 槽串确实全是 .text 代码指针, 形态上与函数指针表相容; 但**没有任何静态引用**指向它 (连 .data 全局都没被引用), 说明若运行期确有取用, 其基址只能来自运行期计算 (如 `lea reg,[0x7E3Exx]` + add, 或从 .text 中的常量偏移 + 已装载基址算出) —— 但 .text 乐队扫描已证明连 0x7E3Exx 这一带都只有 26 条、最高 0x7E3EBC 的常量串地址, **没有 0x7E3Fxx 以上**。故 "虚派发" 属未证实推断。
