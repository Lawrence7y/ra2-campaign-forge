## §1122

**一 · 本轮任务与产物。** R17 第 67 轮，任务=「唯一内容体量（SHA256 内容指纹去重）全量实测」。产物目录 `_r67/`：`dedup_corpus.py`（主实现，**58+7=65 条自测全 PASS**）、`verify_r67.py`（**第二独立实现，24 条自测全 PASS**）、`unique_content_4417.tsv`（4,417 行，回读校验通过）、`run.out.txt` / `verify.out.txt` / `archive.out.txt`（原始日志）、`archive_r67.py`（归档器，含 `--dry`）、`s273.md` / `ledger_1122.md` / `lock_cv.md` / `board_r67.md`（四件套草稿）。

**二 · 五个口径（引用必须带口径，纪律 31）。**

| 口径 | 件数/簇数 | 字节 |
|---|---:|---:|
| A 清单净额（`§2.71` / `F24` 现行） | 4,417 件 | **737,517,286** |
| B 磁盘（本轮全量 `getsize`） | 4,417 件 | **754,228,404** |
| C SHA256 唯一内容（磁盘侧） | **4,087 簇** | **615,909,180** |
| D SHA256 唯一内容（清单侧） | 4,087 簇 | **599,198,062** |
| E 内容等值唯一（跨序列化） | **4,084 簇** | **611,813,919** |

A 与 B 差 **16,711,118**，全部来自 `a2_sites.json` 的净额行（清单 913,237 / 磁盘 17,624,355）。

**三 · 两份独立实现互证。** 主实现按 SHA256 分簇；第二实现**完全不用哈希**（按字节大小分组 → 同大小逐字节比对）。两者对 4,417 件给出**逐簇完全相同**的分簇（`frozenset` 逐簇集合相等，非数字巧合）。控：SHA256 对照 3 条已知向量；去重器正控（字节级复制件必并簇）+ 负控（改 1 字节必不并簇、末字节差 0xFF 也能抓出）；`calls` 比较器负控（改 1 对 / 删 1 对 / 方向写反必须判不等）。

**四 · 重复侧：330 件 / 138,319,224 B，集中在 15 个簇。** 唯一件 4,087/4,417 = **92.53%**；唯一字节 615,909,180/754,228,404 = **81.66%**。含重复簇 **184**（2 件 140 / 3 件 22 / ≥4 件 22）。**Top15 浪费合计 130,989,973 B = 全部重复的 94.7%**；剩 169 簇仅 7,329,251 B（5.3%）。最大单簇 `_oo_disasm_out.txt` **73,899,177 × 2**；份数最多为 `except.txt` 崩溃日志族 **42 份**（单件仅 26,759 B）。

**五 · 🔴 SHA256 文件级去重抓不到那 4 份 `calls`。** 四份 `cluster_size` 全 = 1（`a2` `7a8447d1` / `sm` `ba90546a` / `e8` `043f2205` / `sw` `febdbce6`，两两不同）—— 原因是**序列化不同**（`a2.calls` 是 `{目标hex:[站点hex]}` 913,228 B；另三份 `[[site,target]]` 各 1,365,087 B）。补做**规范串**（排序后十进制 `site\ttarget`，LF 连接，68,253 对 / 1,228,553 B），四份哈希**完全相同** `67a10662007eec7a`，负控（改 1 对 / 删 1 对）均被抓。⇒ 口径 E = C − 2×1,365,087 − 913,228 = **611,813,919 B**（扣减 3,643,402 B，簇数 4,087−3 = 4,084）。**「唯一内容体量」有字节层（C）与内容层（E）两层，报数必须说是哪层。**

**六 · `a2_sites.json` 净额差额闭合（`§2.72` 未取得第 ⑤ 项）。** 由「清单 `bytes` 必须逐行等于磁盘 `getsize`」这条负控抓出 1 行不符。逐字节核算：磁盘 17,624,355 = `dumps(全文)` ✓；`dumps(calls)` 913,228、`dumps(bounds)` 16,711,104、骨架 23。**清单记 913,237 = `len('"calls": ')` 9 + 913,228**；**磁盘−清单 16,711,118 = 16,711,104 + 14**（`{` + `, "bounds": ` + `}`）。⇒ **「差 9 B」= 键名足迹 `'"calls": '`**，非舍入、非骨架漂移。**913,237 是「剔除 bounds 段后该文件在语料里的记账额」，不是磁盘字节。**

**七 · 与纪律 22 的补充分类本轮才有数，且第一版算错了。** **正交拆分**（`coverage` 与 `backup/baseline/before` 两维可兼有）：仅 `coverage` 快照 13 件 / 49,132,148 B（35.52%）、仅备份/基线/归档 108 件 / 3,399,574 B（2.46%）、两者兼有 18 件 / 4,552,562 B（3.29%）、两者皆无 191 件 / 81,234,940 B（58.73%），合计 330 件 / 138,319,224 B。**维度边际：`coverage` 相关 31 件 / 53,684,710 B = 38.81%；备份特征相关 126 件 / 7,952,136 B = 5.75%。**

**八 · 🔴 缺陷记录：第一版把归因算错了（分类不互斥却当互斥报百分比）。** 第一版用 `if 备份特征 / elif coverage` 优先级，把 18 件 4,552,562 B 的兼有项整段吞进「备份」桶 ⇒ 备份桶虚高 12,825,612 B（报 11.7%，实 2.46%）、`coverage` 低报 9.31 个百分点（报 29.5%，实 38.81%）。**错在归属、不在总数**（两版合计都是 330 / 138,319,224）。与纪律 31 同族但落在**分类维度**：**不互斥的类别不能直接报百分比**。修法：独立脚本 `_r67/attr_dup.py`（四桶互斥 + 并集/不相交/容斥三重断言 + **负控 N6**：优先级口径必须与正交口径不同）。**处置**：发现时四件套已落盘 ⇒ 用 `SUPERSEDED.before_r67_write_*` 备份整体回滚（回滚后断言五项 CR 与写前 sha 全等、追加内容已移除），改稿后重写；**不采用在已落盘文后追加更正注**（会让同一文件存在两个冲突数字）。

**九 · 已发布值：数字一个不动。** `F24` / `FACT_INDEX` 语料 **4,417 件 / 737,517,286 B（v5.30）本轮不改** —— 无新增/剔除文件、无字节变动，**只新增口径（C/D/E）**。`F24` 测的是磁盘体量，改口径就换数、不得改 `F24`（`§2.71` 原话）。**`FACT_INDEX.tsv` 本轮未改**，两条限定（唯一体量 C、内容层 E）**只在 `§2.73` 成文，未写入 `limitations` 列**。
