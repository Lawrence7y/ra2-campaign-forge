### ① `F24` —— 修单位错 + 限定倍数口径 + 标明快照（**这处错是我在 v5.11 亲手写进去的**）

v5.11 我在 F24 正文里加了「23,791 文件 / **1.29 GB**；扩展名限制把搜索面**缩小 58 倍**」。执行员 T5 复算后指出：

| 项 | 实测 | 结论 |
|---|---|---|
| `1.29 GB` | `1,383,739,755 B` ÷ 1024³ = **1.2887 GiB**；÷1000³ = **1.3837 GB** | 写的 1.29 其实是 **GiB**，差 **7.37%** |
| 根因 | `mev675.py:281` 用 `{total/1024/1024/1024:.2f} GB` —— **除以 1024³ 却标 GB** | 源头的单位标签就错 |
| `58 倍` | 体积比 75.14/1.29 ≈ **58.25**；**文件数比 68,038/23,791 = 2.86** | 只说「缩小 58 倍」会被读成文件面 |
| 可复现性 | 跑 `--stage scale --scope primary` **现在**得 **24,623 文件 / 1,502,917,464 B**（T5 跑得 24,622，两次之间树又长了 1 个文件） | 数字是**快照且已漂移** |
| 是否落盘 | `stage_scale` 的返回值在 `mev675.py:914` **未接**，无 TSV/JSON，只活在 `REPORT.md` 文本里 | 事后无法从产物重算 |

改法：写成 `1,383,739,755 B = 1.29 GiB（不是 GB）`、`体积比约 58 倍 / 文件数比仅 2.86 倍`、`快照 + 2026-11-22 重跑值`；`limitations` 同步登记。**加锚 `mev675.py`**（单位错的直接证据）。

### ② `F29` —— 「InterlockedIncrement」由**推断**升级为**字节证实**
