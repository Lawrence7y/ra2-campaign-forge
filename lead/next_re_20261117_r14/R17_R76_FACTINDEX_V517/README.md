## 与 v5.16 的区别（1 行 / 3 个字段：`F24` 的 statement + limitations + 1 个锚）

### 为什么要改：**档 C 的分类不自洽**

上一版 `F24` 把 **档 C = 23,347 文件 / 1,300,742,927 B** 当作「更干净的语料」。本轮查实：它的 `selfkind` 分类**把同类对象劈成了两半，而且劈错了方向**。

我直接从 `files_tier_A_snap2.tsv` 数出（四数均可复算）：

| 对象 | 数量 | 字节 | 处置 |
|---|---|---|---|
| `*_report.md` | **72** | 1,029,652 | **被排除**（算自身产物） |
| 裸 `REPORT.md` | **208** | **2,267,327** | **被留在档 C 里**（selfkind 空） |
| `AUDIT_REPORT.md` | 5 | — | 全部被判为自身产物 |

⇒ **被排除的那半（72 个）比误留在内的那半（208 个）小一个量级。**

病灶不是「判据写得不好」，而是**写得太具体**：执行员的判据是「`*_report.md` 算、`*/REPORT.md`（无 `_report` 后缀）不算」——
**字面可机械执行，语义上却是对命名习惯的考古**。已立 **纪律 23**：分类判据必须能回答「为什么这一类该在一边」，并对同类做一致性检验。
