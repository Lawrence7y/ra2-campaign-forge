## D1（机制修订，最重要）：三个遍历器并非都 `call [edx+0x104]`
- **派卡 T2-5 / `R14_COMMON §4.5`** 原文：三遍历器 `0x6D97D0`/`0x6D9920`/`0x6D9A50` 都做"遍历 → `call [edx+0x104]` → `mov byte [reg+0x80],0`"。
- **字节反证**（`EVIDENCE/ev_trav_slice_6D9A50.txt`）：
  - `0x6D97D0`：`call [edx+0x104]` @`0x6D98E9` + `mov byte [esi+0x80],0` @`0x6D98EF` ✓
  - `0x6D9920`：`call [edx+0x104]` @`0x6D9A21` + `mov byte [esi+0x80],0` @`0x6D9A27` ✓
  - `0x6D9A50`：**无** `call [edx+0x104]`；而是 `mov al,[esi+0x80]` @`0x6D9A88` + `test/je`（读脏标记作门控）→ `call 0x6D2790`（直接调用）@`0x6D9B15` → `mov byte [esi+0x80],0` @`0x6D9B1A`。
- **裁定**：该条**升不动为原表述**；但"三遍历器都在绘制后把 `[+0x80]` 清 0"这部分成立（三处 `mov byte …,0` 实测）。`0x6D9A50` 是"只处理脏对象"的变体，与其它两个"逐对象 + 几何裁剪"的语义不同。
