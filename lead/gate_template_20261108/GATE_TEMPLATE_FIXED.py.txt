R0. 总则：门禁判定只回答「本写域新增了什么风险」，不回答「写域里存在什么字样」
--------------------------------------------------------------------------------
【误报来源】误报一/二/三的共同根因：旧门禁把「字面出现」当「违规」——全文子串
  扫禁词（误报一，20 个门禁中 4 个对 *.py 做 .py 禁词子串扫描、10 个对交付 DOC
  做三字面文档扫描，撰写员提取实测）、字面等值查要素词（误报二）、把历史指纹当
  现盘指纹要求（误报三，ask 级口径）。

规则：
  1. 每条检查先回答三问：
     a) 被检对象是谁（新增件 / 派生副本 / 报告文书 / 既有清单件）；
     b) 检查的是「行为」（调用边、启动）还是「字样」；
     c) 若是字样，是否属于受保护语境（证据引证 / 纪律声明 / 历史记录 / 反禁词
        自检清单）。
  2. 判 fail 必须能引用「新增差异」或「结构事实」；仅有字面命中而无行为差异
     ⇒ 放行并记 warnings（不进 problems）。
  3. 【v2 修正】problems 每条必须带 rule_id（R0..R8）与依据出处（文件:行 或
     命令+输出），供事后追溯误报来源（对应 R7 输出契约）。

R1. 结构小节：按「顶层节号集合」匹配，不按字面小节标题匹配
--------------------------------------------------------------------------------
【误报来源】门禁逐字查找 '## 1'..'## 6'（dtrigger_round2 门禁还要 '## 7','## 8'）。
  五份编排方指纹件本轮实测全部含 '## 1'..'## 6'（missing=[]，_w2_checks_out.txt
  §9）——属潜伏误报面，非已发案例；但 '## 1' 无界字面会命中 '## 12'、'## 1.1'。

规则（【v2 修正】收窄匹配）：
  1. 只取 Markdown 顶层标题行：正则 ^##\s+(\d+)(?![.\d]) 抽取整数节号；
     '## 1.1'（子节）、正文「第 7 节」（无 ^## 前缀）、'## 附录 A'（无数字）
     均不入集合，也不被误当成缺失号。
  2. 中文序数标题（'## 一、'）归一化为整数入集合，防止把合法变体误判缺号。
  3. 必填判定：{1..N_required} ⊆ S（N_required 取任务书要求的节数）。
     允许多节、不允许缺号；节号断档才报「缺小节 N」，problems 附 rule_id=R1。
  4. 标题语义不参与判定；若任务书对小节有语义命名要求，走 R2 同义词组机制。

R3. SHA256 指纹锚：三类分治，优先级 R3-3 > R3-2 > R3-1（显式化）
--------------------------------------------------------------------------------
【误报来源】误报三：N-1 r2 交付件 A_RESIDUAL_REFERENCES.md 的绑定行（:130
  「被核对象 SHA256 = 3343cfbe…，字节数 = 26435」，绑定格式成立、格式段内无
  显式路径，撰写员实测）与 :4/:12/:159 的指纹引用全部指向被其就地覆盖的 r1
  （r1 无副本留存，:159 自declare；现盘 r2 = 1209ca4c…/33,431，MD 内不含
  1209ca4c）。20 个既有门禁无一做哈希值 vs 现盘重算的比对（20 个 GATE_CODE
  内 hexdigest 出现 0 次，撰写员提取实测）；N-1 r2 门禁 324c613e 对该件复跑
  ok=true —— 该误报发生在编排方 ask 级验收口径（dwfrun-01a1190d 载荷
  「绑定锚错位…⇒ r2 本身没有指向自身的绑定行…判定这算 ACCEPT 还是 PARTIAL」）。

【v2 修正·优先级】同一行同时落入多条时按 R3-3 → R3-2 → R3-1 顺序只判一次；
  v1 未定优先级，导致对 A_RESIDUAL:130（绑定格式 + 历史指向）两条款各说各话。

  1. R3-1 现盘自锚（self anchor）：
     a) 文件不得声明「整件 SHA256 = 某值」的朴素自绑定——内嵌自身完整哈希的
        字节串无法预先确定（密码学自指不可行）；
     b) 【v2 修正】允许两种可复核自锚，且必须按两阶段顺序生成：
        第一步（字节不动点）：含「字节数 = N」槽位的文件，从槽位='0' 起迭代
            N_{k+1} = len(以 str(N_k) 回填槽位后的全件字节)，
        至 N_{k+1} == N_k 收敛；数学上对任意基准长度 C 存在不动点
        （区间 [10^(d-1)-d, 10^d-1-d] 对 d 连续无缝），迭代单调收敛。
        第二步（扣零哈希）：把 64 位哈希字段置为 64 个 '0'，对全件（此时字节
        槽位已是定值）计算 sha256 并回填哈希字段（等宽 64 字符，长度不变）。
        校验法（门禁视角）：把行内哈希字段替换回 64 个 '0' 后对全件重算，
        应与行内声明一致；同时 len(全件) == 行内字节数。
     c) v1 缺陷登记（复核 6 组试验 + 撰写员 12 组双顺序复现，
        _w2_checks_out.txt §10a）：定宽占位法在「先哈希后字节」顺序下哈希与
        字节双双失配，在「先字节后哈希」顺序下字节仍失配——除非占位宽度恰
        等于最终字节数位数。故定宽占位法弃用。
     d) 修正算法已做 25 例合成样件验证（覆盖 2↔3、3↔4、4↔5、6↔7 位数字
        边界），全部收敛且双校验通过（_w2_checks_out.txt §10b）；
        真实交付件活样 = 本轮 GATE_FALSE_POSITIVES.md（r2）§5 自绑定行，
        校验失败时按未验处理并以复核为准。
  2. R3-2 历史锚（historical anchor）：
     适用范围（【v2 修正】收窄）：仅适用于「非 R3-3 绑定行格式」的指纹引用，
     或显式标注历史/旧版/仅追溯语义的引用（如 A_RESIDUAL:4/:12/:159 的覆盖
     声明语境）。满足任一即豁免值比对：
        a) 就地覆盖声明：「rX 已就地覆盖、无独立副本留存，其指纹为历史锚」
           ——门禁只查声明在场 + 指纹格式合法（64 位十六进制），禁止再要求
           该指纹与现盘一致；
        b) 副本留存声明：旧版以副本保留并给出路径——改走 R3-3 回验副本。
     判 fail 的唯一合法情形：指纹不匹配现盘、又无任何覆盖关系声明（静默失配）。
  3. R3-3 引用锚回验（优先级最高，堵假阴性）：
     凡「被核对象 SHA256 = <64位>，字节数 = <n>」格式的绑定行：
        a) 行内含显式路径 → 对该路径现盘重算并与行内值比对，不一致报
           「引用锚失配」（rule_id=R3-3）——这是查真问题（含伪造指纹防线），
           不是误报；旧门禁全缺失此步（只数行数 ≥1/≥4）；
        b) 行内无显式路径（如 A_RESIDUAL:130）→ 报「绑定行缺路径，需人工
           锚定」（rule_id=R3-3）——不静默豁免、不臆测比对对象；
        c) 被指向对象不在盘 → 报「引用锚指向不在盘对象」，转 R3-2 判断是否
           有覆盖/留存声明。
     实测正例：DECISION_QUESTIONS.md:130 绑定 8a36d60a…/30122 并给出显式
     路径，被指向的 _n10_D13D14_CARDS_20261108.md 在盘且哈希/字节数吻合
     （撰写员实测，_w2_checks_out.txt §8）——回验通过。
  4. 字节数解析兼容：提取数值先剥千分位逗号（'26,435' → 26435）再转 int。
     潜伏变体实测：r'字节数\s*=\s*\d+' 对「字节数 = 26,435」只截到 '26'
     （复核与撰写员各自实测一致，_w2_checks_out.txt §9），一旦进入数值比对
     即成新误报面。

     本版全文零原始字面，采纳方自检命令示范：

  5. 保留既有较新门禁已采用的启动检查式（正则对 AST 更弱，仅作 AST 不可用时的
