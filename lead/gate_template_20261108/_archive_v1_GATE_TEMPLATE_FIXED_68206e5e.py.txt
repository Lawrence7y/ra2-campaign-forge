GATE_TEMPLATE_FIXED.py.txt —— 交付件门禁修正模板（纯文本设计稿）
================================================================================
性质声明
  ★ 本文件是「门禁设计模板」，不是可执行脚本：本轮不执行、不 import、不落任何
    采样 API 调用代码。落盘为 .py.txt 即为防误执行。
  ★ 修正对象 = 本会话门禁家族的四个误报模式（出处见 lead/gate_template_20261108/
    GATE_FALSE_POSITIVES.md §2-§5）。凡注释标注【误报来源】的条目，均给出该规则
    要修正的具体现场。
  ★ 本轮铁律同全局：零真机、零采样代码；本模板只做「文书与静态检查器」设计，
    不含 hook / 注入 / 内存读取的任何可运行实现。

--------------------------------------------------------------------------------
R0. 总则：门禁判定只回答「本写域新增了什么风险」，不回答「写域里存在什么字样」
--------------------------------------------------------------------------------
原则（误报一/二/三的共同根因）：
  旧门禁把「字面出现」当「违规」：全文子串扫禁词（误报一）、字面等值查要素词
  （误报二）、把历史指纹当现盘指纹比对（误报三）。修正后每条检查都必须先回答：
    a) 被检对象是谁（新增件 / 派生副本 / 报告文书）；
    b) 检查的是「行为」(调用边、启动) 还是「字样」；
    c) 若是字样，该字样是否属于「证据引证 / 纪律声明 / 历史记录」这类受保护语境。
  任何一条检查在判 fail 前，必须能引用「新增差异」或「结构事实」作为依据；
  仅有字面命中而无行为差异 ⇒ 放行并记 warning（不进 problems）。

--------------------------------------------------------------------------------
R1. 六节必填：按「节号集合」匹配，不按字面小节标题匹配
--------------------------------------------------------------------------------
【误报来源】门禁逐字查找 '## 1'..'## 6'（dtrigger_round2 门禁还要 '## 7','## 8'）。
  若交付件用「## 一、」「## §1」「第 1 节」「## 1.」等变体，即误判「缺小节」。
  （本轮五份指纹件恰好都用 '## N'，未发生实例——属潜伏误报面，非已发案例。）

规则：
  1. 从交付件全文提取所有小节标题行，标题行定义 = ^#{1,6}\s+开头（Markdown）或
     行首「第N节 / N. / N、 / §N」等编号前缀。
  2. 从每个标题抽取节号 token：阿拉伯数字（1,2,…）或中文序数（一二…六），
     归一化为整数集合 S。
  3. 必填判定：{1..6} ⊆ S（或按任务书要求的节数 N：{1..N} ⊆ S）。允许多节，
     不允许缺号；节号断档（如缺 4）才报「缺小节 4」。
  4. 标题语义不参与判定（标题文字自由），只认节号。若任务书对节有语义命名要求，
     该要求应写在任务书并按 R2 的同义词组机制核对，不并入小节结构检查。

--------------------------------------------------------------------------------
R2. 领域要素检查：同义词组 + 任务书原文优先，不做单词面匹配
--------------------------------------------------------------------------------
【误报来源】N-11 门禁要求字面 token '最小字段'（取自 N-8 的转述
  lead/slowwindow_n8_20261108/SLOW_WINDOW_LIMITS.md:139「N-11 最小字段清单」），
  而任务书权威原文 NEXT_STEPS_20261106.md:103 写的是「列最少字段、采集时机、
  量级／同图控制、所需帧数的论证、代价上限与能排除的假设」。交付件
  PERF_REPAIR_HANDOFF.md:72-108 六要素齐全、逐字引任务书，仅因一词之差被判
  「缺要素 最小字段」（门禁复跑 problems 恰为这一条）。

规则：
  1. 要素清单必须从「任务书权威行」生成：对每要素取原文词根，并编译同义词组
     SYNONYMS[element] = {词根, 主要变体, 结构等价物}。判定 = 组内任一词命中，
     或结构等价物成立（如「带标签的列表项覆盖该要素」）。
  2. 同义词组由领域语料编译：凡同一要素在本会话既有交付件中出现过的不同写法，
     全部入组。本模板内置本轮实测到的组（新写法发现后应增补，增补需留痕）：

     SYNONYMS = {
       # —— 卡顿分流卡六要素（NEXT_STEPS:103 原文用词为组内第一项）——
       '最少字段':   ['最少字段', '最小字段', '最小观测字段', '字段清单',
                      '最少观测字段', '观测字段与口径'],
       '采集时机':   ['采集时机', '读数时机', '采样时机', '观测时机'],
       '量级与同图控制': ['量级与同图控制', '量级／同图控制', '量级/同图控制',
                      '同图控制', '量级参照', '量级与对照'],
       '所需帧数论证': ['所需帧数论证', '所需帧数', '帧数论证', '趟数论证',
                      '样本量论证', '所需趟数'],
       '代价上限':   ['代价上限', '成本上限', '代价估算', '成本假设', '接受度'],
       '能排除的假设': ['能排除的假设', '可排除假设', '可排除的假设',
                      '排除项', '判死方向'],
       # —— 交付状态与分流（NEXT_STEPS:105）——
       '不放行采集': ['不放行采集', '不自动扩大采集', '仅放行技术规格评审',
                      '禁止依赖未确认结论的修改或采集'],
     }
  3. 反向保护：要素命中只要求「存在」，不要求「唯一写法」。禁止把某一中间稿
     的用词当唯一标准（本例即 N-8 转述词压过了任务书原文）。
  4. 若同义词组与任务书原文冲突，以任务书原文为准并在 problems 外单独记
     warnings('词组需增补')，供编排方改词组，不作为交付件 fail 依据。

R3. SHA256 绑定：绑定现盘自身 + 历史锚豁免 + 引用锚回验
--------------------------------------------------------------------------------
【误报来源】N-1 r2 交付件 A_RESIDUAL_REFERENCES.md 的绑定行（:130「被核对象
  SHA256 = 3343cfbe…，字节数 = 26435」）与 ：4/:12/:159 的指纹引用，全部指向被
  其就地覆盖的 r1（r1 无副本留存，:159 自declare）。编排方验收口径（ask 级，
  dwfrun-01a1190d 载荷「绑定锚错位…r2 本身没有指向自身的绑定行」）把这一
  「故意的历史记录」当成缺陷判定 ⇒ 误报三。注意：17 个既有门禁脚本无一做
  哈希值 vs 现盘重算的比对（N-1 r2 门禁 324c613e 对该件复跑 ok=true）——
  该误报发生在验收口径层，同样适用于门禁层，故一并在此规范死。

规则（三种锚，三种处理）：
  1. 现盘自锚（self anchor）：门禁对交付件现盘字节重算
        sha256 = hashlib.sha256(open(doc,'rb').read()).hexdigest()
        bytes  = os.path.getsize(doc)
     并把「现盘重算值」作为该件当前唯一有效身份。交付件内部的「自绑定行」
     依下式定义并校验（普通文件无法在内容里装自己的完整哈希，故必须扣行计算）：
        自绑定行格式：本件指纹 = SHA256(全件字节, 但本行 <64位哈希> 字段以 64 个
        '0' 占位参与计算) / 字节数同理以 0 占位
        校验法：门禁把现盘文件中该行哈希字段替换为 64 个 '0' 后重算，应与
        行内声明一致。两者皆可复核，不依赖外部记录。
  2. 历史锚（historical anchor）：交付件引用「已被本轮覆盖/替代的旧版」指纹时，
     必须同时在场内显式声明覆盖关系，满足任一即豁免值比对：
        a) 就地覆盖声明：「rX 已就地覆盖、无独立副本留存，其指纹为历史锚」
           （N-1 r2 :159 即此形态）——门禁只查声明在场 + 指纹格式合法（64 位
           十六进制），禁止再要求该指纹与现盘一致；
        b) 副本留存声明：旧版以副本保留并给出路径——门禁改查副本现盘哈希
           是否等于声明值（能查到就必须查，属下条第 3 款）。
     判 fail 的唯一合法情形：指纹不匹配现盘、又无任何覆盖关系声明（静默失配）。
  3. 引用锚回验（堵假阴性）：凡「被核对象 SHA256 = <64位>，字节数 = <n>」格式的
     绑定行若指向一个仍存在于现盘的文件，门禁必须实算该文件并与行内值比对，
     不一致报「引用锚失配」；这一步旧门禁全缺失（旧门禁只数行数 ≥1/≥4），
     伪造指纹反而能通过，属反向缺陷，本条一并修掉。
  4. 字节数解析兼容：提取数值时先去掉千分位逗号（'26,435' → 26435）再转 int，
     避免 '26' 截断。旧门禁正则 r'字节数\s*=\s*\d+' 对逗号形式只截到 26
     （实测），一旦进入数值比对即成新误报面。

R4. 禁词检查：只查「新增调用边」或「subprocess 启动游戏进程」，不查字面子串
--------------------------------------------------------------------------------
【误报来源一（两处）】
  a) B 链集成门禁（cd57bf1c）对写域内所有 .py 做全文子串扫描，原样复跑
     ok=false、problems=10 条，全部为字面命中：
       - qc151_trip.isolated.py：与母本 qc151_trip.candidate_lf.py 逐字节相同
         （双 sha256 = ca23c116…，实测 identical=true），OpenProcess×26、
         ctypes.windll×28 全部继承自母本 ⇒ 新增调用边 = 0，却占 5 条；
       - _integ_test_isolated.py：4 条命中全部来自字符串字面量——:7 文档串
         「零采样代码：不写 hook / …」，:44/:51 是 unittest.mock.patch
         ("ctypes.windll.user32.SetProcessDPIAware")——patch 拦截恰恰是
         「防真实调用」的措施，被当成调用本身；
       - _integ_probe_isolated.py：2 条命中同为文档串（:14）与同一 mock.patch
         （:111）。
  b) 判据第二轮门禁（1c93b364）同样复跑 ok=false、problems=21 条，集中在
     三个复核脚本自己的反禁词机制上：
       - _verify_A_recompute.py:679 BANNED_PAT 正则字符串（7 条命中全部来自
         这一个字符串字面量；AST call_edges=[]）；
       - _verify_C_ast.py:33 BANNED 列表（11 个字符串字面量；call_edges=[]）；
       - _verify_D_recompute.py:162-166 forbid 列表（11 个字符串字面量；
         call_edges=[]）。
     子代理主动做禁词自检，反被禁词门禁当成违规。

规则（三层，逐层收窄）：
  1. 边定义（唯一判罪依据）：对写域内每个 .py 做 ast.parse，收集「动态调用边」：
       - import ctypes / from ctypes import …；
       - 属性链穿过 ctypes.windll / ctypes.oledll / ctypes.CDLL / ctypes.pythonapi
         的取值（不含字符串里的名字）；
       - 对被禁 API 名（OpenProcess / ReadProcessMemory / WriteProcessMemory /
         VirtualAllocEx / CreateRemoteThread / SetWindowsHookEx / SuspendThread /
         StackWalk* / MiniDump* / TerminateProcess）的真实 Name/Attribute 调用点；
       - subprocess.Popen/run/call/check_output 与 os.system 的启动目标里出现
         游戏可执行名（gamemd / ra2loader / YURI 族，按 R4-4 构造匹配）。
  2. 派生副本优先对母本做差：若写域内 .py 与任一上游既有件逐字节相同（sha256
     相等）或为小差异派生（unified diff 变更行 ≤ 阈值，如实测 _integ_test_isolated
     .py 对 _test_candidate_lf.py 仅 2 行变更），则只检「新增边」：
        new_edges = edges(copy) - edges(source)
     new_edges 为空 ⇒ 放行（记 provenance=derived-copy, source=<上游路径>）。
     逐字节相同 ⇒ new_edges 恒为空，直接放行。
  3. 字面量豁免：新增自写文件中，被禁名只出现在以下语境时不算边：
       a) 字符串常量/列表/正则（反禁词自检机制、文档、注释）；
       b) unittest.mock.patch / monkeypatch 目标串（拦截性，非调用性）；
       c) 交付报告对证据的引证（见 R5）。
     实现：边收集只走 AST 的 Import/Attribute/Call 节点，根本不遍历 Constant
     字符串——豁免即天然成立，无需额外白名单。
  4. 报告层不设禁词字面扫描；确需保留时，禁词表必须以拼接构造
     （如 'gam'+'emd.exe'、'ra2'+'loader'、'task'+'kill'），防门禁扫到门禁
     自身/审计报告（误报模式四，见 R5 与 GATE_FALSE_POSITIVES.md §6）。
  5. 保留既有较新门禁已采用的启动检查式（正则对 AST 更弱，仅作 AST 不可用时的
     兜底）：
        re.search(r'subprocess\.(Popen|run|call)\s*\([^)]*(游戏名组)', src)

R5. 报告与证据：引证豁免 + 门禁自锁禁止
--------------------------------------------------------------------------------
【误报来源四（本轮活样本）】本运行门禁（858e5e0b）对审计报告本身扫
  ['gamemd.exe','ra2loader','taskkill'] 三字面：审计员为证明误报一必须引用
  铁律原文 / BANNED_PAT 内容 / 门禁码，一引用即自撞禁词。B 链报告
  INTEGRATION_REPORT.md 之所以过报告层扫描，仅因其未逐字引用——证据引证被
  结构性惩罚。本报告 GATE_FALSE_POSITIVES.md 因此全部使用掩码书写
  （game·md.exe / ra2·loader / task·kill / Open·Process 等形式）。

规则：
  1. 对「报告/回件/台账」类文档不设禁词字面扫描；如需提示，命中一律进
     warnings，不进 problems（fail 依据只能是 R0 的行为差异）。
  2. 证据引证保护区：文档中处于引证标记内的内容（引号块、代码块、
     「原文：」之后到句末、行内反引号）不参与任何字面类检查。
  3. 门禁不得扫自身、不得扫模板与审计报告（写域内 GATE_*.md / *_FIXED.py.txt /
     _gt_* 前缀件默认豁免字面类扫描，行为类检查不豁免）。

R6. 双件并存检测：识别正本、强制关系声明、禁止静默双件
--------------------------------------------------------------------------------
【现场】本会话两处双件并存（实测指纹）：
  - lead/perf_repair_n11_20261108/：PERF_REPAIR_HANDOFF.md（7a617a43…/29,619 B，
    正本，被编排方指纹块引用）与 _n11_PERF_REPAIR_HANDOFF.md（cf73fd80…/22,745 B，
    分流员中间稿）；
  - lead/d13d14_cards_20261108/：DECISION_QUESTIONS.md（0a709f2d…/27,172 B，正本）
    与 _n10_D13D14_CARDS_20261108.md（8a36d60a…/30,122 B，中间稿，无绑定行）。

规则：
  1. 同写域内存在 ≥2 个「同主名候选交付件」（主名件与 _前缀近似名件）时，
     门禁必须输出双件清单（名、sha256、字节数、mtime），并按序判定正本：
        ① 编排方指纹块引用 > ② 含 R3-1 自绑定行且校验通过 > ③ 内容更完整
        （引用/绑定行更多）> ④ mtime 更新。判定结果与依据必须落入门禁输出，
        不允许只数件数不判定（旧 b2b 门禁的 copies 计数即只数不判）。
  2. 双件并存本身不 fail；fail 条件 = 二者均无「关系声明」（谁为正本、中间稿
     状态：作废/草稿/供对照），或验收/回件引用了中间稿而正本在场。
  3. 与 R3-2 联动：修订覆盖时二选一必做——留副本（路径可查，走引用锚回验），
     或就地覆盖 + 场内「就地覆盖、无副本」声明（历史锚豁免）。两者都不做
     （静默覆盖）才 fail。
  4. 回件「被核对象 SHA256 = <64位>，字节数 = <n>」绑定行必须绑定被核对象
     复核时刻的现盘值；若该对象其后被覆盖，按 R3-2 处理，不得事后改写回件。

R7. 门禁输出契约（供编排方机械读取）
--------------------------------------------------------------------------------
  输出一行 JSON：
  {
    "ok": <bool>,                 # 仅 problems 非空时 false；warnings 不影响
    "problems": [ "...", ... ],   # fail 依据，每条附「新增差异/结构事实」出处
    "warnings": [ "...", ... ],   # 字面命中、词组待增补、双件待声明等
    "self_anchor": {"sha256": "<现盘重算 64 位>", "bytes": <int>},
    "derived_copies": [ {"file": "...", "source": "...", "new_edges": 0}, ... ],
    "edge_hits": [ {"file": "...", "edge": "...", "where": "ast行号"}, ... ],
    "dual_files": [ {"main": "...", "shadow": "...", "main_basis": "..."} ],
    "bindings": [ {"line": <行号>, "target": "现盘自身|历史锚|引用锚",
                   "declared": "<64位>/<bytes>", "recomputed": "...", "match": <bool>} ]
  }
  problems 条目格式：「<文件/行> <违规> <依据>」；禁止无依据裸词命中入 problems。

R8. 本模板相对旧门禁的替换对照（自查清单）
--------------------------------------------------------------------------------
  旧 '## N' 字面小节检查          → R1 节号集合匹配
  旧 '缺要素 <单词>'             → R2 同义词组 + 任务书原文优先
  旧 交付件全文禁词扫描           → R4+R5 行为边检查 + 引证豁免（报告层取消）
  旧 .py 全面子串扫描             → R4 新增调用边（AST）+ 派生副本对母本做差
  旧 绑定行只数条数               → R3 三类锚分治 + 引用锚回验（堵假阴性）
  旧 copies 只数不判              → R6 正本判定 + 关系声明强制
  无 自绑定机制                   → R3-1 扣行自绑定（可复核）
  无 千分位兼容                   → R3-4 数值解析先去逗号

未验项（模板本身未经实战回归，见 GATE_FALSE_POSITIVES.md §6）：
  - 本模板未改写进任何既有工作流（本轮禁止），其「若用于旧现场应全过」的断言
    仅对误报一/二（复跑 problems 集合）做了纸面推演，未实跑新门禁代码；
  - R3-1 扣行自绑定的哈希口径（占位替换的字节层实现）未做样件验证；
  - R2 词组表仅覆盖本轮实测写法，其他领域（D 线/矩阵/断点闭合）的要素同义组
    未盘点，属待增补状态。
