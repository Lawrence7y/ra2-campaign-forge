## 2 第二步 · 「可比性」的判据（本任务核心产出）

### (a) 定义：什么条件下可以直接比较、差值可以归因

两次评测结果可直接比较、差值可归因，**当且仅当**同时满足 7 条：

1. **同一考题**：样本逐条身份冻结 —— `(id, 全文 sha256, tokens, family)` 四元组集合相同，分母 `n` 相同，类别先验相同。
2. **同一真值**：`expect` 逐个相同，且「什么算正类」的**判读本体**（标注手册）冻结并封 SHA。
3. **同一量**：被比较的列是同一个导出量（同名不等于同义）；评分公式 `ok/fp/fn`、阈值、聚合粒度冻结。
4. **同一评分器**：评测脚本及其全部依赖（谓词、词表、骨架、语料加载路径）逐件 SHA256 + 字节数登记，两侧指纹齐备。
5. **恰变一轴**：`{S 样本集, G 真值标注, I 被测实现, E 评测脚本, M 度量口径}` 五轴中**恰有一轴**不同，且该轴被显式声明、旧/新指纹都留盘。
6. **两侧全量重跑**：改动后在冻结集上重跑**全部层/全部列**，不复用旧列；两次产物逐行可配对。
7. **证据链闭合**：每份回归 JSON 都有生成它的脚本及脚本指纹；任一轴指纹缺失 ⇒ 拒绝出具可比证明（fail-closed）。

差值可归因的意思仅止于此：**「在这份冻结考题、这套冻结真值、这个冻结评分器上，把 I 从 X 换成 Y 导致了 Δ」**。它不是泛化结论，不是「A 比 B 好」的产品结论。

### (b) 四要素逐项判定（+ 第五要素 M）

| 要素 | 变了算不算不可比 | 理由 |
|---|---|---|
| **S 样本集** | **不可比**（硬）。增删样本、换 id、换族、分母变化、类别先验变化，全部落在这里 | 分母/难度/正负配比同时变，`correct/n` 与 `correct` 都不是同一个估计量。例外：若显式声明为「两个不同样本集上的两个独立点估计」，可并列展示，但**禁止报差值、禁止用箭头「→」表示改良** |
| **G 真值标注** | **不可比**（硬）。翻 1 条也不可比 | 评分函数变了。模型输出一个字节没改，分数可以自己涨（本次 3 分即由此而来，§1(b)）。这是最隐蔽、最容易自欺的一类 |
| **I 被测实现** | **唯一「该变」的一项；只变它可以归因** | 这正是 A/B 实验的自变量。但前提见 (c) |
| **E 评测脚本** | **不可比**（硬）。脚本未留盘 ⇒ 更差一档：`INDETERMINATE` | 评分公式、输出列定义、加载路径、指纹先验、例外处理都在脚本里。本次 72 版脚本根本不在盘上 ⇒ 「其余输入相同」只能由输出列反推，**未经脚本级复核**，如实标「未验重跑」（`_gpv_regress.py:64-75`、`GATE_PIPELINE_COMPOSE.md:513` 已自认） |
| **M 度量口径**（第五要素，任务书四要素之外的补充） | **不可比**（硬） | `ok/fp/fn` 定义、分母、类别先验、被比较列的导出规则。⚠️ 分母变化若**仅由** S 引起，归入 S 不重复计轴（否则同一次改动算两遍）；但报数字时仍必须声明分母，见 §5(d) |

**判据的收口规则**：`diff_axes` 数是核心。0 → `REPLICATION`（复现校验，不是改良比较）；1 且 S/M 冻结 → `COMPARABLE`；≥2 且无交叉实测 → `NOT_COMPARABLE`；任一轴指纹缺失 → `INDETERMINATE`（**优先于以上所有判定**，fail-closed）。

### (c) ★ 只改一样（如只改算法、样本与标注不变），差值可归因吗？

**判断：可归因，但归因范围很窄，且需 4 个附加条件，否则会退化成 in-sample 调参。**

可归因成立的条件：① `diff_axes == ['I']`，② E 轴两侧指纹齐备且相同（同一个评分器），③ S/G/M 全部冻结并封 SHA，④ 在冻结集上两侧全量重跑、逐行配对。满足时，Δ 的因果解释是「I 的这一处替换」，报告的写法必须是「在这份冻结语料上，把 I 从 X 换到 Y，配对不一致 b/c、p=…」，**不能写成「改良了 N 分」或「A 优于 B」**。

三条限制必须同时声明：
- **不是泛化**：只说明在这批考题上的行为。若这批考题恰是为修 X 的失败样本而构造的（本次正是：K9「精筛覆盖宽进」是为消掉 20 条 FP 而写，见 `_gp_pipeline.py:168-172`、`_gp_DESIGN.md:287`），则 Δ 是**调参收益**，不是泛化增益；须另用盲留出集。
- **须报配对不确定度**：本次 74 版内 chain vs n13 的不一致对只有 `b=2,c=0`，exact binomial 双侧 `p=0.5000`（本会话实算）；对齐后 `b=0,c=3`，`p=0.2500`（`CHAIN_VS_SINGLE.md:112` 引用，其底层 `_final_align_check.txt` 本会话未逐字复读，标「引用上游实跑」）。两侧都不显著 ⇒ 即使只变一轴，也**不能据此下取舍结论**。
- **同量检查**：`chain` 列若换了导出规则，即便只改「算法」，被比较的也已不是同一个量，应判 M 轴变更而非 I 轴。本次就踩了这条（§1(e)#7）。

### (d) 同时变两样：2×2 交叉设计能否救回可归因性？

**能，但必须四格全部实跑；纸面推演不算。**

方案：设两因素 `F1 ∈ {X0, X1}`（如合成算法：并集 / 逐 span）、`F2 ∈ {Y0, Y1}`（如标注口径：旧 / 新），冻结 S（同一批考题、同一分母）、M（同一评分公式与列定义）、E（同一评分器），跑满 4 格：

| | `Y0` | `Y1` |
|---|---|---|
| `X0` | `m00` | `m01` |
| `X1` | `m10` | `m11` |

- F1 在 Y0 条件下的主效应 `m10 − m00`；在 Y1 条件下 `m11 − m01`
- F2 在 X0 条件下 `m01 − m00`；在 X1 条件下 `m11 − m10`
- 交互项 `(m11 − m10) − (m01 − m00)`。≈0 ⇒ 可做加性分解，分别归因；显著 ≠0 ⇒ **「单一原因」这个提法本身作废**，只能报条件效应，「A 导致了 Δ」不成立
- 报配对不一致对 + exact binomial / bootstrap CI，不只报点估计
- k 个因素 → 2^k 格。本次 k=4（S/G/I/E）⇒ **16 格**；实际可收敛为：先把 S/G/E 冻结，只剩 I 一个因素 2 水平（2 格），或保留 2 因素（算法 × 标注）跑 4 格

**对本次的适用性**：72 版脚本已不可得 ⇒ `m00/m01` 两格**无法重跑**（除非接受「用留盘 JSON 代替实跑」，那只能算「结果复算」，不能算交叉实测）。因此交叉设计**救不回本次**。它能救的是**重建基线之后**的实验。

### (e) ★ 可机检的可比性断言

实装：`lead/comparability_20261109/_cmp_assert.py`（本会话新建于唯一写域，只读取两份 JSON + 一份 manifest，不写任何既有件）。

### (c) ★ 怎么保证「一次只改一样」——可执行的纪律（不是「注意点」）

1. **单一真源 manifest + 硬失败**：`_manifest.json` 是唯一真源，列 S/G/I/E/M 五轴每侧的 `sha256`+`bytes`。评测脚本开头读 manifest，对每件只读件 `hashlib` 复算，任一失配 `raise RuntimeError` 且 `sys.exit(1)`。参考现成实现 `_gp_pipeline.py:30-45`（只对两个谓词做了，扩展到全部件即可）。
2. **CI 门禁 = `_cmp_assert.py`**：每次写完回归 JSON **立即**跑；`verdict ∉ {COMPARABLE, REPLICATION, COMPARABLE_CROSSED}` ⇒ 退出非零，且脚本不得把任何 `correct/n` 数字写进报告文件。门禁代码放在写盘之前，不是之后。
3. **一变更单 = 一轴**：每次跑前填机器可读的变更单 `{"changed_axis": "I", "old_sha256": ..., "new_sha256": ..., "all_other_axes_frozen": true, "reviewer": ...}`，复核方签字；空单或 `changed_axis` 多于 1 项，门禁拒绝执行。
4. **脚本留盘铁律**：每一份回归 JSON 必须与生成它的 `.py` 同目录留盘、同批次封 SHA；**无脚本的 JSON 视为不可核验，禁止进入任何比较**。本次 72 版就是反例（`_gpv_regress.py:64-75` 自认、本会话 `find`+`git log` 复核）。
5. **禁止同轮改 `expect` 与 `chain`**：翻标与改算法必须分成两轮、两个版本号、两份产物；门禁检查「同一轮内 `expect` 差异数 >0 且 `chain` 差异数 >0」⇒ 拒跑。
6. **改一项 = 全列重跑**：`CORPUS` 顶层循环对 `naive/r10/r12/n13/chain` 全部重算（`_gp_regression.py:160-181` 的结构已如此），禁止从旧 JSON 复制 `chain` 列。上游 `_cs_align.py:130` 曾 `row = dict(J[it['id']])` 复制旧列，本会话逐字读到并采纳其自我更正（`CHAIN_VS_SINGLE.md:110`）。
7. **只读域 + 独立写域物理隔离**：语料/标注/脚本目录在跑评测时不可写；改语料必须另起版本号与新目录，**禁止覆盖**；每次跑完复算只读件指纹并与 manifest 比对（本会话末次复算即此模式）。
8. **报数前的自动检查**：报告模板里每个 `X/N` 必须引用一次 `_cmp_assert.py` 的 verdict 与 `scope`；缺引用则由模板渲染器拒绝生成。

### (d) 时间有限只能做一步：做哪一步收益最大？

**主选：step3 的最小版 ——「在已冻结的 68 条共有子集上，只换合成裁决算法，两格都实跑，并把两侧脚本 + manifest 一起留盘」。**

理由（可量化）：当前全部争议的实质是「算法替换值多少」，而本会话 §3(d) 已给出唯一有内部效度的信号 `48/68 → 66/68, +18, p=7.63e-06`，但机检判 `INDETERMINATE` 只因 72 版脚本/实现指纹缺失（E、I 两轴 UNKNOWN）。补一次两格实跑 + 全件留盘，可一次性把 `INDETERMINATE` 变成 `COMPARABLE`，产出**唯一一条可归因的结论**，且成本低（68 条、纯离线、不需要出题、不需要真机、不需要改任何既有件，只需在新写域内重建语料并跑两个算法版本）。

**若连这一步都做不了，退而求其次做 step0 的最小版「脚本 + manifest 留盘」**：因为它把「不可核验」变成「可核验」，是其他一切结论的前提，且能立刻把 72 版从「未验重跑」升级为可复核。**不推荐**把有限时间花在 step1（盲留出集）：出题/双盲/κ 成本最高，而在 E 轴不可核验的前提下，新语料也救不回跨版归因。

⚠️ 无论做哪一步，都不得把结果写成「合成链比单层好/差」——step3 只产生「在同一批考题上，算法 X 相对算法 Y」的条件结论。
