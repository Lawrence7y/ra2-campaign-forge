# DISAGREE · W23 与任务书/前卡的分歧记录

本卡无实质性「不认同」；以下 4 条是对任务书条目的**解释取舍**与对前卡文档的**勘误**，
全部有实测依据。

## 1. 对 W22 APPLY.md 命令语法的勘误（重要，影响回放）
W22 `APPLY.md` §2 写的 `git apply -c core.autocrlf=false -c core.eol=lf ...` 在本机
git 2.54 上是**无效语法**（`error: unknown switch 'c'`，git 不执行任何操作）。`-c`
必须放在子命令之前：`git -c core.autocrlf=false apply ...`。另外本卡还实测到一个
W22 未记录的坑：**在仓库的子目录里**对 `ra2forge/...` 路径补丁跑 `git apply`，git 会
打印 `Skipped patch '...'` 并**静默以 exit 0 退出**（看似成功、实际零改动）；必须在
**仓库根**执行。W23 APPLY.md §2 已按实测修正并写明这两个坑。W22 的回放结论本身
（回放树与 v6 逐字节一致）依然可信——只是文档里的命令串抄错了形式。

## 2. C1/C2 的比较目标从 v0.6 换成 v0.7（用例保留、对比对象前移）
任务书要求「保留 W22 的 14 用例不削弱」。W22 的 C1/C2 语义是「新旧工具在旧清单上行为
一致」——在 v0.7 语境下，把对比对象留在 v0.6 会让这组用例不再测试 v0.7。因此本卡把
C1/C2 的**对比目标**改为 W21 v0.5 参考构建 vs **v0.7**，判据逐条保留（同退出码、
输出逐字节一致、终态逐字节一致），并做两处**显式归一**（非静默）：
- 输出对比剔除 v0.7 在旧清单上多打的**一行**降级警告（`install seal ...` 标记行）；
- C2 终态对比排除 v0.5 卸载后留下的**一个** seal 残留文件，并**新增**断言明确这一
  差异（v0.5 侧留、v0.7 侧清）。
两处均在用例日志里有 `[note] v7-adaptation` 说明。判定：这是**移植**不是**削弱**——
语义断言一条未减，证据反而更强（v0.5×v0.7 双向兼容均实测）。

## 3. S5/S6 的「拒绝而非降级」取舍
任务书允许「明确警告**并拒绝/降级**」。本卡选**拒绝**（exit 7/8、零写入）而非「警告后
继续删」：seal 世代清单 + seal 异常 = 记录未经核验，此时删除/还原的正是 W21 §3 指出的
伪造面；且拒绝状态可被 `verify` 精确指出、恢复路径明确（重装同包）。旧清单（v0.6 及
更早）才是降级（警告后照常）。任务书 S5 的措辞「不得静默删除」得到最强满足。已在
VERIFY.md §3/§4 写清并实现一致。

## 4. `verify` 对孤儿不改变退出码（任务书留白处的取舍）
任务书只规定「有 changed/missing = 非零」。孤儿（`.bak`/`.removed.bak`/staging 残留）
是**未跟踪的残留**，不等于漂移——很多正常场景（用户手工备份、卸载被拒绝后遗留）都会有
孤儿。本卡取「列出 + exit 0」，并在 `--help`、VERIFY.md、S8 用例三处写明。若 Lead
希望孤儿也计入非零退出码，改动是一行（verify.py 的 `_SEVERITY_ORDER` 加一类），但
需要同步改三处文档与 S8 判据——建议先明确语义再改。

## 5. 恢复路径用「重装同包」而非新增 `--rebuild-seal`
任务书未要求就地重算 seal 的命令。本卡刻意**不提供**：任何「就地重算」入口都会同时
服务篡改者（改清单→重算 seal→卸载），与「防误操作 ≠ 抗恶意」的边界陈述打架；重装
同包路径复用既有 install 语义（含 PKG-IDENT01 门禁），S5 用例实测可用。唯一例外
（未盖章包需 `--adopt-legacy`）已写入 VERIFY.md §2.4 与 UNCOVERED 的混用限制。
