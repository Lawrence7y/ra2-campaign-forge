我在 `ra2bench\gamemd.exe` 上直接反汇编 G4 置位点邻域（`[本次实测]`）：

```
0x004C7903  8b 0d 84 ed a8 00   mov ecx, dword ptr [0xa8ed84]    ← 帧计数
0x004C7909  51                  push ecx
0x004C790A  68 0c 0e 82 00      push 0x820e0c                   ← 格式串
0x004C790F  e8 cc ef f3 ff      call 0x4068e0                   ← 打印（见下注）
0x004C7914  83 c4 08            add esp, 8
0x004C7917  c6 05 48 3d a8 00 01  mov byte ptr [0xa83d48], 1     ← ★ G4 置位
0x004C7922  81 c4 70 03 00 00   add esp, 0x370
0x004C7928  c3                  ret
```
`.data` 地址 `0x820E0C` 处的字节与文本实读：
```
50 72 6f 63 65 73 73 69 6e 67 20 45 58 49 54 20 65 76 65 6e 74 20 6f 6e 20 66 72 61 6d 65 20 25 64 0a 00
=> "Processing EXIT event on frame %d\n"
```
紧邻字符串：`TXT_SPECIAL_WARNING`，以及**源码路径 `D:\ra2mdpost\Event.CPP`**。

⇒ 结论分级：
- **`[本次实测]`**：G4 的置位点紧跟「打印帧计数 + 格式串 `Processing EXIT event on frame %d`」；
- **`[静态推断-强]`**：G4 = 「正在处理一个 **EXIT 事件**」的挂起标志；
- **`[转引-新]`**：本镜像含调试源码路径 `D:\ra2mdpost\Event.CPP`（**构建出处线索**，对后续查证有用）；
- **注**：打印走 `call 0x4068E0`，而 `0x4068E0` 磁盘字节是裸 `C3 ret` ⇒ 该打印**运行期可能不输出**
  （可能被 patch 掉，或是发布版去掉了调试输出）。**这不影响 G4 置位**——置位是紧接其后的独立指令。

⇒ 因此「退出/放弃任务确认框 ⇒ G4==1」这个 **P2 预测有硬静态依据**，不是猜测。
