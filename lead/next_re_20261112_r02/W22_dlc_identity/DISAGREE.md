# DISAGREE · 任务书措辞与本卡实现事实的出入（W22 / PKG-IDENT01）

核心需求全部落地；以下是实现时做出的**显式裁量**，每条给理由，供下一轮任务书校正。

## 1. `package_digest` 的定义收窄为"安装集"，不是任务书例句的"构建产物所有散装文件"
任务书：『例如构建产物中所有散装文件的 名字+sha256 按名排序后的 SHA-256』——是例句
不是硬性定义（"定义要写清"是硬要求）。实现取 `package_files()` 集合（BATTLEMD98.INI +
*.MAP + expandmd98.mix），排除 BUILD_REPORT.txt / INSTALL.txt / story.md。理由（IDENTITY.md
§2）：指纹的用途是"多代升级判定 + 条目溯源"，必须恰好指纹化**进入游戏目录的字节**；
报告/说明文档不落盘，计入只会制造"只改文档也翻指纹"的噪声与不可复现性（报告含路径）。
且实现从**计划步骤的 sha** 现场计算（`package_digest_from_steps`），清单指纹与实拷字节
结构性地不可能不一致——这比"先算目录指纹再装"更强。

## 2. `--adopt-legacy` 的适用面比任务书字面宽一侧：对称覆盖"新包未声明"
任务书只点名『有清单但 package_id 为 unknown ⇒ 要求 --adopt-legacy』。实现里，**反向**
情形（清单已声明 id=X、新包无声明）同样 exit 4、同样可被 `--adopt-legacy` 采纳。理由：
两者是同一类"指令边界不清"——工具无法证明新包是 X 的后继，只能猜；保守解都是显式
断言。若任务书本意是"这种情况一律硬拒"，一行 if 即可收紧（当前行为写在
`preinstall_plan` 的 verdict 块，注释已标明）。回归 V1b/P4 只覆盖了任务书点名的一侧。

## 3. 退出码选了 3 / 4（任务书只要求"可区分的非零"）
3 = package_mismatch（异 id，不可释放）；4 = legacy_adopt_required（身份未声明，可显式
采纳）；1 = 其余 OSError/ValueError；2 = argparse 既有约定。理由：两种拒绝的**用户处置
完全不同**（一个只能先卸载，一个加个 flag 就能继续），合并成一个"身份拒绝码"会把
最有用的信号磨掉。若项目要归一为单一码，改 `cli.py` 两行即可。

## 4. "V1 升级"用例在新语义下被迫拆成 V1a/V1b
W21 的 V1 是"未声明包 A→A′ 免 flag 升级"。本卡 T2 落地后，该序列**正确地**变成
exit 4（清单 package_id=unknown ⇒ 不猜）。原样保留会与 P3 自相矛盾。因此 V1 = V1a
（免 flag ⇒ exit 4，零写入）+ V1b（--adopt-legacy ⇒ W21 孤儿升级照旧）。这不是放宽，
是 T2 的必然推论；"同 id 升级免 flag"由 P1 覆盖。

## 5. `--force` 维持 install 侧绝对 no-op
任务书要求"写清 --force 能覆盖什么、不能覆盖什么"。最诚实的答案沿用了 v0.4/v0.5 的
事实：install 侧 --force 从未有过行为，本卡也不给它任何（包括"覆盖身份拒绝"）；
`--help` 文案与 P2 实测（--force 下仍 exit 3、零写入）双证。未实现任何"放宽"，
无需要豁免的裁量。

## 6. 清单保留 `package`（路径）字段
身份判定已完全不依赖路径，但字段保留：`_rollback` 需要旧清单的 `package` 路径做孤儿
回滚重装（W21 语义），且对 v0.3/0.4/0.5 清单保持 schema 连续性。字段语义降级为
"操作数据 + 审计"，不再是身份判据——与任务书"package 只是一个绝对目录路径，不是身份"
的批评一致，修的是**判定**，不是删字段。

## 7. `precheck` 之外新增顶层 `supersedes` 审计块（任务书未点名）
多代升级回滚判定是任务书点名的三件事之一。每条目的 `source_package_digest` 给了
**条目级**来源；`supersedes` 给了**记录级**的上一代三元组（id/版本/指纹）+ adopted_legacy
旗标，链式串起来就是多代史。判定逻辑不读它（仍是"记录+sha256"纪律），纯审计。若嫌
清单膨胀可去掉，功能不受损。
