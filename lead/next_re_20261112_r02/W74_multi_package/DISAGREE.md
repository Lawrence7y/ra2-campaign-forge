# W74 · DISAGREE.md

## 1 · 与卡面预设口径的差异（不是反驳，是澄清）

- **卡面把「两个战役包能不能共存」与「卸载顺序的可逆性」并列成两个问题**。`[本次实测]` 本卡发现：v15 直接拒绝第二个包（零写入），**不存在共存态**，因此"卸载 A→B / B→A 的顺序"在当前实现里**不是一个可表达的 CLI 概念**（`uninstall` 没有 `--package`，只有一份全局清单）。两种顺序实测是同一对调用、结果相同且都还原官方。本卡按语义分别标注并各跑一趟以忠实回答，但结论是"顺序问题不成立于 v15"，而不是"某种顺序更可逆"。这不推翻卡面，只收紧了它的前提。
- **卡面暗示的拒绝退出码可能是 3（`package_mismatch`）**。`[本次实测]` 路线 (a) 的 `--feature-set` 路径下**先命中的是 33 `INPLACE_OFFICIAL_MISMATCH`**（`resolve_integration.py:936-972` 在 `install.py:2026` 先于 `install.py:2032` 的身份闸门执行）。本卡用 append 模式的 B2 单独把 **exit 3** 也实测出来了，证明两道闸门都真实且都不可放行。若只看源码文档 `install.py:306` 的 "初版不支持并存 / CLI exit 3" 就写"拒绝码是 3"，会与真机路线 (a) 的实测不符。

## 2 · 与已签发结论的关系

- `[转引]` `LEAD_RULING_C_line_route_a_first.md`（真机走 (a)、(c) 冻结）、`LEAD_VERIFY_W63.md` / `LEAD_VERIFY_W70.md`（三关链贯通、卸载后官方战役功能级可用）——本卡**不重新论证、不反驳**，且实测与之相容：单包生命周期仍逐字节可逆。
- 本卡新增的是**产品化边界**：(a) 靠独占 `[SOV1]`，而 v15 manifest 是单包记录 → 一次只能一个包。这是 (a) 的能力边界，不是 (a) 本身的失败。

## 3 · 本卡不同意的做法（若后续有人据此推进）

- **不同意**把 `inplace_preflight` 的 33 放宽就宣布"多包共存已支持"：identity 闸门（exit 3）仍会拒绝，且单层 `.bak` / 单 `original_sha256` 无法支撑两层还原点。`[本次实测]` + `[本次读码]` 双重证据见 `MULTIPACK_RESULT.md` §2.2 / §7-C。
- **不同意**用"改 `ra2forge_install.json` 把 `package_id` 手改成 B 的"来伪造共存态再断言可逆性：那是手改记录，不是 v15 行为；本卡没有这么做。
- **不同意**在结论为互斥时做真机（卡面已规定不做）；本卡未取锁、未启动游戏。
