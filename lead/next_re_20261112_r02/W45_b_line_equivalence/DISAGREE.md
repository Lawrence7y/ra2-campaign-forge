# DISAGREE.md · W45 与题面/上游口径不一致处（不迁就）

> 原则：与任务卡措辞或上游隐含前提不一致处**逐条登记并给出取舍理由**，不为了「好看」而迁就；也不擅自扩大范围。分级同 `EQUIVALENCE_SPEC.md` §0.1。

## D1 · 「干净沙箱」不能按字面理解为「未安装任何包的原版」

- **题面**：「臂 A：干净沙箱，进官方战役/单人局」。
- **事实** `[转引]`：真 `ra2youli` 早有既存 v0.3 旧包（`ra2forge_install.json=fe3bdf62…`，「钢铁残响」，`BATTLEMD98.INI` + 替换过的 `ECH01.MAP`），Lead 未卸载、等用户裁决（`PAUSE_STATE_20261113.md:101`、`HANDOFF.md` §9.3）。W43 `TRACK_B_gates.json` 亦判 `is_clean_retail_gold=false` / `overall_verdict=UNDETERMINED`。
- **取舍**：本卡把「干净沙箱」重新定义为「**两臂共同、同一份字节的隔离副本，且两臂对既存 v0.3 旧包做完全相同的处理**」（规格 §2.3 C2 二选一）。A 臂绝不写成「官方未修改原版对照」。
- **理由**：任务书 L89 原文「分析镜像也不能只凭游戏名就视作官方未修改原版；后续『原版对照』须另行确认来源与指纹」`[本次读码]`。若把既存旧包当成「干净」，两臂都会带着它，尚可对照；但若把「卸旧包」只做在一臂，就会把一个 6 文件 / 1,088,616 B 的改动混进自变量。

## D2 · 「装 v13 包」——盘上没有 v13 包，只有 v13 补丁源码树

- **题面**：「臂 B：装 v13 包」。
- **事实** `[本次实测]`：全仓 `rg -l v13` 只命中 `W43_b_line_s3\ra2forge_patched_v13\`（源码树），无任何构建好的包目录；`W44` 用的是 **v12** 工具链 + `--mapselmd --csf-out/--csf-base`。`[转引]` W43 §1：v13 不启用新开关时构建产物与 v12 **8/8 逐字节相同**。
- **取舍**：B 半若执行，须先「用 v13 `cli.py` 从固定 design 构建包 → 记录包产物 SHA-256 / `package_digest` → 安装」；且必须写明「本卡测的是**包安装**对官方路径的扰动，不是 `gamemd.exe` 补丁前后等价」（规格 §0.2）。
- **理由**：本会话禁止改 exe/dll；`gamemd.exe` 两臂必须保持 `73201cc0…` `[本次实测]`。把「v13 包」理解成「打了补丁的 exe」会直接越出授权与可比量定义。

## D3 · `battle_cnt` 被列为「等价可比量」会误报——必须允许设计预期差异

- **题面**：把 `battle_cnt` 与 `scen_filename`/`scen_battle_idx` 并列为只读 RPM 可比量，隐含「两臂应相等」。
- **事实** `[转引]`：W44 `E2E_RESULT.md:106` 实测装包后 `battle_cnt=15`（14 官方 + `RA2F1`），不装包应为 14。装包本就把新 battle 登记进 Battles 表。
- **取舍**：规格 §2.5 白名单 W2 规定判据为 `B − A == k`（`k` 由包内容**事先**算出），而非「相等」；`+k±1` 或官方场景上 `scen_filename`/`scen_battle_idx` 有差异都在白名单外。
- **理由**：否则一次正常安装就会被误判成「行为不等价」。但白名单**不是免责**：`k` 不得事后拟合，且 `scen_filename`/`scen_battle_idx` 在官方路径上必须严格相等。

## D4 · 「存档文件字节」不能直接判等价，必须先有噪声基线与非确定字段白名单

- **题面**：把「存档文件字节」列为可比量，隐含「逐字节相等 ⇒ 等价」。
- **事实** `[转引]`：W44 只做过单臂单次存档（627,453 B / `ef9e51e9…`），没有同臂重复；存档可能含时间戳 / 路径 / RNG 状态等非确定字段，本卡未定位其偏移。
- **取舍**：规格 §3.4 要求「预期差异白名单**开跑前**声明 + `frame` 对齐 ≤1 拍 + A1/A2 噪声基线」；A1≠A2 时**只能写「无法判定」**。
- **理由**：题面本身要求「两臂不等价时要区分『改造导致』还是『环境噪声』」。存档字节是最容易被环境噪声污染的项，不给基线就下结论等于把噪声当改造。

## D5 · `verify` 退出码是安装态门禁，不是行为等价证据

- **题面**：把 `verify` 退出码列为六项可比量之一。
- **事实** `[转引]`：`W23\VERIFY.md:31` 明写「`package_digest` 只能证明清单内部一致，不能证明磁盘上是什么」；RE-N09 L287 通过条件原文「文档门禁 PASS 不代替游戏行为对照」；W43 `UNCOVERED.md` U-W43-14 重申 82/82 只证离线文件层。
- **取舍**：规格 §3.5 把 `verify exit 0` 定性为「允许开始行为对照的**前置门禁**」，**不计入六项行为结论的通过数**，并明写「不得用它替代任何一项行为对照」。
- **理由**：把安装态门禁算进行为态，正是 B 线此前被判「行为验证唯一没做」的漏洞本身（`PAUSE_STATE_20261113.md:29`）。

## D6 · 「同设计」不等于「两臂文件树相同」

- **题面**：混杂因素要求控制「同设计」。
- **取舍**：规格 §2.3 C3 把「同设计」解释为「同一个**官方场景/图/规则/速度/AI 席位/初始条件**，且 B 臂的包由固定 design + 固定构建命令产出、每次用同一包字节」；**不**要求两臂文件树相同——B 臂多出的文件正是自变量。
- **理由**：若要求文件树相同，等于取消 B 臂的安装动作，实验自相矛盾。「同设计」约束的是**游戏侧输入**，不是安装态产物。

## D7 · 「控件可见性」是 Win32 状态，不是渲染

- **题面**：并列「控件可见性」与「渲染侧需注入 ⇒ 不可判」。
- **取舍**：规格 §1.6 用 `IsWindowVisible` 的布尔集合作可比量（可判）；但明确「控件是否被绘制 / 文字渲染是否正确」需截图，**逐帧渲染等价因注入被禁 ⇒ 不可判**（§4.1）。控件文本只用于判存在，不用于判渲染。
- **理由**：与 W44 Q-A（CSF 值驱动主菜单按钮渲染，但控件文本 ≠ 渲染文本）`[转引]` 一致；把 `visible=True` 写成「渲染等价」会重复 C 线已经踩过的坑。

## D8 · 臂 C 不可实现，不假装做了

- **题面**：「可选臂 C：装包但禁用某特性」。
- **事实** `[转引]`：W43 U-W43-6（`resolve()` 未接线、执行层仍是 v12 整包事务）、W36 §3.3.1（构建期可分、安装期全有全无）。
- **取舍**：规格 §2.2 明写 C **本次不可实现/不可判**；若 B 半做了「少一个文件的包」，标为「另一个 `package_digest` 的包」，不称「禁用特性」。
- **理由**：不迁就题面的可选项而伪造一个不存在的开关；否则会给出「独立开关已具备」的假证据，而它恰恰是 B 线四承诺里另一项未完成的工作（`PAUSE_STATE_20261113.md:29`）。

## D9 · 「进官方战役/单人局」不劫持 `[SOV1]` 的可达性未证

- **题面**：臂 A「进官方战役/单人局」，臂 B「同样操作」。
- **事实** `[转引]`：W27/W39/W44 的进图都用了 **D2 诊断变体**（把 `[SOV1] Scenario` 改成我方地图借苏联徽章）；官方原样 `[SOV1]` 打到胜利点 Continue 的 E1 实验未执行（RUNLOG §10.5）。
- **取舍**：规格 §1.7 要求 ≥2 硬指标确认「局内」；`UNKNOWNS.md` U11 登记「官方路径不劫持时是否可达」为 `[待运行验证]`。若不可达，B 半须写「相位不可达 ⇒ 不可判」，**不得**悄悄换 D2 变体后仍称「官方战役」。
- **理由**：换了入口就换了设计，违反 §2.3 C3/C4。

## D10 · 不把「回归 82/82」「游戏没崩」写成等价，也不把「无法判定」粉饰成等价

- **题面口径**已明令，本卡完全采纳，并在规格 §0.3/§3.7 固化为红线与总判定规则。
- **补充不迁就的一点**：任何一项可比量为「不可判」（尤其渲染侧 §4.1）时，总判定只能是「**无法判定**」；不因为「其余五项都等价」就写「行为等价」。
- **理由**：RE-N09 通过条件要求安装态/执行态/行为态**分别**有证据，缺一项即不成立。

## D11 · 还原集合不含 `ra2forge_install.json` / `.seal`

- **题面**已明写；W44 §5 工具缺陷 A 给出实测教训：把安装记录列入还原集合，会用 PREP 时的 v0.3 旧清单覆盖 v12 安装记录，导致 `verify` 临时失败 `[转引]`。
- **取舍**：本卡 `finally` 只逐字节还原 `RA2MD.INI` / `ddraw.ini`（+ `RA2MD.INI.benchbak`），移除投放物；安装记录/seal 属 install/uninstall 生命周期，不属配置还原。`REAL_DIR_PROOF.txt` 也照此标注。
- **不迁就处**：若 B 半在沙箱内做 uninstall，卸载后沙箱的清单/seal 变化是**安装事务结果**，不能拿真目录的 `fe3bdf62…` 去「还原」沙箱；真目录本身全程只读零改动。
