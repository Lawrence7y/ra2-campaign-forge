## 2 · 裁决

1. **真机验收先走 (a)**。理由三条，按权重排序：
   - **不动 `gamemd.exe`**。整个项目的基线不变式（`73201cc0…`）是 A 线/B 线所有对照的锚；改 exe 会让"原版对照"这个概念失效，代价远超收益。
   - **可逆且已有先例**：W27 的 D2/D3 就是这条路，进图证据现成；`.bak` + 清单 `original_sha256` 提供逐字节还原保证（W60 INPLACE2 已实测相等）。
   - **真机风险最低**：失败只影响沙箱里的 INI，不碰代码段。
2. **(c) 不否决，但压在后面**，且设两个前置门：
   - **门 1**：徽章图来源解出（W61 正在查；若第三枚徽章只能渲染成空框，这条路没有产品价值）。
   - **门 2**：明确接受"分发打过补丁的 `gamemd.exe`"，并给版本守卫一个可用口径（例如把改过的 exe 登记为已知构建，而不是一律拒绝）。
3. **(c) 不进本轮机真**。只做离线补丁与静态验证。
4. **不再考虑**"打开隐藏调试列表"路线（W57 静态无写入者 + W58 证明该门控与徽章数量无关）。

## 3 · 真机卡（W63）要验到什么程度才算过

不是"能进图"就算过。**C 线的产品目标是一条可通关的多关链**，所以验收按 W59 的静态结论逐关验：

| 阶段 | 判据（可观测） |
|---|---|
| 进菜单 | 苏联徽章可点（它已被 `[SOV1]` 改写） |
| 进 M1 | `Scen+0x125C` == 我方第 1 关文件名 |
| M1 通关推进 | 结算「任务完成」→ `Continue` → `Scen+0x125C` == 我方第 2 关；`Scen+0x35A0`(WORD stage idx) **递增** |
| M2 通关推进 | 同上 → 第 3 关 |
| M3 终止 | `Scen+0x34AC`(EndOfGame)=yes 生效 ⇒ 走结算/回壳，**不再** `Start_Scenario` 到第 4 关 |
| 卸载 | `BATTLEMD.INI` 逐字节还原（SHA 等于清单 `original_sha256`），投放文件清空 |

`[口径纪律]` 若只验到"进 M1"就停，只能写「(a) 路线能把我方战役送进游戏」，**不得**写「多关链贯通」。这是 W27 当年踩过的坑（把"进图成功"当成"链贯通"）。
