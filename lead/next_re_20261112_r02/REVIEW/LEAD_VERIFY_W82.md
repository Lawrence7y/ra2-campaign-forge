> 记录人：Lead｜时间：2026-11-14 10:29｜卡：W82（**GLM-5.3-Flash**，纯离线，7 个脚本全 exit 0，SHA-256 MATCH）

## 1 · 求值处（VA 级）

| 项 | 值 |
|---|---|
| **事件求值函数** | **`0x0071E940`** |
| 分发方式 | `mov ecx,[ebp+0x2C]` 取 event TYPE；**索引 = type−13**（`0x71E950 lea eax,[ecx-0xD]`，范围 13..61）；压缩字节表 `0x71F248` → 跳转表 `0x71F218` |
| **type 13 → case 0 → `0x0071EC33`** | （type 51 共享同一体） |
| 调用链 | 每帧触发器扫描 `0x6E5414` → `TriggerClass::Spring 0x7264C0`（`0x726522 lea eax,[esi+0x34]` 把触发器内嵌定时器作为 arg3） |

## 2 · **关键：求值是帧差，不是秒**

```
fired  ⟺  ([0xA8ED84] − timer.started)  ≥  timer.duration
```
- `[0xA8ED84]` = **逻辑帧计数器**：主循环 `0x55DE81` 每帧 +1；场景复位 `0x68466B`/`0x686765` 置 0
- 两个操作数**都是帧**，**求值处无任何换算**

## 3 · `15` 在哪：装弹函数 `0x00726400`，被 `type==13` 闸守住

```
0x72642C? cmp dword ptr [edi+0x2C], 0x0D   ; ← type==13 闸
0x726428  mov eax, [edi+0x34]              ; 事件参数 N（设计秒数）
0x72642E  lea eax, [eax+eax*2]             ; N×3
0x726437  lea eax, [eax+eax*4]             ; N×15   ← 写入 timer.duration (0x72643F)
0x726431  mov [esi+0x34], ecx              ; timer.started = 当前帧
```

`[签发]` **`timer.duration = 15 × N`（帧）**。引擎内部**没有秒时钟**，只有帧计数器；`15` 仅作为**换算系数**出现。

`[为什么全镜像搜 `imul` 常量 15 是 0]` 编译器用 **`lea eax,[eax+eax*2]`（×3）+ `lea eax,[eax+eax*4]`（×5）**实现 ×15，**不是 `imul`**。
`[它自己证伪了 step1 那个唯一命中]` `0x006B024E imul eax,[eax],0xf` 是**函数指针表 `0x006AFD7A…0x006B020F` 的误读码**，不参与时间换算。**主动证伪自己的第一步发现，做得对。**

## 4 · 它校正了我一处：`+90` 不是"公式外常量"

`[W82 的精确化]` `+90` = **`timer.started`（装弹时刻的帧值）**，不是凭空加的偏移。所以：
> `frame = started + duration = 90 + 15N`

`[真实秒]` `0.48N + 2.88`（÷31.25）。
`[仍未定谳]` **为什么装弹发生在帧 90**（U1）。它给了可判别的真机做法：读 `*(Trigger+0x34)`（started）与 `+0x3C`（duration），(a) `started≈90, duration=15N` vs (b) `started≈0, duration=15N` 且命中固定在 `15N+90` 帧的转场点。

## 5 · 旁证（同一 15 fps 基准的两处独立印证）

- **type 47 求值体 `0x71EB28`** 用 `0x88888889` 魔数算 **frame/15** 与参数比较（这正是我 step1 看到的形态）
- **任务倒计时 HUD `0x6D4963`** 同样 ÷15 显示秒

⇒ 「**1 秒 = 15 帧**」是引擎触发器/计时器的**系统性时间基准**，不是某处特例。

## 6 · 这条解决了什么（对项目的实际价值）

`[签发]` **`survive(N)` 现在是完全可解释、可预测的**：
> 设 N 为设计秒数 ⇒ `timer.duration = 15N` 帧、`timer.started = 装弹帧（实测 90）` ⇒ **判胜帧 = 15N + 90**、**真实秒 = 0.48N + 2.88**。

`[对既有结论的意义]` 这**反向加固**了 `LEAD_VERIFY_W79.md` 的判断：三关链/五关链的"链推进/终止"结论不受影响；而"8 秒通关"这个说法**现在有了精确的错误原因**（设计 8 秒 ⇒ 实际 6.72 秒，因为 `15×8=120` 帧 + 90 帧起点 = 210 帧 = 6.72 秒）。
`[对今后卡的约束]` **凡涉及时间的判据（等待窗口/超时/对齐）一律按 `15N + 90` 帧算**，不要再写"N 秒"。
