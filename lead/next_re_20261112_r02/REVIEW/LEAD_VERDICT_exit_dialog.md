而 S_sleep 是 `gamemd+0x207f17` —— 两者前 3 帧相同、第 4 帧不同，是可靠的区分点。

## 2 · 决定性的栈对比

**D1a/D1b/D1c（放弃任务确认框打开，三趟完全一致）**：
```
win32u.dll+0x11ac → USER32.dll+0xc7f51 → DDRAW.dll+0x22b06 → gamemd.exe+0x13eb1c
```

**这与批次 B 的 Esc 菜单签名（C1a/C1b/C1c）逐帧完全相同** —— 两种**不同**的模态 UI，**同一签名**。

**S_sleep（14412 基准，仍未被复现）**：
```
ntdll+0x7858c → KERNELBASE+0x16a1f0 → KERNELBASE+0x16a18f → gamemd+0x207f17
→ USER32+0x74775 → USER32+0x3505d → gamemd+0x20833f
```

⇒ **S_sleep 与「模态 UI 打开」无关**，是另一条路径。

## 3 · 因此确立的泛化（本卡最大净收益）

把此前的 `S_menu` **更名并升级为 `S_modal_ui`**：

| 签名 | 帧序列 | 触发条件 | 帧计数 | 四门控 | 等级 |
|---|---|---|---|---|---|
| **S_modal_ui** | `win32u+0x11ac → USER32+0xc7f51 → DDRAW+0x22b06 → gamemd+0x13eb1c` | **任意模态 UI 打开**：Esc 局内菜单 / 放弃任务确认框（**两种已实测**） | **停推** | **全 0** | `[本次实测]` |
