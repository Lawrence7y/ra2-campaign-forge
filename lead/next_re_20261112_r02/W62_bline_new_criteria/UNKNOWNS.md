# UNKNOWNS.md — W62 / RE-N09

> 本卡只交付**判据 + 被验证过的判据工具**，不交付等价性结论。以下按分级列出未定谳项。
> `[本次实测]` 本卡真跑；`[本次读码]` 本卡读过代码/文档；`[静态推断]` 由读码推出、未在本卡实测；`[转引]` 引自上游 REVIEW/卡；`[待运行验证]` 需后续真机卡。

## U1 · `[静态推断]` C 判据最脆弱的假设：**白名单是"名字"，不是"内容"**

`CRITERIA_SPEC.md §1.2` 的引擎派生白名单是**固定名字**集合：`ra2forge_install.json`、`ra2forge_install.json.seal`、`<n>.ra2forge.bak`。审计只看**路径**是否 ⊆ `D`，不看这些文件的内容是否合法。
⇒ 若装包器把恶意/错误字节写进一个恰好叫 `ra2forge_install.json` 的路径，C 判据会放过它。v15 自身有 `verify` 命令管 record 自洽性（`cli.py:34-50` `[本次读码]`），但**本卡未调用、未纳入 C 判据**。这是 C 的结构性盲点。
后续卡可考虑把「install record 的 sha 自洽」作为 C 的第二道门，但那需要在**新卡里事先声明**，不能在本卡事后补。

## U2 · `[静态推断]` C 判据不覆盖**运行期**行为

C 只快照 `install`→`uninstall` 生命周期内的**文件系统写入**。红线禁止启动 `gamemd.exe`，因此本卡**不证明**游戏运行期零干扰（不读活内存、不 attach、`I launched 0 / attached 0`）。措辞上 C = "安装期非侵入性"，不是"运行时不干扰"，更不是"行为等价"（Lead `LEAD_VERIFY_W55B.md §4` `[转引]`）。

## U3 · `[待运行验证]` B 判据的全部观测量都未在真机上采过

`0xA8B230` 取 `Scen*`、`+0x125C` / `+0x35A0` / `+0x34AC` / `+0x34B0` / `+0x34CC` 的地址语义来自 `REVIEW\LEAD_VERIFY_W59.md §5` `[转引]` 与 W39 真机 `[转引]`；`w45_dual_track.py` 的 `ReadProcessMemory`/`EnumWindows` 采集层本卡只读过前 120 行 `[本次读码]`，**未验证**这些地址在后续镜像/不同对局阶段能稳定读到。字段缺失时 `tool_b_stats.py` 会抛错或判 `UNDETERMINABLE`，但"能采到"这件事本卡未证。

## U4 · `[待运行验证]` B 的阈值只在**合成数据**上验证过实现正确性，未做真机校准

`n_min=30` / `N_max=0.30` / `k_ratio=2.0` / `alpha=0.05` / `theta_ui=0.95` / `qs` 全部是 `CRITERIA_SPEC.md §2.5` 的**事先声明值**，本卡只证明统计判据的**实现**能把"同分布"与"明显偏移"分开（`[本次实测]` B-POS/B-NEG/B-NEG2）。
真机帧增量噪声分布未知：若同臂两次运行的 `N_ks > 0.30`，判据会按 B-1 直接输出 `UNDETERMINABLE(reason=noise_band_unstable)` —— **这正是设计意图**（吸收 W55b §2.1 的教训 `[转引]`），但也意味着真机首跑很可能拿不到 `SAME_DISTRIBUTION`/`SHIFT_DETECTED`。

## U5 · `[静态推断]` `dframe` 归一化假设

`CRITERIA_SPEC.md §2.1` 事先声明用帧号**一阶差分**代替 raw frame，理由是跨运行起点不可比。但这假设「帧增量分布」本身是可比量。若引擎帧率被挂钟/系统负载/渲染节流影响，且两臂负载不同，KS 检出的可能是**环境噪声**而非装包效应；B 判据**无法区分**这两者。这与 W55b 的 `N` 不可稳是同源风险 `[转引]`。

## U6 · `[转引]` 部分字段的**值语义**未定谳

`REVIEW\LEAD_VERIFY_W59.md §4` `[转引]`：`[0xA8E9A0]` / `[session+0x30D8]` 语义未定谳；`scen_stage_idx=8` 的值语义仍降级为 `[转引]`。本卡把 `stage_idx` 当**可比量**（只比较多量/多重集），**不解释**其值的含义。若后续卡要按 stage 值下结论，须先定谳。

## U7 · `[静态推断]` UI 控件 id 集合的采集口径未定

`ui_controls` 定义为"可见控件 id 集合"（`EnumWindows`/`EnumChildWindows`）。不同分辨率、皮肤、窗口焦点、DPI 下控件 id / 可见性可能变化；`theta_ui=0.95` 未真机校准。本卡合成数据里 UI 恒定，`J=1.0` `[本次实测]`，不能代表真机。

## U8 · `[本次实测]` C 判据只在**合成沙箱**跑过

沙箱 `gamemd.exe` 是 inert placeholder，`BATTLEMD.INI` 是官方 2733 B baseline，装前文件共 7 个 `[本次实测]`。真实游戏目录会有更多 `*.MIX`/`*.CSF`、其它 mod 的覆盖、符号链接、ACL、只读属性、防病毒占用等。本卡两个用例（普通包 / inplace 包）的写入集形状**不能外推**为"所有包、所有目录布局下都 ⊆ 声明"。

## U9 · `[静态推断]` 自动生成存档名的第二非确定源对 B 观测量是否有影响未知

W55b 发现 `Scenario Description` / `\x05SummaryInformation` 长度相关差异（`LEAD_VERIFY_W55B.md §2.2` `[转引]`）。本卡 B 判据**不使用存档字节**，但该非确定源是否也会扰动帧增量 / 内存字段 / UI，未验证 `[待运行验证]`。

## U10 · `[本次读码]` v15 inplace 的字节改写细节

`battlemd_inplace.py` 已读 `[本次读码]`：纯字节级 helper，只改 `[SOV1]` 四个键、保留 CRLF 与其它节，2733→2730 B；`rewrite_sov1()` 的**逐分支实现**本卡未逐行审计（读了 1-80 行）。C-B 的 `.bak` 逐字节还原证据来自**本卡快照实测** `[本次实测]`，不依赖对该 helper 的静态信任。

## U11 · `[静态推断]` SPEC §1.3 与代码实现的覆盖关系

SPEC 文字描述受保护集合为"匹配 `gamemd.exe`/`ddraw.dll`/`RA2MD.INI` ∪ 装前 `*.MIX`/`*.CSF`"；`tool_c_writeaudit.py:protected_set()` 实际用 **`S_pre` 全部文件 − `D`**（超集，更严格）。这是**收紧**而非放宽，按 §3.4 保留，并在 `DISAGREE.md` 登记 `[本次读码]`。

## U12 · `[待运行验证]` 真机卡需要的样本量

B 判据要求每臂 ≥ `n_min=30` 个 `dframe` 点、每臂 2 条同臂独立轨迹（`n_noise_min=2`），即真机至少 4 趟采集（A1/A2/B1/B2）。W55b 单趟 `gate.n_samples≈11,400` `[转引]`，样本量上足够；但 W55b 的采集是**存档点门控**，本卡 B 要的是**连续帧轨迹**，采集节奏/对齐策略需在真机卡重新设计 `[待运行验证]`。
