## D-W55b-1 · 「frame 对齐后即可判存档等价」这一隐含前提不成立

- **上游隐含前提** `[转引]`：W54 `SAVE_DETERMINISM.md` §5.3 把「frame 对齐存档点」列为第一条硬前置，并写「补齐 1–3 之后，才能……给出『存档字节等价 / 不等价 / 不可判』」；W45 `EQUIVALENCE_RESULT.md:193` 把「修 frame 对齐」列为给 Lead 的最小下一证据第 1 条。措辞容易读成「对齐 + 白名单 + 同帧补样 ⇒ 可以判定」。
- **本卡实测** `[本次实测]`：三条都补齐后（0 拍对齐、4 份同帧样本、白名单事先声明、CFB 具名 stream 比较），**同帧同臂的 `CONTENTS` 整流仍相差 1,316,737 / 1,339,784 字节（≈96–97%）**，噪声带 `N` 巨大且 `N_A ≠ N_B`；跨臂 `D ≤ N`。
- **取舍**：判定仍写 **「仍不可判」**，并把原因从 W45 的「测量链没搭好」改成「测量链搭好了，但被测对象在此粒度下不可分辨」。**不迁就** upstream 隐含的「前置补齐即可判」预期；不把 0 拍对齐写成等价。
- **理由**：W45 §2.4 明文「`D` 只有满足 `D > N` 才可进入改造归因」；§3.4「等价」要求全字节相同 + `A1==A2`；§3.7 任一不可判 ⇒ 总判定不可判。三条同时不满足。

## D-W55b-2 · W54「白名单对元数据平面充分」不是无条件成立

- **W54 结论** `[转引]`：`SAVE_DETERMINISM.md` §0 / §5.1「白名单对『存档元数据平面』充分」，8 份样本全部落在同一等价类、掩码后 `A1==A2==B1==B2`、0 差异字节。
- **本卡实测** `[本次实测]`：
  - **复现成功**：本卡用 W54 的 4 份参考存档独立复现了 W54 的验证（`out\whitelist_crosscheck.json`：4 对全部 `equal_masked=true` / `diff_bytes_masked=0`），白名单 sha256 `dad972c4622d4f573…` 与 W54 原件一致。**W54 在其样本上没错。**
  - **但同一白名单施于 W55b 新存档时，平面视图残留 67–176 个未掩码差异字节**（`out\metadata_plane_residual_analysis.json`）。
- **取舍 / 归因**：
  1. 差异来自 `Scenario Description`（32/34/36/38 B）与 `\x05SummaryInformation`（380/384/388 B）两个流**长度可变**——引擎生成的存档名/描述。W45 的 8 份样本用**固定 typed name**，这两个流长度恒定（42 B / 392 B），W54 从未观察到它们变动，故未列入白名单。
  2. W54 的「平面元数据视图」= 把 14 个非 `CONTENTS` 流**拼接**成一条 3,576 B 视图；只要其中一个流长度变化，其后所有流整体位移 ⇒ 本相同的流被错开，产生伪差异。本卡按偏移定位：140 字节里 86 落在 `\x05SummaryInformation`、27 落在 `Scenario Description`、其余散落在 `Player House` / `Version` / `Play Time` 等**本应相同**的流——正是位移特征。
  3. **按具名 stream 比较（题面纠正的坐标系）则 13/15 流掩码后 0 差异**，3 个墙钟 FILETIME 流被白名单正确掩掉；残留只在上述两个变长流。
- **不迁就处**：**未事后把这两个流加进白名单**。W45 §1.4/§3.4 要求白名单**开跑前**声明，§0.1 禁止事后调整阈值/白名单；把新发现的差异悄悄掩掉等于用结果反推白名单，会造出假的「元数据平面等价」。本卡选择如实登记为**新的、待下一轮事先声明的非确定源**，并统一改用按具名 stream 比较作为判据坐标系。
- **给 Lead 的建议**：若下一轮仍要用「平面元数据视图」，须在开跑前把这两个流及其目录项 size 字段纳入白名单；或（推荐）沿用本卡的按具名 stream 比较。

## D-W55b-4 · 「同 frame 同臂补样」的实现口径：趟内补样失败，改用跨趟补样

- **题面**：「每臂至少 2 份同 frame 存档（共 ≥4 份）」；本卡 `ALIGNMENT_STRATEGY.md` §2.4 计划「每趟在冻结的同一菜单内尝试两次存档」。
- **事实** `[本次实测]`：4 趟各尝试 2 次，但引擎每趟都复用同一个生成文件名且写出**字节完全相同**的第二个文件（sha256 逐一相等，`out\save_dedup.json`）。⇒ 趟内两次**不构成 2 份独立存档**。
- **取舍**：按 sha256 **去重**，以**跨趟** A1/A2 与 B1/B2 满足「每臂 2 份同 frame 存档」（A=2、B=2、总 4）；去重后的 4 份用于 N/D 计算。**未**把重复副本计入样本（否则 `A1_s0` vs `A1_s1` 的差异 = 0 会造出假的 `N=0`，进而可能误判「等价」）。
- **不迁就处**：不写「趟内补样成功」，也不假装拥有 8 份独立样本。`out\` 里 8 个 `.SAV` 文件与去重记录同时保留，Lead 可复核。

## D-W55b-5 · 不把「平面元数据视图残留」写进判据，也不把「0 拍对齐」写成等价

- W54 `step6_whitelist.py` 的 `metadata_plane`（3,576 B 拼接视图）是**一种**比较视图，不是题目要求的坐标系。题面明确纠正：`.SAV` 是 OLE2/CFB，必须**按具名 stream 比较**，FAT/DIFAT 按构造排除。
- **取舍**：本卡判据使用 `cfb_compare.json` 的 `pairs[*].streams`（逐具名流）与 `pairs[*].contents`（`CONTENTS` 整流）；平面视图数值只作为**与 W54 的可比性交叉检查**和残留诊断列入 §4.3 表格，并标注「含变长流位移伪差异，判据不用它」。
- **理由**：用位移污染的平面视图当判据会同时误报（伪差异）与漏报（真差异被位移抵消）。同理，`frame_frozen` 全 2408 只证明**存档点对齐**，不证明**存档内容相等**；不把两者混为一谈。
