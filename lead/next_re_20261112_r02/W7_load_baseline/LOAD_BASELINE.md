## 0. 门控修正披露（先读这段，影响 mode 的解读）

**任务卡事实 5「正常局内 mode≠5」与本卡及 W6 自身数据不符**：

| 证据 | 内容 |
|:--|:--|
| W6 存档 `W6_transition\out\samples.ndjson` | `W_A_load` 493 拍 mode 全 5（frame 推进 315）；`W_A_ingame` 431 拍 mode 全 5（frame 推进 409）；`idle_after_exit` 491 拍 mode 全 5；仅 intro/主菜单为 mode 0 |

⇒ **mode[0xA8B238] 区分不了 加载/局内/退出后闲置（全是 5）**，只能区分 intro/主菜单(0) 与"会话已启动"(5)。

**连带修正**：W6 数据里"加载段 ~21–25 计数/s"的慢速段在本三趟**未复现**（loading 逐秒速率全程 ~32 帧/s，见 §2 注），
故本卡的 loading/ingame 边界（StartGame 后 20.03s）是 **min_load_s+持续窗的时间切分**，不是检测到的状态跃迁；
本卡读数集内**不存在**可靠的加载→局内边界判别器（mode/ABCD58/A8E9A0 都不是）。

## 3. 载体可用性判定

**载体可用（3/3）**。三趟独立启动均：按名称子串唯一命中并选中同一显示名 → UseMap → StartGame →
