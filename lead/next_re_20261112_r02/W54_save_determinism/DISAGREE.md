# W54 · DISAGREE（分歧、纠正、以及本卡不迁就的地方）

> 沿用 W45 `DISAGREE.md` 的写法：把「与上游表述不一致」「本卡中间产物的自我纠正」「刻意不迁就的结论」明写出来，避免被后续卡外推。

## D1 · 与 W45 §2.4「存档含时间/RNG/状态等非确定字段」的措辞分歧 —— 部分证实、部分未观察到

- `[转引]` W45 `EQUIVALENCE_SPEC.md:98`、`EQUIVALENCE_RESULT.md:121`、`UNKNOWNS.md:35-36` 把噪声猜测为「时间戳、路径、RNG 状态、玩家名/时间字符串、指针/句柄、未初始化填充」。
- `[本次实测]` 在**元数据平面**（14 个非-`CONTENTS` 流 + 目录项）里，实证不稳的只有 **一个墙钟 FILETIME 的 7 处副本** + 3 处派生量（`#FAT sectors`、DIFAT 扇区号、`CONTENTS` size）。具体：
  - **时间戳**：证实（3 个时间流 + 3 个 `SummaryInformation` VT_FILETIME 属性 + Root Entry `mtime`）。
  - **玩家名**：`Player Name` / `Player Name2` 两流均为空 (`00 00`) 且四臂全同 ⇒ 未观察到玩家名噪声。
  - **路径 / Executable Name**：`Executable Name` = `"SUN.EXE"` 四臂全同；未发现任何路径字符串 ⇒ 未观察到路径噪声。
  - **RNG 状态 / 指针句柄 / 未初始化填充**：元数据平面上未观察到；`CONTENTS` 高熵主体内**无法判定**（U1 未解）。
- **取舍**：本卡不把未观察到的项写进白名单（任务书硬要求「只覆盖实证不稳区间，不得凭猜测扩大」），也不写「已排除 RNG/指针」。正确写法是「元数据平面上只定位到时间戳；`CONTENTS` 内未定谳」。

## D2 · 与 W45 §2.4「文件名由引擎自动生成、各趟不同」的边界纠正

- `[转引]` W45 `EQUIVALENCE_RESULT.md:121` 把「文件名各趟不同」列为存档噪声来源。
- `[本次实测]` 盘上文件名确实各趟不同（`SAVE2147 / SAVE2EB9 / SAVE7DBC / SAVE27BB / …`），但**存档文件内部**的 `Scenario Description` 流（42 B UTF-16）在 A1/A2/B1/B2 **四份完全相同**（sha `aaf14a43…`）。
- **取舍**：文件名是**文件系统元数据**，不是「存档文件字节」，因此不进入白名单的 `regions`；但它在 W45 §3.4 的「槽位或名字不同 ⇒ 不可判」判据里仍算一条。本卡把它登记在 `not_covered_deliberately`，不悄悄抹掉。

## D3 · 与「按 raw 绝对偏移做全字节比对」这一隐含前提的分歧（最重要）

- `[转引]` W45 `EQUIVALENCE_SPEC.md:97` 写「全字节比对」、`§3.4` 写「字节级严格判据」；`DISAGREE.md:28` D4 把题面读作「逐字节相等 ⇒ 等价」。
- `[本次实测]` `.SAV` 是 **OLE2 / MS-CFB 复合文档**（signature `d0 cf 11 e0 a1 b1 1a e1`）。FAT 扇区交错放在约每 128 扇区处，文件一变长，DIFAT 与所有后续扇区位置都漂移。A1 vs A2 的 raw LCP 只有 **84 B**、97.31% 字节不同；而**按 stream 名比较**时 14 个非-`CONTENTS` 流里有 10 个逐字节相同。
- **取舍**：本卡明确写「raw file 绝对偏移不是可用坐标系」，并给出 §2.4 的 stream 级对齐策略。这不是降低判据严格度，而是**换到能定义「同一字段」的坐标系**；否则「逐字节相等」在容器格式上根本无法证伪。若 W45 重跑仍用 raw 全字节比对，白名单会显得「几乎全文件都要掩」，那是坐标系错误、不是噪声真有 97%。

## D4 · 不迁就：掩码后元数据平面全等，但**拒绝给出任何等价结论**

- `[本次实测]` 掩码后元数据平面 `A1==A2==B1==B2`、8 份样本全等、0 差异字节；跨臂掩码后差异（1,344,847 B）**不大于**同臂噪声（1,344,989 B）。
- 这两条很容易被读成「其实没问题 / 装包无影响」。**本卡拒绝这样写**：
  1. 全文件掩码后 `A1≠A2`（1,344,989 个未掩码差异字节）⇒ 白名单对 §3.4 的「全字节相同」不足；
  2. 四趟存档点 `frame` 未对齐（2404/2408/2441/2412，规格要求 ≤1 拍）`[转引]`；
  3. `CONTENTS` 平面的同臂噪声基线 **从未被测过**（没有同 frame 同臂对）`[本次实测]` U7；
  4. 任务书硬纪律：真正的等价判定要等 W45 框架重跑。
- 因此本卡只交付「白名单 + 掩码比较结果」，交付物里 `verdict_from_this_card` 明写 `INSUFFICIENT for full-file byte equality`。

## D5 · 本卡中间产物的自我纠正：`directory` 项的绝对偏移 3064 → 5112

- `[本次实测]` `EVIDENCE\step3_streamdiff.stdout.txt` 曾把「目录项 15 的 `stream_size` 字段」标成 `abs=3064`，那是按 `1024 + 逻辑偏移` **朴素假设目录扇区连续**算出来的，是错的。
- `[本次实测]` `EVIDENCE\step6b_layout_check.stdout.txt` 用 FAT 链实测：`dirChain=[1,5,6,8]`，逻辑目录字节 2040 落在第 4 个目录扇区 = **扇区 8** ⇒ `(8+1)*512 + 504 = 5112`。A1 在 abs 5112 的字节为 `c8 33 15 00 00 00 00 00`（= 1,389,512），A2 为 `44 d9 14 …`（= 1,366,340），与目录项 size 完全一致；abs 3064 处实测全 0。
- **纠正后**：`SAVE_NONDET_WHITELIST.json` 与 `diff_regions.tsv` 用 **5112**。`step3` 的 stdout 保留原样作为「错误中间步」的证据，不删不改；此处明写纠正，避免 downstream 引用旧值。
- 附带：`step3` 里 `abs=1132`（Root Entry mtime）是**对的**，因为第 1 个目录扇区确实在 abs 1024。

## D6 · 与 W45「四份存档副本保留在 out\save_*.SAV」的数量分歧（轻微）

- `[转引]` W45 `EQUIVALENCE_RESULT.md:123` 说「四份存档副本」。
- `[本次实测]` `W45_b_line_equivalence\out\` 下有 **8** 份 `.SAV`（4 主 + 4 附加/缺陷趟）。`analysis.json` 的 `per_comparable[3].copies` 只登记 4 份主产物。
- **取舍**：4 份主产物用于配对与判据；另 4 份仅作同臂附加样本加宽时间戳经验观测，并明标其 attribution 为 `[静态推断]`（U6）。不把 8 份混成「四臂各两趟」。

## D7 · 与「`CONTENTS` 是 LZO 压缩」这类预期的不迁就

- 任务书 §4 举了「如 LZO」作为可能性，容易让人顺势写「确认是 LZO 压缩存档」。
- `[本次实测]` 长度前缀块遍历、LZO/LCW 的 `(u16,u16)` 块遍历、常见校验和假设 **全部未通过**；4 KiB 熵窗均值 6.62（纯压缩流通常 ≈8.0），且存在 7–8 个 H<6.0 的低熵窗口。
- **取舍**：只写「高熵主体与压缩/稠密状态数组相容，**未能确认 LZO**」，标 `[静态推断]` + U1 `[待运行验证]`。不为了给出漂亮答案而编造块格式或偏移表。

## D8 · 与「白名单开跑前声明」的时间性说明（不是分歧，是边界）

- `[转引]` W45 `EQUIVALENCE_SPEC.md:99` / `DISAGREE.md:30` 要求白名单**开跑前**声明。
- 本卡的白名单是**从 W45 已经跑完的存档里经验导出**的 ⇒ 对 W45 那一轮而言它是**事后**的，不能 retroactively 用来把 W45 §2.4 从「不可判」改成「等价」。
- 它对**未来重跑**才是 `事先声明`（这正是本卡存在的理由）。`SAVE_NONDET_WHITELIST.json` 的 `purpose` 与 `verdict_from_this_card` 都明写了这一点。
