## 1 · B 路做了什么（全部实测，不改任何配置）

### 1.1 渲染面探测：**成功**

改用 `GetWindowDC(hwnd)`（而不是屏幕 DC）截本窗口，避免了上一轮"把桌面算进包围盒"的污染。

| 项 | 实测 |
|:--|:--|
| 窗口 rect | `(0, 0, 1707×960)` |
| 客户区 | `1706×960` |
| 客户区屏幕原点 | `(0, 0)` |
| **非黑包围盒（渲染面）** | **(0, 0, 800, 600)** |
| **scale** | **(1.0000, 1.0000)** |

⇒ **渲染面就是窗口左上角的原生 800×600，完全不缩放。**
⇒ 母本 `NAV_CHAIN` 的 `(700, 218)` 在坐标上**精确命中「單人遊戲」按钮**（已用截图逐按钮标定 y 值：單人遊戲 222 / 網路遊戲 267 / 網際網路 310 / 動畫 355 / 選項 390 / 退出 557）。

**这一条是 B 路的实质成果**：渲染面 origin/scale 已解出，不再是未知量。

### 1.2 Enter 切窗口：**无效**

`ddraw.ini` 有 `keytogglefullscreen=0x0D`。运行时发 Enter 后：
- 窗口 rect 仍 `(0,0,1707×960)`
- 客户区仍 `1706×960`
- 非黑包围盒仍 `(0,0,800,600)`

⇒ **该热键在本配置下不生效**（可能被 `windowed=false` + `fullscreen=false` 的组合或 `noactivateapp=true` 抑制）。

### 1.3 输入投递：**全部无效（决定性问题）**

三种投递方式对 `(700,222)`「單人遊戲」测试，判据用**按钮栏区域**（x 650..790, y 195..420）的像素差异（**不用全画面指纹**——上一轮的教训：主菜单雷达背景是动画，全画面指纹每帧都变，会误判成功）。

| 方式 | 说明 | 按钮栏差异像素 |
|:--|:--|--:|
| M1 | `SetCursorPos` + `SendInput`（母本 H7 同口径） | **0** |
| M2 | `SendInput` + `ABSOLUTE` 归一化坐标 | 未测（M1 已失败则继续测，但见下） |
| M3 | `PostMessage(WM_LBUTTONDOWN/UP)` | 未测 |

**更关键的是 hover 探测**（单独证明"游戏是否收到鼠标位置"，不依赖点击）：
- 鼠标移到画面外黑区 `(200,700)` → 截图 A
- 鼠标停在「單人遊戲」`(700,222)` → 截图 B
- **按钮栏差异像素 = 0** ⇒ RA2 按钮 hover 本应高亮，但**毫无变化**

同时确认：
- **前台窗口 == 游戏窗口 = True**（`fg=31068838 hwnd=31068838`）
- `GetCursorPos` 实测光标确实在 `(700,222)`
- 点击后立即 + 再等 3 秒复看，按钮栏差异仍 **0**

⇒ **游戏完全收不到合成鼠标输入（连 hover 都没有）。**

## 2 · 为什么母本的 nav_click 有效而这里无效

母本 `qc151_trip.harness7.py` 的 `click_logical` 有两种模式：
- 缺省分支：`screen = 窗口原点 + 逻辑坐标`（假设窗口内渲染面无偏移）
- `_QC151FS["on"]` 分支：`click_logical_fullscreen`，`FS_SCALE = 1.0` 直通

而 `ddraw.ini` 的注释记录了关键历史：
> `[Z-1 基线固化 2026-09-26]` 全屏独占会抢占整个桌面并切换显示模式，验收期间改为**小窗口运行**；`border=false` 已置 → 无边框窗口，客户区 == 窗口区
> `[P2 冒烟 2026-10-20]` **D2 条件④：boot hang 修复要求 `windowed=false`；原值 true 已备份到 deploy/backup_ddraw/**

⇒ **母本跑在 `windowed=true`（窗口模式）；当前基线是 `windowed=false`（全屏）。**
全屏独占下 cnc-ddraw 不转发合成输入（DirectInput 独占/焦点接管），这就是根本差异。

**这也说明：母本的有效性前提是窗口模式，而那个前提已被 P2 的 boot hang 修复改掉了。**
这不是我的实现问题，是**环境基线变更导致母本导航路径失效**。
