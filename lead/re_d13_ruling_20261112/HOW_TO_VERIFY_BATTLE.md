# 手动进对战 → 一条命令只读验证 `G_FRAME` 递增

> 用户选择：**「你手动点进对战，我只读验证」**。
> 本件是给用户的**操作说明**，配套脚本：`verify_battle_frame.py`。

---

## 为什么需要你手动点

已实测（`PATH_B_VERDICT.md`）：
- 渲染面已解出：**(0,0)，800×600，scale=1.0**（窗口左上角原生不缩放）
- 母本坐标 `(700,218)` **精确命中**「單人遊戲」按钮
- 但 **全屏模式下游戏完全不接收合成鼠标输入**（hover 都不高亮，按钮栏差异像素 = 0）
- 根因：`ddraw.ini` 从母本时代的 `windowed=true` 被 **[P2 冒烟 2026-10-20] boot hang 修复**改成 `windowed=false`

⇒ 不改配置的前提下，自动化点不进对战。**你手动点一次，之后全部自动。**

## 操作（两步）

### 第 1 步：启动游戏并手动进一局遭遇战

```powershell
cd D:\Project\ra2-campaign-forge\ra2youli
.\gamemd.exe
```

在游戏里点到：**單人遊戲 → 遭遇戰 → 选一张图 → 开始**。
**进到能看见自己基地/单位的局内画面**即可（不需要赢）。

> 提示：局内越忙（多单位）越好——那样更可能出现帧号停滞，也就更可能顺手抓到 E3 真正想要的东西。

### 第 2 步：切回 PowerShell，跑一条命令

```powershell
cd D:\Project\ra2-campaign-forge
python -I -X utf8 lead\re_d13_ruling_20261112\verify_battle_frame.py
```

**不需要你查 pid**，脚本会自动找 `gamemd.exe`。

---

## 这条命令会做什么

| 步 | 动作 | 是否碰游戏 |
|:--|:--|:--|
| 1 | 自动发现 `gamemd.exe`（pid / 位宽 / 路径） | 只读 |
| 2 | 探测四个关键地址可读性（`G_SINGLETON`/`G_TICK`/`G_FRAME`/`G_EXITSTATE`） | 只读 |
| 3 | 轮询 `G_FRAME` 25 秒（每 0.25s 一次），报是否递增 / Δ 分布 / 推算 fps | 只读 |
| 4 | 顺带用 C1 语义检测「帧号停推 ≥1.0s」——这就是 E3 的目标触发条件 | 只读 |

**它不会**：改游戏内存、写文件到游戏目录、终止你的游戏。

### 想看「冻结瞬间栈在哪」就加一个开关

```powershell
python -I -X utf8 lead\re_d13_ruling_20261112\verify_battle_frame.py --stack-on-stall
```

加上这个后，一旦检测到帧号停滞，会自动做**一次**真栈回溯（≤300ms 预算，**逐线程挂→走→立刻恢复**，不留残余挂起）。
这就是 E3 甲案的最终产出：**停滞发生时的真实调用栈**。

---

## 几种可能的结果怎么读

| 输出 | 含义 |
|:--|:--|
| `[PASS] G_FRAME 确实随帧推进` + 约 xx fps | **目标达成**：帧号源验证通过，E3 触发链对真游戏可用 |
| `[NOTE] G_FRAME 全程不变` | 可能还在加载/暂停；或该构建的 `G_FRAME` 语义与我预期不同 ⇒ 需换地址再查 |
| `[FAIL] G_FRAME 全程读不到` | 权限不足，或以管理员运行游戏而脚本不是 |
| `★ 检测到帧号停滞 1.0s` | **这就是 E3 要找的触发点**，加 `--stack-on-stall` 就会给出当时的栈 |

---

## 可选参数

```
--seconds N        轮询秒数（默认 25）
--interval S       采样间隔（默认 0.25）
--stall-n S        停滞阈值秒（默认 1.0，与台账 C1 一致）
--stack-on-stall   检测到停滞后自动做一次真栈回溯
--pid P            （一般不用）手动指定 pid
```
