## 4. 与 v4 草案的差异清单

1. **ret 操作数修正（唯一实质性改动）**：`0x724530` / `0x724540` / `0x724C00`
   三条 cave 的尾部由 v4 的 `c2 04 00`（ret 4）改为 `c3`（ret 0）。
   三者原映像首条 ret 均为 `c3`，实测于 `0x72453C` / `0x72454C` / `0x724C0A`。
2. **cave 长度变化**：`0x724530` 20B→18B，`0x724540` 20B→18B，`0x724C00` 19B→17B。
   其余五条长度与字节完全不变。
3. **门禁判据变化（v4 缺陷的根因）**：v4 的 STEP C 用
   `chk(..., -rsz - 4 + 4 + rsz == 0, ...)`，`rsz` 是函数自己的 ret 尺寸，
   表达式恒为 0，从不读 cave 里的 ret 操作数。v5 改为从 cave 字节反汇编出
   `cave_ret` 并与 `fn_ret` 做等值断言；栈平衡改用一般式
   `净变化 = -fn_ret - 4 + 4 + cave_ret = cave_ret - fn_ret`（必须 == 0），
   对 `ret 0` 函数该式退化为 `-4 ≠ 0`，恒真式在此直接失效。
4. **hook 字节从「公式描述」变成「实测字节」**：v4 的 STEP E 只打印
   `E9 rel32 + N×90` 而不打印实际字节；v5 输出并反汇编验证每条 hook。
5. **新增负控**：v4 无负控；v5 有 NC1a（ret 4→8）、NC1b（c3→ret4，即 v4 真实错误）、
   NC1c（ret4→c3，反向）、NC2（jmp 目标 +1）、NC3（replay 改 1 字节）、
   NC4（用独立重建函数整体注入 v4 三条错误 cave），六个负控必须全部变红，
   否则 `RESULT: FAIL` 且 `EXIT≠0`。
6. **新增结构断言**：`resume` 必须是指令起点、`[va,resume)` 必须有文件支撑、
   节表自洽（VA/文件对齐、不重叠、`va2off(节首)==rawptr`）、cave 槽位互不重叠、
   cave 可完整反汇编无尾字节、hook 跳板从字节反汇编验证指向本 cave、
   `resume != va+hook` 的函数必须恰为 0x724730 且 extra 为完整指令。
7. **门禁自证**：另跑两项元测试（未落盘）——(a) 把 `c7/c11` 强行置真模拟 v4 恒真式，
   门禁 `EXIT=1` 并报「门禁失效」；(b) 用 v4 风格重建 cave 注入主流程，
   三条 c3 函数的主表断言变红、`RESULT: FAIL`、`EXIT=1`。

**未改动的部分**：八条 hook 的覆盖范围、`je`/`jmp` 位移、重放段内容、cave 布局顺序。
