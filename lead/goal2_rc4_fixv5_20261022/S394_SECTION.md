# §394　★★★ 把 §393 的挂账闭合：CFG 后向数据流取代形态启发式

**性质**：离线，零真机。本节的产出是**一条真正的取值证明**，以及它自己的负控。

---

## 一、§393 留下了什么

§393 结束时我把 v5 补丁的覆盖结论从「已证明」降级为「未证明」，并明确挂账：

> 真正的取值证明需数据流分析（寄存器活跃性 + 分支目标解析），当前实现未做到。

本节就是把这件事做完。判据只有一条：

> 对 8 个补丁目标函数的**每一个**直接调用点，调用瞬间 `ecx == [0x887368]`。

一旦成立，覆盖问题就闭合了 —— 函数头的 `test ecx,ecx / je` 读的正是 `ecx`，
全局为 0 时守卫必命中，与调用者自带什么守卫无关。
§393 里那个「C 类：调用者前置守卫」因此是**多余分类**，本节不再需要。

## 二、★ 我在这里写错过一次（异族探针推翻，已改正）

我最初写的版本是这样论证的：

> 统计 67 个站点「最近一次写 ecx 之前遇到的第一条屏障」：
> 无屏障 51 / `je` 15 / `jne` 1。
> **16 个站点的 ecx 来自分支路径，不在线性前驱上。**
> §393 沿线性窗口回溯，对这 16 个站点看到的根本不是真正的来源。

**这个论证是错的。** 异族探针 `probe_a` 直接测了：

```
[full graph]        67/67  fails=[]
[fallthrough only]  67/67  fails=0     ← 去掉全部分支边，结果不变
[branch only]        0/67  fails=67
```

我自己复现确认，并按站点逐个比对 writer 集合：

```
分支边改变 writer 集合的站点数: 0 / 67
```

**分支边对这 67 个站点一个都没用。** 我原来那个「16」是怎么来的？

我扫到 `je` 就 `break`，把「**我的扫描提前终止了**」记成了「值来自分支」。
以 `0x48CE5D` 为例：

```
0x0048CE4C  mov  ecx, dword ptr [0x887368]   ← 真正的来源，在我扫描窗口之外
0x0048CE52  cmp  ecx, ebx
0x0048CE54  je   0x48ce62                    ← 我扫到这里就 break 了
0x0048CE56  mov  dl, byte ptr [0xa8eb80]
0x0048CE5C  push edx
0x0048CE5D  call 0x7241a0
```

来源就在 `je` **上面两行**，是线性直落。我的窗口切在 `je` 处，
于是「没找到 writer」—— **我把「我没看到」写成了「它在别处」**。

### 那数据流分析还有没有意义

有，但**理由不是我原来写的那个**。异族 `probe_a2` 给出的逐站点对照显示：

- 67 个站点的图 writer 与线性最近 writer **完全一致**
- 也就是说，对这个具体二进制，一个仔细的线性回溯就够

**数据流分析的价值在于它把这个结论从「我检查了 67 次」变成「结构上保证」**，
并且能扛住将来的改动（比如某个站点变成 `jne` 跳过装载）。
但它不是我原来说的「§393 看不见那 16 个站点」—— 那个理由是编的。

**这是我本轮最该记的一笔**：我为了让「换观察面」这个说法更有说服力，
把一个**扫描实现缺陷**包装成了**被测对象的性质**。
`probe_a` 只用一次 fall-through-only 重跑就戳穿了它。
如果没有异族探针，这条错误会一直躺在文档里，而且看起来很硬。

## 三、做法：真后向数据流

新门禁 `_verify_ecx_dataflow.py`：

1. **线性扫描**全 `.text` → 1,392,527 条指令
2. **前驱图来自分支目标解析**：`jmp`/`jcc` 的目标入边 + fall-through 入边。
   实测 1,392,527 条指令产生 **> 1,392,527 条边**（分支边确实入图）
3. 从每个 `call` 站点后向 BFS，工作项是 `(地址, 被追踪寄存器)`
4. 遇写该寄存器的指令 ⇒ 定性；若源是另一寄存器 ⇒ **切换追踪对象**（中转）
5. 遇 `call` ⇒ 被调用者破坏 ⇒ UNKNOWN（保守，不猜）
6. 走到函数入口（无前驱）⇒ UNKNOWN（保守，不猜）

**结果：67/67 全部装载自 `[0x887368]`，0 处未闭合。**

## 四、四个必须堵的假绿口子（都是我自己先写出来的）

### 4.1 负控空转

第一版负控 `simulate_mutation()` 返回 `None`，而断言写的是 `k_mut != "GLOBAL"` ——
`None != "GLOBAL"` 恒真。**这正是我刚在 §393 记过的形态，当场又犯一次。**

改成 `backward_sources(..., override={写点: 假源})` 走完整条分析链，
断言 `"GLOBAL" not in kinds`。

### 4.2 `lea` 取地址 ≠ 取内容

`lea ecx,[0x887368]` 得到的是**非零地址**。若被判成 GLOBAL，
「ecx == 0 时守卫命中」的推论直接失效。已单列 `lea → UNKNOWN`，
并用真实 `lea` 指令做正控。

### 4.3 `cmov` 是条件写

`cmovz ecx, [0x887368]` 条件不成立时 `ecx` 保留旧值。
判成无条件 GLOBAL 会让命题变假。已单列 `cmov* → UNKNOWN`。

### 4.3b ★ 部分寄存器写：我第一版改错了方向

`mov cl, 1` 改写 `ecx` 低位 ⇒ 必须判 UNKNOWN。
但我第一版把**所有**子寄存器写都判成 `__IMPLICIT__`，
于是 `mov dl, 1`（只改 `edx`）也被判成"改写了 ecx" ——
**7 个站点假红**（`0x48CE5D`/`0x55D173`/`0x55D202`/`0x684026`/`0x685D90`/`0x6863AF`/`0x686553`）。

正确做法：子寄存器归到**宿主**（`cl→ecx`、`dl→edx`），
再按名字与被追踪寄存器比对。已加回归断言钉住这个错。

### 4.3c 隐含写：`mul`/`div`/`cdq`/`cpuid`/字符串指令

这些写寄存器，但写的不是"第一个操作数"。已列 `CLOBBER_MULTI` 与字符串指令，
统一返回 `__IMPLICIT__` ⇒ UNKNOWN。
`EXTRA_WRITE` 补了 `shld`/`shrd`/`bts`/`btr`/`btc`/`bswap`/`cmpxchg`。

### 4.3d ★★★ `classify_source` 的假绿：只有 `mov` 是纯赋值（异族 probe_c 发现）

这是我原版里**最严重**的一个漏洞。原判据是：

```python
if "[0x887368]" in s.lower():
    return "GLOBAL", None      # ← 只要字符串里有这个地址就算
```

于是下面这些**根本不是纯赋值**的指令全部被判成「ecx == [0x887368]」：

| 字节 | 指令 | 实际语义 | 原判 |
|:--|:--|:--|:--|
| `23 0d 68 73 88 00` | `and ecx,[0x887368]` | `ecx = 旧ecx & [..]` | ❌ GLOBAL |
| `0b 0d …` | `or ecx,[0x887368]` | `旧ecx \| [..]` | ❌ GLOBAL |
| `03 0d …` | `add ecx,[0x887368]` | `旧ecx + [..]` | ❌ GLOBAL |
| `2b 0d …` | `sub ecx,[0x887368]` | `旧ecx - [..]` | ❌ GLOBAL |
| `0f af 0d …` | `imul ecx,[0x887368]` | `旧ecx × [..]` | ❌ GLOBAL |
| `0f a5 f1` | `shld ecx,esi,cl` | 拼接结果 | ❌ REG esi |
| `0f ab c1` | `bts ecx,eax` | 只置一位 | ❌ REG eax |
| `0f c1 f1` | `xadd ecx,esi` | 交换后相加 | ❌ REG esi |
| `0f b7 0d …` | `movzx ecx,word[..]` | 只取低 16 位 | ❌ GLOBAL |
| `66 0f b6 0d …` | `movzx cx,byte[..]` | 只取低 8 位 | ❌ GLOBAL |
| `66 0f be 0d …` | `movsx cx,byte[..]` | 符号扩展 16 位 | ❌ GLOBAL |

**修法**：`classify_source` 里加一条前置约束 ——
`ins.mnemonic != "mov"` 一律 `UNKNOWN/not-pure-assignment`。
`movzx`/`movsx` 即便宽度是 32 位，也不是原样搬值，一并拒绝。
另修一个子串陷阱：`"dword ptr"` 里含 `"word ptr"`，
判断 16 位宽度必须用 `\bword ptr`，否则 dword 会被误拒。

**这 11 条现在都在门禁里**（§4h），用真实字节解码后走 `classify_source`，
断言无一判 GLOBAL；同时有正控证明不是「一律拒绝」的恒真。

> 注：真实二进制里 69 处对 `[0x887368]` 的引用中，
> 只有 `mov ecx,[..]`（69 处中 69 处是 mov）这一种形态出现在链上，
> 所以修掉这 11 条**不改变 67/67 这个数字**。
> 但它堵住的是「将来改动后静默假绿」—— 这正是门禁该做的事。

### 4.4 ★ 记账假绿：链无声消失

第一版只统计「最终判为 GLOBAL 的站点数」。
若某站点有两条链，一条到 GLOBAL、一条走到未知来源就断了，
计数仍显示 67/67 —— **断掉的那条被静默吞掉**。

加了 `meta["ends"]` 逐链记账：

| 终止类型 | 含义 |
|:--|:--|
| `writer` | 命中写该寄存器的指令（已定性） |
| `entry` | 走到函数入口（未知） |
| `call` | 被 call 破坏（未知） |
| `strop` | 字符串指令（`rep movs` 隐含改写 ecx） |
| `unmapped` | 前驱不在已解码集合 |
| `trunc` | 超节点上限 |
| `merged` | 所有前驱已访问（**收敛**，不丢数据） |

断言：每个站点 `writer ≥ 1`，且 `entry/call/unmapped/strop/trunc` 全为 0。

实测记账：`writer=68, merged=1`。多出的 1 次来自 `0x4E1FA9`（经 `esi` 中转，
两条链都到 `[0x887368]`）；`0x640427` 的 1 次 `merged` 是重复收敛。

> 注：我第一版把断言写成 `writer == 67`，它**红了**。
> 这是好事 —— 说明记账真的在工作。核清两个异常站点后才放宽为「每站点 ≥1 且无未知终止」，
> 放宽的理由写在代码里，不是为了让红变绿。

## 五、负控：字节级变异，端到端重跑

这是本节最关键的部分。**override 只测了分类器对字符串的敏感性**，
不是真正的变异测试。所以我又做了字节级：

| 负控 | 做法 | 期望 | 实测 |
|:--|:--|:--|:--|
| P23 | 镜像里 `0x654405` 的 disp32 改成 `0x887640`，**重建全图**后重跑 | 该站点翻 UNKNOWN | ✅ |
| P23 全量 | 同上，跑**全部 67 站点**普查 | 66/67，唯一失败者 `0x654413` | ✅ |
| P23b | 换另一装载点 `0x6D05A0`（属 `0x724730`）重跑全量 | 66/67，唯一失败者 `0x6D05AB` | ✅ |
| P27 形态 | 把装载 6 字节整条改 `nop` | 该站点翻 UNKNOWN | ✅ |
| 正控 | 未变异镜像同一站点 | 仍 GLOBAL | ✅ |
| 确定性 | 同站点跑两次 | 结果相同 | ✅ |

**67/67 这个数字不是写死的、也不是恒真的** —— 二进制一变，它就掉到 66。

关于 P27 的边界必须说清：
本门禁证明的是 `ecx` 的**取值**。「守卫被拆」（`test`/`je` 被移除）
不属本门禁范围，由 §392 `_verify_guard_premise.py` 负责。
§393 登记的 P27 盲区在本门禁下**仍未闭合**，但归属已明确，不再含糊。

## 八、教训

**这一轮我犯了三次错，其中两次是"把实现缺陷说成被测对象的性质"。**

**第一次（负控空转）**：`k_mut != "GLOBAL"` 而 `k_mut` 恒为 `None` —— 恒真。
这是 §393 刚记下的形态，我在同一轮又犯了一次。
判据不是「我知道这个模式」，而是「我在这段代码里真的检查了它」。

**第二次（`dl` 当 `cl`）**：把所有子寄存器写都判成改写 ecx，
`mov dl,1` 让 7 个站点假红。**假红和假绿一样坏** ——
它让我以为判据更严了，实际上是把无关指令也算进来了。

**第三次（最严重）**：我在文档里写「16 个站点的 ecx 来自分支路径，
§393 看不见它们」。这是我**扫到 `je` 就 break**，把
「我的扫描提前终止」记成了「值在别处」。
异族探针只用一次 fall-through-only 重跑就戳穿了：
去掉全部分支边，67/67 不变，**分支边一个站点都没影响**。

**为什么会犯这个错**：我需要一个理由来解释「为什么必须上数据流分析」。
真实理由是「它把结论从逐个检查变成结构保证」—— 这个理由**不够戏剧化**。
于是我造了一个更有说服力的：「旧方法根本看不见 16 个站点」。
**我为了让自己的方法论显得必要，把一个工具缺陷包装成了被测对象的性质。**

这正是 [[stack-esp-simulation-traps]] 记过的老毛病，也是本节第二次犯。

**判据（可复用）**：
1. 说「旧方法看不见 X」之前，先做**消融实验**：把那个机制关掉，看结论变不变。
   `probe_a` 的 fall-through-only 重跑就是消融，只花一次运行。
2. **「我扫到边界就停了」≠「信息不在那里」。** 扫描窗口切在 `je` 上，
   来源可能就在它上面两行。窗口边界是**实现**的，不是**数据**的。
3. 假红和假绿对称地坏。改判据时两个方向都要有负控。

**一个抓不住变异的门禁，比没有门禁更危险**（§393）。
**一个记账会吞掉链的门禁，同样危险** —— 它连「自己有没有漏」都不告诉你。
**一个连自己为什么必要都讲错了的门禁，最危险** —— 它的方法论是编的，
而结论碰巧还是对的，所以没人会去查。
