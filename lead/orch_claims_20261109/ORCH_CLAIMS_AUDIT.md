## 5 防范机制

### 5.1 为什么这么多估算错（四个机制，不臆测心理）

1. **任务书是拼接生成的**：归档 `.mjs` 里 `ASK_ANALYST` 由 `IRON + 【编排方实跑指纹】 + 【实跑结果】 + 【背景——…】 + 【任务：…】` 数组 `.join("\n")` 拼出（本会话实读 `dwfrun-89df48db-…mjs`、`dwfrun-e526a76c-…mjs`）。**背景段是手打散文，指纹段/实跑段是机器生成的**；错全部落在散文段，指纹段 9/9 全对（§2.1）即反证。编排方自己在 `lowered:115` 承认「我在给任务书时经常用『估算』代替『计算』」。
2. **背景数字看起来无害**：`3 行`/`4 件`/`10 个域`/`2.05 倍` 像背景修饰，绕过了编排方给下游设的「不得采信、自己实跑」纪律——该纪律只约束子任务，**不反约束编排方的背景段**。
3. **数字无 hashlib 绑定、口径无机器可检标记**：指纹有双向绑定行，数字没有；`/` 两侧（似然/后验、台账/交付件、实跑/Shim）无任何标签。
4. **纠正不回写数字源**：#8 串了 n4 域、#11 串了域内中稿、#6 串了 Shim，都是「上一个相邻任务里记得的数」被复用；`lowered:122` 本任务书一边贴 `claim19=32768 / claim20=0.14013134`（【复核数据】，全对）一边仍写「心算成 16384」「ρ̄<0.8599」——**同一份文档里贴了≠用了**；`dwfrun-868215ce-…mjs` 贴了 32 域双轨实跑 `rjText` 后散文仍写 10/5（`GATE_REJUDGE_32.md:51-53` 判不符）。

### 5.2 「每个数字须来自实跑或标估算」的可执行做法（按复核破口⑤ 补齐两处缺口）

**结构化数字块 + 派发前门禁（8 条，可直接落进 `.mjs` 的 `GATE_CODE`）**：

1. `CLAIM_NUMBERS = [{id, value, unit, scope, source_kind, source_ref, sha256}]`，`source_kind ∈ {"实跑","文件行","估算"}`；散文段只允许 `{{N.id}}` 占位，禁止裸数字。
2. 派发前裸数字 lint（含中文数字与量词）：逐个要求能按 id 反查；**★ 必须配豁免白名单**（任务书编号、`path:line`、哈希、文件字节数、`output.tail`、§号、日期、指纹段、门禁常量），否则全量误报——本会话实测 `ASK_ANALYST` 段有 **132 个阿拉伯数字 token + 9 个中文数字量词**命中（`_ocw_verify_out.json:bp5`），复核员另报 99 + 11（口径略异，结论同：无豁免策略不可上线）。
3. `source_kind="实跑"` 须附本会话 worldRead stdout + 输出 SHA256；`"文件行"` 须 `path:line` 且当行含该数字；`"估算"` 须逐字渲染成「（估算，未实跑）」且**禁入【任务】/【交付】/【必现要素】**。任何数字缺 `scope` 直接 FAIL。
4. 比率/倍数/件数强制附 `{分子定义, 分母定义, 口径}` 三元组（可拦 #3/#4/#5/#13/#18）。
5. 每个数字带 `domain` + `artifact`，与本次 `DIR` 做一致性检查（可拦 #6/#8/#11）。
6. `CLAIM_NUMBERS` 整块 SHA256 按「被核对象 SHA256 = 」格式写进任务书末尾，下轮必须复贴该哈希形成链（杜绝纠正没回写）。
7. 派发前由编排方自己跑一遍只读复算并把 stdout 贴进【编排方实跑】段（指纹段已这么做，数字段照抄）。
8. **★ 新增：同一文档跨段数值一致性 diff（复核破口⑤ 指出草稿 §4(b) 缺此项，拦不住它自己的动机案例 #19/#20）**：把【编排方实跑/复核数据】段的数值与【背景/CLAIMS/结论模板】段同类数值逐项 diff，不等即 FAIL。可拦本任务书 `32768`↔`16384`、`0.14013134`↔`0.8599` 与 `dwfrun-868215ce` 的 `rjText`↔`10 个域`。
9. **★ 新增：估算显式降级**——允许估算，但标「（估算，未实跑）」并禁入验收段；下游见标记不得当验收基线。

### 5.3 现有做法是否已满足（按复核破口⑤ 更正草稿「约满足第 1、6 条」）
