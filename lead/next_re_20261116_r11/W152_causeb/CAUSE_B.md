## 0 · 五行判决摘要

1. **判决 = 静态不可判**（三选一里的第三项）：无法排除"某条释放路径不调槽 73"，因为本镜像**找不到析构函数**（槽 0 不是析构，§650-4 被独立复现），也找不到对象释放原语 ⇒ 无法枚举"释放建筑"的站点。`[已证·负面边界]`
2. 但**三类"绕过摘链"的具体形态已被排除**：① 不存在第二个摘链实现（真正写 `CellClass+0xE4/+0xE8` 的只有 `0x47E8A0`/`0x47EA90` 两个）；② 不存在"整表重建"（`[0x87F924]` 全镜像 **0 写 / 367 读**）；③ 正常销毁路径**确实**会调摘链（槽 73 mode 0 → `0x5687F0`）。`[已证]`
3. 找到一条**新的、指令级确证的"摘链被条件空转"机制**：两个包装函数前面有一道共享谓词 `0x5F5850`，它读对象自身字节 `+0x81`（硬否决）、`+0x74`（在世界中的锁存）。任一不满足，分派器**直接返回、绝不进包装** ⇒ 链一个节点都不动。这**不是**独立销毁路径，但它让"调过摘链"不等于"摘过链"。`[已证]`
4. 重叠放置的结构后果已用代码钉死：**两个对象都在链里**（先 A 后 B 时为 `A→B`，头仍是 A），既不是"后者覆盖前者"也不是"链断"；真正被破坏的是**建筑唯一的 `+0x30` 后继字段被它 6（或 16）个格的链共享** ⇒ 跨格串联。`[已证·静态]`＋与 §687 真机 30 条多节点链中 28 条含"不占该格"建筑节点一致。
5. ⇒ 台账 §837-2 的降级是正确的：**观测到的现象不需要成因 B 就能解释**。下一条最有区分力的证据不是继续扫静态，而是**定位对象释放原语**（`UNKNOWNS.md` U1 给了 4 个已定位的候选入口）或真机读 `+0x74`/`+0x81`。

### 1.2 三道前置闸门（**任一失败即静默返回，无错误码**）

; ---- 闸门 1：类型/状态字节 ----
mov edx,[edi] / call [edx+0x88]        ; Y = obj->[vptr+0x88]

- **闸门 1 不判空**：若 `obj->[vptr+0x88]` 返回 0，`[0+0x235]` 立即 AV。`[已证]`
  （与台账 L12101 的同一观察一致；这是**另一个**空指针缺陷面，不属本卡，记录备查。）

  ⇒ 契约是"**尽力而为、失败静默**"，调用方无法从返回值知道有没有摘成功。`[已证]`

### 2.1 为什么 A1 是唯一"真正移除"的实现（B5 的细节）

- `+0xE4`/`+0xE8` 的 4 字节写点共 **136** 处，分布在 **65 个函数**（`s11_classify.log`）。
  其中基址是 `esp`/`ebp` 的是栈上局部量（大栈帧函数里 `[esp+0xE4]` 遍地都是）⇒ 剔除。
- 剩下真正可能是 `CellClass` 的，只有 `0x47E8A0`（`0x47E90B`/`0x47E91F`）与
  `0x47EA90`（`0x47EAC4`/`0x47EACF`）。
- 我给的 6 个格指纹（读 `[0x87F924]`、`shl *,9`、调 Add/Remove/`0x47D2B0`、
  有 `cmp [reg+0xE4/8],X` 守卫）在所有 65 个函数里只有 3 个命中：
  - `0x48E740`：`shl` 命中但实为**逐字段清零**（`+4` 到 `+0x14C` 全写 0，`xor ebx,ebx` 后 `mov [esi+off],ebx`）⇒ 构造/清零，不是链维护；
  - `0x565C10`：`shl` 命中但实为**整块结构拷贝**（`mov eax,[esi+0xDC]; mov [edi+0xDC],eax` … 一路 `+0xDC→+0x100`）⇒ 不是链维护；
  - `0x686B20`：命中"调 `0x47D2B0`"，但它的 `+0xE4` 写点是栈上的（`[esp+0xe4]` 类），非格对象。
- ⇒ **没有任何第三方函数能改写某格的链头**。这一点很重要：它把"绕过摘链"的形态
  限制成"**根本没调用**"或"**调用了但空转**"，**不可能**是"另一个函数摘错了"。

## 3 · 谓词 `0x5F5850`：让"调过摘链"≠"摘过链"（本卡最硬的新发现）

复跑：`python s6_gate.py …`、`python s7_pred.py …` → `EVIDENCE/s6_gate.log`、`s7_pred.log`

`0x43F180`（建筑）与 `0x4D3780`（移动）**在 mode 分派之前**都先调同一道闸门：

```asm
0043F193  push ebp                    ; ebp = mode
0043F198  call 0x6F4A70               ; 闸门
0043F19D  test al,al / je 0x43F5E0    ; ★ 返回 0 ⇒ 整函数退出，链一个都不碰
```

`0x6F4A70`（51 B）= 调 `0x5F5850(ecx=obj, mode)`；若为真且 `[obj+0x418]!=0`，
再 `call [vptr+0x274](13)`，然后返回 1。**判定全在 `0x5F5850`**（212 B）：

```asm
005F5854  al = [esi+0x81]                     ; ★ 硬否决
005F585A  if (al != 0) return 0
005F5866  if (mode == 2) {                    ; 查询模式
005F586B      if ([esi+0x80] != 0) return 0
005F5879      if ([esi+0x74] == 0) return 0
005F5884      call [vptr+0x134]() ; return 1
          }
          ; ---- mode 0 / 1 / 3 ----
          ... (建筑且 [+0x520]->[+0xE58]!=0 且 mode==0 时跳过一段刷新)
005F58B4  edi = 0x40DD70(esi); if (edi) { call [edi+0x2c0](); call [edi+0x38](); call [esi+0x1b8](out) }
005F58E1  if (mode==1 || mode==3) {
005F58E7      if ([esi+0x74] != 0) goto 0x5F5908      ; 已在世界中 ⇒ 不挂
005F58F7      [esi+0x74] = 1 ; call [vptr+0x134]() ; return 1
          }
005F5908  if (mode != 0) return 0
005F590C  if ([esi+0x74] == 0) return 0                ; 已不在世界中 ⇒ 不摘
005F5913  [esi+0x74] = 0 ; return 1
```

**语义**：`+0x74` 是"该对象当前是否在世界（在地图上）"的**唯一锁存**；
`+0x80` / `+0x81` 是另外两个 ObjectClass 级标志（`+0x81` = 硬否决/忙）。

⇒ **摘链的前置条件是一个可变的对象字段，而不是"对象是否在链上"。**
只要有任何代码把 `+0x74` 置 0、或把 `+0x81` 置 1，**后续 mode 0 就返回 0，
分派器立刻退出，链一个节点都不摘**，而返回值只是"没做事"，不报错。`[已证]`

### 3.1 这些字段有谁写（`s8_latch.log`）

| 字段 | 写点数 | 函数数 | 其中值得注意的 |
|---|---|---|---|
| `+0x74`（锁存） | **43** | 24 | `0x5F5850` 自己（挂=1/摘=0）；`0x581140` 置 1；`0x5F3900` 三标志一起重置；`0x5FC570`（Overlay 槽 73）清 0 且置 `+0x81=1` |

## 4 · 重叠放置时的具体结构后果（问题 3）

### 4.1 `AddObject` 的完整分支（`EVIDENCE/s5_dump.log`，`0x47E8A0`，489 B）

```asm
head = sel ? [cell+0xE8] : [cell+0xE4]
if (obj == 0) return
if (obj->WhatAmI() == 6 /*建筑*/ && head != 0) {
    ; ---- A 路：追加到链尾 ----
    esi = head ; while (esi->next) esi = esi->next        ; 走到尾
    esi->next = obj ; obj->next = 0
} else {
    ; ---- B 路：头插（带去重）----
    if (head && head->next == obj) goto 通知        ; ★ 只在头插路有去重
    obj->next = head ; cell+[0xE4/E8] = obj
}
通知段：用 cell 的 row/col 组世界坐标 → call 0x47B3A0 → call 0x586360 / 0x5865E0(map)
        → if (mode!=0 或 …) call [obj+0x198]([0xA83D4C])
        → WhatAmI==0xF(步兵) 退出
        → call [obj+0xC0] 为假 退出
        → WhatAmI==6 ⇒ call [obj+0xF0](&世界坐标)   ; ★ 建筑"已占该格"通知
```

`RemoveObject` 的对称通知是 `[obj+0xF4]`（`0x47EB54`），且在"未找到/头为空"两出口**也会调**
（`0x47EAE8 jmp 0x47EAF7` 直接进入通知段，**跳过** `0x47EAF0` 的 `node->next=0`，
独立复现台账 §679-1 的四出口表）。

### 4.2 两栋 3×2 建筑共用一格时，链里到底发生什么

设 A 先放、B 后放，共用格 X（NAPOWR 重叠 §683-2：宽 3、步距 2 ⇒ 重叠一整列）：

| 步骤 | 代码路径 | 结果 |
|---|---|---|
| A 放置 | X 链为空 ⇒ **B 路（头插）** | `A->next = 0`；`X+0xE4 = A` |
| B 放置到 X | `WhatAmI(B)==6` 且 `head=A != 0` ⇒ **A 路（追加）** | 走到尾 `A->next==0` ⇒ `A->next = B`；`B->next = 0`；**`X+0xE4` 仍是 A** |

⇒ **答案：两个对象都在链里**（顺序 `A→B`，头是 A）。既不是"后者覆盖前者"，也不是"链断"。`[已证·静态]`

**但是**：`A->next` 是 **A 自己的唯一字段**，而 A 同时是它 3×2=6 个格的链头。
把它改成 B 之后，**从 A 的另外 5 个格遍历，也会走进 B** —— 而 B 根本不占那 5 个格。
这就是 §685-2 的结构缺陷，且与真机 §687（30 条多节点链中 **28 条**含"不占该格"的建筑节点）
逐条相符。`[已证]`

**A 被摧毁时会发生什么（这才是 UAF 的产生方式）**：

- 摘链循环按 **类型 footprint**（`[type+0xDFC]`，NAPOWR = 6 格）逐格算索引，对每格调 `RemoveObject(cell, A, A->[0x8C])`。
- 在 X 上：`head == B != A` ⇒ 沿链找 A ⇒ `B->next == 0` ⇒ **未找到** ⇒ 走 §679-1 的出口 (3)：
  **不摘链、且不清 `A->next`**。
- 在 A 的其它格上：`head == A` ⇒ 出口 (1)：`head = A->next`（**= B，或更早被别的格追加进去的第三个对象**），
  然后 `A->next = 0`。
- ⇒ 于是 A 的 6 个格**各拿到不同的后继**，而 A 本身仍可能被某一格指着（例如"先处理完的格把 head 交给 A 的 next，
  而某格头仍是 A 但循环没走到它"——台账 §669-2/§679-3 真机正是"16 格只动 2 格"）。
  **A 内存一旦释放，仍指着 A 的格就是悬垂指针。**

⇒ **结论：重叠的破坏力不在"摘链被绕过"，而在"链结构与格归属脱钩"（类别 C1）。**
成因 B 的假设（"某条销毁路径没调摘链"）在**代码层**上不会产生比这更糟的形态，
所以即使它存在，也不是 ②-b 现象的必需解释。

## 5 · 判决

### 5.1 三选一

> ## **静态不可判**

**理由（这是"不能判"，不是"没查到"）**：
问题等价于"**是否存在释放 `BuildingClass` 而不先以 mode 0 调槽 73 的站点**"。
要回答它必须枚举"对象释放"站点，而本镜像里**找不到释放原语、也找不到析构函数**：

1. **槽 0 不是析构**——我独立复现了 §650-3：`[0x7E3EBC] = 0x410260`，是拿 16 字节键
   与 `0x7F7C90`/`0x7F7C80`/`0x7F7C70`/`0x7E9AE0` 逐一 `repe cmpsd` 比对并写回的函数
   （`EVIDENCE/s2_ident.log`）。⇒ §650-4 的"从虚表槽 0 取析构"这条路**确实不可用**。
2. **没有 `operator delete` 导入**，`HeapFree` 全镜像只有 **3** 处绝对引用
   （`0x7C9428`、`0x7CFAAC`、`0x7CFEA9`，全在 `0x7C9xxx–0x7D0xxx` 的静态 CRT 区），
   引擎自己的对象释放走别的东西——而那个"东西"我没定位到（见 `UNKNOWNS.md` U1）。
3. 因此"**绕过**"这个词的判定对象（释放点集合）本身不可枚举 ⇒ 不能断言"不存在"。

### 5.2 但下列三条已被**证明排除**（这一半是硬结论）

| 排除项 | 证据 |

| "存在第二个摘链实现，摘错链/漏清 next" | 65 个链头写点里，只有 `0x47E8A0`/`0x47EA90` 具格上下文；另 2 个带指纹者是清零与整块拷贝（§2.1） `[已证]` |
