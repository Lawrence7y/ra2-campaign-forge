# W151 · UNKNOWNS（分级未证清单）

## U-1 ★最高优先：`0x0055B8F0` 是**零静态引用**的 432 B 函数——谁进入它？

- **已确立（`[已证]`）**：`0x0055B8F0` 是"每 tick 逐数组派发 `obj->vtbl[0x5C]`"的唯一实现，块 3 就是子弹数组（`Count=0xA8ED50`、`Items=0xA8ED44`、派发点 `0x55B960`）。函数体 `0x55B8F0…0x55BA9F`（`pop esi; ret` 收尾）。
- **已排除的四种到达方式（`[已证]`，全部为负）**：
  1. `call rel32`（`E8`）→ `work\branchscan.py 0x55b8f0` = **0 处**
  2. `jmp rel32`（`E9`）/ `jcc rel8|rel32` / `loop jcxz` → 同一扫，**0 处**
  3. 任何节里的**绝对 dword** `0x0055B8F0`（函数指针表 / vtable / 运行时写点）→ `.text/.rdata/.data/.rsrc/.detour` 全扫，**0 处**
  4. Ghidra 分帧：`getFunctionContaining(0x55b960)` = **null**、`getFunctionContaining(0x55b8f0)` = null ⇒ 它不在函数表里（因此也不在任何"callers"统计里）
- **仍有三种可能，本卡无法区分**：
  - (a) 它是本 build 的**死代码**（历史遗留副本），真正的 AI 派发另有其处；
  - (b) 它通过**运行期写入的指针**被调用（写点用 `reg` 计算而非立即数，静态不可见）——但任何静态初始化都该留下 `0x0055B8F0` 这个 dword，没留下；
  - (c) 它被从某段**未分析代码**以 `call [reg]` 形式调入（目标由寄存器决定）。
- **下一条最有区分力的证据**：在 `0x55B960` 与函数入口 `0x55B8F0` 各下一个计数桩，看是否命中。
  - 需要真机 → **本轮未授权**（R11_COMMON §1.1）。等授权后这是单点即可定案。
  - 若要纯静态：反查 `0x55BA9F` 之后紧邻的 `0x55BAA0`/`0x55B880` 都已被 `LogicClass` 虚表收录，而 `0x55B8F0` 没有 ⇒ 若它活着，它必然是"非虚、被同 TU 内直接调用"的形态，那就**必须**有 `E8` 引用——这与 (1) 冲突。**所以我倾向于 (a) 死代码**，但这只是倾向，不是证明。

## U-2 `CellSpread` 范围伤害的候选对象来源（格链 / 空间索引 / 别的）

- `[已证·负]` 不是"遍历全场对象数组"（`0xB0F720/724/730` 的 14 个引用函数全是 Add/Remove 模板；与槽 0x5C 派发集合交集为空）。
- `[未证]` 是格链（`CellClass` 的 `+0xE4`/`+0xE8` 链，见台账 §651）还是别的。我**没有**定位到读 `WarheadTypeClass::CellSpread` 的函数。
- 尝试过但没走通：从 `BulletClass::AI` 的 33 个 callee 逐个查（`0x468BB0`=引爆前提判定、`0x468D80`=阶段推进、`0x5B20F0`=2101 B 无循环、`0x53AB70`=224 B 无循环），没有一个是范围伤害；AI 内的外部虚拟调用只作用在**单个** `*(this+0x10C)` 上。
- **下一条最有区分力的证据**：先定位 `WarheadTypeClass` 的 `CellSpread` 字段偏移（可从未在 AI 闭包内的伤害函数反推），再找它的读者；或直接查 `0x004F54A0`（唯一含 130×130 定长网格循环的函数）的调用者是否在伤害路径上。

## U-3 0.65 ms/发的真实归属（绘制侧 vs 更新侧）

- `[已证]` 更新侧不可能：AI 是 O(1)，无 O(b·n)，指令量级 ~1.8k 条 ⇒ 单发约 10⁴–10⁵ 周期，与 6.5×10⁵ 周期差 1–2 个数量级。
- `[未证]` 绘制侧：`BulletClass::Draw = 0x468090`（923 B、**0 个循环**、19 个 callee）。我没有验证"每帧对每颗子弹调一次 Draw"，也没有量化 blit 成本。
  - 阻碍：真正的绘制入口是 `cnc-ddraw.dll` 的软渲染 blit；`gamemd.exe` 侧只是发 blit 请求。要把 0.65 ms 归到 ddraw 需要跟 ddraw 侧代码，属于另一张卡的范围。
- **下一条最有区分力的证据**：P1 的两种干预（NOP 掉 AI 派发 vs 保持 b 不变但让弹道不可见）二选一，一次实验即可分开。**都涉及改代码/改数据，本轮未授权。**

## U-4 `0xB0F5B8` 这条 `AbstractClass*` 数组的身份

- `[已证]` `BulletClass::AI` 在 `+0x158` 分支里从 `0xB0F5B8/BC/C8` 这个 `DynamicVectorClass<AbstractClass*>` 里摘除自己（搬移，O(Count)）。
- `[已证]` 台账 L21675：`0xB0F5B8 / D8 / F0 / 618 / 640 / 658 / 670 / 698 / 6C8 / 6F0 / 708 / 720` 共 **12 个** `AbstractClass*` 数组。
- `[未证]` **哪一条**是"全部对象"，哪一条是别的用途。注意一个矛盾：BulletClass **构造器**调 `0x5F3900`，其内联 Add（`0x5F3A42`）写的是 **`0xB0F720`**；而 **AI/析构**摘的是 **`0xB0F5B8`**。二者不同 ⇒ 要么子弹同时登记在两个数组里，要么其中一处是别的对象。**我没有闭合这一点**，但它不影响"O(b) 无交互项"的结论。
