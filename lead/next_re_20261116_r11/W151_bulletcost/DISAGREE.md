## D-1 `[已证·推翻]` 子弹容器基址不是 `0x00A8ED3C`

- **我预期**（依 `R11_COMMON.md` §3.3 表格）：容器基址 `0x00A8ED3C`，Items `0x00A8ED40`，Count `0x00A8ED50`。
- **实测 Y**：容器对象基址 = **`0x00A8ED40`**；Items = **`0x00A8ED44`**；Capacity = `0xA8ED48`；Count = `0xA8ED50`（**这条原本就对**）；CapacityIncrement = `0xA8ED54`。
- **因此**：`R11_COMMON` §3.3 的"容器基址 0x00A8ED3C，Items 0x00A8ED40"整行偏移了 4 字节，错。台账 §20713 那一行的 "Items `0x00A8ED40`" 同样错（应是 `0xA8ED44`；`0x00A8ED40` 是 **vptr 槽**）。
- **三路独立证据**：
  1. 构造器 `0x466380`：`0x4664b1 mov ecx,[0xa8ed44]` → `0x4664b7 mov [ecx+eax*4],esi`（把 Bullet\* 存进 `[0xA8ED44]` 指向的数组）；`0x466496 mov ecx,0xa8ed40` + `call [eax+8]`（把 `0xA8ED40` 当容器 `this`）。
  2. `0x006802F0`：容器指针进 `edi` 后，**`[edi+0x10]` = Count、`[edi+4]` = Items** —— 只有 base=`0xA8ED40` 能同时成立。
  3. `W132_arrays\instance_arrays.tsv` 行：`DynamicVectorClass<BulletClass*> base=0x00A8ED40 items=0x00A8ED44 count=0x00A8ED50`。
  4. （旁证）Lead 已入账的 §887 真机实测结论**与本卡一致**。
- **`0xA8ED3C` 是什么**：不属于该容器。全 `.text` 只有 **1** 处引用它（`0x544957`，在 `0x5447C0` 内），与子弹数组无关。与 Lead §887 的"前一变量的尾字"判断相容。

## D-2 `[已证·推翻]` `0x67D300` 不是"每帧对象协调"，是存档/序列化 + COM 流

- **我预期**（依 `R11_COMMON` §3.4 / 台账 §873）：`0x67D300` 遍历 House/Unit/Infantry/Building/Aircraft/Anim/Trigger 7 种数组，是每帧对象/子系统协调的主候选。
- **实测 Y**：
  - 它的数组遍历（如 `0x67E00C` 起的 10 连块）对每个元素做的是：**16 字节 key 匹配**（`0x410260`，常量 `.rdata 0x7F7C70/80/90`、`0x7E9AE0`；返回 `0x80004003`=`E_POINTER`、`0x80004002`=`E_NOINTERFACE`）→ 调 `[0x7E15F4]`(=`0x410868`) → 调对象**槽 2**。
  - 它的**兄弟阶梯**在父函数 `0x67CEF0` 的 `0x67CC5F` 块，遍历子弹等数组后调对象**槽 13 = `0x5F6250`**，那是一个**逐字段序列化器**（把 `+0x30/+0x34/+0x6c/+0x74/+0x80/+0x83/+0x8c/+0x8d/+0x8f/+0x90/+0x9c/+0xa0/+0xa4` 逐个 push 给 `0x4A1D50`/`0x4A1CA0`）。
  - 调用点上下文还夹着格式化串（`0x82A05C` + `0x7CA564`）。
- **因此**："`0x67D300` = 每帧对象协调"错；它是**存档/序列化（含 COM 枚举）**链。`0x67CEF0` 虽然确实被 `0x55D360` 在 `0x55DC92` 调用，但那是 `0x55D360` 内部的**存档支路**，不是 tick 更新支路。
- **附带推翻**：`R11_COMMON` §3.4 说 `0x67D300` "遍历 7 种数组"——本卡实测它至少覆盖 **10+** 条数组（含 `BulletTypeClass` 与 `BulletClass`），"7"这个计数本身也不对（因为它只看了 `mov edx,<立即数>` 的一部分，且漏了未分帧区）。

## D-3 `[已证·推翻]` "`0x4666E0` 有 0 个调用者 ⇒ 无直接调用者"这条观察不足以定性，且它是**分帧缺失**造成的假象

- **我预期**：`BulletClass::AI`（`0x4666E0`）作为虚函数，`ghidra` 会给 0 个静态调用者，属正常（虚调用不可见）。
- **实测 Y**：0 个调用者的**真正原因**是 **`0x0055B8F0…0x55BA9F` 这一段根本不在 Ghidra 函数表里**（`getFunctionContaining(0x55b960)` 返回 null，`DECOMP ?5617904 size=-1`）。也就是说：连"这段代码存在"都没被记录。
- **因此**：本项目里"0 callers"这一读数的解释要改：它既可能是虚调用，也可能是**分帧缺失**。`R11_COMMON` §2.7「不要用无调用者推断死代码」是对的，但需要补一条：**要先用 `branchscan.py` 确认目标确实被扫过**。

## D-4 `[已证]` "`function_atlas.tsv` 覆盖 12,916 函数"不足以支撑"函数级穷举"

- **我预期**：以 `function_atlas.tsv` 为域的 xref/callgraph 扫描（`W131\calledges.raw.log` 62,333 条边）足以回答"谁引用某全局 / 谁派发某虚槽"。
- **实测 Y**：按 atlas 域扫 `call [reg+0x5C]` 得 **129 处 / 91 函数**；按**原始字节**扫同一编码得 **162 处** —— 漏了 **33 处**，且**唯一**的子弹 AI 派发点（`0x55B960`）就在漏掉的那批里。同理，按 atlas 域扫"谁引用 `0xA8ED50`"得 6 个函数，实际有 **15 处 / 8 个函数**。
- **因此**：凡"谁引用 X / 谁派发槽 Y"这类**穷举性**结论，必须用 `work\globalscan.py`（原始字节搜地址 dword）和 `work\patscan.py`（原始字节搜 `FF /2` 编码）复核；atlas 只能当**加速器**，不能当**全集**。

## D-5 `[已证·对 §650-3 的补充，不是推翻]` 槽 0 的 16 字节 key 匹配器**全类共享**

- §650-3 记录 BuildingClass 主虚表槽 0 = `0x00410260` 且"不是析构"。
- 本卡实测：**`BulletClass` 主虚表槽 0 也是 `0x00410260`**（同一函数）。⇒ 它是**跨类共享**的，因此**不可能**是"每类自己的 QueryInterface"（那必须逐类不同）。它更像是引擎里一层**统一的 16 字节键分派**（4 个键：`0x7F7C90` / `0x7F7C80` / `0x7F7C70` / `0x7E9AE0`）。
- **因此**：§650-3 里"可能类 ID/GUID 查询"的猜测可以收窄——它不是 per-class 的，所以不是"对象身份查询"；但对"它到底是什么"，本卡仍 `[未证]`。

## D-6 `[已证·与台账 §733 的推测不符]` 上翘不来自"命中判定/溅射邻域搜索"

- **台账 §733 推测**：0.65 ms/发的成本主体是"位置推进 + 碰撞检测 + 命中判定"，且"若其中含每颗子弹 × 所有对象/所有格的搜索，则是 O(子弹数 × 候选数)"。
- **实测 Y**：`BulletClass::AI` 6422 B 里**只有 1 个真循环**，是"从 `AbstractClass*` 向量里摘自己"（`+0x158` 门控，只在销毁那一次）；33 个 callee **全部无循环**；AI 深度 4 闭包（303 函数）**没有**任何全场对象数组遍历；全二进制**不存在**"遍历全场对象并派发"的循环。
- **因此**：**不存在 O(b·n) 项**；§733 的"O(子弹数 × 候选数)"假设不成立。0.65 ms/发的量级（≈6.5×10⁵ 周期 @1 GHz）比这段代码高 1–2 个数量级 ⇒ b 相关性不可能来自更新循环。头号余候选：**逐发绘制/blit**（本卡 `[未证]`，见 `UNKNOWNS.md` U-3）。

## D-7 `[已证·数字更正]` `0x67D300` 的"111 个回边"应读作"111 个回边指令 / **28** 个循环头"

- `R11_COMMON` §3.4 与台账 §873 用"111 个回边"暗示 111 个循环。本卡用 capstone 重算：`nback=111`，`nloops`（**不同回边目标数**）= **28**。多个分支回边共享同一循环头。
- 不影响任何结论，但"111 个循环里有多少实际执行"这种表述应改为"28 个循环头"。
- 复跑：`python work\q.py fn 0x67d300`。
