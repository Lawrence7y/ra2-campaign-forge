## 2 判据族定义（规则 / 需要的历史信息 / 相对 S 的等待时间）

### 2.1 共同锚与「相对 S」的诚实口径

- 语料只有 `(t, f)`；观测锚 `S_hat = t[runStart]`，物理起点 `S ∈ (t[runStart−1], t[runStart]]`，
  `S_hat − S ∈ [0, e]`，`e` 实测有效 n=28317、min 0.008 / 中位 2.511 / P99 4.145 / max 488.616 ms
  （`_dtrigger_probe_out.txt:245-250`、`_dtrigger_analysis_out.txt:69-74`）。
- 因此**本报告所有 `waitAfterS_hat` / `latency*` 都是下界**：真实相对物理 S 的等待 = 报告值 + `(S_hat−S) ≥ 报告值`；
  :177 的严格 S+50ms 核算需物理 S，本次语料不可得（`_dtrigger_probe_out.txt:250`）。
  `e` 的最大值 488.616ms 是采样掉拍，不证明线程被卡（`RULING_D30.md:78`）。
- 历史基线 = 帧沿到帧沿的帧周期 `t[edge]−t[prevEdge]`（全语料已完成帧间隔 n=28317，P50=32.779ms，
  与 :194 记载 32.0ms 同量级）；滑窗只取 `runStart−1` 及更早的**已完成**帧间隔，**不含当前停滞本身**
  （`_dtrigger_analysis_out.txt:5-7`、`_dtrigger_probe_out.txt:90`）。冷启动历史不足 N 条不触发。
- 名义「500Hz / 每 2ms 一拍」在语料里不成立：相邻采样间隔 n=747437，P50=2.4940ms，
  间隔 <0.05ms 的采样 127861/747437 = 17.107%，`>10ms` 的 1667 条
  （`_independent_recheck_findings_out.txt:9-11`）。故 k 拍计数与墙钟时长不是一一对应。

### 3.1 每个指标的确切定义与它**不是**什么

- `trig`（`triggers`）：该判据在 28381 条帧号游程上的**触发总数**，每游程每判据最多 1 次
  （`_dtrigger_metrics_out.txt:7`）。**不是**真实事件数，也不是配额槽数。
- `false`（`falseTriggers`）：触发但游程最终 `d_final<100ms` 的次数（**事后计费，不参与触发**）
  （`_dtrigger_metrics_out.txt:49`）。**不是**「触发了但 `isRealMatch==False`」的个数：
  `d≥100ms` 游程 n=1704 中有 23 条 `isRealMatch=False`（终局冻结/加载空白/帧回退），按口径 B 被计为「真」
  （`_independent_recheck_findings_out.txt:46-48`）。这是计费口径缺口，见 §5。
- `fRate%`（`falseTriggerRate`）：`false / trig`，保留 6 位小数。
  **不是** `FP/(FP+TN)`，**不是**真实事件标签查准率，**不是** `1 − 查准率` 意义上的工程误报率
  （`RULING_D30.md:12` 亦明确「误报率仅指误触发数/总触发数」）。
- `hits`（`realHits`）：触发落在 `isRealMatch==True` 的 1681 条真实事件上的**事件数**（不看配额的召回上界）
  （`_dtrigger_metrics_out.txt:53`）。**不是**配额下的实际捕获数（`W*/T*`），**不是**查准率，
  **不是**「线程上下文已在 S+50ms 内被保存」。
- `miss`（`missedReal`）：`1681 − hits`（`_dtrigger_metrics_out.txt:8`）。**不是**被误触发抢占的事件数。
- `latP50 / latP95 / latMax`（`latencyP50Ms` / `latencyP95Ms` / `latencyMaxMs`）：**仅真实命中子集**的
  `t[触发点]−t[startTick]`（S_hat 锚）分布；P50=`statistics.median`，P95=线性最近秩 `int(0.95*(n−1))`，
  max=最大值（`_dtrigger_metrics_out.txt:56-59`）。
  **不是**全部触发的 `waitAfterS_hat` 中位：两个统计母体不同——例如 `C2-P95x2` 全 27 次触发的 wait 中位
  73.378ms（`_dtrigger_probe_out.txt:94`），而仅 7 个真实命中的 `latP50=196.034ms`，差 122.656ms
  （`_independent_recheck_out.txt:56-69`）。把二者当同一个「等待中位」会直接误判 :177 余量（同文件 :68-69）。
  **不是**相对物理 S 的等待（是下界，见 §2.1）。小样本下最近秩 P95 可能小于 P50（如 `C2-P99x3`：
  P50=108.391 > P95=104.018），这是实测分布不是错误（`_dtrigger_metrics_out.txt:57-58`）。
- `≤50%`（`within50msRate`）：分母**固定为 1681 条真实事件全集**，「触发且等待 ≤50ms」的真实事件占比；
  漏掉的真实事件按不在 S+50ms 窗口内计 0（`_dtrigger_metrics_out.txt:54-55`）。
  **不是** `within50msRateOverHits`（后者分母为 `realHits`，只在 JSON 中作对照），**不是**对 :177 的合规证明
  （S 不可测、:190 端到端延迟未验），**不是**保存动作生效的占比。
- `>50`：`waitAfterS_hat` 超过 50ms 的**触发数**（观测锚口径，`_dtrigger_supplement_out.txt:33`）。
  **不是**真实事件数，**不是**相对物理 S 的越线数（真实值 ≥ 该列），**不是** :177 的合规判定。
- `≥100`：触发等待已达/越过口径 B 100ms 事后分类门槛的**触发数**；该列 >0 即不再是「提前」候选
  （`_dtrigger_supplement_out.txt:35`）。**不是**误报数，**不是**真实事件数。
- `+e>50`：加上 onset 观测滞后中位 `e=2.511ms` 后超 50ms 的**触发数**（`_dtrigger_supplement_out.txt:4,34`）。
  **不是**逐游程代入各自 `e` 的实测越线数（只加了中位常数），**不是**物理 S 下的严格核算。
- `W1/W3/W5`（每窗配额 N=1/3/5）、`T1/T3/T5`（每会话 trip 配额 N=1/3/5）：按触发时刻升序
  **先到先得**消耗配额后，真实事件被「捕获」的条数 / 1681；**误触发同样消耗配额**
  （`COST_QUOTA.md:13-14`）。**不是** `hits`，**不是**在线保证，**不是**「只由真实事件消耗配额」的理想值，
  **不是**真实线程上下文在 S+50ms 内被保存（`COST_QUOTA.md:649`）。
- `noFalse`：只保留该判据在真实事件上的触发、删掉全部误触发，再跑同一配额后的捕获数
  （`COST_QUOTA.md:191-192`）。**不是**实测性能，是反事实量；可低于理想值（判据自身漏检或触发太晚）。
- `capUpper`：假设 1681 条真实事件**全部在 `t[startTick]` 触发**（最乐观），保留该判据的非真实触发流，
  再跑同一配额（`COST_QUOTA.md:15,154`）。**不是**设计、**不是**工程可达性声明；任何实际判据的触发都晚于
  `t[startTick]`，故它是上界（`COST_QUOTA.md:652`）。
- 表中「理想」行 26/73/117 是**引用** `RULING_D30.md:40-44` 的公布值作对照，不是本件自跑结果；
  本次自跑逐档复现值见 `_cost_quota_stdout.txt:51-56` 与 §4.1。
