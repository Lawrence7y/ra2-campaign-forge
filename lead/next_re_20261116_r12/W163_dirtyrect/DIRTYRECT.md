## Q1 · 脏矩形机制的结构

### 容器身份与布局 `[已证]`

`0xB0CE88` 是 `DynamicVectorClass` 的 Count 字段；base = `0xB0CE78`。构造器 `0x6D1810`（25 B）写 vptr `0x7F429C`/`0x7F42BC`（两张 7 槽虚表，后随 COL `0x80B860`/`0x80B8C8`）、Items、Cap、flags、Count、Inc=`0xA`。

| 偏移 | VA | 证据 |
|---|---|---|
| +0 vptr | 0xB0CE78 | `0x6D1A7D/0x6D1AAE mov [0xB0CE78],0x7F429C/0x7F42BC`；`0x6D2A79 mov edx,[0xB0CE78]` + `0x6D2A89 call [edx+8]`（虚扩容） |
| +4 Items | 0xB0CE7C | 25 处引用（字节=Ghidra），`0x6D2AB8 rep movsd` 写入目标 |
| +8 Capacity | 0xB0CE80 | `0x6D2A44 mov eax,[...]` 与 Count 比较；`0x6D1A6C/0x6D1AED` 构造写 |
| +C/+D flags | 0xB0CE84/85 | `0x6D1A71/0x6D1A78` 写；`0x6D2A59 mov cl,[0xB0CE85]` |
| **+10 Count** | **0xB0CE88** | 27 处引用；已知读点 `0x6D3DF0` 在内 |
| +14 Increment | 0xB0CE8C | `0x6D1A87 mov [0xB0CE8C],0xA`；`0x6D2A6B` 读 |

元素 = **0x14 B = 5 dword**（x1,y1,w,h,1 字节 flag）：`0x6D2AB3 mov ecx,5; rep movsd`，Ghidra 反编译 `local_14[0..3]+local_4` 一致。

### 谁 Add（加入脏矩形）`[已证]`

- **Add 函数 `0x6D2790`**（`FUN_006d2790(x1,y1,w,h,char flag)`，`ret 0x14`=5 参数）。调用者：Ghidra 46 / 字节 47（B 多 `0x6B2A70`，孤儿区，符合 §6.2）。
- 直接来自子弹 AI 的调用者（在深度≤8 闭包内）：23(A)/24(B) 个，最浅 `0x4666E0→0x421EA0(构造器)→0x5F4EC0→0x6D2790` 深度 3。
- 来自子弹**构造器**：`0x466560`（写 vt `0x7E46E4`，即 BulletClass 主表，R12_FACTS §10.5）→ `0x5F4D30` → Add；此函数同时 `inc [0xA8ED50]`（Bullet Count）。
- Add 门控：G_INGAME `[0xA8E9A0]`、位置变化（`[0xAC1380/84/88]` 缓存比较）、`[obj+0x81/+0x74]` 标志、`[0xA8E7AC]==0`。

### 每帧在哪消费/清空 `[已证]`

- 主函数 **`0x6D3D10`**（3643 B / 1004 指令 / 58 call / 10 回边）：含已知读点 `0x6D3DF0`；在 `0x6D4471–0x6D44F7` 顺序调用 8 个遍历函数 `0x6D2B60,0x6D3660,0x6D2DE0,0x6D3470,0x6D3290,0x6D3AC0,0x6D3040,0x6D3870`，再于 `0x6D465F` 调绘制派发 `0x6D8DB0`；`0x6D451C` 写 Count。
- 唯一调用者 `0x4F4480`（双通道一致）；`0x4F4480` 的调用者含 **`0x55D360`（每帧更新）**，双通道一致 ⇒ 每帧执行链闭合：`0x6BB9A0→0x48CCC0→0x55D360→0x4F4480→0x6D3D10→8 遍历+0x6D8DB0`。
- 其它 Count 写者（flush/merge 类）：`0x6D2790`(Add,减/增)、`0x6D2B60`、`0x6DA980`、`0x6D3D10`。

### 合并算法复杂度 `[已证]`

Ghidra 反编译（`EVIDENCE/W163Gather.log:245-402`）逐句证实：

```
local_50=-1; local_4c=0x7fffffff;
if (0 < Count) do {                       // 外层：扫描全部 k 个已存在矩形
   piVar6 = local_58 + Items;             // 取第 i 个矩形(0x14B)
   FUN_00421b60(&new,0,0);                // 交集计算
   if 交集==新矩形 且 flag 条件 → return;  // 去重
   else if 交集==已有矩形 → {
       Count -= 1;
       do { 搬移 5*dword } while (++i < Count);   // 内层 O(k) 左移覆盖
   } else { 计算交面积, 记最小者 }
} while (++i < Count);
if (找到最优) { FUN_00487f40 合并; 写回; return; }
// 否则 append：若 Capacity<=Count 则 `call [vptr+8]` 扩容，然后 Count++、rep movsd
```

⇒ **单次 Add = O(k)**（k=当前矩形数，1 次全扫描 + 命中时 1 次 O(k) 搬移；极端"新矩形覆盖全部已有"时单次可达 O(k²)）。一帧内加 k 个矩形 ⇒ **O(k²)**。不是 O(k log k)（无排序/树/二分结构）。

**对 ① 的意义**：台账 §900-5 实测 `B0CE88` 中位 0、仅 4.2% 非零、max 2393，且 `hi−lo` 仅 +0.30 个矩形/窗；队列每帧清空故采样看不到帧内 k。⇒ **复杂度是静态结构事实，但"它是否吃了 40–60 ms"无法用现有采样判定**（与 §900-5 一致）。

## Q2 · 子弹会不会产生脏矩形？

**答：会，但走"新建/命中/效果/触发器"事件路径，不是"每帧每发固定加"。** 双通道 BFS（Ghidra 1062 / 字节 1570 个函数，深度≤8）对 11 个脏矩形簇目标命中**完全相同**的 11 个（Add、8 遍历、flush、绘制派发）；`0x6DA980` 两通道均 UNREACHABLE。

### 逐跳路径 + 证据等级

**路径 A（最浅，深度 3，双通道逐跳一致）— 子弹 AI → 新对象构造 → 脏矩形 Add：**
| 跳 | 地址 | 站点 | 等级 |
|---|---|---|---|
| 0x4666E0 → 0x421EA0 | 构造器 | `0x4668B8`、`0x467F2D`（均在 Bullet AI 内，边界已验） | `[已证]` |
| 0x421EA0 → 0x5F4EC0 | 位置刷新/登记 | `0x4222E0`/`0x422433`/`0x4224E0` | `[已证]` |
| 0x5F4EC0 → 0x6D2790 | 脏矩形 Add | `0x5F5146`，`FUN_006d2790(x,y,w,h,1)` | `[已证]` |

**路径 B（子弹构造器，深度 1）**：`0x466560`（BulletClass 构造，`[esi]=0x7E46E4`）→ `0x5F4D30` → Add；同时 `inc [0xA8ED50]`。

**路径 C（命中/效果，深度 3–8）**：`0x4666E0→0x468D80→0x4690B0→0x489280→{0x480CB0/0x486E70/0x587180→0x56xx–0x58xx 效果簇}→Add`；共 16 个 Add 调用者经此支。

**路径 D（触发器动作，深度 6–8）**：`0x4666E0→0x468D80→0x4690B0→0x6E53A0→0x7265C0→0x6DD8B0(TActionClass)→{0x6E0490/0x6E2050/0x4F4480→0x6D3D10→0x6D9A50}→Add`。

### 每子弹每帧加几个矩形？`[静态推断]`

- `0x5F4EC0` 每次调用**最多加 1 个矩形**（`FUN_006d2790(...,1)`，一次 `rep movsd` 5 dword），且先做位置缓存比较 `0xAC1380/84/88`：位置未变则直接返回 ⇒ **不是每帧必加**。
- 子弹构造时 `0x5F4D30` 加初始矩形 1 个（1 次）。
- 命中/分裂时经路径 C/D 每产生一个效果对象加 1 个矩形（数量取决于弹类型/目标，静态不可定）。
- ⇒ **"静飞的每发子弹每帧"= 0（除非它自身位置被 0x5F4EC0 类函数调用）**；"每发子弹一生"= 至少 1（构造）+ 命中时若干。精确期望需真机/日志，**本卡判 `[未证]`**。

**结论**：排除了"子弹 → 每帧持续脏矩形 → O(k²)"作为**纯每帧机制**；但"子弹事件 → 一批矩形 + 一批新对象 + 触发器"仍是合理的工作放大路径。

## Q3 · 超线性搜索：有没有 O(b·n) 或 O(b²) 路径？

### 主判：`[已证·负]` 没有找到"外层遍历子弹、内层遍历全体对象"的 O(b·n) 函数

- 全 `.text` 双通道扫"读 `0xA8ED50`(Bullet Count) 且有回边"的函数只有 3 个：`0x466560`(子弹**构造器**，250 B，2 回边，实为 vector 增删)、`0x534450`(1378 B/31 回边)、`0x64DEA0`(11242 B/58 回边，**SYNC 转储**，台账 §881 已判默认不执行)。**没有**一个把 `0xA8ED50` 当外层上界再嵌内存器遍历。
- 深度≤3 闭包内"有回边 + 引用任一容器 Count"只有 3 个：`0x420960`(构造器内 vector 追加)、`0x6D2790`(脏矩形 Add)、`0x7258D0`(构造器/登记，12 回边但路径 `0x421EA0→0x5F65F0→0x7258D0` 属创建链)。**都不是每发子弹每帧的 O(n) 内层遍历**。

## Q5 · `0xA8E9A0`（G_INGAME）能否当"局内"判别量
