# W161 未证清单（分级）

## [未证]（本卡未验，需要新证据）
1. **① 分桶"贴脸全可见"特例**：Q2.3 静态证明绘制是分层+视口裁剪，视口外子弹不画；但 ① 实验几何下是否真"全部子弹在视口内"，本卡无真机 b>0 证据。R12_FACTS §9.3 明列"战斗态 b>0 分段"仍未证。区分证据见报告 Q4-3。
2. **战斗态代码热点归属**：AI / Draw / Blit / 渲染簇谁在 b>0 时真热，本卡纯静态不下结论；需 EIP 采样（Q4-2）。
3. **每发动态指令数**：1794 是 AI 静态指令上界（含 2 回边循环体），真实每发动态路径长度未测；本卡用上界做保守换算，不影响 Q1 判据方向。
4. **目标机主频**：1/2/3 GHz 是明写的假设区间，实际 harness 主机主频未核；但最保守 1 GHz 上界已满足判据，故主频不确定性不翻转结论。
5. **0xA8ED50 等子弹容器引用函数中 0x67C690 / 0x7192F0 的精确语义**：我只确认它们引用 Items/Count 且 `draw_calls=0`，未逐条定性（前者 78 B、后者 2302 B）。不影响"它们不在绘制路径"的结论。
6. **槽 70 (0x5F65D0) 与 0x71CC50 的 Draw 调用语义**：确认有 `call [reg+0x114]`，但未定性是哪些对象类的 Draw；只确认不是子弹数组循环。

## [静态推断]（读代码得出，未在活进程验）
1. 槽 69 = Draw 的"像绘制"特征（surface 虚表间接调用 + 0x4AED70 助手）是从指令形态推断；但 `DrawIfVisible → [eax+0x114]` 的调用链已是 `[已证]`（字节+边界），故槽号判定本身可靠。
2. 0x6D8DB0 是"绘制派发主簇"来自其结构（分层遍历 + 视口裁剪 + 5 次 DrawIfVisible 槽调用）+ 台账佐证；它是每帧渲染主循环这一点未在真机逐帧确认。
3. 0x534450 是 SYNC/调试 dump 函数（循环调 0x725C70 打印），基于调用形态；不影响结论。
