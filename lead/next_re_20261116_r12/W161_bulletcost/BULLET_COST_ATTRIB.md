## Q1 · 0.65 ms/发 的量级是否可能来自更新代码？

### 1.1 静态代价模型口径

- 主函数：`BulletClass::AI` @ `0x4666E0`，atlas `size=6422`（**十进制**，§863），capstone 线性反汇编（skipdata=True）得 **1794 指令 / 816 条含内存操作数指令 / 115 条 call 指令**，与 R12_FACTS §6.1（6422 B / 1794 指令 / 2 回边）**逐项吻合**。
- 回边 2 个：`0x466764→0x46674E`（`jl`）、`0x4678F6→0x467879`（`jl`）—— 证明我的反汇编与 Lead 核过的同一字节流。
- **每元素口径**：AI 是"每发每帧一次"的更新函数；1794 是**静态上界**（回边循环体只在少数分支走，真实动态路径更短）。闭包是"每发若把可达函数全跑一遍"的**极保守上界**（含销毁/错误/CRT 路径，真实每发不会全跑）。

### 1.2 双通道闭包（深度 1–4，逐层）

通道 A = Ghidra `calledges.raw.log` 的 caller→callee；通道 B = **全 `.text` 逐字节线性扫描**（skipdata=True，不依赖 `function_atlas.tsv` 的 `entry+size` 做 callee 发现；只把 call 站点按 atlas entry 归入 caller）。

### 1.3 时间上界换算（主频假设明写）

模型：`time = instructions × CPI / freq`。CPI = 1/2/4（4 是刻意悲观的上界假设），freq = 1.0 / 2.0 / 3.0 GHz。

- 真实每发路径（AI 本体）：3.0 GHz/CPI1 = 0.60 µs ⇒ **650/0.60 ≈ 1083×**；最悲观 1.0 GHz/CPI4 = 7.18 µs ⇒ **650/7.18 ≈ 91×**。小 **2–3 个数量级**。

`[已证]` **判据结论**：即使把整个可达闭包当作每发成本、配上 1 GHz 与 CPI=4 的双重 pessimism，静态上界仍比 650 µs 小 3.6×；真实每发更新路径小 1.5–3 个数量级。⇒ **更新代码（AI + 其调用闭包）不是 0.65 ms/发的主因。**（与 W151 §889-5 的方向一致，但我用双通道把闭包从 303 修正到 303/422 两口径。）

## Q2 · 子弹的绘制路径是什么？它是否每帧遍历子弹数组？

### 2.1 槽 `+0x114` = Draw 的确认/否证

**方法**：从 `0x007E46E4` 起按 dword 读 126 个槽（字节通道，直接读 `.rdata` 原始字节），与 `vtable_members.tsv`（atlas 通道）对账；每槽取 atlas size、首 6 条指令、直接 callee、深度 3 闭包内的绘制原语。

复跑命令：
```bash
python w161_q2_vtable.py         # 全槽 dump + 0 差异对账
python w161_q2_draw.py           # 候选槽 callee 深挖
python w161_q2_render.py         # DrawIfVisible 全反汇编 + 边界校验
```

`[已证]` 结果（详见 `EVIDENCE/Q2_vtable_dump.json` / `Q2_vtable_console.txt`）：
- 125 个非空槽（槽 0–124），槽 125 = 0；**字节通道 vs 台账 125 槽 0 差异**。
- 槽 11 (`+0x2C`) = `0x46B550`，首指令 `mov eax,8`（WhatAmI=8，与台账一致）。
- 槽 23 (`+0x5C`) = `0x4666E0`（AI，6422 B / 1794 指令）。
- 槽 65 (`+0x104`) = `0x5F4B10`（DrawIfVisible，511 B / 165 指令 / 78 访存）。
- 槽 69 (`+0x114`) = `0x468090`（923 B / 277 指令 / 114 访存 / 23 直接 callee）。原始字节：`[0x007E47F8] = 0x00468090`。

**独立判断是否像绘制**（不靠台账）：
- 槽 69 的 23 个直接 callee 含 `0x4AED70`（1317 B，被调用 2 次）、`0x5AF980`(508 B)、`0x6D20E0`(60 B，3 次)，以及多处**虚表间接调用** `[eax+0x6C]` / `[edx+0x1E8]` / `[eax+0x1C8]` / `[edx+0x1D0]`（surface/图层对象方法），并有 `0x4AED70` 内的 surface 指针链（`[edi]` 比对 -1、`[edi+0xC]` 取 surface、`[edx+0x78]` 取 surface 方法） —— 符合"大量操作 surface/像素"的绘制特征。
- **决定性独立证据**：`DrawIfVisible`(0x5F4B10) 做完视口裁剪后，在 **0x5F4CFD `ff 90 14 01 00 00` = `call dword ptr [eax+0x114]`** 调用槽 69；从 0x5F4B10 入口线性反汇编到 0x5F4CFD 恰落指界（`boundary_check → True ok`）。这是 `DrawIfVisible → Draw` 的经典两槽模式。
- `[已证]` **判定：槽 `+0x114` = Draw 确认成立**（从 `[静态推断·未复核]` 升级），且槽 `+0x104` = DrawIfVisible 亦确认。台账 §889-2 的说法正确，但当时标"未复核"；本卡用调用链独立复核。

### 2.2 渲染派发点：有没有"遍历子弹数组 + 调 Draw 槽"的循环？

复跑命令：`python w161_q2_render2.py` + `python w161_q2_cluster.py`

**(a) Draw 槽调用点全表**（字节通道：`FF 9x 14 01 00 00` 模式，6 处全部边界有效）：
| 站点 | 所在函数 | 语义 |
|---|---|---|
| 0x41464F | 0x4144B0 | AircraftClass::Draw 调基类 Draw |
| 0x43D005 | 0x43CEA0 | BuildingClass 绘制 |
| 0x43DC07 | 0x43DA80 | BuildingClass 绘制 |
| **0x5F4CFD** | **0x5F4B10** | **DrawIfVisible → Draw** |
| 0x5F65DC | 0x5F65D0 | 槽70 函数 |
| 0x71CD7B | 0x71CC50 | 其他类 Draw |

直接 call `0x468090`(Draw) 的 rel-call 站点 = **0**（全走虚表）；直接 call `0x5F4B10`(DrawIfVisible) 的站点 = **3**（0x422C8E / 0x73B132 / 0x749B5B，均非子弹数组循环）。

**(b) 子弹容器引用全表**（`sweep_disps_to`，skipdata=True）：
- `0xA8ED40`（vptr）：4 处 → 0x466380 / 0x466560（子弹 ctor/dtor）+ 0x4E62B0（初始化写 vtable 0x7E4678/0x7E4698）。
- `0xA8ED44`（Items）：10 处 → 上述 + 0x534450（调试 dump，循环调 `0x725C70` 打印）+ 0x55B880（数组移除器）+ 0x64DEA0（SYNC dump）+ 0x67C690 + 0x7192F0。
- `0xA8ED50`（Count）：15 处 → 同集合。
- `[已证]` **这些函数里没有一处调用 Draw 槽或 DrawIfVisible**（逐个 `summarize_fn` 的 `draw_calls=0`；`Q2_render_scan2_console.txt`）。

**(c) 真正的渲染派发点**：`call [reg+0x104]`（DrawIfVisible 槽）的 7 个边界有效站点中 **5 个在 `0x6D8DB0` 渲染簇**（0x6D909E / 0x6D916C / 0x6D93FA，另 0x6D97D0:0x6D98E9 与 0x6D9920:0x6D9A21 属同簇延伸）。`0x6D8DB0` 结构：
```
0x6D8F19  lea ebx,[eax+eax*2]; shl ebx,3      ; 层结构 stride = 0x18 (DynamicVectorClass)
0x6D8F2B  mov ecx,[ebx+0x8A0370]              ; 层 count
0x6D8F39  mov eax,[ebx+0x8A0364]              ; 层 Items 基址
0x6D8F43  mov esi,[eax+ecx*4]                 ; 逐对象
0x6D8F88..0x6D8FAC  视口边界检查 [esi+0x9C] vs 0x886fa0..ac  → 越界跳过
0x6D8FDA / 0x6D9122  call 0x5865E0 / 0x6D2140  ; 可见性/fog 检查
0x6D909E / 0x6D916C / 0x6D93FA  call [edx+0x104] ; DrawIfVisible
```
台账 line 5800 佐证：`0x008A0394 = MapClass::ObjectsInLayers Layer-2(Ground).Items`；层基 `0x8A0364 = Layer0.Items`、count `0x8A0370`、stride `0x18`，layer[2].Items = `0x8A0364+2*0x18+4 = 0x8A0394`，自洽。`0x6D8DB0` 唯一调用者 `0x6D465F`（在 `0x6D3D10` 内）。

`[已证]` **判定**：镜像里**没有**"遍历子弹数组 + 调 Draw 槽"的循环；绘制派发是 **`0x6D8DB0` 按 MapClass 分层遍历 + 视口裁剪后调 DrawIfVisible(槽0x104) → Draw(槽0x114)**。已知零引用孤儿 `0x55B8F0`（11 路阶梯，R12_FACTS §9.1 真机 818 万采样 0 命中）不在绘制路径上。

### 2.3 "每发都画"是否成立？

`[已证]` **静态上不成立，特例下不能排除**：
- 反证（静态）：`0x6D8DB0` 对层内每个对象做**视口边界检查**（`[esi+0x9C]` 三坐标 vs `0x886fa0..ac`，越界 `jl/jge → 0x6D940C` 跳过），再经 `0x5865E0`/`0x6D2140` 可见性检查，才调 DrawIfVisible；DrawIfVisible 自身又查 `[esi+0x80]/[esi+0x81]` 标志与 0x6D2140。⇒ **视口外 / 不在 ObjectsInLayers / 标志失败的子弹不画**。"每发都画"要求全部子弹同时在视口内且在层里，静态不成立。
- 特例（[未证]）：① 的实验几何是贴脸战斗（子弹密集、大概率全在视口内），此时"全可见"可能近似成立；但 R12_FACTS §9.3 明确"战斗态 b>0 分段"仍未证，本卡不下结论。

## Q3 · 0.65 ms/发 是统计假象吗？

复跑命令：`python w161_q3_resolvability.py`（输入为 R12_FACTS §8.1 已发布数字，不重算回归）。

### 3.1 量化与台阶的事实底座（引用已核）
- `t_monotonic` 量化到 **15.625 ms**（1/64 s），13 个文件无该字段，精度口径须用 `t_perf_ns`（R12_FACTS §8）。
- 某些窗口 `ms/frame` 呈 **2:1 离散台阶 25.30 / 50.40 ms**（R11_COMMON §3.5），台阶差 **25.10 ms**。
- 拟合：斜率 **0.6496**、RMSE **10.73 ms**（n=60，b≥30）。
- 量化压缩：`b≥75` 端动态范围压到真值 **54.6%**（中位 −45.4%），方向**低估**。

### 3.2 区间式分辨力（不用 p 值/CI）

**(1) 斜率不是常数，而是阶梯的局部斜率（26× 跨度）**：
| 相邻桶 | 中位差 | 局部斜率 |
|---|---|---|
| 0–24 → 25–49 | +1.01 ms | +0.040 |
| 25–49 → 50–74 | +5.54 ms | +0.222 |
| 50–74 → 75–99 | +20.88 ms | +0.835 |
| 75–99 → 100–124 | +25.90 ms | +1.036 |

`[已证]` 局部斜率范围 **0.040 – 1.036 ms/发（26×）**。0.65 只是这条凸阶梯的中段平均值。

**(2) 换 defensible 的拟合口径，斜率在 0.53–0.94 之间都能得到**（同一组分桶中位）：
- 全 5 桶 LSQ = 0.5323；端点 0→112 = 0.5333；b≥25 四桶 = 0.7114；b≥50 三桶 = 0.9356；已发布 b≥30 逐点 = 0.6496。
`[已证]` ⇒ **"给定噪声与量化，斜率落在 ~[0.53, 0.94] 区间都能拟合出接近 0.65 的描述"**；再叠加分桶局部斜率，全区间是 **[0.04, 1.04]**。0.65 不比 0.53 或 0.94 更"真"。

**(3) 噪声/量子/台阶的斜率带宽**：
- RMSE 10.73 / x-span 95 = **0.113 ms/发**（噪声等效带宽）
- 量子 15.625 / 95 = **0.164 ms/发**（量子等效）
- 台阶 25.10 / 95 = **0.264 ms/发**（台阶等效）
- RMSE = 0.43 个 2:1 台阶；总拟合信号 0.6496×95 = 61.7 ms ≈ **3.95 个量子 / 2.46 个台阶**。⇒ 整条"斜率"只由 **2–4 个大台阶**构成，分辨力受台阶粒度支配。

**(4) 占空比重解释**：若 ms/frame 是 25.30 与 50.40 ms 帧的混合，则每发只把慢帧比例改变 **0.6496/25.10 = 2.59%**，约 **39 发**才翻一个完整台阶。0.65 更像是"慢帧占空比随子弹数的变化率"，而非每发 CPU 时间。

**(5) 量化压缩的方向**：真值高端斜率 ≈ 0.6496/0.546 = **1.19 ms/发**；高端局部斜率修正后 **1.53–1.90 ms/发**。⇒ 0.65 在高端的方向是**低估约 1.8×**，**不是上界**。

### 3.3 结论（明确）
`[已证]` **0.65 ms/发 应作为「不可分辨的量（聚合统计量）」处理**，证据：
- 它不是真实物理每发成本：Q1 证明更新代码小 1.5–3 数量级；Q2 证明绘制是按可见性/分层挑的，不是每发必画。
- 它不是干净上界：量化压缩使高端真值（1.19–1.90）反而是 0.65 的约 1.8×。
- 它无法从这批数据里分离：斜率随拟合口径在 0.53–0.94（局部 0.04–1.04）间变动，且被 2:1 台阶/15.625 ms 量子支配为占空比效应。
- 若要选一个最接近的物理读法：0.65 是"每发使慢帧占空比 +2.59%"的线性投影，是**阶梯聚合**，不是可归因到某段代码的每发开销。

## Q4 · 下一条最有区分力的证据（只列 3 条）

每条写清"怎么取 + 能区分哪两个假设"。假设集：H_upd=每发更新代码成本；H_draw=每发绘制/blit 成本；H_step=帧台阶/占空比统计假象；H_geo=接战几何导致的 O(b·n) 邻域/溅射。

1. **分帧时长直方图（离线，先做；零新增真机成本）**
   - 怎么取：从已有 `run.ndjson` 用 `t_perf_ns` 算**单帧** `dt=Δt/Δframe`（非 10 s 窗均值），按 b<25 / b≥75 两桶出 dt 直方图（n、逐值、极差、双峰 vs 单峰），并数每桶 25.30/50.40 两台阶的样本占比。复跑输入是现成语料，无需启动游戏。
   - 区分：**H_step（双峰、慢帧占比随 b 升）vs H_upd/H_draw（单峰整体右移）**。若高 b 桶只是慢帧占比升高而非 dt 连续右移 ⇒ 0.65 是占空比假象，Q3 结论锁死。

2. **战斗态 EIP 高频采样（需真机授权 + 让单位接战的输入序列）**
   - 怎么取：在 `b≥75` 段以 ≥10 kHz 采 EIP，按地址区间归一：`0x4666E0..0x467FF2`（AI）、`0x468090..0x4683C5`（Draw）、Blit*`0x4912B0/0x494B60/0x7BC890`、`0x6D8DB0..0x6DA1FB`（渲染簇）、空闲/等待；同时段设 b<25 对照。R12_FACTS §9.1 已有"EIP 采样 + 正对照"范式可复用。
   - 区分：**H_upd/H_draw（EIP 集中在子弹代码）vs H_step/H_geo（子弹代码不热）**。这是唯一能把"相关"钉到"哪段代码"的证据。

3. **固定几何改可见性的 A/B（真机，可复用接战图）**
   - 怎么取：同一地图、同单位数，比较"贴脸（全在视口）"与"边缘交火（部分子弹出视口）"两臂，控制 b 相近（如都 80–100），各测 ms/frame 中位（t_perf_ns）。
   - 区分：**H_draw（出视口后 ms/frame 明显降 ⇒ 绘制主因）vs H_upd/H_geo（ms/frame 不随可见性变 ⇒ 更新/几何主因）**。直接检验 Q2.3 的"每发都画"特例。
