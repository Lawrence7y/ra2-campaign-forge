## 1 三项自证对象的精确定义

依据：卡面 `DECISION_QUESTIONS.md:118-122`（Q6 责任身份落实；**非技术裁决——来源会话身份补登（行政动作）**；通道 = 来源会话直接补登、无需立 D-xx）、落点件 `C07_IDENTITY_SLOT.md` §3/§5、`NEXT_STEPS_20261106.md:23`（九固定字段实文）与 `:119`（身份落实原则实文，本轮逐字实读）。

### 1(a) reviewerSessionId —— 自证命题：「值-会话绑定」

自证的是「登记件中的这个 ID 确实是填写该登记件的会话在其运行环境中实际取得的运行态标识」，而**不是**「格式合规」（N07/N08 已验，`_f3_c7check.py:176-185/:372-380`）、「不在冒用面」（N09/N10 已验，`:265-268/:382-393`）或「两层一致」（N09 已验）——后三者 V1 已证拦不住一致伪造。

- **合格自证必须包含**：①值逐字；②取值机制的**本会话实跑**证据（命令 + 逐字输出，承 r2 先例 `a_residual_n1_20261108/ACCEPTANCE_RECORDS.json:47` `sessionIdSource` 格式）；③机制非硬编码的可核素材（差分重放声明，B1.3/B1.4）。
- **可以包含**：会话启动时点、所属工作流/派发方、同 ID 在其他件的独立记载。
- **不需要包含**：任何他方会话的 ID；密码学签名（本生态无此机制，r2 先例 `:48` `identityVerifiability` 明言「非密码学签名凭据」）；对格式的再证明（门禁已验）。

### 1(b) sourceTaskId —— 自证命题：「号-任务绑定」

自证的是「这个任务号确实标识了派发 N-11 离线分流任务的那次派发动作」，而**不是**「非空」（H06 已验）或「形如任务号」。注意计划号（`N-11`）**不是**任务号——它是 `NEXT_STEPS_20261106.md:101-107` 定义的工作项号；r2 先例七条 `sourceTaskId=N-1` 全为计划号，被 `C07_IDENTITY_SLOT.md:120`（§5.4 #7）列为「先例与反例」。

- **合格自证必须包含**：①值逐字；②任务号载体（任务号出现的件/记录：引文 + 路径 + 行号，载体先于或同于派发动作）；③承接声明——该任务派发与 `PERF_REPAIR_HANDOFF.md`（N-11 产出件，`:151-152` 自述「任务书未载来源会话 session/run ID，登记为待补 [Q6]，不补造」；指纹已入门禁 H11 四必绑）的对应关系。
- **可以包含**：任务书正文指纹、派发→产出的时间线、多级派发链。
- **不需要包含**：计划号本身作为「任务号」的证明；若真实任务号在盘上无载体（派发只存在于会话间消息），**不得编造**——如实走计划号降级路径（门禁 N11/N12：`unresolved` 必含登记语「正式任务书编号未落实」，`_f3_c7check.py:395-412`；先例 `YI_SUPERSEDE_JIA_BINDING.md:90`），档位封顶 PARTIAL。

### 1(c) reviewerRole —— 自证命题：「角色-签发权绑定」

自证的是「这个角色名确实是该会话在派发动作中实际承担、且持有签发权的角色」，而**不是**「非空且非内部角色」（H06+N01/N02 已拦误抄面）。签发权的授权链在盘上可核：`NEXT_STEPS_20261106.md:119` 指向 `GOAL_RE_CONTINUOUS.md:89-105`（连续执行职责与新流程定义，本轮实读 :85-109）与 D-24。

- **可以包含**：授权裁决书指纹、派发记录中实际使用的角色名。

载体设计（为什么是两件）：登记件容器键集合被锁死恰 13 键（N13 缺+多都拦，`_f3_c7check.py:414-417`）、记录恰 9 字段顺序敏感（H05，`:256`）——自证证据**塞不进登记件**，只能平行承载。因此：**登记件**（`ACCEPTANCE_RECORDS_C07.json`，按 `C07_IDENTITY_SLOT.md` §4.3 C 案与模板 `_c7_record_template.json` 填）载三值本体；**自证声明件**（`C07_ATTESTATION_STATEMENT.md`，模板 `_tp_TP_ATTESTATION_TEMPLATE.md`）载三值的出处与一致性证据。两件互绑 = 三值逐字双录（清单 B3）+ 声明件 §A2 载登记件指纹绑定行（清单 B2；登记件自身指纹无法内嵌，单向绑定）。

- **核验者看什么**：A 组（门禁重跑）+ B 组（绑定行复算、双录逐字一致）。

### L2 出处层——「值从哪里来」

### L3 一致性层——「值与其他已知事实是否自洽」

3. 「本会话持有 GRC:89-105 所述职责」——授权-持有绑定是会话内部事实。
4. 会话启动时点的自报值（运行态不提供时只能「不可得」）。

### 3(c) 对 (b) 类的风险最小化设计（四件套）

1. **机制差分重放**（F 组）：把「值真」（不可核）降级为「机制真 + 机制产出值被如实转录」（可核）。硬编码可检出（r1 破绽②型伪造直接拒绝），伪造者必须改造机制并留下可检痕迹——抬成本、留证据。
2. **独立见证人槽**（声明件 §D）：见证人 = 派发该任务的工作流**编排方**——生态内唯一独立于来源会话的记账方（run 标识由其分配/记录）。见证语句固定措辞：任务 ID↔run 标识对应关系。来源会话只发请求、只得留空，**代填 = 拒绝项**。见证同为声明，但伪造从「单方改文本」变成「两方合谋 + 两处可互查痕迹」；且满足 NEXT:23「验收者与作者不得相同」的独立方要求。
3. **两处独立记载互证 + 外部记载硬条件**：S1 须在声明件之外至少一处**先于补登存在**的载体出现（编排方派发记录 / 工作流日志 / `ROUND_SUBAGENT_LOG_*` / N-4 任务书签署）。全无 → 通过档不可达，登记封顶 PARTIAL + `unresolved`「运行标识无独立见证/独立记载」。判据基线：真实已登 ID 在先例件外有 7 个写域的自然痕迹（本会话实跑 §4-D2），而 V1 合成值只存在于合成它的实验室写域——「零外部记载」有真实先例可对照。
4. **可撤回性（把不可证的「真」转换为可证伪的「一致」）**：声明件 A3 声明语句含撤销条款；登记后任何时点发现跨件矛盾（同会话异 ID / 同 ID 异主 / 见证方撤回）→ 按 §4-D4 降级/撤销；下游引用登记件必须连同其指纹与档位引用，PARTIAL 不得作放行凭据（NEXT:25）。

## 4 伪造检出手段（每条：怎么检 / 什么程度算可疑 / 可疑之后怎么办）

### D1 时间线矛盾

- **怎么检**：声明件 C2 三锚 + S2 内嵌日期成分（若有）+ 盘上自载日期（NEXT_STEPS 2026-11-06、PERF 2026-11-08）。规则：会话启动 ≤ 派发 ≤ 补登；S2 内嵌日期 ∈ [2026-11-06, 补登日]。V1 样本即含此类信号：其合成任务号内嵌 `20261108`（`_f3_V1_t29variant_consistent.json:23`），若声称的派发早于该日期即矛盾。
- **算可疑**：任一序关系违反（如派发晚于补登、任务号日期早于 N-11 定义件日期）→ 不可能；仅缺一锚（如启动不可得）→ 缺口。
- **之后**：不可能 → **拒绝**；缺口 → 存疑（登记 PARTIAL + unresolved 逐条）。

### D2 cross-ref 断裂

- **怎么检**：三值归一化全仓检索（NFKC+去空白+去Cf+casefold），命中按写域分布，与声明件 C1 自报表比对。**本会话演示实跑**（`python -I -X utf8`，lead/ 全树 *.md/*.json/*.py/*.txt）：V1 证明件合成 ID 仅命中合成它的实验室写域 5 件；其合成任务号仅命中两个攻样本写域（32+22 件）；对照：真实已登 ID 段命中 7 个写域（先例件本体 3 件 + 各轮转录件）。方法可行性与「零外部记载」的真实对照基线均成立。
- **算可疑**：自报位置查无 → 自报不实（比断裂更重）；零外部命中且自报如实「无」 → 断裂但可能 innocent（真实新会话可能无痕）。
- **之后**：自报不实 → **拒绝**；断裂如实 → 存疑，登记封顶 PARTIAL + unresolved「运行标识无盘上独立旁证」，且要求补见证（§3(c)-2）或后续证据闭合。

### D3 格式过新

- **怎么检**：①声明件必须写明 S1 形制依据（引先例形制或运行态文档）；②声明承诺的结构位与值自身 hex 比对（如声称 UUID v4 语义则版本/variant 位须相符）；③形制依据的首次出现时间不晚于声称的会话启动。背景：增强版刻意未把 N07 收紧到 v4/variant 位——「依据仅 1 个真实已登 ID，强收有误伤真实运行态 ID 之险」（`C07_GATE_G1_G5_FIX.md:227`），故形制真值面留给本协议的声明+核验组合。
- **算可疑**：声明的形制规范查不到出处、或晚于会话启动才出现 → 存疑；声明与值结构矛盾 → 伪造信号。
- **之后**：矛盾 → **拒绝**；查不到 → 存疑 + 要求补形制出处。

### D4 一致性矛盾（同会话异 ID / 同 ID 异主）

- **怎么检**：全仓检索同一主体（按 ID、按角色、按任务号）的全部自报并两两比对；N-4 签署后同值复用核验（两处落笔，`C07_IDENTITY_SLOT.md:123`）；与 a_residual 两件已登 ID 归一化比对（N10 已拦，复核）。
- **算可疑**：任何一对矛盾（同一会话两件不同 ID；同一 ID 两件不同归属；N-4 复用值与登记件不一致）。
- **之后**：**拒绝**——这是 A3 声明撤销条款的触发条件，登记作废、撤下游引用。

### D5 硬编码证据（r1 破绽②型）

## 6 不可核验项的如实声明与降依赖设计

1. **核心命题不可第三方终证**：「该 sessionId 真的是该会话的」在离线条件下**无法**被第三方最终证实——本生态无密码学身份机制，r2 先例已把它登记为 unresolved（`a_residual_n1_20261108/ACCEPTANCE_RECORDS.json:48`）。本协议**不假装解决它**：§3(c) 四件套（机制差分重放 / 独立见证人 / 外部记载硬条件 / 可撤回性）把「一次性不可证的真」转换为「持续性可证伪的一致 + 多方合谋成本 + 可检痕迹」。这是降依赖，不是消除依赖。
2. **见证人也是会话**：编排方见证同为声明，非密码学证明；它的价值在于独立性（记账方 ≠ 值的主张方）与可交叉检索性（D2/D3/D4 三组独立核对 its 记载）。若连编排方记录都不可得（如派发链全程无盘上痕），协议的诚实产出 = PARTIAL + unresolved + 派发阻塞持续——这是 NEXT:119 既有原则的正确结果，不是协议失灵。
3. **差分重放的效力边界**：F 组证明「机制非硬编码」，不证明「该值属于该会话」；一个真读环境的机制在其会话里产出的值被事后替换文本仍不可检——残余风险由外部记载硬条件与可撤回性兜底。残余不可消除，如实声明。
