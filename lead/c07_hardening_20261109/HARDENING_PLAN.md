### 3.1 ① 在先性钉死（对应 P1；堵 A6 外部记载伪造——报告 :79/:117）

**谁做什么**
- **来源会话**：声明件 §C1 自报表扩为「外部载体清单」固定五列 `{path, carrierType(machine|prose), selfDate(自载时刻), sha256, bytes}`；每件声称的独立记载必须入列，未入列载体一经查出 = 自报不实（拒绝；与⑤闭环）。
- **编排方**：任务书发布「载体分类规范 + 可信自然痕迹写域白名单」（与⑤共用一份，白名单制非黑名单制，理由见 §4.1-①）。
- **核验者**：对清单内每载体跑三步检法（见下），产出 PRIOR / NOT-PRIOR / UNDECIDABLE。
- **门禁脚本**：本轮零改动（在先性属清单 D/E 组核验面）。

**产出什么**：声明件 §C1 载体清单表（模板增列，纯文字）；核验者「在先性核验留痕件」每载体一行 `{path, tracked, firstCommit(有则填), mtime, selfDate, carrierVerdict, priorVerdict}`。

**怎么检**（三步+组合判定；1/2 本会话已验可行性，3 本会话已实跑）
1. **git 在先性**：`git ls-files --error-unmatch <path>` 判跟踪；跟踪者 `git log --format="%H %ad" --date=iso-strict --follow -- <path>` 取首条提交时刻 ≤ 补登锚 → git 在先性成立。可行性实证（本会话实跑）：`git log --oneline -- lead/c07_truth_protocol_20261109/` 输出空、`git ls-files lead/ | wc -l` = 2141、HEAD=2657458；两台账有历史（设计件 §2.1(c) 记 `GOAL_THREE_TARGETS_20261018.md` 首查 2657458 / 2026-11-01T19:35:33+08:00）。
2. **mtime 一致性**：`stat -c '%y %n' <path>`：要求 mtime ≥ 自载时刻 且 mtime ≤ 补登锚。**单向否定性证据**：矛盾 → NOT-PRIOR + 伪造信号；一致 → 不构成证明（§4.1-① utime 面）。本会话复证样例：伪造件 mtime 2026-11-09 06:51:56 vs 自载 2026-11-06T10:24（:11）当场穿帮。
3. **载体认定**：按 §2.3 口径——可解析 json 顶层含 recordedAt+sessionId → 机器载体（本会话实跑 1000 json → 130 载体）；其余一律散文。
4. **组合判定（按载体分流——对报告 :131 字面判据的必要修正）**：报告原文「`git log --follow -- <载体>` 无历史则不为先」若不分载体类型会把机器运行态载体（hook-status 等设计上不 git 跟踪）连真实在先性一起判死——本会话实跑证明五个 c07 写域+a_residual 先例件**全部** `??` untracked。故落地为：**机器载体** + mtime/recordedAt 自洽 + 写域在白名单内 + recordedAt ≤ 补登锚 → PRIOR（允许无 git 历史；实证 `lead/.mimosa/hook-status/` 各件 :3-4 即含 recordedAt+sessionId）；**散文载体** → 必须 git 在先性成立才 PRIOR，untracked 散文 = NOT-PRIOR（伪造 .md 正是此类）；任何矛盾 → NOT-PRIOR + 伪造信号。

**堵住哪个**：A6 主体形态（散文伪造记载：untracked 散文即 NOT-PRIOR → 通过档硬条件右支失效，当前五 c07 域全 `??` 本会话实跑）；A6 的 mtime 忘改变体（本会话实跑复现穿帮）；A1 的在先性面（外来真实 ID 载体 recordedAt=2026-11-01 与自称 2026-11-09 归属的时间差，与⑤ C1 交叉核闭环）。

**成本等级：中**（清单 D4/E3 加检法 + 协议 §5(d)「外部独立记载」定义注解 + 白名单 + 留痕件格式，均纯文字；`_hd_carrier_scan.py` 已备可复用）。附一项**流程决策成本**：散文载体要可判 PRIOR 须加「登记完成 = 本地 commit（不 push）」条款，与现行「不 commit」纪律冲突，**须用户裁决，本件不代决**（§5.4 未验项 3）。

## 4 漏点判定与互为前提

### 4.1 每项漏点（加固之后还剩什么攻击能过——逐项如实判定，不粉饰）

**① 漏点**
- **os.utime 双伪造**：先写伪造 recordedAt 再 `os.utime` 对齐假 mtime → git/mtime/载体三检全过。mtime 检查天生单向（只有不一致才有证明力）。NTFS $SI/$FILE_NAME 双时戳差需读 raw attribute，越出离线文书协议边界且铁律禁采样代码 → **堵不住**；只能要求核验者对毫秒位精度、时区换算做人工抽查抬成本。
- **git 造史**：`git commit --date` 本地伪造早于补登的历史 commit（本地仓无 push、无签名、reflog 可 expire）→ **git 判据的拦截面 = 不会/不愿用 git 的伪造者，对 git 熟手为零**。反向（删文件留 blob）反而帮核验者（`git log --all`/`git fsck` 可查）。
- **编排方合谋**：编排方亲手落一件假机器载体即全过三步检法——①不解决合谋（P7 域）。
- **白名单时序窗口**：白名单制 fail-closed 的残余 = 派发时未预见的合法新写域被误杀 → 诚实会话降档 PARTIAL（漏认不误认，方向安全但有效力代价）。
- **commit 条款未决**：不裁决则散文载体永远不可 PRIOR，通过档右支实际只剩机器载体一途（降级面，非漏洞面）。

**② 漏点**
- **编排方合谋**：编排方写假见证 = 全过——②的价值恰是协议 §3(c)-2 原理（协议 :93 亲读「伪造从『单方改文本』变成『两方合谋 + 两处可互查痕迹』」）：把单方伪造变两方合谋；**合谋本身堵不住**（P7 域）。
- **同账户写穿**：本仓全部写域同一 OS 账户，「编排方写域」是纪律约定不是权限边界——来源会话技术上可直接往编排方写域写件。只能靠检法 3/4 事后追责，不能事前阻止；痕迹链本身可整体伪造（继承① utime 面）。
- **见证件本体机载体化滥用**：若未来有人把见证件造成含 recordedAt+sessionId 形状冒充机器载体——由 natureNote 必检 + ⑤ 口径（c07- 声明性件归 prose）压制，但任何约定边界都有下一层伪装空间。

**③ 漏点**
- **对照集污染**：伪造者往旧写域埋伪造 hook-status（json 两字段 + utime）→ L2 收进伪造 ID，给自己 S1 洗「自然痕迹」——这不是 N10 问题，是①⑤的在先性/分类问题，**③不解决**。
- **对照集 DoS**：海量假载体拖垮扫描 → fail-closed 变全员 FAIL = 可用性攻击 → 装载器必须带预算上限（文件数/单件字节/总时长，超限 FAIL 并如实报「装载不完整」）；攻击者仍可用它干扰诚实登记（可接受的降级面，如实报）。
- **动态装载误报**：L2 混入非 dwf 形态 ID（本会话实测 dwf=82 / session_hex=6 / other=5）与他件引用性载体（第三方引用你的 ID）→ 靠 C1 自报豁免；豁免可被滥用（自报他人载体）但触发⑤ D1 自报不实闭环拒绝。
- **扫描规模**：全仓 walk 超 120s（报告 :159 实录）→ 不限定范围门禁跑不完——本项「高」成本主因之一，预算化后残余 = 大仓库场景覆盖不全。

**④ 漏点**
- **选择性呈现 / 留痕件伪造**：留痕件在核验者自己写域——核验者可只出示有利留痕、或事后伪造留痕件（写文件 + utime）。**锚定强度 = 核验者诚实度**；核验者被收买（A10，报告 :83「结构性，与铁则3 同根」）不受本项约束——P7 域，堵不住。
- **无密码学时间戳服务**（生态无）：本地 mtime 可 utime，锚只对「不会改文件的伪造者」硬。
- **会话启动锚仍自报**：本项只锚补登时刻；启动不可得的改进是「不再两可」（统一封顶 PARTIAL），不是「变得可证」。

**⑤ 漏点**
- **多域撒伪造载体凑门槛**：≥2 域 × ≥2 件自洽伪造 json（utime 对齐）即过门槛——门槛只抬成本（从 1 件 md → 跨域 ≥4 件自洽载体），**不消除**（①漏点继承）。
- **白名单误杀+误登**：白名单外合法新写域被误杀（漏认方向）；伪造树抢在白名单更新前落盘且编排方误登白名单 → 全过（合谋/失误面）。
- **分类边界是约定不是物理**：schema 伪装、字段大小写变体、嵌套而非顶层两字段等花样需口径逐版堵；「顶层两字段」口径比宽口径窄而可复算，但任何约定边界都存在下一层伪装空间。

### 4.2 互为前提关系（无环）

- **④ 是①的基准**：没有可信补登锚（留痕件墙钟），①的「mtime/recordedAt ≤ 补登锚」比较无从谈起——④必须先落。
- **⑤ 是①③的载体认定前提**：①的组合判定与③的 L2 装载都消费「机器载体 vs 散文」口径与白名单——⑤第二落。
- **① 封通过档 OR 右支**（P1 严重级）；**② 封 OR 左支**（P2 严重级）——两支各自独立成立即解锁，故两项都须落，缺一仍单点可达。
- **③ 的新 N10 语义依赖⑤的 C1 自报闭环**（命中豁免/拦截分流）；**② 消费①③④⑤全部口径**（见证件身份核=③的检索、见证件时点=④的锚、见证件可信度=①⑤的载体与白名单）——②最后闭合。
- **无环**：按 §5.2 顺序实施，每项落成即独立生效；②最后闭合后整体达到 §5.2(b) 描述的组合效果。
