### 2.1 ① 在先性钉死（对应 P1，堵 A6 外部记载伪造——`PROTOCOL_ATTACK_TEST.md:79/:117`）

**背景事实（本会话实跑）**：A6 伪造外部记载的两件拆穿武器都在盘上但清单零检项——mtime 2026-11-09 06:51:56 vs 自载 2026-11-06T10:24（本会话 `stat -c '%y %n'` + `grep` 实跑复证，伪造件 `lead/c07_protocol_attacks_20261109/_pa_a6_forged_extrecord.md:11` 自注「伪造的自载日期」）；五个 c07 写域 `git status --porcelain` 全 `??`、`git log -- lead/c07_truth_protocol_20261109/` 空输出、HEAD=2657458。

**(a) 谁做什么**
- **来源会话**：声明件 §C1 自报表扩为「外部载体清单」固定五列 `{path, carrierType(machine|prose), selfDate(自载时刻), sha256/bytes}`；每件声称的独立记载必须入列，未入列的载体一经查出 = 自报不实（拒绝，闭环见⑤）。
- **编排方**：任务书发布「载体分类规范 + 可信自然痕迹写域白名单」（与⑤共用同一份，动态维护；白名单制而非黑名单制的理由见漏点 (i)）。
- **核验者**：对清单内每载体跑三步检法（见 (c)），产出在先性判定 PRIOR / NOT-PRIOR / UNDECIDABLE。
- **门禁脚本**：本轮零改动（在先性属清单 D/E 组核验面）。未来若纳入门禁，走独立检查项 N22+，不动现有 36 项（改动成本见 §2.3 ③）。

**(b) 产出什么**
- 声明件 §C1 载体清单表（模板增列，纯文字改动）。
- 核验者「在先性核验留痕件」：每载体一行 `{path, tracked(yes/no), firstCommit(有则填), mtime, selfDate, carrierVerdict, priorVerdict}`。
- 三值判定：PRIOR（先于补登锚成立）/ NOT-PRIOR / UNDECIDABLE（→存疑）。

**(c) 怎么检**（三条，全部本会话已验可行性）
1. **git 在先性**：`git ls-files --error-unmatch <path>` 判是否跟踪；跟踪者 `git log --format="%H %ad" --date=iso-strict --follow -- <path>` 取首条提交时刻，≤ 补登锚 → git 在先性成立。两台账实证可行：`GOAL_THREE_TARGETS_20261018.md` 首查即得 `2657458 2026-11-01T19:35:33+08:00` 与 `3146a7b 2026-10-21…`（本会话实跑）。
2. **mtime 一致性**：`stat -c '%y %n' <path>`：要求 mtime ≥ 自载时刻 且 mtime ≤ 补登锚。**单向否定性证据**：矛盾 → NOT-PRIOR + 伪造信号；一致 → 不构成证明（utime 漏点见 (e)）。
3. **载体认定**：*.json 可解析且顶层含 `recordedAt`(ISO8601) + `sessionId`(非空) 两字段 → 机器载体（口径=`_hd_carrier_scan.py` 本会话实跑：999 个 json 解析 → 129 件载体）；其余一律散文。
4. **组合判定表**：机器载体 + mtime/recordedAt 自洽 + 写域在编排方白名单内 + recordedAt ≤ 补登锚 → PRIOR（**允许无 git 历史**——hook-status 等运行态件设计上不跟踪，实跑 `lead/.mimosa/hook-status/session_0eb16a5e….json:3-4` 即含 recordedAt+sessionId）；散文载体 → 必须 git 在先性成立才 PRIOR，untracked 散文 = NOT-PRIOR；任何 mtime/recordedAt/自载矛盾 → NOT-PRIOR。

**(d) 堵住哪个具体攻击**
- **A6 主体形态（散文伪造记载）**：untracked 散文 = NOT-PRIOR → 通过档硬条件右支失效。当前五个 c07 写域全 `??`（本会话实跑），伪造 .md 正是此类。
- **A6 的 mtime 忘改变体**：矛盾当场可见（本会话实跑复证如上）。
- **A1 的在先性面**：外来真实 ID 的载体 recordedAt（2026-11-01）与声称会话（2026-11-09 补登）的时间差暴露「ID 早于自称归属」——与⑤ C1 交叉核闭环。

**(e) 漏点（加固之后还剩什么能过）**
- (f) **os.utime 伪造 mtime**：先写伪造 recordedAt 再 `os.utime` 对齐假 mtime，双检全过。mtime 检查天生单向（只有不一致才有证明力）；NTFS 双时戳差（$SI/$FILE_INFORMATION）需读 raw attribute，越出离线文书协议边界，**不许写采样代码** → 堵不住，只能要求核验者对毫秒位精度、时区换算一致性做人工抽查抬成本。
- (g) **git 先 commit 再删 / 会动 git 的伪造者**：删了文件 blob 仍在历史（`git log --all`/`git fsck` 反而帮助核验者）——真堵不住的是反方向：`git commit --date` 本地伪造早于补登的历史 commit（本地仓无 push、无签名、committer date 可任意写、reflog 可 expire）→ **git 判据的拦截面 = 不会/不愿用 git 的伪造者**，对 git 熟手为零。且本仓 a_residual 先例件本身 untracked（本会话实跑 `git ls-files lead/a_residual_n1_20261108/` 空输出）：散文载体若要可判 PRIOR，协议必须加「登记完成 = 本地 commit（不 push）」条款——这与现行「不 commit」纪律冲突，属流程决策，**实施时须用户裁决**；不改则散文载体永远不可 PRIOR，硬条件右支实际只剩机器载体一途。
- (h) **编排方合谋**：亲手落一件假机器载体即全过三步检法——①不解决合谋（P7 域）。
- (i) **白名单/黑名单时序窗口**：黑名单制（列攻样本域）对清单未及的新伪造树漏判；本方案改用白名单制（可信自然痕迹写域由编排方派发时预先登记，白名单外一律不计自然痕迹，fail-closed）——残余窗口 = 派发时未预见的合法新写域被误杀 → 诚实会话降档 PARTIAL（漏认不误认，方向安全但有效力代价）。

**(f′) 成本**

## 3 实施优先级与组合效果

**(a) 顺序与性价比**：**④ → ⑤ → ① → ③ → ②**。④ 最便宜（纯文字）且是①「先于补登」比较基准的前提——没有可信补登锚，PRIOR/NOT-PRIOR 无从谈起；⑤ 的载体分类口径是①③载体认定的共同前提；①② 各封一条通过档 OR 硬支路（P1/P2 均「严重」级）；③ 单独只堵「中等」级 P4 且是唯一要动门禁代码+全量回归的 → 最后。若资源只够两项：**④+②**（最便宜的锚定 + 封 OR 左支）——但②的见证件身份交叉核仍需⑤的载体口径，故推荐至少四项（③可缓）。

**(b) 全部实施后攻击者还需要的条件**：要么 (i) 在白名单写域伪造 ≥2 域 × ≥2 件 mtime/recordedAt/自载三自洽、形制逼真的机器载体 + 一条能通过 C1/D1 交叉核的自报链（②不选时）；要么 (ii) 编排方合谋（或写穿编排方写域并伪造其 ID 痕迹链）。再加：时间线与核验留痕件锚一致、不留下任何 git/mtime 矛盾、熬过可撤回性巡检（D4 跨件矛盾随时降级）。成本从「一件散文+零工具、逐字面可达 REGISTERED」（A1+A4+A6 实跑结论）抬到「跨域多载体伪造+时戳工程+白名单博弈（或）编排方合谋」。

**(c) 互为前提**：④ 是①的基准（补登锚）；⑤ 是①③的载体认定前提；② 消费①④③⑤全部口径（见证件身份核=③的检索、见证件时点=④的锚、见证件可信度=①⑤的载体与白名单）；③ 的新 N10 语义依赖⑤的 C1 自报闭环。**无环**：按 (a) 序实施每项落成即可独立生效，② 最后闭合。

**(d) 能力边界（必须明说）**：全部实施后协议**仍不能证明值为真**。①同账户文件系统 utime 可伪造一切本地时戳与载体；②编排方合谋/写域写穿堵不住；③对照集可污染、可 DoS；④锚定强度=核验者诚实度（A10 不动）；⑤分类边界是约定。P7 原样成立：协议效力 = 抬成本 + 留可检痕迹 + 可撤回性持续暴露（报告 §5.5 口径），从「逐字面零成本伪造」升到「合谋级/工程级伪造」——**不升格为真值证明**。生态若不给会话身份密码学/平台级记账，此边界不移动。
