## 0. 一句话结论

**`0x6579E0` 属于 HUD/侧边栏渲染—雷达小地图子系统（`RadarClass` 一族的每帧绘制状态机），不是网络/输入/AI 层；但它确实是一个「玩家可见的过场影片显示接管」：更准确地说，是动作 100 `PlayIngameMovie` / 117 `PlayIngameMovieAndPause` 的侧边栏/雷达影片队列消费者。队列计数 `0xB45B68 > 0` 且当前影片带 `pause=true` 时，它使 `Scenario+0x62C` 挂起；队列清空时释放。因此它与动作 10 `PlayMovie` / 100 / 117 同属玩家可见影片面，但只与 100/117 共用从属入队器；动作 10 是另一条全屏播放链。** 注意：领队预检 `LEADER_PRECHECK_20261105.md:53` 称此路径「不经 TActionClass 派发」，应理解为「`0x6579E0` 不直接是动作派发块」；字节链显示动作 100/117 可经 `0x5BF390 → 0xB45B68 → 0x48D080 → 侧边栏绘制 → 0x6579E0` 间接到达它，见 §4。

## 3. 追 `0x653446` 到所属子系统

### 3.1 直接调用者链与边界

`0x653446` **不是函数头**，它位于 `0x653100` 函数体内（函数头 `sub esp,0x38; ret 4` 在 `0x653100/0x653127`，完整尾 `0x653731`）。`0x653395` 按 `[esi+0x14B0]` 做 4 路跳表 `0x653734`，其中表项 `[2] = 0x653444`；`0x653444` 装 `ecx=esi` 后在 `0x653446` 调 `0x6579E0`：

```
00653379  cmp [esi+0x14AC], ebp
00653385  mov eax, [esi+0x14B0]
0065338C  cmp eax, 3
00653395  jmp dword [eax*4 + 0x653734]     ; 0x653734表 = {0x6534EA,0x65339C,0x653444,0x6534EA}
...
00653444  mov ecx, esi
00653446  call 0x6579E0
```

上层直接链（全部由本次 68,253 条直接调用普查得到；每级只列直接 `E8` 调用）：

```
0x6D0E38  call 0x6A6C30   ; SidebarClass::v[16] 整帧协调
0x6A6FFC  call 0x63FB20   ; PowerClass::v[16]
0x63FDAC  call 0x653100   ; RadarClass::v[16]（vtable 0x7F0384 → 0x653100）
0x653446  call 0x6579E0   ; Radar 影片队列 / 挂起沿
```

`docs/re/radar_minimap_dots.md:23-40` 已把这条链画作 `GScreenClass::Draw / 主循环 → SidebarClass::v[16] 0x6A6C30 → PowerClass::v[16] 0x63FB20 → RadarClass::v[16] 0x653100 → 0x6579E0`，并明确 `0x655C50` 是单位点绘制、`0x656EC0` 是雷达地形+视口矩形、`0x653FA0` 是雷达文字/标签。本轮从字节复核 `0x653100` 的直接调用集：`0x4AED70`（4 处 blit）、`0x65FDD0`（雷达事件闪烁）、`0x656EC0`（地形/视口）、`0x653FA0`（文字）、`0x6579E0`（本对象）、`0x6C8C40`（时钟）等 20 点，`0x63FDAC` 之前 `0x63FD8F` 也调 `0x4AED70`；属于**每帧 HUD/渲染链**，不是消息泵、网络包处理或 AI 决策。

### 3.2 主循环把队列泵接到帧上

`0x48D080` 是冻结体与正常体都调用的函数（`P01/REPORT.md:73`；`Q02/REPORT.md:69,88`）。本次反汇编其开头：

```
0048D08C  call 0x406F70             ; AudioFrameUpdate（33ms 音频帧更新）
0048D091  mov eax, [0xB45B68]       ; 队列计数
0048D096  test eax,eax
0048D09A  mov eax, [0xB45B5C]
0048D0A7  call dword [edx+8]        ; vtable+8：推进当前影片
0048D0AA  ... 网络/会话模式分支
```

`0x5BF500` 则在 `0x683F4F / 0x684048 / 0x7773CF / 0x777594 / 0x7778E4` 五处调用，同样读 `[0xB45B68]` 后调当前项 `vtable+0xC`（`0x5BF515`）。这证明队列由主循环/会话层持续泵，而 `0x6579E0` 在侧边栏绘制帧里消费其状态并施加世界挂起。

**归类结论**：`0x6579E0` = **渲染/UI 子系统的 `RadarClass` 影片显示状态机**（带音频辅助调用和场景挂起副作用）；不是输入、网络、AI 层。若按任务书给的五类强制单选，归「渲染/影片呈现」最贴近；但必须注明它跨到场景暂停控制。

## 4. 是不是「玩家可见的过场 / 影片 / 简报接管」？

### 4.1 是：玩家可见影片队列（证据闭合）

1. **身份串**：`Radar: Movie done / Next movie / Movie full redrawn` 三条日志，见 §2.2；调试串位于 `.rdata`，函数内以 `push VA` 引用。
2. **画面**：`0x657A84` 与 `0x653100` 多处调 `0x4AED70`（侧边栏/雷达 blit），并写雷达矩形 `+0x120C`；`0x657BE6/0x657C1A` 切换 `+0x14AC` 状态，`0x657BF0` 设 `+0x14FC = 0x19`；`0x657C69` 调 `0x55AF40`（显示刷新）；`0x657C2C / 0x657930` 调 `0x5BF530 / 0x5BF580`（影片音频模式恢复/切换）。这是玩家可见的侧边栏/雷达影片呈现，不是不可见后台计时器。
3. **队列**：`0xB45B5C` 是播放项数组，`0xB45B68` 是计数；`0x657AD8/ADE` 取 `[0]` 当前项，`0x657B67` 播完后移位并 `dec` 计数，`0x657BA4` 打 `"Next movie"`；`0x5BF390` 是入队器（见 §4.2）。队列项的 vtable `+4/+0x14` 分别被用作「初始化/绘制」与「是否播完」、`+4` 字节是 `pause` 旗标。
4. **可脚本触发**：动作 100 `PlayIngameMovie` 与 117 `PlayIngameMovieAndPause` 的内联派发块/从属体都直接调 `0x5BF390`：
   - 动作 100 内联 `0x6DF546..0x6DF54E`：`mov ecx,[esi+0x90]; xor dl,dl; call 0x5BF390`（`pause=0`）；从属 `0x6E1720..0x6E1728` 同式。
   - 动作 117 内联 `0x6DF90E..0x6DF916`：`mov ecx,[esi+0x90]; mov dl,1; call 0x5BF390`（`pause=1`）；从属 `0x6E1740..0x6E1748` 同式。
   - `docs/re/trigger_system_manifest.md:237,254` 分别把 100 / 117 定名为 `PlayIngameMovie` / `PlayIngameMovieAndPause`，从属体为 `0x6E1720 / 0x6E1740`；`YRpp/TActionClass.h:125-126` 给出同名地址。
   - `0x5BF390` 在 `0x5BF3A8` 用 `[0xABF394]`（YRpp `Unsorted.h:408` 的 `DynamicVectorClass<MovieInfo> Movies`）按影片 id 取 `MovieInfo*`，`0x5BF3F4` 把 `dl` 写入播放项 `+4`（pause），`0x5BF43A/43B` 做 `inc [0xB45B68]` 并存入 `[0xB45B5C]` 数组。因此 117 的 `pause=1` 会在下一绘制帧经 `0x6579E0` 触发 `0x684060(0)`；100 的 `pause=0` 不触发挂起。
5. **不是全屏过场链**：动作 10 `PlayMovie` 内联 `0x6DE72F..0x6DE76C` 走 `0x72DDB0 → [0x887640] vtable+0x14 → 0x6842F0 → 0x5BF260 → 0x6842F0 → vtable+0x18 → 0x72DEF0`；从属 `0x6E16D0` 同调用集（`trigger_system_manifest.md:749-762,524`）。`0x5BF260` 在 `0x5BF293` 取 `[0xABF394]` 影片项后调 `0x5BED40`（`0x5BED40` 内 `0x5BEDEC call 0x432690`，仓内 `docs/NEXT_RE_AND_MODERNIZATION.md:51,72` 把 `0x432C70–0x432E39` 定名为 `BinkMovieClass::Play`，逐帧 Blit 到主表面并检测 ESC）。本次普查 `call 0x5BF390` 恰 4 点（100/117 的内联+从属），`call 0x5BF260` 恰 12 点（含动作 10 的 `0x6DE755`、从属 `0x6E16F9`），二者不互相调用：动作 10 不写 `0xB45B68`，故**不直接进 `0x6579E0` 的挂起路径**。
6. **不是简报**：`ScenarioClass::Brief/Briefing` 字段见 `YRpp/ScenarioClass.h:132-142`，但本函数不读这些字段；日志、队列结构和触发动作名都指向 movie，而非 `Briefing` 文本/CSF。仓内 `YRpp/LoadProgressManager.h:47` 的 `LoadBriefing` 也没有在本链出现。故「简报接管」本线无法证实，应写为**不是**简报链。

### 4.2 与任务书提示的「同族」如何精确表述

- **同族（影片呈现 + 暂停世界）**：动作 117 与 `0x6579E0` 是同一条链——117 入队 `pause=1`，`0x6579E0` 读该旗标后 `call 0x684060(0)`；动作 100 是同一显示队列但不暂停。因此任务书里「动作 10 / 117 同族」需要收窄为 **117 直接同链，10 是并行全屏影片族**。
- **不是动作 110 / 127**：`0x6DF703`（110 PauseGame）与 `0x6E4086`（其从属 `0x6E4080`）直接调 `0x684060`，不经 `0xB45B68`；`0x6DFAC5`（127 StartChronoScreenEffect）调渐变启动器 `0x53B460`。领队预检 `:28-33,44-45` 与 `trigger_system_manifest.md:247,264` 已定谳，本线未推翻。
- **「引擎内部、不可控」需修正**：任务书 §1.6 与领队预检 `:53,73` 称此路径「引擎内部对象状态机 / 无脚本入口」。字节证据只支持「`0x6579E0` 本身不是 `TActionClass::Execute` 的派发块且唯一直接调用者是绘制函数」；但动作 100/117 经 `0x5BF390` 写同一全局队列，故在单机局里**脚本可达**（至少 117 可让 `+0x62C` 非零）。是否还存在非脚本入队点：`0x5BF2B0` 是与 `0x5BF390` 几乎同体的另一个入队函数（同样 `inc [0xB45B68]` @`0x5BF341`），但本次直接调用普查中 `call 0x5BF2B0` 为 **0**，且数据段 dword 扫描未发现指向它的函数指针；其入口可能通过间接调用，本线**无法判定**是否有非脚本入队。另 `0x7591B1` 写 `[0xB45B68]=eax`，属队列清理/初始化邻域，未追到运行期触发者，也标未验。

## 5. 六个提示库函数的分层判定

> 任务书 `TASK.md:53-54` 把它们列为「它调用的库函数」；严格说，`0x6579E0` 本体内直接调用的只有 `0x7529E0`，前四个中的三个在紧邻的 `0x6578F0` 雷达影片状态机内被调用，后两个在动作 105 `TalkBubble` 从属体内被调用。下面按「同一雷达影片对象/相关库簇」全部给出分层，并标清实际调用位置。
