## 二、`0xA8EB44 / 0xA8EB50` 是什么（仓内既有记载，已核）

`docs/re/net_sync_checksum.md:261`：

```
for each Building:              // 数组 0xA8EB44 / 计数 0xA8EB50
```

`docs/re/LESSONS_20261003_RE_INSTRUMENTS.md:397`：

> `B_inst` 建筑实例表 `0x00A8EB40/50`（`@PAVBuildingClass@@`）…
> **实例表 `0x00A8EB50` 至今 0 次真机读数**

⇒ `0xA8EB44` = **建筑实例向量（`DynamicVectorClass<BuildingClass*>`）的 Items 指针**，
      `0xA8EB50` = 同向量的 Count。
      **`b_items == 0` = 该向量从未分配过（Items 指针为 NULL），即「这张图从头到尾没有任何建筑实例」。**

### 3.3 ★★ 但这**不是因果**，反例明确

| 反例 | 事实 | 说明 |
|---|---|---|
| `t55k_20261020`（同图 `93c2974b`、842 单位） | `b_items=ZERO` 但 **p50=32.3 满帧** | **无建筑也能满帧** |
| `l3_20261021`（同图 `f3bb0a4e`、1342 单位） | `b_items=set`、`b_max=3–4` 但 **p50=105/73/92** | **有建筑也能慢** |

⇒ **`b_items==0` 既不是「慢」的充分条件，也不是必要条件。**
它的真实价值是**一条干净的分层变量**（把语料劈成两群），而不是原因。

**最可能的正确读法**：`b_items==0` 标记的是「这局**没有建筑参与**」。
而「有无建筑」会改变**战斗形态**（有建筑 → 单位围攻建筑 → 寻路/目标选择路径不同），
进而改变每帧成本。**但这条链条本轮没有证据**，只是最简约的解释，须标 [推演]。
