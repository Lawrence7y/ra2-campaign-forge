# D-20 步骤 B 结论 · 「可见单位数」不存在现成计数 VA

> 依 D-20 定谳（`dwfrun-abf90739`，`magpie/codex/gpt-6.1-sol$medium`，快裁）：
> 「先执行 B：从 `DrawIfVisible 0x5F4B7F` 追踪可视性判定、对象遍历及计数读写，
> 输出地址与指令证据，**区分「现成计数」「需遍历推导」「未定位」三种结果**」。
> **本文给出结论：属第 (ii) 类「需遍历推导」——不存在现成计数。**
> 零真机、零采样实现、只读反汇编。

## 0. 一句话结论

**全镜像找不到任何「可见单位数」的现成计数 VA。**
`DrawIfVisible` 全镜像只有 **3 个调用点**（不是 W3 说的「渲染主簇逐单位调用」），
其中 `0x422C8E` 是一个 3 指令透传包装；判定核心 `IsVisible 0x6D2140` 有 **139 个调用点**，
但**没有任何调用点维护计数器**。

⇒ 按 D-20 出口条件：**记录缺口，转 A**，不为补齐 F6 强行认定某个 VA。

## 1. 证据（我实跑，`_b_visibility_probe.py` / `_b_counter_hunt.py` / `_b_callers_probe.py`）

### 1.1 `DrawIfVisible 0x5F4B10` 的完整控制流

```
005F4B13  a06beda800        mov al,[0xA8ED6B]        ; 全局抑制位
005F4B23  a15035b700        mov eax,[0xB73550]       ; hwnd
005F4B34  8a8680000000      mov al,[esi+0x80]        ; 对象隐藏标志 A
005F4B3E  8a8681000000      mov al,[esi+0x81]        ; 对象隐藏标志 B
005F4B5D  ff92ac000000      call [edx+0xac]          ; 取对象屏幕坐标
005F4B6A  e8d1d50d00        call 0x6D2140            ; IsVisible
005F4B71  7515              jne 0x5F4B88             ; 可见 → 绘制
005F4B7F  32c0              xor al,al                ; ← 早退（可见性判定失败）
005F4B85  c20c00            ret 0xC
```

**注意**：函数**没有第二参数输出、没有写任何全局**。
它的返回值只是一个布尔（`al`）。**它自己不计数，也不给调用方提供计数钩子。**

### 1.2 `DrawIfVisible` 全镜像**只有 3 个调用点**

```
00422C8E    ← 3 指令透传包装（0x422C83..0x422C8E: push edx / push eax / call）
0073B132
00749B5B
```

⇒ **W3 `Q1_C2_RENDER.md` 称「0x6D8DB0 外层遍历 5 个 Layer、内层逐单位调 DrawIfVisible」
与我实测不符**：`0x6D8DB0..0x6DA1FB`（1603 条指令）内
`call 0x5F4B10` **count = 0**。

### 1.3 渲染簇内**零处写全局 dword**

在 `0x6D8DB0..0x6DA1FB` 内扫「`mov [abs], reg` 形式写全局 dword」：
**total global dword writes: 0**。
19 处 `inc/dec` **全是寄存器操作**（`inc eax` / `dec eax` 等），**没有一处落内存**。

⇒ **该簇不维护任何全局可见计数。**

### 1.4 `IsVisible 0x6D2140` 有 139 个调用点，但都不计数

139 个调用点分布在整个引擎里（`0x4146C6`、`0x430289`、`0x436050`…），
**它们各自只取布尔返回值**（典型形态 `call 0x6D2140 / test al,al / jne ...`）。
**没有任何一处在其后跟 `inc [全局]`。**

## 2. 判定：属第 (ii) 类「需遍历推导」

| 类别 | 是否成立 | 依据 |
|---|---|---|
| (i) 存在现成计数 VA | **❌** | 1.3 渲染簇零全局写；1.4 139 个调用点均不计数 |
| **(ii) 需遍历推导** | **✅** | 可见性 = 对每个对象调 `IsVisible` 的**结果**；要得数量必须**自己遍历对象表再逐个判定** |
| (iii) 未定位 | 部分 | 判定函数已定位（`0x6D2140`），但**「可遍历的对象表 + 视口参数」这套组合尚未定成一个可读 VA** |

**若要「遍历推导」，最少需要两个可读量**：
1. **对象表**（哪几个 Layer 容器、Items/Count 在哪）——已部分已知
   （`0x8A0370`/`0x8A03A0` 等，W1/W3 用过）
2. **视口参数**（`IsVisible` 内部比对的矩形边界）——**仍未定位**
   （`0x887308`/`0x88730C` 是 `DSurface` 指针，不是视口，§563 已订正）

⇒ **遍历推导在外部不可行**：即使拿到对象表，也要复现 `IsVisible` 的投影计算
（`0x6D2140` 内部把 3D 坐标做等轴测投影再比对视口裕量），
**这等价于在外部实现一遍渲染判定**，成本与风险都远超「读一个计数器」。

## 3. 按 D-20 出口条件执行

D-20 原文：

> 「**B 的出口**：得到可读量及语义证据即转 A；**若无现成计数或静态链仍不足，
> 记录已追踪范围与 F6 未定位，转 A，不为补齐 F6 强行认定某个 VA**。」

**本步执行**：
- **记录已追踪范围**：`0x5F4B10`（全函数）、`0x6D2140`（头部 + 139 调用点计数）、
  `0x6D8DB0..0x6DA1FB`（1603 条，零 DrawIfVisible 调用、零全局写）；
- **F6（可见单位数）仍标未定位**；
- **不强行指定任何 VA**；
- **转 A**：按 D-19 的帧沿规格，用**现有四 VA + 帧号**做候选件与离线单测。

## 4. 对目标①的意义（诚实表述）

**C2（渲染）这条线，在「不实现外部判定」的前提下，无法用单一计数器代理。**
这**强化**了 D-19 的判断——「四 VA 不足以完全解耦」，
也**削弱**了「用 1 个 VA 代表屏内可见单位数」的想法。

**但 C2 并未被排除**：它仍是理论上的强解释源（§566 已证裁剪跳过整链）。
只是**它无法被只读计数器观测**，除非：
- (a) 采「脏矩形 Count」`0x00B0CE88` 作为**间接代理**（D-19 已采纳，但语义受限）；或
- (b) **遍历对象表 + 复现投影判定**（成本高，本轮判为不可行）。

## 5. 诚实账

1. **我亲验**：`0x5F4B10` 全函数 30 条指令；`call 0x5F4B10` = **3** 处；
   `call 0x6D2140` = **139** 处；`0x6D8DB0..0x6DA1FB` 内 `call 0x5F4B10` = **0**、
   全局 dword 写 = **0**、4 字节 `inc/dec` = 19 处**全为寄存器**。
2. **我未验**：`0x73B132` 与 `0x749B5B` 两个调用点的上下文（只读了 `0x422C8E`）。
   **这不影响结论**（那两处也只是调用点，不是计数点）。
3. **我未验**：`IsVisible 0x6D2140` 的完整投影算法（只读了头部 0x80 字节）。
4. **我未验**：`0x00B0CE88`（脏矩形 Count）与可见单位数的**定量关系**——D-19 已判「未校准」。
