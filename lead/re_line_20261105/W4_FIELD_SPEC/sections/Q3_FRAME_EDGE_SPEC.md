## 0. 一句话结论

把「观测到 `CurrentFrame` 变化时追加读取四 VA」写成一张**可逐项核对**的规格卡：沿用既有 500 Hz
`CurrentFrame` 只读轮询，仅在其读数发生 `df ≥ 1` 变化时，按**固定读序**追加读取四个分散 VA，
每个读数带自己的起止时间戳，并用**帧号前/后读**把这段读序括起来以暴露跨帧污染；
`df>1` 只产**一个**事件并标漏沿/跨帧聚合，不补造逐帧值；读失败记 `null` 不补 0；
新增负担按设计算账为 `20λ B/s、5λ 次跨进程读调用/秒`（`λ` = 每秒触发沿数，名义上限 500 ⇒
`≤10 000 B/s、≤2500 次/秒`）。这是**名义操作数算账，不是耗时、CPU% 或扰动实测**。
**本规格是设计，不是实现；实现须用户明示授权。**

## 3. 触发判据（含 `df>1`）

### 3.1 记号（纯逻辑契约，不是代码）

- 轮询拍：`(t_k, f_k)`。`t_k` = 宿主 `perf_counter` 时刻，**在该拍帧号读之前取**（沿用 `harness8_v4.py:4022`）；
  `f_k` = `0x00A8ED84` 的 32 位读数，或 `null`。
- `f_prev` = 上一次**成功**帧号读的值；`t_prev` = 其对应拍时刻。首拍无前驱 ⇒ `first`。
- `d = f_k − f_prev`：**两个 32 位值按普通整数相减**，此步**不做模 2³² 重解释**。
  （若做模重解释，回绕/重置会被误判成巨大的 `d>1`，必须避免。）
- `n_failed_between` = 自 `f_prev` 以来帧号读失败的拍数（沿用 `:4026-4028` 的失败留痕）。

### 3.2 精确触发条件

> **触发 ⟺ `f_prev ≠ null` 且 `f_k ≠ null` 且 `d ≥ 1`。**
> 每次触发**恰好产出一个样本**（`d=1` 与 `d>1` 都只产一个），不多产、不补产。

### 3.3 判定表（唯一判据，不含任何未声明阈值）

| `d` / 状态 | 类别 | 是否触发四字段读序 | 记录动作 | 依据 |
|---|---|---|---|---|
| 无 `f_prev`（首拍） | `first` / 基线 | 否 | 建基线，不污染 `unjudgeable` 计数 | `RULING_D19.md:59`；`A1_OFFLINE_DELIVERABLE.md:51`（只读核对，不作为规范） |
| `f_k = null` | `read_failed` | 否 | 该拍记 `null`、失败计数 +1；**不计入冻结持续**、不当作 `d=0`、不产边沿 | `harness8_v4.py:4026-4028,4043-4045`；`RULING_D19.md:59` |
| `d = 0` | `same_frame`（帧号冻结） | 否 | 累计**帧号**冻结持续时段（从该值段起点到值变化时刻，口径同 `max_stall_s`，`harness8_v4.py:4742-4743,4781-4783`）；**不宣称业务字段冻结** | `TASK.md:31-33`；`FACTBASE_D19.md:32` |

### 3.4 对 W3「83 次完全重复 / 信息熵增益严格为 0」前提的处理

本规格**不采用**该前提。`FACTBASE_D19.md:32` 记录 `0x42CC80` 在同步重试时再次推进代际戳，
`TASK.md:31-33` 判 W3 `Q3_SAMPLE_PLAN.md:209-211` 的「帧号区间内业务字段完全冻结」已被破坏。
因此：本规格**只在帧沿追加读**是为了控制新增负担，**不是**因为「非沿拍必无信息」；
本规格同时**不宣称**帧沿档已充分、不宣称 500 Hz 必要或最优（`RULING_D19.md:41,100`）。

### 3.5 观测延迟与逻辑帧对应边界（必须写进记录）

- `t_k` 是**首次观测**时刻，且是在帧号读**之前**取的 ⇒ 它是观测的上界锚，不是 CPU 事件的微秒真值
  （`RULING_D19.md:68,101`；`harness8_v4.py:4022-4025`）。
- `CurrentFrame` 在帧尾自增写回（`FACTBASE_D19.md:32`）⇒ 「观测到 `f` 变化」相对真实帧推进有最多约一个
  轮询间隔的宿主侧发现延迟；**名义 2 ms，实达未验**（`:5169`；`RULING_D19.md:27`）。
- ⇒ 四字段读数**不能**称为「帧末真值」「单帧精确快照」或「微秒级回归」输入；
  `Q3_SAMPLE_PLAN.md:238` 的「微秒级回归分析」不被本规格继承。

## 4. 非原子性披露（★ 强制）

**四地址不连续，16 字节是总载荷，不是一次连续读。**

| 地址（升序） | 字段 | 到下一地址的间隔 |
|---|---|---|
| `0x0087E8E0` | 工作区代际「尝试」代理 | → `0x00A8EC34`：**2 163 540 B = `0x210354`** |
| `0x00A8EC34` | 索敌入口调用累计代理 | → `0x00A8ED50`：**284 B = `0x11C`** |
| `0x00A8ED50` | 注册 Bullet 对象向量 Count | → `0x00A8ED84`（帧号，**非四字段之一**）：**52 B = `0x34`** |
| `0x00A8ED84` | `CurrentFrame`（既有帧号 VA） | → `0x00B0CE88`：**516 356 B = `0x7E104`** |
| `0x00B0CE88` | 脏矩形向量当前 Count | — |

- 四 VA 来源：`TASK.md:23-26`；帧号 VA：`harness8_v4.py:3831`。
- 四 VA 最小–最大跨度 **`2 680 232 B = 0x28E5A8`**；四个 4 字节字段合计 **16 B 总载荷**，
  但至少需要 **4 次独立的 4 字节读**。上述间隔与跨度由本次实跑算术核对，见 §9 命令②。
- 因此 `Q3_SAMPLE_PLAN.md:236` 的「单次 16 字节连读快照」**在只读、非挂起、非注入约束下不可实现**：
  不存在覆盖这四个地址的单一连续区间；`FACTBASE_D19.md:71` 明写「四VA分散于不同位置，引用中的
  『16字节连读』不能被当成单次连续地址读取已可实现的证明」；`RULING_D19.md:58,101` 明令
  「四VA不连续，不能称一个原子16字节快照」「四个分散VA不是原子快照」。
- **即使**每个 4 字节读自身可视为对齐 32 位访问，目标进程**未被挂起也不得被挂起**
  （`RULING_D17_D18.md:78`；`TASK.md:100-103`），因此四次读可能落在不同逻辑帧、甚至跨越渲染前/后相位。
  `card_00B0CE88.md:122` 明记「`Render` 绘制完成后逐条弹空，读到的值强依赖采样时刻落在渲染前/后」。
- ⇒ 本规格的样本是**带各自时间戳的四个分散读数 + 一个帧号括弧**，**不是**某一时刻的一致切面；
  一切「同一帧、同一时刻、原子快照」的表述禁止出现在记录与分析产物中。
- 单字段 4 字节读也不等于「业务语义原子」：`card_0087E8E0.md:239-240` 记回绕那次代际戳
  「清工作区 + 两次自增跳 0 到 1」，读值可能落在中间态；本规格不对此作中间态推断。

## 5. 四字段读序、时间戳与理由（★ 强制）

### 5.1 固定读序（逻辑步骤，非代码；顺序固定、不得运行期重排）

| 步 | 逻辑操作 | 地址 | 载荷 | 时间戳 | 是否新增跨进程读 |
|---|---|---|---|---|---|
| `S0` | 帧号**前读**，复用该拍既有轮询读数 `f_pre` | `0x00A8ED84` | 4 B | `t_0_start`（既有，读前取）；读完成时刻由 `S1` 的 `t_1_start` 给出上界 | **否（复用）** |
| `S1` | 读 `gen_stamp` | `0x0087E8E0` | 4 B | `t_1_start` / `t_1_end` | 是 |
| `S2` | 读 `threat_calls` | `0x00A8EC34` | 4 B | `t_2_start` / `t_2_end` | 是 |
| `S3` | 读 `dirty_rect_count` | `0x00B0CE88` | 4 B | `t_3_start` / `t_3_end` | 是 |
| `S4` | 读 `bullet_count` | `0x00A8ED50` | 4 B | `t_4_start` / `t_4_end` | 是 |
| `S5` | 帧号**后读** `f_post`（**附加帧号校验读，单列成本**） | `0x00A8ED84` | 4 B | `t_5_start` / `t_5_end` | 是（**附加读**） |

- 读段整体边界 `T_seg_start = t_1_start`、`T_seg_end = t_5_end` 另记，供「每字段或读段起止时间戳」
  逐项核对（`RULING_D19.md:59`）。
- 每个 `S1..S5` 的值是「32 位读数」或 `null`；六组时刻用宿主单调时钟，统一单位与零点（同现有
  `time.perf_counter`，`harness8_v4.py:4009-4010,5321`）。宿主时钟读取**不是**对目标进程的跨进程读调用，
  不计入 §8 的「系统调用次数」口径，但计入未量化负担（§8.5）。
- 记录中必须原样落 **读序标识**（如 `S0,S1,S2,S3,S4,S5`）与字段→地址映射，使下游可机械核对顺序；
  **重排即作废该记录**。

### 5.2 为什么是这个顺序（逐条理由）

1. **固定且可核对**：D-19 要求「在观测卡写定读序」(`RULING_D19.md:59`)。任一重排都会改变
   `t_i` 与字段的对应关系，从而改变跨帧归属与相位解释；故顺序写死、随记录落盘、不得自适应调整。
   字段顺序取 `TASK.md:23-26` 的四 VA 列举顺序，便于与四张规格卡逐项对齐，不引入新口径。
2. **`S0` 复用而非另读**：既有轮询每拍已经在 `harness8_v4.py:4025` 读一次帧号并留下 `t_now`
   (`:4022`)。把它当作 `f_pre` 可省一次跨进程读，**且**让四字段读序紧贴该拍的帧号观测，
   缩短「帧号观测 → 业务读数」的间隔。代价是既有拍只提供**读前**时间戳：因此本规格明确
   `f_pre` 的取值时刻只能界定在 `(t_0_start, t_1_start)` 内，不得宣称精确取数时刻（§3.5）。
3. **两个「差分型」字段在前（`S1,S2`）**：它们的分析量是相邻沿之间的**差分**
   （代际尝试代理、索敌入口累计代理，`TASK.md:23-24`）。把它们尽量靠近 `f_pre` 锚点，可减小
   下一次帧推进的业务写混入本次差分的机会。特别地**不能**假设「同一帧号区间内它们冻结」——
   `FACTBASE_D19.md:32`、`TASK.md:31-33` 已反证该前提。
4. **两个「瞬时水位型」字段在后（`S3,S4`）**：脏矩形 Count、注册 Bullet Count 是**瞬时队列/容器长度**，
   不是积分量（`RULING_D19.md:23-24`）。它们只在各自 `t_i` 上有意义，绝不换算成「每帧次数」；
   固定槽位至少让跨沿的采样相位可复现，**但无法消除相位依赖**：`card_00B0CE88.md:122` 记录 `Render`
   尾部弹空，故 `S3` 值强依赖落在渲染前/后；这一限制必须随记录披露，不得靠排序修复。
5. **`S5` 帧号后读最后**：用一个独立的帧号读**括住**整段读序，是唯一能在「不挂起目标进程」前提下
   暴露「读序期间又推进了帧」的手段（§6）。置于最后使括弧覆盖 `S1..S4` 全部四次读。
   **不采用**「每个字段前后各读一次帧号」：那会把跨进程读调用从 5 次/沿提高到 ≥9 次/沿，
   且仍无法保证四个分散地址的一致性（§4），收益不抵负担。
6. **不采用合并/批量读**：四地址跨度 `0x28E5A8` B（§4），任何「一次连续读 16 B」既覆盖不到，
   也会把 §4 的非原子性伪装成原子快照。

### 5.3 四字段的语义边界（随记录带入，禁止越界解释）

| 字段 | 能说 | 不能说 |
|---|---|---|
| `gen_stamp` | 搜索入口/同步重试/回绕各推进了几次代际 | 实际展开节点数、搜索成功次数、单次耗时（`TASK.md:23`；`card_0087E8E0.md:239-242`） |
| `threat_calls` | 索敌入口被调用了几次 | 每次扫描工作量、扫描单元数、索敌耗时（`TASK.md:24`；`RULING_D19.md:22`） |
| `dirty_rect_count` | 当前脏矩形队列里有几条 | 屏内可见单位数、每帧绘制调用数、渲染耗时；少量/零 Count 不自动排除渲染（`RULING_D19.md:23`；`card_00B0CE88.md:210`） |
| `bullet_count` | 注册表里有几个 Bullet 对象 | 本帧实际活跃更新数（更新另受对象 `+0x98` 一字节活跃标志门控）、动画/伤害总成本（`RULING_D19.md:24`；`card_00A8ED50.md:12,139-141`） |

## 6. 读失败记 `null`（不补 0）与跨帧归属处理

### 6.1 读失败

- 契约参照：`_rpm_u32` 失败返回 `None`（`harness8_v4.py:3929,3942-3944`）；`_rpm_counters` 「任一项读失败
  ⇒ 该项 `null`（不写 0）」(`:3984`)；`_rpm_mem_kb` 「不可测写 `null` 不写 0」(`:3963`)；
  裁决 `RULING_D19.md:59`、`RULING_D17_D18.md:71`。
- **逐字段独立**：`S1..S5` 任一失败只把**该字段**记为 `null`，其余字段照常保留；
  **不重试**（重试会改变时序并增加负担）、不补 0、不前向填充、不插值、不用旧值顶替、不丢弃整条记录。
- **帧号读失败**：`f_pre = null` ⇒ 该拍按 §3.3 记 `read_failed`，不触发、不产样本、不计冻结；
  `f_post = null` ⇒ `cross_frame = null`（**未知，不是 `false`**），该样本保留但其归属标「不可验证」。
- **差分计算**：任一端为 `null` ⇒ 该差分记 `null`/不可判，不得按 0 处理；跨 `null` 区间不做累计。
- 记录格式须能区分 `null` 与数值 `0`（例如 JSON `null`），并在汇总中单列 `n_read_fail_total`
  与各字段失败计数；失败率本身是**待验的运行期指征**，不是本规格可调的阈值。

### 6.2 跨帧归属

| 括弧结果（`f_post − f_pre`，普通整数差） | 归属处理 |
|---|---|
| `= 0` | `cross_frame = false`；四字段归属「帧号 `f_pre` 的观测区间 `[t_0_start, t_5_end]`」。**但仍禁止称其为单帧一致快照**：同一帧号 ≠ 同一时刻，`CurrentFrame` 在帧尾自增（`FACTBASE_D19.md:32`），且同帧号区间内业务字段可推进（`TASK.md:31-33`）；两次读仍落在读段内不同墙钟时刻。 |
| `> 0`（记 `m`） | `cross_frame = true`；归属改为**跨帧区间 `[f_pre, f_post]`、跨越 `m` 次帧推进**，**不硬认某一帧**；该样本禁止用于单帧相平面/单帧回归。`m>1` 时追加 `aggregate_within_bracket`，`missed_frames_lower_bound += (m−1)`。 |
| `< 0` | `unjudgeable`：重置 / 帧号回绕 / 进程重启不可区分，整条标不可判，不算差分。 |
| `f_post = null` | `cross_frame = null`（未知），归属标「不可验证」，不猜 `false`。 |

- **触发层 `df>1` 与括弧层 `m>1` 是两种不同漏沿**，各自计数、不得合并：前者是两次轮询之间漏掉的帧沿，
  后者是四次分散读期间又推进的帧。
- **不补造逐帧值**：`df>1` 只产一个样本并标 `aggregate_over_N_frames`；既不按 `dt/df` 平均拆分，
  也不生成中间帧的假观测（`RULING_D19.md:59`；`harness8_v4.py:4738-4740,4792-4802` 明禁 `dt/df` 式）。
- **帧号冻结**：`d=0` 连续段只累计**帧号**冻结持续时段，记录须带明文注记「不得据此宣称业务字段冻结」
  （`RULING_D19.md:59`；`FACTBASE_D19.md:32`；`TASK.md:31-33`）。
- **字段自身的回绕/重置/生命周期**（差分分析的必要条件，逐字段适用）：
  - `gen_stamp` 回绕那次 `Δ=2`（从 `0xFFFFFFFF` 跳到 `1`，跳过 0），不是 1；构造初值 `0xFFFFFFFF`；
    按字节链首次调用即走回绕分支（`card_0087E8E0.md:239-242`）。
  - `threat_calls` 为纯模 2³² 回绕；进程重启的向下跳变**不是**回绕；读档恢复未验（`card_00A8EC34.md:150-154,206-210`）。
  - `dirty_rect_count`、`bullet_count` 的**下降是正常语义**（渲染尾部弹空 / 对象出队），
    **不得**把下降当作异常或回绕；相应路径 `card_00B0CE88.md:121-123`、`card_00A8ED50.md:126`。
  - 凡「重置 / 回绕 / 进程生命周期变化不能判明」的区间一律 `unjudgeable`，跨该区间不做差分
    （`RULING_D19.md:59`；`RULING_D17_D18.md:70`）。
- **不得用旧 measure 验证新增字段真值**：`RULING_D17_D18.md:62`、`RULING_D19.md:57`。

## 8. 新增负担量化（只算账，不实现）

### 8.1 口径（先限定，避免把「算账」说成「实测」）
