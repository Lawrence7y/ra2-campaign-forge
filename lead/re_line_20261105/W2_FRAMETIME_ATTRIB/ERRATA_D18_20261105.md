## 一、必须撤回的三类表述

### 1. 「Dijkstra 2000 节点」——**撤回**

W2 定稿在下列位置使用该数字：`:37`（一句话结论）、`:217`（候选 C1 行）、`:232-237`（机制依据与耗时推演）。
**该数字对已核目标与指定调用路径不成立**（技术事实见下文第二节）。
`:233` 的「硬编码 2000」、`:237` 把「单次展开 2000」与「0.5~1.5 ms」串接的推演，**一并撤回**。

### 2. 「`0x887308 / 0x88730C` = 视口左上角 X/Y 坐标」——**撤回**

W2 定稿 `:305`（及 §4.2 第 1 项）把这两个全局当作视口坐标。
**实为 `DSurface` 对象指针槽**（vtable `0x007E85D4`，RTTI `.?AVDSurface@@`）。
⇒ 「视口不可判」的**结论仍成立**，但**理由须改写**：
不是「未采 `0x887308/0x88730C`」，而是「**尚未定位视口坐标的真实 VA，且测量窗内零截图**」。

### 3. 「`GenerationStamp` = 实际 Dijkstra 展开次数」——**降级**

W2 定稿 `:316` 隐含此读法。**须降级为**：
`0x0087E8E0`（=`0x0087E8B8+0x28`）是**搜索入口 / 工作区代际的尝试计数**，
**回绕时会清零并跳过 0**，且**入口递增早于可能失败的检查**
⇒ **不能等同于实际展开次数，更不能换算成 CPU 耗时**。

## 二、技术事实（D-18 认定的、可引用的版本）

对 `gamemd.exe`（SHA256 `73201cc021497c9567742f718bf1dc78c22e9ae16c7e7365354b65f3fcf67476`）
的**已核目标与指定调用路径**：

```
0x4D3E3B   68 D0 07 00 00        push 0x7D0            ; 调用方压第三参数 = 2000
0x4CBC1C   6A FF                  push -1               ; 包装层【未转发】2000，改传 -1
0x4CBC1E   6A FF                  push -1               ; （第五参数位置）
0x42CBFB   52                     push edx              ; FindPath 把第五参数透传给 SearchCore
0x42CC02   E8 …                   call 0x429A90
0x429D51   8B 44 24 70            mov eax,[esp+0x70]    ; = -1
0x429D57   7D 08                  jge 0x429D61          ; 非负则保留
0x429D59   C7 44 24 70 F7 FF 00 00  mov dword [esp+0x70],0xFFF7   ; 负值→65527
```

**正确表述（可直接引用）**：

> 对上述指定路径，`SearchCore` 的单次**节点处理/展开轮数上限**为 `0xFFF7` = 65527
> （负预算缺省值）；**非负传入预算原样保留**。

**不得由此推出的**（D-18 明确列为「不支持」）：
- ❌ 所有调用路径统一为 65527
- ❌ 每次搜索**都会用满** 65527
- ❌ 65527 = 「最多能碰的不同格子数」
- ❌ 65527 = 整次 `FindPath` 的总工作量
- ❌ **按 32.76 倍线性推算帧时**（搜索可提前终止：到目标 / 开放集耗尽 / 其他早退）

## 三、`+0x3C` 字段名的更正

`docs/re/pathfinding_deep_dive.md:74` 把 `+0x3C` 名为 `MaxNodeBudget`（称由外层传入 2000）。
核证：`0x42C92F mov [ebp+0x3C],ecx` 存的是 `FindPath` 的**第七参数**，
**实际预算走第五参数**，`+0x3C` **不是预算槽**；其完整语义**待补**。
（该更正由 RE-ATLAS 在 `docs/re/` 落实；本线只在此登记。）
