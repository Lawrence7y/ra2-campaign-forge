# §350 29 处 `call [reg+0xA8]` 的对象来源分档

**轮次**：§350　**心跳**：2026-10-22 08:17:48　**性质**：只读离线，零真机

---

## 0. 一句话结论

**静态上找不到任何一处直接拿雷达本体当 `reg`。** MATCH = 0。

分档结果：**MATCH=0，GLOBAL-ONLY=5，UNKNOWN=24**。

最重要的一条：**这个 MATCH=0 不是"没人触发 v[42]"，而是"这条路根本不走 `call [reg+0xA8]`"**——因为 `RadarClass::One_Time()` 在**自己函数体内**用 `mov ecx, esi` 透传 this 调 `v[42]`（§346 已证），那是一次 `call [eax+0xA8]` 站点，但它就在 `0x4A88AA`，本来就属这一批。所以雷达触发 v[42] 是**内部行为，不产生新站点**。

真正的收获是 **GLOBAL-ONLY 那 5 处**，其中两处在 `Scenario.CPP` 的显示模式切换路径上，带 null 守卫。

---

## 1. 先分清两个全局（这是本轮最容易混的地方）

我一开始以为 `[0xA8B23C]` 可能是雷达。**不是。**

| 全局 | 性质 | 证据 |
|---|---|---|
| `0x87F7E8` | **对象本体** | `.data` BSS（`rsize` 止于 `0x87E000`），文件里无内容。§347 已证全文件只有 1 个写点 `0x40D1B2` 写 vtable |
| `0xA8B23C` | **指针变量** | `.data` BSS，文件里无内容。**10 个写点 / 164 个读点** |

判据：`[0xA8B23C]` 的 10 个写点里，**没有任何一处**把 `0x87F7E8` 写进去（已断言）。它的写点源来自别的对象（例如 `0x5E5447` 处 `ebp` 从 `0x5D5F30` 的返回值来）。

**所以 `[0xA8B23C]` 是一个"当前活动对象"指针，指向什么取决于运行时，不是雷达。**

## 3. 值得注意的发现：`0x68589C` / `0x685FE6` 有 null 守卫

这两处在 `Scenario.CPP`（`0x685856` 附近有 `D:\ra2mdpost\Scenario.CPP` 字符串和 `Toggle display mode back to shell res`），形态是：

```asm
0x00685890  mov ecx, [0xA8B23C]    ; 取当前活动对象
0x00685896  cmp ecx, esi           ; ← 判空（esi 此时为 0）
0x00685898  je 0x6858AA            ; ← 空则跳过
0x0068589A  mov edx, [ecx]         ; 取 vtable
0x0068589C  call [edx + 0xA8]      ; slot42 = 0x4A8960
```

**这与 §346 找到的 28 个无守卫站点形成鲜明对比。** 引擎自己在调 `v[42]` 前是判空的——只有那 28 个粗心的地方没判。

而且 `slot42 = 0x4A8960` 正是"视口尺寸变更 + 缓冲重建"，显示模式切换时调它完全合理。

**这是 §349 要找的"别的时机"的有力候选**：显示模式切换 → 对当前场景对象调 slot42 → 进 `0x4A8960`。

## 4. 一个必须说清的边界

MATCH=0 看起来像"排除了雷达"，但它**不能**推出"没有雷达路径"。原因：

`RadarClass::One_Time()` 调 `v[42]` 的方式是**自己内部** `mov ecx,esi` → `call [eax+0xA8]`。那个站点就是 `0x4A88AA`，在 29 处之内。它的 `reg` 是 `eax <- [esi]`，`esi` 是这一个函数的 `this`。

**所以"雷达触发 v[42]"这个行为本身不产生独立的入口站点** —— 它就在 `0x652CF0` 内部，是 §346 链的第一跳。

真正的复现问题因此变成：**`0x4A8960` 被调用的其他时机有哪些**，而 `0x68589C` / `0x685FE6` 是目前找到的、有守卫的、语义吻合的候选。

## 5. 本轮最大的技术教训：切片器必须追 vtable 那一层

**首版切片器把 29 站全部判为 UNKNOWN。** 原因：

`call [reg+0xA8]` 里的 `reg` 通常是 **vtable 指针**，不是对象：

```asm
0x00685890  mov ecx, [0xA8B23C]    ; ecx = 对象
0x0068589A  mov edx, [ecx]         ; edx = vtable ← 站点用的是这个
0x0068589C  call [edx + 0xA8]
```

我的首版只看 `reg`（= `edx`）的直接定义，看到 `edx <- [ecx]` 就停了，没有继续追 `ecx`。于是全部 UNKNOWN。

**修正后**：`trace_reg` 遇到 `reg <- [base]`（disp==0）时继续追 `base`。这样才追到 `ecx <- [0xA8B23C]`，得出 GLOBAL-ONLY。

这条修正写成了断言：`UNKNOWN 不再是 29`。负控 N-4 把 `trace_reg` 短路回旧行为，该断言立刻转红。
