# §347 0x652CF0 的前置条件：对象身份解谜（单例被构造两次）

**轮次**：§347　**心跳**：2026-10-22 07:51:35　**性质**：只读离线，零真机

---

## 0. 一句话结论

`0x652CF0`（§346 链的起点）**就是全局单例 `0x87F7E8` 对象的虚表 slot 5**。这个对象在启动时被**构造两次**：先写表 A 的 vtable `0x7E1964`，随后被构造器改写为表 B 的 `0x7F0344`。运行时它是**表 B 对象**，所以 slot 5 = `0x652CF0` 恒成立，`except.txt` 里的 `Edi=0x87F7E8` 完全自洽。

**这把 §346 遗留的「前置条件」问题从"对象可能不存在"改判为"对象几乎总存在"**，也把复现判据从"对象是否存活"精确到"清零之后是否仍跑到这条链"。

---

## 1. 起点：`0x652CF0` 没有 E8 调用者

| 项 | 值 |
|---|---|
| E8 直接调用者 | **0 处** |
| 作为 dword 在 `.rdata` 出现 | **1 处**：`0x7F0358` |
| 所在 vtable 表头 | `0x7F0344` |
| 槽号 | **slot[5]** |

它只能经虚表调用，没有别的入口。这一步把"谁调用它"收敛成"谁在它身上触发 slot 5"。

---

## 2. 发现：同表前一槽是构造器

`0x7F0354`（slot 4）= `0x6587A0`，其函数体是：

```asm
0x006587A0  push ebx / push ebp / push esi / push edi
0x006587A4  mov edi, ecx
0x006587A6  lea ecx, [edi + 0x14c0]
0x006587AC  mov [edi], 0x7F0344      ← 写 vtable
0x006587B2  call 0x405C00
0x006587B9  call 0x655A90
```

标准 C++ 构造器骨架。对象尺寸下界 ≥ `0x14C0`。

---

## 3. 关键结构：两张 vtable 是同基类的两个派生类

| 项 | 表 A `0x7E1964` | 表 B `0x7F0344` |
|---|---|---|
| 长度 | 55 槽 | 54 槽 |
| slot[0] | `0x4F4240` | `0x4F4240`（同） |
| slot[42] | `0x4A8960` | `0x4A8960`（同） |
| slot[4] | `0x40D290` | `0x6587A0` |
| **slot[5]** | **`0x5BDF30`** | **`0x652CF0`** |
| slot[34] | `0x6ABD30` | `0x654320` |

**21 个槽覆盖不同**：4, 5, 7, 8, 10, 16, 18, 19, 20, 21, 26, 30, 31, 33, 34, 35, 40, 44, 49, 50, 53。

`slot[0]` 与 `slot[42]` 相同、覆盖槽不碰这两格，是完全自洽的继承布局。**这是同一基类的两个派生类 vtable**，不是两张无关的表。

一个重要后果：`0x4A8960`（崩溃链 L3）在**两张表里都是 slot 42**，所以无论对象是哪个派生类，`call [eax+0xA8]` 都会落到同一个函数。这解释了为什么这条链在两种对象上都成立。

## 4. 决定性：`0x87F7E8` 被构造两次

全局初始化函数 `0x40D1B0` 的完整序列：

```asm
0x0040D1B0  push esi / push edi
0x0040D1B2  mov [0x87F7E8], 0x7E1964    ← 先设表 A
0x0040D1BC  mov [0x884D00], 0x7E195C
0x0040D1C6  mov esi, 0x884B84
0x0040D1CB  mov edi, 4                  ← 循环 4 次
0x0040D1D0  sub esi, 0xF94
0x0040D1E3  call 0x40AFD0               （分配）
0x0040D1EA  call 0x40D300               （子对象初始化）
0x0040D1F0  jne 0x40D1D0
0x0040D1F2  mov ecx, 0x87F7E8           ← ★ this = 单例
0x0040D1F7  call 0x652C00               ← ★ 表 B 构造器
0x0040D1FE  ret
```

而 `0x652C00`（表 B 的另一个构造点，6 个调用者）内部：

```asm
0x00652C00  push ebx / push ebp / push esi / push edi
0x00652C04  mov edi, ecx                ← edi = this = 0x87F7E8
0x00652C06  lea ecx, [edi + 0x14C0]
0x00652C0C  mov [edi], 0x7F0344         ← ★ 把 vtable 改写成表 B
0x00652C12  call 0x405C00
0x00652C19  call 0x655A90
0x00652C1E  lea esi, [edi + 0x1488]
0x00652C24  mov ebp, 0x16               ← 0x16 = 22 个 0x18 大小子对象
...（析构循环）
```

**结论：`[0x87F7E8]` 的运行时 vtable 是 `0x7F0344`（表 B），不是 `0x7E1964`。** 表 A 的写入是构造过程中的临时状态。

这三处事实相互印证：
1. `0x40D1F2 mov ecx, 0x87F7E8` 后紧接 `call 0x652C00`；
2. `0x652C00` 内 `mov edi, ecx` → `mov [edi], 0x7F0344`；
3. `except.txt` 的 `Edi=0x87F7E8` 与"跑的是 `0x652CF0`"因此不矛盾。

## 5. 顺带解开：`0x6ABD30` 为何在链上却没有 E8 调用者

`0x4A8960` 内有：

```asm
0x004A8B0E  mov ecx, 0x87F7E8
0x004A8B13  call 0x6ABD30        ← 直接 E8 调用
```

`0x6ABD30` 在表 A 是 slot[34]，**在表 B 没有槽位**。所以这处只能是直接调用，不可能经虚表——已断言确认。

这也反向证明：`0x4A8960` 里对 `0x87F7E8` 的使用是"以单例为 this 直接调子函数"，而不是"读 vtable 派发"。

## 6. 构造点过滤：数据区里的假命中

`0x7F0344` 在 `.text` 内作为立即数出现 4 处，但需双重过滤（指令形态 + 所在函数被调用过）：

| 引用点 | 指令 | 函数 | 调用者 | 判定 |
|---|---|---|---|---|
| `0x652B47` | `mov [esi], 0x7F0344` | `0x652960` | 1 | 有效 |
| `0x652C0E` | `mov [edi], 0x7F0344` | `0x652C00` | 6 | **有效（全局初始化调用）** |
| `0x6587AE` | `mov [edi], 0x7F0344` | `0x6587A0` | **0** | 经虚表 slot4 调用 |
| `0x6A4F7A` | `mov [edi], 0x7F0344` | `0x6A4F20` | 1 | 有效 |

`0x6587A0` 没有 E8 调用者，但它是**表 B 的 slot[4]**（已断言），走虚表调用。它与 `0x652C00` 前 0x60 字节相似度 **90.6%**，是同构两版。

## 7. 对复现策略的修正（本轮最重要产出）

§346 我写"反复关窗才是靶"，但当时的隐含前提是"对象得活着才有这条路"。**本轮把这个前提推翻了**：

| 旧表述 | 新事实 |
|---|---|
| 需要一个活动对象 | 对象是**全局单例**，启动时构造，整局存活 |
| 关窗时对象可能已析构 | 它不析构（全局对象，`0x40D1B0` 无对应 destroy 遍全局） |
| 复现判据 = 对象存活 | **复现判据 = 清零后是否仍跑到这条链** |

所以 18% 非随机性的真正来源收窄了：**不是对象状态，是关窗分支的选择**。要么走到这条链（崩），要么没走到（不崩）。

这也让修复方案更清晰：
- **最小修复**：在 `0x654413` 前加 null 守卫（`test ecx,ecx / je`），一处 6 字节。
- **等价修复**：把钱上移到 `0x6403A3` 或 `0x4A8B13` 之前（但那两处守卫本来就有，只是位置在调用之后——把它们前移也成立）。

### 本轮踩的坑

1. **`MOV` 立即数地址 vs 指令地址**：`C7 07 <imm32>` 的立即数从指令 **+2** 开始。我拿指令地址 `0x6587AC` 去比引用点 `0x6587AE`，恒不命中。
2. **猜表长**：写死"恰有 43 槽，slot42 是末槽"，实测 A=55/B=54。表长是数据，不能猜。
3. **"两表等长"是错判据**：派生类可以追加自己的槽。正确判据是"长度接近 + 共性槽一致 + 存在覆盖槽"。
4. **"有效构造器"要两条判据**：指令形态正确 **且** 所在函数被调用过。`0x6587A0` 形态对但 E8 调用者为 0——它走虚表，所以判据要补"是否在虚表里"这条分支。
5. **数据区假命中**：`0x652B00` 区整段是数据，从任意偏移都能"解出"看似合法的 `mov [esi],0x7F0344`。必须用函数调用图过滤。
