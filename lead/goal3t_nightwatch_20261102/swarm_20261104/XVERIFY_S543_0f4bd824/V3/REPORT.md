按「能在本仓离线做 / 必须真机」分层。三条都写成可判别的二元形式，且各自能独立否证 S543。

**T1（离线）：结算屏签名不得出现在「本局还没打」的更早阶段截图里。** 已跑，未构成反例。
判据：对每个「窗末命中结算屏签名」的趟，查其 `frame_target_01.png`/`navsig_*` 是否同签名；
若某趟**开局阶段**图也是结算屏，则该屏不可能是「本局打完」的结果 ⇒ S543 对该窗归因错。
我确实跑出了危险信号（`archive_T35/frame_target_01.png`、`archive_T37/frame_target_01.png`、
`archive_T37/navsig_nav_start_pre_00_x.png`、`archive_T37..T49/navsig_burst_04_x.png`
都命中结算屏签名，而 T35/T37 是**无冻结窗**的趟），**但两条都排除了**：
(a) `navsig_burst_04_x.png` 全仓只有 2 个字节值铺在 13 个目录，且**组内 mtime 全同**
（`6ed7766a` 跨 11 趟全为 10-18 12:57:14）⇒ 复制残留，不是 11 次独立采集（§9 A 类）；
(b) `archive_T35`/`archive_T37` 的 `frame_target_01.png` 虽各自独立拍（mtime 互异）且解出 `00:00:16`，
但**这两趟目录内没有任何 `measure_w*.json`**（我实查：`measure json = 无`）⇒ 与 29 窗无关。
⇒ **T1 存活不过**，方向未被推翻。反过来 T1 还挖出一个 S543 没说的更强事实：
`l1_20261023` 的结算屏出现在**测窗之前**（§0.1 表），即「测窗一开始就已经是结算态」。

**T2（真机，一条即可判死）：在 df==0 窗内读 `0xA8E9A0 (InGame)` 一次。**
S543 说那些窗是「对局已结束」⇒ 期望 `InGame==0`；
若实测 `InGame==1` 而 `0xA8ED84` 恒等、且 `0xAA0430` 泵计数仍在涨 ⇒ 局还没结束，
窗就在那里不推进 ⇒ **S543 错，回到引擎停摆**。这条正是 BATCH1 判别表 P-B/P-C 已有的 VA，
零新工具成本。

**T3（真机，判「结束」还是「卡住」的黄金判据）：在停推窗内送一次输入，看屏是否响应。**
结算屏对鼠标点击有确定反应（翻页 / 返回 / 退出，屏会变）；引擎停摆时屏不会变。
采点方式：停推窗内先拍一张、`PostMessage` 一次点击/回车、再拍一张。
判据：两张有差 ⇒ 结算屏（S543 对）；两张逐像素相同且 `InGame==1` ⇒ 停摆（S543 错）。
（注意与 §539 的「采样通道正常」不冲突——采样通道是外部 rpm，不是游戏内响应。）

**T4（离线，专门打「时间=帧/常数」这条）：把屏显时间与 `ScenarioClass+0x614 (ElapsedTimer)`
的历史读数对账。** 若屏显时间随真实秒走而与帧号脱钩（我已证 940→32 与 945→31 违反单调），
则时间字段不能用来做「帧号换算」的自洽验证——S543 的证据 1 整段应删；
但「结算屏在场」这一判据仍由 T2/T3 承担。

## 9. 出处有效性：哪些图能用、哪些不能用（S543 与 §538/§539 都没做这道对账）

我把「跨趟同字节」按 **mtime 是否也相同** 分成两类，结论比「目录被复用」精确得多：

**A 类 = 复制残留（不能用）**：`navsig_burst_04_x.png` 全仓只有 2 个字节值，却铺在 13 个目录里，
且**每个字节值组内 mtime 全同**：

```
sha=f61c9808  跨 2 趟  mtime 全同 10-18 12:27:33
sha=6ed7766a  跨 11 趟 mtime 全同 10-18 12:57:14
```
⇒ 这些不是「11 次采集到同一画面」，而是**同一份文件被铺进 11 个目录**
（inode 各异、st_nlink=1 ⇒ 是复制件，不是硬链接；mtime 全同 ⇒ 复制时保留了源时间戳）。
**这正好解释了 §8-T1 的疑点**：我先前看到「结算屏签名出现在 navsig_burst_04」，
那**不是**「开局前就有结算屏」的证据，而是复制残留。⇒ **T1 判为「不构成反例」，S543 的方向在此点未被推翻。**

**B 类 = 独立采集到同一静态屏（可用）**：`frame_target_01.png` 51 张里 4 个跨趟重复组，
**组内 mtime 全部互异**（如 sha=b633740a 跨 12 趟、12 个不同 mtime）
⇒ 这些是各自独立拍的同一张静态屏（开局简报/装载画面是位图，跨趟一致很正常）。

**C 类 = 窗末取证（S543 的主证据）——我逐张做了 png mtime vs 本窗 json mtime 对账：**

```
全仓 measure_w*_end_x.png 中，mtime 与本窗 measure_w{k}.json 相差 >2s 的只有 1 张：
  archive_T38\measure_w1_end_x.png   差 -4411s
其余 24 张全部「同刻」（差 ≤2s）。
```
⇒ **24/25 张窗末取证的时间戳归因成立**，S543 的主证据链**没有塌**；
只有 `T38/w1` 这一张是外来件（§3.2 另有 harness 自述与解码时间双重佐证）。

⇒ 修正后的影响面（比初稿保守、也更准）：
1. **S543 §七.6 的登记不成立**：「T35/T37/l3_* 的 frame_target_01 本身也是计分屏，
   范围比 29 窗更广」——`archive_T35/frame_target_01` 与 `archive_T37/frame_target_01`
   确实解出了时间字段（`00:00:16`），但这两趟**没有 measure_w0.json**（12:27:34 / 12:57:16 各拍一次），
   所以「范围更广」只是**别的趟的开局图**，与 29 窗无关；不得据此扩大结论。
2. **`navsig_*` 系列一律不得作为任何单趟的现场证据**（A 类）。
3. §538/§539 不受此条影响（它们只用 JSON，不用图）。
