## 勘误 1：`docs/re/ARCHITECTURE_ATLAS.md` §8.4 —— 地址写错

### 事实

`ARCHITECTURE_ATLAS.md` 有 **6 处**把「CurrentFrame 递增点」写成 `0x0055DE73`：

| 行号 | 原文 |
|---|---|
| 260 | `L4["CurrentFrame++ 唯一推进点 (0x0055DE73)"]` |
| 1927 | `F4["★ 全镜像唯一 CurrentFrame++ 自增写点 (0x0055DE73)"]` |
| 2008 | 「**全镜像唯一定常递增写入点位于 `0x0055DE73`**：」 |
| 2418 | 「全镜像仅 `0x0055DE73` 处定常执行递增」 |
| 2819 | 「CurrentFrame++ 唯一在 0x55DE73」 |
| 2841 | 「轮询器**早于** `CurrentFrame++`（`0x55DE73`）」 |

### 字节事实（Leader 亲读）

```
0x55DE73: 8B 15 84 ED A8 00    mov  edx, [0x00A8ED84]   ← 这是【读】，不是递增
0x55DE79: A1 84 77 B0 00       mov  eax, [0x00B07784]
0x55DE7E: 42                   inc  edx                  ← 【自增在此】
0x55DE7F: 3B C7                cmp  eax, edi
0x55DE81: 89 15 84 ED A8 00    mov  [0x00A8ED84], edx   ← 【写回在此】
```

复核命令（Leader 已跑，PASS）：
```
rd(0x55DE7E, 1)  = 42
rd(0x55DE81, 6)  = 891584eda800
```

### 自相矛盾证据

同一节 §8.4（第 2010–2013 行）**自己贴的代码块**标注的正是 `0x0055DE7E: 42  inc edx`。
即：**散文与代码块矛盾，代码块是对的，散文地址错**。

### 应改为

| 位置 | 应改为 |
|---|---|
| 260 / 1927 / 2008 / 2418 / 2819 / 2841 | **自增执行点 `0x0055DE7E`（字节 `42` `inc edx`）；写回点 `0x0055DE81`（字节 `89 15 84 ED A8 00`）。`0x55DE73` 是读点（`mov edx,[0xA8ED84]`）。** |

**严重度**：高。按行 2841 的用法（「轮询器早于 CurrentFrame++（0x55DE73）」），读者若去反汇编 `0x55DE73` 会看到一条 `mov`，无法理解「递增」从何而来，可能推出「文档有误→整节不可信」或「我读错了二进制」两种错误结论。

## 勘误 2：`docs/re/clock_frame_loop.md` —— 同一文档内部自相矛盾

### 事实：同一份文档里，同一个全局有两种互斥的说法

| 行号 | 原文 | 语义 |
|---|---|---|
| 86 | 「`0xA8ED80` \| **「快进/跳过 Sleep」标志**（=1 时 `0x55D360` 跳过 Sleep 块）」 | 快进 |
| 215 | `if (![0xA8ED80]) { // 非快进` | 快进 |
| 433 | 「`0xA8ED80` \| **快进（跳过 Sleep）标志**」 | 快进 |
| **477** | 「**`0xA8ED80` 为 `AppHasFocus` 标志**。正常游戏（有焦点）时直接跳过 Sleep 块（零 Sleep）；`Sleep(500)`（单机暂停）与 `Sleep(10)`（联机后台保活）**仅在失去焦点后台运行时生效**！」 | **焦点** |
| **526** | 「当游戏**失焦**（`[0xA8ED80]==0`）进入 `Sleep(500)` 时，单机模式下 `MainLogicFrame` 挂起……重获焦点后立即单调推进」 | **焦点** |

### 字节裁决

唯一写者是 `0x7778CE`（`mov [0xA8ED80], al`），守卫链：
```
uMsg==0x1C (WM_ACTIVATEAPP) ∧ hwnd==[0xB73550] ∧ wParam≠0 ∧ 旧值≠新值
```
⇒ **语义是焦点态**。`re_atlas/evidence/r063a_flag_writer_closure.md` 已独立定谳，
引擎内调试串为 `Focus_Loss()` / `Focus_Restore()`。

### 精确化：不是「跳过 Sleep 块」，是跳过**整个 Sleep+泵循环**

```
0x55D377  mov al,[0xA8ED80]
0x55D383  test al,al
0x55D385  jne 0x55D3BB        ← 旗标=1 直接跳到帧体，Sleep 与泵【两者都跳过】
--- 旗标=0 才进入下面 ---
0x55D387  mov esi,[0x7E11F0]  ; KERNEL32!Sleep
0x55D38D  mov eax,[0xA8B238]  ; GameMode
0x55D39B  push 0x1F4 / call esi     ; Sleep(500)  ← Mode∈{0,5}
0x55D3A2  call 0x5D4D50             ; MessagePump
0x55D3A7  mov al,[0xA8ED80]
0x55D3AE  je 0x55D38D               ; 仍为 0 → 回到循环顶
```

### 应改为

| 行号 | 应改为 |
|---|---|
| 86 / 433 | 把「快进/跳过 Sleep 标志」改为「**焦点标志**（`AppHasFocus`；=1 时**跳过整个 Sleep+消息泵循环**）」。并注：`=1` 不代表「快进」，而代表「前台有焦点，无需等待」。 |
| 215 | `if (![0xA8ED80]) { // 失焦：进入 Sleep+泵等待循环（非快进）` |
| 477 / 526 | **这两行是对的，保留**；但应上移到 §1 全局表处作为主定义，避免读者先看到 86/215/433 的错误说法。 |

**严重度**：中高。行 477 与 526 已经把正确结论写在文末「关键修正」表里，
但读者若只读 §1 全局表（86 行）与 §3.2 伪码（215 行）就会带着错误模型离开。

## 勘误 3：`docs/re/clock_frame_loop.md` §3.2 伪码缺两条出口

### 事实

§3.2 的 MainLogicFrame 伪码（约 207–250 行）列出了 `if (![0xA8E9A0]) return`、
Sleep 块、帧号阈值、耗时记账、inc、`0x55E160`，但**未列出**：

1. **`0x55D877` 单机局挂起门**：`GameMode∈{0,5} ∧ [GameLogic+0x62C]≠0` 时，
   走 pump / `0x48D080` / `0x53B560` / `LogicUpdate` / `0x4F4480` 后 **直接 ret，不推帧**。
2. **四旗标门**：`[0xA8ECD0]/[0xA83D49]/[0x8B41C0]/[0xA83D48]` 任一非零 ⇒ `jne 0x55DEC8`
   ⇒ 跳过 inc ⇒ 落到 `0x55DEDB`。

### 影响

伪码是读者理解帧循环的**主要入口**。缺这两条，读者会认为
「只要进了 MainLogicFrame 就一定会 inc」（除了 `[0xA8E9A0]==0` 早退），
从而无法解释任何「帧号不推进」现象。

### 应改为

在伪码 `edx = CurrentFrame; inc edx` 之前插入两条分支说明，并注明
三处 `ret`（`0x55D877` / `0x55DEC7` / `0x55DEDB`）中前两者可绕过 inc。

**严重度**：中高（漏项，不是错误；但直接妨碍对「帧号冻结」的理解）。
