# §531 订正：我上一轮把「停滞」当成了「正常抖动」（2026-11-03）

> **本件推翻 §531 的核心论证。§531 说「N=1.0s 站不住、存在结构性矛盾」——该结论建立在一个概念错误上。**

---

## §0 订正结论

| §531 原说法 | 实际情况 |
|---|---|
| 「N 硬下界 > 0.594s，因为正常抖动 p99 达 594ms」 | **错**。594ms 那个数是**停滞本身**，不是正常抖动 |
| 「安全采样窗口（>0.6s）与停滞主体（0.1–0.2s）不重叠」 | **不成立**。N=1.0s 的误触率实测为 **0** |
| 「N=1.0s 覆盖率仅 2.88%，站不住」 | 覆盖率数字本身没错，但**「覆盖率」不是正确的评价指标**（见 §3） |

---

## §1 错误的来源

§531 计算「正常推进抖动」时，用的是**相邻帧沿之间的间隔**：
```
gaps = t[edge_k] − t[edge_{k−1}]
```
其中 `edge` 是**帧号变化点**。

**但「相邻帧沿之间的间隔」正是停滞的定义**——帧号不变的那段就是停滞。
把这个量当作「正常抖动」，等于**把要测的东西当成了噪声底**，逻辑上循环了。

§531 由此得到「p99 = 594ms」并据此断言 N 必须 > 0.594s。**这个推理是错的。**

## §2 正确的算法：只取真实连续推进

正常推进 = 帧号**逐次 +1**（`Δf == 1`）的相邻帧沿。排除所有跳变/停滞：

| 分位 | 拍数 | 毫秒 |
|---|---|---|
| p50 | 16 | 40.0 |
| p90 | 40 | 100.0 |
| p95 | 56 | 140.0 |
| p99 | 93 | 232.5 |
| p99.5 | 111 | 277.5 |
| **p99.9** | **183** | **457.5** |
| **max** | **360** | **900.0** |

样本 n = **28212**（全部 97 窗的连续推进对）。

⇒ **真实正常抖动上限 = 360 拍 = 900ms**，与 §531 用的 594ms 是不同的量（后者是停滞）。

## §3 误触率 vs K（这才是决定 N 的正确指标）

「误触」= 正常的 `Δf==1` 推进，被「帧号停推超 K 拍」误判为冻结：

| K | 毫秒 | 误触数 | 误触率 |
|---|---|---|---|
| 20 | 50 | 6644 | 23.55% |
| 40 | 100 | 2829 | **10.03%** |
| 60 | 150 | 1170 | 4.15% |
| 80 | 200 | 483 | 1.71% |
| 100 | 250 | 213 | 0.76% |
| 160 | 400 | 40 | 0.14% |
| 240 | 600 | 8 | 0.028% |
| **400** | **1000** | **0** | **0.000%** |

⇒ **N = 1.0s（K=400）时，正常推进的误触率实测为 0。**
§531 说 1.0s 「会漏掉 97% 的停滞」——但那只说明它**只采长停**，**不说明它会误触**。

## §4 「覆盖率」不是正确的评价指标

§531 用「N 能覆盖多少停滞段」来评价 N，得出「N=1.0s 只覆盖 2.88%」。
但 E3 的**目标不是覆盖所有停滞**，而是**在冻结瞬间抓一次栈**。

- 一次采样只能看到**一个**时刻的栈；
- 采 3% 的长停，与采 87% 的短停，**看到的栈可能完全一样**（都是「帧号不推进时引擎在哪」）；
- 因此**「覆盖率」高低不直接决定 E3 的判别价值**。

§531 把「覆盖率」当成 N 的否决条件，是**用错了指标**。

## §5 订正后：N 的合理取值

| 约束 | 值 |
|---|---|
| 误触率 = 0 所需最小 K | **400 拍 = 1000ms** |
| 误触率 < 0.15% 所需 K | 160 拍 = 400ms |

⇒ **N = 1.0s 是一个站得住的选择**（误触率 0），甚至偏保守（p99.9 只需 457ms）。

**§530 卡片原本建议的 N = 1.0s 无须更改。**

## §6 但 §531 有一条推论仍然成立

**「MiniDump 采不到 0.1–0.2s 短停」这条仍然对**：
- dump 自身停顿数百 ms–秒，若 N=1.0s 触发，采的是**长停**（≥1.0s），dump 来得及；
- 但若想采 0.1–0.2s 短停，dump 物理上做不到——**这与 N 取值无关，是 dump 机制本身的限制**。

⇒ **订正后仍然成立的限制：走乙案（MiniDump）只能采 ≥1.0s 的长停，不能采短停主体。**
但这**不再是「结构性矛盾」**，而是「乙案的能力边界」——可以选择接受（出路 A 仍然有效）。

## §7 本件的错误性质与教训

**这是本程第三次同类错误**：
1. §515：枚举漏数据根散件 → 异族指出
2. §522：11 窗下全称结论 → 异族判 REFUTED
3. **§531：把「停滞」当成「正常抖动」→ 自己复核时发现**

**共同点：都用了一个「看起来合理的量」，但没有检验它是否与测量目标循环定义。**

**新增第 5 条方法纪律**：
> **凡以某个量作「噪声底/正常基线」，必须先检验它与待测量是否同源。**
> **判别方法：问「这个量的定义里，是否包含了我要测的现象？」——若包含，它就不是噪声底。**

## §8 诚实账

1. 本件**未经异族核验**。
2. 「Δf==1 才是正常推进」这个判据**未独立验证**——存在跳帧（Δf>1）的正常场景被我排除了，
   若那些场景的抖动更大，K=400 的误触率可能不为 0。
   实测跳幅分布：`Δf=1` 占绝大多数（§518 已记 1050/1051），
   但**本件未单独统计 Δf>1 处的拍间隔**——这是遗留缺口。
3. §531 的「结构性矛盾」表述**作废**；但其「dump 采不到短停」的能力边界**保留**。
4. 本件不改变「N=1.0s」的建议，**但也不代表 E3 一定可行**——短停采不到的边界仍在。
