# E3 触发阈值 N 的复算依据（2026-11-03，纯离线）

> **目的**：§530 卡片里建议 `N = 1.0s` 是**目测值**。按 §528 的教训（边界压在最值上 → C3 错误），
> 本件用全量数据复算 N 的可行区间，并检验 1.0s 是否站得住。
>
> **结论先行：1.0s 站不住。而且这个区间本身存在结构性矛盾，见 §4。**

---

## §0 结论

| 项 | 结果 |
|---|---|
| N 的下界（不能误触正常抖动） | **> 0.594s**（全量 62 窗的帧沿间隔 p99 最大值） |
| N 的上界（需覆盖目标停滞） | **无明确上界**——但 N 越大，覆盖的停滞事件越少 |
| **N=1.0s 的实际覆盖率** | **仅 2.88%**（50/1734 段） |
| **停滞事件的主体** | **87.7% 是 0.1–0.2s 的短停**（1521/1734） |
| **结构性矛盾** | N 必须 >0.594s 才能不误触，但 87.7% 的停滞短于 0.2s ⇒ **安全采样窗口与主体现象不重叠** |

## §1 下界：正常推进抖动有多大

对全量 62 个「帧沿数 ≥10」的窗，计算相邻帧沿间隔的 p50/p99：

| 统计量 | 中位 | 范围 |
|---|---|---|
| 帧沿间隔 p50 | 32.4 ms | 31.4 – 351.2 ms |
| 帧沿间隔 **p99** | **45.8 ms** | **35.4 – 594.4 ms** |

**p99 最大值 = 594.4ms**（`l3_20261031hb w1`）。其余高位窗：`ha w0` 490.7ms、`hb w0` 474.5ms、
`hb w2` 404.8ms、`v3a w2` 305.7ms。

⇒ **N 若 < 0.594s，会把正常推进抖动误判成冻结**，采到错误的时刻。

## §4 ★ 结构性矛盾（本件最重要的发现）

```
N 的硬下界： > 0.594s   （否则误触正常抖动）
停滞主体：   0.1–0.2s   （占 87.7%）
                   ↑
        这两者完全不重叠
```

⇒ **用「帧号停推超 N 秒」作为 E3 触发条件，若 N 选在安全区（>0.6s），
采到的必然只是那 3% 的长停，无法代表占 87.7% 的短停主体。**

**这不是调参能解决的——是触发机制与现象尺度不匹配。**

## §5 三条出路（供裁决，本线不自行选择）

### 出路 A：接受偏差，明确声明只采「长停」

- N = 0.7s（安全区内、覆盖率与 0.6 相同但余量更大）
- **明确声明：采到的是 3% 的长停，不代表 87.7% 的短停主体**
- 价值：仍能看到「冻结瞬间在哪个函数里等」，长停与短停的等待点**可能相同**（未验证）
- 成本：最低，不需要改采样机制

### 出路 B：改触发机制——不靠时间阈值，靠「已进入冻结态」

- 用**更细的判据**：不是「停推超 N 秒」，而是「帧号在最近 K 次采样中完全未变」（K 次 × 采样间隔）
- 但本线 harness 采样率 ~400Hz（2.5ms/拍），K=240 次 ≈ 0.6s，**仍绕不开下界**
- ⇒ **这条实际上退化为出路 A**，除非降低判定用的采样率（那又需要改 harness，属冻结件）

### 出路 C：采「短停」需换观测手段

- 0.1–0.2s 的短停要采到，必须 **< 0.1s 的响应延迟**，而 `MiniDumpWriteDump` 本身停顿就达数百 ms
- ⇒ **乙案（dump）在物理上不可能采到短停**
- 甲案（SuspendThread，≤50ms/次）理论上可以，但方案自述「可能自造死锁」
- ⇒ **要覆盖短停主体，只能走甲案，且必须接受自造死锁风险**

## §7 诚实账

1. **本件未经异族核验**。
2. 「正常抖动 p99 = 0.594s」来自 `l3_20261031hb w1` **单窗**，样本薄；
   若取 p95 则下界可降到约 0.35s，但**本线不敢用更松的分位**（§528 教训）。
3. 「长停与短停的等待点可能相同」**纯属推测，零证据**。
4. 出路 C 中「甲案能采到短停」是**理论推断**，未验证；甲案的自造死锁风险未独立评估。
5. 本件**不选择出路**，只提供数据。
