- **判定一（单段主导=引擎停摆型/帧钟冻结算到底）：REFUTED。**

## ⑦ 反对意见

1. **「单段主导」签名不充分，机制归因被 BOOT 窗污染。** 反例窗 B% 高达 63.9–94.5%，按 B% 排序恰是该类的旗舰成员，实为「f=0 加载段+窗尾恢复」窗。建议给单段主导追加约束（主导段为最末平台 / 帧值≠0 / span 下限），否则该类不是同质类。
2. **数据存在帧计器重置（3668→0），「严格递增」不是全局性质。** 判定二的成立依赖「多次型」切分恰好排除了含重置/帧值 0 的窗——这是类定义的产物，不宜当作帧钟行为的普适定律外推。
3. **T=0.1s 阈值附近敏感。** 22 个窗含 0.1±0.002s 的平台（如 l1c w0 有 18 个），nSegs 对舍入口径敏感（>T 严格 vs ≥T）；但 3 个反例的判定对该扰动稳健（hb 窗最近阈值的平台为 0.0961s，即使计入也只把 B% 抬到 ≈66.3%，仍是 63pp 级反例）。
4. **数据根 3 散件是「整窗冻结、无推进」窗（B%=100%），不在任何判定集合内**；若被核验件把它们计入「单段主导」，其 freezeStart 无定义，恒等式在该口径下无意义——核对口径时需留意。
5. **4 个空窗（len(t)=0）按任务书定义剔除**；若被核验件的"全量窗数"为 101 而非 97，差异即源于此。
