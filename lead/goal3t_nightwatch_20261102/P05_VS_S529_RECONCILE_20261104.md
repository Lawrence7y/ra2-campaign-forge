# P05 与 §529 的冲突辨析：两段不重叠，结论互补而非矛盾（2026-11-04）

> **触发**：他会话 run `dwfrun-169a2a53` 的 P05 产出 `REPORT.md`，其唯象结论是
> 「4 份 wait-trace 全为多次型慢爬，**无一存在秒级完全停摆**」；
> 而本线 §529 的结论是「12 个 measure 窗全为引擎停摆型、冻结后帧增量 = 0」。
> 表面相反。本件核实是否真冲突。

---

## §0 结论

**不冲突。两段完全不重叠，测的是同一趟游戏的两个不同阶段，结论互补。**

| | P05 | 本线 §529 |
|---|---|---|
| 数据源 | `h8_wait_trace.json` × 4（v4-b/c/d/e） | `measure_w*.json` × 12 窗 |
| **覆盖阶段** | **等待段**（帧 0→800） | **采窗段**（帧 925→1707 之后） |
| 时长 | 37.07s（v4-e） | 25s/窗 |
| 结论 | **多次型慢爬**（最长静止 0.25s） | **引擎停摆型**（冻结后零推进） |

**实测对齐证据（v4-e）**：

```
wait_trace:  t 0.0006 .. 37.0729 s   帧 0 → 800
measure_w0:  t 8774.78 .. 8799.78 s  帧 925 → 1707
```

帧号连续（800 → 925）⇒ 同一次游戏会话；**wait_trace 在前、measure 在后、两段无重叠**。

## §1 这个区分改写了什么

### 1.1 原来以为的

本线此前把「停滞」当作一个整体现象，用 measure 窗数据得出「引擎停摆型」，
并据此推测「满速运行后突然冻结」。

### 1.2 实际是两个阶段

| 阶段 | 时段 | 表现 |
|---|---|---|
| **等待段**（装载/等待开战） | 帧 0→800，约 37s | **慢爬**：5s 窗速率 1.6–3.4 帧/s，最长静止 1.246s（v4-b） |
| **采窗段**（战斗测量窗） | 帧 925+，每窗 25s | **停摆**：12 窗冻结后帧增量恒为 0，冻结时长 2.6–24.7s |

⇒ **「等待段慢爬 + 采窗段停摆」是同一趟的先后两种行为**，不是互相否证。

### 1.3 但这带来一个新问题（必须记）

**为什么同一次游戏，等待段是「慢爬」而采窗段是「完全停摆」？**

本线目前**不能回答**。可能的方向（**均为推测，零证据**）：
- 等待段与战斗段的代码路径不同（等待段可能仍在跑菜单/装载逻辑）；
- 战斗段触发了某种阻塞；
- 两段的观测通道不同（wait_trace 是等待环逐拍，measure 是采窗采样）。

**须真机侧证据（如 E3）才能定因**——这正好回到 D-13 的裁决。

## §2 P05 的其他结论（本线采信其数据，不采信其跨线推断）

### 2.1 与本线一致的部分（互为独立佐证）

| P05 结论 | 本线对应 |

| 引擎 coverage 99.9984% / 1394120 insns / 66 resync | §536 修复版 **100.00%/1394120/66** — insns 与 resync **逐位相同**（覆盖率差异见 §2.3） |

**⇒ P05 的数据与台账多处逐位吻合，其数据可信。**

### 2.2 P05 的一个正面发现（本线采纳）

**「唯一 >5s 的完全静止段是 v4-b 头平台 16.651s @ 帧0」——但它在战斗段外**（首推进前，菜单/装载期）。

⇒ 与本线 §529 的 `f[0]==0 ⇒ 加载段型` 判据**方向一致**（都把「帧计数器未起计」的段排除出停滞）。

### 2.3 一处数值差异（须登记，不裁）

P05 报覆盖率 **99.99837567729335%**；本线 §536 修复版报 **100.00%**。

差异来源：P05 用原件 `Engine.coverage`（`covered/TSZ`，逐指令累加 size）；
本线 `_stream_fix.cov` 同样算法。**两者 insns=1394120、resync=66 逐位相同**，
但覆盖率末位差 0.0016%——**疑为 `TSZ` 分母或末段处理差异**，本线**未复算**，登记为待查。

### 2.4 P05 的跨线推断（本线不采信其效力）

P05 §1.4 称「这 4 份数据能排除秒级引擎停摆，不能区分细粒度睡眠自旋与 (a) 出口」。

**其「排除秒级停摆」的适用范围仅限 wait-trace 覆盖的等待段**（0–37s）。
它**不能**外推到采窗段——本线 §529 已测到采窗段存在 2.6–24.7s 的完全冻结。
⇒ **P05 该句若不限定范围，会被误读为「不存在秒级停摆」的全局结论。本线明确限定。**
