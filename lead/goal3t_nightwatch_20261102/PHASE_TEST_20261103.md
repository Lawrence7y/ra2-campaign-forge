## §0 结论

**两个时间假设都不成立。**

| 假设 | 统计量 | 结论 |
|---|---|---|
| H_phase（趟内越后越卡） | `Spearman ρ(window, B%) = −0.0403` | **不成立**（\|ρ\|<0.2） |
| H_uptime（开机越久越卡） | `Spearman ρ(开机秒, B%) = +0.0395` | **不成立**（\|ρ\|<0.2） |

**「趟内单调升」的现象存在但统计不显著**：10 个高变化趟中 6 个单调升、2 降、2 非单调；
对 8 个可判趟做单侧二项检验 **P(X≥6|p=0.5)=0.1445，p≥0.05 ⇒ 不能排除随机**。

⇒ `l3_20261023q` 的 0%/0%/84.62% **是个例，不是系统规律**。
但对该个例的解剖发现了一个**明确的形态特征**（见 §4），这是本轮唯一的正面增量。

## §1 方法：两套独立时间轴，分别报告不混算

| 轴 | 量 | 混杂结构 |
|---|---|---|
| 轴1 趟内相位 | `window` ∈ {0,1,2}；另用 `t_abs0` 求窗间真实时间差 | 同 BOOT、同会话、同 units0 的干净对照 |
| 轴2 开机时长 | `samples.t[0]` | 跨趟，混入会话/BOOT 差异 |

**纪律来源**：D-12② 要求 BOOT 身份双轴分列、禁混算；此处两轴混杂结构不同，同理分列。

**`samples.t` 基准的实测核验（非猜测）**：同一趟三窗内 `samples.t[0] − t_abs0` 差值恒定在 ±3ms：

```
l3_20261023q: -1793337038.086 / -.085 / -.083
l3_1101v4e  : -1793667257.098 / -.096 / -.097
l1c_20261021: -1792547143.095 / -.094 / -.094
```

⇒ `samples.t` 是与墙钟同速的单调时钟。交叉验证：`l3_1101v4e` 的 `samples.t[0]=8774.8s`
与 BOOT#8 实测 uptime≈2.4h(8640s) 吻合 ⇒ **`samples.t` = 自 BOOT 起秒数**。
⚠ 该偏移在不同 BOOT 间差约 33 万秒，故**轴2 只在同一 BOOT 内可比**。

探针：`_phase_test.py` → `_phase_test_out.txt`。

## §4 ★ 唯一正面增量：`l3_20261023q w2` 的解剖

这是本轮最有价值的观察。该窗结构：

| 时刻 | 帧值 | units | ws_kb | techno |
|---|---|---|---|---|
| 0.000s | 4516 | 811 | 139128 | 976 |
| 1.0s | 4546 | 811 | 139132 | 976 |
| 2.0s | 4578 | 811 | 139132 | 975 |
| 3.0s | 4609 | 811 | 139132 | 975 |
| **3.844s** | **4636（最后一次变化）** | 811 | 139132 | 975 |
| 4.0s – 25.0s | **恒为 4636** | **811（全程不变）** | 140920（6s 处阶跃一次） | 975（恒定） |

**关键事实**：
- 帧号在 **t_rel = 3.844s 处停在 4636，此后 21.156s 完全不动**，直到窗末。
- 同期 **`units` 恒为 811（单位没减少）、`techno` 恒为 975**（战斗对象仍在）。
- `ws_kb` 只在 6s 处阶跃一次，之后全程平坦。

⇒ **战斗单位仍在场、内存无抖动，但帧钟完全冻结 21 秒。**
这是**「引擎停摆」**特征，不是「算得慢」（算得慢会看到帧号缓慢递增；这里是**零**递增）。

**对比多次型簇**（§521 已证）：多次型是帧号**严格递增**（`distinct_f==nseg`）的连续慢爬。
**两者是不同现象**：
- 多次型 = 慢但不停（整窗低帧率）；
- `q w2` 型 = 完全停（帧钟冻结，单位仍在）。

**这正是「单段主导」簇的极端形态**（最长段占 100%）。

## §6 诚实账

1. **两轴都只做相关/分层，不做因果**；各趟 units0 与会话共变，混杂未完全剥离。
2. `window` 只是序号，不等于时间相位；本件用 `t_abs0` 求真实窗间差（`q` 三窗间隔实测
   25.019s / 25.016s，间隔均匀，故此趟序号≈相位）。
3. `samples.t` 基准已实测核验（§1）；**轴2 只在同一 BOOT 内可比**，跨 BOOT 会混入 BOOT 身份差异。
   本件的轴2 分层表**跨了多个 BOOT**，故该表的解读力弱于 `ρ` 检验本身——**引用时须注明**。
4. 已排除全窗冻结窗（同 §521 理由）。
5. **二项检验的样本只有 8 个**，即便显著也不足以下结论；本件如实报「不显著」。
6. **本件未经异族核验**，不做机制定谳。§4 的形态描述是**观察**，不是机制归因。
7. §4 只有**一个窗**（`q w2`）的解剖——但 §7 已把它推广到 11 窗。仍属**观察**，非机制归因。

## §7 ★ 同型推广：11 个单段主导窗全部是「帧钟冻结算到底」

**11/11 全部符合「帧钟冻结至窗末」模式。**

两个补充观察：

1. **`l1_20261023e1 w0` 与 `hb w0` 是例外中的例外**：它们的冻结时长只有 0.018s / 0.025s
   （B% 分别 0.4431 / 0.6372，**均已低于 25%，本不在目标批**）。原因是它们是
   `no_advance` 的 4s 短窗（§521 已登记），属拒采窗，不参与本模式。

2. **冻结起始时刻跨 0.265s – 18.380s，跨度极大**；且**越早冻结 → B% 越高**（显然，
   因为冻结时长 = 窗长 − 起始）。**这说明「单段主导」的 B% 差异主要是「何时冻结」的差异，
   不是「冻结多深」的差异**——一旦冻结，就是彻底不动（帧号零递增）。

3. **`units` 变化与形态无关**：恒定（4 窗）、2 档、5 档、8 档、10 档都有。
   ⇒ **单位减少不是冻结的原因**，至少不是必要条件。

**⇒ 「单段主导」= 引擎停摆型。B% 只反映停摆发生的早晚。**

## §8 与多次型簇的最终区分（本轮收口）

| 维度 | 单段主导（13 窗） | 多次型（11 窗） |
|---|---|---|
| 帧号轨迹 | **停住不动**（零递增） | **严格递增**（`distinct_f==nseg`） |
| B%(T=0.2) | **不变**（段全 >0.2s） | **归零/近零** |
| 最长段占 100% | 是 | 否（1–3%） |
| 物理含义 | **引擎停摆** | **整窗低帧率** |

**这是两种本质不同的现象**，不是同一现象的两种切分。**该结论已获异族 CONFIRMED（§521 三项）。**
