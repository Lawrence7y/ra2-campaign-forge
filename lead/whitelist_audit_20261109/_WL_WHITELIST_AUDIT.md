## 3 第三步：白名单机制本身

### 3(a) 用白名单验证「没放松」，这个验证有效吗 —— **无效（作为语义验证）**

### 3(b) 有效的验证应该长什么样

- **白名单来源独立**：由**不参与被测系统设计、不参与派发**的第三方（独立裁定组 / 独立标注员）从任务书原文与主件原文出发，先给出「哪些 (域, 要素) 是真误报、哪些是真缺失」的**盲标注**，且标注时不知道 R9S 会翻哪些项；白名单 = 盲标注结果，不是 SPECS 的键表。
- **预注册 + 封印**：白名单在跑回归**之前**以 `hashlib` 指纹封印（含标注理由、标注员、时间），回归脚本只能读封印值，不得由被测系统作者修改；判据作者不得同时是标注员。
- **验证对象换位**：回归不检查「flips ⊆ 白名单」，而检查「**对每一个 flip，独立裁定其语义是否真在场**」；`no_relaxation` 的定义应为 `∀flip: independent_truth(flip) == True`，而非 `∀flip: flip ∈ WHITELIST`。
- **双盲 + 反例注入**：正负样本由第三方构造并混入被测系统未知的自然措辞；至少包含「形式像而实质空」的对抗样本，且判定阈值（全部抓住）预先注册。
- **分离两种失败**：把「白名单集合错」与「判据把真缺失判在场」分开报；前者应报 `whitelist_invalid`，后者报 `relaxation_detected`。当前公式把两者混成一个布尔。

### 3(c) 「白名单不可自证」的替代方案（不执行）

**方案：独立真值表 + 逐项对抗回归（Truth-Table Gating）**

1. 第三方对每个 (域, token) 项预注册三值真值 `T ∈ {PRESENT, ABSENT, UNVERIFIABLE}`，附 `file:line` 原文锚与理由，封印 SHA256。
2. 判据输出对每个项给 `(present, layer, evidence[])`；门禁对**全部 302 项**比对 `present == (T==PRESENT)`，任何不一致即 FAIL（不再用「白名单」概念，改用「逐项真值」）。
3. 对每个 `T==PRESENT` 的项，另注入一组由第三方构造的「保留表层结构、抽走关键语义值」的对抗变体（指针值 / 未决问句 / 自然否定 / 占位 / 跨小节），要求判据**全部判 ABSENT**；抓不住即 FAIL。
4. `T==UNVERIFIABLE` 的项不参与 PASS 统计，单列报「未验」，不许用 `no_relaxation=True` 掩盖。
5. 白名单若仍需存在，只能是「已登记为 UNVERIFIABLE 的暂挂清单」，且**不得参与 PASS 计算**；它的缩小/扩大由第三方裁定，不由判据作者改。

（本会话不执行改法；按纪律只给方案。）
