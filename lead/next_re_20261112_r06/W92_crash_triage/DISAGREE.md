# W92 DISAGREE（与既有结论/卡片摘要的分歧）

**D-1｜Lead 已自行更正（W92 解析确认）**：W91 P1/P2 不是同一签名。P1 = EIP 0x00000000 / Access 0（取指 fault），P2 = EIP 0x006F36FE / Access 0x11378560。W92 按 4+1 条签名出具（另加 W88_C4b、W88_C7 拆分与 ra2youli 历史件，共 6 实测 + 1 转述）。

**D-2｜"W88 三份 fresh"实为三个不同签名**：C1、C4b、C7 崩点/坏值各不同（见签名表 S1/S2/S3）。C1 与 C4b 同调用点（0x47C538），C7 在同族兄弟函数（0x47C4FD）。原始卡片把 W88 当单一签名，会漏掉"同一调用点两种 fault 时机"这个关键证据（ESP 0x…044 vs 0x…040）。

**D-3｜"EAX=0x000A0008 是垃圾 vptr"需要限定**：C7/P1 的 EAX 不是小整数而是**堆地址**（0x15FD38E8 / 0x10D6E7A0）。即 W88 内部就有两种坏值形态：小整数垃圾（C1/C4b）与堆指针覆盖（C7）；P1 是堆指针覆盖 + 假虚表槽值恰为 0。统一叫"垃圾 vptr"没错，但坏值**类型**不同，指向的破坏面证据（写入者行为）可能不同。

**D-4｜对 Lead "Eip=0 → vtable 槽本身为 0 或函数指针为 0" 二选一的回答**：判"函数指针为 0"，但**两个原始选项都不成立**——假 vptr 是非零堆指针，真虚表（.rdata 0x7E1000+）未被触及。真实机制：对象头首 dword（vptr 槽）被堆指针覆盖，随后 `call [heap+0x2C]` 读到 0/0x14。这不削弱 cell-list 假设（坏对象仍在链上），但"vtable 内容被清零"可以排除。

**D-5｜ra2youli 历史件不参与机制归并投票**：它崩在 NULL 全局单例（[0x00887368]=0 → this=0），且非本轮产生（mtime 2026-11-13 06:29，环境/时点不同）。作为第 5 个实测样本入库，但不用于支持/反驳 cell-list 假设。

**D-6｜"IsCellOccupied 属 InfantryClass"（R03 转述）**：函数名本身在镜像中无符号证据，仅 0x51BF90 入口形态与 0x51C2D3 指令形态相符。名字沿用转述，标注 `[转述，不可复核]`。
