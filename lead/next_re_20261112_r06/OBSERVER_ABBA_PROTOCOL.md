# 观测器扰动校准协议（ABBA）· 面向 cnc-ddraw 限帧通道与窗口线程 CPU 消耗率

> 编制：Lead｜2026-11-14｜依据：`lead/next_re_20261112_r03/RULING_GPT61SOL.md` **§Q3 护栏**（独立裁决方 Codex `codex/gpt-6.1-sol`，effort=high）
> 适用：任何要在真机上"开观测器"的卡。**本协议未执行过**（截至本文件落盘）；执行后须回来补执行记录与判决。

## 0 · 这份协议解决什么、不解决什么

| | |
|---|---|
| **解决** | 观测器（1 kHz RPM 轮询、ETW 会话）本身会不会抬高被测的窗口线程 CPU / 干扰节拍 —— 即「观测器扰动是否在预算内」 |
| **不解决** | **"画面是否卡"**。裁决 Q3 明确：没有**独立画面参照**（外置高速摄像或已证精度的独立仪器）时，只能产出"开启观测时看到的节奏"，**不得**裁定原始画面 |
| **因此** | 本协议通过 ⇒ 只能说「**该观测器可用于测 CPU 消耗率，扰动在预算内**」；**不能**说"渲染侧已可信"

## 2 · 设计：区组 ABBA，A=开观测、B=关观测

- **区组** = 一段连续的同一局内时间，内部按 **A→B→B→A** 顺序切 4 个等长片段（ABBA 抵消时间趋势）。
- **片段长度**：**60 s**（裁决要求"每段固定时长并在切换后预热"）。切换后**丢弃前 10 s** 作预热，只用后 50 s 做统计。
- **区组数**：**≥5**（裁决明文）。本轮先做 **3 个区组 = 12 片段 ≈ 12 min 局内**；3 与 5 的差别必须写进报告（这是**降配**，不是满足裁决）。
- **同一趟内完成所有区组**（避免跨趟的机器状态漂移）；若一局撑不住 12 min，则拆成两趟并**把"趟"作为额外分层**写进报告。
- 记录：每片段的起止 `t_perf_ns`、观测器开关时刻（写进独立时间戳日志）、观测器进程自身 CPU、事件丢失计数（ETW 才有）。

## 3 · 预注册判读（跑之前写死，不许事后调）

对每个片段算 `rate_i`（窗口线程 CPU 消耗率）。按区组内配对：`d_block = mean(A) − mean(B)`（同区组内）。
汇总 3 个 `d_block`，报 **均值与极差**（3 点算不出稳健 95 % CI，如实写"仅 3 区组，未达裁决的 5 区组"）。

裁决给的**工程容忍度**（本轮预算）：
1. **窗口线程 CPU 增量**：`d` 的 **95 % 上界 ≤ 单核 0.5 个百分点**；
2. **画面参照 p95 间隔增幅 ≤ 10 %** ——**本轮做不到**（无独立参照）⇒ 记 **未覆盖**；
3. **长间隔次数增量 ≤ 1 次/分钟** —— 用观测器自己的「限帧放行间隔 >50 ms 次数」近似，**但要注明这不是显示层**；
4. **有效区间无相关事件丢失**（ETW 才适用；`logman stop` 的 lost-events 必须存）。

**三档判决**：
- `d` 均值 ≤ 0.5 pp **且** 3 个区组方向一致 ⇒ 「**观测器扰动在预算内（3 区组降配），可用于测 CPU 消耗率**」；
- `d` 均值 > 0.5 pp ⇒ 「**观测器本身显著影响被测**」⇒ 该观测器**不得**同时用于"测 CPU"，只能单独用于"测它自己那条链路"；
- 3 个区组方向不一致（有的正有的负）⇒ 「**未分辨**，按裁决不得据此纳入正式仪器」。

## 4 · 反例与陷阱（本项目已踩过的，逐条防）
1. **别把"观测器 CPU 低"当成"没扰动"** —— 要去比**被测线程**的 CPU，不是观测器自己的。
2. **别用通配清场** —— 上一卡 `save*.sav` 通配误删过沙箱基线存档；清场一律按 **manifest 差集**。
3. **别跨趟比较** —— 交战臂运行间波动约 8 %（§626-2），跨趟会把扰动埋进噪声里。**必须区组内配对**。
4. **别用 cycle 通道做主判据** —— 与 FILETIME 有两处不一致记录（§626-4；W90 U1）；FILETIME 为主，cycle 只作旁证。
5. **别在片段边界上统计** —— 切换后必须预热丢弃（本协议 10 s）。
6. **trip 目录唯一**，绝不复用（复用已造成过一次证据覆盖）。
