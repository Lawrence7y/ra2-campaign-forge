## 4 可复用规范：交付件版本锚与双件管理 v1（DA-SPEC）

**总则**：对「文件绑定自身哈希」的自指悖论，本会话既有件一律答「不可计算、移交登记」（JSON:53、_n10_:240、PERF_REPAIR_HANDOFF.md:132、_r3_:111 四处同款），结果造成 5 个正本完全无锚。自指悖论可解——对**规范化字节流**（锚行哈希字段清零）计算哈希即可，见 R1。

### R1 件内自锚（规范化自绑定，强制）

- **条文**：每个交付件（正本、登记件、复核回件、修订版）必须件内含唯一锚行，行首格式（ASCII）：
  `DA-ANCHOR: sha256=<64hex> bytes=<10位零填充> rule=zeroed-field-v1`
  锚值 = 将锚行中 `sha256=` 后 64 字符替换为 64 个 `0` 后所得字节流的 SHA256；`bytes` = 全文件字节数（含锚行），10 位零填充定宽。字段定宽保证两次填充均不改变文件长度，锚值稳定可复核。
- **复核算法**（任何验收方无歧义重放）：
  ```python
  raw = open(path, 'rb').read()
  lines = raw.split(b'\n')
  hit = [l for l in lines if l.startswith(b'DA-ANCHOR: sha256=')]
  assert len(hit) == 1
  l = hit[0]
  field = l[18:82]                       # sha256 字段
  nbytes = int(l[l.index(b'bytes=')+6:l.index(b'bytes=')+16], 10)
  assert len(raw) == nbytes              # 字节数绑定
  canon = raw.replace(l, l[:18] + b'0'*64 + l[82:], 1)
  assert hashlib.sha256(canon).hexdigest() == field.decode()
  ```
- **为什么需要**：无件内自锚时，交付件字节流不被任何东西锁定——验收链可以同时"成立"而正本早已被覆盖（本会话 5 个正本完全无锚，§3.2-1；实例一 r2 JSON 即此状态）。既有「由回执登记」做法的失效模式已实演：登记它的输出件可能事后被追加（_verify_hy4_out.txt 漂移，§3.2-6①）。
- **违规实例**：DECISION_QUESTIONS.md（27172 B）、MATRIX_BINDING_FACTS.md（19663 B）、S604_GAP_RECHECK.md（19291 B）、R2_BREAKPOINTS_CLOSURE.md（22351 B）、ACCEPTANCE_RECORDS.json（27965 B）——五件正本层，自身指纹域内 0 登记（§3.2-1）。

### R2 修订覆盖处置（强制）

- **条文**：就地修订（rN→rN+1 覆盖同名件）必须二选一：**(a)** 旧版复制为冻结副本（如 `_r1_<原名>`）后覆盖；**(b)** 无法保留副本时，件内显式声明「旧版不可复算」，且**覆写前实算输出件必须留存于写域**（输出件含旧版 SHA256+字节数，mtime 早于新版落盘）。替代声明必须写明旧版两件指纹与修订动因（r2 MD :4 为合规模板）。
- **为什么需要**：r1 被覆盖后，其锚 `3343cfbe…/26435` 现盘不可复算；若无 `_n1_records_out.txt:9`（mtime 10:04 早于 r2 落盘 10:47）这条覆写前输出，r1 的「覆写前实算复核一致」（r2 MD :128-130）将沦为孤证。而 r1 JSON（15e4731c…/18045）连这类佐证都没有——不可复算且无旁证。
- **违规实例**：a_residual_n1 域 r1 两件就地覆盖、无独立副本（A_RESIDUAL_REFERENCES.md:159 自认）；其中 r1 JSON 无任何覆写前输出件佐证。

### R3 双件并存管理（强制）

- **条文**：同写域出现同题双件（正本/草稿、正本/登记本体、承接件/原件）时：**(a)** 恰好一件件内自标为验收对象（正本），**正本必须在件内明文指认另一件及其字节数**；**(b)** 另一件回指正本或明示「本文为前置/本体，验收对象见 X」；**(c)** 正本必须满足 R1；**(d)** 禁止在无声明的情况下让两件各自独立流通。
- **为什么需要**：双件并存时「哪件算数」若无件内明文，验收者只能靠文件大小或 mtime 猜；一旦两件被不同轮次引用（如编排方清单引用 A、验收链引用 B），锚链分叉。
- **合规实例（供沿袭）**：PERF_REPAIR_HANDOFF.md:6-9（「前置草稿 _n11_（同目录、22745 B）……本件为验收对象」）、DECISION_QUESTIONS.md:3（「登记动作本体 = _n10_，本件为其承接汇总」）。
- **违规实例**：matrix_binding 域——正本 MATRIX_BINDING_FACTS.md:90 把五个 _m_ 件绑为「五件主产出」，但正本自身完全无锚（§3.2-1），且「验收对象=正本」无对等明文；双件关系声明了、正本锚没跟上，R3(c) 不满足。

### R4 验收绑定必须指向正本（强制）

- **条文**：验收记录 / sha256Line / 回执指纹清单，最终必须锚定**当轮正本**的现盘指纹。若复核发生在草稿层（被核对象=草稿），正本落位后必须补一条「正本绑定行」（可由承接件或输出件承载），并显式声明草稿判定如何传递到正本（逐字承接/修订点清单）。禁止验收清单只含中间件、不含正本。
- **为什么需要**：实例三现状——验收链（编排方清单 + DECISION_QUESTIONS.md:130）只锚 8a36d60a…/30122（_n10_），承接正本 DECISION_QUESTIONS.md 的 27172 B 不被任何件锁定；同理实例二验收链绑定停在草稿层，正本仅靠单点输出件。验收者按清单复核会"全 MATCH"却从未锁定正本字节流。
- **违规实例**：d13d14_cards 域正本 0a709f2d…/27172 域内 0 登记（`grep -rn 0a709f2d` exit=1）；perf_repair_n11 域唯一被核对象行（PERF_REPAIR_HANDOFF.md:117）指向草稿。

### R5 版本锚失效处置（强制，禁止静默沿用）

- **条文**：任何「记录值 ≠ 现盘实算」场合（覆盖漂移、回件后追加、行号漂移、上游件再改写）：**(a)** 禁止静默沿用旧值或旧行号；**(b)** 必须件内登记四要素——旧值、现值、漂移发现方式（实跑命令）、影响面（哪些行号锚/结论作废）；**(c)** 影响面内引用一律改用「文件:行 + 当时指纹」双锚或声明不可沿用；**(d)** 无法归因时明写「主体/时点未验」，不得补造原因。
- **为什么需要**：本轮三个实样证明失效是常态而非例外：hy4 输出件回件后被追加 7516 字节（自报 0614af13/18694 → 现盘 f38adf59/26210，R2_BREAKPOINTS_CLOSURE.md:100）；PENDING_DECISIONS.md 汇总后再次漂移（A_RESIDUAL_REFERENCES.md:38，故「任何 PD 行号锚点不可沿用」）；r1 就地覆盖致锚不可复算（:159）。三例中前两例因按 (b)(c)(d) 处置而未污染下游——反向证明本条有效。
- **违规实例（反例=静默沿用风险点）**：若下游件引用 `_verify_hy4_out.txt` 行号而不核对现盘指纹，:114-255 追加段会使旧行号全部错位——R2:92 指出的「引文行号错置」正是这类失效的已发生案例（_dD_PHYSICAL_S_ALIGNMENT.md:108-110 引文错置，R2 :92 实读核实）。

### R6 复核回件格式（沿本轮铁律成文）

- **条文**：复核回件必须含原文行「被核对象 SHA256 = <64位>，字节数 = <n>」，且该值须为回件会话 hashlib 实算；被核对象为多件时逐件给行；被核对象为聚合（拼接/目录）时必须给出拼接顺序与单件指纹（MATRIX_BINDING_FACTS.md:89-90 为合规模板，本会话复算命中）。
- **为什么需要**：无此行则复核不可复核；聚合不给顺序则聚合指纹不可重放。

### R7 实现分级（过渡期最低要求）

- L1 = R1 件内自锚；L2 = 双件互绑（同域配对件互相绑定对方现盘指纹，如 JSON→MD 已有 8 处，反方向补齐即成对）；L3 = 输出件登记（现状最低限，但输出件自身须受 L1/L2 保护）。
