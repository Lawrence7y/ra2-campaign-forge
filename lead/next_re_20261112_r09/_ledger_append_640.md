## §640 · 定谳：**「引擎忘记摘链」被推翻**；cell 链维护是标准头插+删除；`CellClass` 访问路径为两级间接（2026-11-14）

- **性质**：W104（**DeepSeek**，小卡，判读 W100 的 13 份证据）＋ W105（**GLM-5.3-Flash**，小卡，修正 W99 方法缺陷重做普查）＋ **Lead 亲自反汇编复核**后签发（`lead\next_re_20261112_r09\REVIEW\LEAD_VERIFY_W104_W105.md`）。**本条证伪 Lead 自己在派 W99 时定的 UAF 强假设，并确立 `CellClass` 的访问结构。**条目标号 `§640-1…6`。
- **§640-1 [已证] `CellClass` 访问路径：不存在单一静态基址，两级间接，表项可为 NULL**
  | 事实 | 值 | 证据 |
  |---|---|---|
  | cell 指针表**指针**存放于全局 | `0x0087F924` | `0x00429DF5: a1 24 F9 87 00  mov eax,[0x87F924]` |
  | 索引 = `Y*512 + X`（行步长 **512**，非地图宽 100） | `shl ecx,9` + `add ecx,edx` | `0x00429DFA / 0x00429DFD` |
  | 表项 = **指针**，**可为 NULL** | 两级解引用 | `0x00429E19: 8b18 mov ebx,[eax]`；`0x00429E1F: 85db test ebx,ebx`；`0x00429E21: je` |
  | 无效格 fallback = **静态槽** | `0x0089C2E0` | `0x00429E04: b8e0c28900 mov eax,0x89C2E0` → 同跳 `0x429E19` |
  | 另一静态锚点 | `0x00ABDC50` | `0x00566565: be50dcab00`（与 `push 0x148` 同函数）；`0x005780DE: b950dcab00` |
  | `stride = 0x148` | 328 B | `0x005663C3: 68 48 01 00 00 push 0x148`（`step11:271`）；遍历步长 `0x00566AA6: add ebp,0x148`（`step9:95`） |
  | 表容量 `512×512×4 = 1 MB` | —— | `[静态推断]`（`shl 9` + `cmp eax,0x40000` 两条独立线索） |
  - ⇒ **对只读哨兵的三条硬约束**：① 必须**两级解引用**；② 必须先**判 NULL**（否则第一个空格子就崩/误报）；③ 起步锚点用**运行时读** `[0x87F924]` 与 `[0x89C2E0]`，**不要**在静态镜像里找数组。
- **§640-2 [已证·推翻 Lead 假设] 「建筑被摧毁后忘记从 cell 链摘掉」不成立**
  - Lead 亲验摘链函数 `0x0047EA90`（逐指令见签发件 §2-1）：
    ```
    按第2参数选链(+0xE4 / +0xE8) → cmp 链头,node
      · 是链头：链头 ← node->next        (0x47EAC4 / 0x47EACF)
      · 在链中：遍历到 prev->next==node，prev->next ← node->next  (0x47EADB–0x47EAEA)
      · 两种情况都执行 node->next ← 0                          (0x47EAF0)
      · 之后 call WhatAmI()，==0xF(15) 则返回；否则 call [vptr+0xC0]；再判 ==6
    ```
  - **三条独立理由**：① 摘链同时覆盖"是链头"与"在链中"；② **两条链都支持**（按参数选），不存在"只摘 A 不摘 B"；③ **没有"无条件整链替换"** —— 全 `.text` 里唯一形似 `head ← [this+0x30]` 的两条**全在 `head==this` 守卫之后**。
  - ⇒ 就"**忘记摘链**"这个具体形态，**判推翻**。`[已证]`
  - `[未证]` UAF 的**其它**形态仍开放：重复摘、遍历期失效、摘错链。
- **§640-3 [已证] 链表维护是标准写法**：头插在 `0x47E90B / 0x47E91F`（`[ebp+0x30] ← esi`，然后 `head ← ebp`）；条件摘链另有 4 处 `cmp [同字段],X; jne; store`（`0x436A2D` / `0x62FEFE` / `0x678874` / `0x6F105D`，Lead 抽验 `0x00436A25–0x436A2D` 确认）。**没有偷懒写法。**
- **§640-4 [已证·硬约束] `+0xE4` / `+0xE8` 是"通用偏移"，不是 `CellClass` 专属标记**
  - W105 普查出 A 类（`base` 非 `esp/ebp` 的写）**114 条**，其中 **19 条**经"是否正在装虚表"判据剔除（他类构造）⇒ 真候选 **95 条**；**95 条里没有一条能静态证明 base 就是 `CellClass`**。
  - 同偏移撞车实证：`0x74CE4C` 写 `0xFFFFFFFF`、`0x721A44` 写 `12`、`0x62F1E9` 写 `0x40000000`、`0x60Dxxx` 写规则全局指针；`0x004358A9` 的 `mov [esi+0xE4],eax` 紧跟 `mov [esi],0x7e3ad0`（写虚表 ⇒ 他类构造）。
  - ⇒ **凡"按偏移搜 cell 链写点"的做法一律不可用**，必须额外证明对象类型。**本条推翻本轮 W99/W105 普查路线的可用性前提。**
- **§640-5 [已证] 哨兵状态：逻辑已验证，**尚不可上真机**
  - `cell_sentinel.py` `--self-test` **14 checks / 0 failed / GREEN**（含"连扫 3 次无状态污染"回归项）；两条链都扫；带节点上限与已访问集合。
  - **不可上真机**两条理由：① `--attach` **未实现**（派发时故意排除，避免同卡既设计又做危险操作）；② **白名单 280 条会漏 vtable 起点**（"相邻 vtable 被合并成游程"未处理）⇒ 合法 vptr 会被判非法，`--self-test` 绿**证明不了**真机不误报。
  - ⇒ 本条目**只把哨兵登记为"逻辑已验证"，不登记为"可用仪器"**。
- **§640-6 [已证·派发方法整改生效]** 本轮初版 4 张卡里 3 张（W99/W100/W101）在 85–95 % 处失败，根因是**单卡塞 3–13 个子步骤 + 长报告**。改派"一卡一问、≤1 报告 + 1 脚本、报告优先、给硬时限"后，**W104 / W105 两卡全部按时交付，且都自行发现并纠正了自己上一版的两处错误**（W104：引错行号 + 合成内存复用地址致假 FAIL；W105：首版脚本把"条件替换"误标成"无条件替换"）。
  - ⇒ **"一卡一问 + 报告优先 + 硬时限"是本轮可复用的派发纪律。**
