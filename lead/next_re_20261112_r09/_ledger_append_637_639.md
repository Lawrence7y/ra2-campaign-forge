## §637 · 定谳：引擎文件名哈希规则（5/5 复现）+ `ARTMD.INI` 落点 + `§632-6` 关闭（2026-11-14）

- **性质**：W101（GLM 离线，**在 85 % 进度处失败但收尾消息与证据完整**）＋ **Lead 亲算复核**后签发（`lead\next_re_20261112_r09\REVIEW\LEAD_SALVAGE_W99_W100_W101.md` §1；Leade 复算脚本 `_lead_verify_engine_hash.py` / 输出 `_lead_verify_engine_hash_out.txt`）。**本条关闭 §632-6 的 `[未证]`，并勘误 Lead 自己的一条结论。**条目标号 `§637-1…5`。
- **§637-1 [已证·Lead 亲算] 引擎哈希规则**
  > `h(name) = crc32( 完整 4 字节块前缀 + 残留 k 字节 + [k] + 残留首字节 × (3−k) )`，其中 `k = len(name) % 4`（`k = 0` 时退化为普通 `crc32`）。

  | 名字 | len | `k` | 引擎哈希 | 零售 id | 判定 |
  |---|---:|---:|---|---|---|
  | `ARTMD.INI` | 9 | 1 | `5B47D8D5` | `5B47D8D5` | **HIT** |
  | `RULESMD.INI` | 11 | 3 | `8218F9F4` | `8218F9F4` | **HIT** |
  | `LOCALMD.MIX` | 11 | 3 | `FBE0D09D` | `FBE0D09D` | **HIT** |
  | `LOCAL.MIX` | 9 | 1 | `A8548FD9` | `A8548FD9` | **HIT** |
  | `ART.INI` | 7 | 3 | `F91B2C8B` | `F91B2C8B` | **HIT** |
  | | | | | | **5/5** |

  - **零自由参数 + 五个独立零售 id 同时命中** ⇒ `[已证]`。
  - `[过程记录]` Lead 第一次实现算成 **3/5**（`ARTMD.INI`、`LOCAL.MIX` 两个 `k=1` 的名字未中），根因是我把"名字前几个字节"错当成"残留块首字节"。修正后 5/5。**这是本轮第 3 次"先算错再纠正"（前两次见 §636-5 / §636-6）。**
- **§637-2 [已证] `ARTMD.INI` 的真实落点（MIX 普查实读）**
  ```
  ra2md.mix  (depth 0)  ->  id FBE0D09D = LOCALMD.MIX (嵌套, 4,819,480 B)
  ra2md.mix  (depth 1, 所在包 FBE0D09D)
      id 5B47D8D5   size 336,535   kind=ini   name=ARTMD.INI(engine)
      first_line = "; ART.INI"
      markers: Foundation=×580, Image=×383, Cameo=×248, Voxel=×96, [NAPOWR]×1, [NATSLA]×1
  ```
  - 大小 **336,535 B** 与 W97 提取件 `cand_ra2md_0xFBE0D09D_0x5B47D8D5.ini`（SHA-256 `E1F03783…BA31`）**同尺寸**；文件名两个 id 正是 `LOCALMD.MIX` 与 `ARTMD.INI`。
  - ⇒ **引擎读的就是 W97 那份文件。`§632-6` 的「引擎实际读哪份 art 库 `[未证]`」关闭。**
  - ⇒ **`§632-1` 的 `NAPOWR = 3×2` / `TESLA`（经 `Image=NATSLA`）`= 1×1` 适用于引擎真实配置**（`ARTMD.INI` 在普查里**只命中 1 次**，无歧义）。
- **§637-3 [已证·勘误 Lead] 「发行版把三个大 INI 换了名字」作废**
  - 原表述（§632-6、以及 R09 事实底座 §5）：「引擎按 `0xAF902833` 取 `ARTMD.INI`、按 `0x1F674573` 取 `RULESMD.INI`，而这两个名字在 MIX 里处处不存在 ⇒ 发行版把三个大 INI 换了名字。」
  - **实际**：`0xAF902833` / `0x1F674573` 只是普通 `zlib.crc32(UPPER(name))`，**引擎从不用这个值查找**。**名字从未被改。**
  - 我此前的自纠「是名字假设错，不是 API 用法错」**只对了一半**：名字没错，错的是**哈希算法**。
  - ⇒ 连带关闭 `§630-3-2` 里关于 `mixlib.get()` 返回 `None` 的全部争论（`W95 UNKNOWNS` 相关项）：**是 `mixlib` 的哈希算错**。
- **§637-4 [已证] 项目自有代码缺陷：`ra2forge/mixlib.py` 对 `len%4≠0` 的名字静默失效（已登记，未修复）**
  - `mixlib.py:205 crc_hash()` = `zlib.crc32(name.upper())`；`classic_hash()` 是 TS 变体。**两者都不是引擎哈希。**
  - ⇒ 对 `len % 4 != 0` 的名字（`ARTMD.INI`=9、`RULESMD.INI`=11、`RA2F_M1.MAP`=10 … **约 75 % 的名字**），`get(name)` **必然返回 None 且不报错**。
  - ⇒ `write_mix()`（`mixlib.py:349`）用 `crc_hash` 写条目 id。
  - **本次为何没炸**：`[已证]` 地图是**松散 `.MAP` 文件**加载（`sandbox_game` 内确有 `ECH01.MAP`/`ECH02.MAP`/`ECH03.MAP` 松散件），走目录枚举，**不经 MIX 哈希**。`expandmd98.mix`（43,361 B，3 条目，id 恰为 `crc_upper` 的 ECH01/02/03）内**无明文名称数据库**（ASCII 搜 `RA2F_M1.MAP` **零命中**）。
  - **整改建议**：加 `engine_hash()`，`get()`/`write_mix()` 双试 + 冲突检测 + 用本条 5 个 id 当测试向量。**本轮只读，未改任何文件。**
- **§637-5 [未证] `RULESMD.INI` 有两份，谁生效未知**：`expandmd01.mix`（depth 0，**743,215 B**）与 `LOCALMD.MIX`（depth 1，**742,958 B**），尺寸不同 ⇒ 两份不同文件，存在遮蔽关系。

## §639 · `g_far` 的 4.91 pp 是**仿真发散**，不是测量误差；并发现跨趟频率系统项（2026-11-14）

- **性质**：Lead 亲算，用 ndjson 的 `win_cycle`（`QueryThreadCycleTime`）通道。脚本 `_lead_diag_gfar.py` / 输出 `_lead_diag_gfar_out.txt`；汇总 L6。条目标号 `§639-1…3`。
- **§639-1 [已证] 归因表**（`MHz*` = `ΣΔwin_cycle / (ΣΔwin_cpu_ms/1000) / 1e6` ≈ 执行期有效时钟；`cyc/wall_s` ≈ 工作量）

  | 格 | rate 差 | cpu_ms 差 | 频率差 | `cyc/wall_s` 差 | 判读 |
  |---|---:|---:|---:|---:|---|
  | `g_idle` | +0.6353 pp | +3.45 % | **+0.02 %** | +3.48 % | 工作量差 |
  | `g_near` | +0.2393 pp | +0.81 % | −0.61 % | +0.19 % | 工作量几乎相同 |
  | **`g_far`** | **+4.9062 pp** | **+15.13 %** | **−1.11 %** | **+13.86 %** | **r2 真多干约 14 % 的活** |

  - ⇒ **频率几乎没变（−1.11 %），而执行的周期数多了 13.86 %** ⇒ `g_far` 的 4.91 pp **不是观测误差、不是前台、不是邻负载、不是采样精度不足**，而是**仿真本身发散**（同一图/同配置/同对象数，两次运行引擎实际计算量差约 14 %）。
  - ⇒ 这条与 §635-2-4 / §635-6 一致：`§634` 的行军分量与"工作量内在波动"同量级，**无法通过提高采样率/延长窗口/减少邻负载消除，只能靠多次重复并如实报极差**。
- **§639-2 [已证] 新发现的跨趟系统项：有效时钟在 ±2.1 % 内漂移**：六趟 `MHz*` 实测 `3112.8 … 3247.5`（中心≈3180，跨度 ±2.1 %）。FILETIME 是墙钟耗时 ⇒ **同等工作量在低频趟里耗时更长 ⇒ rate 偏高**。换算到 34.88 pp 上约 **±0.73 pp**，**与 ABBA 的 0.5 pp 判据阈同量级，此前从未登记**。
- **§639-3 [未证]** ① 漂移来源（涡轮/热/其它进程争用）未定；② 用 `cyc/wall_s` 作"频率无关"口径需先验证 `QueryThreadCycleTime` 在本场景的可靠性（本次只做自洽性检查）。
