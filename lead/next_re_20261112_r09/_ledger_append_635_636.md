## §636 · 崩溃族函数与虚表普查（Lead 亲验，2026-11-14）

- **性质**：Lead 亲自用 capstone 从 `gamemd.exe` 原始字节重算，**不引用任何既有转述**。脚本 `lead\next_re_20261112_r09\_lead_verify_47C5.py` / `_lead_vtable_census.py` / `_lead_caller_census.py`，输出同名 `_lead_*_out.txt`。汇总件 `lead\next_re_20261112_r09\LEAD_FINDINGS_R09.md`。条目标号 `§636-1…5`。
- **§636-1 [已证] 崩溃族三处实现与其语义**
  | 地址 | 形态 | 语义 |
  |---|---|---|
  | `0x0047C4D0` | `ret 8`，2 参数 | 在链 A/B 里找 `WhatAmI()==wanted` 的第一个对象（wanted 来自 `[esp+0xC]`） |
  | `0x0047C520` | `ret`，0 参数 | 在链 A 里找 **`WhatAmI()==6`** 的第一个对象 |
  | `0x0047C550` | `ret`，读 `[esp+8]` | 第三处同族实现（**台账此前从未登记**） |
  - 三处入口共同守卫：`mov al,[0x00A8E9A0]; test al,al; je <skip>`（全局 bool，语义 `[未证]`）。
  - 逐指令原文见 `LEAD_FINDINGS_R09.md` L1；关键 4 条：
    - `0x0047C52A  8bb1e4000000  mov esi,[ecx+0xE4]` **PASS**（mem disp 实测 `0xE4`）
    - `0x0047C538  ff502c        call [eax+0x2C]` **PASS**（`eax=[esi]`=节点 vptr）
    - **next 指针 = `+0x30`**（`0x0047C540 / 0x0047C504: mov esi,[esi+0x30]`）
    - **`+0xE4` 与 `+0xE8` 是两条独立对象链**（`0x47C4D0` 按第 2 参数切换）⇒ **任何只处理 `+0xE4` 的摘链逻辑都会漏链**
    - 链终止 = `NULL`（`test esi,esi / jne`），**非环、无哨兵**（限这两个函数）
    - `0x000A0008 + 0x2C = 0x000A0034` **MATCH**（与 S1 `except.txt` 的 Access address 逐位一致）
- **§636-2 [已证·勘误 §629-3]** §629-3 写「`0x0047C4D0`（`ret 8`，wanted-id=`0x24`）」——**`0x24` 不是常量，是函数参数**（`0x0047C4F5: mov edi,[esp+0xC]`，`0x0047C500: cmp eax,edi`）。凡引用"该函数找 0x24 类"须按此重读。
- **§636-3 [已证] 虚表普查与 WhatAmI 阶梯**：`.rdata 0x7E1000..0x812000` 内「连续可执行指针游程」 **939** 条，其中 **112** 条槽 11 可解 `mov eax,N;ret`；N 覆盖 **1..73**（缺 31/52/58/64），另有 **40 条假阳性**（N 为 `8489908` 类巨值，实为别的 getter 返常量）。
  - 锚点 **PASS**：vtable `0x007EB058` 槽 **107** = `0x0051BF90` 精确命中；该 vtable 槽 11 = `0x00523340` ⇒ 该类 `WhatAmI()` = **15**。`WhatAmI()==6` 的 vtable = `0x007E3EBC`（槽 11 = `0x00459EC0`）。
  - **重要限制**：游程是"最大连续可执行指针段"，**相邻 vtable 会被合并**，游程起点的槽 11 只反映第一个 vtable ⇒ **该表不能当"合法 vptr 起点全表"**（会漏，造成哨兵假阳性），用途限定为已知起点的 WhatAmI 反查 + 疑似值二次确认。
  - `[未证]` 类 ID 6 的真实类名。类 ID **不是** 0..7 线性梯队（上锚给 15）⇒ 按公开枚举"Unit=6"的猜测**无依据，不采**。另：§623-ERR-3 称 `0x51BF90` "由 RTTI 定" 而 §629-2 已证**镜像无 RTTI**，两条必有其一措辞有误（本条只保证字节事实）。
- **§636-4 [已证·判读转折] 三处函数 `call rel32` 调用点共 149 处**（`0x47C520` **134** / `0x47C550` **9** / `0x47C4D0` **6**）；`.rdata` 数据项引用 **0 处** ⇒ 它们**不是虚函数**，是通用访问器。
  - ⇒ **崩溃点 `0x0047C538` 不是"某具体引擎操作的专属故障点"**：它只是 149 个可能踩到同一条坏链的入口之一，**谁先踩到纯属时序偶然**。
  - ⇒ **崩溃点位置不得用于归因**。② 的诊断必须走**状态侧**（谁把链弄坏），不能走**代码侧**（哪个函数崩的）。这与 §629-3"机制至少 3 个不得合并"一致，并解释了 §623-ERR-3 那次误判的根源。
- **§636-5 [已证·负结果·Lead 自身方法失败]** `0x00A8E9A0` 守卫的读写普查**方法失败、结果作废**：在字节流里搜 imm32 后"向前回退 1..15 字节猜指令起点"**没有唯一性**，产出 `sbb eax,0xa8e9a0` / `adc eax,0xa8e9a0` 这类跨指令垃圾（37 个"读点"全废、0 个"写点"、86 处未定位）。
  - **不产出任何关于 `0xA8E9A0` 语义的结论。**
  - 教训（与 §636-6 同源）：**"在字节流里搜常量"不能替代"按指令边界解码"**。正确做法：先线性扫描并对函数边界做验证（`ret`/`int3`/`nop` 填充切段，遇无效编码标"边界未定"而非静默跳过），再在**已验证边界集合**上做操作数匹配。
- **§636-6 [已证·方法学] 线性反汇编的起始地址必须是已证实的指令边界**：我以 `0x0047C4C0` 起解，capstone **静默返回 0 条**。根因：首字节 `c6 5f 5e` 中 `C6` 的 modrm `reg` 位必须为 `/0`，而 `0x5f` 的 reg=3 ⇒ **非法编码**，起点落在前一条指令中间。真函数入口在 `0x0047C4D0`（上一函数 `ret 0xC` @ `0x47C4C7` + 6 个 `0x90` 之后）。
  - ⇒ **空结果极易被误读成"这里没有代码"**。**先证边界，再解语义。**
