## 2 · W105 裁决：**采信**，且它的核心否定结果 **证伪了 Lead 的 UAF 强假设**

### 2-1 Lead 亲验 `0x0047EA90`（完整摘链函数）—— 逐条反汇编

```
0x0047EA90  sub esp,0xc ; push esi ; mov esi,[esp+0x14]   ; esi = node（待摘对象）
0x0047EA99  mov edi,ecx                                    ; edi = this（cell）
0x0047EA9B  test esi,esi ; je 0x47EB8F                     ; node==NULL 直接出
0x0047EAA3  mov cl,[esp+0x1c] ; test cl,cl                 ; 第 2 参数：选哪条链
0x0047EAAB  mov eax,[edi+0xE8]      (cl≠0 → 链 B)
0x0047EAB3  mov eax,[edi+0xE4]      (cl=0 → 链 A)
0x0047EAB9  cmp eax,esi ; jne 0x47EAD7                     ; 链头 == node ?
0x0047EAC1/CC  mov eax/ecx,[esi+0x30]                      ; next = node->next
0x0047EAC4/CF  mov [edi+0xE8 or +0xE4],eax/ecx             ; 链头 ← next（摘头）
0x0047EAD7  test eax,eax ; je 0x47EAF7                     ; 空链 → 跳过
0x0047EADB  mov ecx,[eax+0x30] ; cmp ecx,esi ; je 0x47EAEA ; 遍历找前驱，直到 prev->next == node
0x0047EAEA  mov edx,[esi+0x30] ; mov [eax+0x30],edx        ; prev->next = node->next（摘中）
0x0047EAF0  mov dword [esi+0x30],0                         ; 被摘节点的 next 置 0
0x0047EAF7  mov eax,[esi] ; call [eax+0x2C]                ; WhatAmI()
0x0047EAFE  cmp eax,0xF ; je 0x47EB8F                      ; == 15 → 直接返回
0x0047EB0B  call [edx+0xC0]                                ; 某谓词
0x0047EB19  call [eax+0x2C] ; cmp eax,6                    ; 再判 ==6
```

**判定：这是一个写得完整的摘链函数。**

### 2-2 **UAF 强假设被证伪（`[已证]`）**

Lead 在派 W99 时的强假设是：
> 「建筑被摧毁后**没有**从某些 `CellClass+0xE4` 链里摘掉 ⇒ 内存回收复用后首 dword 变垃圾」。

**被证伪，三条独立理由**：
1. **摘链存在且完整**：同时处理"是链头"（`0x47EAC4/CF`）与"在链中"（`0x47EADB–0x47EAEA`），摘后 `next` 置 0。
2. **两条链都支持**：按第 2 参数选 `+0xE4` / `+0xE8`，不存在"只摘 A 不摘 B"的缺陷。
3. **没有"无条件整链替换"**：W105 普查 114 条 A 类写点，唯一形似 `head ← [this+0x30]` 的**两条全在 `head==this` 守卫之后**（W105 首版脚本误标"不比较 this"，已自行勘误）。Lead 亲自复核该函数，确认守卫存在。

### 2-3 W105 的普查质量（采信依据）

- 解码 **1,394,120** 条指令；无效编码仅 **64 处 / 66 字节**（覆盖率实质完整）。
- **自检对着 Lead 的 L1 三条全 PASS**（`0x47C52A` / `0x47C4E3` / `0x47C538`）。
- 修掉了 W99 的**两个**方法缺陷：① 只扫 SIB 形式（W105 补了 modrm-disp32：A 类里 **112/114 是非 SIB**）；② 未排除 `esp/ebp` 基址（C 类 229 条，其中写 76 / 读 153 —— 正是 W99 假阳性的主体）。
- 额外加了"是否正在装虚表"判据，剔除 **19 条他类构造**（A 类 114 → **真候选 95**）。Lead 实读 `0x004358A9` 那条正是反例（紧跟 `mov [esi],0x7e3ad0` 写虚表）。

### 2-4 `[已证]` 条件摘链与头插形态（W105 报，Lead 抽验 1 条）

- **条件摘链 4 处**：`0x436A2D` / `0x62FEFE` / `0x678874` / `0x6F105D`（形态 `cmp [同字段],X; jne; store`）。Lead 实读 `0x00436A25–0x436A2D`：`cmp [esi+0xE4],edi; jne; mov [esi+0xE4],eax` —— 确认。
- **头插形态**：`0x47E90B/0x47E91F`（`[ebp+0x30] ← esi`，然后 `head ← ebp`）。
- 这两者合起来说明链表维护是"标准头插 + 标准删除"，**没有偷懒写法**。

### 2-5 `[未证]` 仍存在的关键缺口（W105 自认，我采纳）

- **95 条真候选里，没有一条能静态证明 base 就是 `CellClass`**。同偏移撞车的实证：`0x74CE4C` 写 `0xFFFFFFFF`、`0x721A44` 写 `12`、`0x62F1E9` 写 `0x40000000`、`0x60Dxxx` 写规则全局指针。
- ⇒ **`+0xE4` / `+0xE8` 是"通用偏移"，不是 `CellClass` 专属标记。** 本条对后续所有卡片都是硬约束：**凡按偏移搜"cell 链头写点"的做法，都必须额外证明对象类型，否则清单不可用。**
- W105 的最终判定：**UAF 假设「静态无法判定」** —— 摘链机制存在 ⇒ 不能支持；但候选无法定型 ⇒ 也不能推翻。**Lead 裁决：比 W105 更严 —— 按 §2-2，就"忘记摘链"这个具体形态，可以判「推翻」；UAF 的其它形态（重复摘、遍历期失效、摘错链）仍未排除。**
