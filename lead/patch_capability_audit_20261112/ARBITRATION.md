## 3 · 我亲自复算的关键事实（仲裁依据，不依赖任何一方自述）

### 3.1 `ra2opt` 的构建身份门到底有没有

```
Select-String -Path "ra2opt\*.py" -Pattern 'KNOWN_GAMEMD|def identity|identity\('
```

实测引用点**只有 4 处**：

| 位置 | 性质 |
|:--|:--|
| `__init__.py:19` | 字典定义 |
| `game.py:104` | `def identity(self, name)`，L117 用 `KNOWN_GAMEMD.get(text_sha)` 查表 |
| `audit.py:109` | 只读体检调用 |
| `cli.py:308-310` | `seed --verify` 调用 |
| `optimize.py:344` | **在 `status()`（L338-356）内**，只读状态查询 |

**关键**：`optimize.py` 的 `apply()` 函数范围是 **L112–L327**（下一个顶层 `def` 是 L328 `verify`）。L344 在 **`status()` 里，不在 `apply()` 里**。
⇒ **`apply()` 全函数体从不调用 `identity()` / 查 `KNOWN_GAMEMD`**。`apply()` 入口只校验 `profile ∈ PROFILES`（L118-119）与 `g.valid`（目录里有 `gamemd.exe`，L122-123）。
⇒ **「未知构建拒绝安装并输出原因」= 规范要求、仓库无实现。** 两版结论一致，我独立确认。

**必须分开的两件事**（这是仲裁要点）：
- **能识别**：`identity()` 能用 `.text` sha 认出版本 —— **有**（且基线可对证，见 §4）
- **会拒绝**：`apply()` 在身份未知时拒装 —— **没有**

## 5 · 教训（写进派发纪律）

1. **重派前必须先确认前一个 worker 真的死了**。「25 分钟零落盘」不等于死亡——本轮 WP-K 只是长推理，后来活了并落了盘。**判据应改为：看进程是否仍在消费 + 看是否有近期文件写入，而不是只看时长。**
2. **写域互斥必须由调度方记账**，不能靠「我派了不重叠的任务」这个假设。本轮 12 个写域里，只有这一个被重复占用，恰好就是这个「重派」的包。
3. **子代理侧的处置是对的**：发现被覆盖 → 不丢对方成果（复制保留）→ 上报仲裁。这套动作值得固化成任务书标准条款。
4. **两个 worker 同域时，最终盘面是「最后写入者胜」**，中间态会丢。因此**重派的包必须换写域**（例如 `_v2` 后缀），而不是复用原目录。
