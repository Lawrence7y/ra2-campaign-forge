## 2.114 R110（2026-11-24）· COM 暴露面：172 个类的 QI 认 17 个 IID（6 个是标准 OLE 接口，5 个与 RTTI 类名互相印证）；COL.offset 的可证伪预测 12/12 命中；「第二套函数边界」判为不存在

### 2.114.1 本轮定位：R109 留下的两条「已确定判据、未做推论」的线

R109 §EK 把 slot0 = QueryInterface 用构造性字节特征定了下来（repe cmpsd + IID 比对 + 0x80004003/0x80004002），
但从没反查过「每个 QI 到底认几个 IID、这些 IID 是什么」。§EK9 的未取得项里第 ⑥ 条也留了一句
「32 位无 .pdata 已确认，但 __try/__except 异常处理表是否存在未查」。本轮就做这两条，
外加一条对 R109 自身数字的复核（起因是本节 2.114.6 的正则缺陷）。

### 2.114.2 COM 暴露面：172/954 个类的 QI 认 17 个 distinct IID

判据（构造性，逐条可复核）：slot0 函数体头 120 B 内按序出现
`mov ecx,4` → `mov edi,<imm32>` → … → `repe cmpsd`，且 imm32 必须落在 PE 数据节（节区间从 PE 头现读）。
实测 **172/954 = 18.0%**。

- 反控：随机 20000 个指令起点同判据同窗口命中 105（0.525%）⇒ **富集 34.3 倍**。
  进一步拆：这 105 里 78 个是「窗口漂进了已知 QI 函数头」（0.390%），说明基线高不是判据松。
- distinct QI **实现**只有 **90 个**（< 172 个类）⇒ 大量类共享同一实现（模板工厂族）。
- 每类认的 IID 个数分布：`1→1 类 / 2→92 类 / 3→3 类 / 4→76 类`，四项和 = 172。
- distinct IID 按指针 **17**、按 16 字节内容去重也 **17**（双射，无两个指针指向同一 GUID 内容）。
- 全部 17 个指针落在 `.rdata/.data/.detour`，**0 个**落在 `.text`。

17 个 IID 与标准 OLE 接口的对照（GUID 字节与类名是**两条独立证据**：前者在 slot0 的函数体里，
后者在 RTTI 的 TD 名字里）：

| 指针 | GUID | 认领类数 | 标准语义 |
|---|---|---|---|
| 0x7f7c90 | 00000000-0000-0000-C000-000000000046 | 171 | IUnknown |
| 0x7f7ca0 | 00000001-0000-0000-C000-000000000046 | 78 | IClassFactory |
| 0x7f7cf0 | 0000000C-0000-0000-C000-000000000046 | 1 | IStream → **CStreamClass** |
| 0x7f7cb0 | B196B287-BAB4-101A-B69C-00AA00341D07 | 1 | IEnumConnections → **EnumConnectionsClass** |
| 0x7f7cc0 | B196B286-BAB4-101A-B69C-00AA00341D07 | 1 | IConnectionPoint → **ConnectionPointClass** |
| 0x7f7ce0 | B196B285-BAB4-101A-B69C-00AA00341D07 | 1 | IEnumConnectionPoints → **EnumConnectionPointsClass** |

**四个 IID 的语义与其认领类的 RTTI 类名逐字对应**（右侧箭头），这是两条独立链的收敛，不是同义反复。
其余 11 个是自研 IID（尾 8 字节不是 `c000000000000046`，也不是 B196B2xx 家族），
其中 `170DAC82-12E4-11D2-8175-006008055BB5` 被 **76 个类**共同认领 —— 这是本镜像里最宽的私有接口。

### 2.114.3 一个假例外被查清：AircraftClass 是**经委托**认得 IUnknown

r110a 的 S7 报「172 个类里 1 个（AircraftClass）不认 IUnknown」。逐字节看它的 slot0（0x414290）
前 20 条指令就明白了：

```
0x414290 push ebx / mov ebx,[esp+8] / ...
0x4142a2 call 0x410260          ← 0x410260 是 AbstractClass 的 QI，体内比对 IUnknown
0x4142a7 test eax,eax / jge 0x4142e9
0x4142ab mov ecx,4 ; mov edi,0x7e9b40 ; repe cmpsd   ← 基类失败后才比自己的 IID
```

即派生类 QI = **委托基类 QI + 追加自己的 IID**。这是我判据的盲区（自错 L-04），不是语义反例。
按「直接 + 委托闭包」重算：**172/172 全部认得 IUnknown**（90 个实现里 89 个直接、1 个经委托）。
委托边全镜像只有 **1 条**，无环；反控随机 20000 起点同判据命中 3（0.015%）⇒ 富集 74.1 倍。

### 2.114.4 COL.offset 的语义：给一个能被证伪的预测，12/12 命中

R109 §EK4 只报了分布「COL.offset==0 占 942/954，其余 12 张全为 4」，把 12 张一句括注为「基类子对象」。
那只是**解释**，没做**预测检验**。本轮把 12 张的类名全部列出，全是 Locomotion 族
（Drive/DropPod/Fly/Hover/Jumpjet/Mech/Rocket/Ship/Teleport/Tunnel/Walk + 基类 LocomotionClass）。

可证伪预测：若 offset 语义是「该 vtable 在对象内的字节偏移」，则这 12 张的装配点必须是
`mov [reg + 4], <vtable_va>`。**实测 12/12 的 disp 全为 4**，且每个类有 2～6 个装配点、无例外。
反向（修正版，见自错 L-06）：offset==0 且有装配点的 846 张表里，**无任何 disp==0 装配点**的仅 51 张（6.0%）。
反控：全段 8240 个 `mov [reg+disp], imm32` 写入点里 disp==4 的只占 **5.52%**（455 个），
若语义为假，12 张全部落在 disp==4 的概率约 **8.0e-16**。

### 2.114.5 「第二套函数边界」判为**不存在**（R109 §EK9⑥ 未取得项）

三条独立判据，全部构造性：

- **SEH 链**：`.text` 内 `mov eax,fs:[0]` 14 处、`mov fs:[0],esp` 15 处、`push dword fs:[0]` 1 处、
  `mov fs:[0],eax` **0 处**；「取链头→挂帧」距离 <64 B 的成对点 **15 个**，落在 **6 个** HB 函数里
  ⇒ 覆盖 **6/17766 = 0.03%**。
- **C++ EH**：magic 0x19930520/21/22/10 在镜像内共 2 处对齐命中，只有 **1 处**满足完整 FuncInfo 形态
  （magic + 紧随 3 个 0 + 后续指针落在数据节）：`0x87c1d0` 在 `.data`。
  另一处 `0x7f993c` 在 `.rdata`，紧跟的是星期字符串 `4d6e7553`("SunM")，判为**字节巧合**。
  `.text` 内那处 `0x7d9f7e` 周边全是立即数，同样是巧合。
- **引用**：`.text` 中指向该唯一 FuncInfo 的立即数引用 **3 条**（0x7cb3a6 / 0x7cc1ab / 0x7cc1b4）。

三者都远不足以当边界源 ⇒ **本镜像只有一套现成函数边界（HB），没有第二套**。
这不是「没找到」，是「算了三条路，每条都给不出量级」。

### 2.114.6 复核 R109 的 E3b/E3c：一条正则缺陷，总数对、分类全错

起因：本轮 r110d 第一稿的位移正则写错（自错 L-05），排查时发现 R109 的
`_r109/r109a_attr.py`、`r109e_container.py`、`r109f_vtmodel.py` 三处用的是同一条正则：

```
^(?:dword ptr )?\[([a-z0-9+* ]+)\](?: \+ (0x[0-9a-f]+))?, (0x[0-9a-f]+)$
```

其字符类 `[a-z0-9+* ]` 含空格与 `+`，贪婪匹配会把 `"esi + 0x15c"` 整段吞进 group(1)，
于是 group(2)（位移）恒为 `None` ⇒ **disp 恒为 0**。量化：4611 条装配点里 group(1) 含空格的 **5131 条**（含全部写入点形态）。

后果（实测，不是推断；分桶口径见下）：

| 口径 | 数值 |
|---|---|
| R109 报「写偏移 0」 | 2762 |
| R109 报「非 0 偏移」 | 1849（实际是 4611 − 2762，不是位移） |
| **正确分桶**：裸寄存器基址装配点合计 | **4271** |
| ├ 其中 disp==0 | **2774** |
| ├ 其中 disp≠0 | **1497** |
| 绝对地址 `[0x87e73c], vt` | **340** |
| 负位移 `[eax - 8], vt` | **5** |
| **装配点总数** | **4616** |

**注意两个「2762」不是同一口径**（本轮自错 L-14）：
R109 的 2762 是「基址字面值恰好是 7 个经典寄存器之一且 disp 为 0」；
本轮正确分桶里 disp==0 的是 **2774** —— 多出的 12 条是 `[esp], <vt>`（直接压栈写入，基址是 esp，
R109 的白名单里虽含 esp 但其正则把它们导向了别的桶）。两者差 12，引用时不得混用。

即：**总数 4616 = 4271 + 340 + 5**；而 R109 报的 4611 = 4616 − 5（旧正则字符类不含 `-`，
5 条负位移一条没进）。**R109 的总数凑巧接近，但「2762 / 1849」这个二分是假的** ——
1849 里混着 1497 条真非零位移与 340 条绝对地址写入，二者语义完全不同
（前者是 this 内偏移，后者是全局对象地址）。

受污染的具体结论：
- §EK4④ 的「写 `[reg+0]`=vt 的点 2762 / 非 0 偏移 1849」→ 应为 **2774 / 1497 / 340 / 5**（四桶，合计 4616）。
- §EK4④ 的「写 `[reg+0]`=vt 后同 reg 又被 `[reg+disp≠0]` 读 = 1304/2438（53.5%）」
  → 正确判据（正确正则 + HB 硬边界）为 **1478/1637 = 90.3%**。
  差异分解：`1304→1478` 来自边界由「遇 ret 即停」（R109 自证是错判据 P）换成 HB；
  `2438→1637` 来自分母由「基址非纯寄存器的写入点」换成「真装了 vt 的函数」。
  反控：随机 20000 起点所在 HB 段含「写 `[reg+0]`=vt」的占 12.71% ⇒ 富集 7.1 倍。
- **方向不变**：vt 位于 this+0 这个结论**加强**了（53.5% → 90.3%），不是推翻。
  但引 R109 §EK4④ 时必须改用新数字，或直接引本条。

### 2.114.8 自错 13 处（全部由断言当场抓住）

- L-01 `iids_of` 在 `mov edi,imm` 处重置 `ecx4`，致 954 个 slot0 全抽空（S2 报 0/954）。
- L-02 反控窗口用 700 B，随机起点漂进真 QI 体，基线虚高到 1.895%（富集仅 9.6 倍）。限头 120 B 后 0.525%。
- L-03 把 PE 里的 **RVA** 当 VA 硬编码 `DATA` 区间致 `0x7f7c90` 被判「不在数据节」（S3 假 FAIL 173 条）。改为从 PE 节表现读。
- L-04 判据盲区：派生类 QI **委托**基类 QI，致 S7 假报「1 个类不认 IUnknown」。
- L-05（三次）位移正则：① `[a-z0-9+* ]` 贪婪吞 `+ 0x4` ⇒ disp 恒 0；② 只认 `0x` 前缀漏十进制位移 ⇒ 装配点 4611 掉到 4138；③ 同时认两种格式后仍未覆盖绝对地址。
- L-06 反向预测写错：「offset==0 的表装配 disp 必须全为 0」实测 208 张违例。不是语义被否证，是 vtable 可被写进**成员子对象**的偏移处。
- L-07 断言写成「原正则的 at0 虚高」，实测 at0_old == at0_new == 2762（必然相等，因判据与 disp 无关）。
- L-08 r110f 只取 `mov eax,fs:[0]` 作取链头，漏 `push dword fs:[0]`，致 SEH 对数 15→14、函数 6→5。
- L-09 断言「json 里 iunk_share 字段存在」—— 实测不存在，**审计员说的是对的**。
- L-10 漏掉绝对地址写入 `[0x87e73c], vt`（340 条）= 4616 − 4271 − 5 的差额。
- L-11 把「解析覆盖率 ≥99%」当不变量。实测 93%，剩下 680 条是负位移/比例变址。正确不变量是「未解析形态里无 vtable 写入」。
- L-12 上一条的不变量实测仍有 **5 条** vtable 写入落在未解析形态里，全是负位移 `[eax - 8], 0x7e192c` 等。
- L-13 断言「装配点总数 == 4611」，实测 4616。R109 的 4611 是它旧正则数的，而旧正则字符类不含 `-`，5 条负位移一条没进。
