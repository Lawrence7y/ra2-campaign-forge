## 一、方法：变异测试，不是再数一遍

「断言有没有真的读那个量」不能靠读代码判断 —— 我上一轮已经在这上面栽过两次
（G-52 把编译器优化当规则、G-53 把供给方当消费方）。所以改成**实测**：

给门禁加一个环境变量钩子 `R032_MUTATE=VA=BYTE`，在**内存副本**里翻转一个字节
（磁盘上的 exe 不动），然后重跑门禁，看**哪条断言变红**。
一条断言若声称测量 X，而改动 X 所在的那个字节它**不变红**，它就是装饰。

```python
# verify_r032_claims.py
MUTATIONS = {}
_parse_mutations(os.environ.get("R032_MUTATE", "").split(","))
for _va, _byte in MUTATIONS.items():
    _fo = _va_to_fileoff(_va)
    if _fo is None:
        raise SystemExit(f"mutation target 0x{_va:08X} is not disk-backed")
    _RAW[_fo] = _byte
```

`_va_to_fileoff` 按段表判界，BSS 目标直接报错退出（而不是静默改到别处）。

## 二、结果：5/5 killed

| 变异 | 改了什么 | 预期变红 | 实际变红 | 判定 |
|:--|:--|:--|:--|:--|
| `ReadString ret 0x14 → 0x10` | `0x528BC7`，arity 5→4 | P2 | **N2, P2** | ✅ KILLS |
| `GetKeyCount call → NOP` | `0x672372`，删掉一次枚举调用 | P3, P4, P6 | **P3, P4, P6** | ✅ KILLS |
| `je → jmp`（值门控失效） | `0x6723AA`，`74`→`EB` | P7 | **P3, P7** | ✅ KILLS |
| `<none>` 字面量破坏 | `0x817474`，首字节→NUL | P8 | **P8** | ✅ KILLS |
| `[General]` 键字面量破坏 | `0x83CF2C`，首字节→NUL | P5, P10 | **P5, P10** | ✅ KILLS |

**P1 已从统计中排除**：它哈希**整个文件**，任何变异都会让它红。
保留它会让每个用例都"看起来被杀"，反而掩盖真正不读量的断言。
这不是放宽，是去掉恒真噪声（同 G-46 的恒真式教训）。

**两条附带信息**（好迹象，不是问题）：
- `ret 0x14→0x10` 同时打红 **N2** —— 负控确实在监视 arity 判定不是常数。
- `je→jmp` 同时打红 **P3** —— P3 独立地在测同一段"读值→注册"链路。

## 三、自审发现并已修掉的三条装饰性断言

变异测试**之前**我先按「哪个字节变了会让它红」逐条自查，抓到三条。
它们有一个共同形状：**拿一个下界或"不等于"去比，而不是断言实测值**。

### 3.1 P5 原来写 `n_fixed != 5`

```python
check("P5", n_fixed != 5, ...)      # ← 旧
```

**缺陷**：如果提取器彻底坏掉、`n_fixed` 变成 **0**，这条**照样通过**。
它只否证了「等于 5」，没有证明「等于 15」。而 H-015 被推翻的核心正是**15 这个值**。

```python
check("P5", n_fixed == 15 and n_keys == 660, ...)   # ← 新
```

### 3.2 P6 原来写 `len(A) + len(B) == 20`

```python
check("P6", len(counts["A"]) + len(counts["B"]) == 20, ...)   # ← 旧
```

**缺陷**：**20 + 0 也等于 20**。如果分族判据坏掉、所有 loader 全落进 A，
这条依然绿 —— 而它的名字叫「分成两族」，恰恰没测"分成"。

```python
check("P6", len(counts["A"]) == 17 and len(counts["B"]) == 3 and not counts["C"], ...)  # ← 新
```

### 3.3 P3 原来写 `len(STAGE_SITES) >= 15`

**缺陷**：下界断言。若某个 loader 的站点解析失效、从 16 掉到 15，仍然绿。
实测稳定在 16，就该钉 16。

```python
check("P3", not stage_bad and len(STAGE_SITES) == 16, ...)   # ← 新
```

**三条改完后仍全绿**（说明原来的测量是对的，只是断言写得松）。
这正是 S388 那句的实例：**测量对 ≠ 断言硬**。

## 四、诚实清点：13 条里几条被变异验证过

| 断言 | 是否被变异杀死 | 说明 |
|:--|:--|:--|
| P1 sha256 | ❌ 不适用 | 恒真式（任何改动都红），已从统计排除 |
| P2 arity | ✅ 被 `ret 0x14→0x10` 杀死 | |
| P3 注册的是值 | ✅ 被 `je→jmp` 与 `GetKeyCount→NOP` 两次杀死 | |
| P4 20 个枚举 loader | ✅ 被 `GetKeyCount→NOP` 杀死 | |
| P5 15 个 loader / 660 站点 | ✅ 被 `[General]` 键字面量杀死 | |
| P6 17:3 分族 | ✅ 被 `GetKeyCount→NOP` 杀死 | |
| P7 值门控 | ✅ 被 `je→jmp` 杀死 | |
| P8 `<none>` 挡板 | ✅ 被字面量变异杀死 | |
| P9 `0x889F64` 是 BSS | ❌ **未验证** | 见下 |
| P10 660−9=651 | ✅ 被键字面量杀死 | |
| N1 负控（MP 不在枚举集） | ❌ **未单独验证** | 与 P4 同源 |
| N2 负控（arity 非常数） | ✅ 被 `ret` 变异杀死 | |
| N3 负控（闭包 > 线性） | ❌ **未验证** | 见下 |

**⇒ 13 条里 8 条被变异杀死，1 条是恒真式，4 条未验证。**

未验证的四条我**不宣称**它们已被证明有效，逐条说明原因：

- **P9**（`0x889F64` 是 BSS）：变异目标必须在盘上有字节；BSS 恰恰没有字节，
  所以「改一个字节看它红」这个方法对它**结构性不适用**。
  它需要另一种负控（例如把段表边界改错，让它读到 `.data` 尾部）—— 本轮未做。
- **N1**（`Read_MultiplayerDialogSettings` 不在枚举集合）：它与 P4 同源，
  P4 被杀时它没红（因为 MP 本来就不在集合里，删掉 VehicleTypes 不影响它）。
  要单独验证需要另做一次针对性变异 —— 本轮未做。
- **N3**（闭包 5069 > 线性 5062）：它比的是两个**自身计算结果**，
  没有外部期望值可钉。要变异验证得改 `Read_General` 的冷块入口，
  使闭包等于线性 —— 本轮未做。
- **P1**：恒真式，已在 `mutate_r032_gate.py` 里显式排除并写明理由。

## 五、这一轮真正学到的一条

上一轮我在 G-53 写下「结论要追到消费方」。这一轮补上它的**对偶**：

> **断言要追到「哪个字节变了会让它红」。答不出来的，就是装饰。**

而且这条不能靠**读**代码判断 —— 我自查抓到的三条（P5/P6/P3）都是读了才发现的，
但"读了才发现"本身也证明我上一轮写完就没做这件事。
真正把问题逼出来的是**变异**：`GetKeyCount → NOP` 这一刀，
我原本预期它杀 P6、以为 P4 会活（因为 GetKeyName 还在），实测**两个都死了**；
而我前两次尝试（retarget 到 GetSection、retarget 到 ReadString）**两个都没死** ——
如果只靠推理，我会得出"P4/P6 是装饰"的错误结论。**是实测纠正了预期**。

⇒ 新增 **G-54** + 纪律 #44。

## 七、诚实边界

- 5 个变异只覆盖 5 条断言，**不是 13 条的完整验证**（见 §四）。
- 变异只翻**一个字节**，无法证明"断言对任何改动都敏感"，只能证明"至少有一个字节能让它红"。
- 本轮**未**做 P9 / N1 / N3 的替代负控，如实标为"未验证"。
- 门禁与变异驱动都只读 exe；变异作用于内存副本，磁盘文件未改（P1 基线每轮复验 sha256）。
- 全部结论绑定 sha256 `73201cc0…f67476`。
