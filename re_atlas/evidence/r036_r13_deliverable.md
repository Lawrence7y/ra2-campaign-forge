### 2.1 69 这个数的口径（P6）

R-035/STATUS 写「69 个源文件」。实测 `__FILE__` 去重后是 **74** 个不同 basename，
其中 **5 个文件的全部站点都落在任何入口闭包之外**：

| 零归属文件 | 站点 |
|:--|--:|
| `CD.CPP` | 1 |
| `Event.CPP` | 7 |
| `GameDlg.CPP` | 1 |
| `Score.CPP` | 8 |
| `stlscore.cpp` | 2 |

74 − 5 = **69**。所以「69 个源文件」的准确说法是**「至少有一个站点能归属到函数的源文件数」**，
不是「镜像里有 69 个源文件」。这个区别在引用时会咬人：若拿 69 当分母算「覆盖率」，
分母少 5 个；若拿它当「这个构建包含哪些 .cpp」，则漏掉 5 个。

### 2.2 17 个函数（P5）

六种（入口集 × 归属规则）组合里，三种给 17、一种给 18、一种给 23：

| 组合 | 函数数 |
|:--|--:|
| `flat\|T2` + 最早入口优先 | **17** |
| `flat\|T2` + 首次命中 | **17** |
| `LOWER+UPPER` + 首次命中 | **17** |
| `flat\|T2` + 最小闭包 | 18 |
| `flat\|T2` + 全部所有者 | 23 |
| `LOWER+UPPER` + 全部所有者 | 18 |

17 在三路独立口径下稳定，可以引用。清单见交付件 §A。

**一个必须记录的坑**：`RadarClass::One_Time` 的 push 站点在 `0x652CF3`，
函数体在 `0x652CF0`，但「最早入口优先」把它归给 `0x63F7B0` ——
因为 `0x63F7B0` 是 `jmp 0x652CF0` 的**尾调用 thunk**（`e9 3b 35 01 00` + 11×`90`），
地址更早。两者指向同一函数体。交付件登记入口地址，**不据此断言函数本体地址**。

## 三、**不可复现**的量：R-035 §六 的 761

R-035 §六 报：

```
path 425 | format 147 | text 289 | ident 277 | debug 合计 761
```

本轮在 **12 种（入口集, 归属规则）组合**下实测 debug 归属：

| 入口集 | 规则 | path | fmt | text | ident | debug |
|:--|:--|--:|--:|--:|--:|--:|
| flat\|T2 | 最早入口优先 | **425** | 146 | 288 | 274 | 758 |
| flat\|T2 | 首次命中 | 425 | 146 | 288 | 274 | 758 |
| flat\|T2 | 最大闭包 | 422 | 146 | 288 | 274 | 755 |
| flat\|T2 | 最小闭包 | 464 | 163 | 305 | 304 | 838 |
| flat\|T2 | 丢嵌套所有者 | 458 | 172 | 317 | 296 | 822 |
| flat\|T2 | 丢嵌套+唯一 | 405 | 135 | 278 | 268 | 730 |
| flat\|T2 去嵌套 | 全部所有者 | 456 | 170 | 315 | 296 | 818 |
| flat (15,224) | 首次命中 | 409 | 136 | 258 | 253 | 707 |
| LOWER+UPPER (14,242) | 首次命中 | 415 | 145 | 285 | 271 | 744 |
| LOWER+UPPER | 最小闭包 | 422 | 154 | 293 | 291 | 770 |
| LOWER+UPPER | 丢嵌套所有者 | 432 | 163 | 307 | 289 | 788 |
| flat\|T2 | 走查顺序 pop | 440 | **147** | 291 | 279 | 779 |

**结论**：
- `path = 425` 在「最早入口优先」下**精确复现**（两种 seed 顺序都给 425）。
- `format = 147` 在「走查顺序 pop」下精确复现，但那种口径下 path 是 440，不是 425。
- **没有任何一种闭包口径同时命中 425/147/289/277/761**。最近的是 758（差 −3）。

### 3.1 R-036b 追加：地址类规则命中**合计** 761，但四列不符

上表全部是**闭包类**规则（用 CFG 闭包判定归属）。补测**地址类**规则（按地址取最近前驱入口）：

| 入口集 | 规则 | path | fmt | text | ident | debug |
|:--|:--|--:|--:|--:|--:|--:|
| `roots_call\|T2` (14,238) | 最近前驱**且**闭包包含 | 418 | 149 | 290 | 289 | **761** ✅ |
| `roots_call\|T2` | 最近前驱（不判闭包） | 454 | 175 | 315 | 317 | 826 |
| `roots_call\|T2` | 最近前驱 + 回退找包含者 | 421 | 153 | 292 | 290 | 769 |
| `roots_call\|heads` (14,242) | 最近前驱且闭包包含 | 419 | 149 | 290 | 289 | 762 |
| `flat` (15,224) | 最近前驱且闭包包含 | 457 | **147** | 269 | 283 | 789 |
| `flat\|T2` (16,110) | 最近前驱且闭包包含 | 473 | 156 | 299 | 304 | 841 |

**合计 761 精确命中**，入口集 `roots_call | T2` = 13,352 + 886 = **14,238**
（这个数不是凑出来的：另一条独立构造 `flat_dn | heads` − 5 也给 14,238）。

**但四列不符**：418/149/290/289 vs R-035 的 425/147/289/277。差值集中在
ident **−12** 与 path **+7** —— 两个方向相反，不像是同一个偏移。

**显著性检验**：21 种（入口集 × 规则）组合里**只有 1 种**命中 761。
但该命中**不是刀锋**：随机删 T2 候选 1/2/5 个，结果仍是 761；
删 10 个 → 760，删 20 个 → 759–760，删 50 个 → 755–759，删 100 个 → 752–756。
随机删 roots_call 1/5 个 → 760–761。⇒ 761 是这个口径下的**稳定值**，不是巧合。

**判定**：**合计可复现，分列不可复现**。可能的原因（均未验证）：
R-035 的分类器把某些串分进了不同类（ident vs path），或对 INI reader 包装函数
做了额外排除。**没有证据**能判定是哪一种，所以不采用该规则，只登记。

**为什么不采信合计命中**：四列同时不符时，合计相等只能说明两类误差相互抵消，
不能说明规则正确。若拿它去改写 R-035 §六，会把 425/147/289/277 四个可核对的
数字换成 418/149/290/289 —— 用「一个总数对」换「四个分项错」，是净损失。


### 为什么不能「修到 761」

要凑到 761 就得挑一个口径，而口径选择会同时改变 path（425 → 440 或 464），
即**用一个可复现的数换掉另一个**。这是 G-56 的变种：**没有独立证据能判定哪个口径是
R-035 当初用的**，因为 R-035 没把归属代码落盘（只在 `verify_r035_claims.py` 里
验了站点计数，没验函数归属）。所以只能登记，不能「调参到对」。

### 同源的第二个不可复现量

R-035 §2 引「426,741 个地址、40% 重叠」。本轮实测：

| 入口集 | Σ闭包 | 并集 | 超出 | 超出/并集 | >1 所有者的地址 |
|:--|--:|--:|--:|--:|--:|
| flat\|T2 (16,110) | 1,596,441 | 1,073,260 | **523,181** | **48.7%** | 228,884 |
| flat (15,224) | 1,529,944 | 1,019,137 | 510,807 | 50.1% | 222,419 |

两个入口集都给 51 万量级 / 49–50%，与 R-035 的 426,741 / 40% 不符。
**该数字同样不可复现**，一并登记。它不影响任何结论（重叠率只是「为什么要去嵌套」的
动机描述），但**引用时必须重算，不能照抄**。

## 四、变异测试：6/6 精确杀死

判定用**精确集合相等**（`red == expect`），不是「命中一条就算」。理由：若用后者，
任何触发 P1（全镜像哈希）的变异都会「杀死」所有断言 —— 这正是台账里
G-57「计数虚高：N/N PASS 本身无意义」的形态。

| 变异 | 预期红 | 实际红 | 判定 |
|:--|:--|:--|:--|
| 破坏 T2 锚点 `0x403A80` 序言 | P1,P2 | P1,P2 | ✅ KILLED |
| `__FILE__` push `0x410994` 不再 0x68 | P1,P3,P7 | P1,P3,P7 | ✅ KILLED |
| ident push `0x410A98` 不再 0x68 | P1,P3 | P1,P3 | ✅ KILLED |
| 纯名 `0x81C6D8` 的 `::` 破坏 | P1,P4 | P1,P4 | ✅ KILLED |
| 名字 push `0x652CF3` 不再 0x68 | P1,P4,P5 | P1,P4,P5 | ✅ KILLED |
| 单站点文件 `ToolTip.cpp` 唯一 push 移除 | P1,P3,P6,P7 | P1,P3,P6,P7 | ✅ KILLED |

**第 3 条是关键**：ident 类**不属于** debug 合计（path+format+text），
所以 P7 必须保持绿。实测确实只有 P1/P3 红 —— 这条验证了「四分类是分开数的」，
而不是「四个数一起动」。

**第 6 条也是关键**：`ToolTip.cpp` 只有 1 个站点（`0x724AFA`）。移除它，
该文件从「可归属」变「零归属」，69 → 68，而 basename 普查仍是 74。
这是唯一能杀死 P6 的变异；先前用 `AbsType.cpp`（2 站点）时 P6 不红，
因为还剩一个站点撑着 —— 与 R-035 变异测试里「P11 选错目标」同型（G-55）。

## 五、诚实边界

1. **17 个函数名未逐条验证「字面量 = 该函数的名字」。** `push 'Theme::Stop'`
   只说明这个函数**提到了** `Theme::Stop`，不排除它是日志里提到别人的函数。
   自洽的只有 `0x652CF3 push 'RadarClass::One_Time()'`（在 `0x652CF0` 体内）。
2. **归属规则是「最早入口优先」，这是选择，不是定论。** 选它的唯一理由是它复现了
   R-035 的 path=425；换规则 path 会变。交付件里所有函数地址都受这条规则影响。
3. **`0x63F7B0` 是 thunk 不是本体**（见 §2.2）。若下游需要函数本体地址，
   须再跟一次 `jmp`。
4. **761 与 426,741 的处置见 §3.1**：761 的**合计**在地址类规则下可复现且稳定，
   但四列不符，故不采用；426,741 完全不可复现。两者都不影响 R-035 的
   主结论（分母 13,352/14,242、覆盖率 4.10%/3.91%），那些是另外的门禁验的。
5. **未做异族盲验。** 本轮数字全由本线自写探针得出。按 §2 P0 纪律属新欠账。
6. **交付件 §D 有 5,882 行逐站点明细**，本报告不重复；复核任意一行请查
   `evidence/r036_r13_deliverable.txt` 的 §D。
