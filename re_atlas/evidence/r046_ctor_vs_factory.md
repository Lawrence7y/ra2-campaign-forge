# R-046 · L-4 残余定谳：`ScriptTypeClass` 双构造现场 = **plain ctor（0x6916B0）vs INI find-or-create 工厂（0x691C00）**

## 1. 结论

R-045 登记「两 ctor 变体（`0x6916C7`/`0x691C8B` 同型双零+清零）归属未定谳」——本轮定谳：
**两条是同一类 `ScriptTypeClass` 的两个入口，不是派生变体**：

- **C1 plain ctor** @`0x6916B0..0x69176C`：头 `mov eax,[esp+4]; push esi; mov esi,ecx(this);
  push eax; call 0x410800`（rel32 复算）——**census：体内 E8 目标集合恰={0x410800}**（唯一调用，
  无分配器）⇒ 构造器本体（new 由调用方完成）。
- **C2 INI find-or-create 工厂** @`0x691C00..0x691D41`：头后双串守卫
  `push '<none>'(0x817474)` / `push 'none'(0x817694)` → `call 0x7C8D20`（strcmp 形态助手，
  rel32 复算），命中即失败返回；否则按名扫注册表向量 `[0x8B41CC]`（`add ecx,0x24`
  = AbstractType Name 槽）比对，**未命中** `push 0x234; call 0x7C8E17`（分配包装头
  `6a01 ff742408 e8…` 钉死；0x234=GetSize）→ 新对象 `mov ecx,esi; call 0x410800`。
  现场紧邻 `"ScriptTypes"` 串（0x69197D 区）⇒ 这是 `[ScriptTypes]` 节解析的 find-or-create。
- **C3 同一类铁证**：两站共享 init 尾 **0x2F 字节逐字节相等**（[+0x9C]←0、[+0xA0]←0、
  主 vptr `0x7F1008` + 三 facet `0x7F0FEC/0x7F0FE4/0x7F0FDC`）⇒ vptr 组全同，**无派生变体**。
- **C4 注册表登记协议**：两站尾同型 `mov [esi+0x98],eax`（@0x691763/@0x691D26）——
  线性查自身于 `[0x8B41CC]`/`[0x8B41D8]` 后写下标 ⇒ 构造与工厂**都**把对象登记进
  ScriptTypes 注册表向量并把**下标存 +0x98**。
- **C5 dtor** @0x691770：`mov dl,1`（deleting 标志）→ 重装 vptr → `call 0x7258D0` →
  unregister：`[0x8B41D8]--`@0x6917BF + **SIB 压缩** `mov edx,[ecx+eax*4];
  mov [ecx+eax*4-4],edx`@0x6917CE/7D1（后项整体下移）→ `call 0x4109C0`（析构助手）。
- **C6 census 精确集合**：双零对 `{0x6916BD,0x691C81}`、`[reg+0x98],eax` 写
  `{0x691763,0x691D26}`——全区恰两处，与 C1/C2 一 ctor 一工厂吻合，**无第三形态**。

## 2. 顺带定谳的一处 R-045 疑点

R-045 把 `0x691A5B` 记成「初始化域第三形态（ebx 来源不宣称）」——本轮 census 证明

## 3. 诚实账（本轮抓到）

1. read 长度 vs hex 字节数不符**再次 ×2**（C3 0x35≠0x2F、C5 址 0x6917BD≠0x6917BF）——
   G-61 判据 2 第四次现场（R-044×2、R-045×2、R-046×2 连三轮同型！）。**教训升级：
   写窗口断言前必须先打印 hex 字节数再落 read 参数，两步并作一步=同一轮内先 dump 后写**。
   如实记录防线分工：这类长度错由**门禁首跑红**暴露（恒假即 FAIL），变异套件**抓不到**
   它（断言恒假时突变后仍假、rc=1 但不定位原因）——共享字节设计防的是预期集写错，不是
   长度错。唯一有效防线是先 dump 后写码的工序顺序。
2. 代码草稿残留 `if False else` 表达式两处 + `".hex()"` 误写——Write 后 grep 自查发现，
   落盘版清理；「草稿残留进交付件」新形态，靠跑前通读 stderr 输出发现。
3. C7 首版两守卫窗 hex 我加了空格分隔再 `.replace` 拼写绕弯——重写为纯 hex 串。
4. **C1 强化普查第一版踩 G-60 判据 2（切片双偏移混用）**：`e8_targets` 把 `tb`（已按
   `_fileoff(b0)` 切出段内容）又用**绝对文件偏移** `tb[fo]` 索引 ⇒ 普查集合错、C1 恒假
   FAIL；修正为整 `blob`+`fo`（单一寻址心智模型）。这是本线**第三次**踩同一条切片坑
   （R-041 双加段基址、本轮混用两种偏移）——G-65 的「判据连犯」在寻址子型同样成立。
5. 「散文声明升级为可杀 census」的正例：C1 原「全函数零分配调用」只是解读，现改为
   「ctor 体内 E8 目标集合恰={0x410800}」——G-57 精神的主动执行（不等被质疑再补）。
