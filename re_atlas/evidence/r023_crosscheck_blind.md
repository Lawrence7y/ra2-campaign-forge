# R-023 异族盲验（收窄版）

二进制：`ra2youli/gamemd.exe`（只读）。段表与题给一致，文件偏移用 `fo = 0x1000 + (va - 0x401000)`。
所有窗口均用「从已知指令边界链式解码」取得，未使用单次大段 `md.disasm()`。

## Q1 函数边界

- 结论：真尾 = **`0x0052D42F`**（`ret`，其后 `0x52D430` 已是另一个函数）。`0x52D30B` 那条 `ret` **不是**函数真尾，它只是一个落空时的出口。
- 证据（从 `0x52CD70` 链式解码，443 条指令，收在 `0x52D42F`，全程无解码断裂）：
  - 函数内共 4 条 `ret`：`0x52D032`、`0x52D0B3`、`0x52D30B`、`0x52D42F`（`ins[-1] = 0x52D42F ret`）。
  - `0x52D423 pop edi / 0x52D424 pop esi / 0x52D425 pop ebp / 0x52D426 mov al,1 / 0x52D428 pop ebx / 0x52D429 add esp,0x30c / 0x52D42F ret`
    → 与函数入口 `0x52CD70 sub esp,0x30c; push ebx/push ebp/push esi/push edi` 完全对称，返回值 `al=1`（成功），是主出口。
  - `0x52D430` 处字节 `8b442408 81ec80000000 ...`（`mov eax,[esp+8]; sub esp,0x80`），是一条全新的、用 `ret 0x10` 结尾的窗口过程式函数（在 `0x52D430..0x52D720` 内有 14 条 `ret`/`ret 0x10`）。
  - 交叉引用佐证：`0x52D0D3  push 0x52D430` 后接 `call dword ptr [0x7e13d4]`——`0x52D430` 是作为回调（对话框过程）地址被**当作数据压栈**传入的，不是被 `jmp`/`call` 直接进入。`0x52D430` 在全 `.text` 里**没有任何分支或 call 直接指向它**（全段 rel32/Jcc 扫描为空），只有这一处 `push imm32`（`0x52D0D4` 前一字节为 `0x68`）。
- **`0x52D30C` 之后是否同函数：是。** 理由：
  - `0x52D277  0f8e8f000000  jle 0x52D30C` —— 从函数主体内**正向跳入** `0x52D30C`，所以 `0x52D30C` 起的代码属于同一函数。
  - `0x52D245  0f85da000000  jne 0x52D325` —— 又一条正向跳转跨过 `0x52D30C..0x52D324` 直接进 `0x52D325`，说明 `0x52D30C` 那段是 `jle` 分支的专属块，`0x52D325` 是汇合点。
  - `0x52D325` 顺流而下经 `0x52D32D jle 0x52D357` → `0x52D357`（`push 0x82621C "AIMD.INI"`）→ `0x52D3D7` → `0x52D404` → `0x52D423` 弹栈收尾 → `0x52D42F ret`。
  - 也就是说：`0x52D30C` 与 `0x52D325` 之间无 `ret`，`0x52D325` 一路直落到 `0x52D42F`，中途不返回。`0x52D30B` 的 `ret` 只在 `jle` 未触发那次以外的情况被波及——它是 `0x52D2FF..0x52D30B` 那条弹栈尾的出口，属于**同一个函数的另一条退出路径**，不是终点。

## Q2 全局写入频次

- 每个全局是否都仍被别处写：**是，18 个全部**都在 `0x52D149..0x52D22C` 之外还有写入。最少的是 `0xA8B31E`（2 处：`0x5C4931`、`0x7972BB`），最多的是 `0xA8B262`（22 处）。
- 量级：严格「写」指令（`mov [abs],reg` / `mov [abs],imm` / `mov byte [abs],reg`，仅 `89/88/C6/C7` + ModRM rm=101 或 `A2/A3` moffs，排除 `cmp`/`push`/`test`）
  - 全 `.text` 共 **243** 处；
  - 其中批 1（`0x52D15B..0x52D22D`）= 18，批 2（`0x5B69FC..0x5B6B3D`）= 17；
  - **批 1 之外 = 208 处**（含批 2 的 17 处）。即「几十处~两百处」量级，单个全局通常 8~17 处。
  - 按簇（间隔 > 0x400 切分）看，除批 1/批 2 外还有 21 个簇，几个大簇：
    `0x5B7C41..0x5B83A2`(24)、`0x5B9676..0x5B9A4D`(18)、`0x5C48BC..0x5C497D`(17)、
    `0x79727E..0x7972FD`(19，18 个全局一次全写，疑似初始化/复位)、`0x78F787..0x78FDCB`(35)、
    `0x5DEAD4..0x5DF3FD`(20)、`0x76EDD9..0x76EE71`(15)。
- 证据（抽查）：
  - `0x5B832B a1 e0718800` `mov eax,[0x8871e0]` → `0x5B8330 8b88 84140000` `mov ecx,[eax+0x1484]` → **`0x5B8336 890d 5cb2a800` `mov [0xa8b25c],ecx`**（与批 1 完全同源：同一个 Rules 单例、同一个 +0x1484 偏移）。
  - `0x5C4912 8a85 b1000000` `mov al,[ebp+0xb1]` → **`0x5C4918 a2 1db3a800` `mov [0xa8b31d],al`**；`0x5C493B a3 78b2a800` `mov [0xa8b278],eax`。
  - **`0x6AD75A a3 5cb2a800` `mov [0xa8b25c],eax`** —— `call esi` 之后用返回值直接写，语义与「读规则」无关，是**独立的另一路写者**。
  - **`0x797292 a2 1fb3a800` `mov [0xa8b31f],al`**，紧随 `0x797297/0x79729D/0x7972A3/0x7972A9/0x7972AF/0x7972B4/0x7972BA/0x7972BF/0x7972C4/0x7972C9` 连续写 `0xa8b260/0xa8b261/0xa8b320/0xa8b31c/0xa8b31d/0xa8b258/0xa8b31e/0xa8b274/0xa8b278/0xa8b262` —— 这是一处**批量清零/复位**，18 个全局几乎一次全覆盖。
- 结论性判断：这组全局**不是** `0x52D149` 段落私有的缓存；至少存在 3 组独立的写者族（`0x5B7C..0x5B9A` 的规则解码变体、`0x5C48..0x5C49` 的另一结构拷贝、`0x7972..` 的初始化复位），外加 `0x6AD75A`、`0x78F787..` 等散点。

## Q3 第二个成批写入点

- 函数起点：**`0x005B67F0`**。函数体 `0x5B67F0 .. 0x5B6CC4`（`0x5B6CC0 c20400 ret 4`，其后 `0x5B6CC5..0x5B6CCF` 为 `90` 填充）。入口字节 `8a0d58b2a800 53 8b5c2408 56`（`mov cl,[0xa8b258]; push ebx; mov ebx,[esp+8]; push esi`），无标准序言但**仅有一个 call 入口**：`0x5B635F e88c040000  call 0x5B67F0`（调用者 `0x5B6020` 那个函数，`call` 前 `0x5B635E push eax`，返回后 `0x5B6364 cmp al,1`）。函数内只有两条 `ret`：`0x5B69E1 ret 4`（提前退出，返回 0）、`0x5B6CC0 ret 4`（正常返回 1）。整个函数被 `0x5B67F0..0x5B6CC4` 的 `0x90` 填充与前后函数隔开。
- 调试字符串（原文，均为 `push imm32` 引用）：
  - `0x5B69E4  push 0x0082C7A4` → **`"Decoding game options\n"`**（批写代码块的直接前导，批写从 `0x5B69FC` 开始）
  - `0x5B6BAA  push 0x0082C78C` → **`"Scenario has changed\n"`**（批写之后，字符串比较失败分支）
  - 相邻但不在本函数内的字符串（同一字符串池，供定位用）：`0x82C7CC "TXT_SENDING_GO_ACK"`、`0x82C7E0 "Cleaning up the temporary decompression buffers\n"`、`0x82C884 "got_file is false. Download failed\n"`、`0x82C89C "File_From_Host to receive the file download"`、`0x82C8E4 "Preview mode ack sent\n"`。这些说明整个 `0x5B6xxx` 区域属于**联机/多人游戏（Modem / 场景同步）子系统**。
- 写入几个全局 / 缺哪个：**17 个，缺 `0xA8B31E`**。逐条（`0x5B69E4..0x5B6B3D` 内全部绝对地址写）：
  `0xA8B258(0x5B69FA,byte) 0xA8B320(0x5B6A0C) 0xA8B260(0x5B6A25) 0xA8B261(0x5B6A49) 0xA8B31F(0x5B6A5C) 0xA8B31D(0x5B6A6F) 0xA8B274(0x5B6A7B,dword) 0xA8B278(0x5B6A88,dword) 0x822CF4(0x5B6A96,dword) 0xA8B25C(0x5B6A9F,dword) 0xA8B270(0x5B6AAA,dword) 0xA8B268(0x5B6AD1,dword) 0xA8B262(0x5B6AE9) 0xA8B263(0x5B6AFB) 0xA8B264(0x5B6B0D) 0xA8B26C(0x5B6B29) 0xA8B31C(0x5B6B3B, imm 1)`
  → 18 个里恰好少 `0xA8B31E`。已额外核验：本函数内没有任何更宽的存储（dword/qword 写覆盖 `0xA8B31E` 地址）间接写到它（扫描 `0x5B67F0..0x5B6CCF` 内全部绝对地址存储的 `[disp, disp+size)` 区间，命中为空）。
  另注：紧邻的**只读比对**块 `0x5B6800..0x5B6977` 确实**读**了 `0xA8B31E`（`0x5B68xx` 一带以及 `0x5B696A` 的 `0xA8B26C` 比较），所以缺写不是漏扫，而是语义上真的没回写。
- 源结构偏移范围：`ebx` 指向的对象（每次 `call` 时 `push` 进来的参数），读取偏移 **`0x7e .. 0xa3`**：
  - `+0x7e`(dword) → `0xA8B25C`
  - `+0x82` 位 0/1/2/4 → `0xA8B258` / `0xA8B260` / `0xA8B261` / `0xA8BB08`
  - `+0x8a`,`+0x8b`,`+0x8c`,`+0x8d`(byte) → `0x822CF4`,`0xA8B270`,`0xA8B274`,`0xA8B278`
  - `+0x8e` 位 1/2/3/4/5/6/7 → `0xA8B31D`,`0xA8B320`,`0xA8B31F`,`0xA8B262`,`0xA8B263`,`0xA8B264`,`0xA8B26C`
  - `+0x92`(dword) → `0xA8ED94`；`+0x96`(dword) → `0xA8E960`；`+0x9e`(dword) → `0xA8BB04`
  - `+0xa2`(byte) → `0xA8B268`；`+0xa3`(字符串起始) → 拷入 `0xA8B8E0`
  - `+0xb0`(字符串) → 拷入 `0xA8BAE2`
  即：**源数据是一个 `+0x7e` 起、到 `+0xa3` 结束的定长结构（长度约 0x26 字节），带位域、字符串跟在尾部**。批 1（`0x52D149`）的源偏移是 `+0x1484 .. +0x14ba`（来自 `[0x8871e0]` 单例），两者偏移体系完全不同，**不是同一结构**。

## 我踩到的坑

1. **VA→RVA 换算**：第一版把 `va` 直接当 RVA 查段，`foff()` 全部返回 `None`，静默什么都不打印。必须先减 `0x400000`。
2. **窗口起点必须落在指令边界**：从 `0x52D1E0` 起解码出来的是 `mov dl,0xa8` / `add byte ptr [edx+0x14b590],cl` 这种垃圾，会误判成「一堆奇怪的全局写」。从 `0x52D149` 起链式解才正确。
3. **两套「写入」判据结果不同**：先按 capstone 的 operand 判定（`ins.operands[0]` 是 MEM 即是写），但在密集区里，前一条指令的尾部字节可能被错误地当成新指令起点，产生 `unknown`。最终采用**纯字节形态**判据（`89/88/C6/C7` + ModRM `rm=101`，或 `A2/A3` moffs）与 operand 判据**双路互校**，两边总数一致（243 处）。
4. **字面量误报**：`0xA8B320` 在 `0x43768` 一带出现 8 次，都是立即数/常量，不是写；`0x822CF4` 在 `0x52DB6F` 一带是 `6a04 68f42c8200` 即 `push 0x822cf4`（当**指针参数**传），也不是写；`0xA8B31C` 在 `0x5EAD85` 一带是 `81fb 1cb3a800` 即 `cmp ebx,0xa8b31c`。字节形态判据全部正确排除了这些。
5. **函数边界不能只看 `ret`**：`0x52D30B` 有 `ret` 但后面紧跟的都是同函数代码（被 `jle` 正向跳入）。只按「遇到 ret 就断」会把函数切短 0x124 字节。
6. **`push imm32` 当函数指针**：`0x52D0D3 push 0x52D430` 会让「把 0x52D430 当函数起点」看起来可疑；靠 `ret 0x10` + 无任何 `jmp/call` 直指 + 前一条是 `0x52D42F ret` 三点确认它是独立函数。

## 置信度边界

- **Q1 是高置信**：链式解码 443 条指令无断裂、序言/尾栈完全对称、`0x52D430` 有独立 `ret 0x10` 与 `push` 取址，三重证据一致。剩余风险：若 `0x52D325..0x52D42F` 之间藏有对跳转表的间接跳（`jmp [reg*4+X]`），则在特定路径下可能不在 `0x52D42F` 返回——但本函数内不存在间接跳（全函数只有 `call dword ptr [reg+8]` 这类虚调用，无 `jmp [mem]`）。
- **Q2 的量级可靠、精确计数不可靠**：字节形态扫描会把「恰好在别处出现同样 4 字节」的立即数/指针误计（已尽力用 opcode 形态排除，但仍可能有个位数残差）；反之，用**基址寄存器 + 偏移**聚合写入（例如 `mov [ebx+0x1484],ecx` 后间接走另一全局）根本扫不到，因为目标不是绝对地址。因此 208 这个数是「绝对地址直写」的**下界**。另外 BSS/运行时动态改写（`0xA8B2xx` 一带若被 `rep movs`/`memcpy` 整块覆盖）不在指令扫描可见范围内——`0x79727E..0x7972FD` 那个 18 连写簇很像初始化复位，但也不能排除还有整块拷贝路径。
- **Q3 的函数起点与缺项是高置信**（唯一 call 入口 + 精确 17 项枚举 + 宽写覆盖检查为空）。**源结构偏移范围**是基于本函数内 `ebx` 的可见使用推出的**下界**：`+0x7e..+0xa3` 之外（如 `+0x58` 或更早的字段）是否也属于同一结构，本函数不读就看不到，无法从这一处反推结构真实大小。判定「与批 1 不是同一结构」只基于两侧偏移字面不同，未验证两者在运行期是否指向同一对象。
- 本报告**未**运行游戏、未挂调试器、未对照仓库内任何既有 `verify_r023*` / `kb/30_ini_subsystem.md`；全部结论仅由字节与指令推出。
