# R-031 中间裁定 · §12 的「模板键/误归属」两类机制（3 站点实证）

背景：claim 12.3「带 `%` 的键只有一处」被推翻 —— 当前证据文件里含 `%` 的
"键"共 **21 个不同键 / 34 站点**。逐站解码（3 处全追，其余同形待全量），
分**两类，处置不同**：

## 类 1 · 模板键（归属成立，但**不是可照抄的字面量**）

### 样本 `'%d'`（ReadString 调用 `0x691908`，函数 `0x6918A0`）

```text
0x006918D6  lea eax,[esp+0x1C] ; push 0x817F6C("%d") ; push eax
0x006918E0  call 0x7C8EF4      ; sprintf(buf,"%d",edi)   ← 键名=数字串
0x006918EC  call 0x727CF0      ; CString 链（[esp+0x18] ← 同一构造）
0x00691904  push edx           ; ★ KEY 槽 = 栈缓冲（运行期拼装）
0x00691908  call 0x528A10
```

⇒ 键**真由 `%d` 模板构造**，M1 记的串没错；但键名要按实际编号展开
（`0`、`1`、…）——`%` 串本身**不可写进 INI**。`'%d,%d,%d'`、`'%s%d'`、
`'%03d'`、`'LV%d'`、`'Map%d'`、`'TV%d'`、`'BurstDelay%d'` 等同理
（含静态段者照 `PowerUp%01dYSort` 规矩展开，纯动态段者键名完全运行期）。

### 样本 `'Tile%02dAnim'`（ReadString 调用 `0x546524`，函数 `0x545150`）

```text
0x005464F0  push 0x829194 ; push eax ; call 0x7C8EF4   ; sprintf 模板
0x00546520  lea ecx,[esp+0x4C]
0x00546524  call 0x528A10                              ; dst 槽即 sprintf 缓冲
```

⇒ `PowerUp%01dYSort` 的同类。**12.3 的"只有一处"因此不成立**：
真模板键至少 15+ 个（`Tile%02d*` 五个、`EliteStage%d`、`EliteWeapon%d`、
`%sBarrelLength/…TurretLocked/…Sounds`、`FiringSyncFrame%d` 等）。
数字/口径上这些**在 2,305 里是合法行**，只是键名列应读作模板。

## 类 2 · 真误归属（M1 把**别的调用消费掉的串**记成键）

### 样本 `'D:\ra2mdpost\Scenario.CPP'`（GetSection 调用 `0x686ED0`，函数 `0x686B20`）

```text
0x00686E72  push 0x400 ; push 0xC5F ; push 0x83D838    ; ← 断言串（带行号 0xC5F）
0x00686E85  call 0x734E60                              ; ★ CSF/断言助手已消费
0x00686E8B  mov eax,[0xA8B230] ; add eax,0x125C ; push eax  ; NAME 槽=运行期缓冲
0x00686ED0  call 0x526810                              ; GetSection
```

⇒ 真 NAME 是 `[0xA8B230]+0x125C` 的运行期串，**属 §12.2「键在 BSS」**；
`Scenario.CPP` 是 51 条指令之前别的 call 的参数，被 M1"最后一个字面量"规则
错挂到本调用上。**这一站点被错记为"已恢复"** ⇒ 121 是下界。

（`'%d'` 样本在 R-031 早期草稿里被我误归入此类，追栈后改判类 1：
键槽与 sprintf 缓冲同链。类 2 目前确证 1 处，全量清点进行中。）

## 影响汇总（待异族 M2 全量后定稿）

|:---|:---|
