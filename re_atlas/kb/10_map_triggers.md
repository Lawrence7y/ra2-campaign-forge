## 1. `TActionClass::Execute` — 动作派发 [实证]

### 1.1 入口

```
0x006DD8B0  81 EC 40 02 00 00     sub esp, 0x240     ; 大栈帧（0x240 字节局部）
0x006DD8B6  B0 01                 mov al, 1
0x006DD8B8  53                    push ebx
0x006DD8B9  55                    push ebp
0x006DD8BA  56                    push esi
0x006DD8BB  8B F1                 mov esi, ecx        ; this = TActionClass*
0x006DD8BD  8B 8C 24 54 02 00 00  mov ecx, [esp+0x254] ; 参数（含 pEvent/触发者）
0x006DD8C4  33 ED                 xor ebp, ebp
0x006DD8C6  3B CD                 cmp ecx, ebp
0x006DD8C8  57                    push edi
0x006DD8C9  74 0C                 je 0x6DD8D7
0x006DD8CB  8A 91 90 00 00 00     mov dl, [ecx+0x90]  ; 读对象某标志位
```

要点：`mov al,1` 落在 prologue 中间，是"默认返回值 = true"的赋值；
`0x240` 栈帧说明该函数有大量分支局部（与 145 项动作表吻合）。

### 1.2 派发点 [实证]

```
0x006DD8E7  jmp dword ptr [edx*4 + 0x6DFDEC]
```

`edx` 是动作索引，直接以 4 字节步长索引 `0x6DFDEC` 的绝对地址数组。

### 1.3 表形态 [实证]

`tools/` 中的一次性探针读取 `0x6DFDEC + 4*i`（i=0..144），**145/145 个 dword 全部落在
`.text`（`0x401000..0x7E1000`）内**，其中 **143 个唯一目标**（有 2 组重复项，
即两个动作号共享同一实现——这与语料"部分动作是别名"的说法相容，未逐项展开）。

| 指标 | 值 |
|:---|---:|
| 表项数 | 145 |
| 落在 .text | 145（100%） |
| 唯一目标 | 143 |
| 最小目标 | `0x006DD8EE` |
| 最大目标 | `0x006DFDDD` |

**145 → 143 差的 2：不是"别名"，是共享 epilogue** [实证]

唯一被多个动作号共用的目标是 **`0x006DFDDB`**，被动作下标 **38 / 91 / 92** 三点引用：

```
0x006DFDDB  B0 01                 mov al, 1        ; ★ 返回值 = true
0x006DFDDD  5F 5E 5D 5B           pop edi; pop esi; pop ebp; pop ebx
0x006DFDE1  81 C4 40 02 00 00     add esp, 0x240   ; ★ 与入口的 sub esp,0x240 配对
0x006DFDE7  C2 10 00              ret 0x10         ; 4 参数 stdcall
0x006DFDEC  --（跳表起点）
```

⇒ 这是三个"无副作用、恒返回 true"的动作**共用的尾块**：
`add esp,0x240` 精确抵消入口的 `sub esp,0x240`，`ret 0x10` 说明该尾块所属函数
以 4 个 4 字节栈参数平栈。

**145 项动作的调用约定** [实证]：对 145 个目标各扫首 0x400 字节找第一条 `C2 imm16`，
**136 项命中 `ret 0x10`**（4 参数 stdcall），其余 9 项因函数更长或走
`pop`+`ret` 形态未在窗口内命中，分布为 `0x8`×1 与若干显非 epilogue 的假值
（`0xFFFB`/`0xF8C1` 等，属扫到指令中间字节的伪命中）。
**保守结论**：**存在一个主导约定 `ret 0x10`（4 参数）**，但不宣称 145/145 全同。

**对编译器的含义**：动作 38/91/92 **不是三个独立实现**，而是"什么都不做、返回成功"
的三个动作号（典型是 `No-op` / `Comment` / `End of list` 之类）。
建模时应表示为"空实现"而不是三个函数。

**读表注意**：本件是**绝对地址数组**（`0x006DEA37` 这种形态），
不是"相对表基址的偏移"。任何把表项当 offset 再加基址的读法都会全错。

## 2. `TeamClass::AI` — 队伍脚本动作派发 [实证]

```
0x006E9050  55                  push ebp
0x006E9051  8B 6C 24 08         mov ebp, [esp+8]      ; arg
0x006E9055  56 57               push esi; push edi
0x006E9057  8B F9               mov edi, ecx          ; this = TeamClass*
0x006E9059  8B 47 3C            mov eax, [edi+0x3C]   ; Team 的当前脚本指针/状态
0x006E905C  3B E8               cmp ebp, eax
0x006E905E  74 70               je 0x6E90D0           ; 早退：状态未变
```

**字段实证**：`TeamClass+0x3C` 是"当前脚本执行状态"类字段（与传入参数比较后早退）。

### 2.1 表形态 [实证]

| 指标 | 值 |
|:---|---:|
| 表地址 | `0x006E9F74` |
| 表项数 | 65 |
| 落在 .text | **65 / 65（100%）** |
| 唯一目标 | **65**（无别名） |
| 最小 / 最大目标 | `0x006E9462` / `0x006E9F0D` |

**与 §1 的差别**：队伍脚本动作 65 项**无重复目标**，而触发器动作 145 项有 2 组别名。
这对编译器有意义：队伍脚本动作可以"一号一实现"地建模，触发器动作需允许别名。

## 3. `TEventClass::HasOccured` — 事件判定 [实证，含新发现]

### 3.1 入口与范围检查

```
0x0071E940  83 EC 1C              sub esp, 0x1C
0x0071E943  53 55                 push ebx; push ebp
0x0071E945  8B E9                 mov ebp, ecx          ; this = TEventClass*
0x0071E947  56 57                 push esi; push edi
0x0071E949  89 6C 24 10           mov [esp+0x10], ebp
0x0071E94D  8B 4D 2C              mov ecx, [ebp+0x2C]   ; ★ 事件类型 ID
0x0071E950  8D 41 F3              lea eax, [ecx-0xD]    ; ID - 0xD
0x0071E953  83 F8 30              cmp eax, 0x30         ; 上限 0x30
0x0071E956  0F 87 07 03 00 00     ja 0x71EC63           ; 越界 -> 跳到"未知事件"分支（注意它也在表内）
```

**字段实证**：`TEventClass+0x2C` = 事件类型 ID；**合法 ID 下界 0x0D**，
`ID-0x0D <= 0x30` ⇒ 名义上界 `0x3D`。

### 3.2 派发是**两级**，不是一级 [实证]

```
0x0071E950  8D 41 F3              lea eax, [ecx-0xD]     ; EventKind - 0x0D
0x0071E953  83 F8 30              cmp eax, 0x30          ; <= 0x30 (49 槽)
0x0071E956  0F 87 07 03 00 00     ja  0x71EC63           ; 越界 -> 兜底
0x0071E964  FF 24 95 18 F2 71 00  jmp dword ptr [edx*4 + 0x71F218]
```

- **一级表** `0x71F218`：**12 个 dword，12 个唯一目标**（全部在 .text）。
- **二级选择表** `0x71F248`：**49 字节**，每字节是一个**一级表下标（0..11）**，
  值 `0x0B`（=11）是"兜底"档。

⇒ 正确读法：`target = table1[ table2[ EventKind - 0x0D ] ]`。
**不是** `table1[EventKind-0x0D]` —— 这正是我最初误读的原因，也把
`0x0B0B0B0B` 这类跨字节拼接当成了"填充魔数"。实际它是
`table1` 之后紧接着的 `table2` 字节序列，被 4 字节步长跨读后拼出来的假值。
