## 2.168 · R163：F24 的 86.19% 不是算错的数、是**主语错**的数（它测的是盘上语料覆盖率、被写成了二进制性质）；`bounds` 的生成规则被复原成一条等式，R162 遗留的「65 条指令内位移」随之作废

**一 · 本轮入口（从 R162 待办第 1 条进，不走比值空间）.** R162 已用 56 个自然量比值把「86.19% 是 bounds 段某个比值」这条解释**否掉**（最近差 13.69 个百分点），并写明下轮入口是 `a2_sites` 的生成器侧。本轮**没找到生成器**（详见第五点），但在找的过程中撞到了这数的**原始量测表**就在盘上。

**二 · 原始量测表在盘、且它的主语是「盘上语料」不是「二进制」.** `R17_R95_T1_A2SITES/REPORT.md` §5.3（26,976 B，sha256 `be6d4d0f…`）逐字写着：用 **4,743 份文本 EVIDENCE** 扫「`VA  指令字节  助记符`」行、取与 `bounds` 相交的，得 **192,341 / 1,392,592 = 13.81%**，**提供这些行的文件 961 份**，其余 **1,200,251 条（86.19%）只以地址形式存在、盘上没有任何字节与之对应**。三个数**互相自洽**：`1,392,592 − 192,341 = 1,200,251` 精确成立、`192,341/1,392,592 = 13.811727%`、`1,200,251/1,392,592 = 86.188273%`（四舍五入正是 13.81 / 86.19）。⇒ **86.19% 是「盘上语料没覆盖到」的补集**，不是「二进制里没有字节」。F24 正文把这层「语料主语」丢了、写成二进制性质 ⇒ 这是**口径滑移**，不是算术错误。

**三 · 同一批地址用二进制判据测出来是 100% / 99.992%，两者不矛盾.** 弱判据（落在某节 `SizeOfRawData` 覆盖内）实测 **1,392,592 / 1,392,592 = 100.000000%**，未命中 0 条；强判据（落在指令起始集）R136 三分实现同测得 **99.992%**。⇒ 语料判据 13.81% 与二进制判据 100% **测的不是同一个东西**，R136 与 R95 之间从来没有矛盾。**反控**：`ImageBase` 本身不落在任何节、映像外 `0x900000` 不命中 ⇒ 弱判据不是恒真。

**四 · 这条数的语料基础现盘已不在 ⇒ 它当前既不可复核也不可反驳.** 作用域决定数字，三个作用域都给：①**仅 `lead/next_re_20261117_r14` 下的大写 `EVIDENCE`**：目录 **5** 个、文件 **5** 个、含「地址+字节+助记符」行 **0** 个；②**全库大写 `EVIDENCE`**：目录 **6** 个、文件 **52** 个、含该形态行的 **35** 个、地址并集落在 `bounds` 内 **1,556** 条（其中 `DISASM_FN_*` 子集 **14** 个文件 / **141** 条唯一地址，**141/141** 与 `gamemd.exe` 同址字节全等）；③**全库大小写不敏感 `evidence`**：目录 **8** 个、文件 **217** 个、覆盖 **1,704** 条。三个作用域**都远够不到 192,341**（差 1~3 个数量级）。两个生成器脚本 `q4_covering.py` / `q4_covering_verify.py` **均不存在**，而 R95 §7 的复算清单里**仍写着这两个文件名** ⇒ 表与盘不一致；R95 依赖的 `C01_census/EVIDENCE/slice_disasm.txt` **现盘不存在**（该目录只剩 `callgraph.json`），R95 自己的 4,743 份语料也不在了。**反控**：把语料换成 `bounds` 自身 ⇒ 覆盖率 100%（扫描器不是恒 0）；伪语料 2 行被解析出 2 个 VA 且覆盖率 0（解析器有分辨力）。

**五 · `bounds` 的生成规则被复原成一条等式（R162 的「65 条指令内位移」作废）.** 本轮用三种口径各自独立实现（plain+单字节重对齐 / capstone `skipdata=True` / **objdump 第三方**）实测：plain+resync 起点 **1,394,120**、skipdata 起点 **1,394,186**、objdump 起点 **1,401,544**。决定性结果：**`bounds` 逐条等于「skipdata 起点中地址 < VirtualSize 尾界 `0x7E038D`」那一部分**，两侧差集全空；`skipdata − bounds` 的 **1,594 条全部落在尾填充区 `0x7E038D..0x7E0FFF`**；`1,392,592 + 1,594 = 1,394,186` 精确闭合。⇒ R162 报的「65 条在 bounds 但非（plain）起点」**不是指令内位移**，是**基准选错**（拿 plain 起点当基准）造成的假遗留 —— 那 65 条在 skipdata 口径下**全部是真起点**（数据区被逐字节跳过处）。R162 的两个数本轮**逐条复现**：`bounds − plain起点 = 65`、`plain起点 − bounds = 1,593`（全 ≥ 尾界）、65 条的相对前一条 plain 起点位移分布 **1:22 2:20 3:14 4:1 5:1 6:6 7:1**。**反控**：只有 skipdata 使「截到尾界后」与 bounds 逐条相等（P3 差 9,063 条）；尾界 +1 ⇒ 恰多 1 条、尾界 −1 ⇒ bounds 侧恰缺 1 条、不截断 ⇒ 多 1,594 条。

**六 · 「首字节就错」的扫描器缺陷本轮又犯了一次（S-478）.** 首版 `plain` 直接 `disasm_lite`、**没做失败处重对齐** ⇒ 155,215 条（首个不可解码字节就停），据此写出三条假 FAIL。这与 R162 的 S-476（`consumed==0` 时整块跳 64 KB）是**同一族**：把「流提前结束」当成「已扫完」。

**七 · 切分点 `0x48948A` 是**计数边界**不是内容边界.** 它恰是 `bounds` 排序后的第 **192,341** 个元素（0-based 192,340），`<= 0x48948A` 恰 192,341 条。R158 报的「两侧密度同族（0.3446 / 0.3428）、gap 分布同族」由此得到解释：**按秩切任何位置都得到密度接近的两段**。本轮全秩扫描（步长 2 万、68 个切点）实测相对差 min **0.0361%** / median **1.3992%** / max **12.8033%**，`0x48948A` 处 **0.5286%** 排在第 **23.5** 百分位，**有 16 个秩切点比它更「同族」**（最小在秩 620,000）⇒ **密度同族完全不能标识这个切分点**，R158 那条形态观察不能用来判同源/异源。

**八 · F24 语料值三桶独立重写复算.** 不跑 R152 的脚本、不看它的中间产物，从清单 `tier_final_4417.tsv`（**696,579 B / sha256 `363a1199…` / 4,417 数据行**）与现盘重算：存在 **65 件 / 44,470,975 B**、同字节 **64 件 / 26,846,620 B**、字节不同 **1 件**（`a2_sites.json` 清单 913,237 vs 盘 17,624,355）、不存在 **4,352 件 / 709,757,429 B**；件数闭合 65+4,352=4,417、字节闭合 `26,846,620+913,237+709,757,429 = 737,517,286` 与 `44,470,975−16,711,118+709,757,429 = 737,517,286` 两式同解。**差 +16,711,118 的身份被钉死**：`a2_sites.json` 里分段标记 `}, "bounds": [` 的**起始偏移恰是 913,237**，`bounds` 段 = 17,624,355 − 913,237 = **16,711,118 B** ⇒ 清单那个 913,237 就是「只算 `calls` 段」的值。**反控**：rel 拼仓库根得 0 件、rel 加 `junk_` 前缀得 0 件、清单 bytes 全 +1 ⇒ 同字节桶归 0、把 a2_sites 清单字节改成现盘值 ⇒ 同字节桶变 65。
