### 2.107.1 第 3 列「可执行判据」对门禁是纯自由文本：31 行全改成单字符 x，exit 仍是 0

r103a_freetext.py（15 项）+ 执行员 hy4 #160 独立复现，两造逐项一致：

| 变异 | exit | FAIL 数 | 说明 |
|---|---|---|---|
| 31 行第 3 列全改 `x` | **0** | 0 | 门禁对第 3 列无任何内容级校验 |
| 只改 id 3 的第 3 列 | **0** | 0 | 该行今天真被 C11 读，但 C11 只读第 7 列与第 4 列 |
| 31 行第 3 列全改 `TBD` | 1 | 31 | 唯一会读它的是 C9 的占位词判定 |

全脚本对第 3 列只有一处读取（check_disc.py:96 的 `_PLACE_IS(r[2].strip())`），只判「是不是占位符」。
表头把它叫「可执行判据（逐字截取）」，实测 28/31 行确实逐字在 R14_COMMON 正文里，
但**那 3 行（31/32/33）不在**：id 31 的正文标题只有半句（定义句在下一行）、id 32/33 的正文用直角引号
「」而表里用弯引号 “”，另有 id 32 的正文多一个 `⇒` 前缀。⇒「逐字截取」这个说法对 3 行不成立，
且门禁不查它是否可执行 —— 这是本节第一条实测结论。

### 2.107.2 第 4 列「必查的现有数据锚」：26 行改了看不见，5 行被 R5 的 sha256 绑定

### 2.107.3 第 2 列「节」只校验「存在」，不校验「对应」：31 行全指 §2.14 也 exit 0

| 变异 | exit | FAIL |
|---|---|---|
| 31 行第 2 列全改 `§2.14`（真实存在） | **0** | 0 |
| 31 行第 2 列全改 `§2.999`（不存在） | 1 | 31 条 C8 |

C8 只判 `r[1].lstrip('§').strip() in secs`（check_disc.py:221-223），而 secs 是全文所有 `## x.y` 的集合。
⇒ 指向任意一个存在的节都能过。**严格化零误伤**：从正文反推每个「纪律 N ·」所属的 `## 2.x` 节，
31/31 行的第 2 列都落在该集合内；唯一歧义是纪律 1 在正文出现于 2.14（定义）与 2.26（引用），
故 C13 按**集合成员**判而非单值。

### 2.107.8 🐞 事故：沙箱 symlink 写穿透，真实改写了 5 条自述行的 anchors

写 r103a 的 M5「完整伪造链」测试时，沙箱只把 check_disc.py / DISC_RECHECK.tsv / DISC_UNVERIFIABLE.tsv /
R14_COMMON.md 复制成实体，**DISC_RECHECK 第 5 列引用的 23 个产物仍是 symlink**。
M5 要「覆写产物里的自述行」，于是写操作经 symlink 直落**真树**，把 id 3/4/22/27/28 的
`anchors=sha256:...` 改成了 FORGED 值，真门禁随即 exit 1。
发现与处置：真门禁检查当场报 `R5 anchors mismatch` 的 5 条 FAIL ⇒ 立即按原锚值逐字节还原
（5/5 复原，真门禁回 exit 0，五项 CR 不变量全绿）。**没有隐藏、没有美化**。
机制的关键不是「末端文件是 symlink」而是「**父目录**是 symlink」：
`os.path.islink(文件)` 返回 False，所以只查末端拦不住（r103f E1c2 实测）。
结构性修复：sbxlib 的 PRODUCTS 全部 materialize 成实体，并加 `escape_path()` 逐段查 symlink、
`guard_write()` 写前抛错。反控：用 R102 的旧建法复现同一路径，escape_path 正确报出
`…/R17_R61_FACTINDEX_V58` 这一段，guard_write 抛 RuntimeError。
