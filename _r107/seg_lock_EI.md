EI4. ✅ **CALLTGT 判据的失败模式被量化，不是「个别失误」而是结构性盲区**。

EI5. ✅ **7 张 DEC 形态的输入溯源：从「只证了 dec」推进到「结构字段/调用返回值」**（R106 §EH10③ 的正面回答）。
逐张给赋值链，终点分布 **THIS_FIELD 3 / CALL_RET_FIELD 4**，**无 UNKNOWN**：
- `0x4c8114` ← `mov al,[esi]`（0x4c6cc8，this 基址，偏移 **0x0**，高 24 位由更早 `xor eax,eax` 清零）；
- `0x69b15c` ← `mov eax,[esi]`（0x69af2a，this 偏移 **0x0**）；
- `0x6dfdec` ← `mov edx,[esi+0x2c]`（0x6dd8d7，this 偏移 **0x2c**）；
- `0x708d54` ← `mov eax,[eax+0x3d4]`（0x708c3e），基址 eax 来自 `call dword ptr [eax+0x84]` 的返回值，**槽 0x84、字段偏移 0x3d4**；
- `0x728e08` ← `mov eax,[edi+0x14]`（0x728c0a），基址 edi 来自 `[esp+0x30]` 的栈参数；
- `0x7291ac` ← `mov ecx,[esi+0x14]`（0x728e5f），esi 是栈参数，**字段偏移 0x14**；

⇒ R106 §EH6 说「偏移 0xc/0x5c 只拿到数值、未证字段」，本轮的对照结论是：7 张 DEC 里
**没有一张**是 0xc/0x5c；0xc 是 `[ebp+0xc]`（栈参数，见 EI6），0x5c 是 `[esi+0x5c]`（this 字段）。

EI7. 🔴 **R106 §EH4「看错寄存器会 100% 拿噪声（18/19 错）」不成立**。

EI10. 📌 **本轮新增可复用判据（建议进纪律）**
1. 「函数入口必须被 call 直接引用」**不足以**定所属函数：vtable 槽值里 **93.4%** 不是 call 目标，
   只经虚表调度的虚方法会被静默漏掉，并让判据回退到更早的构造函数给出错答。
   定所属函数必须同时收 **call 目标 ∪ vtable 槽值**两类候选。
2. 「从 S 线性解码能落到 H」**不是**所属函数的证据——实测 19/19 全都能落到（含错答案）。
   **必须加「其间 ret 数为 0」**：有 ret 就说明中间隔着函数界。这是本轮唯一有判别力的机械条件。
3. 「对齐填充后接非填充字节」在 .text 里**鉴别力为负**（立即数字节遍地都是），不可作函数起点判据。
4. 判寄存器来源必须**同宽同名匹配**：`mov al,[m]` 不是 `eax` 的定义（只清低 8 位）；
   遇到 `xor r,r` 自写要当成「清零」而不是「追踪目标」，否则会原地打转越过函数入口。
5. 零假设检验**必须先定尾向**再读 P 值：观测值低于期望时看下尾、高于期望时看上尾。
   本轮审计员 P 值算对、尾向读反，得出了与事实相反的「不显著」。
6. 多源不一致（四件套正文 vs 自己上一轮的 JSON 产物）时**先核盘再引用**：本轮我照抄 LEAD_LOCK 的
   0x6dd5b0 而未核 r106f JSON 的 0x6dd8b0（E-l1）。
7. 派执行员卡**必须把任务切成「不依赖全 program CFG」的形态**：本轮 exec 卡写了 4 问，
   它自行扩展到全 .text CFG 后超时，4 问零交付。
