## 1. 裁决

**三键持久补入两份游戏目录 ini，值一律 `0`（不是 1）。补键不新增任何节。**

| 键 | 权威节名 | 源码读点 | 源 ini 现值 |

**Lead 亲跑复算依据（`[实证]`）**：
- 源 `ra2render/ra2render.ini` = 23 键，sha `FD9EBB32DCB6CDA7…`；其中三键值**本身就是 0**（行号见上表）。
- `ra2youli/ra2render.ini` 与 `ra2bench/ra2render.ini` = 各 20 键、两份逐字节相同，sha `B8BB8238E5BD06E1…`；**三键全缺**。
- 两份游戏目录 ini 的节表为 `[Render] / [Logic] / [Speed] / [System] / [FogOfWar]` —— **三键的目标节全部已存在** ⇒ 补键**零新增节**。

## 2. 为什么值必须是 0

| 状态 | 代码行为 | 日志「来源」 |
|---|---|---|
| 键缺失 | 走编译期默认 0 | `默认值` |
| 键存在 = 0 | 同 0 | `ini` |

⇒ 补键=0 **行为完全不变**，只把「代码在、开关缺」这个**部署缺陷**闭合，同时**不触碰**「默认开关 = 0」红线，也不改变出箱行为。
⇒ **禁止**写成 1。把三键写成 1 才会真正改变出箱行为与对拍基线，那需要单独一张卡与真机对拍，不在本裁决范围。
