# PERF-INT01 · 将已验收测量元数据原型集成为项目工具

> 用户授权继续项目任务。以 WORK_CHAIN 最新双执行池为准；本卡只新增离线工具与使用说明，不启动游戏、不读写进程内存、不部署补丁。

## 目标与依赖

IMPL001/PERF 的 `validate_measurement.py` 原型已有实现、自测、独立审计及合规通道负控。先由调度者核验现件与 `perf/control/REPORT.md`、`dispatch.json` 的接受状态和指纹；确认成立后集成，不重做原型。如果事实与台账冲突，先登记具体差异，不盲目覆盖。

## 写域与职责

- 实现包唯一写者：新增 `tools/validate_measurement.py`、`docs/re/measurement_record_schema.md`，及 `out/re_work/work_chain/IMPL001/perf/integration/worker/**`。如果目标文件已存在先读取并核对所有者，不能直接覆盖。
- 独立审计包：只写 `perf/integration/review/**`，只读新增工具、文档、原型和 fixtures。
- 原 PERF 普通调度会话：只写本线 control，包括 integration 状态、派发记录、独立复算和返工。
- 禁止改其他 tools、ra2re、ra2forge、ra2render、游戏目录、原型/fixtures 与其他会话产物。

## 行为与验收

1. 复用已核验原型实现，保留 Python 标准库 CLI、输入 JSON、`--json`、退出码 0/1/2、nearest-rank P95/P99 和字段错误定位；不要在集成时顺手改算法或 schema。
2. 说明实际单位数及其运行证据是必填，地图名义单位数不能替代；验证器只验证记录形态，不证明数据真伪或真实性能收益。
3. 文档给出最小合法记录（仅合成示例）、三次采样要求、有效与无效退出码、运行命令、运行证据引用及与 H1 重测的关系。不能把示例哈希和耗时写成真机实测。
4. 以原 fixtures 至少覆盖有效、布尔单位数、NaN/Infinity、名义/实际不一致以及缺失计数证据；用真实解释器保存命令、输出、退出码；确认新工具与原型对应输入结果一致，输入文件未改。
5. 审计者独立核对复制/集成内容、文档与实际 CLI 一致，并跑至少一个额外负控。若内部 shell 不可用，命令验证交给获准且有有效 shell 的外部 harness，不伪造运行。
6. 实现与独立审计顺序执行；无依赖的文档/用例审阅可并行。使用三家外部 harness 或 DSH 内部指定三模型，明确写域与真实身份。

交付报告、指纹、原始运行输出与最终判定。通过后这是一项可使用的离线基线工具，不等于 M0 高负载测量完成；下一步为真实场景采样卡，运行时取证与游戏实例仍需专门卡明确边界。
