## 四、本轮重大技术突破与终局定谳亮点

### 1. E 系列核心冲突终极定谳
- **E1 存档主函数定性**：
  取证 `0x0067D1AF: call 0x0067D300`，实证 `0x0067D300` 是核心流数据落盘函数 **`Save_Core`**；真正统揽复合文档（IStorage）建档事务的入口为 **`0x0067D0C0`**（镜像 0 引用，经 COM 虚表/外层接口调度）；
- **E2 读写一一对应冲突推翻**：
  实测读档入口 `0x0067CEF0` 内部连续调用的 16 个函数（`0x00680FF0..0x006812E0`）仅为**存档头元数据解包设值器（Save Header Accessors）**，而写侧 `0x0067D300` 串联了 35 块深层对象池序列化；推翻“0x680F70 与 Save 侧 35 块一一对应”的历史误判；
- **E3 存档代码长度勘误**：
  实测 `0x0067D300` 末尾指令为 `0x0067E43A: C3 ret`，净指令长度为 **4410 字节**（含 ret 为 4411 字节）。历史记录的 4416B 系因直接取下一函数起始对齐边界 `0x0067E440 - 0x0067D300 = 0x1140 = 4416 字节`，误计入了 5 字节的 `0x90` (NOP) 填充对齐空隙；
- **E4 单例数组与计数器平叛**：
  实证 `0x0064DCB3` 与 `0x0041EC90`，判定 `0x00A8022C / 0x00A80238` 归属于 **`AircraftClass::Array`**（`house_team_ai_update.md:118` 标注为 House 系笔误，真正的 House 数组位于 `0x0087F77C / 0x0087F788`，RTTI = 4）；同时在 `0x004E70FD` 与 `0x006F0859` 实证 TeamType 结构中 `0x00A8ECA4` 为 `Items` 指针、`0x00A8ECA8` 为 `Capacity`，活动计数器 `Count` 为 **`0x00A8ECB0`**；
- **E-1 动作与脚本体系隔离**：
  实证 `0x006E944B`（`cmp eax, 0x40; jmp [eax*4 + 0x6E9F74]`）跳转表第 49 项指向 `0x006E9CE1`（在 `0x006E9CE8` 写 `[esi+0x84], 0`），确证其属于 **`TeamClass::AI` 队伍脚本动作 49**；而 `TActionClass`（地图触发器动作）Action 49 严格为视口缩放 `Zoom In`。

### 2. 重大结构与全局变量纠偏
- **35 块 0x80 模板可执行体确证**：
  对 `0x0067FDF0 .. 0x00680EF0` 的 35 个 0x80 块进行全量哈希，证实 **MD5 100% 逐字节完全等同**（`cb13908da7ed66fb2a7545323b865a3d`）。全镜像直接 DWORD 引用计数均为 0，推翻“函数调度表”假说，确证为编译器模板展开的可执行代码副本；
- **fs_mix 全局指针本质澄清**：
  静态磁盘中 `0x00884DF8` 与 `0x00884E50` 留存 UTF-16LE 宽字符碎片（"ider1", "GUI:Credits"）。汇编取证 `0x005302B1` 与 `0x005303DB` 证实运行时动态执行 `mov [884DF8], eax` 写入堆分配的 `MixFileClass*` 对象指针。静态只读名串假设彻底降标澄清。

### 3. 虚表、物理尺寸与跳板安全定谳
- **虚表双轨混淆厘清**：
  确立 `ObjectClass::Draw` 为 Slot 69（偏移 `+0x114`）；`TechnoClass::CreateGap/DestroyGap` 为 Slot 261/262（偏移 `+0x414`/`+0x418`）；`FootClass::MoveTo/StopMoving` 为 Slot 319/320（偏移 `+0x4FC`/`+0x500`），清除跨继承层级与进制换算断层；
- **对象物理尺寸铁证**：
  实证 `ParticleClass` 为 312 字节（`0x138`，11 处 new）、`BulletClass` 为 352 字节（`0x160`，4 处 new）、`AnimClass` 为 456 字节（`0x1C8`，152 处 new）、`SuperClass` 为 128 字节（`0x80`，`0x006CE210` 虚方法内联返回 0x80）；
- **H-D5 跳板机器码重大漏洞修正**：
  原案 `83 E0 FF` 因 x86 立即数符号扩展为 `and eax, 0xFFFFFFFF`，在 1000 帧后必致环形数组越页崩溃。强制裁定采纳 `0F B6 C0`（`movzx eax, al`，3 字节零扩展）；
- **音频钩子平栈平衡**：
  实证 `PlayGlobal`（`0x00750920`）采用 `ret 8`、`PlayAt`（`0x007509E0`）采用 `ret 4`，严禁使用裸 `ret`；
- **寻敌与寻路算子数学定谳**：
  实证 Greatest_Threat 3 处比对均为严格 `jle`，确定同分先见原则；实证寻路主循环 `0x0042CCD0` 零距离启发式，确证为纯有界 Dijkstra 展开。

## 【task-11 / `[v1.5.35]` 收尾补录】S21 遗留"待注明/待复核"两项的最终裁定

本报告 §2.6 的 35 个模板函数 MD5 与「读档侧函数计数」两项遗留问题，已在 `[v1.5.35]` 收尾中定谳（**不修改本报告任何原有正文，仅在此追加**）：

1. **35 个模板函数 MD5 的长度口径** —— `docs/re/cross_doc_consistency_audit.md §2.6` 原文用的是 **128 B 口径**（含尾部 1 字节 `0x90` 对齐填充）：`cb13908da7ed66fb2a7545323b865a3d`；
   另有同样正确的 **127 B 口径**（纯代码长度，末字节 `C3` = `ret`）：`9f6770a9cd27b9fa49558adf28c92f10`。
   两者各自 **35/35 唯一**，差异恰为尾部 1 字节填充，**不构成矛盾**；今后引用必须标注字节长度。
   复算：`python out/re_work/errata/audit_template_md5.py`。

2. **读档侧函数计数 16 vs 15** —— 两者**不是矛盾而是两种口径**，实测均正确：
   - **16** = `Game::Load` 侧（`0x67CE00..0x67E500`）直接 `call` 命中的**不同助手函数地址数**（范围 `0x680F70..0x681840`，共 17 处 call）；
   - **15** = 同一区域内的**调用点个数**，目标窗口收窄为 `0x680FF0..0x6812E0`（排除 `0x680F70`@`0x67D193` 与 `0x681840`@`0x67E4CA`，含 `0x680FF0` 被调 2 次）；
   - **不含**寄存器/虚表间接调用（同区 140 处），**不含** `0x67FDD0/0x67FDE0` 流包装助手；
   - ★ 勘误：原「3 个包装助手 `0x67FDD0/0x67FDE0/0x67FDA0`」有误 —— `0x67FDA0` 落在 `0x0067FD9E = 81 C4 84 00 00 00`（`add esp,0x84`）的 imm32 中段，**全镜像指向它的相对引用为 0**，非函数入口。
