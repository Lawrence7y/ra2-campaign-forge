## 1. 决策问题

P-2.x（`Cell+0x134` 三处 6B NOP + 保护包）落地后，**联机握手是否强制校验补丁身份/配置**？

| 方 | 口径（原文摘要） | 出处 |
|---|---|---|
| **甲（不加键）** | **不采纳**把 `EnableGapProtection`/`EnableSpySatGate` 纳入联机握手校验字段；策略 = 全员强制同值 + 禁混端（文档级） | `gap_protection_install_spec.md` §4.3 / `RE_COORDINATION.md`；P21 §7、P223 §7「不加新握手键」 |
| **乙（G4.1 硬握手）** | 握手键**必须含** `EnableGapProtection` + `gapProtectionPatchesInstalled`（期望 **3**）；混端**拒绝开局**（硬拒，不等 DESYNC） | `savegame_product_checklist.md` G4.1/G4.2；`ARCHITECTURE_ATLAS.md` §12.4 |

**为何必须裁**：混端（一端 P-2.x、一端原版）因 `+0x134` 进 `.SAV`，在补丁后第一次 `RevealArea2/3/Reshroud` **必 DESYNC**（触发点不是读档瞬间）[前证]。甲靠文档禁令，乙靠握手拦截——两者对「谁在开局前拦住误配」的回答不同，且 G4.1/G4.2 是产品出厂 **P0** 门禁，甲在字面上**无法勾选** G4.1。

## 5. 推荐

**推荐 C4（分阶段）：现阶段维持甲；「MP 可发布」宣称前必须闭合乙或书面改判 G4.1。**

1. **现阶段（开发/对拍期）——裁「维持甲」**
   - 与 `RE_COORDINATION.md:1775` 既裁、落地卡「不新增握手键」、v2/v3 红线一致 [前证]；
   - 安全姿势 = 全员同构建同开关 + 禁混端 + `MpActive` 强制不装 + 启动日志留痕 + installed 计数审计（MP-1..MP-8）；
   - **不**新开协议字段，**不**动网络消息面。

2. **宣称「MP 可发布」之前——二选一，不可回避**
   - **路径 B（推荐）**：裁乙，按 **C2 最小键集**（仅 G4.1 两键；`EnableRadarSweepWindow`/`EnableSWChargeOpt` **同裁决一并定**，裁决前不实现）出**独立握手设计卡** → 实装 → G4.1/G4.2 实测 → 方可进入发布门；
   - **路径 J**：坚持甲，则 Lead **书面改写** G4.1/G4.2 为等效验收（须写明混端误配责任与支持边界）。**未改判据前，甲路径下 G4.1 永远 No-Go。**

3. **不推荐**
   - 半开（握手只告警不拒局）：仍属协议改动，却换不来 G4.2「硬拒」，两头不讨好；
   - 全开关进握手：乙-R6 过度拒绝；
   - 用 B5/任何对拍全绿「顺手宣布可发布」：违 G-R5。
