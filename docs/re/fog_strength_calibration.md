## §1 换算公式（订正后；含原记与勘误块）
**订正后（本卡落地口径）**
```
T = 目标「净压暗（保留比例）」百分比 = 100 × 雾中像素亮度 / 同点无雾像素亮度
m = (T / 100) / 0.71875                      // 0.71875 = s_fogFirstStageGainUpstream（唯一真源常量）
s = clamp(round(512 × (1 − m)), 0, 511)      // 桩强度（1/256 定点），上限 511 见 §2
预测净压暗（保留比例）= 0.71875 × (1 − s/512) ≈ T/100
```
- 推导：桩算式 `out_ch = c_ch − ((⌈c_ch/2⌉ × s) >> 8)`；偶数通道精确为 `c_ch − (c_ch·s)/512` ⇒ 桩保留 `1 − s/512`（全色域违例 0）⇒ 净保留 = 0.71875 × (1 − s/512)，反解即上式。
- **原记（Lead 任务卡口径，已作废）**：`out = c − ((delta·s)>>8)`, `delta = ceil(c/2)` ⇒ 曾据此写 `m = 1 − s/256`、`s = round(m × 256)`。**错因**：把 `t=(⌈c/2⌉·s)>>8` 中的 s 当成 256 分母的乘子，实际等效分母是 512（乘子 `1 − s/512`）。校验：s=256 ⇒ 0.5（正确）而非 `1−256/256=0`。
- **自动档不受影响**：auto ⇒ s=256 ⇒ 净保留 0.359375 = 23/64（= 上一卡实测定谳基线，本卡未改）。

## §2 上限为何取 511（卡面二选一：**取 511**）
- **反例（s=512, 纯白 c=0xFFFF）**：R 段 `⌈31/2⌉×512>>8 = 32 > 31 ⇒ out_R = −1`；桩体随后 `shl ecx,11` 使低 16 位 = `0xF800` ⇒ **R 段借位翻满(31)、G/B 段被 1 污染**（16 位寄存器回绕，不是钳位）。即纯白像素会翻成纯红噪点。
- **取 511 的性质（已穷举证明）**：∀c∈[0,65535], s∈[0,511]，`⌈c_ch/2⌉·s >> 8 ≤ c_ch` ⇒ 逐通道输出天然落在 [0,31]/[0,63]/[0,31]，**桩内零改动、零钳位**（100,663,296 次通道运算，越界 0；见 sim_out.txt [3][4]）。
- 选 511 的额外好处：不触碰桩体字节 ⇒ auto 等价性论证只需覆盖换算层与写入点两态分支。

## 附录 B · auto 等价性论证（A/B；本卡重做）
1. **源码级**：auto 分支执行的仍是校准前那一条语句 `s_fogBlendStrength = (uint16_t)strength;`（blitter_hooks.cpp:1679-1686）；数值档才走 `(strength × scale) >> 8` 分支；强度全局写点全件唯一（1 处 store + 1 处恢复）。
2. **产物级**【原记·旧构建字节】：`0x233F 74 1C`(je) 令 auto 直接落到 `0x235D` 的**共用 store** `66 A3 6C 30 02 10`；旧件同点 `0x22DC 74 14` → `0x22F2 66 A3 64 20 02 10`。auto 执行路径共 4+1 条指令：`mov esi,0x100` / `mov dx,[scale]` / `cmp dx,si` / `je` / store；其中前两条与 cmp **新旧逐字节相同**，`mov dx,[scale]` 仅数据地址 imm32 随 .data 重排变化，`je` 仅 rel8 因**被跳过的**数值档体变长而变（20 B → 28 B）。**auto 不执行数值档体**（含新钳位 0x1FF），故本卡换算订正不触碰 auto 路径。
3. **桩级**：两桩体各 119 B，新旧仅强度全局地址 imm32 2 字节不同；c50 掩码/delta/imul-shr/落像素/续跳逐字节相同。
4. **数据级**：新件 `s_fogBlendStrength` 初值 256（同旧件）；热路径判别 `cmp dx,si` 中 si ≡ 0x100，与 auto 分支写入值一致。
5. **穷举级**：`stub(c, s=本格强度)` 对 65,536 色 × 8 强度档 {0,48,64,96,128,144,192,256} = **524,288 组，失配 0**（sim_out.txt [1] 原文：`失配数 = 0`）。
6. ⇒ auto 档下 (c, s) 输入、桩体代码、写入点语句均与旧件一致 ⇒ 像素逐位一致。真机若仍有差异，首查构建环境，再跑附录 D-①。
