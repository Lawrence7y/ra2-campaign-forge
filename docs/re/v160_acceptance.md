## 三、独立验收核验准则（依据《实测证据标准》）

在 ZCode 提交 `Z-1′` 交付物后，Antigravity 将依照以下准则开展独立复核：

### 1. 证据真实性准入条件（硬性红线）
1. **真实截图要求**：
   - 截图分辨率须与游戏配置分辨率一致；
   - 截图文件体量必须符合真实游戏画面特征（例如 2560×1440 真实 PNG 体量通常在 1.5MB 至 2.5MB 之间，800×600 真实截图通常在 300KB 至 800KB 之间）；
   - 所有提交的截图其 MD5、SHA256 哈希值必须**互不相同**；
   - 图像内唯一颜色数必须丰富（真实战斗/基地画面唯一颜色数通常 $\ge 20,000$ 种），严禁单色或纯黑色占位图。
     > **【勘误 2026-09-29 · MIMO-BENCHPRIS】** 原文「$\ge 20,000$ 种」**在本渲染路径不可达**：ZC-9B 实测截图唯一色数 978–1756（16-bit RGB565 + cnc-ddraw + 夜景战术区），既有已验收证据同量级（zc9 A1 = 1042 色；用户报告原图 = 1101 色）。**建议口径改为「≥800 色，且与既有已验收证据同量级」**。原文保留不删字，以本勘误为准。详见 `out/re_work/mimo_benchpris/audit/threshold_census.md`。
2. **运行期留痕凭证**：
   - 提供执行期间 Windows 进程列表（含 `gamemd.exe` PID 与启动时间）；
   - 提供游戏生成的真实存档文件（文件头具有 Westwood 存档魔数，文件体量符合典型几十至上百 KB 特征）；
   - 提供 `ra2render.log` 运行期日志输出（记录 INI 解析、Hook 安装与运行期心跳）；
   - 2 秒周期遥测计数器输出（`telemetry.json`，含每 2 秒渲染帧数、TickMiss、直视 Cell 数等）。
3. **时间线自洽性**：
   - 整个实测流程包含游戏加载、遭遇战开局、战斗推进、配置切换、读档验证，留存时间戳跨度必须符合实际操作时间（不得少于合理的操作用时）。

### 2. 四大核心功能实测验证要点
1. **小地图迷雾化实测复核**：
   - 静态视角下，当巡逻部队离开某一区域失去视野时，小地图对应区域是否在 0 帧内（即下一刷新周期）即刻退回灰雾；
   - 撤出视野后，敌军红点是否彻底消失，底图是否保持 50% 变暗的地形；
2. **敌方建筑三态实测复核**：
   - 初始黑雾中，敌军建筑是否完全不可见（无地基框、无血条、无阴影）；
   - 派出侦察单位探测后，敌军建筑是否显示已知轮廓；
   - 侦察单位撤离后，建筑轮廓是否常驻留在灰雾中，且与灰雾半透明正常叠加；
   - 己方建筑与盟军建筑在任何状态下均不受门控干扰。
3. **灰雾 4 帧平滑过渡实测复核**：
   - 单位在视野边界往返移动时，灰雾边缘是否呈现 4 帧平滑过渡（视觉无剧烈硬切）；
   - 渐变过程中地表与建筑物是否出现任何颜色溢出、闪烁、彩色噪点或全黑下溢死斑。
4. **跨战局与读档一致性实测复核**：
   - 重新开始一局新遭遇战时，上一局探明的敌方建筑记忆是否被 100% 清零，杜绝幽灵建筑；
   - 载入早期存档时，是否正常根据存档当刻的视野重新盖章，不崩溃、无逻辑分叉。
