# RA2 / 尤复：底层现代化 总体任务概览

> **2026-10-02 方向调整**：当前交付路线以 [PROJECT_DIRECTION.md](PROJECT_DIRECTION.md) 为准：可信基线 → 真实负载/闪退测量 + 安全修改基础 + DLC 最小样例 → 有收益的修复和内容工具扩展。下文 L0–L5 与 M0–M5 保留为历史技术路线；GPU 化、64 位化、全面重写不再是预定交付顺序，须由测量和兼容验证决定。完全逆向不作为交付前提。

> 目标定义：**读取原版安装的资产与数据（MIX / INI / MAP / UI 美术），保留原版核心玩法与界面，
> 只替换"实现层"（渲染、数据布局、内存模型），使游戏匹配现代计算机性能并消除结构性闪退。**
>
> 证据与实测数据见 [REWRITE_RESEARCH.md](REWRITE_RESEARCH.md)。本文只讲**做什么、按什么顺序、怎么验收**。

---

## 0. 三条决策原则

1. **先测量，再动手。** "卡在哪一层"必须用数字回答（M0），否则会把几个月的力气花在错误的那一层。
2. **改动优先压在"契约之外"。** 渲染 / 数据布局 / 位宽属于**实现**；规则 / 触发器 / AI / 存档属于**契约**。
   实现层怎么换都不算改游戏，契约层动一点就是另一个游戏。**收益的大头在实现层。**
3. **能复用绝不重写。** 资产、规则、地图、UI 美术、乃至"原版 exe 作为对拍裁判"——全部复用。
   本仓库的 `ra2forge`（数据层）与 `ra2opt`（稳定性层）已经吃掉了相当一部分工作量。

### M0 的否定结果（这条改变了下一步的优先级）

三次采样（开局 / 同局稍后 / 冷酷 AI 数分钟后）实测：进程只占 **0.21–0.24 个核**，
空闲 81–85%，**余量 4–5 倍**。原版引擎在正常 2 人遭遇战里**根本没有 CPU 瓶颈**。

但 blit 族确实是最大的单一热点群（占忙时 11.6% → 16.6%，随场面上升），
其中 `BlitTransXlatAlphaZRead@G`（单位绘制主路径）在复杂场景独占 15.6%。

**结论：在能复现堵塞之前，L1（渲染接管）的收益上限是未知的，因此不该先做 L1。**
先把"多单位"造出来——见任务清单里新加的第一步。

## 1. ROI 阶梯（按"每单位改动换到的收益"排序）

> 说明：**收益**按对"多单位卡顿 + 闪退"这两个原始诉求的直接贡献排序。
> **改动面**指需要触碰多少"不该碰的东西"（契约层 = 危险，实现层 = 安全）。

| 级 | 动作 | 改动面 | 收益 | 成本 | 风险 | 何时做 |
|---|---|---|---|---|---|---|
| **L0** | cnc-ddraw 升级 + LAA + 栈 + 配置 + 启动器（ra2opt 那套） | 配置 / PE 头 / wrapper | 闪退大幅减少 | **已完成** | 极低 | ✅ 已完成 |
| **L1** | **渲染解耦 + GPU 批渲染** | 实现层（注入式 DLL） | **解决大部分"多单位卡顿"**，画面顺滑 | 1–2 月 | 中 | **首做** |
| **L2** | 数据布局与算法定向优化（空间索引 / 缓存 / 遍历改写） | 实现层（同 L1 通道） | 高（同屏物件数上限抬升） | 1–3 月 | 中高（需裁判） | L1 之后 |
| **L3** | 64 位化 / 内存模型 | 实现层，但接近重写 | 高（消除 4GB 天花板，长局不崩） | 数月 | 高 | 仅当 L1/L2 撞墙 |
| **L4** | 模拟核心并行化 | 实现层（但**顺序敏感**） | 中（且易帮倒忙） | 数月 | **极高**（破坏确定性） | 长期，最后 |
| **L5** | 触发器 / 战役运行时 | **契约层** | 无（除非 L3+ 已做） | 数月 | 高 | 长期，可选 |

**读法**：L1 + L2 就覆盖了原始诉求的绝大部分，且**全程不碰契约层**。
L4/L5 是"想更进一步"时才付的账，不要提前付。

### 反 ROI 清单（**不要先做**的事）

| 不要做 | 原因 |
|---|---|
| 重做引擎的资产管线 | `ra2forge` 已有 MIX(含加密头)/LZO/Format80/地图/触发器，实测验证过 |
| 重做 UI 美术或布局 | 原版 UI 是**现成位图 + 固定布局**，直接复用即是像素级一致，又省钱又像 |
| 先并行模拟核心 | 15Hz 有 66ms 预算，单核够用；并行会破坏顺序 → 回放/联机/触发器全乱 |
| 在没有 oracle 的情况下改模拟层 | 改完无法判断"还是不是红警2"——这是所有重写项目翻车的地方 |
| 用 Python / TypeScript 做运行时 | 反例已实测：`ChronoStorm` 仓库 82 KB / 21 提交；`openra2` 活跃 4 天后停摆 |
| 一上来做战役与触发器 | 那是所有重写项目的共同盲区、也是最晚能到的部分（见 RESEARCH §4.3） |

## 3. 里程碑与验收门

> 每个门都必须是**可测**的。测不过就是没完成，不允许用"感觉差不多了"过关。

| 里程碑 | 时长 | 产出物 | 验收门（可测） | 失败信号（早停） |
|---|---|---|---|---|
| **M0 基线测量** | 1–2 周 | `perf-profile.md` + `python -m ra2re perf` | ~~每 tick 时间分解~~ → **改成：能复现「忙时 ≥80% 单核」的重载状态**，并给出「忙时占比 vs 单位数」曲线；重复测量误差 < 10% | ⚠️ **已触发一半**：剖析工具做完了，但三轮采样只看到 21–24% 单核（4–5 倍余量），**堵塞没复现** → 必须先把重载场景造出来，否则 L1 不该开工 |
| **M1 渲染接管** | 4–8 周 | 注入式 DLL + GPU 批渲染 | 重载状态下 **tick 超时率 = 0**、帧率 ≥ 60、同位置截图与参考**结构一致**（网格对齐、调色板一致、UI 元素位置一致） | 若重载下 blit 占比仍 < 30%，说明瓶颈不在渲染 → 转向 L2/L3 |
| **M2 oracle 骨架** ★ | 2–4 周 | `symbols.json`（**988 类**继承图 + 954 个 vtable 地址）+ 3–5 个纯函数对拍 harness | 1000 组随机输入对拍**一致率 100%**；harness 可在 CI 里跑 | **这是整个项目的关键里程碑**：做不出来则后续所有模拟层改动都不可验证 |
| **M3 热点优化** | 1–3 月 | 空间索引 / 缓存 / 遍历改写补丁 | 500/1000 物件下每 tick 时间**下降 ≥ 50%**，且 M2 的 oracle 全过；连续 1 小时长局不崩 | 若单点优化收益 < 10%，说明热点不在代码而在架构 → 触发 L3 |
| **M4 位宽/内存**（长期） | 数月 | 64 位构建 | 大地图 + 2000 物件长局无内存失败；2GB/4GB 天花板消失 | — |
| **M5 触发器运行时**（长期） | 数月 | 触发器解释器 | 《钢铁残响》通关（战役链 + 触发器 + 目标判定全部走通） | — |

**关键路径**：`M0 →（判断）→ M1 → M2 → M3`。M2 之前**不许动模拟层**。

## 5. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **契约漂移**：换了实现却悄悄改了行为 | 变成"另一个游戏"，且难以察觉 | oracle 对拍（M2）作为硬门；每条改动标注"影响契约/不影响契约" |
| **hook 不稳定**：注入后崩溃率高于原版 | 比不优化更糟 | 纯用户态注入、可一键卸载；把"长局 2000 物件跑 1 小时不崩"列为验收指标 |
| **版本漂移**：exe 一换全部失效 | 工作白做 | 注入前用 `.text` 指纹（`c0368a17…`）校验版本，不匹配就拒绝注入 |
| **时间估计乐观** | 项目烂尾 | M0/M1 兼作**证伪点**；M1 失败即早停并重新评估 |
| **等价性无裁判** | 无法判断进度 | **M2 必须早做**；参考 `vera20k` 在 6 个月 AI 主导后 AI/触发器仍在 Not yet 的现实 |
| **法律风险** | 项目无法公开 | 见下节 |

## 6. 法律与 clean-room 纪律

1. **永不打包 EA 资产或代码**：新引擎启动时要求用户指向自己的正版安装（`Vanguard` 的"双资产模式"可作长期兜底）。
2. **clean-room 惯例**：一队产出规格说明，另一队照规格实现，避免"看着反汇编抄代码"。
3. **oracle 的边界**：把原版当黑盒**调用**（喂输入、读输出）是安全的；把反汇编结果直接翻译成新代码风险高。
   实践中至少要做到"每条移植逻辑标注来源函数 + 独立实现"。
4. **参考 exe 的出处**：用官方渠道的干净 1.001；现有整合版含 `.detour` 与第三方 `xyr.dll`，
   会把补丁行为误当原版行为。

> 从态度问题变成了数据问题：**接管点有地址、继承链有验证、基线有数字、而且知道了当前根本没有堵塞**。

### 已完成产出的用法

```bash
python -m ra2re rtti            # 重新生成符号数据（只读原版 exe）
python -m ra2re selftest        # 18 项自检：布局自洽性 + 已知类层次 + vtable 单调性 + 确定性
```

`symbols.json` 里每个类的字段：`type_descriptor_va` / `col_va` / `vtable_va` /
`vfunc_count` / `vfuncs[]` / `bases[]`。M1 直接用它做拦截，M2 用它定位要对拍的函数。
