## 2. 派发与并行

**供应商限制（用户追加）**：DSH 调度者使用 OpenCode Go 路由 `provider=opencode-go`、`model=deepseek-v4.1-flash`。禁止使用 `deepseek-official` 和 `deepseek-account`，不以恢复官方密钥作为继续条件；模型身份仍须读回核验。

用户允许各 harness 多开会话、多个 subagent 并行。调度层负责能力预检、额度与模型核对、所有权和依赖安排；可用并行度以实际通道为准。

**本地后台上限已解除（2026-10-03）**：Harness Pilot 运行设置 `maxConcurrent=0` 表示不限数量，已热应用到本机 DSH。不得继续按历史 4 槽位拒绝或排队；下述初始并行规模只是调度参考，不是硬性上限。实际新增任务根据就绪工作、写域与可用通道安排，完成回执与验收规则保持有效。

**并行执行优先（2026-10-03 用户追加要求）**：后续任务主动拆成可独立验收的小包，多开独立会话和子代理加速。初始争取 3～6 个实际执行包并行；超过该范围时按剩余额度、响应延迟、写域冲突与验收能力扩容，不为凑数量重复派发。一个执行包完成后及时用下一张就绪卡补位；独立审计可与其他无依赖执行包并行。调度层记录真实 running 数、等待依赖数、待验收数和并行受限原因，不能将准备中的任务算作正在执行。

**调度会话也并行（2026-10-03 用户追加要求）**：DSH 派发任务的会话可多开，不将全部任务集中在单一调度会话。初始可设 2～3 个调度会话，按性能/稳定性、安全修改、DLC 工具链或独立验收划分职责；工作量不足时合并，按实际瓶颈扩容。每个调度会话使用 OpenCode Go / DeepSeek V4.1 Flash，并挂到本项目工作区，分别管理自己的执行会话/子代理、收集交付、复算与返工。

**会话形态澄清**：上述调度者必须是通过 `session/create(workspaceId=...)` 建立的独立普通 DSH 会话，具备自己的任务上下文、外部 harness 派发能力和验收队列。一个主会话创建的 Agent Teams 队友或执行子代理不计为独立调度会话，也不能替代此要求。每个独立调度会话再调用外部 harness 或执行子代理完成它负责的任务包。

各调度会话使用唯一任务前缀、互斥的 control 子目录和明确任务所有权。指定一个总协调会话作为全局派发索引与公共状态件的唯一写者；其他调度会话提交分线状态，由它汇总，不并发覆盖同一总表。跨线依赖、运行时代码单写者和真机实例预约由总协调者安排；难题和重大争议仍提交 Codex。并行规模统一计算全部调度会话派出的执行包，避免每条线分别扩容导致额度与验收队列失控。

真机测试、同一模块修改与具有上游依赖的任务继续按独占/顺序约束执行。GUI 并行以独立会话身份验证为前提；原生 DSH 子代理和可用的外部 harness 后台任务均可组成执行池，统一管理写域与验收。

**DSH 工作区归属（2026-10-03 用户要求）**：之后本项目的普通 DSH 会话必须关联 `ra2-campaign-forge` 工作区。使用 DSH Bridge 创建时检查 `workspace_attached=true`；直接调用 DSH 时传 `workspaceId`，不能仅传 cwd。当前工作区 ID 为 `3796a7ca-9fbe-4b5f-a605-372270afdeef`，调用前按路径解析并核验。原生 subagent 保持父子关系，在已关联的项目父会话下展示，不伪装成独立普通会话。

## 3. 独立验收与升级

DSH 调度者不能只转述执行方报告。至少核验文件与指纹、命令退出码、相关门禁，并用独立算法或直接实读复算关键结论。已有验证器的 PASS 不代替对判据本身的检查。

| 情形 | 处理 |
|---|---|
| 明确的小任务、可运行判据、结论可复现 | DSH 自主派发、验收、返工 |
| 字节/结构/归属证据相互矛盾，执行方结论冲突 | 保留双方原件，提交 Codex 裁决 |
| 同一问题两轮返工仍未闭合 | 停止重复派发，提交根因与证据给 Codex |
| 模拟、随机数、存档或联机契约的设计变更；关键 Hook 安全方案 | 先由 Codex 做设计/风险判断，再派实现与验证 |
| 调度层自己编写复杂验证器 | 安排独立复核和负控，重大争议提交 Codex |

两个模型一致不能替代证据。所有层都区分静态字节、语义归属、实际执行和行为结果。Codex 负责关键复核和汇总审阅，日常独立验收由 DSH 承担。

### 5.6 写域互斥的收尾自证与「未审×未动」交叉比对（2026-10-04 追加）

并发会话写同一棵树时，写域合规不能只写「未越权」声明。本批（DLC HIGH-1 复核 / HIGH-2 修复）两张卡的可复制做法：

- **「写域清单 + 收尾扫描」三桶分类**：开工先记**起点锚**（本卡自有文件的 mtime）；锚文件必须先断言存在——引用不存在的锚会让 `find -newermt ""` **静默匹配全部文件**、首轮分类失真（`DLC_HIGH2_FIX_REPORT.md:188`）。收尾对全树扫描，把改动文件分成 **MINE（写域内）/ 卡片授权沙箱 / UNEXPECTED** 三桶；UNEXPECTED 桶必须给**归因证据**（落在哪些并发写域目录、自己的命令参数里出现这些目录名 0 次），不能只报数字（`DLC_HIGH1_REAUDIT.md:242–243`；`DLC_HIGH2_FIX_REPORT.md:165`）。
- **并发提示只登记、不处置**：运行期观测到他卡写域在推进（如 `singleton/`、`ACCEPTANCE.md`），原样登记路径与 mtime、不读为证据、不修改（`SINGLETON_CENSUS_REPORT.md:315`）；引用他卡文件按**时点指纹**（sha + mtime）钉版本，交付后他方再改写则引用号需按新指纹重钉（`LIVE_CARD_02.md:688`）。
- **「未审范围」×「未动范围」交叉比对**：验收一张修复卡时，把**审计者报告的「未审范围」清单**与**修复者报告的「未动/未闭合」清单**做**交集**，交集项显式登记为下一张卡的最高优先候选——本批 HIGH-2（备份槽写侧别名）恰好落在修复者只披露读取侧、审计者首轮未探针的那条缝里（`DLC_HIGH1_REAUDIT.md:190–191`、`DLC_HIGH2_FIX_REPORT.md:126`）。「双方都没写 = 不存在」是本批实证过的坑。

### 5.7 「修复范围枚举」= 修一族缺陷的**强制前置**（2026-10-04 ROUND3 追加）

**触发条件**：任何"修一个缺陷族"（安全门禁 / 校验规则 / 补丁模板 / 口径更正）的卡，**开工第一步先交范围清单，未交不得动代码**。依据：第三批实测里同一族**第 3 次同型复发**——HIGH-1 修好但 HIGH-2 在备份槽、HIGH-2 修好但 **HIGH-3 在修复自身新引入的暂存名**、HIGH-4 在安装记录、MEDIUM-8 在主拷贝（`LESSONS_20261003_AGENTS_AND_HARNESS.md` §7.1；`DLC_HIGH2_REAUDIT.md:132,244–248,250–260`；`ACCEPTANCE.md:1102–1116`）。

**四项清单（缺一即判"族未做完"，不得写"已修"）**：

1. **点名形态**——被缺陷报告点名的那一处，逐项列"修前坏 / 修后好"实测（原有要求，不变）。
2. **派生路径**——凡由同一个槽位名/记录名派生的路径**逐项列全并施加同等判据**：`.bak`、`.bak.<stage>`、`<name>.<stage>`、`.removed.bak`、临时名、暂存目录（`DLC_HIGH2_REAUDIT.md:132`；仪器篇 T38）。
3. **同语义写点**——同一语义（写文件 / 备份 / 恢复 / 读回 / 删除 / 记录）在代码里有几个写点，**逐个查是否都用了同一原语**；"用了安全原语"必须回答"用了几个点、还剩几个点"，且按符号定位不引行号钉死（`DLC_HIGH2_REAUDIT.md:135,256–260`、`DLC_HIGH2_FIX_REPORT.md:156`；仪器篇 T40）。
4. **记录侧 / 读侧对称**——写侧设了门禁的，读侧与凭据文件（安装记录、清单、listing）是否同等；读侧"先读后判"也算穿透（`DLC_HIGH2_REAUDIT.md:16,262–266`）。

**配套三条**（同批实测，均属"范围"而非"写法"）：

- **绝对句反查**：范围枚举完成后，把 docstring/报告里所有 `never`/`不可能`/`一定`/`唯一`/`全量` 逐句对到**已测形态清单**上；未逐形态实测的降为限定式（仪器篇 T39；`DLC_HIGH2_REAUDIT.md:21,286,287,290`）。
- **形态矩阵**：不跟随/穿透类断言必须**逐形态**实测（活链接 / 悬空链接 / 硬链接 / 目录占位 × 预植 / 窗内 × 读 / 写），并带**正向对照**证明夹具真的会穿透——本轮的 `O_CREAT|O_EXCL` 平台陷阱正是只测了活链接一形态（仪器篇 T37；`DLC_HIGH2_REAUDIT.md:94–104,103`）。
- **限度申报也复算**："某件不在现盘、故用代理件"是**事实主张**，先跑一次哈希普查再决定是否需要代理；被推翻过的同一措辞会在下一张卡原样复活（`RC4_BATCH2_REAUDIT.md:225–239`；`ACCEPTANCE.md:1131,1200`；AGENTS §7.5）。

**验收口径**：修复卡的"未闭合项"清单**不视为闭合面全集**；验收方须自行按上面四项取"清单外的闭合面"（AGENTS §7.4）。继承面一问固定要问：**"声明未动的这段代码，与前代快照是否逐字节相同？"** 相同 ⇒ 属继承缺陷族，同族判据可直接复用、零发明（`DLC_LEGACY_AUDIT.md:6,12,83`；`ACCEPTANCE.md:1143`）。
