二、A1「535 对可比对且全部跨层」
=======================================================================
【我复算成立，且比被审方更强】
  直接槽(1013) 中能与同 COL 修饰名兄弟表比对的槽 = 535
  其余 478 个 = 无任何兄弟表存在该槽号
  535 对中两边 mdisp 不同（跨层）= 535，同层 = 0
补充独立量（被审方未给）：535 对里两侧目标地址相同 = 0；两侧起首 16 字节全同 = 0。

关于"535 是不是全部"与"478 是什么"，我的答案：
  535 是"能比对"意义上的全部，但它不是 1013 的子集划分的唯一读法：
  - 我给的重分组口径（见 R1）下，同组可比较的槽会涨到 987，说明 535 这个数
    完全由"同 COL 修饰名"这一窄分组定义决定，不是语料本身的硬上界。
  478 的成因我逐槽查过，结论是单一成因，不是三种混合：
    兄弟表(同修饰名的其他表)存在、但该表的槽数 <= 槽号 k（槽号越界）  = 478 / 478
    单表组内无其他表（无兄弟表）                                     = 0
    兄弟表有该槽号但全是调整器或同值                                  = 0
  越界槽号集中在 12..40 区间（前 10 个各 12 次），即"派生表比基表短"，
  不是"该槽被删"。所以被审方把 478 说成"无任何兄弟表有该槽号"在字面上准确。

三、A2「跳板跟随 1 跳 / 8 跳 COLLAPSE 均为 0」
=======================================================================
【数成立，但该主张是空心的（vacuously true）——这是我最重要的一条反对意见】
  我的实现：canon 在每跳先读目标首部字节，仅当该处本身就是一条跳板指令
  （E9 rel32 / EB rel8 / FF25 绝对间址）才跟随；maxhop=1 与 8 两个口径。
  结果：hop=1 COLLAPSE=0/535，hop=8 COLLAPSE=0/535 —— 与主张一致。
  环处理：seen 集合，一旦目标已在 seen 中或目标不落 .text 立即停止返回当前地址。
          535 对里没有任何一对触发过环或越界（见下）。

  但关键事实：535 对里"任一侧首部是可跟随跳板"的对数 = 0。
  两侧首字节类型全部是普通函数体（8b4424 / 8b4c24 / c20400 / 32c0c2 / 8b0d30 …）。
  也就是说 canon 在这 535 对上从未生效过一次，"跟随 0 跳"和"跟随 8 跳"是同一个映射，
  COLLAPSE=0 等价于"两侧地址本来就不同"（=535），并不验证任何跳板归并逻辑。
  连"canon 是否真的在工作"都无法被这组数据检验。

  我做了两个加固：
  (a) 把调整器 thunk 也当跳板（83/81 6C 24 04 imm + E9 rel32，5/8 字节指令长度正确解析）
      hop=1 与 hop=8 均 COLLAPSE=0/535；此时 canon 确实改变地址的对数 = 10（正好是
      535 对中兄弟槽本身为调整器的 10 对），10 对逐一比对仍全 distinct。
      （顺带说明：被审脚本 canon 的 ring 检测靠 list 比较，性能无碍；但我发现
       另一支脚本的 adjthunk 若按 4/7 字节步长解析会错位，我按 5/8 字节修正。）
  (b) 用 capstone 版 canon（跟随任意无条件 jmp，含 jmp [abs]）hop=8：COLLAPSE=0。
  (c) 近似坍缩(p²canon(v)==w 或 canon(w)==v，另一侧不 canon)：0。

  结论口径：A2 的"数是 0"我复算成立；A2 的"证明了没有跳板坍缩"我判不成立，
  因为样本内跳板数=0，该主张零信息量。

四、A3「295 不同 / 137 相同 / 103 不可解」
=======================================================================
【三个数我全部复算成立，但"不可解"的解读不成立】
  我的口径：从目标首字节起，按 capstone 线性反汇编，窗口 96 字节；
  遇到 ret 立即取立即数（无立即数记 0）；遇到 jmp / int3 / hlt 且地址>起点则中止
  并记为不可解；起点本身是 jmp 也记为不可解。
  结果：diff=295  same=137  unres=103  合计 535    —— 与主张逐数吻合。

  口径敏感性（我加测，被审方未给）：
    win= 96   diff=295 same=137 unres=103
    win=256   diff=341 same=139 unres= 55
    win=2048  diff=362 same=142 unres= 31

  用 295 去论证"调用约定物理上不可能共用入口"会漏掉 67 对实际也不同约定的对。

  ret 偏移分布（可解者）：min=84  p50=216  p90=533  max=867 字节；>96 的占 88/92。
  这直接说明 96 字节窗口与语料不匹配。

五、R1（改"同组"定义为 同层基类身份 + mdisp）
=======================================================================
我的实现：对每条 COL 取 pCHD，读 [pCHD+8]=基类数 n、[pCHD+12]=BCD 数组指针，
遍历 BCD 取 [BCD+8]==COL.mdisp 的那条，再取 [BCD+0] 所指 TD 记录的 +8 名字
（TD 校验：该 dword == 0x7F9594，全库 988 个 TD 记录）。1214/1214 条 COL 全部解析成功。

  【我复算不成立：535 会显著变化，不是 535】
  三种分组口径，兄弟对按"该槽号在所有同组表里存在且值不为调整器"全体展开：
    分组 = 同 COL 修饰名            组数 954  可比对槽 535   兄弟对  781   跨层 781   同层 0
    分组 = (层基类, mdisp)          组数 965  可比对槽 987   兄弟对 3526   跨层 0     同层 3526
    分组 = 层基类（不含 mdisp）     组数 962  可比对槽 807   兄弟对 4153   跨层 627   同层 3526
  关键数字：(层基类, mdisp) 口径下兄弟对 = 3526，与 535 差一个数量级。
  若采用 (层基类, mdisp)，同层同槽位比较下"目标相同"的对 = 32864，占兄弟对 36390 的 90.3%
  （36390 含调整器兄弟；排除调整器后为 3526 对里 32864? —— 精确数：
    全兄弟 36390，目标相同 32864，原址不同 3526，canon(8,含adj) 后仍不同 3526）。
  换言之：在正确的同层口径下"同槽位同实现"是常态（90%），只有在"同修饰名但跨层"的
  窄口径里才 100% 不同。A1 的 535/535 跨层是全称命题，但它是分组选择造成的，不是发现。
  另：535 个槽在 (层基类, mdisp) 口径下，有 432 个能在同层组里找到"目标完全相同"的兄弟。
  即 535 个"跨层不同"槽中的 432 个，在同层里都有同实现孪生 —— 这才是有信息量的结论，
  被审方没有测。

  注意：R1 提示里"挑 mdisp == COL.mdisp 的那条 BCD"我已照做，并因此发现
  pCHD+8 是基类数、pCHD+12 是 BCD 数组指针，BCD+0 是 pTD、BCD+8 是 mdisp 偏移；
  BCD+12 恒为 0xffffffff（vbase 偏移），BCD+4 是与 mdisp 无关的字段 ——
  我第一版按 BCD+8/BCD+12 双猜，只有 +8 命中 361 条，+12 命中 0 条，可交叉确认布局。

七、R3（103 对不可解抽查）
=======================================================================
【我判：主要是"96 字节窗口太短"，不是"真的无 ret"】
  不可解侧共 105 条（103 对，2 对双侧都不可解）：

  （"无 ret"侧基本是 jmp 到另一函数的尾块，属 32 位 MSVC 的共享尾合并，非真无返回）。

  我实测：严格剔除调整器兄弟后，96 窗口 diff=303 same=137 unres=95。

九、三档结论汇总
=======================================================================
【我复算成立】
  - P1/P2/P3/P4 全部数值：1214 COL / 1214 VT / 14044 槽 / 954 名称组 / 94 多表组 /
    260 非主表 COL / 1318 非主表槽 / 305 调整器 / 1013 直接槽。
  - A1 的 535、535 全跨层、478 无兄弟槽（且 478 的单一成因 = 兄弟表槽号越界）。
  - A2 的 COLLAPSE=0（1 跳与 8 跳），R2 各替代 canon 亦全 0。
  - A3 的三个数 295/137/103（在 96 字节窗口 + 遇 jmp/int3 中止的口径下逐数复现）。
  - Q 四个地址 refs=77/75/78/205。

【我复算不成立（或主张的推论不成立）】
  - A2 的解读："没有跳板坍缩"这一结论无证据力 —— 535 对中可跟随跳板数 = 0，
    canon 从未改变过任何地址，主张空心。加上调整器 thunk 后也只有 10 对动过，仍全 distinct。
  - A3 的解读："103 不可解 = 96 字节窗口内解不到 ret"字面成立，但把它当作
    "这些实现没有返回"或"无法比较调用约定"不成立：73/105 条不可解侧在 2048 窗口内
    正常解到 ret；且 295 这个"不同"数是窗口截断后的下界，放宽后为 362。
  - R1：535 不是不变式。改成 (层基类, mdisp) 后，可比对槽 987、兄弟对 3526、
    同层完全相同 32864/36390(90.3%)。且原 535 槽中有 432 个在同层组里能找到同目标孪生。
    "535 全部跨层"是分组定义的产物，不是语料事实。
  - A1 的 535 与 A3 的 103 口径不自洽：A1 剔除调整器槽，A3 配对未剔除调整器兄弟，
    10 对调整器兄弟混入 103。严格口径应为 diff=303 / same=137 / unres=95。

【我没测（给原因）】
  - 未对 535 对做"语义等价"判定（例如同一函数经不同编译单元重复生成、或经
    mid-function 入口进入同体）：需要控制流图/符号求值，超出本卡"不跑长任务"的只读边界。
  - 未测 0x4C9150 那 205 个引用在运行期是否真的被派发（需动态，属 win-main 节点任务）。
  - 未测 478 个越界槽在 vtable 之外是否另有 RTTI 补充表（本 PE 未见，但未穷举）。
  - 未复核 .detour 段（0xb93000-0xb96000，12KB）内是否有 vtable/COL 副本；
    我的 COL/VT 枚举只扫了 .rdata 与 .data，与前置事实口径一致，若 .detour 含副本会漏。
  - 未测 capstone 对 535 对实现体的完整反汇编正确性（只用线性扫描到首个 ret/终止指令）。

=======================================================================
十一、给主会话的判断
=======================================================================
三条主张的"数"全部可复现，但只有 A1 的数是硬事实（535/535 跨层、478 越界）。
A2 是全称命题但样本内跳板数为 0，属空真，不宜作为"已排除跳板坍缩"的证据入账。
A3 的三个数依赖 96 字节窗口，该窗口与语料不匹配（p90=533、max=867），
建议改用"扫到首个 ret 或函数边界（int3/尾 jmp）"而非固定 96 字节，
且 A1/A3 的调整器剔除口径必须统一，否则 103 里混入 10 个口径噪声。
R1 表明"同修饰名"分组才是 535 这个数字的唯一来源；换成同层分组，
同槽位同实现是 90% 的常态，这才是对下游更有用的结论。
