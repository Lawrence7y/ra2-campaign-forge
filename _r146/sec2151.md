## 2.151 R146 · R145 的两条「未定」被一手字节推翻：① 大位移组不是「结构未定」，是**堆分配 0x18C0 字节对象内嵌异构子对象**的 vptr 写（宿主 0x665650，73 站点 / 8 张虚表 / 54 个位移非等差）；② 0x7E1FB4（INoticeSource）不是「无主虚表」，是 **AbstractClass 链上第 4 个子对象**（mdisp=12）的 vptr，被同槽覆盖属正常构造序列

**一 · 起点与两条待办的原文。** R145（§2.150）第九节把两件事标为未取得：「③ 只被瞬态覆盖的 `0x7E1FB4`（`INoticeSource`）它到底是哪个对象的活 vptr 未定；④ 大位移组（278 站点 / 一致率 0.1259 / lift 15.87）是什么结构仍未定位」，并建议「按成员数组 / 结构体两假说做可失败判据」。本轮把两条都用现盘字节做掉。结论是：**两个假说都错**，而且「无主」这个措辞本身错。

**二 · 口径先对齐（S-322 的教训：残余 / 覆盖这类词必须随身带口径）。** R144 的 278 是**严格口径**（`r143lib.RE_STORE`，其正则在 `[eax - 8]` 这种减号两侧有空格、位移为负的形态上返回 `None`，整类拒收）。本轮用完整内存操作数解析器重算「`mov dword ptr <mem>, imm ∈ VTS` 且 `disp ≠ 0` 且基址 ∈ 通用寄存器」：站点共 **1,310**，其中 small（`disp ∈ {4,8,12}`）**1,027**、large（其余）**283**。严格口径 large 仍是 **278**，差 **5**，这 5 个的位移是 **-8 / -8 / -8 / -4 / -8** —— 与 R145 已定位的负位移形态逐项吻合，这本身就是「宽容解析只多吃负位移」的正控（`r146b` 断言）。

**三 · 大位移组是什么：一手现场。** 做法是 base 寄存器有界回溯（`_r146/r146e_root.py`，最多退 60 条指令）。这里我先犯了一个错：把 `push / test / cmp` 这类**只读**操作数的指令当成寄存器定义点，于是大多数回溯在第一步就「命中」了，分布完全失真（IMM 占比虚高到 4.2% 属于巧合）。改成「只有写目的寄存器的助记符才算定义点」之后，定位到单点最集中的宿主函数 **0x665650**：其内 large 站点 **73** 个、涉及 **8** 张不同虚表。逐指令上下文（`r146d`）给出决定性序列：

```
00665A30  lea      ecx, [esi + 0x2bc]
00665A37  mov      dword ptr [esi + 0x2b4], edi
00665A3D  mov      dword ptr [esi + 0x2b0], ebx
00665A43  mov      dword ptr [esi + 0x2a0], 0x7eb6d4   <== TypeList<PBVAnimTypeClass>
00665A4D  call     0x525680
00665A52  push     ebx
00665A53  lea      ecx, [esi + 0x2d8]
00665A66  mov      dword ptr [esi + 0x2bc], 0x7eb6d4   <== 下一个子对象
00665A70  call     0x525680
```

即：**每 28 字节（0x1c）一个内嵌子对象**，先写 vptr 到子对象起点，紧接着 `lea ecx, [esi + 子对象起点 + 0x1c]` 把下个子对象的 this 装进 ecx、`call` 构造它。`TypeList<H>`（`0x7E4DD8`）在同一函数内出现 **54** 次、写在 **54 个互不相同**的位移上（856, 884, …, 5104），位移差集**不是等差**（`r146h` 实测步长集合 `{28,32,36,40,56,60,88,104}`）—— 所以**不是数组**；不同虚表写在不同成员位移上 —— 所以**是多个异构内嵌子对象**。

宿主对象的大小由唯一调用者一手给出：

```
0052BABE  push     0x18c0
0052BAC3  call     0x7c8e17        ; 分配入口（内部 push 1 + call 0x7c9442）
0052BAC8  add      esp, 4
0052BACB  cmp      eax, ebx
0052BACD  je       0x52bafa
0052BACF  mov      ecx, eax        ; this = 新分配对象
0052BAD1  call     0x665650        ; 构造
0052BAD8  mov      dword ptr [0x8871e0], eax   ; 存进静态指针
```

⇒ 宿主是**堆分配的 0x18C0（约 6.2 KB）大对象**，构造完成后指针存进静态地址 `0x8871E0`。这是本项目第一次用**直接的分配 + thiscall 序列**（而不是靠「静态区里没有该地址」之类的排除法）判定宿主类别。故 R145 待办 #3 的正解是：**既不是成员数组，也不是静态容器内嵌**，而是「堆对象里一串异构内嵌子对象」。

**四 · 0x7E1FB4 是什么：同一槽上的基类子对象 vptr。** `r146f` 给出 0x410170 段的完整序列：

```
00410170  mov      eax, ecx                               ; this
00410174  mov      dword ptr [eax + 8],  0x7e1fbc        ; INoticeSink 子对象 vptr
0041017B  mov      dword ptr [eax + 0xc],0x7e1fb4        ; INoticeSource 子对象 vptr
0041018B  mov      cl, byte ptr [eax + 0x14]
00410191  mov      dword ptr [eax + 0x10], 0xffffffff
00410198  mov      dword ptr [eax],    0x7e1f50          ; AbstractClass 主 vptr
0041019E  mov      dword ptr [eax + 4], 0x7e1f34
004101A5  mov      dword ptr [eax + 8], 0x7e1f2c          ; 覆盖 INoticeSink 槽
004101AC  mov      dword ptr [eax + 0xc],0x7e1f24          ; 覆盖 INoticeSource 槽
```

`r146i` 把归属钉成可失败断言：`AbstractClass` 的 CHD 里 `numBaseClasses = 8`（**含 `[0]` 自身**，见第六节的措辞更正），其中 `INoticeSink` 的 **mdisp = 8**、`INoticeSource` 的 **mdisp = 12**，与它们被写的位移 **8 / 12 逐一相等**；覆盖者 `0x7E1F24` 的 `COL.locator`（即 `COL+4`）恰为 **12**，即同一槽上的**派生类** vptr。三处写 `0x7E1FB4` 的函数里，同函数还各有 **5 / 5 / 9** 个别的槽的 vptr 写 ⇒ 它们是**子对象构造函数**，不是 INoticeSource 的独占 ctor。

⇒ R145 的「瞬态 = 只有被覆盖的站点」这个判定是对的，但由此推出「谁的对象未定」是错的：**它明确是 AbstractClass 派生对象内 INoticeSource 这个基类子对象（对象偏移 12）的 vptr**。现盘没有「INoticeSource 作为最派生类被构造」的路径，所以它在运行期不会静止存在 —— **「归属明确」与「运行期静止存在」是两件事，必须分开写**（R145 那句话把两件事合成了一句，是措辞病）。

**五 · 反控（每条判据都在已知量的另一侧跑了一遍）。** ① small 桶 **202/202** 个「(函数, base) 多站点组」的位移是**步长 4 的等差数列**（= 多继承子对象，已知真值），large 桶只有 **7/15** 组等差且步长 28 / 24；② `LayerClass`（`0x7E6060`，R145 已证持久）的 CHD 结构与本组明显不同（见六）；③ 宽容口径比严格口径多 5 站点且全为负位移，与 R145 的根因同源；④ `r146b` 里我写过两条**退化判据**并被断言当场抓出：J1 用「disp − COL.offset 的残差」再判等差（残差把 small 组全压成 0，正控直接 FAIL），J2 把「站点自己」的 (vt, disp) 记进集合再查询（恒真，small 组也是 0/1027）。两处都改掉了，记在 LEAD_LOCK 的自错条目里。

**六 · 跨家族审计（规则 D）与三处措辞更正。** 审计员 #326（deepseek，10 回合 / 6.67 分 / 无 OVERTIME）提出三条批评，我用 `_r146/r146j_audit_recheck.py` 逐条亲测复算，**11/11 PASS，三条全部成立**：

  - **（a）我的断言有歧义（S-324）**：`.?AVINoticeSource@@` 在镜像里被**两个**地址指代 —— 自有虚表 **`0x7E1FB4`**（`COL 0x7FB160`、`locator = 0`，`.text` 解码命中 **3** 次、全 `eax`、全位移 12）与 AbstractClass 组的 **`0x7E1F24`**（`COL 0x7FAFD8`、`locator = 12`，命中 **5** 次、位移全 12、基址集合 `{eax, ecx, esi}`）。写「那个虚表地址出现 3 次」会被读成后者。凡「某个类的虚表」都必须带 **COL VA + locator** 才能唯一定位。
  - **（b）我的断言是事实性错误（S-323）**：`LayerClass` 的 CHD `numBaseClasses = 3`，但 `pBaseClassArray[0]` 是**类自身**（`nCB = 2`），真基类只有 **2** 个。写「基类链长度是 3」会被读成「3 个基类」。本条的 same 错误也适用 `AbstractClass`（8 项 = 自身 + 7 个真基类）。另外，「mdisp 全 0」在单继承下本就是默认值、几乎不构成证据，要论证「无多重继承位移、无虚基类」必须同引 `pdisp 全 -1`。
  - **（c）计数口径必须声明（S-325）**：「原始对齐 dword」与「解码后的立即数」会不同 —— 实测 `0x7E1FC8` raw = **3** / decode = **0**（跨 dword 边界的巧合命中），而 `0x7E1FB4` 与 `0x7E1FBC` 两种口径相同。

**七 · 执行员盲测（规则 D）与两处措辞采纳。** 执行员 #325（hy4，24 回合 / **10.08 分** / 回收打 `[OVERTIME: 实测 10.08′ vs 预算 8.0′]`，如实登记）独立重算三项：严格口径 **1,027 / 278**、宽容 **283** 且多出的 5 个位移 **-8 / -8 / -8 / -4 / -8**、`0x7E1FB4` 命中 **3** 次且位移全 12 —— **三项与我逐项相同**。它自报基准：`VTS = 1,218`（TDs 988 / COL 1214）、exe **4,825,360 B**、sha256 `73201cc0…`。它还自主提出两条，我都采纳了：

  - **我卡面写的「严格口径只吃 `[reg+0xNN]` / `[reg-NN]` 无空格形态」与 capstone 实际打印不符** —— capstone 原始输出是 `[eax + 0xc]`（加号两侧有空格），严格口径拒的只有**减号**那一类。这是我在卡面下的措辞错，不是数值错。
  - **`0x4A8660` 写的正是 `0x7E6060`** —— 即 R144 §七「该虚表未找到装表站点」也是被同一个负位移盲区漏掉的（R145 已修此根因，但当时只登记了「新增覆盖恰一张」，没有回头改 R144 的措辞；这一项留作**旧节更正**待办，需单独一卡 + 门禁回归）。

**八 · 未取得（不粉饰）。** ① 宿主 `0x665650` 的**成员类型序列**只解到 8 张虚表名，其余非 vptr 字段未解析；② `0x8871E0` 这个静态指针在运行期何时被重新赋值、对象何时释放 —— unknown（动态项）；③ `0x7E1FB4` 是否曾作为**最派生**类实例存在：静态侧没有构造路径，但这不等于运行期不存在（例如指针强转后直接构造基类子对象），需动态验证；④ `0x7C8E17` 我只证它是**分配入口**（`push 1` + `call 0x7C9442`），**未证**它是 `operator new` 本体 —— 引用时必须按这个措辞；⑤ 动态项（虚表运行期读取、3,805 处寄存器 `call/jmp` 落点、35 个静态容器运行期值、窗口表 r66 后快照）仍留 win-main；⑥ 已判死线继续禁投：具名池、无名池、direct-only(D2)、D4结构性无、静态④、动态④、证据指针791行、D-48攻②-b。
