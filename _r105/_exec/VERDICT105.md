# R105 EXEC 独立复算结论（hy4）

被测：`ra2bench/gamemd.exe`，sha256 `73201cc021497c9567742f718bf1dc78c22e9ae16c7e7365354b65f3fcf67476`。
脚本：`_r105/_exec/r105_exec.py`；全部数字：`_r105/_exec/r105_exec.json`。
未读取、未 import 主会话的 `r105a_tableentries.py/json`。

## 口径（自己从 exe 字节实现）

- PE 手工解析（`struct`）：`ImageBase` + `.text.VirtualAddress` 得 VA 起点，`.text.Misc_VirtualSize` 同时作为 iced 解码缓冲长度和 DWORD 读取的长度上界；读写均小端。
- 线性扫描：iced-x86 1.22.0（vendored at `_r104/vendor`），`Decoder(32, text, ip=B)` 逐单元推进；每个单元的 `ip` 记为“单元起点”，另用 `is_invalid` 区分合法/非法起点（两者不是同一集合）。
- **表**的定义：`JMP` + op0 `MEMORY` + `memory_index_scale==4` + `memory_index != NONE` + `memory_displacement` 落在 `.text`；跳过 `is_invalid` 单元；按 disp 分组（分组即持有该表的指令集合）。从 disp 起每 4 字节读 DWORD，只要读出的 DWORD 值仍在 `.text` 内就继续，到第一个越界值或满 512 项为止；只保留项数 `n >= 2` 的表。
- **B1 归属表**：`detail` 中 `class=="B1"` 的 `host` 字符串按十六进制解析；宿主落在 `[base, base+4*n)` 即归属该表。**不做 `(host-base)%4==0` 的对齐过滤**：B1 的 31 个宿主中有 3 个（`0x6dfe19`、`0x6dfe41`、`0x708d55`）分别落在 `0x6dfdec`、`0x708d54` 两张表的非对齐内部；若按 DWORD 对齐过滤会漏掉这 3 个宿主和这 2 张表，得到 15 表/245 项的错数。卡面要求的“落在几张表内”应按字节区间判定。
- **项值合法性**：`val in unit_ip_set AND val not in invalid_starts`；只用“在 ip 集合内”不够，因为非法字节也产出 ip。
- **函数入口判据**：(a) `val > holder_ip`；(b) `val` 是否属于 `{CALL + NEAR_BRANCH32 → near_branch_target}`；(c) 每表 `max(vals) - holder_ip`。

## 逐问对照

### Q1 表枚举
- 表总数：**360**
- 持有指令总数（仅这 360 张表内）：**378**（全部满足 disp 条件的持有指令组数 368、指令总数 386）
- 项值总数：**2702**

### Q2 B1 定位
- B1 行数：**41**
- 去重后宿主数：**31**（41 行里多个 `a` 共享同一 host）
- 宿主落在表内的数量：**31/31**，去重后表 base 数：**19**
- 这 19 张表合计项值：**292**
- 表基址：`0x46f5a0, 0x48db10, 0x48dd10, 0x4c8114, 0x5001e4, 0x58bda4, 0x69b15c, 0x6a92c4, 0x6adbdc, 0x6b0238, 0x6dfdec, 0x708d54, 0x71f2c0, 0x71f328, 0x71f778, 0x71f9e0, 0x728e08, 0x7291ac, 0x79f028`

### Q3 项值是否合法单元起点
- 292 个项值中，合法单元起点（非 invalid）：**292/292**
- 其中 292 个都在 ip 集合内、0 个 invalid、0 个不在 ip 集合内。
- 反面提示：全 .text 线性扫描共 1,392,537 个单元，其中 66 个是 invalid；非法起点确实存在，所以“非 invalid”不是恒真判据。

### Q4 是不是函数入口
- (a) 项值严格大于本表持有指令地址：**292/292**
- (b) 项值是任何 `CALL rel32` 直接目标的数量：**0**（call 目标集合总数 6,728）
- (c) 每表跨度 `max(vals) - holder`：min **10**、median **457**、max **9462**（字节）。逐表明细见 JSON 的 `Q4.span_rows`。
- 结论：三项联合指向“函数内 case 标签”，而不是函数入口 —— 前向性对 case 标签是结构性必然，对函数入口无要求；无 call 直引排除了常规函数入口；跨度与 holder 同处一个函数体范围。

### Q5 反控（判据非恒 0 的证明）
- 随机 292 个 `.text` 地址、跑 200 次，“合法单元起点”比例：中位数 **0.3425**（0.27397～0.42123，p05=0.2979、p95=0.3938、mean=0.3436）。与真表项的 1.0 相差约 0.66，判据有判别力。
- 从 6,728 个 call 目标里随机抽 292 个，“在 call 目标集合中”：**292/292**。
- 所以 A3b（“项值不是 call 目标”）对真表项恒 0 是因为对象本身不是函数入口，不是因为判据恒 0：对真函数入口样本，同一判据给出 0/292 命中（即全部被判为 call 目标）。

## 与主会话预期的一致性
Q1=360/378/2702、Q2=41/31/19/292、Q3=292、Q4=(292,0)、Q5 随机比例 < 1 且 call 反控 292/292 —— **全部一致**，没有口径差异需要申报（唯一需要写明的是 B1 宿主归属不做 4 字节对齐过滤，理由见上）。
