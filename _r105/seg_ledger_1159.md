### 一 · 为什么必须换判据

R104 待办原话是「验是否合法函数起点（prologue 形态/被 call 直引/链可达）」。三条实测：
- 「前一条单元是 ret/jmp」判 prologue → 得 **275/292**。MSVC 的 case 体几乎都以 jmp/ret 收尾，
  这个数说明的是「.text 里到处是 jmp」，**零判别力**。
- 「链可达」在 switch 内恒成立，**零判别力**。
- 「被 call 直引」有判别力（见第三节），但它是**否证**「是函数入口」，不能正面证「是代码」。

结论：这批表是 **switch 分派表**，项值是 **case 标签（函数内基本块）**，不是函数入口。
判据若写成「必须像函数入口」，会把 292 个真实代码全判成「不是合法起点」——是判据错，不是对象错。

### 二 · 四条同时成立的闭环（本轮判据）

| 编号 | 判据 | 实测 |
|---|---|---|
| A1 | 项值是 iced 线性扫描下的**合法**（非 invalid）单元起点 | **292/292** |
| A3a | 项值严格**大于**本表持有指令地址（前向性） | **292/292** |
| A3b | 项值**不是**任何 `call rel32` 的直接目标（描述性，不作证据） | **0/292**（P=0.62，不显著） |
| A5 | 项值**能经该表的分派结构取到**（无死槽） | **292/292** |

A5 是本轮最硬的一条：两级形态按字节表实际取值集合算可达、直接形态按 [0,BOUND] 算可达，与 [0,n) 求交。
若某项永不可能是分派目标，把它叫 case 标签就没有依据。

**A3b 的力度必须单独声明（本轮最大一次降级）**：「0/292 是 call 目标」在零假设下**不显著** ——
基率①随机 .text 地址 = 6,728/4,060,045 = 0.001657 ⇒ 期望 0.484、P(X=0) = **0.6161**；
基率②随机合法起点 = 6,692/1,392,471 = 0.004806 ⇒ 期望 1.403、P(X=0) = **0.2450**（②才是可比基率）。
两个 P 均 >> 0.05。故 A3b **只是描述性伴随事实，不构成「非函数入口」的证据**；
主力是 A3a 前向性与 A5 可达性。引用「0 个 call 目标」必须连这两个 P 值一起引。

### 三 · 口径与跨实现互证

- 表 = `jmp r/m32` + op0 MEMORY + index scale==4 + index 非 NONE + disp32 在 .text；从 disp 连续读 DWORD，
  首个越出 .text 即止（上限 512 项），保留 n >= 2。**360 张表 / 378 持有指令 / 2,702 项**（三处独立实现同值）。
- B1 的 41 行去重得 31 宿主 → **19 张表 / 292 项**。
  **宿主归属必须按字节区间判、不得做 DWORD 对齐过滤**：3 个宿主（0x6dfe19 / 0x6dfe41 / 0x708d55）非对齐，
  过滤会漏掉 3 宿主与 2 张表，得 15 表 / 245 项的错数（此点由执行员 hy4 #168 主动提出，主会话复算确认）。
- **call 目标集合 6,728**：iced 1.22.0 与 capstone 5.0.7 **两实现同值**；第三方 objdump 亦同值 6,728。
- 19 张表分两种 idiom，均字节闭合：
  - 两级 10 张：`cmp k,BOUND / ja / xor r,r / mov rl,[k+BYTETAB] / jmp [rl*4+TAB]`，
    BYTETAB == base+4n（10/10）、字节值 < n（10/10）、BOUND+1 输入压缩到 <= n 目标（10/10）。
  - 直接 9 张：`cmp k,BOUND / ja / jmp [k*4+TAB]`，BOUND == n-1（9/9）。

### 四 · 自错 4 处（全部如实保留）

1. A2 按单一 idiom 写断言 → **9/19 FAIL**。真 idiom 是两种，两级形态里被 cmp 的是输入值、jmp 用压缩下标，
   结构性不可能同寄存器。
2. A3 用 prologue / 前一条 ret-jmp 判函数入口 → 275/292，零判别力（见第一节）。
3. A3 反控「从 call 目标集合抽 292 个再查该集合，命中 292/292」是**同义反复**，由 deepseek #169 指出，
   批评成立。已换成：随机 292 条 call **指令**重算 target 命中 292/292；随机 292 个 .text 地址命中
   call 目标集合中位 **0.0000**（max 0.0137、群体比例 0.00166）。
4. **「31 个宿主全部是 invalid 单元起点」是错的，实测 30/31**：0x728e15 不在 ip 集合里，
   落在 0x728e10（`ror byte ptr [ebp-73E1FF8Eh],1`，len=6）内部、偏移 5。
   正确口径 30 在 ip 集合且全 invalid、0 合法、1 不在集合。
   **这与 R104 EF10 的 0x728e16 口径分歧是同一地址，连续两轮栽在它上面**，根因同一个：
   把「在 ip 集合里」当成「是 invalid 起点」而不另行判成员。已加覆盖映射 IP_COVER。
5. **把 A3b 的「0/292」写成「强证据」是统计错**（同一审计员 #169 指出，我复算确认）：
   零假设下 P=0.6161 / 0.2450，均不显著。真实计数不等于显著效应；这条已立为纪律候选。
