## 2.109 R17 第 105 轮 · 跳转表项的存在性判据：19 张分派表的 292 个项值全部是「可经分派到达的合法代码起点」，0 个是函数入口

R104 把 B1 的 41 个宿主定性为跳转表项，留下「表项值指向的真实函数入口未逐一定性」。
本轮把这个提法本身校正过来：这批表是 **switch 分派表**，项值是 case 标签，不是函数入口。
认定「项值是代码」靠的不是「像不像函数入口」，而是下面四条同时成立的闭环。

### 2.109.1 口径先钉死：360 张表 / 2,702 项 / 其中 19 张 292 项
表 = 「jmp r/m32 且 op0 为 MEMORY、index scale==4、index 寄存器非 NONE、disp32 落在 .text」的持有指令所指的 disp32，
从 disp 起连续读 DWORD，读到第一个不在 .text 内的值即止（上限 512 项），保留项数 >= 2 者。
实测 360 张表 / 378 条持有指令 / 2,702 项（两套独立实现 + 一个子代理，三处同值）。
B1 的 41 行去重得 31 个宿主，落在 19 张表内、合计 292 个项值。
**宿主归属必须按字节区间判、不得按 DWORD 对齐过滤**：31 个宿主里 3 个（0x6dfe19 / 0x6dfe41 / 0x708d55）
落在非对齐位置，对齐过滤会漏掉这 3 个宿主与 2 张表，得 15 表 / 245 项的错数。

### 2.109.2 A1：292/292 项值都是**合法**单元起点
线性扫描 1,392,537 单元、sum(len)=4,060,045=.text VirtualSize（铺满）、其中 invalid 66 个。
292 个项值逐个查 `is_invalid`：292 个全为 False。**两个集合必须分开** ——
「在 ip 集合里」不等于「是合法起点」（invalid 字节也会产出 ip）；同样，「单独解码」口径下
0 个 invalid，与线性扫描口径 292/292 是两条各自成立的测量，不得合并成一个数。

### 2.109.3 A2：19 张表分两种 idiom，两种都被字节实测确认
- **两级形态 10 张**：`cmp k, BOUND / ja default / xor r,r / mov rl,[k+BYTETAB] / jmp [rl*4+TAB]`。
  BYTETAB **恰好紧贴 DWORD 表尾**（== base + 4n），10/10 全部如此；表中每个字节值 **< n**（10/10）；
  BOUND+1 个输入值压缩映射到 <= n 个目标（有重复，10/10）。这是 MSVC 压缩跳转表的固定布局。
- **直接形态 9 张**：`cmp k, BOUND / ja default / jmp [k*4+TAB]`，BOUND == n-1（9/9）。

**自错登记**：本条第一版断言「多数持有指令前是 cmp 同一索引寄存器 + jcc」，实测 9/19 FAIL。
逐窗口打印后确认是**判据错而不是对象错**：两级形态里被 cmp 的是输入值 k、jmp 用的是从字节表加载的
压缩下标 rl，两者结构性不可能相同。已改为按形态分类，并保留 N3 反控（去掉同寄存器约束后
命中 19/19 > 9/19，证明该约束确实在起作用）。

### 2.109.4 A3：判据与**力度必须分开报** —— A3b 数值为真但不构成证据
- **A3a 前向性 292/292**：每个项值都严格大于本表持有指令地址。case 标签必在 holder 之后，函数入口无此要求。
- **A3b 无 call 直引 0/292**：项值从不是任何 `call rel32` 的直接目标（call 目标集合 6,728 个，
  iced 与 capstone 两实现同值）。**但这条单独不构成「非函数入口」的证据**，见 2.109.4.1。
- **A3c 跨度聚类**：同表内项值跨度最大 0x24f6 = 9,462 字节，仍在该函数体内。

#### 2.109.4.1 A3b 的统计力度：如实降级（由跨家族审计员指出，主会话独立复算确认）
「0/292 是 call 目标」在两种零假设下都**不显著**：
- 基率①随机 .text 地址命中 call 目标 = 6,728/4,060,045 = 0.001657 ⇒ 期望 0.484 个，P(X=0) = **0.6161**
- 基率②随机「合法起点」命中 call 目标 = 6,692/1,392,471 = 0.004806 ⇒ 期望 1.403 个，P(X=0) = **0.2450**
基率②才是可比基率（292 个项值全部是合法起点）。两个 P 都远大于 0.05。
⇒ **数值为真，但不构成统计证据。** 推翻「函数入口」的主力是 A3a 前向性与 2.109.5 的可达性，
不是 A3b。凡引用「0 个 call 目标」必须同时给这两个 P 值，不得再写成「强证据」。

**自错登记（第 2 处）**：第一版用「前一条单元是 ret/jmp」判函数入口，得 275/292，
这个判据**没有判别力** —— MSVC 的 case 体几乎都以 jmp/ret 收尾，275 说明的是「.text 里到处是 jmp」。
弃用该判据。

**自错登记（第 3 处，由跨家族审计员 deepseek #169 抓出）**：第一版的反控是「从 call 目标集合里
抽 292 个再查该集合，命中 292/292」，这是**同义反复**，只能证明实现无 off-by-one。
已换成两条非同义反复反控：随机 292 条 call **指令**重算 target 命中 292/292；
随机 292 个 .text 地址命中 call 目标集合的中位比例 0.0000（最大 0.0137，群体比例 0.00166）。

**自错登记（第 5 处，同一审计员，本轮代价最大的一处）**：我把「0/292」直接写成「强证据」，
没有算零假设下的 P 值。复算后 P=0.6161 / 0.2450，不显著（见 2.109.4.1）。
**这是统计基本功的缺失，不是口径分歧** —— 一个真实计数不等于一个显著效应。

### 2.109.5 A5：292/292 项值都能经分派结构取到 —— 没有一项是摆设
两级形态按字节表实际取值集合算可达、直接形态按 [0, BOUND] 算可达，与 [0, n) 求交：
292/292 可达、**0 个死槽**。这条是「项值是 case 标签」最硬的闭合 ——
若某项永不可能是分派目标，把它叫 case 标签就没有依据。

### 2.109.6 如实登记的第 4 处自错：0x728e15（同一地址连续两轮栽）
我最初报「B1 的 31 个宿主全部是 invalid 单元起点（31/31）」，**错**。实测 30/31：
0x728e15 **不在 ip 集合里**，它落在 0x728e10（`ror byte ptr [ebp-73E1FF8Eh],1`，len=6）这条指令内部，偏移 5。
故正确口径是 30 个在 ip 集合且全 invalid、0 个合法、1 个不在集合。
这与 R104 EF10 记的「0x728e16 口径分歧」是**同一个地址**，连续两轮在它上面出错，
原因是同一个：把「在 ip 集合里」当成「是 invalid 起点」而不另行判定成员。

### 2.109.7 可复用判据（建议进纪律）
1. `.text` 内见到「位移 0 的条件跳转」→ 先测是否某个 `jmp [reg*4+base]` 表的项内字节（R104 已立）。
2. 见到「两个解码器都拒解」的地址 → 先测是否落在「全项为 .text 指针」的 DWORD 表体内（R104 已立）。
3. **判「表项是代码还是数据」不得用 prologue 形态或「前一条是 ret/jmp」** ——
   对 case 标签两者都成立、对函数入口也成立，零判别力。应改用本节的闭环
   （合法起点 / 前向性 / 经分派可达），**不要用「无 call 直引」当主判据**（见 2.109.4.1）。
4. 引用任何「表项是否函数入口」的数字，必须同时给「合法起点」与「call 目标」两个口径，
   缺一个就把「是代码」与「是函数入口」混成一个命题。
5. **任何「0 个命中」型结论必须附零假设 P 值**。基数小、样本 292 时，「0 个」常常完全不显著
   （本轮 P=0.62），把它写成「强证据」是统计错，与口径错同族。

### 2.109.8 未取得
① 19 张表所属的 **19 个函数**本身未逐个命名（只证了项值是 case 标签，未证每个 switch 的语义）；
② 两级形态的字节表把 BOUND+1 个输入映射到 n 个 case，**哪些输入共用一个 case** 未逐表列出；
③ 直接形态的表 0x728e08 有 4 项同值 0x728de0（跨度 0），这 4 个 case 是否真的等价未证；
④ 258/276 个去重项值从不被任何直接分支引用（只经表间接到达）—— 这与「间接跳转」自洽，
   但「是否有 case 永不执行」需要运行期采样，win-main 仍 OFFLINE；
⑤ 未碰门禁与 FACT_INDEX（本轮主攻 R104 遗留的 gamemd 缺口）。
