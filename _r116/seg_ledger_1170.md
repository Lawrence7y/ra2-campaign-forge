
## §1170 R116（2026-11-24）· IID 的客户端请求面：0x7f7c80 侧定死为 IPersistStream 角色（36/36 耦合 + 数据流 35/35）；0x7f7c70 侧仍 L4 未证，不编 IPersist

R116.1 **换面的理由**：R112–R115 四轮全在**服务端**（类 slot0 的 `repe cmpsd` 比对序列）判
0x7f7c70 / 0x7f7c80，该面上两者永远同现于同一批函数、命中写回同一指针 ⇒ 认领类各 90 类、
对称差 0 ⇒ 不可区分。**该结论正确**，但适用域仅服务端识别集。本轮改读**客户端请求集**
（谁把哪个 IID 当 riid 请求、返回值交给哪个 ole32 API）。识别集对称**不蕴含**请求集对称。

R116.2 **字节事实（L1）**：0x7f7c70 = `0000010C-0000-0000-C000-000000000046`，
0x7f7c80 = `00000109-0000-0000-C000-000000000046`。全 .rdata 的 GUID 形状常量（+4 dw==0、
+8 dw==0xC0、+12 dw==0x46000000）共 **6 个**：0x7f7c70 / 0x7f7c80 / 0x7f7c90 / 0x7f7ca0 /
0x7f7cf0 / 0x7f7d00。

R116.3 **请求面实测（L1，两套独立实现同值）**：0x7f7c80 任意 4B 命中 64 = mov 4 + **push 60**，
落在 **36** 个函数；0x7f7c70 任意 4B 命中 **4**，**全部**是 `mov edi,imm32`（服务端 cmpsd 基址，
imm 起点 0x4102b1 / 0x4f68c9 / 0x5125dd / 0x55aa2d），**push 站点 0 / 请求函数 0**。
对照：IUnknown(0x7f7c90) push 56 / 8 函数；0x7f7d00 push 2 / 2 函数；
0x7f7ca0、0x7f7cf0 push 0。
替代解释已排除且**反控有正控**：两步形态 `mov R,imm ; push R` 全 .text 实测 **273 例**
（正控存活）其中 0x7f7c70 者 0；栈槽形态 `mov [esp+X],imm32` 实测 **4495 例**（正控存活）
其中 0x7f7c70 者 0；全镜像扫描确认 0x7f7c70 的 4 处全在 .text，不在 .data/.rdata。

R116.4 **与 ole32 的耦合（L2，仅依赖 ole32!OleSaveToStream 的公开签名
`HRESULT OleSaveToStream(IPersistStream *pPStm, IStream *pStm)` 这一条外部事实）**：
36 个请求 0x7f7c80 的函数**全部**在请求之后调用 OleSaveToStream（IAT 0x7e15f4），
两种调用形态都算（直接 `call [IAT]` 与 `mov reg,[IAT] ; call reg`）⇒ **36/36**。
数据流：35 个「QI(0x7f7c80) → OleSaveToStream」站点中 **35/35** 可机械证明
「第 1 实参 == QI 从 ppv 栈槽装回的接口指针」（ppv 由更早的 `lea` 定义，非紧邻指令）；
ppv 偏移错开 4 字节后命中 **0**（有牙反控）；换成 IUnknown 同样数据流命中 **0**。
第三面：`OleLoadFromStream` 第 2 形参即 REFIID，8 个调用点中该位 0x7ed358 出现 **5** 次、
0x7e9af0 出现 1 次、**0x7f7c70 0 次** ⇒ 该位确实承载 IID。

R116.5 **关键降级：独立证据数只有 2 类代码形状**。35 个站点不是 35 份独立实现：
① 35 个 dispatcher 调用点全部满足锚形态 `mov ecx,esi ; mov edx,imm32 ; call rel32`；
② 35 份被调函数体前 **112 字节逐字节全等**；③ 35 个 `edx` 两两不同且全落 .data。
⇒ 实为 **1 个例程模板 + 1 张 35 项 .data 表**；独立证据数在**代码**维度是 **1**、
在**数据项**维度是 35；按抹掉立即数的指令形状去重，36 个请求函数只有 **2 类**。
审计员据此判「97.2% vs 0%」**不可当效应量**：Fisher 单侧 p = 2.70e-09（方向极显著），
但 target 去重后仅 2 类、baseline 仅 10 对且其中 8 对与 IUnknown 反控完全重叠。
**主会话接受该降级**，上述所有比例必须与本节同框引用。

R116.6 **分级裁决**：1.1/1.2/1.3/1.5 = **L1**（字节事实）；1.4 = **L2**（依赖 API 签名）；
1.6「0x7f7c80 的语义 = IPersistStream」= **L3**（在 L2 之上，已列出未排除的替代解释：
通用「任何 ole32 能存的接口都交出去」包装器对其它未出现的 IID 一视同仁）；
**1.7「0x7f7c70 的语义 = IPersist」= L4 未证，不编**。
不编的理由：该 IID 零正面客户端证据，名字只能来自「沉默 + 排除法」；而 COM 继承约定
**预测**这个沉默（IPersistStream 继承 IPersist，客户端只需请求派生接口）
⇒ 基类 push 计数 0 是正常用法的预期结果，不是它等于 IPersist 的证据。

R116.7 **与 R112 的关系（范畴不越界）**：R112 命题域 = 服务端识别面（域内不可区分，**仍正确**）；
R116 命题域 = 客户端请求面（高度不对称）。二者正交、可同时为真：
一个类可同时响应两个 IID（服务端对称），客户端因类型需要只请求派生接口（客户端不对称）。
用 R116 + 外部 SDK 签名去声称「R112 错了」是拿域外前提推翻域内结论。
本轮正确表述：**边界从「静态不可区分」推进到「引入外部命名前提后可推定派生侧」，
R112 在其域内仍正确，基类侧仍未取得独立证据。**

R116.8 **跨家族配对与复算（规则 D）**：exec **deepseek** task 208 派发后 14 分钟无产物、
阻塞 `do_epoll_wait`、无子进程，超 8 分钟预算 ⇒ 按 **[OVERTIME] 如实登记并终止，
未当作正常完成、其产物未采用**。audit **hy4** task 209 产出 VERDICT，判 C1–C5/C7/C8 PASS、
**C6 FAIL（越界）**。其 4 条措辞修正（C2 须附 S-24 口径 35→36 且命中的全是 Save 不是 Load；
C3「先请求」是文本序非控制流序；C4 与 C7 数据重叠 80% 故非独立反控；A2b 的 exp=0 是退化比较）
+ 2 条方法论批评（基类解释无法用本镜像排除；R116 不构成对 R112 的证伪）
**全部由主会话写 r116l 逐条复算 11/11 PASS**；其中 1 条为如实登记的审计员数字不符：
其「target 至少 34 时 p = 4.7e-07」我复算 = **1.62e-08**（差 29 倍），
但主结果 p(35)=2.698e-09 逐位吻合、两者都远低于阈值，**不动摇其结论**。
主会话**接受 C6 越界**：本机实测**不存在**任何 IID→接口名 映射表（无 objidl.h 等），
「0x7f7c70 = IPersist」在本机无法机检。

R116.9 **本轮自错（如实登记）**：S-23 自参照基线（把被测 0x7f7c80 自己算进基线，46 对里 35 对是它自己，
循环对照）→ 留一法修正为 0/10；S-24 IAT 调用形态漏检（只认直接 `call [IAT]`，
漏 `mov reg,[IAT]; call reg`）→ 误得 35 耦合，修正后 36/36；
S-25 把模板拷贝当多份独立证据（= R115 S-15 复发）→ 三粒度并列；
S-26 把「数值落在 .text 区间」当指针（命中实为 UTF-16 字符串 "t\0y\0"、"G\0U\0"）→ 判据作废；
S-27 HB 漏检 0x67d300 真入口（前一函数以 `ret 4` 结束 + `e8` call 直达 + 入口形态一致）
且 ModRM 解码两版都错（本镜像 reg==rm==5 使第二版碰巧蒙对，对 `mov eax,[IAT]` 会错）；
S-28 反控打在不下手的地方（= R115 S-16 复发，检测器对 0x7f7c80 也命中 0）
→ 先构造正控 273/4495 例；
S-29 审计员次要数字不符，如实登记不复算成一致。

R116.10 **断言与纪律**：12 个脚本共 51 项断言全 PASS、连跑两次一致；
全程 `disasm_lite` + 逐函数 <=2000 B 窗口，**未**对 .text 整段开 `detail=True`，
脚本均带 timeout，收口前核对无孤儿进程。

R116.11 **未取得（不粉饰）**：① 0x7f7c70 的接口名（本机无 IID→名字映射表，
需外部 SDK 头文件或 win-main 动态采样）；② 0x7f7c80 的 L3 结论中「通用包装器」这一替代解释
未完全排除；③ 35 项 .data 表中 30 项落在 BSS 尾部（无文件字节），其运行期内容未取得；
④ `IPersistStream` 的**方法数**仍未取得（R113 起的老欠账，`COL.offset==0` 静态读不到）；
⑤ 门禁 C15「节内空洞」只有漏洞证明、无门禁子项（R115 遗留，本轮未动）。
